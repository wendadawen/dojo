# 文章大纲

## 1. 页面开头

- 开场场景（构造示例，贯穿全文的引子）：一个 5 轮客服对话部署在 4×H100 的 PD 分离集群上（1P_3D）。第 2 轮用户只追加了 50 个 token，但系统要把「第 1 轮输入 1000 token + 第 1 轮回复 200 token + 新 50 token」共 1250 token 全部送回 P 节点重算 KV，再经网络传回 D。数字为构造示例，目的：让「重算」与「传输」两个动作在第一个场景里就可见。
- 定位摘要：论文用「区分 full prefill 与 append-prefill 的干扰差异 + 按请求动态路由」解决「PD 分离在多轮对话下重算历史 KV、KV 传输饱和带宽」的问题。
- 论文元信息：作者、单位、ICML 2026、arXiv:2603.13358v2、代码仓库。
- 核心问题块（5 题，每题配解答折叠块）。
- 过渡到第 1 章：先把这个场景里的低效拆成两个可量化的机制。

### 第 1 章「多轮对话暴露 PD 分离的两个代价：历史重算与 KV 传输」（回答 Q1）

- 章节问题：(a) 第 2 轮的 1250 token 里哪些是重复计算？(b) 为什么 P 节点明明「知道」上一轮的回复内容却还要重算？(c) 这些 KV 传输有多重？

- 前置知识引用：moe-serving（PD 分离、KV cache、TTFT/TPOT）、prefix-caching（KV 复用意味着什么——为第 2 章 append-prefill 铺垫）。

### 第 2 章「full prefill 与 append-prefill 差一个数量级：复杂度与实测干扰」（回答 Q2）

- 章节问题：(a) append-prefill 与 full prefill 的计算量差多少？(b) 这个差距在 GPU 实测里表现为什么？(c) 它为什么能推翻「所有 prefill 都必须隔离」的前提？
- 答案要点：F2 复杂度对比 $O(n^2)$ vs $O(m(n+m))$（引 standard-attention 的 $O(n^2)$ 推导链接，不重复）；append-prefill 定义依赖 prefix cache 命中（引 prefix-caching）；$n/m$ 倍便宜的手算（贯穿示例：full 1250² vs append 50×1250，差 25 倍）；干扰实测 N1（48% vs 2%）、N2（4 并发 +57% vs +21%）、N3（32K 时 3–4× vs 64K <25%）；「PD 分离隐含前提被精细化」的表述（误解 2 纠正：full prefill 仍需隔离）。
- 原图：G1（Fig.2）。
- 表达材料：数值手算（贯穿示例）；G1 原图。
- 前置知识引用：standard-attention、prefix-caching、moe-serving（TPOT 定义）。

## 3. 贯穿示例

贯穿问题：一个 5 轮客服对话（构造示例，数字自设并全程标注）：
- 第 1 轮：输入 1000 token，回复 200 token
- 第 2 轮：追加输入 50 token（后续轮次按同模式增长，页面重点用第 2 轮手算）
- 底层常量：Llama-3.1-8B、$s_{\text{kv}}=128$ KiB/token（论文 App.D）

推进：
- 第 1 章：x=0 下第 2 轮 prefill 的 token 数 = 1000+200+50 = 1250；KV 传输量 = 1250 × 128 KiB ≈ 156 MB（构造计算）
- 第 2 章：append-prefill 只算 50 个新 token 的 attention（每个关注 1250 个 key）；与 full prefill 1250² 相比计算量差 1250/50 = 25 倍
- 第 3 章：同一对话在 1P_3D/2P_2D/3P_1D 下的 TTFT 改善幅度对照（引 N5）
- 第 4 章：给这个第 2 轮请求打分（构造的 Δ 值代入 Eq.1，两种权重下决策翻转）
- 第 5 章：这 156 MB 在 NVLink（~1ms）/HDR（~6ms）/100GbE（~16ms）下的传输时间差（构造计算，方法对齐 F3/N15）

覆盖检查：贯穿示例覆盖第 1/2/4/5 章的关键推进；第 3 章复用配置对照，第 6 章用「这个对话的负载画像（多轮、短追加）」落到适用建议。
