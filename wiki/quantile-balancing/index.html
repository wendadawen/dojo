    Quantile Balancing：从路由分数分位数直接推导 MoE 专家 bias

    主要依据：Kimi K3 Technical Report §2.3.3 (Eq.13–14)、Appendix C (balanced-assignment 推导)、Appendix D (histogram 估计)；DeepSeek-V3 Technical Report (arXiv:2412.19437) §3.3；HuggingFace moonshotai/Kimi-K3 config.json。

    896 个专家，每个 token 只用 16 个——如果总有一部分专家被冷落、另一部分被挤爆，训练会怎样？更关键的是：怎么把负载调平，还不干扰模型本身在学的东西？

    Quantile Balancing（QB）是 Kimi K3 的 MoE 负载均衡方法，从一次前向传播的路由分数分位数直接算出每个专家的 bias，替代 DeepSeek-V3 的固定步长 sign 更新。它不引入任何损失项，只改 bias 的更新规则：从"走固定小步"变成"一步跳到精确解"。[C17, N1]

    最容易误解

    • "QB 是一种新的损失函数"——QB 是 bias 的更新规则，不引入任何损失项，它替代的是 bias 的更新方式而非损失函数。
    • "QB 一步就能完美均衡任何负载"——QB 是交替求解器的一轮更新，论文报告在近 10³ 专家时"几步内"收敛；手算例子恰好一步收敛，但不代表一般情况。
    • "bias 参与了 mixture weight 的计算"——bias 只加到 router 分数上做 Top-k 选择，归一化权重只用原始分数计算。

    auxiliary-loss-free 路由——bias 做什么、不做什么

    在讲 QB 之前，先理解它所处的路由框架。MoE（混合专家模型）的基本路由机制见 MoE 大模型推理与服务基础。这里只说 QB 直接依赖的部分。

    MoE 路由的核心是：对每个 token $x_i$，router（一个线性层 $W_r$）打出每个专家的分数 $s_{i,j} = \sigma(W_r x_i)_j$，其中 $\sigma$ 是 sigmoid。$\sigma$ 的作用是将实数分数压到 $(0,1)$ 区间。然后选分数最高的 $k$ 个专家处理这个 token。

    auxiliary-loss-free 路由的关键设计是给每个专家加一个 bias $b_j$，但 bias 只参与"选谁"，不参与"用多少"：[F1]

    $$T_i = \text{argtopk}(s_i + b), \qquad p_{i,j} = \frac{s_{i,j}}{\sum_{r \in T_i} s_{i,r}}, \quad j \in T_i$$

    其中：

    • $s_i$：token $i$ 对所有专家的分数向量，$s_{i,j} \in (0,1)$。
    • $b$：长度为 $n$（专家数）的 bias 向量，$b_j$ 是专家 $j$ 的偏置。
    • $T_i$：token $i$ 选中的 $k$ 个专家集合，选的是 $s_i + b$ 中最大的 $k$ 个。
    • $p_{i,j}$：归一化权重（mixture weight），只用原始分数 $s$ 计算，不含 $b$。

    因为 $b$ 从 $p_{i,j}$ 的计算中被省略，它只调节分发（选哪些专家），不改变 mixture weight 也不进入基于梯度的优化目标。这就是"auxiliary-loss-free"的含义——不需要额外的负载均衡损失项来干扰主训练目标。auxiliary-loss-free routing 的完整概念见 auxiliary-loss-free routing。

    用两个快速检查验证 bias 的角色。第一，如果所有专家的 bias 同时加常数 $c$，则 $s_{i,j} + b_j + c = (s_{i,j} + b_j) + c$，Top-k 选择不变——因为所有分数同时平移，相对排序不变。第二，归一化权重 $p_{i,j}$ 不含 $b$，所以 bias 完全不影响专家的输出权重，只影响"这个 token 分给谁"。

    bias 能调节负载：给冷门专家加正 bias 会提高它进入 Top-k 的概率，给过热专家减 bias 会降低它被选中的概率。但 bias 本身怎么更新？下一章看 DeepSeek-V3 的做法和它的瓶颈。

    完成本章后，用下面几个问题检查自己是否跟上：

    • bias 加到分数上选 Top-k 后，如果两个 expert 的 bias 同时加 0.1，Top-k 选择会变吗。归一化权重 $p$ 会变吗。
    • $p_{i,j}$ 的公式中分母 $\sum_{r \in T_i} s_{i,r}$ 为什么不含 $b_r$。这保证了 bias 不影响什么。

    本章说明了 bias 在路由中的角色——只影响选谁，不进权重。但 bias 本身怎么更新、为什么固定步长更新在大规模时失效——下一章讲 DeepSeek-V3 的 sign 更新及其瓶颈。

    DeepSeek-V3 的固定步长更新——为什么 896 专家时失效

    DeepSeek-V3 提出 auxiliary-loss-free 路由时，bias 的更新规则是固定步长的 sign 更新：[C2, F2]

    $$b_j^{(t+1)} = b_j^{(t)} + \gamma \cdot \text{sign}(\bar{\ell}^{(t)} - \ell_j^{(t)})$$

    其中：

    • $\ell_j^{(t)}$：第 $t$ 步训练中专家 $j$ 实际收到的 token 数（负载）。
    • $\bar{\ell}^{(t)}$：所有专家的平均负载 $= mk/n$（$m$ 个 token，$n$ 个专家，每个选 $k$ 个）。
    • $\gamma$：固定步长超参数，控制 bias 变化速度。
    • $\text{sign}(\cdot)$：符号函数，正数返回 $+1$，负数返回 $-1$，零返回 $0$。

    当 $\bar{\ell} > \ell_j$（专家 $j$ 负载低于平均，偏冷门），$\text{sign}$ 为 $+1$，bias 增大 $\gamma$，让该专家更容易被选中。当 $\bar{\ell} < \ell_j$（专家 $j$ 过热），$\text{sign}$ 为 $-1$，bias 减小 $\gamma$，压制该专家。

    这个更新有一个根本性的两难：$\gamma$ 只有一个值，既要够大才能快速纠正不均衡，又要够小才不会在均衡附近来回震荡。sign 只保留了负载误差的方向，丢掉了幅度。无论专家多了 100 个 token 还是多了 1 个 token，$\text{sign}(\bar{\ell} - \ell_j)$ 都返回 $-1$，bias 都只走 $\gamma$ 这一步。

    教学示例。 假设 $\gamma = 0.001$，某专家负载 $\ell_j = 100$，目标 $\bar{\ell} = 50$（多了 50 个）。$\text{sign}(50 - 100) = \text{sign}(-50) = -1$，每步 bias 减 $0.001$。另一个场景中负载 $\ell_j = 51$（只多了 1 个），$\text{sign}(50 - 51) = \text{sign}(-1) = -1$，每步 bias 也减 $0.001$。两种差距相差 50 倍，但 bias 的更新幅度完全相同——sign 丢失了"差多远"的信息。前者需要约 50000 步才能把 bias 调到合理水平。

    K3 将 routed expert 池扩大到 896 per layer，每个 token 选 16 个（$k=16$）。这些数字来自 K3 官方 config.json（num_experts: 896, num_experts_per_token: 16, topk_method: "noaux_tc"）。[C17, N1] 专家数从前代 K2 的 384 扩大到 896（K3 报告 Table 1）后，sign 更新只保留方向的缺陷被放大：收敛慢、均衡附近震荡、部分专家长期训练不足，拖慢专家并行训练。

    sign 更新只走固定小步，QB 的思路是：能不能从当前分数分布直接算出"正确的 bias 应该是多少"——不是走一小步，而是一步跳到目标？

    完成本章后，用下面几个问题检查自己是否跟上：

    • $\gamma = 0.001$ 时，负载从 100 降到目标 50，sign 更新需要多少步才能让 bias 减少合理量。这说明了 sign 更新的什么问题。
    • sign 函数在 $\bar{\ell} - \ell_j = -50$ 和 $\bar{\ell} - \ell_j = -1$ 时返回值相同，这丢失了什么信息。

    本章说明了 sign 更新在大规模专家时的瓶颈——只保留方向、步长固定。但能不能从当前分数分布直接算出"正确的 bias 应该是多少"——下一章讲 QB 的核心机制。

    QB 的核心机制——从一次前向推导下一个 bias

    QB 从一次前向传播的分数推导出下一个 bias。整个过程可以画成一条流水线：

    前向传播
  │
  ▼
Top-(k+1) 路由 ──► 前 k 个 = 实际路由 T_i
                   第 (k+1) 个 = cutoff α_i
  │
  ▼
margins = s_{i,j} − α_i        （raw score 减 cutoff）
  │
  ▼
每专家取 (1−k/n) 分位数          （使恰好 q 个 margin 超过阈值）
  │                              b̃_j = −quantile_{1−k/n}(margins_{:,j})
  ▼
mean-centering                  b = b̃ − mean(b̃)·1
  │
  ▼
下一步生效（因果性）              batch 不用自己推导的 bias 路由

    下面逐步拆解。

    步骤 1：Top-(k+1) 路由得 cutoff α_i

    QB 不是做 Top-k，而是做 Top-(k+1)。对 token $i$，把 $s_{i,j} + b_j^{(t)}$ 从大到小排序，取前 $k+1$ 个。前 $k$ 个是实际路由 $T_i$（与普通 Top-k 相同），第 $(k+1)$ 个就是 cutoff $\alpha_i$——"要进 Top-k 必须超过的分数线"。

    从 Top-(k+1) 取 cutoff 的好处是：不需要额外做一次 token 侧的分位数计算来估计"门槛在哪"，cutoff 是路由的副产品。

    步骤 2：计算 margins

    对每个 token $i$ 和每个专家 $j$，计算 margin：

    $$\text{margin}_{i,j} = s_{i,j} - \alpha_i$$

    注意这里用的是 raw score $s_{i,j}$ 减 cutoff $\alpha_i$。$\alpha_i$ 来自 Top-(k+1) 的 biased score（含旧 bias $b^{(t)}$），但 $s_{i,j}$ 不含 bias。所以旧 bias 只通过 cutoff $\alpha_i$ 间接进入 margin，raw score 保持"干净"。

    margin 的直觉含义：它衡量"专家 $j$ 对 token $i$ 的吸引力，减去进入 Top-k 的门槛"。margin 为正说明该专家的 raw 分数超过了 cutoff（在 biased 分数下它本可以进 Top-k），margin 为零说明恰好等于 cutoff，margin 为负说明不够格。

    步骤 3：取 (1−k/n) 分位数得 b̃

    对每个专家 $j$，收集所有 $m$ 个 token 对它的 margin，取 $(1 - k/n)$ 分位数，取负就是 b̃：[C1, F3]

    $$\tilde{b}_j^{(t+1)} \leftarrow -\text{quantile}_{1-k/n}\left(s_{:,j}^{(t)} - \alpha^{(t)}\right)$$

    分位数的最小定义：将一组数从小到大排列，$(1-k/n)$ 分位数是这样一个阈值——恰好 $k/n$ 比例的数超过它。例如 8 个数取 $0.75$ 分位数，就是第 3 大的值（8 个中恰好 $2/8 = 0.25$ 比例超过它）。

    为什么是 $(1-k/n)$ 分位数？目标负载 $q = mk/n$，即每个专家应该收到 $q$ 个 token。设 $-\tilde{b}_j$ 为阈值，margin 超过 $-\tilde{b}_j$ 的 token 数就是会被路由到专家 $j$ 的 token 数。要使这个数恰好等于 $q$，阈值应设在第 $(q+1)$ 大的 margin 上——恰好 $q$ 个 margin 严格超过它。因为 $q/m = k/n$，第 $(q+1)$ 大的 margin 就是 $(1-k/n)$ 分位数。

    补充：为什么 (q+1)-th largest margin 等于 (1−k/n) 分位数

    给定专家 $j$ 的 $m$ 个 margin，将它们从大到小排列：$v_1 \geq v_2 \geq \cdots \geq v_m$。设 $-\tilde{b}_j = v_{q+1}$（第 $(q+1)$ 大），则恰好 $q$ 个 margin 严格大于 $-\tilde{b}_j$（即 $v_1, \ldots, v_q$），其余 $m - q$ 个不超过它。

    "恰好 $q/m$ 比例的数超过阈值"就是 $(1 - q/m)$ 分位数的定义。代入 $q = mk/n$：

    $$1 - \frac{q}{m} = 1 - \frac{mk/n}{m} = 1 - \frac{k}{n}$$

    所以 $(q+1)$-th largest $= (1-k/n)$ 分位数。QB 取负号是因为 bias 越大越容易被选中，而 margin 越大说明该专家越"热门"，所以 bias 应与 margin 的分位数符号相反。

    步骤 4：mean-centering

    最后减去均值：

    $$b^{(t+1)} \leftarrow \tilde{b}^{(t+1)} - \text{mean}\left(\tilde{b}^{(t+1)}\right) \cdot \mathbf{1}$$

    mean-centering 去掉一个所有专家共有的公共偏移。因为 Top-k 选择只取决于各专家 biased score 的相对排序，所有 expert 同时加减常数不改变排序结果。这一步保证 bias 的绝对值不漂移，只保留专家间的相对差异。

    因果性：更新在下一步生效。第 $t$ 步的前向传播算出 $b^{(t+1)}$，但第 $t$ 步的 batch 用的是 $b^{(t)}$（上一步算出的）。一个 batch 绝不用自己推导的 bias 路由——否则会造成信息泄漏。

    公式讲清了，现在用手算例子验证每一步。

    代码：手算例子的完整 QB 计算 
    """
QB 手算例子验证：m=8, n=4, k=1（纯 Python，无第三方库）
教学示例：分数为人为构造，QB 计算过程与真实机制一致。
"""

# 教学示例分数矩阵 (8 tokens, 4 experts)
scores = [
    [0.7, 0.3, 0.8, 0.5],  # T1
    [0.7, 0.5, 0.4, 0.2],  # T2
    [0.6, 0.8, 0.1, 0.2],  # T3
    [0.9, 0.2, 0.8, 0.1],  # T4
    [0.8, 0.4, 0.6, 0.6],  # T5
    [0.7, 0.8, 0.2, 0.3],  # T6
    [0.8, 0.5, 0.3, 0.4],  # T7
    [0.1, 0.8, 0.7, 0.7],  # T8
]

m = len(scores)      # 8 tokens
n = len(scores[0])   # 4 experts
k = 1
q = m * k // n       # target load = 2

# Step 0: 初始路由 (bias = 0)
bias = [0.0] * n
routes0 = []
cutoffs = []
for i in range(m):
    biased = [(scores[i][j] + bias[j], j) for j in range(n)]
    biased.sort(reverse=True)  # descending by biased score
    routes0.append(biased[0][1])    # top-1 expert
    cutoffs.append(biased[k][0])    # (k+1)-th = 2nd largest

loads0 = [0] * n
for r in routes0:
    loads0[r] += 1

print("=== 初始路由 (b=0) ===")
for i in range(m):
    print(f"  T{i+1}: -> E{routes0[i]+1}, alpha={cutoffs[i]:.1f}")
print(f"  loads = {loads0}  (target q={q})")

# Step 1: margins = s - alpha
margins = [[scores[i][j] - cutoffs[i] for j in range(n)] for i in range(m)]

# Step 2: 每专家 (1-k/n) 分位数 = (q+1)-th largest = 3rd largest
b_tilde = [0.0] * n
for j in range(n):
    col = sorted([margins[i][j] for i in range(m)], reverse=True)
    quantile_val = col[q]  # 0-indexed: index q = (q+1)-th largest
    b_tilde[j] = -quantile_val
    print(f"  E{j+1} margins desc: {[f'{v:+.1f}' for v in col]}")
    print(f"    3rd largest = {quantile_val:+.1f}, b_tilde = {-quantile_val:+.1f}")

# Step 3: mean-centering
mean_b = sum(b_tilde) / n
bias_new = [b - mean_b for b in b_tilde]

    QB 为什么好——从平衡分配到对偶的视角

    手算例子验证了 QB 的机制，但它为什么比 sign 更新好？为什么不需要 $\gamma$ 这类超参数？答案来自将负载均衡看作一个最优化问题。

    平衡分配问题

    给定 $m$ 个 token 对 $n$ 个专家的分数 $s \in \mathbb{R}^{m \times n}$，每个 token 选 $k$ 个专家，每个专家服务 $mk/n$ 个 token。最大分数均衡分配是：

    $$\max_{x_{i,j} \in \{0,1\}} \sum_{i,j} x_{i,j} s_{i,j} \qquad \text{s.t.} \quad \sum_j x_{i,j} = k, \quad \sum_i x_{i,j} = \frac{mk}{n}$$

    这是整数规划，但线性松弛（$x_{i,j} \in [0,1]$）后由二部图 b-matching 多面体的整性保证最优解为整数，所以松弛是精确的。

    对偶目标与交替求解

    引入对偶乘子 $\alpha_i$（token 侧）和 $\beta_j$（专家侧），对偶目标为：[F4]

    $$\min_{\alpha, \beta} L(\alpha, \beta) := \sum_{i,j} \max\left(0, s_{i,j} - \alpha_i - \beta_j\right) + k \sum_i \alpha_i + \frac{mk}{n} \sum_j \beta_j$$

    交替求解器固定一方求另一方：给定 $\beta$，$\alpha_i$ 的最优是 $s_i - \beta$ 的 $(1-k/n)$ 分位数；给定 $\alpha$，$\beta_j$ 的最优是 $s_{:,j} - \alpha$ 的 $(1-k/n)$ 分位数。[F5] 两次更新都是同一个分位数，QB 的名字由此而来。

    补充：从对偶目标到 coordinate minimizer

    给定 $\alpha$ 固定，对 $\beta_j$ 求 $L$ 的最小值。目标中与 $\beta_j$ 相关的项为：

    $$L_j(\beta_j) = \sum_{i=1}^{m} \max(0, s_{i,j} - \alpha_i - \beta_j) + \frac{mk}{n} \beta_j$$

    令 $m_i = s_{i,j} - \alpha_i$（即 margin），则 $L_j(\beta_j) = \sum_i \max(0, m_i - \beta_j) + \frac{mk}{n} \beta_j$。

    这是关于 $\beta_j$ 的分段线性函数。$L_j$ 对 $\beta_j$ 的（次）梯度为：

    $$\frac{\partial L_j}{\partial \beta_j} = -\sum_{i=1}^{m} \mathbb{1}[m_i > \beta_j] + \frac{mk}{n}$$

    第一项是 $\beta_j$ 上方 margin 的个数的负数，第二项是目标负载 $q = mk/n$。令梯度为零，得 $\beta_j$ 上方的 margin 数 $= q$，即 $\beta_j$ 是第 $(q+1)$ 大的 margin，也就是 $(1-k/n)$ 分位数。

    因为 $b_j = -\beta_j$（bias 是阈值的负数），所以 $b_j = -\text{quantile}_{1-k/n}(margins_{:,j})$，正是 Eq.14。

    sign 更新是 SignSGD，QB 是 coordinate minimizer

    对偶目标对 $\beta_j$ 的（次）梯度恰好是：

    $$\frac{\partial L}{\partial \beta_j} = \frac{mk}{n} - \sum_{i=1}^{m} \mathbb{1}\left[s_{i,j} - \alpha_i - \beta_j > 0\right] = \underbrace{\frac{mk}{n}}_{\text{目标负载}} - \underbrace{\ell_j}_{\text{实际负载}}$$

    DeepSeek-V3 的 sign 更新 $b_j \leftarrow b_j + \gamma \cdot \text{sign}(\bar{\ell} - \ell_j)$ 恰好是对这个梯度做 SignSGD（因 $b = -\beta$，对 $\beta$ 的梯度下降等价于对 $b$ 的 sign 更新，推导见折叠块；只保留方向，步长固定为 $\gamma$）。[F6] 而 QB 直接跳到该对偶目标的精确 coordinate minimizer——不求梯度方向再走步，而是直接算出使该坐标最优的值。

    DeepSeek-V3 sign 更新QB
    求解策略SignSGD（梯度方向 × 固定步长）精确 coordinate minimizer
    保留信息只保留方向保留完整分布（通过分位数）
    超参数需要 $\gamma$（权衡慢适应与震荡）无超参数
    收敛慢，大规模时震荡近 $10^3$ 专家时几步内收敛[C1]
    对同一目标都是对偶目标 $L(\alpha, \beta)$ 的求解

    这就是 QB 无需 $\gamma$ 的根本原因：它不是在走梯度步，而是在直接求精确解。代价是每步需要计算分位数（而非简单的 sign），但直方图估计（下一章）使这个代价可控。

    完成本章后，用下面几个问题检查自己是否跟上：

    • $\partial L / \partial \beta_j$ 在负载恰好均衡时等于 $0$，说明什么。sign 更新在均衡时 $\text{sign}(0) = 0$ 也不更新，两者在均衡点行为一致——区别在非均衡时怎么走。
    • SignSGD 只保留梯度方向不保留幅度，QB 保留了什么信息使得它能一步跳到精确解。

    本章从对偶理论说明了 QB 为什么比 sign 更新好——它直接求精确 coordinate minimizer 而非走梯度步。但训练时百万级 margin 无法全量收集——下一章讲直方图估计如何以固定成本恢复分位数。

    训练时的直方图估计与推理冻结

    QB 公式要求对每个专家的 $m$ 个 margin 取分位数。在 K3 训练中，$m$ 是百万级，分布在多张 GPU 和多个梯度累积步上。全量收集 $O(mn)$ 个 margin 来做精确分位数在训练循环内不可行。

    关键观察：QB 不需要 margin 本身，只需要每个专家的 margin 分布。直方图以固定成本概括分布。

    直方图估计机制

    对每个专家维护一个 $B$ 个 bin 的直方图。分箱范围为 $[b_{\min}-1, b_{\max}+1]$，其中 $b_{\min}$、$b_{\max}$ 是当前 bias 的极值。因为 router 分数 $s_{i,j} \in (0,1)$（sigmoid 输出），cutoff $\alpha_i$ 也是某个 biased score，落在 $(b_{\min}, 1+b_{\max})$ 内，所以所有 $r_{i,j} = \alpha_i - s_{i,j} = -\text{margin}_{i,j}$（与上文 margin 符号相反；来源称 $r$ 为 required bias）落在 $[b_{\min}-1, b_{\max}+1]$ 内。[C14, F7] 范围每步重算，bin width $w = (b_{\max} - b_{\min} + 2)/B$ 随 bias 扩散而自适应。

    训练时的流程：

    代码：直方图估计的分位数恢复 
    输入：每 rank 的本地 margins r_{i,j}（前向传播产出）
状态：per-expert 直方图 H ∈ N^{n×B}（每步新建）
分箱范围 [lo, hi] = [b_min - 1, b_max + 1]
bin width w = (hi - lo) / B
目标 rank = ⌈q⌉（q = mk/n）

对每个 rank（无通信）：
    对每个 (i, j)：
        bin_idx = floor((r_{i,j} - lo) / w)
        H[j, bin_idx] += 1          # scatter-add 本地 counts

all-reduce 汇总 H（一次整数 all-reduce，nB 个值）

对每个专家 j：
    找第一个 bin β_j 使累积 count ≥ ⌈q⌉
    c_j = bin β_j 前的累积 count
    h_j = bin β_j 内的 count
    分位数 = lo + (β_j + clip((q - c_j) / h_j, 0, 1)) × w
    b̃_j = 分位数    # 注意 r = α - s = -margin，所以取 k/n 分位数

b = b̃ - mean(b̃)·1    # mean-centering
输出：下一步的 bias b

    通信只在 step 结束时做一次 all-reduce，汇总 $nB$ 个整数 per layer per step，与 $m$ 无关。每个 rank 从同一份 pooled counts 恢复分位数。因为 counts 可加，全局直方图精确代表整个 pooled batch，不受 token 如何分布在各 rank 或累积步上影响——估计的是全局 batch 的分位数，而非各 rank 分位数的平均。

    从 pooled counts 恢复分位数：找第一个累计 count 达到 $\lceil q \rceil$ 的 bin，在 bin 内线性插值：

    $$\tilde{b}_j = b_{\min} - 1 + \left(\beta_j + \text{clip}\left(\frac{q - c_j}{h_j}, 0, 1\right)\right) w$$

    其中 $\beta_j$ 是选中 bin 的索引，$c_j$ 是其前累计 count，$h_j$ 是 bin 内 count。

    误差与成本

    分位数误差不超过 bin width $w$。$B = 1000$ 时误差最多几个 $10^{-3}$，观测不到残余负载不均衡。[N2] 通信成本是 $nB$ 个整数 per layer per step，在 K3 配置下低于 raw margins 交换成本的 1%。[N3]

    推理冻结

    训练结束后 bias 冻结。推理时路由是固定的 Top-k 选择加冻结 bias，不需要任何分位数计算、直方图或 all-reduce。这保证了训练-推理一致性：训练时学到的 bias 直接用于推理。

    训练推理
    bias 状态每步更新冻结
    分位数计算直方图估计（all-reduce）无
    路由Top-k on $(s + b^{(t)})$Top-k on $(s + b_{\text{final}})$
    额外通信$nB$ 整数/layer/step无

    作为进一步优化，维护估计分位数的 EMA（指数移动平均）可以减少批次间采样噪声，进一步改善负载均衡。[C16]
