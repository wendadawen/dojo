    Quantile Balancing

    正文 1,943 字 · 约 6 分钟阅读

    Quantile Balancing（QB）是混合专家模型里给每个专家算偏置、用来调负载均衡的方法。它解决的问题是：一个 batch（一次一起处理的一批 token）的 token 应该均匀分给各个专家，但路由只按分数取高分，负载容易不均衡。QB 不靠一步步试，而是用一次前向（把输入算成输出的那一遍）得到的这批路由分数一次算出偏置：先给每个 token 定一个阈值（它那一行带偏置的分数里第 $k+1$ 高的值），把每个专家的分数减去对应阈值后取分位数（一组数里指定比例以下的阈值）、取负，再减掉均值，使每个专家恰好收到目标数量的 token。它替代的是固定步长的偏置更新。混合专家（MoE）的每一层有若干个并列的专家子网络；一个 token（模型处理的一段文本的单位）由路由层算出一组分数，只送给分数最高的几个专家；这里用 sigmoid（把任意实数映到 0 到 1 之间的 S 形函数）算分数。

    1. 加在路由分数上的专家偏置

    路由层对每个 token $x_i$ 算一组分数 $s_i = \operatorname{Sigmoid}(W_r x_i)$，$W_r$ 是路由层权重，然后选分数最高的 $k$ 个专家。QB 给每个专家 $j$ 一个偏置 $b_j$，加在分数上参与选择：选的是 $s_i + b$ 最大的 $k$ 个专家。选定之后，token 对这个专家的权重 $p_{i,j}$ 只用原始分数 $s_{i,j}$ 归一化，不含偏置。偏置因此只决定把 token 送到哪些专家，不进入混合权重，也不进入路由层的梯度，所以它可以在不干扰模型参数学习的前提下单独调负载。

    选择和权重的公式

    $$T_i = \operatorname{argtopk}(s_i + b), \qquad p_{i,j} = \frac{s_{i,j}}{\sum_{r \in T_i} s_{i,r}}, \quad j \in T_i$$

    $T_i$ 是 token $i$ 选中的 $k$ 个专家的集合。

    2. 旧的偏置更新为什么不够

    旧的偏置更新走固定步长：每步把偏置加上 $\gamma \cdot \operatorname{sign}(\bar\ell - \ell_j)$，$\bar\ell$ 是专家平均负载、$\ell_j$ 是专家 $j$ 的负载、$\gamma$ 是固定步长。负载高于平均就减、低于平均就加，一次只改变 $\gamma$。步长 $\gamma$ 两难：取大了偏置来回震荡，取小了又适应得太慢。专家池增大时，把负载维持均衡会变得更难，而不均衡的路由会拖慢专家并行训练（把不同专家放到不同设备上的训练方式），也可能让部分专家训练不充分。

    3. 从一次前向推出下一个偏置

    QB 从一次前向得到的这批分数里，直接算出每个专家为达到目标负载应有的偏置。记一批有 $m$ 个 token、$n$ 个专家、每个 token 选 $k$ 个，目标负载是每个专家 $q := mk/n$ 个 token。

    第一步，把选择从 Top-$k$ 换成在带偏置的分数 $s_i + b$ 上取 Top-$(k+1)$：前 $k$ 个是实际选中的专家，第 $k+1$ 个给出一个阈值 $\alpha_i$——一个专家要进 token $i$ 的 Top-$k$，分数必须超过它，所以 $\alpha_i$ 叫 cutoff。第二步，算每对 $(i,j)$ 的 margin $s_{i,j} - \alpha_i$，即原始分数减去 cutoff；用原始分数（不含旧偏置）相减，旧偏置只通过 cutoff 进来。

    第三步，反解出使专家 $j$ 恰好收到 $q$ 个 token 的偏置。在 cutoff 固定时，专家 $j$ 收到的 token 数是「margin 超过某个阈值」的个数，这个数随阈值单调下降；把它定成 $q$，阈值就落在第 $q+1$ 大的 margin 上，也就是 margin 的 $1-k/n$ 分位数。于是取

    $$\tilde b_j \leftarrow -\operatorname{quantile}_{1-k/n}\!\left(s_{:,j} - \alpha\right)$$

    第四步，减去全体偏置的均值：$b \leftarrow \tilde b - \operatorname{mean}(\tilde b)\cdot\mathbf{1}$。一个公共偏移同时加在或减在所有专家的分数上，不改变它们之间的相对大小，也就不改变 Top-$k$ 选择，减掉它只是把偏置的均值定到零。更新在下一步才生效，一个 batch 不会用自己算出的偏置来路由：这批 token 已经走完了前向，新偏置留给下一批。

    为什么阈值是 (1−k/n) 分位数

    设 −b̃_j 为阈值，专家 j 收到的 token 数就是 margin 超过这个阈值的个数：

    $$q := \sum_{i=1}^{m} \mathbf{1}\!\left[s_{i,j} + \tilde b_j > \alpha_i\right]$$

    这个计数随阈值 −b̃_j 单调递减。假设 margin 互不相等，要让计数恰好等于 $q$，阈值就取第 $q+1$ 大的 margin：比它大的正好有 $q$ 个。而 $q/m = k/n$，所以超过阈值的是 $k/n$ 比例，阈值就是 $1-k/n$ 分位数。

    4. 手算一遍

    取 $m = 6$ 个 token、$n = 3$ 个专家、$k = 1$，初始偏置全为 $0$，目标负载 $q = mk/n = 2$。分数表如下，每一行是一个 token 对三个专家的分数（2 位小数）：

    $E_1$$E_2$$E_3$
    $t_1$0.450.550.25
    $t_2$0.650.900.40
    $t_3$0.900.600.20
    $t_4$0.550.600.20
    $t_5$0.600.800.10
    $t_6$0.850.550.80

    偏置全为 $0$ 时按每行最大值路由，得到的负载是 $(2, 4, 0)$：$E_3$ 一个 token 也没收到，负载很不均。

    一步步算出新偏置

    $k = 1$，cutoff $\alpha_i$ 是每行第 2 大的分数：

    1. $t_1$ 的分数排序 $0.55, 0.45$，$\alpha_1 = 0.45$；$t_2$：$0.90, 0.65$，$\alpha_2 = 0.65$；$t_3$：$0.90, 0.60$，$\alpha_3 = 0.60$。
    2. $t_4$：$0.60, 0.55$，$\alpha_4 = 0.55$；$t_5$：$0.80, 0.60$，$\alpha_5 = 0.60$；$t_6$：$0.85, 0.80$，$\alpha_6 = 0.80$。
    3. 算 margin $s_{i,j} - \alpha_i$，每个专家一列。$E_1$：$(0, 0, 0.3, 0, 0, 0.05)$，从大到小为 $0.3, 0.05, 0, 0, 0, 0$。
    4. $E_1$ 第 $q+1 = 3$ 大的 margin 是 $0$，故 $\tilde b_1 = 0$。$E_2$：$(0.1, 0.25, 0, 0.05, 0.2, -0.25)$，从大到小为 $0.25, 0.2, 0.1, 0.05, 0, -0.25$，第 3 大为 $0.1$，$\tilde b_2 = -0.1$。
    5. $E_3$：$(-0.2, -0.25, -0.4, -0.35, -0.5, 0)$，从大到小为 $0, -0.2, -0.25, -0.35, -0.4, -0.5$，第 3 大为 $-0.25$，$\tilde b_3 = 0.25$。
    6. $\tilde b = (0, -0.1, 0.25)$，均值 $0.05$。减均值得 $b = (-0.05, -0.15, 0.20)$。

    用新偏置重新路由，三个专家各收到 $2$ 个 token，负载变成 $(2, 2, 2)$。再走一步得到的偏置不变，说明这一步落在了均衡解上；这里只是用同一张表离线验证这个解是稳定的。

    代码验证 
    scores = [[0.45, 0.55, 0.25],
          [0.65, 0.90, 0.40],
          [0.90, 0.60, 0.20],
          [0.55, 0.60, 0.20],
          [0.60, 0.80, 0.10],
          [0.85, 0.55, 0.80]]
m, n, k = len(scores), len(scores[0]), 1
q = m * k // n

def route(b):
    load = [0] * n
    for row in scores:
        j = max(range(n), key=lambda j: (row[j] + b[j], -j))
        load[j] += 1
    return load

def qb_step(b):
    alpha = [sorted((row[j] + b[j] for j in range(n)), reverse=True)[k] for row in scores]
    tilde = [0.0] * n
    for j in range(n):
        margins = sorted((scores[i][j] - alpha[i] for i in range(m)), reverse=True)
        tilde[j] = -margins[q]
    mean = sum(tilde) / n
    return [x - mean for x in tilde]

print("loads before:", route([0.0] * n))
b = qb_step([0.0] * n)
print("bias after step:", [round(x, 3) for x in b])
print("loads after:", route(b))
print("bias after another step:", [round(x, 3) for x in qb_step(b)])

    5. 为什么几步就能收敛

    旧更新和 QB 是同一个优化目标上的两种解法。这个目标是「最大分数的均衡分配」：在「每个 token 恰好选 $k$ 个专家、每个专家恰好服务 $q$ 个 token」的约束下，让被选中配对的分数之和最大。把它松弛成连续变量后取对偶（对偶指把带约束的最大化改写为对新引入的乘子求最小），就得到一个只关于两组乘子的最小化问题。在这个对偶问题里，每个乘子单独看，精确最优恰好是前一步写的那条分位数；旧更新相当于在这个对偶目标上每步只沿次梯度（不可导点处替代梯度的方向）的符号走一小步，QB 则一步取到精确最优。这就是 QB 不需要学习率类超参数（优化时控制每步走多远的系数）、在专家很多时也能几步内收敛的原因。

    对偶推导
    1. 均衡分配问题：$\max_{x_{i,j}\in\{0,1\}}\sum_{i,j} x_{i,j} s_{i,j}$，约束每个 token $\sum_j x_{i,j} = k$、每个专家 $\sum_i x_{i,j} = mk/n$（设为整数）。$x_{i,j} = 1$ 表示 token $i$ 分配给专家 $j$。
    2. 松弛 $x_{i,j}\in[0,1]$ 得到线性规划，其最优解仍是整数（这类分配问题的可行域是二部图匹配多面体，线性规划的最优解总可以取到整数），松弛不损失最优值。给 token 侧、专家侧各引入乘子 $\alpha_i$、$\beta_j$，写成 max–min 形式后交换次序。

    3. 内层对 $x$ 逐个最大化，$s_{i,j} - \alpha_i - \beta_j > 0$ 时取 1、否则取 0，代回得到对偶目标

      $$L(\alpha, \beta) = \sum_{i,j}\max(0, s_{i,j}-\alpha_i-\beta_j) + k\sum_i \alpha_i + \frac{mk}{n}\sum_j \beta_j$$

    4. 交替最小化：固定 $\beta$ 解 $\alpha$（按 token 分块），固定 $\alpha$ 解 $\beta$（按专家分块）。$\beta$ 固定的子目标对 $\alpha$ 分段线性，当恰有 $k$ 个「$s_{i,j}-\beta_j$」在 $\alpha$ 之上时最小，所以取 $\alpha_i^*$ 为 $s_i - \beta$ 的 $1-k/n$ 分位数；对称地 $\beta_j^*$ 为 $s_{:,j} - \alpha$ 的 $1-k/n$ 分位数。两边都是同一个分位数，方法因此得名。
    5. 专家侧子目标的次梯度（不可导点处替代梯度的方向）是 $\partial L/\partial\beta_j = mk/n - \sum_i \mathbf{1}[s_{i,j}-\alpha_i-\beta_j>0]$，即目标负载减实际负载；又因 $b = -\beta$，在 $\beta$ 上做一步就对应到 $b$ 上的一次改动。

    6. 大规模训练怎么算分位数

    真实训练里 $m$ 是百万级，用来算分位数的量 $r_{i,j} = \alpha_i - s_{i,j}$（margin $s_{i,j}-\alpha_i$ 的相反数）有 $O(mn)$ 个，分布在多个数据并行 rank（每张加速卡一个副本）和梯度累积步（一次参数更新里累积的若干小批）上，训练循环里收齐再排序算精确分位数做不到。QB 改用每个专家一张 $r$ 的直方图：每个 rank 在前向时把本地 $r$ 分散累加（scatter-add）进本地的计数矩阵，这一步不通信；一个训练步结束时做一次 all-reduce（一种集合通信，把所有 rank 的计数相加并广播给每个 rank），得到全局计数；再从合并后的计数里读出分位数。因为计数可加，只要把各 rank 的计数相加，得到的就是整批 token 的直方图，而不是各 rank 分位数的平均。分位的取法：找第一个累计计数达到 $\lceil q\rceil$ 的 bin（直方图的一个区间），在 bin 内线性插值。

    直方图分位数估计的细节
    1. 分箱范围：路由分数是 sigmoid 输出，落在 $(0,1)$；cutoff $\alpha_i$ 本身是某个专家的带偏置分数 $s_{i,j'} + b_{j'}$，落在 $(b_{\min}, 1 + b_{\max})$，$b_{\min}$、$b_{\max}$ 是当前偏置的极值。于是 $r_{i,j} = \alpha_i - s_{i,j}$ 落在 $[b_{\min}-1, b_{\max}+1]$。把这个区间均分成 $B$ 个 bin，每步重算范围，bin 宽 $w = (b_{\max}-b_{\min}+2)/B$。
    2. 计数矩阵：前向时每个 rank 把本地的 $r_{i,j}$ scatter-add 进每专家的计数矩阵 $H \in \mathbb{N}^{n\times B}$，跨小批累加。

    3. 恢复分位数：直方图把每个专家的每个 token 记一次，累计到某个 bin 的计数就是 $r$ 不超过该 bin 右侧的 token 数；要取的分位数对应计数 $q = mk/n$（即前面那个第 $q+1$ 大的 margin 落在的位置）。设累计计数达到 $\lceil q\rceil$ 的那个 bin 的 0 起下标为 $\rho_j$、其左侧累计 $c_j$ 个、bin 内 $h_j$ 个，则

      $$\tilde b_j = b_{\min} - 1 + \left(\rho_j + \operatorname{clip}\!\left(\frac{q-c_j}{h_j}, 0, 1\right)\right) w$$

    4. 误差与通信：累计计数在 bin 边界上精确，所以真分位数与估计值落在同一个 bin，误差不超过 bin 宽 $w$；$B = 1000$ 时误差最多几个 $10^{-3}$，观测不到残余负载不均衡。唯一的通信是每层每步一次 $nB$ 个整数的 all-reduce，与 $m$ 无关。对估计出的分位数沿步做指数移动平均（按权重递减地加权历史值），可以减小批间采样噪声。

    推理时偏置已经固定，路由退化成一次普通的 Top-$k$ 选择，不需要任何分位数计算。

    7. 适用条件与边界

    QB 的推导前提是目标负载 $q = mk/n$ 为整数，且 margins 没有恰好相等的并列——假设无并列，才会有恰好 $q$ 个 margin 落在阈值之上；实践中并列的概率为零。它只调偏置、不改变每个 token 选 $k$ 个这个稀疏性；负载靠调这里的偏置来拉平，不在损失（训练时要最小化的那个量）上另加一项（这种加在损失上、用来约束参数的一项叫正则），所以把它当成一种损失或正则是误解。另外一个误解是把「一步就均衡」推广成总是几步收敛：手算里一步到位是因为那张分数表恰好落在均衡解上，专家规模接近 $10^3$ 时仍能在几步内收敛。这个对偶视角的分配问题都假定每个专家恰好服务 $q$ 个 token。
