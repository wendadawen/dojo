# Quantile Balancing 教学大纲

## 1. 页面开头

**钩子问题**：896 个专家，每个 token 只用 16 个——如果总有一部分专家被冷落、另一部分被挤爆，训练会怎样？更关键的是：怎么把负载调平，还不干扰模型本身在学的东西？

**一句话解释**：Quantile Balancing（QB）是 K3 的 MoE 负载均衡方法，从一次前向传播的路由分数分位数直接算出每个专家的 bias，替代 DeepSeek-V3 的固定步长更新。

**学习承诺**（读完你能回答）：见 learning-goals 组件，5 个问题对应 Q1–Q5。

**首个场景**：8 个 token 分配给 4 个专家、每个 token 选 1 个专家——初始路由给出负载 (4,3,1,0)，QB 一步把它变成 (2,2,2,2)。这个手算例子贯穿全文。

**过渡到第一章**：在算这个例子之前，先理解为什么需要 bias、bias 在路由中做什么。

## 2. 章节设计

### S1：auxiliary-loss-free 路由——bias 做什么、不做什么

- **教学问题**：bias 在路由中起什么作用？为什么说"auxiliary-loss-free"？
- **对应范围**：C1, F1；Q1, Q2
- **正文要点**：
  - MoE 路由基本回顾（引用 wiki/moe-serving）：router 打分 s = σ(W_r x_i)，选 Top-k
  - auxiliary-loss-free 的核心设计（C1, F1）：Top-k 选 (s+b)，权重 p 只用 s 归一化
  - bias 只影响"选谁"，不进 mixture weight 和梯度——这是"free"的含义
  - 引用前置概念 auxiliary-loss-free routing（占位，未生成）
- **前置知识安排**：引用 wiki/moe-serving 的 MoE 路由基本概念
- **完成检查**：bias 加到分数上选 Top-k 后，如果两个 expert 的 bias 同时加 0.1，Top-k 选择会变吗？归一化权重 p 会变吗？
- **过渡**：bias 能调负载，但 bias 本身怎么更新？下一章看 DeepSeek-V3 的做法和它的瓶颈。

### S2：DeepSeek-V3 的固定步长更新——为什么 896 专家时失效

- **教学问题**：DeepSeek-V3 怎么更新 bias？为什么大规模专家时力不从心？
- **对应范围**：C2, C3, F2；Q1
- **正文要点**：
  - sign 更新公式 F2：b ← b + γ·sign(ℓ̄ − ℓ_j)
  - 逐符号解释：ℓ̄ 是平均负载，ℓ_j 是专家 j 负载，γ 是固定步长
  - γ 的两难：大 γ→震荡，小 γ→慢适应（C3）
  - sign 只保留方向不保留幅度（C3）——896 专家时收敛慢、震荡
  - 不均衡的后果：EP 训练变慢、部分专家训练不足
  - K3 的 896 专家 / top-16 配置（N1, C17）
- **讲解材料**：sign 更新公式（F2）展示方向信息丢失；数字例子（sign(3−2)=sign(1)=+1 与 sign(100−2)=sign(98)=+1 相同方向不同幅度）
- **完成检查**：γ=0.001 时 expert 负载从 100 到目标 50，需要多少步 sign 更新才能到 50 附近？sign(50−100)=sign(−50)=−1，每步减 0.001，约 50000 步——这说明什么？
- **过渡**：sign 更新只走固定小步，QB 的思路是：能不能从当前分数分布直接算出"正确的 bias 应该是多少"？

### S3：QB 的核心机制——从一次前向推导下一个 bias

- **教学问题**：QB 怎么从一次前向传播算出每个专家的 bias？公式每一步在做什么？
- **对应范围**：C4, C5, C6, C7, C8, F3；Q2
- **正文要点**：
  - 整体流程图示（ASCII）：前向→Top-(k+1)→cutoff α_i→margins→分位数→b̃→mean-center→b
  - 步骤 1：Top-(k+1) 路由得 cutoff α_i（C4）——第 (k+1) 个就是"要进 Top-k 必须超过的线"
  - 步骤 2：margins = s_{i,j} − α_i（C5）——raw score 减 cutoff，旧 bias 只通过 α 进入
  - 步骤 3：b̃_j = −quantile_{1−k/n}(margins_{:,j})（C6, F3）——为什么是 (1−k/n) 分位数
  - 关键推导：设 −b̃_j 为阈值，超过它的 margin 数 = 被路由到 j 的 token 数 = q = mk/n；q/m = k/n，所以阈值是 (1−k/n) 分位数
  - 步骤 4：mean-centering（C7）——去掉公共偏移，Top-k 不变
  - 因果性（C8）：更新在下一步生效
- **讲解材料**：
  - ASCII 流程图展示整体流程
  - 公式 F3 逐步拆解
  - 关键推导放折叠块（从"超过阈值的 margin 数 = q"到"(1−k/n) 分位数"）
- **前置知识**：分位数的最小定义（一组数中指定比例以下的阈值，如 0.75 分位数 = 75% 的数不超过它）
- **完成检查**：m=8, n=4, k=1 时 q=？(1−k/n)=？分位数取第几个最大值？mean-centering 后 b 的和是多少？
- **过渡**：公式讲清了，现在用手算例子验证每一步。

### S4：手算 m=8, n=4, k=1 的 QB 例子

- **教学问题**：给定具体分数，能不能从头到尾手算一遍 QB？
- **对应范围**：C10；Q3
- **正文要点**：
  - 教学示例标记：8×4 分数矩阵（1 位小数），初始 b=0
  - 步骤 1：Top-1 路由得 loads (4,3,1,0)，Top-2 得 cutoff α_i
  - 步骤 2：计算 8×4 margins 矩阵
  - 步骤 3：每个专家找 3rd largest margin（即 0.75 分位数）
    - E1: 3rd largest = 0.2 → b̃₁ = −0.2
    - E2: 3rd largest = 0.1 → b̃₂ = −0.1
    - E3: 3rd largest = 0.0 → b̃₃ = 0.0
    - E4: 3rd largest = −0.1 → b̃₄ = 0.1
  - 步骤 4：mean = −0.05，b = (−0.15, −0.05, 0.05, 0.15)
  - 步骤 5：验证新路由 → (2,2,2,2) ✓
  - 对照表：初始路由 vs QB 后路由，标出哪些 token 改变了
- **讲解材料**：

  - 每专家 margin 排序表格
  - 对照表格（初始 vs QB 后路由）
  - 可运行代码折叠块：验证手算结果
- **完成检查**：如果 T1 的 E3 分数从 0.8 改成 0.75，cutoff α₁ 变不变？margin 变不变？b̃₃ 变不变？
- **过渡**：手算验证了机制，但 QB 为什么比 sign 更新好？下一章从对偶理论解释。

### S5：QB 为什么好——从平衡分配到对偶的视角

- **教学问题**：QB 和 sign 更新本质上是什么关系？为什么 QB 不需要 γ？
- **对应范围**：C11, C12, C13, F4, F5, F6；Q4
- **正文要点**：
  - 平衡分配问题（C12, F4）：最大化总分数，约束每个 token 选 k、每个专家服务 q 个
  - 线性松弛→对偶→交替求解器（C13）
  - 交替求解器每步都是 (1−k/n) 分位数（F5）
  - sign 更新是对偶目标的 SignSGD（C11, F6）：(sub)gradient = 目标负载 − 实际负载
  - QB = 精确 coordinate minimizer，sign = 只保留方向的 SignSGD
  - 这解释了：QB 无需 γ、几步收敛（C11）
- **讲解材料**：
  - 对偶目标公式 F4
  - (sub)gradient 公式 F6
  - 对照表格：sign vs QB（求解策略、超参数、收敛速度）
  - 推导折叠块：从对偶目标到 coordinate minimizer 的关键步骤
- **完成检查**：F6 的 subgradient 在负载恰好均衡时等于 0，说明什么？sign 更新在均衡时 sign(0)=0 也不更新，两者在均衡点行为一致——区别在非均衡时怎么走？
- **过渡**：理论讲清了，但 m 是百万级、分布在多卡上——怎么实际算分位数？下一章看直方图估计。

### S6：训练时的直方图估计与推理冻结

- **教学问题**：百万级 margins 怎么算分位数？推理时还需要吗？
- **对应范围**：C9, C14, C15, C16, F7, N2, N3；Q5
- **正文要点**：
  - 问题：O(mn) margins 无法在训练循环内全量收集（C14 引出）
  - 直方图估计：每专家维护 B 个 bin 的 counts
  - 分箱范围 [b_min−1, b_max+1]（C15）——为什么有界
  - 前向时各 rank scatter-add 本地 counts，无通信；step 结束一次 all-reduce 汇总（C14）
  - 从 pooled counts 恢复分位数：找第一个累计 count ≥ ⌈q⌉ 的 bin，bin 内线性插值（F7）
  - 误差 ≤ bin width w，B=1000 时误差几个 10⁻³，观测不到残余不均衡（N2, C15）
  - counts 可加 → 全局直方图精确代表 pooled batch（C16）
  - 通信成本 nB 整数/layer/step，与 m 无关，<1% raw margins 交换成本（N3）
  - 推理：bias 冻结，纯 Top-k 选择，无分位数计算（C9）
  - EMA 平滑减少批次间噪声（C14 末尾）
- **讲解材料**：
  - 伪代码折叠块：直方图估计的 scatter-add → all-reduce → 恢复分位数
  - 直方图分位数恢复公式 F7
  - 对照表格：训练 vs 推理的 bias 状态
- **完成检查**：如果 B=10 而非 1000，分位数误差上限变大还是变小？为什么 all-reduce 的是 counts 而不是 margins 本身？
