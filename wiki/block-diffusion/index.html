    块扩散语言模型（Block Diffusion）：块间从左到右、块内并行去噪的生成范式

    主要依据：Arriola et al., "Block Diffusion: Interpolating between Autoregressive and Diffusion Language Models", ICLR 2025（arXiv:2503.09573）；DFlash 论文（arXiv:2602.06036v2, ICML 2026）中对块扩散草稿用法的描述。来源编号见文末来源与范围说明。

    一个语言模型要生成 8 个 token。自回归模型从左到右逐个写，共 8 次串行前向——每跑一次完整的网络，只为多得到一个 token。想一次前向同时写出 8 个 token？各位置互相看不见对方写了什么，相邻两个位置很容易各猜各的、凑不成一句话。块扩散（block diffusion）给出的折中是：把「从左到右」的顺序从 token 级放宽到块级——切成 2 个块、每块 4 个 token，块与块之间仍然从左到右，块内 4 个位置一次并行写出。

    块扩散语言模型（block diffusion language model）就是这样一类生成范式：序列被切成若干块，块间做自回归，块内做扩散去噪。它从自回归一侧保住了生成顺序、KV cache 和任意长度生成，又从扩散一侧拿到块内并行性。本文讲清它的结构与采样过程：注意力掩码怎么设计、缓存怎么工作、块内怎么从全遮住一步步去噪，以及它被 DFlash 用作投机解码草稿器时的单步简化形态。

    本文的学习基础是三个已讲解的概念：自回归解码的逐 token 因果结构见因果掩码；注意力中 K/V 投影的含义见标准 Transformer 注意力；草稿—验证循环见投机解码。块扩散本身不依赖这三个概念的推导细节，只需要其结论。

    核心问题

    1. 块扩散怎么在自回归和扩散之间折中——「块间自回归、块内并行去噪」各是什么意思？

      解答：串行次数从 token 数降到块数，块内一次并行处理

      自回归把似然分解到每个 token，$L$ 个 token 要 $L$ 次串行前向；掩码扩散把全部位置一起并行预测，但需要多轮精化且生成长度固定。块扩散取中间：$\log p_\theta(x)=\sum_{b=1}^{B}\log p_\theta(x^b\mid x^{<b})$，串行步从 $L$ 次降到 $B=L/L'$ 次，每步内部块内 $L'$ 个位置并行处理。块大小 $L'=1$ 退化为自回归，$L'=L$ 退化为全并行扩散。完整论证见「1. 块间自回归、块内并行——两个范式各让一步」。

    2. block-causal 注意力掩码长什么样，为什么一张掩码能同时做块间条件和块内双向交互？

      解答：块 $b$ 可见块 $1..b$，跨块因果、块内双向

      掩码规则只有一条：块 $b$ 的 token 可以看到块 $1$ 到块 $b$ 的所有 token。跨块方向是因果的（后面的块看前面的块，反之不可见），块内是双向的（同块所有位置互看）。单一 transformer 用这一张掩码，训练时就能在一次前向里并行计算所有块各自的去噪损失。图示与完整论证见「2. block-causal 注意力掩码——一张掩码管两件事」。

    3. KV cache 在块扩散里怎么工作，为什么全并行扩散语言模型做不到？

      解答：K/V 是每块的输出，生成下一块时直接复用

      块扩散模型的签名是 $x^b_{\text{logits}},\mathbf{K}^b,\mathbf{V}^b\gets x^b_\theta(x^b_t,\mathbf{K}^{1:b-1},\mathbf{V}^{1:b-1})$：模型对每块同时输出预测分数和该块的 K/V，生成第 $b+1$ 块时直接复用 $\mathbf{K}^{1:b}$，不重算历史。全并行扩散每轮去噪要基于整句当前状态重新计算所有位置，没有稳定增长的「已定」前缀可缓存，且生成长度固定。见「3. KV cache 与灵活长度——从扩散侧保住的东西」。

    4. 块内采样怎么做——从全 mask 到整块 token，去噪轮数起什么作用？

      解答：逐轮揭开、已揭开不遮回；轮数是质量与延迟的旋钮

      每块从全 mask 初始化；每轮去噪，模型并行给出所有仍被遮住位置的预测，按置信度揭开一部分（已揭开的不再遮回），重复直到整块揭开，然后更新缓存进入下一块。轮数多则后面的位置能看到前面已揭开的 token，质量好但串行前向多；轮数取 1 就是纯并行预测，互相看不到对方揭开的 token（彼此只见到 $[\mathrm{MASK}]$）。见「4. 块内去噪——从全 mask 到整块 token」。

    5. 块扩散为什么适合当投机解码的草稿器——DFlash 把它简化成什么？

      解答：草稿器只求快和可验证，单步并行的块内不完美由验证兜底

      草稿模型猜错的 token 会被目标模型在验证时拒绝，代价只是一次验证开销，所以草稿器不要求单块完美。DFlash 取去噪轮数 $=1$ 的极端：块内一次前向并行预测整块（块大小 16，Qwen3；或 10，LLaMA-3.1），配合目标模型特征做条件；起草成本不随 token 数线性增长。见「5. 当草稿器用——块扩散在 DFlash 里的形态」。

    1. 块间自回归、块内并行——两个范式各让一步

    先把两个端点放清楚。自回归（AR）模型把序列似然分解为每个 token 的条件概率之积[F1]：

    $$\log p_\theta(x)=\sum_{\ell=1}^{L}\log p_\theta\!\left(x^{\ell}\mid x^{<\ell}\right).$$
    • $x$：长度为 $L$ 的 token 序列；$x^{\ell}$ 是第 $\ell$ 个 token。
    • $x^{<\ell}$：第 $\ell$ 个位置之前的全部 token。
    • 求和跑遍 $L$ 个位置——每生成一个 token 都要等前面的全部写完。

    这个分解让训练高效（下一 token 预测），但生成本质串行：$L$ 个 token 要 $L$ 次前向，一步接一步[C1]。

    另一端是掩码扩散（masked diffusion）语言模型。本文只需要它的最小含义：把要生成的位置全部替换成掩码 token $[\mathrm{MASK}]$，模型一次前向并行给出所有被遮位置的预测；由于各位置互相看不到彼此的预测，通常要迭代多轮——每轮揭开一部分、剩余位置基于新状态重新预测——才能收敛到连贯的句子。它的代价有两个：整句一起处理导致生成长度必须预先固定；每一轮去噪都要对全部位置重新计算，没有可以跨轮复用的「已定」部分[C11]。

    块扩散在两者之间落位：序列切成 $B$ 个长度为 $L'$ 的块（$B=L/L'$），似然按块分解[F2]：

    $$\log p_\theta(x)=\sum_{b=1}^{B}\log p_\theta\!\left(x^{b}\mid x^{<b}\right),$$
    • $x^{b}$：第 $b$ 个块，含 $L'$ 个连续 token。
    • $x^{<b}$：第 $b$ 块之前的全部 token。
    • 每个块内因子 $p_\theta(x^{b}\mid x^{<b})$ 由掩码扩散建模：块内 $L'$ 个位置并行去噪[C1]。

    串行链的粒度从 token 变成了块：外层是 $B$ 步的自回归，每步内部是一次（或多轮）并行去噪。三个范式放在一起：

    自回归全并行掩码扩散块扩散
    似然分解粒度逐 token[F1]整句一起逐块[F2]
    串行前向次数（生成 $L$ 个 token）$L$去噪轮数（与 $L$ 无关的固定长度）$B\times$（每块去噪轮数）
    块内位置能否互看不能（因果）能（双向）能（块内双向）[C2]
    生成长度任意固定[C11]任意（按块扩展）[C4]
    KV cache支持不支持[C11]支持[C3]

    两个极端值得记住。块大小 $L'=1$ 时块扩散退化成自回归——但此时扩散训练目标虽然在期望上等价于自回归似然，梯度方差却很高，训练效率反而差[C6]；块大小 $L'=L$ 时退化成全并行扩散。块大小因此是一个真实的设计变量，不是越大越好（见第 4、5 章的权衡）。

    构造示例（数字为人为构造，便于手算）。生成 8 个 token：

    • 自回归：$8$ 次串行前向，每次为 $1$ 个新位置计算。
    • 块扩散、块大小 $L'=4$（$B=2$ 块）、每块去噪 $2$ 轮：$2\times2=4$ 次串行前向，每次为 $4$ 个位置并行计算。
    • 同样配置、每块 $1$ 轮：$2$ 次串行前向。

    每次前向内，$4$ 个位置的 query/K/V 投影是一次并行矩阵乘，GPU 执行它的效率远高于把 4 个位置拆成 4 次串行的小前向——这正是并行性的收益来源。这个 8 token、2 块的例子会在第 4、5 章继续推进。

    本章问题

    1. 自回归和掩码扩散各自的串行/并行结构是什么？

      解答：自回归逐 token 串行；掩码扩散整句并行但需多轮精化

      自回归按 $\log p_\theta(x)=\sum_{\ell=1}^{L}\log p_\theta(x^{\ell}\mid x^{<\ell})$ 分解[F1]，每个 token 依赖全部前文，$L$ 个 token 需要 $L$ 次串行前向。掩码扩散把全部待生成位置同时遮住、一次前向并行预测，但各位置看不到彼此的输出，需要多轮「揭开一部分、重预测剩余」的迭代才能连贯，且整句处理使长度固定、无跨轮缓存[C11]。

    2. 块分解公式把串行次数降到多少？两个极端退化成什么？

      解答：降到 $B=L/L'$ 次乘以每块轮数；两端退化成 AR 与全并行扩散

      按 $\log p_\theta(x)=\sum_{b=1}^{B}\log p_\theta(x^{b}\mid x^{<b})$ 分解[F2]，串行步从 $L$ 降到 $B$ 步（每步内部一次或多轮并行去噪）。$L'=1$ 时退化为自回归——且此极限下扩散目标期望等价于 AR 似然但梯度方差高[C6]；$L'=L$ 时退化为全并行扩散。以 8 token、块大小 4、每块 1 轮为例：串行前向 $8$ 次降为 $2$ 次（构造示例）。

    2. block-causal 注意力掩码——一张掩码管两件事

    块扩散落到 transformer 上，结构上只改一处：注意力掩码。规则是「块 $b$ 的 token 可以看到块 $1$ 到块 $b$ 的所有 token」[C2]。它同时规定了两件事：

    • 跨块方向是因果的：后面的块可以看到前面的块，前面的块看不到后面的块——这就是因果掩码的块级版本，保证块间自回归的分解顺序。
    • 块内是双向的：同一个块里的所有位置互相可见——这是扩散侧的属性，让块内并行预测的位置互为上下文。

    这张掩码的另一个直接收益在训练侧：同一个 transformer 一次前向就能同时为所有块产出预测——每个块看到的恰是「自己 + 更早的块」，与推理时一致，于是各块的去噪损失可以在同一次前向里并行算出[C2]。训练目标本身是把掩码扩散的变分下界（NELBO）分别应用到每个块上再求和[F4]，本页不推导它，只需要结论：它存在、可微、且可以按块并行计算。

    补充：为什么训练时每个块至少要过两次模型

    想把全部块一次性算完会遇到一个错位：计算第 $b$ 块的去噪损失，需要模型对「带噪的第 $b$ 块」做前向；而第 $b+1$ 块做条件时，需要的是「干净的第 $b$ 块」的前向结果。同一次前向无法既带噪又干净，所以每个块至少要经过模型两次——一次带噪（算自己的损失）、一次干净（为后续块提供条件）[C5]。BD3LM 的做法是把所有块拼成一条序列、用块间禁止注意的稀疏掩码，在尽量少的前向里完成这一计算[C2]。这一限制属于训练效率话题，不影响推理侧的机制理解。

    本章问题

    1. block-causal 掩码的规则是什么，跨块与块内方向分别怎么设？

      解答：块 $b$ 可见块 $1..b$；跨块因果、块内双向

      规则只有一条：块 $b$ 的 token 可以注意块 $1$ 到块 $b$ 的所有 token[C2]。跨块方向上，后面的块能看到前面的块、前面的块看不到后面的块（因果），支撑块间自回归分解；块内所有位置互看（双向），支撑并行去噪。对 8 token、2 块的例子，掩码呈现三个区域：两个 $4\times4$ 的块内全可见区、左下 $4\times8$ 的跨块可见区、右上 $4\times4$ 的全遮挡区（见上图）。

    2. 为什么同一张掩码让训练能一次前向算所有块？

      解答：每个块看到的上下文与推理时一致，各块损失可在同一次前向并行计算

      训练时把所有块放进一条序列，用 block-causal 掩码：块 $b$ 的位置看到的是「自己（带噪）+ 更早的块（干净）」，与推理时第 $b$ 块的条件结构一致，所以各块的去噪损失能在一次前向中同时算出[C2]。限制是每个块至少要过两次模型（一次带噪算损失、一次干净供后续块做条件）[C5]，属于训练效率细节。训练目标 NELBO 按块求和[F4]，本页只引用其可并行计算的结论。

    3. KV cache 与灵活长度——从扩散侧保住的东西

    『2. block-causal 注意力掩码——一张掩码管两件事』的掩码解释了「怎么算」，这一章解释「怎么不重算」。在标准注意力里，注意力计算需要每个位置的 K（键）与 V（值）投影；自回归解码用 KV cache 把已生成前缀的 K/V 存下来，每步只算新位置的投影。块扩散沿用同样的思路，只是缓存的粒度变成块。模型的完整签名是[F3]：

    $$x^b_{\text{logits}},\ \mathbf{K}^b,\ \mathbf{V}^b\ \gets\ x^b_\theta\!\left(x^b_t,\ \mathbf{K}^{1:b-1},\ \mathbf{V}^{1:b-1}\right).$$
    • $x^b_t$：第 $b$ 块的当前（可能部分被遮）内容——输入。
    • $\mathbf{K}^{1:b-1},\mathbf{V}^{1:b-1}$：前面所有块累计的 K/V 缓存——输入，等价于以 $x^{<b}$ 为条件。
    • $x^b_{\text{logits}}$：模型对第 $b$ 块各位置的词表预测分数——输出。
    • $\mathbf{K}^b,\mathbf{V}^b$：模型这次前向为第 $b$ 块算出的 K/V——输出，之后并入缓存供后续块使用[C3]。

    关键在最后一行：K/V 不只是注意力的中间量，被显式定义为模型的输出。生成第 $b+1$ 块时，把 $\mathbf{K}^{1:b}$ 直接拼进注意力的键值序列，历史块的前向不再重算。块间每完成一块，「已定」的前缀就增长一块，缓存随之增长——这与自回归 KV cache 的行为完全同构，只是步长从 1 个 token 变成 $L'$ 个。

    对照之下，全并行扩散语言模型两样都做不到[C4][C11]：

    • 没有稳定前缀：每一轮去噪后整句状态都变了（被揭开的 token 变多），下一轮要基于新状态对所有位置重新计算，上一轮的 K/V 不能复用。
    • 长度固定：序列要在开始前定长，无法「生成到满意为止」，也不能按需延长。

    块扩散按块推进的结构恰好把这两样都找回来：块间是严格自回归的，前缀一旦定下就不再改动（缓存有效）；生成长度按块数增长，想要多长就多生成几个块[C4]。

    本章问题

    1. K/V 怎么作为每块的输出被缓存和复用？

      解答：模型签名把 K/V 列为输出，生成下一块时拼接复用

      签名 $x^b_{\text{logits}},\mathbf{K}^b,\mathbf{V}^b\gets x^b_\theta(x^b_t,\mathbf{K}^{1:b-1},\mathbf{V}^{1:b-1})$[F3]里，$\mathbf{K}^{1:b-1},\mathbf{V}^{1:b-1}$ 是输入（历史缓存），$\mathbf{K}^b,\mathbf{V}^b$ 是本次输出[C3]。第 $b+1$ 块的前向把 $\mathbf{K}^{1:b}$ 拼进键值序列直接使用，不重算历史。行为与自回归 KV cache 同构，缓存步长从 1 个 token 变为 $L'$ 个。

    2. 全并行扩散语言模型为什么做不到这两点？

      解答：每轮整句状态都变，无稳定前缀可缓存；且长度需预先固定

      全并行扩散每轮去噪后，被揭开的 token 增多、整句输入状态改变，下一轮必须对所有位置重新前向，上一轮的 K/V 无法复用——没有稳定增长的「已定」前缀[C11]。同时整句一起处理要求生成长度预先固定[C4]。块扩散因为块间严格自回归，每完成一块前缀即固定、缓存随之增长，长度按块数扩展，两样都保住了[C4]。

    4. 块内去噪——从全 mask 到整块 token

    到这里还差运行时的另一半：一块之内，怎么从「全部遮住」走到「全部揭开」？采样按块推进[C7]，每一块经历同一个循环：

    1. 初始化：块内 $L'$ 个位置全部置为 $[\mathrm{MASK}]$。
    2. 去噪一轮：模型一次前向，并行给出所有仍被遮住位置的预测。
    3. 揭开一部分：按揭开规则把一部分被遮位置揭开（揭开哪些位置由 noise schedule 决定，与预测置信度无关[C8]），已揭开的不再遮回。
    4. 重复 2–3 直到整块揭开，然后把这块的 K/V 并入缓存，进入下一块[C7]。
    代码：块扩散采样的伪代码（简化自 BD3LM 的推理算法） 
    输入：已生成前缀 prefix，块大小 L'，去噪轮数上限 T，模型 x_theta
状态：KV 缓存 K_all, V_all（初始为 prefix 的 K/V）
循环：还有要生成的块时执行
    block ← [MASK] × L'                          # 当前块全遮
    对 t 从 1 到 T 执行
        logits, K_blk, V_blk ← x_theta(block, K_all, V_all)   # 一次前向，并行预测所有被遮位置
        S ← noise_schedule(t) 决定本轮要揭开的 block 位置集合
        对 S 中每个位置 i：block[i] ← argmax(logits[i])
        若 block 已无被遮位置：跳出轮循环
    输出 block 作为新的一段 token
    K_all, V_all ← K_all ⊕ K_blk, V_all ⊕ V_blk     # 并入缓存
输出：全部块的 token 依次拼接

    验证的机制：外层循环逐块推进、内层循环逐轮去噪，对应正文第 1–4 步；「已揭开不遮回」由内层只处理「仍被遮的位置」保证。

    观察重点：每轮去噪的前向次数是 1，与该轮揭开多少位置无关——并行性在这里；串行前向总数等于所有块的轮数之和。

    简化条件：真实实现里每轮揭开多少位置由噪声调度决定（置信度阈值随轮数变化），且训练目标（NELBO）保证模型学到的条件分布支撑这一采样过程；伪代码只保留「按置信度揭开、不遮回、逐块推进」的骨架。

    贯穿示例继续（构造数据）。『1. 块间自回归、块内并行——两个范式各让一步』的 8 token 序列假设前 4 个 token 是 decoding is now parallel，看第 1 块两轮去噪的状态演进：

    阶段位置 1位置 2位置 3位置 4说明
    初始$[\mathrm{MASK}]$$[\mathrm{MASK}]$$[\mathrm{MASK}]$$[\mathrm{MASK}]$块内全遮
    第 1 轮后decoding$[\mathrm{MASK}]$$[\mathrm{MASK}]$$[\mathrm{MASK}]$四位置并行预测，按 noise schedule 揭开位置 1（示意，非按置信度）
    第 2 轮后decodingisnowparallel剩余位置的重新预测已能看到位置 1 的 token，一次全部揭开

    注意第 2 轮的关键差别：位置 2–4 这轮的预测是「看着位置 1 已揭开的 decoding」做出的——块内双向注意力把已揭开的位置变成未揭开位置的上下文。这正是去噪轮数存在的意义：轮数越多，后面的位置能看到越多已确定的内容。轮数是质量与延迟之间的旋钮：每多一轮，多一次串行前向、后段位置的条件更充分；轮数取 1，所有位置在互相看不到对方揭开的 token 的条件下一次写完（彼此只见到 $[\mathrm{MASK}]$）——纯并行预测，也是块内最不连贯的形态。BD3LM 与 SSD-LM（Han et al. 2022 提出的另一种块扩散方法，用高斯嵌入扩散而非离散掩码）的对比中，BD3LM 以不超过序列长度的 NFE 达到 gen PPL $25.7$（vs SSD-LM $T=1$K、$\geq40$K NFE 下的 $37.2$）；NFE 可比时 SSD-LM 用 $T=25$ 步退化到 gen PPL $281.3$[N2]；轮数从几十到上千都是合法取值，取 1 同样合法，只是把连贯性问题留给了使用场景去消化（下一章）。

    补充：揭开规则、first-hitting 与「已揭开不遮回」

    揭开规则由 noise schedule 与 first-hitting 采样器共同决定——BD3LM 附录描述的是 first-hitting：给定 $t$ 时所有被遮 token 的转移概率相同，揭开"哪个 token"由解析采样的随机时间决定，与预测置信度无关。把 token 揭开又遮回去，等价于引入额外反向跳转，需要重新推导才能保证采样分布正确。BD3LM 采用掩码扩散的高效采样器，token 一旦揭开就固定，生成步数（NFE）因此有上界：最坏每轮只揭开一个位置，一块最多 $L'$ 轮[C8]。这是采样器设计的选择，不是扩散模型的内在要求；「不遮回」换来的是轮数可控与缓存安全（已揭开的 token 不会再变）。

    本章问题

    1. 一块的采样循环分几步？每轮揭开哪些位置？

      解答：初始化全遮 → 并行预测 → 按置信度揭开一部分 → 循环至整块揭开

      四步：①块内 $L'$ 个位置全置 $[\mathrm{MASK}]$；②模型一次前向并行预测所有仍被遮的位置；③按置信度揭开一部分（已揭开的不遮回[C8]）；④整块揭开后把该块 K/V 并入缓存进入下一块[C7]。每轮揭开哪些由预测置信度决定——按 noise schedule 决定揭开顺序，后揭的位置能看到先揭的内容（与按预测置信度高低排序无关）。构造示例中第 1 块两轮完成：第 1 轮只揭位置 1，第 2 轮在位置 1 已可见的条件下一次揭开其余三个位置。

    2. 去噪轮数怎么权衡质量与延迟？轮数为 1 意味着什么？

      解答：轮数多则后段条件充分但串行前向多；轮数 1 即纯并行预测

      每轮去噪让后面的位置看到更多已揭开的 token，质量上升；但每轮是一次串行前向，延迟随轮数线性增加。轮数取 1 时所有位置在互相看不到对方揭开的 token 的条件下一次写完（纯并行预测），串行成本最低、块内连贯性最差。BD3LM 自身在 T=5K 步下达到 gen PPL 25.7；SSD-LM 用 $T=1$K 步、$\geq40$K NFE 达到 37.2，NFE 可比（用 $T=25$ 步）时退化到 281.3[N2]；轮数是部署时按「块内连贯要求」调节的旋钮，『5. 当草稿器用——块扩散在 DFlash 里的形态』正是把它拧到 1 的例子。

    5. 当草稿器用——块扩散在 DFlash 里的形态

    块扩散作为独立生成模型有一个坦率的短板：同等规模下似然建模仍逊于自回归模型[C11]。但换个岗位，短板可以不成问题。投机解码里，草稿模型负责猜、目标模型负责验证——猜错的草稿 token 会被验证拒绝，损失只是一次验证开销，输出的分布始终由目标模型保证。也就是说，草稿器的要求是「快」和「可验证」，不要求单块完美。

    这正好对上块扩散的取值空间：把『4. 块内去噪——从全 mask 到整块 token』的旋钮拧到极端——去噪轮数取 1。DFlash 就是这样使用块扩散的：草稿器一次前向并行预测整块所有位置，不做迭代去噪[C9]；块大小 16（Qwen3 系列）/ 10（LLaMA-3.1）[N1]，消融中另含 8；起草延迟对块大小基本不敏感（中等块大小范围内）——一次并行前向的成本远低于同规模模型串行写同样多 token 的成本[C10]。对比自回归草稿器（如 EAGLE 系列的单层草稿网络）[C10]：它们每多猜一个 token 就多一次串行前向，草稿长度被延迟卡死。

    「块间自回归」在草稿器语境里对应物清晰：每个草稿—验证周期结束时，目标模型产出的那个 token（接受全部草稿时的 bonus token，或拒绝处的修正 token）成为下一轮草稿的条件锚点——正对应训练时「以干净 token 为块首」的构块方式[C9]。

    贯穿示例收尾（构造数据）。8 token 的目标，块大小 4，两个周期：

    • 周期一：草稿器以已验证 token 为锚，一次前向写出 4 个位置；目标模型验证——前 3 个接受，第 4 个被拒，目标模型在该位置重采样补上。产出 $3+1=4$ 个 token。
    • 周期二：以周期一末尾的目标 token 为锚再写 4 个；验证接受 3 个、修正 1 个。产出 4 个 token。
    • 合计：8 个 token，草稿前向 2 次、验证前向 2 次——串行步共 4 步，对比自回归的 8 步（构造示例，用于演示周期结算；真实接受率由模型质量决定）。

    单步并行预测的代价是块内不连贯——进一步修复（保留并行、不放弃 one-pass 设计）见DFlash 2；DFlash 完整的推理管线（目标模型特征如何注入草稿器）与训练方法见DFlash 论文解析。

    本章问题

    1. 草稿器的需求为什么允许块内不完美？

      解答：错误草稿被验证拒绝，代价只是一次验证开销，输出由目标模型保证

      投机解码的验证步骤用目标模型一次前向核对整块草稿：接受匹配的前缀、在首个不匹配处按目标模型分布修正（见投机解码）。草稿猜错的后果不是错误输出，而是该轮少接受几个 token——损失的只是已经付出的那次验证计算。因此草稿器可以牺牲单块完美换取速度；块扩散似然逊于自回归的短板[C11]在这个岗位上不构成问题。

    2. DFlash 把块扩散简化成什么？起草成本怎么随块大小变化？

      解答：轮数取 1 的一次前向并行预测；中等块大小下起草延迟对块大小基本不敏感

      DFlash 取去噪轮数 $=1$：块内所有被遮位置一次前向并行预测，不做迭代去噪[C9]，块大小取 8–16[N1]。起草成本是一次并行前向 $t_{\text{parallel}}$，远低于同规模模型串行写 $\gamma$ 个 token 的 $\gamma\cdot t_{\text{step}}$，且在中等块大小范围内对块大小基本不敏感[C10]——多猜 token 不再线性增加串行延迟，这是它相对自回归草稿器（如 EAGLE 的单层草稿网络）的结构优势。块内连贯性缺口由验证兜底；进一步处理见DFlash 2。
