    Stable LatentMoE：把路由专家放进隐空间，再用三件稳定化修复极端稀疏

    主要依据：Kimi K3 技术报告 §2.3-2.3.3（Eq. 11-14）与官方 config.json（Hugging Face moonshotai/Kimi-K3）；DeepSeekMoE 论文（arXiv:2401.06066）§3.2。

    若要把一个 MoE 层的专家池扩到 896、每 token 激活扩到 16，会发生什么？直觉上"专家多了、每个 token 走的路径多了"应该更好。但在 2.8 万亿参数规模下，K3 团队发现这条路上有两个具体的失败点——路由分支内部激活爆炸，以及近千专家的负载失衡——必须用三件稳定化才能让这个扩大后的稀疏层真正跑起来[C3, N4, N6]。本页只讲 Stable LatentMoE 的层结构与三件稳定化的插入位置；MoE 基础、SiTU-GLU、Quantile Balancing 等独立概念只引用结论，完整推导见对应概念页。本文说明这套结构如何构造、为何如此设计。

    核心问题

    1. 为什么 LatentMoE 要把路由专家放进比全模型宽度更窄的隐空间？这解决了什么问题，代价是什么？

      解答：分离两个宽度，收益与代价

      LatentMoE 分离全模型宽度 $d$ 与路由专家宽度 $\ell$：共享专家保留全宽 $d$ 的路径处理通用变换，路由专家经下投影 $W_\downarrow$ 在更窄的隐空间 $\ell$（$\ell < d$）操作，再经上投影 $W_\uparrow$ 投回。解决的问题是扩大专家池时通信与权重流量随路由倍数线性增长；代价是路由分支多出两次投影，形成更长的矩阵乘法链，成为激活爆炸的根源之一。完整论证见「1. 扩大专家池的代价」。

    2. Stable LatentMoE 的层结构是什么？共享分支、路由分支、$W_\downarrow$、$W_\uparrow$、RMSNorm 各自的位置和职责是什么？

      解答：两支相加，Eq. 11 数据流

      层输出由两支相加得到：$y = \sum_{j=1}^{N_s} E_j^{\text{shared}}(x) + W_\uparrow\,\mathrm{RMSNorm}(u)$，其中 $u = \sum_{i \in T_k(x)} p_i E_i^{\text{routed}}(W_\downarrow x)$（Eq. 11）。共享分支全宽、无路由、不经 RMSNorm；路由分支先经 $W_\downarrow$ 压入隐空间，Top-k 个路由专家按 $p_i$ 加权聚合，聚合结果先 RMSNorm 归一再经 $W_\uparrow$ 投回。结构细节见「2. Stable LatentMoE 的层结构」。

    3. 极端稀疏下的两个失败模式是什么？三件稳定化分别修复哪一个？

      解答：激活爆炸与负载失衡，各管一段

      失败模式一是路由分支近四个连续矩阵乘法链上的激活爆炸；失败模式二是近千专家的负载失衡。Normalized LatentMoE 管 $u$ 的尺度、SiTU-GLU 管路由 FFN 内部的激活上界，二者协同修复激活爆炸；Quantile Balancing 修复负载失衡。见「3. 极端稀疏下的两个失败模式」与「4. 三件稳定化」。

    4. RMSNorm 插在路由聚合之后、上投影之前，为什么这个位置是必要的？

      解答：只有此处能抹尺度、保信息

      $u$ 的尺度随选中专家集合 $T_k(x)$ 与路由权重 $p_i$ 逐 token 漂移，不归一化会把尺度抖动透传到 $W_\uparrow$ 的输出。放在 $W_\downarrow$ 之前、$W_\uparrow$ 之后或专家内部，会分别破坏共享分支的输入、抹掉路由权重传递的相对大小信息、或无法解决聚合后的尺度漂移。完整论证见「5. 为什么 RMSNorm 必须插在路由聚合之后」。

    5. Stable LatentMoE 的适用边界是什么？它依赖哪些独立概念，不能单独推出什么结论？

      解答：结论限于 K3 规模与配置

      结论在 K3 的规模与配置下成立（$N=896$、$k=16$、$\ell=3584$、$d=7168$、2.8 万亿参数、bfloat16 训练），依赖 MoE 基础、SiTU-GLU、Quantile Balancing、DeepSeekMoE、RMSNorm 等独立概念。不能推出任何 MoE 都该用 LatentMoE、SiTU-GLU 一定优于 SwiGLU、QB 一定优于辅助损失等结论。见「6. 适用边界与不能推出的结论」。

    1. 扩大专家池的代价——为什么需要 LatentMoE

    普通 MoE 层里，每个被选中的路由专家都直接接收完整的 $d$ 维 token 表示 $x$，并在 $d$ 维空间里做 FFN 变换（详见MoE 基础）。这意味着扩大路由倍数——更多专家、更多每 token 激活——会让路由通信与专家权重流量随路由倍数线性增长：每多一个被选中的专家，就要把 $d$ 维向量送过去、把 $d$ 维变换后的向量取回来。[C1]

    LatentMoE 的对策是分离全模型宽度与路由专家宽度：共享专家保留全宽 $d$ 的路径处理通用变换；路由专家则在一个比 $d$ 更窄的隐空间 $\ell$ 里操作[C2]。具体做法是在路由分支两端各加一次投影——下投影 $W_\downarrow$ 把 $x \in \mathbb{R}^d$ 压到 $z = W_\downarrow x \in \mathbb{R}^\ell$，路由专家在 $\ell$ 维空间里处理 $z$，上投影 $W_\uparrow$ 把结果投回 $\mathbb{R}^d$。

    $$z = W_\downarrow x, \qquad W_\downarrow \in \mathbb{R}^{\ell \times d}, \quad z \in \mathbb{R}^\ell.$$

    这里的 $W_\downarrow$ 是下投影矩阵，把 $d$ 维输入压到 $\ell$ 维；$z$ 是隐空间表示。代价是路由分支多出 $W_\downarrow$ 与 $W_\uparrow$ 两次投影，形成更长的矩阵乘法链——这一点在极端稀疏下的两个失败模式一章会看到它是激活爆炸的根源[C3]。但收益是：路由专家内部的 FFN 只在 $\ell$ 维空间操作，扩大路由专家数不再让每个被选中的专家都背一份全宽流量。

    对比项普通 MoE（全宽路由）LatentMoE（隐空间路由）
    路由专家的输入空间$\mathbb{R}^d$（全宽）$\mathbb{R}^\ell$（紧凑隐空间，$\ell < d$）
    扩大专家池的代价通信与权重流量随路由倍数线性增长路由专家 FFN 在 $\ell$ 维操作，扩大池子不再线性增加全宽流量
    额外开销无路由分支多出 $W_\downarrow$、$W_\uparrow$ 两次投影
    共享专家路径通常也是全宽保留全宽 $d$，不走隐空间

    本章说明了 LatentMoE 分离两个宽度的动机与代价。但层结构的完整数据流——$W_\downarrow$、$W_\uparrow$、共享专家、路由专家、RMSNorm 各在什么位置——尚未摆清，下一章讲 Stable LatentMoE 层的完整结构。

    本章问题

    1. 用一句话说明 LatentMoE 分离了哪两个宽度。

      解答：全模型宽度与路由专家宽度

      LatentMoE 分离全模型宽度 $d$ 与路由专家宽度 $\ell$：共享专家保留全宽 $d$ 的路径处理通用变换，路由专家经 $W_\downarrow$ 压入更窄的隐空间 $\ell$（$\ell < d$）操作、经 $W_\uparrow$ 投回。扩大路由专家池因此不再让每个被选中的专家承担全宽流量。

    2. LatentMoE 路由分支多出哪两次投影？各自的方向是什么（$d \to \ell$ 还是 $\ell \to d$）？

      解答：下投影与上投影

      下投影 $W_\downarrow \in \mathbb{R}^{\ell \times d}$ 把输入从 $d$ 维压到 $\ell$ 维（$d \to \ell$）；上投影 $W_\uparrow \in \mathbb{R}^{d \times \ell}$ 把路由结果投回 $d$ 维（$\ell \to d$）。代价是路由分支形成更长的矩阵乘法链，是极端稀疏下激活爆炸的根源之一。

    3. 共享专家走全宽还是隐空间？

      解答：共享专家走全宽

      共享专家走全宽：直接接收 $x \in \mathbb{R}^d$、输出 $\mathbb{R}^d$，不经过 $W_\downarrow$ 与 $W_\uparrow$；只有路由分支走隐空间。

    2. Stable LatentMoE 的层结构——共享分支、路由分支与 RMSNorm 的位置

    K3 的 Stable LatentMoE 层沿用 DeepSeekMoE 提出的"共享专家 + 路由专家"组织：共享专家无路由、所有 token 必经，承担通用变换；路由专家参与 Top-k 选择，承担差异化变换（DeepSeekMoE 论文 §3.2；完整机制见DeepSeekMoE）[C7]。K3 每层固定 $N_s = 2$ 个全宽共享专家[C8]。

    对输入 $x \in \mathbb{R}^d$，Stable LatentMoE 层的输出 $y \in \mathbb{R}^d$ 由两支相加得到（K3 报告 Eq. 11）[F1]：

    $$u = \sum_{i \in T_k(x)} p_i \, E_i^{\text{routed}}(W_\downarrow x), \qquad y = \sum_{j=1}^{N_s} E_j^{\text{shared}}(x) + W_\uparrow \, \mathrm{RMSNorm}(u).$$

    每个符号的含义：

    • $x \in \mathbb{R}^d$：层输入，$d$ 是全模型宽度。
    • $W_\downarrow \in \mathbb{R}^{\ell \times d}$：下投影，把 $x$ 压到隐空间 $\mathbb{R}^\ell$。
    • $E_i^{\text{routed}}: \mathbb{R}^\ell \to \mathbb{R}^\ell$：第 $i$ 个路由专家的 FFN，输入输出都在隐空间。
    • $T_k(x)$：对 token $x$ 选中的 Top-k 路由专家下标集合。
    • $p_i$：路由权重，由路由器给出，对 $T_k(x)$ 内的 $i$ 非零。
    • $u \in \mathbb{R}^\ell$：路由专家的加权聚合。
    • $\mathrm{RMSNorm}$：按均方根归一化（本文只需"按均方根归一化"这一基本作用）。
    • $W_\uparrow \in \mathbb{R}^{d \times \ell}$：上投影，把归一化后的 $u$ 投回 $\mathbb{R}^d$。
    • $E_j^{\text{shared}}: \mathbb{R}^d \to \mathbb{R}^d$：第 $j$ 个共享专家的 FFN，输入输出都在全宽 $d$。
    • $N_s$：共享专家数，K3 取 $N_s = 2$。

    用 K3 的实际配置把抽象符号填满（来自 config.json）[N1, N2, N3, N4, N8]：

    本章问题

    1. 画出 Eq. 11 的数据流，标出 RMSNorm 的位置。

      解答：共享支与路由支相加

      输入 $x$ 分两支。共享支：$E_1^{\text{shared}}(x) + E_2^{\text{shared}}(x)$，全宽、无路由。路由支：$x$ 经 $W_\downarrow$ 得 $z$，分发给 Top-k 选中的路由专家，按 $p_i$ 加权聚合得 $u$，先 RMSNorm 归一、再经 $W_\uparrow$ 投回。两支相加得 $y$。RMSNorm 插在路由聚合 $u$ 之后、上投影 $W_\uparrow$ 之前。

    2. $W_\uparrow$ 作用于 RMSNorm 的输出还是 $u$ 本身？共享专家的输入空间是 $d$ 还是 $\ell$？

      解答：作用于归一化结果；共享专家输入为全宽

      $W_\uparrow$ 作用于 $\mathrm{RMSNorm}(u)$，不是 $u$ 本身——这是 K3 相对原始 LatentMoE 的核心改造（Normalized LatentMoE）。共享专家的输入空间是全宽 $d$：直接接收 $x \in \mathbb{R}^d$，不经隐空间。

    3. 用 K3 的数字回答：每 token 实际经过几个专家（共享 + 路由）？

      解答：16 个路由专家加 2 个共享专家

      每 token 经过 $k = 16$ 个路由专家加 $N_s = 2$ 个共享专家，共 18 个。896 是路由专家池的总数，每 token 只激活其中 16 个；稀疏度 56 是 $N/k$，不是每 token 走的专家数。

    3. 极端稀疏下的两个失败模式——激活爆炸与负载失衡

    LatentMoE 让扩大专家池变得可负担，但 K3 在 $N=896, k=16$（稀疏度 56）、2.8 万亿参数规模下发现两个具体的失败点[C3, N4, N5, N6]。

    3.1 失败模式一——路由分支激活爆炸

    路由分支的结构是 $W_\downarrow \to$ 门控多分支路由 FFN $\to W_\uparrow$，这是近四个连续矩阵乘法的链——$W_\downarrow$ 一次、路由 FFN 内部门支与值支各一次、$W_\uparrow$ 一次。这条链的条件数本来就差（连续投影会放大数值扰动），再叠加 2.8 万亿参数的规模，路由分支内部就会出现激活异常增大，威胁训练稳定性[C3, N6]。

    3.2 失败模式二——近千专家负载失衡

    K3 用的是无辅助损失路由（auxiliary-loss-free，DeepSeek-V3 引入[C12]）：在每个专家的路由分数上加一个 bias $b_j$ 用于 Top-k 选择，但 bias 不进入 mixture 权重。原方法用固定步长规则 $b_j^{(t+1)} = b_j^{(t)} + \gamma \cdot \mathrm{sign}(\bar{\ell} - \ell_j)$ 更新 bias——步长 $\gamma$ 太小则适应慢，太大则负载振荡。这套规则在专家数较少时够用，但平衡近 $10^3$ 个专家的负载已经超出它的适用范围：部分专家被过度使用、部分专家几乎不被使用（"dying expert"），拖慢专家并行训练并让部分专家训练不足[C12]。

    两个失败模式的总览：

    失败模式发生位置原因症状修复方法（三件稳定化一章展开）
    激活爆炸路由分支的矩阵乘法链连续 4 次矩阵乘法 + 2.8T 规模内部激活异常增大Normalized LatentMoE + SiTU-GLU
    负载失衡路由器的 bias 更新固定步长规则在近千专家下失效部分专家过热、部分 dyingQuantile Balancing

    本章明确了两个失败模式的发生位置与原因。但三件稳定化分别修复哪个失败、怎么修复——Normalized LatentMoE 插在哪里、SiTU-GLU 如何限幅、QB 如何设 bias——尚未展开，下一章讲三件稳定化的机制。

    本章问题

    1. 激活爆炸发生在路由分支的哪一段（哪几次矩阵乘法）？

      解答：近四个连续矩阵乘法的链

      发生在路由分支近四个连续矩阵乘法的链上：$W_\downarrow$ 一次、路由 FFN 内部门支与值支各一次、$W_\uparrow$ 一次。连续投影条件数差、会放大数值扰动，叠加 2.8 万亿参数的规模，路由分支内部出现激活异常增大，威胁训练稳定性。

    2. 负载失衡为什么随专家数增大而恶化？原 bias 更新规则的步长 $\gamma$ 面临什么两难？

      解答：固定步长规则在近千专家下失效

      原无辅助损失路由用固定步长规则 $b_j^{(t+1)} = b_j^{(t)} + \gamma \cdot \mathrm{sign}(\bar{\ell} - \ell_j)$ 更新 bias：步长 $\gamma$ 太小则适应慢，太大则负载振荡。专家数较少时够用；平衡近 $10^3$ 个专家的负载已超出该规则的适用范围，出现部分专家被过度使用、部分几乎不被使用（dying expert）。

    4. 三件稳定化——Normalized LatentMoE、SiTU-GLU、Quantile Balancing

    Stable LatentMoE 的"Stable"由三件稳定化承担，分别修复极端稀疏下的两个失败模式。

    4.1 Normalized LatentMoE——在路由聚合后插 RMSNorm

    原始 LatentMoE 直接把 $W_\uparrow$ 作用于聚合表示 $u$。但 $u$ 的尺度会随选中专家集合 $T_k(x)$ 与路由权重 $p_i$ 变化——不同 token 选不同专家、不同权重，$u$ 的尺度逐 token 漂移。K3 在 $u$ 与 $W_\uparrow$ 之间插入 RMSNorm，把 $u$ 归一化到稳定尺度后再交给 $W_\uparrow$，降低路由分支对尺度变化的敏感度[C9]。这是 Eq. 11 中 $W_\uparrow \, \mathrm{RMSNorm}(u)$ 这一项的来源，修复激活爆炸中"尺度放大"的部分。为什么 RMSNorm 必须插在路由聚合之后一章会单独论证这个位置的必要性。

    4.2 SiTU-GLU——给路由专家 FFN 一个有界激活

    路由专家 FFN 内部用 SiTU-GLU 作为激活函数（K3 报告 Eq. 12；完整机制见SiTU-GLU）[F3, C11]：

    $$\mathrm{SiTU\text{-}GLU}(x) = \beta_1 \tanh\!\left(\frac{W_g x}{\beta_1}\right) \odot \mathrm{Sigmoid}(W_g x) \odot \beta_2 \tanh\!\left(\frac{W_u x}{\beta_2}\right).$$

    这里只需要知道一个结论：两个线性因子都被 $\tanh$ 的 softcap 限幅，乘积有上界 $\beta_1 \beta_2$。K3 取 $\beta_1 = 4$（gate 支）、$\beta_2 = 25$（up 支），上界为 $4 \times 25 = 100$[N7]。softcap 在原点附近近似线性（保留 SwiGLU 的局部响应），在大幅值处被 $\beta$ 限幅（抑制激活爆炸）。SiTU-GLU 修复激活爆炸中"激活无界"的部分。softcap 的极限情形、与硬截断的对比、近原点展开等推导不在此展开。

    4.3 Quantile Balancing——从分位数设置专家 bias

    K3 在 DeepSeek-V3 无辅助损失路由的基础上改进 bias 更新规则——Quantile Balancing（QB，K3 报告 Eq. 14；完整推导见Quantile Balancing）[F4, C12]。核心结论是：每一步从路由分数的 $(1 - k/n)$ 分位数设置每个专家的 bias，使每专家获得目标负载 $q = mk/n$（$m$ 是 batch 内 token 数、$n$ 是专家数）：

    $$\tilde{b}_j^{(t+1)} \leftarrow -\mathrm{quantile}_{1-k/n}\!\left(s_{:,j}^{(t)} - \alpha^{(t)}\right), \qquad b_j^{(t+1)} \leftarrow \tilde{b}_j^{(t+1)} - \mathrm{mean}\!\left(\tilde{b}^{(t+1)}\right) \cdot \mathbf{1}.$$

    这里 $s_{:,j}^{(t)}$ 是 batch 内所有 token 对专家 $j$ 的原始路由分数、$\alpha^{(t)}$ 是 Top-$(k+1)$ 路由的截断值。第二行减去均值是为了去掉一个不影响 Top-k 选择的公共偏移[C13]。QB 修复负载失衡。Top-$(k+1)$ 截断的推导、直方图估计的工程实现见Quantile Balancing。

    4.4 三件稳定化与两个失败的对应关系

    稳定化修复哪个失败机制（一句话）引用
    Normalized LatentMoE激活爆炸（尺度放大部分）在 $u$ 与 $W_\uparrow$ 之间插 RMSNorm「为什么 RMSNorm 必须插在路由聚合之后」一章[C9]；K3 §2.3.1
    SiTU-GLU激活爆炸（激活无界部分）两线性因子 softcap 限幅，上界 $\beta_1\beta_2=100$wiki/situ-glu/[C11]；K3 §2.3.2

    注意三件稳定化是各管一段、不可互相替代：Normalized LatentMoE 只管 $u$ 的尺度，不管路由 FFN 内部激活是否无界；SiTU-GLU 只管路由 FFN 内部的激活上界，不管 $u$ 聚合后的尺度；QB 只管负载分布，不管激活数值。两个失败模式的修复各需两件稳定化协同（激活爆炸 = Normalized LatentMoE + SiTU-GLU），不是一件搞定一个。

    本章给出了三件稳定化的机制与对应关系。但 RMSNorm 插在路由聚合后、上投影前这个位置为什么不可换——换位置会发生什么——尚未论证，下一章「为什么 RMSNorm 必须插在路由聚合之后」单独论证这个位置的必要性。

    本章问题

    1. 三件稳定化分别修复哪个失败？激活爆炸的修复为什么需要两件协同？

      解答：各管一段、不可互相替代

      Normalized LatentMoE 修复激活爆炸中尺度放大的部分（在 $u$ 与 $W_\uparrow$ 之间插 RMSNorm）；SiTU-GLU 修复激活无界的部分（softcap 限幅，上界 $\beta_1\beta_2 = 100$）；Quantile Balancing 修复负载失衡。前两者各管一段——一个管 $u$ 的尺度、一个管路由 FFN 内部的激活上界——不可互相替代，需协同才能完整修复激活爆炸。

    2. RMSNorm 插在哪两个量之间？SiTU-GLU 在 K3 配置下的激活上界是多少？

      解答：聚合后、上投影前；上界 100

      RMSNorm 插在路由聚合 $u$ 之后、上投影 $W_\uparrow$ 之前。SiTU-GLU 的激活上界为 $\beta_1\beta_2 = 4 \times 25 = 100$（$\beta_1 = 4$，gate 支；$\beta_2 = 25$，up 支）。

    5. 为什么 RMSNorm 必须插在路由聚合之后——Normalized LatentMoE 的位置必要性

    三件稳定化一章已给出结论：RMSNorm 插在路由聚合 $u$ 之后、上投影 $W_\uparrow$ 之前。这一章单独论证这个位置为什么是必要的——换位置会发生什么。

    5.1 $u$ 的尺度由什么决定

    聚合表示 $u = \sum_{i \in T_k(x)} p_i \, E_i^{\text{routed}}(z)$ 的尺度由两个因素决定：选中的专家集合 $T_k(x)$（不同专家的 FFN 输出幅度不同），以及路由权重 $p_i$（同一组专家、不同权重组合，加权结果幅度不同）。不同 token 选不同专家、不同权重，$u$ 的尺度就会逐 token 漂移。

    5.2 不插 RMSNorm 会怎样

    原始 LatentMoE 直接 $W_\uparrow u$：$u$ 的尺度变化原样透传到 $W_\uparrow$ 的输出，再与共享分支 $\sum E_j^{\text{shared}}(x)$ 相加。共享分支处理的是稳定的 $x$，输出尺度相对稳定；路由分支却带来逐 token 抖动的尺度。两支相加时，共享分支要"消化"这种尺度抖动，训练稳定性受损——这就是极端稀疏下的两个失败模式一章中失败模式一的"尺度放大"的具体机制[C3]。

    5.3 插 RMSNorm 后怎样

    插入 RMSNorm 后变成 $W_\uparrow \, \mathrm{RMSNorm}(u)$：$u$ 被按均方根归一化到稳定尺度，$W_\uparrow$ 的输入分布不再逐 token 大幅漂移。归一化只抹掉尺度，不抹掉方向——$u$ 的方向信息（哪些维度大、哪些维度小）被保留，因为 RMSNorm 是逐向量除以自身的 RMS，不跨维度混合。除稳定训练外，K3 报告还观察到这一改造持续改善验证损失与下游基准[C10]（该结论是 K3 自称，未提供独立复现）。

    5.4 换位置会怎样

    这个位置不可换：

    • 放在 $W_\downarrow$ 之前（归一化 $x$）：会改变共享分支看到的 $x$，破坏共享分支对原始输入的依赖。共享支本不该被路由支的稳定化改造影响。
    • 放在 $W_\uparrow$ 之后：会把路由分支的最终输出强行拉到固定尺度，抹掉路由权重 $p_i$ 传递的相对大小信息——$p_i$ 大的 token 与 $p_i$ 小的 token，其路由贡献的差异会被归一化抹平。
    • 放在路由 FFN 内部（每个专家内部各自归一化）：改变的是单个专家的输出分布，不解决聚合后 $u$ 的尺度漂移——而尺度漂移正是问题所在。

    原 LatentMoE 与 Normalized LatentMoE 的对照：

    对比项原 LatentMoENormalized LatentMoE（K3）
    上投影作用对象$W_\uparrow u$$W_\uparrow \, \mathrm{RMSNorm}(u)$
    $u$ 的尺度是否归一化否，逐 token 漂移是，归一化到稳定尺度
    $W_\uparrow$ 输入分布随 $T_k(x)$ 与 $p_i$ 变化尺度稳定，方向保留
    与共享支相加时共享支要消化路由支的尺度抖动两支尺度匹配更稳定
    展开：构造两个不同 $T_k$ 与 $p_i$ 的 $u$，对比归一化前后

    构造示例。把隐空间维度缩小到 $\ell = 2$ 便于手算，构造两个 token 的聚合结果 $u$。

    Token A：选中专家 1、2，权重 $p_1 = p_2 = 0.5$，专家输出 $E_1(z) = (2, 0)$、$E_2(z) = (0, 2)$。则

    $$u_A = 0.5 \times (2, 0) + 0.5 \times (0, 2) = (1, 1).$$

    Token B：选中专家 3、4，权重 $p_3 = p_4 = 0.5$，专家输出 $E_3(z) = (20, 0)$、$E_4(z) = (0, 20)$。则

    $$u_B = 0.5 \times (20, 0) + 0.5 \times (0, 20) = (10, 10).$$

    RMS 的定义为 $\mathrm{RMS}(u) = \sqrt{\frac{1}{\ell}\sum_{i=1}^{\ell} u_i^2}$（简化条件：省略 RMSNorm 的可学习缩放参数 $\gamma$）。

    $u_A$ 的 RMS $= \sqrt{(1^2 + 1^2)/2} = \sqrt{1} = 1$；$u_B$ 的 RMS $= \sqrt{(10^2 + 10^2)/2} = \sqrt{100} = 10$。归一化前 $u_B$ 的尺度是 $u_A$ 的 10 倍，$W_\uparrow u_B$ 的输出尺度也是 $W_\uparrow u_A$ 的 10 倍——这就是"尺度逐 token 漂移"。

    归一化后：$\mathrm{RMSNorm}(u_A) = (1, 1) / 1 = (1, 1)$；$\mathrm{RMSNorm}(u_B) = (10, 10) / 10 = (1, 1)$。两个 token 的归一化结果完全一致——尺度被抹平，方向（$(1,1)$ 与 $(10,10)$ 同向）被保留。$W_\uparrow$ 看到的输入分布不再因 token 不同而大幅漂移。

    这个例子是人为构造的（专家输出幅度相差 10 倍），目的是让尺度漂移可手算可见，不代表 K3 实际训练中的数值范围。实际 $\ell = 3584$、专家输出幅度由训练决定。

    本章论证了 RMSNorm 位置的必要性。但 Stable LatentMoE 的结论在什么规模与配置下成立、依赖哪些独立概念、不能单独推出什么——尚未界定，下一章讲适用边界与不能推出的结论。

    本章问题

    1. $u$ 的尺度由哪两个因素决定？RMSNorm 放在 $W_\uparrow$ 之后会丢失什么信息？

      解答：专家集合与路由权重；放后会抹掉权重信息

      $u$ 的尺度由选中的专家集合 $T_k(x)$（不同专家的 FFN 输出幅度不同）与路由权重 $p_i$（同一组专家、不同权重组合的加权结果幅度不同）决定，因此逐 token 漂移。放在 $W_\uparrow$ 之后会把路由分支的最终输出强行拉到固定尺度，抹掉 $p_i$ 传递的相对大小信息——路由贡献大的 token 与贡献小的 token 的差异被归一化抹平。

    2. 用构造示例的数字说明：归一化前 $u_A$ 与 $u_B$ 的 RMS 相差几倍？归一化后呢？

      解答：归一化前相差 10 倍，归一化后一致

      归一化前 $u_A = (1,1)$ 的 RMS 为 1、$u_B = (10,10)$ 的 RMS 为 10，相差 10 倍，$W_\uparrow$ 的输出尺度随之相差 10 倍——这就是尺度逐 token 漂移。归一化后两者都变为 $(1,1)$：尺度被抹平、方向保留，$W_\uparrow$ 的输入分布不再逐 token 大幅漂移。

    3. "RMSNorm 改造还持续改善验证损失与下游基准"这一结论的置信状态如何？

      解答：K3 自称，未提供独立复现

      该结论来自 K3 报告的自述，未提供独立复现；引用时应注明这一来源状态。

    6. 适用边界与不能推出的结论

    Stable LatentMoE 的结论在 K3 的规模与配置下成立：$N = 896$ 路由专家、$k = 16$ 每 token 激活、$\ell = 3584$ 隐空间宽度、$d = 7168$ 全宽、2.8 万亿参数、bfloat16 训练。它不解决"如何选择 $N$ 与 $k$"、"如何选择 $\ell$"、"如何在更小规模下判断是否需要 LatentMoE"——K3 报告未给出这些问题的判据，本文不补。

    它依赖以下独立概念：

    • MoE 基础（路由 + 专家 + Top-k）——提供路由与 Top-k 的基础。
    • SiTU-GLU——提供有界激活的完整机制。
    • Quantile Balancing——提供分位数 bias 更新的完整推导。
    • DeepSeekMoE 组织——提供 shared+routed 组织公式。
    • RMSNorm——独立概念页暂未生成，本文只用"按均方根归一化"这一基本作用。
    • LatentMoE 原始架构——本文内联了其最小必要结构作为对照。

    不能从本文推出的结论：

    • 不能推出"任何 MoE 都应该用 LatentMoE"——LatentMoE 的收益在扩大专家池时才显现，小规模 MoE 可能不需要。
    • 不能推出"SiTU-GLU 一定优于 SwiGLU"——SiTU-GLU 是为修复 LatentMoE 路由分支在 2.8T 规模下的激活爆炸而设计，其它架构/规模下 SwiGLU 仍是有效选择。
    • 不能推出"QB 一定优于辅助损失"——QB 是为近千专家的负载均衡而设计，专家数较少时辅助损失或原 bias 更新可能已足够。
    • 不能推出"RMSNorm 插在任何位置都有效"——为什么 RMSNorm 必须插在路由聚合之后一章已说明位置不可换。
    • 不能推出"三件稳定化可以独立使用"——三件稳定化一章已说明激活爆炸的修复需要 Normalized LatentMoE 与 SiTU-GLU 协同。

    综上，Stable LatentMoE 用 LatentMoE 的两个宽度分离让 896 路由专家的扩大可负担，用 Normalized LatentMoE 与 SiTU-GLU 协同修复路由分支激活爆炸，用 Quantile Balancing 修复近千专家的负载失衡。三件稳定化各管一段、不可互相替代，其结论在 K3 的规模与配置下成立，不可外推到任意 MoE。

    辅助解释与类比边界

    "尺度放大"用于解释极端稀疏下的两个失败模式一章中失败模式一的 $u$ 的尺度变化如何透传到 $W_\uparrow$ 输出；它只描述矩阵乘法链中尺度因子的传播，不涵盖条件数、梯度爆炸等数值分析的完整内容，正式判断以 Eq. 11 与 RMSNorm 的数学定义为准。"抹尺度保方向"用于解释 RMSNorm 的作用；它只描述 RMSNorm 按均方根归一化、不跨维度混合这一性质，不覆盖 RMSNorm 与 LayerNorm 的差异、可学习参数 $\gamma$ 的作用等内部细节。
