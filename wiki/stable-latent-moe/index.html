    Stable LatentMoE：把路由专家放进隐空间，再用三件稳定化修复极端稀疏

    主要依据：Kimi K3 技术报告 §2.3-2.3.3（Eq. 11-14）与官方 config.json（Hugging Face moonshotai/Kimi-K3）；DeepSeekMoE 论文（arXiv:2401.06066）§3.2。

    如果你要把一个 MoE 层的专家池扩到 896、每 token 激活扩到 16，会发生什么？直觉上"专家多了、每个 token 走的路径多了"应该更好。但在 2.8 万亿参数规模下，K3 团队发现这条路上有两个具体的失败点——路由分支内部激活爆炸，以及近千专家的负载失衡——必须用三件稳定化才能让这个扩大后的稀疏层真正跑起来。这一页讲清楚 K3 的 Stable LatentMoE 是怎么动的、为什么这么动。

    扩大专家池的代价：为什么需要 LatentMoE

    普通 MoE 层里，每个被选中的路由专家都直接接收完整的 $d$ 维 token 表示 $x$，并在 $d$ 维空间里做 FFN 变换（详见MoE 基础）。这意味着扩大路由倍数——更多专家、更多每 token 激活——会让路由通信与专家权重流量随路由倍数线性增长：每多一个被选中的专家，就要把 $d$ 维向量送过去、把 $d$ 维变换后的向量取回来。

    LatentMoE 的对策是分离全模型宽度与路由专家宽度：共享专家保留全宽 $d$ 的路径处理通用变换；路由专家则在一个比 $d$ 更窄的隐空间 $\ell$ 里操作。具体做法是在路由分支两端各加一次投影——下投影 $W_\downarrow$ 把 $x \in \mathbb{R}^d$ 压到 $z = W_\downarrow x \in \mathbb{R}^\ell$，路由专家在 $\ell$ 维空间里处理 $z$，上投影 $W_\uparrow$ 把结果投回 $\mathbb{R}^d$。

    $$z = W_\downarrow x, \qquad W_\downarrow \in \mathbb{R}^{\ell \times d}, \quad z \in \mathbb{R}^\ell.$$

    这里的 $W_\downarrow$ 是下投影矩阵，把 $d$ 维输入压到 $\ell$ 维；$z$ 是隐空间表示。代价是路由分支多出 $W_\downarrow$ 与 $W_\uparrow$ 两次投影，形成更长的矩阵乘法链——这一点在 S3 会看到它是激活爆炸的根源。但收益是：路由专家内部的 FFN 只在 $\ell$ 维空间操作，扩大路由专家数不再让每个被选中的专家都背一份全宽流量。

    对比项普通 MoE（全宽路由）LatentMoE（隐空间路由）
    路由专家的输入空间$\mathbb{R}^d$（全宽）$\mathbb{R}^\ell$（紧凑隐空间，$\ell < d$）
    扩大专家池的代价通信与权重流量随路由倍数线性增长路由专家 FFN 在 $\ell$ 维操作，扩大池子不再线性增加全宽流量
    额外开销无路由分支多出 $W_\downarrow$、$W_\uparrow$ 两次投影
    共享专家路径通常也是全宽保留全宽 $d$，不走隐空间

    Stable LatentMoE 的层结构：共享分支、路由分支与 RMSNorm 的位置

    K3 的 Stable LatentMoE 层沿用 DeepSeekMoE 提出的"共享专家 + 路由专家"组织：共享专家无路由、所有 token 必经，承担通用变换；路由专家参与 Top-k 选择，承担差异化变换（DeepSeekMoE 论文 §3.2；该概念页暂未生成）。K3 每层固定 $N_s = 2$ 个全宽共享专家。

    对输入 $x \in \mathbb{R}^d$，Stable LatentMoE 层的输出 $y \in \mathbb{R}^d$ 由两支相加得到（K3 报告 Eq. 11）：

    $$u = \sum_{i \in T_k(x)} p_i \, E_i^{\text{routed}}(W_\downarrow x), \qquad y = \sum_{j=1}^{N_s} E_j^{\text{shared}}(x) + W_\uparrow \, \mathrm{RMSNorm}(u).$$

    每个符号的含义：

    • $x \in \mathbb{R}^d$：层输入，$d$ 是全模型宽度。
    • $W_\downarrow \in \mathbb{R}^{\ell \times d}$：下投影，把 $x$ 压到隐空间 $\mathbb{R}^\ell$。
    • $E_i^{\text{routed}}: \mathbb{R}^\ell \to \mathbb{R}^\ell$：第 $i$ 个路由专家的 FFN，输入输出都在隐空间。
    • $T_k(x)$：对 token $x$ 选中的 Top-k 路由专家下标集合。
    • $p_i$：路由权重，由路由器给出，对 $T_k(x)$ 内的 $i$ 非零。
    • $u \in \mathbb{R}^\ell$：路由专家的加权聚合。
    • $\mathrm{RMSNorm}$：按均方根归一化（RMSNorm 概念页暂未生成；本文只需"按均方根归一化"这一基本作用）。
    • $W_\uparrow \in \mathbb{R}^{d \times \ell}$：上投影，把归一化后的 $u$ 投回 $\mathbb{R}^d$。
    • $E_j^{\text{shared}}: \mathbb{R}^d \to \mathbb{R}^d$：第 $j$ 个共享专家的 FFN，输入输出都在全宽 $d$。
    • $N_s$：共享专家数，K3 取 $N_s = 2$。

    极端稀疏下的两个失败模式：激活爆炸与负载失衡

    LatentMoE 让扩大专家池变得可负担，但 K3 在 $N=896, k=16$（稀疏度 56）、2.8 万亿参数规模下发现两个具体的失败点。

    失败模式一：路由分支激活爆炸

    路由分支的结构是 $W_\downarrow \to$ 门控多分支路由 FFN $\to W_\uparrow$，这是近四个连续矩阵乘法的链——$W_\downarrow$ 一次、路由 FFN 内部门支与值支各一次、$W_\uparrow$ 一次。这条链的条件数本来就差（连续投影会放大数值扰动），再叠加 2.8 万亿参数的规模，路由分支内部就会出现激活异常增大，威胁训练稳定性。

    路由分支的矩阵乘法链（激活爆炸的发生位置）

  x ∈ R^d ──► W_↓ ──► z ∈ R^ℓ ──► [路由 FFN：门支 × 值支] ──► u ∈ R^ℓ ──► W_↑ ──► R^d
              (1)         (2)(3)                              (4)
              └────────── 近四个连续矩阵乘法，条件数差 ──────────┘
                                              2.8T 规模 → 激活爆炸

    失败模式二：近千专家负载失衡

    K3 用的是无辅助损失路由（auxiliary-loss-free，DeepSeek-V3 引入）：在每个专家的路由分数上加一个 bias $b_j$ 用于 Top-k 选择，但 bias 不进入 mixture 权重。原方法用固定步长规则 $b_j^{(t+1)} = b_j^{(t)} + \gamma \cdot \mathrm{sign}(\bar{\ell} - \ell_j)$ 更新 bias——步长 $\gamma$ 太小则适应慢，太大则负载振荡。这套规则在专家数较少时够用，但平衡近 $10^3$ 个专家的负载已经超出它的适用范围：部分专家被过度使用、部分专家几乎不被使用（"dying expert"），拖慢专家并行训练并让部分专家训练不足。

    三件稳定化：Normalized LatentMoE、SiTU-GLU、Quantile Balancing

    Stable LatentMoE 的"Stable"由三件稳定化承担，分别修复 S3 的两个失败模式。

    Normalized LatentMoE：在路由聚合后插 RMSNorm

    原始 LatentMoE 直接把 $W_\uparrow$ 作用于聚合表示 $u$。但 $u$ 的尺度会随选中专家集合 $T_k(x)$ 与路由权重 $p_i$ 变化——不同 token 选不同专家、不同权重，$u$ 的尺度逐 token 漂移。K3 在 $u$ 与 $W_\uparrow$ 之间插入 RMSNorm，把 $u$ 归一化到稳定尺度后再交给 $W_\uparrow$，降低路由分支对尺度变化的敏感度。这是 Eq. 11 中 $W_\uparrow \, \mathrm{RMSNorm}(u)$ 这一项的来源，修复激活爆炸中"尺度放大"的部分。S5 会单独论证这个位置的必要性。

    SiTU-GLU：给路由专家 FFN 一个有界激活

    路由专家 FFN 内部用 SiTU-GLU 作为激活函数（K3 报告 Eq. 12；完整机制见SiTU-GLU）：

    $$\mathrm{SiTU\text{-}GLU}(x) = \beta_1 \tanh\!\left(\frac{W_g x}{\beta_1}\right) \odot \mathrm{Sigmoid}(W_g x) \odot \beta_2 \tanh\!\left(\frac{W_u x}{\beta_2}\right).$$

    这里只需要知道一个结论：两个线性因子都被 $\tanh$ 的 softcap 限幅，乘积有上界 $\beta_1 \beta_2$。K3 取 $\beta_1 = 4$（gate 支）、$\beta_2 = 25$（up 支），上界为 $4 \times 25 = 100$。softcap 在原点附近近似线性（保留 SwiGLU 的局部响应），在大幅值处被 $\beta$ 限幅（抑制激活爆炸）。SiTU-GLU 修复激活爆炸中"激活无界"的部分。softcap 的极限情形、与硬截断的对比、近原点展开等推导不在此展开。

    Quantile Balancing：从分位数设置专家 bias

    K3 在 DeepSeek-V3 无辅助损失路由的基础上改进 bias 更新规则——Quantile Balancing（QB，K3 报告 Eq. 14；完整推导属独立概念页，暂未生成）。核心结论是：每一步从路由分数的 $(1 - k/n)$ 分位数设置每个专家的 bias，使每专家获得目标负载 $q = mk/n$（$m$ 是 batch 内 token 数、$n$ 是专家数）：

    $$\tilde{b}_j^{(t+1)} \leftarrow -\mathrm{quantile}_{1-k/n}\!\left(s_{:,j}^{(t)} - \alpha^{(t)}\right), \qquad b_j^{(t+1)} \leftarrow \tilde{b}_j^{(t+1)} - \mathrm{mean}\!\left(\tilde{b}^{(t+1)}\right) \cdot \mathbf{1}.$$

    这里 $s_{:,j}^{(t)}$ 是 batch 内所有 token 对专家 $j$ 的原始路由分数、$\alpha^{(t)}$ 是 Top-$(k+1)$ 路由的截断值。第二行减去均值是为了去掉一个不影响 Top-k 选择的公共偏移。QB 修复负载失衡。Top-$(k+1)$ 截断的推导、直方图估计的工程实现不在此展开。

    为什么 RMSNorm 必须插在路由聚合之后：Normalized LatentMoE 的位置必要性

    S4 已经给出结论：RMSNorm 插在路由聚合 $u$ 之后、上投影 $W_\uparrow$ 之前。这一章单独论证这个位置为什么是必要的——换位置会发生什么。

    $u$ 的尺度由什么决定

    聚合表示 $u = \sum_{i \in T_k(x)} p_i \, E_i^{\text{routed}}(z)$ 的尺度由两个因素决定：选中的专家集合 $T_k(x)$（不同专家的 FFN 输出幅度不同），以及路由权重 $p_i$（同一组专家、不同权重组合，加权结果幅度不同）。不同 token 选不同专家、不同权重，$u$ 的尺度就会逐 token 漂移。

    不插 RMSNorm 会怎样

    原始 LatentMoE 直接 $W_\uparrow u$：$u$ 的尺度变化原样透传到 $W_\uparrow$ 的输出，再与共享分支 $\sum E_j^{\text{shared}}(x)$ 相加。共享分支处理的是稳定的 $x$，输出尺度相对稳定；路由分支却带来逐 token 抖动的尺度。两支相加时，共享分支要"消化"这种尺度抖动，训练稳定性受损——这就是 S3 失败模式一中"尺度放大"的具体机制。

    插 RMSNorm 后怎样

    插入 RMSNorm 后变成 $W_\uparrow \, \mathrm{RMSNorm}(u)$：$u$ 被按均方根归一化到稳定尺度，$W_\uparrow$ 的输入分布不再逐 token 大幅漂移。归一化只抹掉尺度，不抹掉方向——$u$ 的方向信息（哪些维度大、哪些维度小）被保留，因为 RMSNorm 是逐向量除以自身的 RMS，不跨维度混合。除稳定训练外，K3 报告还观察到这一改造持续改善验证损失与下游基准（K3 §2.3.1；该结论是 K3 自称，未提供独立复现）。

    换位置会怎样

    这个位置不可换：

    • 放在 $W_\downarrow$ 之前（归一化 $x$）：会改变共享分支看到的 $x$，破坏共享分支对原始输入的依赖。共享支本不该被路由支的稳定化改造影响。
    • 放在 $W_\uparrow$ 之后：会把路由分支的最终输出强行拉到固定尺度，抹掉路由权重 $p_i$ 传递的相对大小信息——$p_i$ 大的 token 与 $p_i$ 小的 token，其路由贡献的差异会被归一化抹平。
    • 放在路由 FFN 内部（每个专家内部各自归一化）：改变的是单个专家的输出分布，不解决聚合后 $u$ 的尺度漂移——而尺度漂移正是问题所在。

    原 LatentMoE 与 Normalized LatentMoE 的对照：

    对比项原 LatentMoENormalized LatentMoE（K3）
    上投影作用对象$W_\uparrow u$$W_\uparrow \, \mathrm{RMSNorm}(u)$
    $u$ 的尺度是否归一化否，逐 token 漂移是，归一化到稳定尺度
    $W_\uparrow$ 输入分布随 $T_k(x)$ 与 $p_i$ 变化尺度稳定，方向保留
    与共享支相加时共享支要消化路由支的尺度抖动两支尺度匹配更稳定
    教学示例：构造两个不同 $T_k$ 与 $p_i$ 的 $u$，对比归一化前后

    教学示例。把隐空间维度缩小到 $\ell = 2$ 便于手算，构造两个 token 的聚合结果 $u$。

    Token A：选中专家 1、2，权重 $p_1 = p_2 = 0.5$，专家输出 $E_1(z) = (2, 0)$、$E_2(z) = (0, 2)$。则

    $$u_A = 0.5 \times (2, 0) + 0.5 \times (0, 2) = (1, 1).$$

    Token B：选中专家 3、4，权重 $p_3 = p_4 = 0.5$，专家输出 $E_3(z) = (20, 0)$、$E_4(z) = (0, 20)$。则

    $$u_B = 0.5 \times (20, 0) + 0.5 \times (0, 20) = (10, 10).$$

    RMS 的定义为 $\mathrm{RMS}(u) = \sqrt{\frac{1}{\ell}\sum_{i=1}^{\ell} u_i^2}$（教学简化：省略 RMSNorm 的可学习缩放参数 $\gamma$）。

    $u_A$ 的 RMS $= \sqrt{(1^2 + 1^2)/2} = \sqrt{1} = 1$；$u_B$ 的 RMS $= \sqrt{(10^2 + 10^2)/2} = \sqrt{100} = 10$。归一化前 $u_B$ 的尺度是 $u_A$ 的 10 倍，$W_\uparrow u_B$ 的输出尺度也是 $W_\uparrow u_A$ 的 10 倍——这就是"尺度逐 token 漂移"。

    归一化后：$\mathrm{RMSNorm}(u_A) = (1, 1) / 1 = (1, 1)$；$\mathrm{RMSNorm}(u_B) = (10, 10) / 10 = (1, 1)$。两个 token 的归一化结果完全一致——尺度被抹平，方向（$(1,1)$ 与 $(10,10)$ 同向）被保留。$W_\uparrow$ 看到的输入分布不再因 token 不同而大幅漂移。

    这个例子是人为构造的（专家输出幅度相差 10 倍），目的是让尺度漂移可手算可见，不代表 K3 实际训练中的数值范围。实际 $\ell = 3584$、专家输出幅度由训练决定。

    适用边界与不能推出的结论

    Stable LatentMoE 的结论在 K3 的规模与配置下成立：$N = 896$ 路由专家、$k = 16$ 每 token 激活、$\ell = 3584$ 隐空间宽度、$d = 7168$ 全宽、2.8 万亿参数、bfloat16 训练。它不解决"如何选择 $N$ 与 $k$"、"如何选择 $\ell$"、"如何在更小规模下判断是否需要 LatentMoE"——K3 报告未给出这些问题的判据，本文不补。

    它依赖以下独立概念：

    • MoE 基础（路由 + 专家 + Top-k）——已生成。
    • SiTU-GLU——已生成，提供有界激活的完整机制。
    • Quantile Balancing——独立概念页暂未生成，本文只引用其分位数结论。
    • DeepSeekMoE 组织——独立概念页暂未生成，本文只引用其 shared+routed 组织公式。
    • RMSNorm——独立概念页暂未生成，本文只用"按均方根归一化"这一基本作用。
    • LatentMoE 原始架构——独立概念页暂未生成，本文内联了其最小必要结构作为对照。

    不能从本文推出的结论：

    • 不能推出"任何 MoE 都应该用 LatentMoE"——LatentMoE 的收益在扩大专家池时才显现，小规模 MoE 可能不需要。
    • 不能推出"SiTU-GLU 一定优于 SwiGLU"——SiTU-GLU 是为修复 LatentMoE 路由分支在 2.8T 规模下的激活爆炸而设计，其它架构/规模下 SwiGLU 仍是有效选择。
    • 不能推出"QB 一定优于辅助损失"——QB 是为近千专家的负载均衡而设计，专家数较少时辅助损失或原 bias 更新可能已足够。
    • 不能推出"RMSNorm 插在任何位置都有效"——S5 已说明位置不可换。
    • 不能推出"三件稳定化可以独立使用"——S4 已说明激活爆炸的修复需要 Normalized LatentMoE 与 SiTU-GLU 协同。

    教学解释与类比边界

    "尺度放大"用于解释 S3 失败模式一中 $u$ 的尺度变化如何透传到 $W_\uparrow$ 输出；它只描述矩阵乘法链中尺度因子的传播，不涵盖条件数、梯度爆炸等数值分析的完整内容，正式判断以 Eq. 11 与 RMSNorm 的数学定义为准。"抹尺度保方向"用于解释 RMSNorm 的作用；它只描述 RMSNorm 按均方根归一化、不跨维度混合这一性质，不覆盖 RMSNorm 与 LayerNorm 的差异、可学习参数 $\gamma$ 的作用等内部细节。
