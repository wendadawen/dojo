# Stable LatentMoE 教学大纲

## 1. 页面开头

### 1.1 钩子问题

"如果你要把一个 MoE 层的专家池从 64 扩到 896、每 token 激活从 8 扩到 16，会发生什么？直觉上'专家多了、每个 token 走的路径多了'应该更好。但在 2.8T 参数规模下，K3 团队发现这条路上有两个具体的失败点，必须用三件稳定化才能让这个扩大后的稀疏层真正跑起来。"

### 1.2 一句话解释

Stable LatentMoE 是 Kimi K3 的 MoE 层结构：把路由专家放进比全模型宽度更窄的隐空间，再用三件稳定化（路由分支归一化、有界激活、分位数负载均衡）修复极端稀疏下出现的两个失败模式。

### 1.3 学习承诺（学习目标 Q1-Q5）

见 scope.md §3。开头用 `learning-goals` 组件列出 Q1-Q5 的简化版。

### 1.4 首个具体场景

钩子问题中的"扩到 896 / 16"即 K3 的实际配置（N4, N5）。

### 1.5 与第一章的过渡

"我们先看清楚在扩大专家池之前，普通 MoE 的路由分支在做什么——这才能看出 K3 为什么要动它。"

## 2. 章节设计

### S1：扩大专家池的代价——为什么需要 LatentMoE

- **主要教学问题**：在普通 MoE 下，扩大专家池与每 token 激活数，会让每个被选中的路由专家接收什么、产生什么代价？
- **对应范围**：Q1；C1；C2。
- **正文要点**：
  - 普通 MoE 中每个被选中的路由专家接收全宽 $d$ 维 token 表示（引用 `wiki/moe-serving/`）。
  - 扩大路由倍数（更多专家、更多激活）→ 通信与专家权重流量随路由倍数线性增长。
  - LatentMoE 的对策：分离全宽与路由宽度——共享专家走全宽 $d$，路由专家在紧凑隐空间 $\ell$ 操作。
- **讲解材料及职责**：
  - 对照表（普通 MoE vs LatentMoE 的路由分支宽度）：展示结构差异。
  - 公式（隐空间投影 $z = W_\downarrow x$）：表达投影关系。
- **前置知识安排**：引用 `wiki/moe-serving/`（MoE 基础）。
- **完成检查**：
  - 用一句话说明 LatentMoE 分离了哪两个宽度。
  - 指出 LatentMoE 路由分支多出哪两次投影。
- **过渡**：LatentMoE 让扩大专家池变得可负担，但 K3 在 896/16 的极端稀疏下发现两个失败点——下一章看具体是什么。

### S2：Stable LatentMoE 的层结构——共享分支、路由分支与 RMSNorm 的位置

- **主要教学问题**：一个 Stable LatentMoE 层的具体数据流是什么？$W_\downarrow$、$W_\uparrow$、共享专家、路由专家、RMSNorm 各在什么位置？
- **对应范围**：Q2；C1, C7, C8, C9；F1, F2。
- **正文要点**：
  - K3 沿用 DeepSeekMoE 的 shared+routed 组织（引用 F2）：共享专家无路由、所有 token 必经；路由专家参与 Top-k。
  - Eq. 11 完整公式（F1）：$u = \sum p_i E_i^{\text{routed}}(W_\downarrow x)$，$y = \sum E_j^{\text{shared}}(x) + W_\uparrow \mathrm{RMSNorm}(u)$。
  - 每个符号的含义：$x \in \mathbb{R}^d$、$z = W_\downarrow x \in \mathbb{R}^\ell$、$u \in \mathbb{R}^\ell$、$E^{\text{shared}}: \mathbb{R}^d \to \mathbb{R}^d$、$E^{\text{routed}}: \mathbb{R}^\ell \to \mathbb{R}^\ell$、$p_i$ 路由权重、$T_k(x)$ Top-k 集合、$N_s = 2$。
  - K3 的具体配置数字（N1-N4）：$d=7168, \ell=3584, N=896, k=16, N_s=2$。
  - 共享专家不走隐空间（澄清常见误解）。
- **讲解材料及职责**：
  - ASCII 图示：Stable LatentMoE 层数据流（共享支 + 路由支 + RMSNorm 位置）。
  - 公式 F1：层输出定义。
  - 对照表：共享分支 vs 路由分支的输入空间、是否路由、是否经 $W_\downarrow$/$W_\uparrow$、是否经 RMSNorm。
- **前置知识安排**：DeepSeekMoE 未生成概念页，正文用一句话说明其组织方式并标注"详见 DeepSeekMoE 论文 §3.2"。
- **完成检查**：
  - 画出 Eq. 11 的数据流，标出 RMSNorm 的位置。
  - 说明共享专家的输入空间是 $d$ 还是 $\ell$。
  - 指出 $W_\uparrow$ 作用于 RMSNorm 的输出还是 $u$ 本身。
- **过渡**：现在结构清楚了，但还看不出 RMSNorm 为什么必须插在这里——下一章看两个失败模式就明白。

### S3：极端稀疏下的两个失败模式——激活爆炸与负载失衡

- **主要教学问题**：在 K3 的规模与稀疏度下，原始 LatentMoE 会出现哪两个具体的失败？分别由什么引起？
- **对应范围**：Q3 的前半；C3, C4, C5；N5, N6。
- **正文要点**：
  - 失败模式一：路由分支 = $W_\downarrow$ → 门控多分支 FFN → $W_\uparrow$，是近四个连续矩阵乘法的链（C3）。条件数差 + 2.8T 规模（N6）→ 路由分支内部激活爆炸（C4）。
  - 失败模式二：平衡近 $10^3$ 个专家的负载超出无辅助损失方法的适用范围（C5）。原方法的固定步长 bias 更新在大专家池下要么慢要么振荡。
- **讲解材料及职责**：
  - ASCII 图示：路由分支的矩阵乘法链（$W_\downarrow$ → FFN(多分支) → $W_\uparrow$）。
  - 对照表：两个失败模式（位置、原因、症状、修复方法预告）。
- **前置知识安排**：无新前置；引用 S2 已建立的层结构。
- **完成检查**：
  - 指出激活爆炸发生在路由分支的哪一段。
  - 说明负载失衡问题随专家数增大而恶化的原因。
- **过渡**：两个失败点都定位了，下一章看三件稳定化分别修复哪一个。

### S4：三件稳定化——Normalized LatentMoE、SiTU-GLU、Quantile Balancing

- **主要教学问题**：三件稳定化分别是什么？各自修复 S3 中的哪个失败？
- **对应范围**：Q3 的后半、Q4；C6, C9, C10, C11, C12, C13；F3, F4；N7。
- **正文要点**：
  - **Normalized LatentMoE**（C9）：原始 LatentMoE 直接 $W_\uparrow u$，$u$ 的尺度随选中专家与路由权重变化；K3 在 $u$ 与 $W_\uparrow$ 之间插 RMSNorm，切断尺度变化向 $W_\uparrow$ 的透传。修复失败模式一的"尺度放大"部分。
  - **SiTU-GLU**（C11, F3）：路由专家 FFN 的有界激活，上界 $\beta_1\beta_2 = 100$（N7），近原点近似 Swish。修复失败模式一的"激活无界"部分。完整机制引用 `wiki/situ-glu/`。
  - **Quantile Balancing**（C12, C13, F4）：在 DeepSeek-V3 无辅助损失路由基础上改进 bias 更新——从路由分数的 $(1-k/n)$ 分位数设置每专家 bias。修复失败模式二。完整推导引用 `wiki/quantile-balancing/`（占位）。
  - 三件稳定化与两个失败的对应关系总览。
- **讲解材料及职责**：
  - 对照表：三件稳定化（修复哪个失败、机制一句话、引用页面）。
  - 公式 F3（SiTU-GLU）：仅引用上界结论，不展开推导。
  - 公式 F4（QB 更新）：仅引用分位数结论，不展开推导。
- **前置知识安排**：
  - SiTU-GLU：引用 `wiki/situ-glu/index.html`。
  - Quantile Balancing：占位提示，正文保留最小衔接。
- **完成检查**：
  - 三件稳定化分别修复哪个失败？
  - SiTU-GLU 的上界是多少？
  - RMSNorm 插在什么位置？
- **过渡**：三件稳定化的修复方向清楚了，但 Normalized LatentMoE 是 K3 相对原始 LatentMoE 的核心结构改造，需要单独说清它的位置为什么是必要的。

### S5：为什么 RMSNorm 必须插在路由聚合之后——Normalized LatentMoE 的位置必要性

- **主要教学问题**：RMSNorm 的位置为什么必须是"路由聚合之后、上投影之前"？换位置会发生什么？
- **对应范围**：Q4；C9, C10。
- **正文要点**：
  - $u = \sum p_i E_i^{\text{routed}}(z)$ 的尺度由两个因素决定：选中的专家集合 $T_k(x)$、路由权重 $p_i$。不同 token 选不同专家、不同权重 → $u$ 的尺度逐 token 变化。
  - 原 LatentMoE 直接 $W_\uparrow u$ → 尺度变化透传到 $W_\uparrow$ 的输出，再与共享分支相加，共享分支要"消化"这种尺度抖动。
  - 插入 RMSNorm 后：$W_\uparrow \mathrm{RMSNorm}(u)$，$u$ 被归一化到稳定尺度，$W_\uparrow$ 的输入分布不再逐 token 大幅漂移。
  - C10：除稳定训练外，还持续改善验证损失与下游基准（K3 报告自称）。
  - 位置不可换：放在 $W_\downarrow$ 之前会归一化 $x$（破坏共享分支对原始 $x$ 的依赖）；放在 $W_\uparrow$ 之后会把路由分支的输出强行拉到固定尺度，抹掉路由权重 $p_i$ 的相对大小信息。
- **讲解材料及职责**：
  - 对照表：原 LatentMoE vs Normalized LatentMoE（$W_\uparrow u$ vs $W_\uparrow \mathrm{RMSNorm}(u)$）。
  - 数字例子（折叠块）：教学示例，构造两个不同 $T_k$ 与 $p_i$ 的 $u$，对比归一化前后的尺度。
- **前置知识安排**：RMSNorm 未生成概念页，正文用一句话说明其基本作用（按均方根归一化）并标注"详见原始论文"。
- **完成检查**：
  - 说明 $u$ 的尺度由哪两个因素决定。
  - 指出 RMSNorm 放在 $W_\uparrow$ 之后会丢失什么信息。
  - 说明 C10 的成立条件（K3 配置）。
- **过渡**：层结构与三件稳定化都讲完了，最后明确这套方案的适用边界。
