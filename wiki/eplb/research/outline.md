# EPLB 文章大纲

## 1. 页面开头

- 场景引入：一个 8 卡专家并行部署，12 个逻辑专家，各专家一段时间的 token 负载统计（表：e0–e11 = 90…86，官方 README 示例数据，页面说明这是示例数据非实测）。两个观察：(a) 12 个专家的槽没法均分到 8 张卡；(b) 最热的专家 e10 一家就吃 183 个 token，而 8 卡均摊预算只有 129.125。若不做处理，e10 所在的卡必然超载、拖慢整层。
- 简要解释：EPLB（Expert Parallelism Load Balancer）是 DeepSeek 开源的专家并行负载均衡算法，也是 vLLM 的内置功能：复制高负载专家（冗余专家），再按估计负载把物理专家均衡地打包到节点与 GPU；线上按统计周期性重算。
- blockquote.meta：主要依据 = deepseek-ai/EPLB 仓库（README 与 eplb.py）、DeepSeek-V3 技术报告（arXiv:2412.19437）、vLLM 文档与源码。
- learning-goals：核心问题 Q1–Q5（与 scope.md 一致）。
- misconceptions（3 条）：EPLB 改路由？不改，改「放哪、复制几份」；冗余=每 token 多算？不多算，多占显存；一次排好永久均衡？周期性重排跟随漂移。
- 过渡：先弄清「为什么慢」——木桶效应。

## 2. 章节设计

### 第 1 章 专家并行的木桶效应——最慢的卡决定整层时间

- 章节问题：
  1. 一张 GPU 的负载由什么决定？整层计算时间由什么决定？
  2. 训练时已经用 bias 均衡了，为什么推理部署还会不均？
- 完成答案要点：
  1. 负载 ≈ 发往该卡所持专家的 token 数（dispatch 后各卡独立算，同步点等最慢者）；层利用率 = 平均负载/最大负载（构造两卡 800/200 例：62.5%）。
  2. bias 增减发生在训练步末（报告原文），推理没有训练步，路由规则固定（推断，标注）；线上 token 分布随 workload 高度倾斜（vLLM 文档原句）；V3 承诺训练与推理都不丢 token，所以要用部署层手段。
- 对应范围：C1、C12（含推断标注）、F2（构造）；前置 moe-serving（EP/all-toall、6对2构造例）、aux-loss-free-routing（bias 机制）。
- 正文要点：EP 数据流一句话回顾＋链接；木桶效应量化；训练均衡 vs 推理漂移对比表；V3 不丢 token 的立场。
- 表达材料：对照表（训练期 bias 均衡 vs 推理期 EPLB：作用层/调节对象/生效时机）；构造小例（两卡 800/200）。
- 前置知识：moe-serving 链接（EP 与 dispatch/combine）、aux-loss-free-routing 链接（bias 只调选谁）。

### 第 2 章 冗余专家——用参数副本分摊计算，顺带对齐显存槽位

- 章节问题：
  1. 逻辑专家和物理专家是什么关系？副本如何分摊负载？
  2. 为什么冗余专家同时解决了「槽位数不整除」的问题？
  3. 复制哪些专家？贪心规则是什么、为什么有效？
- 完成答案要点：
  1. 逻辑专家 = 模型定义的专家；物理专家 = 显存里的一份副本；一个逻辑专家可有 $c_e$ 个副本，每副本承载 $w_e/c_e$（F1）；每 token 激活专家数不变（仍是 top-k）。
  2. 每卡槽位固定（显存均匀）要求物理专家数整除 GPU 数；12 → 16 = 8×2，多出的 4 个槽就是冗余副本的容身之处；复制冷专家也能凑数但对均衡无益。
  3. 贪心：每次给 $w_e/c_e$ 最大的专家 +1 副本；手算 12→16（全局视角）：e10(183→91.5)、e5(165→82.5)、e1(132→66)、e4(104→52)；复制后最大单副本负载 91.5 < 预算 129.125；对照：复制最冷的 e7（4→2+2）后最大负载仍 183。
- 对应范围：C2、C6、C8、C9（整除）、F1、N2（贪心手算部分）。
- 正文要点：逻辑/物理定义、均摊公式、槽位整除、贪心规则与手算、均摊假设的边界。
- 表达材料：公式 F1＋符号表；手算表格（贪心每步选谁、单副本负载变化）；对照小例（复制热 vs 冷专家）。
- 前置知识：deepseek-moe 链接（路由专家/共享专家/top-k）。
- 过渡：贪心只回答「复制谁」；还没回答「放哪」。放到哪张卡还牵涉节点与分组——第 3 章。

### 第 3 章 三步排布——组进节点、节点内复制、再均衡装进 GPU

- 章节问题：
  1. 为什么要先把「组」装进节点？组是什么？
  2. 三步各自做什么？如何在官方示例上完整手算？
  3. 全局策略何时启用？与层次策略相比得失如何？
- 完成答案要点：
  1. 组 = 逻辑专家的固定分组（EPLB 的 num_groups 参数，组是连续编号分块）；V3 的节点受限路由按「节点上专家的最高 K_r/M 亲和和」选至多 M 个节点（C3），组不跨节点时组内 token 不出节点；跨节点走 IB（50 GB/s）、节点内走 NVLink（160 GB/s，3.2×）（C19），所以组局部性值钱。
  2. Step1 组→节点均衡打包（组负载 262/330/116/325 降序贪心 → 节点0={G1,G2}=446、节点1={G0,G3}=587）；Step2 节点内贪心复制（node0 复制 e5、e4；node1 复制 e10、e1）；Step3 物理→GPU 均衡打包（物理负载=逻辑/副本数；node0 手算全过程：82.5,82.5,73,61,52,52,39,4 → 四卡 121.5/86.5/125/113）；最终 8 卡负载 86.5–156，与官方输出逐槽一致（N1）。
  3. 触发条件：num_groups % num_nodes != 0 或 decode 大 EP；同例全局重算：复制 e10,e5,e1,e4，8 卡负载 95.5–138.5，max/mean 1.07 vs 层次 1.21；全局更均衡但组可能跨节点。
- 对应范围：C3、C5、C7、C19、N1、N2。
- 正文要点：组与组受限路由、三步机制、完整手算、官方输出核对、全局策略与取舍。
- 表达材料：
  - SVG 排布图（最终方案：2 节点 × 4 GPU × 2 专家槽，冗余副本用 dg-accent 描边，坐标脚本预计算）；
  - 手算表格（Step1 组打包、Step2 副本、Step3 GPU 负载）；
  - 对照表（层次 vs 全局：触发条件、复制范围、组局部性、GPU 负载区间、max/mean）；
  - 伪代码折叠块（三步算法）；
  - 可运行代码折叠块（纯 Python 复刻，输出 = 官方 tensor）。
- 前置知识：第 2 章贪心；C3/C19 已在本章给出。

### 第 4 章 周期性重平衡——从线上统计到权重搬运

- 章节问题：
  1. 重平衡的完整闭环是什么？各环节多久一次？
  2. V3 的 prefill 与 decode 部署分别怎么用冗余专家？
  3. vLLM 里怎么启用 EPLB？参数、每卡专家数与内存开销怎么算？
- 完成答案要点：
  1. 闭环：每次前向收集负载统计 → 每 T 重算排布（V3 线上约每 10 分钟；vLLM 默认每 3000 步、用最近 1000 步窗口）→ 搬运权重 + 更新物理映射与路由表 → 继续服务；负载预测不在 EPLB 范围（移动平均是常见做法，C4）。
  2. prefill：4 节点 32 卡、EP32、32 冗余、每卡 8+1，节点内重排不增加跨节点 all-toall（C10）；decode：40 节点 320 卡、EP320、每卡 1 专家、64 卡承载冗余+共享、共享专家视为必选路由专家（每 token 9 专家）、无需重排（C11）。
  3. vLLM：--enable-eplb；参数表（window_size/step_interval/num_redundant_experts/log_balancedness/policy）；每卡专家数 = (总数+冗余)/EP（V3 EP32：(256+32)/32=9，与报告 8+1 一致）；内存开销公式与 2.4 GB 数字；preserve_intragpu_slots 减少搬运（C16）。
- 对应范围：C4、C10、C11、C13、C14、C15、C16、N4、N5、N6。
- 正文要点：闭环各环节、V3 两个阶段部署、vLLM 参数与公式、槽位保持。
- 表达材料：dg-flow 闭环图（统计→重算→搬运→更新，循环箭头说明）；vLLM 参数表；V3 部署对照表（prefill vs decode）；补充折叠块（V3 动态冗余探索：每卡 16 只激活 9，C18）。
- 前置知识：model-parallelism 链接（TP4/DP8 术语，一句话）。

### 第 5 章 边界——EPLB 不解决什么

- 章节问题：
  1. 哪些问题被官方明确划出范围？
  2. EPLB 的贪心与约束意味着什么做不到的事？后续工作往哪走？
- 完成答案要点：
  1. 负载预测（C4）；路由层均衡（bias 调选谁、EPLB 调放哪，互补两层）；通信 kernel 效率（DeepEP 等另属一题）。
  2. 贪心非最优（构造例层次 1.21 vs 全局 1.07，且全局也非最优解）；整除约束（C9）；冗余占显存（C15 公式）；周期性重排有滞后，跟不上实时漂移——UltraEP 用配额实时规划、MoonEP 追求每 rank 恰好 S×K token（链接两页）。
- 对应范围：C4、C9、C13、C15、N2（取舍数字）；相邻概念链接。
- 正文要点：四条边界逐条给出「不解决什么 + 谁解决/怎么绕」。
- 表达材料：边界对照表（问题 / EPLB 是否管 / 谁管）。
