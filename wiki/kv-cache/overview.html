概念概览 · KV cache

KV cache（键值缓存）：让每个新 token 免于重算全部历史

推理时保存每个 token 在每层的注意力 $k/v$ 向量：与查询无关，算一次可反复用，把自回归生成的平方级重算降为线性——代价是线性增长的显存占用。

更新于 2026-08-19

这是什么

KV cache 是推理时保存的注意力 key/value 张量：每个 token 在每一层算出的 $k$、$v$ 向量被留下来，后续每步生成直接读取，不再重算。它解决的问题是自回归生成的重复计算——每个新 token 的注意力都需要全部历史的 K/V。

为什么需要它

注意力中第 $t$ 个 token 的查询 $q_t$ 要与全部历史 $k_1,\ldots,k_t$ 计算相似度并聚合全部 $v_1,\ldots,v_t$。这些 $k_i,v_i$ 只由第 $i$ 个 token 的输入与模型参数决定（$k_i=x_i W_K$），与当前查询无关，因此算一次即可反复使用。不缓存时生成 $n$ 个 token 需要约 $n^2/2$ 组 K/V 计算，缓存后降为 $n$ 组。

核心机制

  • 两阶段产生与使用：prefill 一次性并行处理全部输入 token 并写入其 KV cache；decode 每步只算 1 个新 token 的 $k,v$ 追加进缓存，用 $q$ 读取全部缓存。prefill 计算密集，decode 访存密集。
  • 大小公式：每 token 字节数 $=2\cdot L_{\text{layers}}\cdot H_{\text{kv}}\cdot d_{\text{head}}\cdot b$（K/V 两份、层数、KV 头数、头维度、每元素字节数）。GQA 通过减少 KV 头数直接缩小缓存。
  • 实例：Llama-3.1-8B（GQA，32 层、8 KV 头、头维 128、bf16）为 128 KB/token；20,000 token 文档约 2.44 GB，128K 上下文窗口的单请求 16 GB。MHA 的 OPT-13B 为 800 KB/token。

关键结论与边界

  • KV cache 随 token 数线性增长、随并发请求数相乘，且与静态模型权重共用显存（13B 模型 40GB A100 上权重约 65%、KV cache 约 30%）——40 GB 只够 Llama-3.1-8B 缓存约 0.3M token。
  • 缓存只省计算、不省存储：显存不足时只能逐出（重算）或分层（搬到 CPU/SSD 再搬回），这是分页管理、前缀缓存与分层传输等后续机制的全部动机。
  • 公式适用于标准 MHA/GQA 结构；KV 量化只改变 $b$，sliding window、稀疏注意力、MLA 等结构不在其内。
