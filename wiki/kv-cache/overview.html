KV Cache

KV cache 是自回归生成时把每层已算过的 key 和 value 留下来复用的机制，让生成每个新 token 时不必重算全部历史。

把每层算过的 key 和 value 存下来

大语言模型写文本时一次只预测一个 token——token 是模型读写文本的最小单位，可以是一个词，也可以是词的一部分——而每个新 token 都要用到前面所有 token 的信息，这种一个接一个往下写的方式叫自回归生成。模型由若干结构相同的层堆叠而成，每层里都有一层注意力：它把每个位置的输入投影成三个向量，分别是 query、key 和 value，算某个位置的输出时，用它的 query 去和各个位置的 key 比较，按比较结果把对应的 value 加权求和。KV cache 做的事，就是在这个逐步生成的过程中，把每一层已经算出来的 key 和 value 留在显存（GPU 的内存）里，供后面的 token 直接取用，省去重算。

不存就要每步重算全部历史

模型每预测一个新 token，都要用到全部历史 token 的 key 和 value。如果每次都用时才算，那么生成第 $t$ 个 token 时，要从头把整段序列重算一遍：不光当前这个位置要算，前面 $t-1$ 个位置也要连同它们的注意力一起重新过一遍。序列长度指已经生成的 token 个数。不缓存时，每步都要这样重跑一遍，每步开销随序列长度二次增长；缓存后每步只算当前这一个位置、只和已有的各个位置各比较一次，开销随长度线性增长。

每步只算新 token，追加进缓存

有了缓存之后，每步对当前这个 token 算它的 query、key 和 value：key 和 value 接在缓存里旧的部分之后，追加进缓存；query 拿去和缓存里的全部 key 比较，按比较结果把缓存里的全部 value 加权求和，得到这一步的输出。历史的 key 和 value 不再重算，每步只往缓存里加一个新 token 的量，旧的部分保持不变。
