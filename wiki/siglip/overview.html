SigLIP

把 CLIP 的 softmax 对比损失换成逐对 sigmoid 二分类损失——每个 (image, text) 对独立判断"配不配"，不需 batch 内全局归一化。

更新于 2026-08-09 · 依据 Zhai et al. 2023 ICCV Oral, arXiv:2303.15343v4

是什么

SigLIP（Sigmoid Loss for Language-Image Pre-training，Zhai et al. 2023）是一种视觉-语言对比预训练的损失函数。模型架构与 CLIP（Radford et al. 2021）完全相同（图像塔常用 ViT + 文本塔常用 Transformer + 共享嵌入空间 + 可学习温度），只是把 CLIP 的 softmax 对比损失换成 sigmoid 二分类损失：对 batch 内所有 $|B|\times|B|$ 个 (image, text) 对独立计算 $\log\sigma(z_{ij}(t\,x_i\cdot y_j+b))$，其中 $z_{ij}=+1$ 表示配对、$-1$ 表示不配对，$t$ 是可学习温度、$b$ 是可学习 bias。CLIP 的 softmax 分母 $\sum_j e^{t\,x_i\cdot y_j}$ 被去掉——每个对的梯度不再依赖 batch 内其他对。

为什么需要它

  • CLIP softmax 分母 $\sum_j e^{t\,x_i\cdot y_j}$ 让每个对的梯度依赖整个 batch 的所有嵌入；某个对的训练信号是"对 hardest negative 的相对优势"，batch 小时 hardest negative 往往太弱、梯度噪声大。
  • 分布式训练时每个设备需要 all-gather 全部 $|B|$ 个嵌入到本地才能算分母——这是 CLIP 训练在多设备上的核心通信瓶颈。
  • softmax 数值不稳定问题早已通过 log-sum-exp trick 解决，所以这不是 SigLIP 的主要动机；论文 §3.2 明确动机是"conceptually decouples the batch size from the definition of the task"——把 batch size 与损失定义解耦。
  • SigLIP 让小算力场景（4 个 TPUv4 / 2 天）能训出强 zero-shot 模型；CLIP 在同等算力下几乎不可行。

核心直觉

  • 每个对独立。CLIP 把每个图像看作"$|B|$ 选 1"多分类，正确文本应胜过其他所有；SigLIP 把每个 (image, text) 对看作独立的"配不配"二分类，不要求"胜过其他文本"。
  • 无分母耦合。CLIP 每个对的损失通过分母 $\sum_j$ 与所有 $y_j$ 耦合；SigLIP 每对 $\log\sigma(z_{ij}(t\,x_i\cdot y_j+b))$ 只依赖该对的 $x_i, y_j, z_{ij}, t, b$，独立求和。
  • batch 解耦。softmax 依赖 batch 内 hard negative 池；sigmoid 不依赖——小 batch 下仍能产生固定幅度的梯度，因此 SigLIP 在 batch < 16k 时显著优于 softmax（论文 §4.2）。
  • 可学习 bias $b$ 是关键。batch 内正对仅 $|B|$ 个、负对 $|B|^2-|B|$ 个，比例 $1:(|B|-1)$；$|B|=32\text{k}$ 时 1:32767。若没有 $b$，初始 logits 偏向"大多数负对"使训练初期产生大量错误方向梯度。$b$ 初始化为 $-10$，让 $\sigma(b)=\sigma(-10)\approx 0.0000454$，等价于"初始时预测偏向负类"（与数据先验一致），少数正对的大梯度抵消多数负对的数量优势。
  • 分布式友好。每个对独立计算使 chunked 实现成为可能——batch 可切分到多设备，逐次 swap 文本嵌入并累加损失，避免 all-gather（论文 §3.3）。

关键结论与边界

  • SigLiT 84.5% / 4 TPUv4 / 2 天。冻结 ViT-g/14 + Large 文本塔，batch 20k，训 107k 步，ImageNet zero-shot 84.5%（论文 Table 1 + §4.4）。CLIP 在此算力级别几乎不可行。
  • SigLIP from scratch 72.1% / 32 TPUv4 / 2 天。对照 CLIP 同水平 72.6% 用约 2500 TPUv3-days（论文 §4.5 末段引用 [30]）。SigLIP 用 64 TPUv4-days 达到 CLIP 同水平，算力大幅降低。
  • 32k batch 接近最优。ImageNet zero-shot 在 32k 达 73.2%，更大 batch 几乎不再提升；多语言 retrieval 反而下降（XM avg 34.9 → 32.7，XM zh 32.5 → 23.7）；batch = 1 M 边际收益快速消失（论文摘要 + Table 2）。成立条件：Base 模型 + 30B examples seen。
  • SigLIP 不是普遍比 CLIP 好。论文 §4.2 明确显示 sigmoid 显著优于 softmax 仅在 batch < 16k；batch 增大时优势缩小。
  • K3 选择"不从 SigLIP 初始化"。MoonViT-V2 的目标是"视频 + 自定义训练目标"，与 SigLIP 的"静态图像 + 对比损失"目标不同；K3 选择从零训练更稳定，与 SigLIP 质量无关。详见 MoonViT-V2 概念页。
