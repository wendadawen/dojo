    OPD（On-Policy Distillation）：学生自己生成、教师逐 token 打分

    主要依据：Agarwal et al. 2023《On-Policy Distillation of Language Models: Learning from Self-Generated Mistakes》（GKD 论文，arXiv:2306.13649）；Lu & Thinking Machines Lab 2025《On-Policy Distillation》；Qwen3 Technical Report §4.5 / §4.7（arXiv:2505.09388）；Kimi K3 Technical Report §4.1.3（arXiv:2607.24653）。

    同一个 Qwen3-8B、同一个蒸馏起点，两条继续训练的路线给出的账单差别悬殊：走强化学习，AIME'24 从 55.0 提到 67.6，花 17,920 GPU 小时；换 on-policy 蒸馏，提到 74.4，只花 1,800 小时——约十分之一的成本、更高的分数[C8, N1]。便宜的关键差别只有一处：强化学习等学生把整道题做完，只对最终答案发一次奖励；on-policy 蒸馏让学生自己写，教师对学生写下的每一个 token 打一次分。

    On-policy Distillation（OPD，在线策略蒸馏）是一种把已训练好的强教师模型的能力转移给学生模型的训练方法：训练序列不是教师生成的，而是学生当前策略自己采样出的轨迹——这就是 on-policy 的含义；教师不重写答案，只在学生实际到达的每个位置上，对学生采样的那个 token 给出一个分数——教师概率与学生概率之比的对数。这个逐 token 的分数作为稠密信号进入学生的更新。

    本文的学习目标包括：说明 off-policy 蒸馏在自回归模型上的分布失配与 OPD 的解法；描述 OPD 一步训练的完整机制；手算一个 3-token 词表下的逐 token 分数并判断更新方向；从信号密度与实测数字说明 OPD 相比强化学习的效率来源；说明 OPD 的能力边界与失效条件。

    先看失配是怎么发生的。一个学生模型解数学题时写下了"显然可得"——一个教师不会写的跳跃步骤。off-policy 蒸馏帮不上忙：教师给出的训练例子里全是"设未知数"这样的规整步骤，学生推理时却要不断接续自己写下的前缀；一旦早期走偏，之后的每一步都发生在训练时从未出现过的语境里。为什么训练序列的来源这么关键，下一章从分布失配讲起。

    核心问题

    1. 为什么在教师生成的序列上训练学生（off-policy 蒸馏）会在推理时失配，on-policy 蒸馏如何消除这个失配？

      解答：训练分布与推理分布不一致导致复合误差，换训练数据来源可消除

      off-policy 蒸馏训练时学生只见过教师（或数据集）的前缀，推理时却要接续自己生成的前缀；早期一个教师不会犯的错就把学生带进训练从未覆盖的状态，误差复合放大。OPD 把训练分布换成学生自己的生成分布（GKD，即 Generalized Knowledge Distillation 框架的 $\lambda=1$ 端点），教师反馈在学生实际到达的每个状态上给出，训练-推理失配消失。见"1. 为什么需要 on-policy"一章。

    2. OPD 一步训练的完整机制是什么——学生怎么采样、教师怎么打分、分数怎么进入更新？

      解答：学生采样、教师一次前向、对数概率比作 advantage 进策略梯度

      四步：学生采样 token（采样时顺手得到学生 logprob）；教师对学生轨迹做一次前向读出教师 logprob；逐 token 计算分数 $r=\log(\pi_{\text{teacher}}(y_t)/\pi_S(y_t))$（即负的 per-token reverse KL 采样值）；$r$ 作为该 token 的 advantage（优势值，策略梯度中的标量乘子）乘进 $\nabla\log\pi_S(y_t)$ 完成更新。教师参数不变、梯度不从教师流向学生。见"2. 机制"一章。

    3. 手算：给定教师与学生在某前缀下的 next-token 分布和学生实际采样的 token，分数是多少、更新方向是什么？

      解答：教师更认可的 token 得正分被鼓励，反之被抑制

      构造示例：学生 $(0.3,0.4,0.3)$、教师 $(0.6,0.3,0.1)$ 时，采样 A 得 $r=\ln 2\approx+0.693$（鼓励），采样 B 得 $\ln 0.75\approx-0.288$（抑制），采样 C 得 $\ln(1/3)\approx-1.099$（强抑制）；期望分数等于负的 reverse KL（例中 $\approx-0.237$）。见"2. 机制"一章。

    4. 相比带奖励模型的强化学习，OPD 的样本效率和计算效率来自哪里？有哪些实测证据？

      解答：逐 token 稠密信号，配教师只需一次前向；三组实测数字

      效率来源：每个 episode 传递 $O(N)$ bits（强化学习只有 $O(1)$ bits）；reverse KL 意义上不可被 hack；不需要单独的奖励模型；不需要完整 rollout；教师只需一次前向、轨迹由更便宜的学生生成。证据：Qwen3 Table 21（约 1/10 GPU 小时且分数更高）、Thinking Machines 的 9–30× 成本缩减与 7–10× 梯度步、GKD 的任务级改进。见"3. 为什么比 RL 便宜"一章。

    5. OPD 不能做什么？什么条件下会失效？

      解答：只转移教师已有能力，教师弱或覆盖不足时失效

      OPD 不发明新能力——强化学习是搜索、能发现新策略，蒸馏只学已有策略的最终形态；学生学习以教师分布为参照（方向性结论）；教师策略必须落在学生初始化的支持集内，否则要先 SFT 扩支持集或显著加大 batch；需要可查询 logprobs 的强教师与能消费 per-token advantage 的训练框架。见"4. 实现选择"与"5. 边界"两章。

    常见误解

    • "on-policy 蒸馏就是用学生自己生成的数据做 SFT"——少了关键一半：教师逐 token 反馈。Thinking Machines 的对照实验显示，自采样 SFT 在任何大于零的实用学习率下都会导致指令遵循评估上的退化，OPD 的要点不是"数据来自学生"，而是教师反馈持续校准学生访问的每个状态。
    • "教师的梯度会回传到学生"——不会。教师只输出标量分数（一次前向），分数是常数乘子；更新只经过学生的 $\nabla\log\pi_S(y_t)$，教师参数不变。K3 用停梯度算子 $\text{sg}$ 把这一点显式化。
    • "蒸馏能让学生超越教师、学会教师不会的东西"——信号方向始终指向教师分布，要超越教师需要带任务奖励的强化学习探索；GKD 自蒸馏实验中学生测试分数超过教师，是本文推断的分布匹配下的评估特例（来源只登记现象、未作解释），不是新能力。
    • "OPD 必须用 reverse KL"——散度是自由度。GKD 框架里 forward KL、reverse KL、广义 JSD 都可以，最优选择任务相关；Thinking Machines 与 K3 的实践恰好都取 reverse KL 形式。

    1. 为什么需要 on-policy——学生会在训练没见过的状态上犯错

    本文讨论的 on-policy 蒸馏以 off-policy 蒸馏为对照基准：教师生成完整序列（或使用固定数据集）、学生在这些序列上拟合的形态，也就是 知识蒸馏 页讲解的 Hinton 蒸馏（监督蒸馏）与序列级蒸馏（SeqKD）。该页说明了软分布携带什么信息；本文只用其结论，不重复展开。

    两个词先说清楚。训练序列从哪里来，决定一个训练过程是 off-policy 还是 on-policy：训练序列来自固定数据集或教师策略，是 off-policy——这些序列不是学生自己会生成的；训练序列由学生当前策略 $\pi_S$ 自己采样，是 on-policy——训练分布就是学生此刻的生成分布。

    off-policy 蒸馏在自回归模型上有一个结构性缺陷。Agarwal 等人 2023 年把它表述为蒸馏方法的核心动机：现有 KD 方法"在训练见到的输出序列与学生推理时自己生成的序列之间存在分布失配"[C1]。失配为什么致命——复合误差：学生推理时一旦早期犯一个教师不会犯的错，就会"偏离训练时观察到的状态越来越远"[C1]。教师的反馈从来没有覆盖这些状态；学生在没有信号的地方继续生成，每一步都比上一步更偏离训练分布。

    on-policy 的定义性事实：OPD 的训练分布就是学生自己的生成分布。这不是工程偏好而是方法定义——教师打分发生在学生实际到达的每个状态（前缀）上，因此不存在"训练时的状态"与"推理时的状态"两套分布。这个思路有谱系：模仿学习里的 DAGGER（Ross et al. 2010）靠"教师评估学生所到状态"迭代修正分布失配，过程奖励模型对推理每一步打分也是同样的粒度思想（两个出处均见 Thinking Machines 博文的谱系说明）。

    同一个工作给出了统一的框架：GKD（Generalized Knowledge Distillation）。训练目标仍然是在序列上最小化教师与学生的逐 token 散度，但"序列从哪来"变成一个连续参数——学生数据比例 $\lambda\in[0,1]$[C2, F3]：

    $$L(\theta)=(1-\lambda)\,\mathbb{E}_{(x,y)\sim(X,Y)}\big[\mathcal{D}(\pi_{\text{teacher}}\|\pi_S^{\theta})(y\mid x)\big]+\lambda\,\mathbb{E}_{x\sim X}\Big[\mathbb{E}_{y\sim\pi_S(\cdot\mid x)}\big[\mathcal{D}(\pi_{\text{teacher}}\|\pi_S^{\theta})(y\mid x)\big]\Big]$$
    • $\lambda\in[0,1]$：学生数据比例；前一项在固定数据集上、后一项在学生自采样上。
    • $(X,Y)$：固定数据集中的输入-输出对，可以是真实标签也可以是教师生成序列。
    • $\pi_S^\theta$：参数为 $\theta$ 的学生策略；自采样项里 $y\sim\pi_S(\cdot\mid x)$ 且不对采样过程反向传播。
    • $\mathcal{D}$：师生分布的散度（KL 或 JSD，见"4. 实现选择"）。

    $\lambda=0$ 退化为监督蒸馏（supervised KD），$\lambda=1$ 就是在线策略蒸馏（on-policy KD）——GKD 论文原话："监督蒸馏与 on-policy 蒸馏分别是 GKD 把散度设为 forward KL、学生数据比例 $\lambda$ 取 0 和 1 的实例"[C2]。实现上 GKD 不对学生的采样过程反向传播，训练稳定且计算高效[C2]。

    本章问题

    1. 为什么学生推理时的错误会越滚越大，而 off-policy 蒸馏帮不上忙？

      解答：错误前缀是训练分布外的状态，反馈从未覆盖

      off-policy 蒸馏训练时学生只见过教师或数据集的前缀；学生推理时接续的是自己生成的前缀，早期一个教师不会犯的错就把它带进训练从未覆盖的状态，之后步步失配、误差复合放大。教师的逐 token 反馈只在训练序列的状态上给过，覆盖不到这些新状态。

    2. GKD 框架里 $\lambda$ 从 0 调到 1 改变了什么，没改变什么？

      解答：只换训练序列来源，打分方式不变

      $\lambda$ 是学生数据比例：$\lambda=0$ 时训练序列全部来自固定数据集（监督蒸馏），$\lambda=1$ 时全部由学生自己采样（on-policy 蒸馏），中间值混合两种来源。改变的是"学生学习的状态是哪些"，不变的是训练目标本身——在序列上最小化教师与学生的逐 token 散度。实现上都不对学生的采样过程反向传播。

    2. 机制——学生采样、教师逐 token 打分

    训练序列的来源换成学生自己之后，下一个问题是教师在这条轨迹上到底怎么"教"。先把打分的粒度说精确：GKD 把教师-学生的差异定义为逐位置的 next-token 分布散度、按序列长度取平均[C3, F2]：

    $$\mathcal{D}(\pi_{\text{teacher}}\|\pi_S)(y\mid x):=\frac{1}{L_y}\sum_{n=1}^{L_y}\mathcal{D}\big(\pi_{\text{teacher}}(\cdot\mid y_{<n},x)\,\big\|\,\pi_S(\cdot\mid y_{<n},x)\big)$$
    • $L_y$：输出序列 $y$ 的长度；散度在每个位置上算、按长度平均。
    • $n$：位置索引，对应"已生成前缀 $y_{<n}$ 后下一个 token 的分布"。
    • $\pi_{\text{teacher}}(\cdot\mid y_{<n},x)$：教师在位置 $n$ 的 next-token 概率分布。
    • $\pi_S(\cdot\mid y_{<n},x)$：学生同一位置上的 next-token 概率分布。
    • $\mathcal{D}$：该位置上的散度（KL、JSD 等）。

    散度不作用在整段序列的概率上，而是作用在每个位置 $n$ 的"下一个 token 的分布"上。这决定了反馈天然是逐 token 的。本文最常用的散度是 KL 散度（最小定义）：$\mathrm{KL}(P\|Q)=\sum_c P(c)\log\big(P(c)/Q(c)\big)$，衡量用 $Q$ 近似 $P$ 的差异，方向不对称；其中 $\mathrm{KL}(\pi_S\|\pi_{\text{teacher}})$ 这个方向（期望在学生分布上取）习惯上叫 reverse KL。

    Thinking Machines 的实现把 on-policy 蒸馏落成强化学习栈里的四步[C4]：

    分数的定义只有一行[C4, F4]：

    $$r(y_t\mid x,y_{<t})=\log\pi_{\text{teacher}}(y_t\mid x,y_{<t})-\log\pi_S(y_t\mid x,y_{<t})=\log\frac{\pi_{\text{teacher}}(y_t\mid x,y_{<t})}{\pi_S(y_t\mid x,y_{<t})}$$
    • $x$：输入 query。
    • $y_{<t}$：第 $t$ 个 token 之前已生成的前缀。
    • $y_t$：学生在 $y_{<t}$ 之后采样的 token；分数仅与这个被采样的 token 有关。
    • $\pi_{\text{teacher}}(y_t\mid x,y_{<t})$、$\pi_S(y_t\mid x,y_{<t})$：教师与学生在该位置给 $y_t$ 的概率。

    教师比学生更认可这个 token，分数为正；更不认可，为负。这个数在 Thinking Machines 的记法里就是该 token 的负 reverse KL 采样值——原话是"我们把 per-token advantage 设为负的 reverse KL，然后调用 RL 的 importance-sampling 损失对学生做训练更新"[C4]。折扣因子取零：学生只优化眼前的下一个 token，不对未来 token 做信用分配；实验中非零折扣并没有改善性能[C4]。

    分数怎么变成参数更新？这里需要策略梯度的最小定义：参数更新正比于 $\nabla_\theta\log\pi_S(y_t)\cdot A$（完整条件 $x,y_{<t}$ 见上图），其中 $A$ 是一个标量乘子（advantage）。$A$ 为正时这一步抬高被采样 token 的对数概率，为负时压低。OPD 把 $r(y_t)$ 直接放进 $A$ 的位置[C4]。计算上有一个重要不对称：学生采样时本来就要算自己的 logprob（importance-sampling 损失需要它）；教师那边只需要对学生轨迹做一次前向读出 logprob，"不需要把 logprob 从教师模型里反传"[C4]。对已有带 KL 正则的强化学习实现，接入蒸馏是"换掉正则模型"级别的改动[C4]。

    教师是奖励来源，不是梯度来源。教师对学生轨迹做一次前向、输出标量分数，分数作为常数乘子进入学生的更新；梯度只走 $\nabla\log\pi_S(y_t)$ 这一条路径，教师参数不更新。Kimi K3 在 MOPD 里把这个机制显式化：分数外层套裁剪 $\text{clip}$、内层套停梯度 $\text{sg}$，即 $\text{clip}(\text{sg}(\cdot),-R_{\max},R_{\max})$，作为稠密奖励接入 RL 框架、支持 partial rollout[C16, F6]。$\text{sg}$ 把"分数是常数"写进公式，$\text{clip}$ 截断极端分数。完整的多教师机制见 MOPD 页。

    构造示例。3-token 词表 $\{A,B,C\}$，某个前缀下学生与教师的 next-token 分布如下，逐 token 分数一并列出：

    token学生 $\pi_S$教师 $\pi_{\text{teacher}}$分数 $r=\log(\pi_{\text{teacher}}/\pi_S)$更新方向
    A$0.3$$0.6$$\ln 2\approx+0.693$抬高 $\log\pi_S(A)$
    B$0.4$$0.3$$\ln 0.75\approx-0.288$压低 $\log\pi_S(B)$
    C$0.3$$0.1$$\ln(1/3)\approx-1.099$压低 $\log\pi_S(C)$

    学生自己采样：采到 B 的概率最大（$0.4$），但采到 B 得到负分——这一步会压低 $\log\pi_S(B)$；采到 A 得正分，抬高 $\log\pi_S(A)$；采到 C 得到三个里最强的负分。训练把学生的分布从 $(0.3,0.4,0.3)$ 往教师的 $(0.6,0.3,0.1)$ 推。注意打分不重写答案：教师不告诉学生"该写 A"，只在学生写下的 token 上给方向信号。

    前缀推进后分布改变，打分跟着状态走。学生选了 A 之后，新的前缀下学生 $(0.5,0.3,0.2)$、教师 $(0.2,0.5,0.3)$；此时采样 B 得 $r=\ln(0.5/0.3)\approx+0.511$。同一个 token B，在第一个位置被抑制、在第二个位置被鼓励——分数永远在学生实际到达的状态上计算，这正是 on-policy 的价值。

    把三种采样结果按学生自己的概率加权，得到期望分数。代入数字：

    $$\mathbb{E}[r]=0.3\times 0.693+0.4\times(-0.288)+0.3\times(-1.099)\approx-0.237$$

    而同一组分布的 reverse KL $\approx+0.237$。期望分数恰好等于负的 reverse KL[F5]：

    $$\mathbb{E}_{y_t\sim\pi_S}\big[r(y_t)\big]=\sum_c \pi_S(c)\log\frac{\pi_{\text{teacher}}(c)}{\pi_S(c)}=-\mathrm{KL}(\pi_S\|\pi_{\text{teacher}})$$
    • $c$：词表中的一个 token（本例中即 A、B、C），求和遍历整个词表。
    • $\pi_S(c)$、$\pi_{\text{teacher}}(c)$：学生与教师在同一前缀下给 token $c$ 的概率；期望按学生的 next-token 分布加权。

    "advantage = 负 reverse KL"在这个例子里逐位对上。完整手算见下方折叠块；期望意义上策略梯度视角与散度视角的等价推导见第二个折叠块。

    展开：期望分数与 reverse KL 的完整手算

    构造示例，沿用正文 3-token 词表。期望分数逐项展开：

    $$\mathbb{E}[r]=0.3\times\ln\tfrac{0.6}{0.3}+0.4\times\ln\tfrac{0.3}{0.4}+0.3\times\ln\tfrac{0.1}{0.3}$$

    $$=0.3\times 0.693+0.4\times(-0.288)+0.3\times(-1.099)=0.208-0.115-0.329\approx-0.237$$

    reverse KL 逐项展开：

    $$\mathrm{KL}(\pi_S\|\pi_{\text{teacher}})=0.3\times\ln\tfrac{0.3}{0.6}+0.4\times\ln\tfrac{0.4}{0.3}+0.3\times\ln\tfrac{0.3}{0.1}$$

    $$=0.3\times(-0.693)+0.4\times 0.288+0.3\times 1.099=-0.208+0.115+0.329\approx+0.237$$

    两式每一项互为相反数（同一个对数比值取负、乘的是同一个 $\pi_S(c)$），因此整体相差一个符号，验证 $\mathbb{E}[r]=-\mathrm{KL}(\pi_S\|\pi_{\text{teacher}})$。

    补充：策略梯度视角与散度视角的等价推导[F7]

    推导（由定义直接推出，非外部公式）。在同一前缀的位置上，把 $r=\log(\pi_{\text{teacher}}/\pi_S)$ 代入策略梯度的期望：

    $$\mathbb{E}_{y\sim\pi_S}\big[\nabla_\theta\log\pi_S(y)\cdot r(y)\big]=\mathbb{E}_{y\sim\pi_S}\Big[\nabla_\theta\log\pi_S(y)\cdot\log\tfrac{\pi_{\text{teacher}}(y)}{\pi_S(y)}\Big]$$

    关键一步是 log-derivative 恒等式 $\nabla_\theta\pi_S(y)=\pi_S(y)\,\nabla_\theta\log\pi_S(y)$。对 reverse KL 求梯度（教师不依赖 $\theta$）：

    $$\nabla_\theta\,\mathrm{KL}(\pi_S\|\pi_{\text{teacher}})=\sum_c\nabla_\theta\pi_S(c)\Big[\log\tfrac{\pi_S(c)}{\pi_{\text{teacher}}(c)}+1\Big]=\mathbb{E}_{y\sim\pi_S}\Big[\nabla_\theta\log\pi_S(y)\cdot\log\tfrac{\pi_S(y)}{\pi_{\text{teacher}}(y)}\Big]$$

    其中常数项 $\sum_c\nabla_\theta\pi_S(c)=\nabla_\theta 1=0$ 被消去。两个期望只差一个负号：带 $r$ 的策略梯度期望恰是 $-\nabla_\theta\mathrm{KL}(\pi_S\|\pi_{\text{teacher}})$ 的无偏估计。所以"最小化 reverse KL"（GKD 的散度视角，$\lambda=1$）与"把 $r$ 当 advantage 走策略梯度"（Thinking Machines 的 RL 视角）在期望更新方向上一致——前提是不对采样过程反向传播，这正是 GKD 的做法。逐位置求和再按长度平均，就回到 GKD 的 per-token 散度形式。

    代码：复算逐 token 分数并验证期望分数等于负 reverse KL 
    import math, random

# 位置 t：教师与学生对 3-token 词表 {A, B, C} 的 next-token 分布
teacher = [0.6, 0.3, 0.1]
student = [0.3, 0.4, 0.3]

# 逐 token 分数 r = log(pi_teacher / pi_student)
for i, name in enumerate("ABC"):
    r = math.log(teacher[i] / student[i])
    print(f"采样 {name}: r = ln({teacher[i]}/{student[i]}) = {r:+.3f}")

# 期望分数（精确计算）与 reverse KL 对照
exp_r = sum(p * math.log(t / s) for p, t, s in zip(student, teacher, student))
kl = sum(p * math.log(s / t) for p, s, t in zip(student, student, teacher))
print(f"E[r]        = {exp_r:+.4f}")
print(f"KL(S || T)  = {kl:+.4f}   (E[r] = -KL)")

# 蒙特卡洛验证：学生按自己的分布采样 200000 个 token
random.seed(0)
n, total = 200000, 0.0
for _ in range(n):
    u, acc, i = random.random(), 0.0, 0
    for j, p in enumerate(student):
        acc += p
        if u < acc:
            i = j
            break
    total += math.log(teacher[i] / student[i])
print(f"蒙特卡洛 E[r]（{n} 次采样）= {total / n:+.4f}")

# 第二位置：前缀推进后分布改变，同一个 token 的分数随之改变
teacher2, student2 = [0.2, 0.5, 0.3], [0.5, 0.3, 0.2]
r2 = math.log(teacher2[1] / student2[1])
print(f"第二位置采样 B: r = ln({teacher2[1]}/{student2[1]}) = {r2:+.3f}")

    预期输出：

    采样 A: r = ln(0.6/0.3) = +0.693
采样 B: r = ln(0.3/0.4) = -0.288
采样 C: r = ln(0.1/0.3) = -1.099
E[r]        = -0.2367
KL(S || T)  = +0.2367   (E[r] = -KL)
蒙特卡洛 E[r]（200000 次采样）= -0.2363
第二位置采样 B: r = ln(0.5/0.3) = +0.511

    验证的机制：逐 token 分数公式 $r=\log(\pi_{\text{teacher}}/\pi_S)$ 对应正文表格的三个值；期望分数与 reverse KL 的精确对照对应恒等式 $\mathbb{E}[r]=-\mathrm{KL}(\pi_S\|\pi_{\text{teacher}})$；第二位置对应"分数随学生实际到达的状态改变"。

    观察重点：蒙特卡洛估计（$-0.2363$）落在精确值（$-0.2367$）附近——期望分数确实由学生的采样分布加权，学生最偏好的 token B 同时是得负分的 token。

    简化条件：3-token 词表与固定前缀代替真实词表与多变前缀；省略采样温度、批量组织、优化器与参数化；验证的是分数计算与期望恒等式，不是训练收敛过程。

    本章问题

    1. 教师对学生的"打分"具体是什么数，怎么算出来的？

      解答：教师概率与学生概率之比的对数，一次前向即可得到

      学生在前缀 $y_{<t}$ 后采样 $y_t$；教师对学生轨迹做一次前向读出 $\log\pi_{\text{teacher}}(y_t)$，学生的 $\log\pi_S(y_t)$ 在采样时已经算出。分数 $r=\log\pi_{\text{teacher}}(y_t)-\log\pi_S(y_t)$：教师更认可为正、更不认可为负。它同时是该 token 的负 reverse KL 采样值，折扣因子取零意味着学生只优化下一个 token。

    2. 这个分数怎么变成参数更新？教师参数会变吗？

      解答：作 advantage 乘进策略梯度，教师不变

      分数 $r$ 作为该 token 的 advantage 放进策略梯度 $\nabla_\theta\log\pi_S(y_t)\cdot r$：正分数抬高被采样 token 的对数概率，负分数压低。分数是常数乘子，梯度只经过学生一侧；教师参数不更新——K3 的 $\text{sg}$ 算子把这一点显式化。对带 KL 正则的 RL 实现，接入只需换掉正则模型。

    3. GKD 的散度视角和 Thinking Machines 的 advantage 视角矛盾吗？

      解答：期望更新方向一致

      不矛盾。用 log-derivative 恒等式可以推出：带 $r=\log(\pi_{\text{teacher}}/\pi_S)$ 的策略梯度期望恰是 $-\nabla_\theta\mathrm{KL}(\pi_S\|\pi_{\text{teacher}})$ 的无偏估计（推导见本章折叠块）。"最小化 reverse KL"与"把 $r$ 当 advantage"在期望上等价，前提是不对采样过程反向传播。

    3. 为什么比 RL 便宜——每个 token 都有信号

    机制清楚后，效率问题自然浮出：逐 token 打分到底比"做完再打分"多提供了什么？一句话说清：强化学习每个 episode 只教 $O(1)$ bits，蒸馏教 $O(N)$ bits[C5]。奖励模型对整段响应给一个分数，不管这段有多少 token——"每个训练 episode 传递固定数量的比特"；学生只知道"21 是错的"，不知道错在运算顺序还是算术本身。逐 token 分数把信息量变成与 token 数成正比。（下文 pass@64 记号：同一 prompt 采样 64 次、其中至少一次正确的比例，衡量模型的探索宽度。）

    维度强化学习（奖励模型 / 可验证奖励）on-policy 蒸馏
    奖励来源单独训练的奖励模型或规则验证教师模型的一次前向
    信号粒度序列级（稀疏）逐 token（稠密）
    每 episode 信息量$O(1)$ bits$O(N)$ bits
    能否被 hack奖励模型可能被 hackreverse KL 意义上不可 hack
    完整 rollout需要，且要在与评估相当的上下文长度上训练不需要，partial rollout 可用
    能力上限可以超过教师（探索新策略）以教师为参照

    逐项看。reverse KL "不可被 hack"：低 KL 总是对应教师视角下高概率的理想行为，真实场景的奖励模型通常不具备这个性质；同时也不需要单独训练一个奖励模型[C5]。逐 token 分数不需要等 rollout 跑完就能算，可以用更短、不完整的 rollout 训练[C6]；强化学习则必须在与评估相当的上下文长度上训练，否则策略学不到上下文限制、招致格式惩罚[C12]。计算不对称（第 2 章）：教师只需一次前向，轨迹由更便宜的学生生成[C4]。强 SFT 初始化下每 episode 的 bits 更多、梯度噪声更小，batch size 可以小得多[C12]——这个条件的另一面见下一章。

    逐 token 粒度还能看到序列级奖励看不到的东西。Thinking Machines 给了一个例子：学生在 SimpleBench 一道物理题上把它当纯数学题做错，教师（235B）惩罚的是把学生引偏的那些短语开头的 token——"分岔 token"（Thinking Machines 把它们与推理中的关键岔路点联系起来）；最终错误答案反而不被惩罚，因为它在给定前缀后完全可预测。逐 token 打分把纠错信号集中在真正决定走向的位置上（出自该博客的实验展示，作为粒度直觉的辅助解释）。

    实测证据有三组。第一组，Qwen3[C8, N1]：

    强化学习提 12.6 分花 17,920 GPU 小时，蒸馏提 19.4 分花 1,800——Qwen3 报告的结论是"蒸馏以大约只有十分之一的 GPU 小时取得明显更好的性能"[C8]。pass@64 上蒸馏从 90.0 提到 93.3、强化学习无提升（保持在 90.0）；Qwen3 的解读是"从教师 logits 蒸馏让学生扩展了探索空间、提升了推理潜力"，而强化学习"对 pass@64 没有带来任何提升"[C8]。实验条件：Qwen3-8B，比较只覆盖数学与代码类查询。

    第三组，GKD 的早期证据[C17, N3]：T5 系列（教师 T5-XL，学生 T5-small/base/large）上，GKD 相对基线蒸馏方法的任务级改进在摘要（XSum）、翻译（WMT）、算术（GSM8K）上分别是 2.1×、1.7×、1.9×；XSum 上 on-policy GKD 只用 5% 的子采样数据（10K 条）且不用真实标签，就超过用全量数据的监督蒸馏。学生采样带来的额外计算开销约 1.8–2.2 倍，换取的是数据效率[N3]。

    本章问题

    1. 为什么"每个 token 都有分数"能让训练步数少一个数量级？

      解答：每 episode 的信息量从 $O(1)$ bits 到 $O(N)$ bits

      强化学习的序列级奖励不管生成多少 token 都只传递固定比特数，学生不知道错在哪一步；逐 token 分数把信息量变成与 token 数成正比，梯度噪声更小。配套的省算路径：教师一次前向即可打分、无需单独的奖励模型、不需要等 rollout 跑完（partial rollout 可用）、强初始化下可用小 batch。

    2. "1,800 对 17,920 GPU 小时"这组数字的实验条件是什么，能推出什么、不能推出什么？

      解答：Qwen3-8B 的数学与代码查询，结论限于该配置

      条件：Qwen3-8B、同一个 off-policy 蒸馏起点、只比较数学与代码类查询。能推出：该配置下蒸馏以约 1/10 GPU 小时取得更高 AIME'24（74.4 对 67.6）且 pass@64 提升。不能推出：所有任务、所有规模上都如此；也不能推出蒸馏总是优于 RL——RL 的能力上限在教师之外（见"5. 边界"）。

    4. 实现选择——散度、初始化与 RL 的组合

    效率结论的成立有前提。打分用什么散度、学生初始化覆盖到什么程度，都会改变结果；蒸馏甚至可以和强化学习同时进行。这一章收拢这些选择。

    GKD 的第二个自由度是散度本身。三种常用选择[C11, F1]：

    散度方向 / 定义行为倾向
    forward KL$\mathrm{KL}(\pi_{\text{teacher}}\|\pi_S)$mass-covering：覆盖教师的多个模式
    reverse KL$\mathrm{KL}(\pi_S\|\pi_{\text{teacher}})$mode-seeking：集中到教师的单一行为
    广义 JSD($\beta$)对凸混合分布取两项 KL（公式见下）有界；$\beta\to 0$ 近似 forward KL、$\beta\to 1$ 近似 reverse KL
    $$\mathcal{D}_{JSD(\beta)}(P\|Q)=\beta\,\mathrm{KL}\big(P\|\beta P+(1-\beta)Q\big)+(1-\beta)\,\mathrm{KL}\big(Q\|\beta P+(1-\beta)Q\big)$$[F1]
    • $P$、$Q$：两个概率分布（本文中即教师与学生的 next-token 分布）。
    • $\beta\in(0,1)$：凸组合系数；$\beta\to 0$ 时 JSD 的梯度行为近似 forward KL，$\beta\to 1$ 时近似 reverse KL。
    • $M=\beta P+(1-\beta)Q$：$P$、$Q$ 的凸混合分布；KL 始终对该混合分布取。

    最优散度任务相关。GKD 的实验结论：温度采样评估下，mode-seeking 散度（reverse KL、JSD(0.9)）生成质量高但多样性低，"特定任务需要在多样性与性能之间权衡后选择散度"[C11]。Thinking Machines 选 reverse KL 有三个理由：mode-seeking——"学教师的一个具体行为，而不是把概率分散到多个次优选项"；与 RL 天然协同——RL 优化的本来就是奖励模型诱导出的某种序列级 reverse KL，而蒸馏的 reverse KL 不可 hack；以及支持集分工——"SFT 用 forward KL 负责给新 token 加支持，reverse KL 方法再在初始化的支持集内做模式寻求"[C11]。

    支持集分工直接给出一个硬条件：教师策略必须落在学生初始化的支持集（取非零概率的 token 集合）内。学生在某位置对教师高概率的 token 给出零概率时，reverse KL 推不动它——需要先用 SFT 或领域微调把支持集扩出来，或者"显著更大的 batch size"[C12]。反过来，强 SFT 初始化（教师策略已在支持集内）时蒸馏可以用小得多的 batch[C12]。Qwen3 的流水线正是这么安排的：先 off-policy 蒸馏打底——教师 /think 与 /no_think 两种模式的输出合并做响应蒸馏，让轻量学生先具备基础推理与模式切换能力；再进 on-policy 阶段——学生自己生成序列，logits 与教师（Qwen3-32B 或 Qwen3-235B-A22B）对齐、最小化 KL 散度[C7]（Qwen3 报告未指明此处 KL 的方向，此处保持同等粒度）。

    蒸馏还能与强化学习同时进行。GKD 把 RL 目标与蒸馏项加权组合：正则化对象从标准 RLHF（基于人类反馈的强化学习）的初始策略换成教师策略，$\alpha$ 控制蒸馏强度，$\alpha=1$ 退化为纯蒸馏；GKD 建议与 RL 组合时用 reverse KL 或 JSD(0.9)[C14]。公式与说明见折叠块。

    补充：GKD 把蒸馏与 RL 同时进行的组合目标（其公式 (5)）

    $$\mathbb{E}_{x\sim X}\Big[(1-\alpha)\,\mathbb{E}_{y\sim\pi_S^{\theta}}\big[r(y)\big]-\alpha\,\mathbb{E}_{y\sim\pi_S}\big[\mathcal{D}(\pi_{\text{teacher}}\|\pi_S^{\theta})(y\mid x)\big]\Big]$$[C14]

    • $\alpha\in[0,1]$：蒸馏强度权重，$\alpha=1$ 时退化为纯蒸馏。
    • $r(y)$：任务奖励（RL 目标项），与第 2 章的 per-token 蒸馏分数 $r(y_t)$ 是不同对象。
    • $X$、$\pi_S$、$\pi_{\text{teacher}}$、$\mathcal{D}$：沿用前文定义。

    前一项是 RL 目标，后一项是 on-policy 蒸馏项。与标准 RLHF 的关键区别：正则化对象从初始策略换成教师策略——蒸馏项在优化奖励的同时把学生往教师行为上拉，GKD 提出这可以降低"对齐税"。GKD 自称是首个同时执行蒸馏与 RL 微调的工作，且组合时几乎不引入额外超参（复用 RLHF 经验）[C14]。

    本章问题

    1. 什么时候必须先 SFT 或领域微调、再做 OPD？

      解答：教师策略不在学生初始化的支持集内时

      reverse KL 在初始化支持集内做模式寻求、推不动零概率 token：学生缺领域知识、相关 token 概率为零时，要先扩支持集（SFT 或 mid-training，中期领域训练）或显著加大 batch size。覆盖已满足时相反——强 SFT 初始化下逐 token 稠密信号让小 batch 也可行。Qwen3 的先例是先 off-policy 蒸馏打底、再 on-policy 蒸馏。

    2. 蒸馏能和强化学习同时做吗？怎么组合？

      解答：能，蒸馏项把 RL 正则到教师策略

      GKD 的组合目标把任务奖励项与 on-policy 蒸馏项按 $\alpha\in[0,1]$ 加权：$\alpha=1$ 是纯蒸馏，$\alpha$ 变小则奖励权重增大。与标准 RLHF 的差别是正则化对象从初始策略换成教师策略——奖励驱动探索、蒸馏保持行为。GKD 建议组合时选 reverse KL 或 JSD(0.9)。

    5. 边界——OPD 能做什么、不能做什么

    分工的根源在于两种方法用计算做什么。强化学习的本质是搜索——"应当把 RL 理解为把大部分计算花在搜索上——rollout 一个策略并分配信用——而不是花在更新上"，在语义空间里"绊倒"出新策略；蒸馏则"不需要建模 RL 课程中的中间策略，只学最终学到的那个策略"[C10]。这决定了两者的边界互补：RL 能发现教师没有的新能力，但"要求基模型有非零的成功率才能起步"；蒸馏没有这个起步要求，但要教师可查询、且教师策略在学生支持集内[C10]。

    学生以教师为参照——这是从分数公式的符号行为推出的方向性结论：$r=\log(\pi_{\text{teacher}}/\pi_S)$ 的方向永远指向教师分布，学生不会靠这个信号显著超越教师（此为公式结构的推断，各来源均未作为定理明文陈述；MOPD 页对 K3 的 Eq.15 作了同样处理）。有一个登记在案的特例：GKD 附录 A.1 的自蒸馏实验（同架构同大小的 Flan-T5-large 师生，GSM8K），on-policy GKD 学生在测试集上超过了教师[C15]——此现象 GKD 论文未作解释，本文推断它属于分布匹配目标下的评估现象（如采样与评估方式的差异），不是发明了教师没有的能力。

    汇总成三个适用条件：第一，存在可查询 logprobs 的强教师——教师弱，学生学到的就是弱表现；第二，教师策略在学生初始化的支持集内，或者愿意先 SFT 或 mid-training、用大 batch 换覆盖；第三，训练框架能消费 per-token advantage——现成的 RL 栈即可，对带 KL 正则的实现只是换掉正则模型[C4]。三条都满足时，OPD 是把已有能力高效转移给学生的方案；任何一条不满足，它就退化为不可用或成本优势缩水。

    维度OPD 能做OPD 不能做
    能力来源转移教师已有的能力（含 RL 训出的策略）发明教师没有的能力（需要 RL 探索）
    知识注入恢复学生已有行为的同时注入教师行为直接教学生支持集外的全新知识（需先扩支持集）
    上限逼近教师分布显著超越教师（信号方向不越过教师）
    起步条件无"非零成功率"要求——（但要求支持集覆盖，见上一章）

    OPD 的扩展方向也值得记一笔：K3 把 per-token OPD 奖励（$\text{sg}$ 与 $\text{clip}$ 加固的 Eq.15）作为基础，在上面建了多教师路由——9 个教师按（领域，努力程度）轮流指导一个统一学生（学生记为 $\pi_\theta(y_t\mid e,x,y_{<t})$，$e\in\{\text{low},\text{high},\text{max}\}$ 出现在条件记号中）[C16, N4]，即 MOPD。多教师如何选、条件化学生如何工作，见 MOPD 页，本文不展开。

    本章问题

    1. 想让学生超过教师，OPD 做得到吗？

      解答：常规情况做不到，要超越需要 RL 探索

      分数 $r=\log(\pi_{\text{teacher}}/\pi_S)$ 的方向永远指向教师分布：教师比学生更认可才有正分，学生学的是逼近教师。要获得教师没有的能力需要带任务奖励的 RL 探索（RL 本质是搜索，能"绊倒"到新策略）。GKD 自蒸馏实验中学生测试分数超过教师是分布匹配下的评估特例，不构成反例。

    2. OPD 与强化学习的合理分工是什么？

      解答：RL 负责搜索发现，OPD 负责高效转移

      RL 把计算花在 rollout 与信用分配上、能发现新策略，但要求基模型有非零成功率起步；OPD 把计算花在逐 token 的稠密反馈上、只学已有策略的最终形态，无起步要求但需要教师可查询与支持集覆盖。两者可按 $\alpha$ 组合（见"4. 实现选择"），也可按 Qwen3/TML 的实践接力：RL 先把教师训强，OPD 再把策略高效转移给学生。

    3-token 词表代替数万 token 的真实词表：可推出分数的符号行为与期望恒等式；不可推出真实训练中每个位置都要算教师前向的算力规模。手算例子固定前缀、单步推进：可推出单步更新方向；不可推出多步轨迹上的行为（折扣为零的设定本身来自 Thinking Machines，非本文假设）。代码省略采样温度、批量组织、优化器与参数化：验证的是分数计算与恒等式，不是训练收敛。Qwen3 §4.5 未指明其 on-policy 阶段 KL 的方向，正文保持同等粒度、不补方向。"学生以教师为参照"为方向性推断（公式结构），来源未作定理陈述；GKD 自蒸馏特例的"评估现象"归因同为本文推断，来源未作解释。
