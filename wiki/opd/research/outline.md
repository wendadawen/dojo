# OPD（On-Policy Distillation）— 教学大纲

## 1. 页面开头

### 钩子问题

Qwen3-8B 从同一个蒸馏起点继续训练：走强化学习，AIME'24 从 55.0 提到 67.6，花 17,920 GPU 小时；换 on-policy 蒸馏，提到 74.4，只花 1,800 小时——大约十分之一的成本、更好的结果。同样是从强教师模型学习，为什么"让学生自己写、教师逐步打分"会比"让学生试错、给最终答案发奖励"便宜这么多？

这就是 on-policy 蒸馏（OPD）要回答的问题——把训练分布换成学生自己的生成分布，把监督信号换成教师在每个 token 上的逐个反馈。

### 学习承诺

读完这一页，你应该能够：

- 说明为什么在教师生成的序列上训练学生会在推理时失配，on-policy 蒸馏如何消除这个失配；
- 描述 OPD 一步训练的完整机制：学生采样、教师逐 token 打分、分数作为 advantage 进入策略梯度；
- 手算一个 3-token 词表下的逐 token 奖励，判断每个 token 被鼓励还是被抑制；
- 从信号密度与实测数字说明 OPD 相比 RL 的效率来源；
- 说明 OPD 的能力边界：不能教新知识、以教师为参照、覆盖条件，以及它与 GKD/MOPD 的关系。

### 第一个具体场景

一个学生在做数学题时写下了"显然可得"——一个跳跃步骤。off-policy 蒸馏永远看不见这个前缀，因为教师的例子里全是"设未知数"这样的步骤；教师只在完整、正确的推理链上给过反馈。学生推理时却要不断接续自己写下的前缀，一旦早期走偏，就进入训练时从未出现过的状态，之后步步都在"没学过"的语境里生成。

### 过渡

失配的根源是"训练用的序列不是学生自己会生成的序列"。下一章看 GKD 如何用一个参数把"用谁的数据"变成连续可调的选择。

## 2. 章节设计

### S1：为什么需要 on-policy——学生会在训练没见过的状态上犯错

- 主要教学问题：off-policy 蒸馏（固定数据集/教师序列）在自回归模型上有什么结构性缺陷？on-policy 蒸馏的解法是什么？
- 对应范围：C1、C2、C13（反面印证）、C17（辅助）。服务 Q1。
- 正文要点：
  - off-policy/on-policy 的最小定义：训练数据来自学生当前策略自身即 on-policy；
  - 复合误差链条：学生早期犯教师不会犯的错 → 进入训练没见过的状态 → 之后步步失配（C1，引 TML "diverging ever farther" 原句）；
  - GKD 统一框架：$\lambda\in[0,1]$ 混合固定数据集与学生自采样两项；$\lambda=0$ 是 supervised KD、$\lambda=1$ 是 on-policy KD（C2，引 "instantiations" 原句）；
  - GKD 不对采样分布反传（C2）；
  - DAGGER 谱系一句话（A1）；
  - 反面对照：自采样 SFT 形似而非 OPD——KL=0 数据集上任何实用学习率都退化（C13，误解 1 的证据）。
- 表达材料及职责：
  - 对照表格（组件 14）：off-policy 蒸馏 vs on-policy 蒸馏——训练数据来源、学生学习的状态、反馈密度、失败模式。承担"两个方案的结构差异"对比职责。
  - callout-blue（组件 01）：on-policy 的定义性事实——训练分布 = 学生自己的生成分布。
- 前置知识安排：知识蒸馏页链接（`../knowledge-distillation/index.html`，读者需要"off-policy 蒸馏在教师序列上拟合"的基准形态）。
- 本章问题（2 题，含答案要点）：
  - Q：为什么学生推理时的错误会越滚越大，而 off-policy 蒸馏帮不上忙？A：训练只见过教师前缀；学生自己的错误前缀是训练分布外的状态；教师反馈从未覆盖这些状态，误差复合。
  - Q：GKD 框架里 $\lambda$ 从 0 调到 1 改变了什么？A：训练序列的来源从固定数据集/教师输出过渡到学生自采样；$\lambda=0$ 即 supervised KD，$\lambda=1$ 即 on-policy KD；打分（散度）本身不变。
- 过渡：数据来源换成了学生自己的轨迹，下一个问题是——教师在这条轨迹上到底怎么"教"。

### S2：机制——学生采样、教师逐 token 打分

- 主要教学问题：OPD 一步训练的完整流程是什么？逐 token 分数怎么算、怎么用？
- 对应范围：C3、C4、F2、F3、F4、F5、F7；C16（K3 变体，简要）。服务 Q2、Q3。
- 正文要点：
  - per-token 粒度：散度作用在每个位置的 next-token 分布上，按长度平均（C3，F2）；
  - TML 路径四步：学生采样（顺手得到学生 logprob）→ 教师一次前向 compute_logprobs → 逐 token 分数 $r=\log\pi_{\text{teacher}}(y_t)-\log\pi_S(y_t)$（= 负 per-token reverse KL，F4）→ $r$ 作 advantage 进策略梯度更新；
  - 策略梯度最小定义（内联，标注最小定义）：$\nabla\log\pi_S(y_t)\cdot A$，正 $A$ 抬高该 token 概率、负 $A$ 压低；
  - 折扣因子为 0：学生只优化下一个 token（C4）；
  - 教师角色澄清：只出标量分数，无梯度回传（误解 2；对照 K3 的 $\text{sg}$ 把它显式化，C16）；
  - K3 Eq.15 一句话：加 $\text{clip}$ 与 $\text{sg}$ 的工程变体，链接 MOPD 页；
  - 手算示例（计算示例，嵌入）：3-token 词表，学生 $(0.3,0.4,0.3)$、教师 $(0.6,0.3,0.1)$，采样 B 得 $r=\ln(0.75)\approx-0.288$；采样 A 得 $\ln 2\approx+0.693$；采样 C 得 $\ln(1/3)\approx-1.099$；符号与更新方向逐一说明；
  - 第二位置延伸：前缀变为"已选 A"后教师 $(0.2,0.5,0.3)$、学生 $(0.5,0.3,0.2)$，采样 B 得 $r=\ln(5/3)\approx+0.511$——打分发生在学生实际到达的状态（贯穿示例推进）；
  - 期望自检：$\mathbb{E}[r]=-\mathrm{KL}(\pi_S\|\pi_T)\approx-0.237$，手算 KL 对照（F5，数值示例折叠块给全过程）。
- 表达材料及职责：
  - 图示·结构 A 顺序流程（组件 13，dg-flow）：① 学生采样 $y_t$（同时得学生 logprob）→ ② 教师前向得教师 logprob → ③ 逐 token 分数 → ④ advantage 进策略梯度更新学生。承担"一步训练的完整流程"职责。图内公式用 foreignObject。
  - 数值示例折叠块（组件 10）：期望奖励与 KL 的完整手算。
  - 补充折叠块（组件 09）：策略梯度视角与散度视角的等价推导（F7，log-derivative 恒等式；标注为推导、非外部公式）。
  - 可运行代码折叠块（组件 12）：Python 复算手算示例 + 蒙特卡洛验证 $\mathbb{E}[r]=-\mathrm{KL}$；实际运行后把真实输出写进页面。
  - 对照表格（组件 14）：教师角色——"奖励来源 vs 梯度来源"两栏。
- 前置知识安排：KL 散度最小定义（内联，标注）；策略梯度最小定义（内联，标注）；MOPD 页链接（K3 变体处）。
- 本章问题（3 题，含答案要点）：
  - Q：教师对学生的"打分"具体是什么数？A：学生在该前缀下采样 token 的教师概率与学生概率之比的对数 $r=\log(\pi_T/\pi_S)$；教师更认可为正、更不认可为负；等价于该 token 的负 reverse KL 采样值。
  - Q：这个分数怎么变成参数更新？A：作为该 token 的 advantage 乘进 $\nabla\log\pi_S(y_t)$；正分数抬高采样 token 的对数概率，负分数压低；教师参数不变。
  - Q：GKD 的散度视角和 TML 的 advantage 视角矛盾吗？A：不矛盾；策略梯度带 $r=\log(\pi_T/\pi_S)$ 的期望更新是 $-\nabla\mathrm{KL}(\pi_S\|\pi_T)$ 的无偏估计（推导见折叠块），两个视角在期望上一致。
- 过渡：机制清楚后，效率问题自然浮出——逐 token 打分到底比 RL 的最终奖励多提供了什么？

### S3：为什么比 RL 便宜——每个 token 都有信号

- 主要教学问题：OPD 相比带奖励模型的 RL，样本效率和计算效率的来源是什么？实测证据有哪些？
- 对应范围：C5、C6、C9、C8、C10、N1、N2、N3、A2。服务 Q4。
- 正文要点：
  - 信号密度：RL 每 episode $O(1)$ bits（"21 是错的"不指出错在哪一步），蒸馏 $O(N)$ bits（C5）；
  - 不可 hack 与无需奖励模型（C5）；
  - 无需完整 rollout：partial rollouts 可用；RL 必须在评估长度上下文训练（C6）；
  - 计算不对称：教师一次前向出 logprob，轨迹由便宜的学生生成（C4 的计算面）；
  - 强初始化可用小 batch：每 episode 更多 bits 降低梯度噪声（C12 的正面一半）；
  - 实测三组：Qwen3 Table 21（C8，N1 全行数字）；TML 成本（C9，N2：150 步 60%→70%、9–30×、7–10× 步、50–100× 计算）；GKD 早期证据（C17，N3：2.1×/1.7×/1.9×、5% 数据超过全量 supervised KD）；
  - forking tokens 直觉（A2）：教师惩罚的是把学生引偏的开头 token，最终错误答案反而不被惩罚——逐 token 粒度才能看到这一点。
- 表达材料及职责：
  - 对照表格（组件 14）：RL vs on-policy 蒸馏——奖励来源、信号粒度、每 episode bits、需要完整 rollout、可否被 hack、额外模型。
  - 对照表格（组件 14）：Qwen3 Table 21 摘录（方法/AIME'24/pass@64/GPU 小时）——数字全部来自 N1。
- 前置知识安排：无新增（RLVR 一句话内联说明）。
- 本章问题（2 题，含答案要点）：
  - Q：为什么"每个 token 都有分数"能让训练步数少一个数量级？A：每个 episode 传递 $O(N)$ bits，梯度噪声更小、信号更稠密；教师单前向即可打分，不用 rollout 到终局再由奖励模型评分。
  - Q：1,800 vs 17,920 GPU 小时这组数字的实验条件是什么？A：Qwen3-8B、同一 off-policy 蒸馏起点、数学与代码查询；蒸馏 AIME'24 74.4 对 RL 67.6，pass@64 上蒸馏 90.0→93.3 而 RL 无提升；结论限于该配置。
- 过渡：效率成立有前提——打分用的散度形式、学生的初始化都会改变结果。下一章看这些实现选择。

### S4：实现选择——散度、初始化、与 RL 组合

- 主要教学问题：forward KL、reverse KL、JSD 怎么选？初始化与 batch size 的条件是什么？蒸馏能否与 RL 同时进行？
- 对应范围：C11、C12、C14、C15（自蒸馏特例放 S5）、F1、A3、A4。服务 Q5（条件部分）。
- 正文要点：
  - 散度是 GKD 的第二个自由度：forward KL（mass-covering）、reverse KL（mode-seeking）、广义 JSD($\beta$)（F1；$\beta\to0$ 近似 forward KL、有界）；
  - GKD 实验结论：最优散度任务相关；温度采样评估下 mode-seeking 质量高、多样性低（C11）；
  - TML 选 reverse KL 的理由：mode-seeking 学教师单一行为；与 RL 的序列级 reverse KL 天然协同；unhackable（C11）；
  - 支持集分工：SFT/forward KL 扩支持集，reverse KL 在初始化支持集内做模式寻求（C11）；
  - 初始化与 batch：教师策略在学生支持集内 → 小 batch 可行；否则需显著更大 batch（C12；A4：LoRA rank 32 下 SFT 后落后 13% vs 蒸馏后 6%）；
  - GKD+RL 组合：正则化对象从初始策略换成教师策略，$\alpha$ 控制强度（C14，公式 F：GKD 公式 (5) 放折叠块）；
  - Qwen3 的工程先例：先 off-policy 打底（模式切换能力）再 on-policy（A5，C7——放此处或 S5 均可，规划放此处）。
- 表达材料及职责：
  - 对照表格（组件 14）：forward KL / reverse KL / JSD——优化方向、行为倾向（mass-covering vs mode-seeking）、适用注意。
  - 补充折叠块（组件 09）：GKD 公式 (5) 与 $\alpha$ 的说明（C14 的公式细节）。
- 前置知识安排：KL 方向性在此处展开（最小定义已在 S2 给出）。
- 本章问题（2 题，含答案要点）：
  - Q：什么时候必须先 SFT/midtrain 再做 OPD？A：教师策略不在学生初始化支持集内时（如学生缺领域知识、相关 token 概率为零），reverse KL 推不动零概率 token；先扩支持集，再在支持集内模式寻求；覆盖不足的另一路是显著加大 batch。
  - Q：蒸馏能和 RL 同时做吗？A：能；GKD 把 RL 目标与蒸馏项按 $\alpha$ 加权，蒸馏项正则到教师策略而非初始策略；$\alpha=1$ 退化为纯蒸馏。
- 过渡：选择空间清楚了，最后收拢到 OPD 的能力边界。

### S5：边界——OPD 能做什么、不能做什么

- 主要教学问题：OPD 的能力上限和失效条件是什么？它与 MOPD、与 RL 的分工在哪里？
- 对应范围：C10、C15、C16、C13（边界面）、误解 3。服务 Q5。
- 正文要点：
  - 不发明新能力：RL 是搜索、发现新策略；蒸馏只学 RL/教师已有的最终策略，不建模中间课程（C10）；
  - 起步条件互补：RL 要非零成功率起步；蒸馏无此要求但要覆盖（C10）；
  - 以教师为参照：信号方向不越过教师分布（方向性结论，标注）；特例：GKD 自蒸馏中同架构学生测试分数可超教师（C15）——评估现象而非新能力；
  - 三个适用条件汇总：可查询 logprobs 的强教师、覆盖的教师支持集、能消费 per-token advantage 的训练框架；
  - 与 MOPD 的衔接：多教师 + 条件化学生 = K3 的扩展，per-token OPD 奖励即 Eq.15 的内核（C16，链接 `../mopd/index.html`）；
  - 能/不能对照收束全页。
- 表达材料及职责：
  - 对照表格（组件 14）：OPD 能做 / 不能做（能力来源、知识更新、超越教师、起步条件等行）。
- 前置知识安排：MOPD 页链接。
- 本章问题（2 题，含答案要点）：
  - Q：想让学生超过教师，OPD 做得到吗？A：常规情况做不到——奖励方向始终指向教师分布；要超越需要带任务奖励的 RL 探索。GKD 自蒸馏中测试分数超教师是分布匹配下的评估特例。
  - Q：OPD 与 RL 的合理分工是什么？A：RL 负责搜索/发现新策略与新能力（要求非零成功率起步），OPD 负责把已有策略高效转移给学生（要求教师可查询、支持集覆盖）；两者可按 $\alpha$ 组合（见上一章）。
- 过渡：无（收尾章）。
