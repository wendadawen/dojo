OPD（On-Policy Distillation，在线策略蒸馏）

训练序列由学生模型自己采样，教师模型对学生写下的每个 token 给出对数概率比分数，作为稠密的 per-token 信号接入策略梯度更新。解决 off-policy 蒸馏的分布失配，同时把训练信息量从强化学习的"每序列一次奖励"提高到"每 token 一次反馈"。

更新于 2026-08-25 · 主要依据 GKD 论文（arXiv:2306.13649）、Thinking Machines《On-Policy Distillation》(2025)、Qwen3 技术报告 §4.5、Kimi K3 技术报告 §4.1.3

1. 为什么需要它

  • off-policy 蒸馏（监督蒸馏 / SeqKD）在教师或数据集生成的序列上训练学生，学生推理时却要接续自己生成的前缀——两个分布不一致（分布失配），学生早期一个教师不会犯的错就会把它带进训练从未覆盖的状态，误差复合放大。
  • 强化学习虽然有探索能力，但序列级奖励每个 episode 只传递固定信息量，不知道错在哪一步，还要求基模型有非零成功率才能起步。
  • 需要一个"在学生自己的状态上给稠密反馈"的转移方法：GKD 论文（Agarwal et al. 2023）把它统一为 $\lambda=1$ 的特例，Thinking Machines、Qwen3、Kimi K3 把它落成了工业可用的训练流程。

2. 核心机制

  • 学生采样，教师打分：训练轨迹由学生当前策略生成（on-policy 的含义）；教师不重写答案，只对学生轨迹做一次前向，读出教师对每个 token 的对数概率。
  • 对数概率比就是分数：$r(y_t)=\log(\pi_{\text{teacher}}(y_t)/\pi_S(y_t))$——教师比学生更认可的 token 得正分被鼓励，反之被抑制。期望意义下这个分数等于负的 reverse KL。
  • 分数作 advantage 进策略梯度：每个 token 的分数直接放进 $\nabla\log\pi_S(y_t)\cdot A$ 的 $A$ 位置，复用现成 RL 栈（对带 KL 正则的实现只需换掉正则模型）；教师参数不变、梯度不从教师流向学生。
  • 折扣因子取零：学生只优化眼前的下一个 token，不对未来 token 做信用分配（实践上非零折扣没有改善）。

3. 关键结论与边界

  • 效率证据：Qwen3-8B 上，on-policy 蒸馏以约 1/10 的 GPU 小时（1,800 对 17,920）在 AIME'24 上超过强化学习（74.4 对 67.6），pass@64（同一 prompt 采样 64 次、至少一次正确的比例）也只有蒸馏在提升；Thinking Machines 报告 9–30× 成本缩减、自蒸馏场景 7–10× 梯度步。条件：数学与代码类查询、强教师、强初始化。
  • 只转移、不发明：强化学习的本质是搜索、能发现新策略；蒸馏只学已有策略的最终形态。学生以教师分布为参照（方向性结论），要超越教师需要带任务奖励的 RL 探索。
  • 覆盖是硬条件：教师策略要落在学生初始化的支持集内；学生缺领域知识时要先 SFT 或中期领域训练（mid-training）扩支持集，或显著加大 batch size。Qwen3 的先例是先 off-policy 蒸馏打底、再 on-policy 蒸馏。
  • 散度是自由度：forward KL（覆盖多模式）、reverse KL（集中单一模式）、广义 JSD 都可用于打分，最优选择任务相关；Thinking Machines 与 K3 的实践取 reverse KL 形式。
  • 形似而非的陷阱：用学生自采样数据做普通 SFT 不是 OPD——没有教师逐 token 反馈，实测任何实用学习率下都会在指令遵循评估上退化。
