    投机解码：用小模型猜、大模型核的无损推理加速

    主要依据：Leviathan, Kalman, Matias. "Fast Inference from Transformers via Speculative Decoding." arXiv:2211.17192, ICML 2023 Oral；Chen, Borgeaud, Irving, Lespiau, Sifre, Jumper. "Accelerating Large Language Model Decoding with Speculative Sampling." arXiv:2302.01318, DeepMind 2023。

    让一个 70B 模型生成 100 个 token，为什么必须串行调用 100 次大模型？每次调用要把全部约 140GB 权重从显存读一遍，却只用它算 1 个 token 的概率——剩下的算力白白空转。能不能把这些空转的算力用来「猜」未来几个 token、再让大模型一次核对？投机解码（Speculative Decoding）就是回答这个问题的方法：用一个小而快的 draft 模型自回归地猜若干个候选 token，大 target 模型一次性并行验证，按修改版拒绝采样规则接受匹配的、修正不匹配的，从而在不改变输出分布的前提下减少大模型的串行调用次数。Chen et al. 2023 把同一机制称为 Speculative Sampling[C1]。

    核心问题

    1. 自回归解码慢在哪里，为什么「并行验证多个 token」几乎不增加成本？

      解答：单步解码受内存带宽限制，多算几个位置几乎免费

      每生成一个 token 都要把模型全部权重从显存读一遍（70B 模型约 140GB），墙钟时间由内存带宽决定，所需算术量相对极低，计算单元大量空闲。因果注意力让同一次前向传播同时对序列每个位置输出分布，多算 $\gamma$ 个位置落在空闲计算单元上，几乎不增加时间。机制见「1. 为什么串行解码慢」。

    2. Draft-then-Verify 一轮做了什么，每个 token 在什么条件下被接受或拒绝？

      解答：draft 猜 $\gamma$ 个候选，target 一次前向按比值逐位判定

      draft 模型自回归采样 $\gamma$ 个候选并记录每步分布 $q_i$；target 对拼接后的序列做一次前向，得到 $\gamma+1$ 个位置分布 $p_i$。对每个候选 $x_i$ 以 $a_i = \min(1, p_i(x_i)/q_i(x_i))$ 的概率接受：$p_i \geq q_i$ 必接受，$p_i < q_i$ 按比值概率接受，$p_i = 0$ 必拒绝。首个拒绝处从残差分布重采样一个 token 并停止；全部接受时从 $p_{\gamma+1}$ 免费多采一个。流程见「2. Draft-then-Verify」。

    3. 为什么这个接受/拒绝规则能保证输出分布与纯 target 采样完全相同？

      解答：接受步骤的偏置被残差重采样恰好补回

      单位置上 token $x$ 被采出的概率分两条互斥路径：draft 采到且接受贡献 $\min(q(x), p(x))$，发生拒绝且残差重采样到 $x$ 贡献 $\max(0, p(x)-q(x))$；由恒等式 $\min(a,b) + \max(0, b-a) = b$，两者相加恰为 $p(x)$。逐位置成立即整条序列的输出分布与纯 target 采样相同。证明见「3. 为什么这条规则能保分布」。

    4. 接受率 $\alpha$ 和草稿长度 $\gamma$ 如何决定加速比，什么时候反而更慢？

      解答：$S = (1-\alpha^{\gamma+1})/[(1-\alpha)(1+\gamma c)]$，低接受率或高负载会退化

      每轮期望产出 $\mathbb{E}[L] = (1-\alpha^{\gamma+1})/(1-\alpha)$ 个 token，成本为 $1 + \gamma c$（$c$ 为 draft 与 target 单步时间比），加速比 $S = \mathbb{E}[L]/(1+\gamma c)$。$\alpha$ 低或 $c$ 大时 $S$ 趋向 1 甚至小于 1；高负载批处理下「空闲算力」消失，实测出现 1.4×-1.8× 减速。量化分析见「4. 能快多少」。

    5. 贪心解码下规则如何退化，与采样情形的关系是什么？

      解答：退化为逐位 argmax 匹配，是采样情形的特例

      贪心对应 $p$、$q$ 退化为点质量分布：draft 与 target 的 argmax 相同时比值为 1、必接受；不同时 $p(x) = 0$、必拒绝，残差重采样直接取 target 的 argmax。因此规则变为「逐位检查 draft 的 argmax 是否等于 target 的 argmax，遇到不等处取 target 的 argmax 并停止」，输出与纯 target 贪心解码一致。讨论见「3. 为什么这条规则能保分布」。

    1. 为什么串行解码慢——内存带宽留下的「免费午餐」

    自回归解码的工作方式是：每次把已生成的 token 序列喂给模型，模型做一次前向传播，得到下一个位置上的概率分布，从中采样一个 token，再把它拼回序列、重复下一步。每一步都依赖上一步的输出，因此必须串行。这里的「一次前向传播」会用到一个叫 KV cache 的机制——把历史 token 的注意力键值缓存下来，避免重复计算——但每一步仍然要把模型的全部权重从显存读一遍。

    关键在于单 token 前向传播的瓶颈是什么。一个 70B 参数的模型在 FP16 下权重约 140GB；H100 显卡 HBM 带宽 3.35 TB/s（见 GPU 执行模型）。教学计算：把全部权重从 HBM 读到计算单元的理论下限约为 $140\text{ GB} / 3.35\text{ TB/s} \approx 42$ 毫秒，与具体生成什么 token 无关。相比之下，算出一个 token 概率所需的乘加运算量相对很低，计算单元（SM / Tensor Core）大量时间在等权重到达——单步解码是内存带宽受限（memory-bandwidth bound），而非计算受限[C2]。

    这一点带来一个反直觉的机会。Transformer 的因果注意力让一次前向传播可以同时对序列每个位置输出分布（见 标准 Transformer 注意力）。如果把输入序列延长 $\gamma$ 个位置，同一次前向传播就额外给出了 $\gamma$ 个位置上的分布，而墙钟时间几乎不变——因为瓶颈是「把权重读一遍」这件事，读一遍权重之后，多用它算几个位置的乘积几乎不增加时间，多余的算术落在原本空闲的计算单元上。这就是投机解码的硬件前提：

    单 token 解码（标准）$\gamma+1$ token 验证（投机）
    读权重（约 140GB）约 42ms约 42ms
    计算位置数1 个，耗时 $\approx 0$$\gamma+1$ 个，耗时 $\approx 0 + \varepsilon$
    单步总计$\approx 42$ms$\approx 42$ms
    单步产出1 个 token$1 \sim \gamma+1$ 个 token

    教学解释。 把「读权重」理解为「开车去仓库取货」：取一次货的开车时间是固定的，不管取一件还是取 $\gamma+1$ 件，开车时间都一样；只要这 $\gamma+1$ 件货值得取，跑一趟就更划算。这个类比只帮助理解「读权重」与「算位置」的时间量级差异。它不覆盖批量推理下的吞吐竞争（高并发时多个请求要抢同一份带宽），也不覆盖流水线并行下的气泡问题；正式判断仍以单流低负载下的带宽分析与「能快多少」一章的加速比公式为准。

    这条「免费午餐」有一个硬条件：单流低负载。当批处理规模变大、多个请求已经把计算单元占满时，「空闲算力」就不存在了，验证 $\gamma+1$ 个位置会挤占本可服务其他请求的算力，反而降低总吞吐。这个边界在「能快多少」与「工程实例与边界」两章再展开。

    本章问题

    1. 用一句话说出为什么单 token 解码是带宽受限而非计算受限。

      解答：单步墙钟时间由读权重决定，算术量极低

      每步要把全部权重从显存读一遍（70B 模型约 140GB，理论下限约 42ms），而算出一个 token 概率所需的乘加运算量相对极低，计算单元大部分时间在等权重到达。

    2. 「验证 $\gamma$ 个 token」与「生成 1 个 token」墙钟时间为何相近？说出硬件原因。

      解答：瓶颈是读权重，多算位置落在空闲计算单元上

      瓶颈是把权重读一遍这件事，与算几个位置无关。读完一遍权重后，因果注意力允许同一次前向对 $\gamma+1$ 个位置同时输出分布，额外乘加落在原本空闲的计算单元上，几乎不增加时间。

    3. 这条「验证几乎免费」的结论在什么负载条件下不成立？

      解答：高并发批处理下不成立

      多个请求把计算单元占满后，「空闲算力」不再存在，验证 $\gamma+1$ 个位置会挤占本可服务其他请求的算力，总吞吐反而下降（vLLM 实测高查询率下出现 1.4×-1.8× 减速）。

    硬件允许「免费」核对 $\gamma$ 个 token——但核对什么？这 $\gamma$ 个候选 token 从哪里来？下一章讲 draft 模型如何提供候选、target 模型如何核对。

    2. Draft-then-Verify——一轮做了什么

    投机解码用两个模型协同：一个小的 draft 模型 $q$（快但可能不准），一个大的 target 模型 $p$（慢但准，其分布 $p$ 是希望最终采样的目标分布）。每轮（一个 "superstep"）做五件事[C3-C6]：

    逐步说明。 步骤 1：draft 模型用普通自回归方式采样 $\gamma$ 个 token $x_1,\dots,x_\gamma$，每步都记下分布 $q_i$（即 draft 在第 $i$ 步给各 token 的概率）。步骤 2：把前缀和 $\gamma$ 个 draft token 拼成一条序列，target 模型做一次前向传播，因为因果注意力，同时得到 $\gamma+1$ 个位置上的分布 $p_1,\dots,p_{\gamma+1}$（最后一个 $p_{\gamma+1}$ 是 bonus 位置，见步骤 5）。步骤 3：从左到右逐位判断。对第 $i$ 个 draft token $x_i$，计算接受概率

    $$a_i = \min\!\left(1, \frac{p_i(x_i)}{q_i(x_i)}\right).$$

    这个公式有三条边界，对应三种情形[F1]：

    条件$p_i(x_i)/q_i(x_i)$接受概率 $a_i$动作
    $p_i(x_i) \geq q_i(x_i)$$\geq 1$$1$必接受
    $p_i(x_i) < q_i(x_i)$$\in (0,1)$$p_i(x_i)/q_i(x_i)$概率接受
    $p_i(x_i) = 0$$0$$0$必拒绝

    直觉是：如果 target 觉得这个 token 至少和 draft 一样可能（$p \geq q$），就放心接受；如果 target 觉得 draft 高估了它（$p < q$），就以两者比值概率接受，比值越低越倾向于拒绝。这听起来像调参，但「为什么这条规则能保分布」一章会证明这个比值恰好让输出分布回到 $p$，不是任意选择。

    步骤 4：在首个被拒绝的位置 $i^\*$，丢弃 $x_{i^\*}$ 及其后的全部 draft token，从残差分布[F2]

    $$p'_{i^\*}(x) = \frac{\max\!\big(0,\ p_{i^\*}(x) - q_{i^\*}(x)\big)}{\sum_{x'} \max\!\big(0,\ p_{i^\*}(x') - q_{i^\*}(x')\big)}$$

    重采样一个 token 作为该位置最终输出，并结束本轮（不再验证后续 draft token）。残差分布把 target 比 draft「多给」的概率拿出来重新分配——直观上是在修正 draft 高估某些 token 造成的偏差。为什么不能直接从 $p$ 重采样？因为接受步骤已经偏向 $q$ 高的 token，必须用残差把被低估的部分补回去；「为什么这条规则能保分布」一章会严格证明这一点。注意：若 $p_i \leq q_i$ 处处成立（$p$ 被 $q$ 支配），则 $\max(0, p_i - q_i)$ 全为零、残差归一化无定义，但此时 $\min(1, p_i/q_i) = 1$ 处处成立、永不拒绝，残差分支根本不会被触发。

    步骤 5：若 $\gamma$ 个 draft token 全部被接受，target 同一次前向传播已经给出了第 $\gamma+1$ 个位置的分布 $p_{\gamma+1}$，可以免费从中采样一个 bonus token——「免费」是因为它复用了已经做过的那一次前向传播，不需要额外调用 target。本轮最多产出 $\gamma+1$ 个 token。

    一轮的最差情况是首个 draft token 就被拒绝：此时仍从残差重采样出 1 个 token，产出与纯 target 解码相同（1 个 token，1 次 target 调用），只是浪费了 draft 的工作。因此投机解码从不比纯解码产出更少——它只可能更快，不可能更慢（单流下；高并发的退化见「能快多少」一章）。

    代码：Draft-then-Verify 一轮的伪代码（把五步形式化）

    以下是伪代码，不是 Python。它形式化上面五步，便于后续对照公式与代码。

    输入：
  当前前缀 prefix
  draft 模型 q 与 target 模型 p（共享词表）
  草稿长度 γ（正整数）

状态：
  本轮产出序列 out ← 空列表

核心步骤：
  # 步骤 1：Draft
  for i ← 1 to γ:
      从 q_i(· | prefix + out + 已采样的 draft) 采样 x_i
      记录分布 q_i

  # 步骤 2：Verify（一次 target 调用）
  令 S ← prefix + [x_1, …, x_γ]
  一次 p 前向传播，得 p_1, …, p_γ, p_{γ+1}

  # 步骤 3-4：逐位接受/拒绝
  rejected ← false
  for i ← 1 to γ:
      a_i ← min(1, p_i(x_i) / q_i(x_i))
      以概率 a_i 接受：
          把 x_i 加入 out
      否则（首个拒绝）：
          从 p'_i(x) = norm(max(0, p_i(x) - q_i(x))) 重采样一个 token y
          把 y 加入 out
          rejected ← true
          break

  # 步骤 5：Bonus（仅当全部接受）
  if not rejected:
      从 p_{γ+1} 采样一个 token b
      把 b 加入 out

输出：out（长度为 1 ~ γ+1）

    注意 $p_i, q_i$ 都是给定前缀与之前 token 的条件分布，伪代码中省略条件记号以突出主线。每轮的 target 调用次数始终为 1，draft 调用次数始终为 $\gamma$，与接受多少无关。

    本章问题

    1. 说出 $\gamma$ 个 draft token 是怎么来的、为什么 target 只需要一次前向传播。

      解答：draft 自回归采样，因果注意力让一次前向出全部位置分布

      draft 模型用普通自回归方式逐个采样 $\gamma$ 个候选，并记录每步分布 $q_i$。把前缀与 $\gamma$ 个候选拼成一条序列后，因果注意力使 target 的一次前向同时给出 $\gamma+1$ 个位置的条件分布（最后一个为 bonus 位置，全部接受时可免费多采一个 token）。

    2. 给定 $p(x)=0.4$、$q(x)=0.5$，算出 $a(x)$ 并说出是必接受还是概率接受。

      解答：$a(x) = 0.8$，概率接受

      $a(x) = \min(1, 0.4/0.5) = 0.8$。因 $p(x) < q(x)$（target 认为 draft 高估了这个 token），以 0.8 的概率接受、0.2 的概率拒绝。

    3. 说出残差分布在什么条件下才会被触发、什么条件下永远不会被触发。

      解答：首个拒绝处触发；$p \leq q$ 处处成立时永不触发

      残差分布仅在某个位置出现首个拒绝后才被使用，用于重采样该位置的输出并结束本轮。若 $p_i \leq q_i$ 处处成立，则 $\min(1, p_i/q_i) = 1$ 处处成立、永不拒绝，残差分支根本不会被触发。

    机制讲完了——但为什么接受概率要写成 $\min(1, p/q)$？为什么拒绝后要从 $\max(0, p-q)$ 重采样而不是直接从 $p$？这些选择不是任意调参，下一章证明它们组合起来恰好让输出分布回到 $p$。

    3. 为什么这条规则能保分布——单位置证明

    这一章回答投机解码最核心的问题：为什么这条接受/拒绝规则能保证输出分布与纯 target 采样完全相同（lossless）？答案浓缩成一句话：因为接受步骤偏置了分布，残差重采样恰好把偏置的部分补回去。下面把这句话展开成可手算的证明。

    先固定一个位置 $i$，省略条件记号，记 $p = p_i$、$q = q_i$。考虑某个特定 token $x$ 最终被「采出」的概率 $\Pr[\text{emit } x]$。它有两条互斥路径：

    路径 A：draft 采样到 $x$ 且被接受。概率为 $q(x) \cdot a(x) = q(x) \cdot \min\!\left(1, \frac{p(x)}{q(x)}\right) = \min(q(x), p(x))$。

    路径 B：某个 token 被拒（不一定是 $x$），从残差重采样到 $x$。这条路径要分两步算。

    先算「任意 token 被拒」的总概率 $\beta$。路径 A 在所有 token 上求和给出「被接受」的总概率 $\sum_{x'} \min(q(x'), p(x'))$，因此

    $$\beta = 1 - \sum_{x'} \min(q(x'), p(x')).$$

    再算残差分布的归一化常数。注意一个恒等式：对任意实数 $a, b$，$\min(a, b) + \max(0, b - a) = b$（若 $b \geq a$ 则 $\min=a, \max=b-a$，和为 $b$；若 $b < a$ 则 $\min=b, \max=0$，和仍为 $b$）。把 $a = q(x'), b = p(x')$ 代入并对所有 $x'$ 求和，得

    $$\sum_{x'} \max\!\big(0,\ p(x') - q(x')\big) = \sum_{x'} \big(p(x') - \min(p(x'), q(x'))\big) = 1 - \sum_{x'} \min(p(x'), q(x')) = \beta.$$

    所以残差分布 $p'(x) = \max(0, p(x) - q(x)) / \beta$ 的归一化常数恰好等于拒绝概率 $\beta$——这不是巧合，是 $\min + \max$ 恒等式的直接推论。于是路径 B 的概率为「拒绝」乘以「拒绝后重采样到 $x$」：

    $$\beta \cdot p'(x) = \beta \cdot \frac{\max(0, p(x) - q(x))}{\beta} = \max\!\big(0,\ p(x) - q(x)\big).$$

    两条路径相加（互斥，故可直接相加）：

    $$\Pr[\text{emit } x] = \min\!\big(q(x), p(x)\big) + \max\!\big(0,\ p(x) - q(x)\big) = p(x).$$

    最后一步再次用 $\min(a,b) + \max(0, b-a) = b$（取 $a = q(x), b = p(x)$）。这就证明了：在任意一个位置上，投机解码最终采出 $x$ 的概率恰好等于 target 分布 $p(x)$[F3]。逐位置成立则按归纳法对整轮、整条序列成立——输出分布与纯 target 采样在数学上完全相同（仅受硬件数值精度影响）。这是投机解码「无损」性质的全部依据。

    补充：单位置输出分布等于 p 的五步展开

    把上面散在各处的步骤收拢成一条可逐行复算的推导链。固定位置 $i$，省略条件记号。

    已知：$p(x), q(x)$ 为同一词表上的概率分布；$a(x) = \min(1, p(x)/q(x))$；$p'(x) = \max(0, p(x)-q(x)) / Z$，$Z = \sum_{x'} \max(0, p(x')-q(x'))$。

    第 1 步（路径 A 概率）：

    $$\Pr[\text{draft } x \text{ and accept}] = q(x) \cdot a(x) = q(x) \cdot \min\!\left(1, \frac{p(x)}{q(x)}\right) = \min(q(x), p(x)).$$

    第 2 步（任意拒绝概率）：

    $$\beta = 1 - \sum_{x'} \Pr[\text{draft } x' \text{ and accept}] = 1 - \sum_{x'} \min(q(x'), p(x')).$$

    第 3 步（残差归一化常数等于 $\beta$）：用恒等式 $\min(a,b) + \max(0, b-a) = b$，取 $a = q(x'), b = p(x')$，对所有 $x'$ 求和：

    $$Z = \sum_{x'} \max(0, p(x') - q(x')) = \sum_{x'} (p(x') - \min(p(x'), q(x'))) = 1 - \sum_{x'} \min(p(x'), q(x')) = \beta.$$

    第 4 步（路径 B 概率）：「发生拒绝且重采样到 $x$」= 拒绝概率 $\times$ 残差条件概率：

    $$\beta \cdot p'(x) = \beta \cdot \frac{\max(0, p(x) - q(x))}{Z} = \beta \cdot \frac{\max(0, p(x) - q(x))}{\beta} = \max(0, p(x) - q(x)).$$

    第 5 步（总和）：路径 A 与路径 B 互斥，相加：

    $$\Pr[\text{emit } x] = \min(q(x), p(x)) + \max(0, p(x) - q(x)) = p(x),$$

    最后一步再用一次 $\min(a,b) + \max(0, b-a) = b$（取 $a = q(x), b = p(x)$）。证毕。

    这个证明还顺手给出接受率的一个有用形式。「为什么这条规则能保分布」一章的 $\beta$ 是「拒绝概率」，那么「平均接受概率」$\alpha = 1 - \beta = \sum_x \min(p(x), q(x))$。用恒等式 $\min(a, b) = (a + b - |a - b|)/2$ 代入：

    $$\alpha = \sum_x \min(p(x), q(x)) = \sum_x \frac{p(x) + q(x) - |p(x) - q(x)|}{2} = 1 - \frac{1}{2}\sum_x |p(x) - q(x)| = 1 - \mathrm{TV}(p, q),$$

    其中 $\mathrm{TV}(p, q) = \frac{1}{2}\sum_x |p(x) - q(x)|$ 是两个分布的总变差距离（total variation distance）[F4]。这说明 $\alpha$ 是分布相似度的度量：draft 越像 target、$\mathrm{TV}$ 越小、$\alpha$ 越接近 1。$\alpha = 1$ 当且仅当 $p = q$（draft 与 target 完全一致），此时每个 token 必接受。$\alpha = 0$ 当且仅当 $p$ 与 $q$ 支撑集不相交（draft 永远猜不中 target 会采的 token），此时每个 token 必拒。

    最后看贪心解码的退化情形。贪心解码（greedy decoding）是每步取 argmax 的解码方式，对应 $p$ 与 $q$ 都退化为点质量分布——即 $p$ 把全部概率放在 target 的 argmax 上、$q$ 把全部概率放在 draft 的 argmax 上。此时 $p(x)/q(x)$ 只可能取两个值：若 draft 的 argmax 与 target 的 argmax 相同，则 $p(x) = q(x) = 1$、比值为 1、$\min(1, 1) = 1$，接受；若不同，则 $p(x) = 0$、比值为 0、$\min(1, 0) = 0$，拒绝。残差分布 $\mathrm{norm}(\max(0, p - q))$ 退化为 target 的 argmax 处概率 1，即直接取 target 的 argmax。因此贪心情形下规则退化为「逐位检查 draft 的 argmax 是否等于 target 的 argmax，遇到不等处取 target 的 argmax 并停止」——输出与纯 target 贪心解码逐 token 一致[C7]。这是投机解码最易懂的入口，工程中也常用；但它只是采样情形（$p, q$ 为一般分布）的特例，不是另一套机制。

    本章问题

    1. 写出单位置 $\Pr[\text{emit } x]$ 的两条路径分解。

      解答：路径 A 给 $\min(q, p)$，路径 B 给 $\max(0, p-q)$

      路径 A「draft 采到 $x$ 且被接受」贡献 $q(x)\min(1, p(x)/q(x)) = \min(q(x), p(x))$；路径 B「发生拒绝且从残差重采样到 $x$」贡献 $\beta \cdot p'(x) = \max(0, p(x)-q(x))$，其中 $\beta$ 为拒绝概率。两条路径互斥，相加恰为 $p(x)$。

    2. 说出残差分布的归一化常数为什么恰好等于拒绝概率 $\beta$（指出用了哪条恒等式）。

      解答：用 $\min(a,b) + \max(0, b-a) = b$ 对全部 token 求和

      取 $a = q(x')$、$b = p(x')$ 并对所有 $x'$ 求和：$\sum_{x'} \max(0, p - q) = 1 - \sum_{x'} \min(p, q) = \beta$。残差的归一化常数与拒绝概率是同一个量，这是恒等式的直接推论，不是巧合。

    3. 说出 $\alpha$ 与 $\mathrm{TV}(p, q)$ 的关系，并据此判断「draft 越像 target」时 $\alpha$ 如何变化。

      解答：$\alpha = 1 - \mathrm{TV}(p, q)$，越相似越高

      $\alpha = \sum_x \min(p(x), q(x)) = 1 - \mathrm{TV}(p, q)$。draft 越像 target、总变差越小、$\alpha$ 越接近 1；$p = q$ 时 $\alpha = 1$ 必接受，支撑集不相交时 $\alpha = 0$ 必拒。

    现在规则保分布已证明——那么实际跑起来能快多少？这取决于接受率和草稿长度，下一章用期望 token 数和加速比公式量化。

    4. 能快多少——期望 token 数与加速比

    「为什么这条规则能保分布」一章给出 $\alpha = \sum_x \min(p(x), q(x))$ 作为单位置平均接受概率。这一章把 $\alpha$ 代入两个公式：期望 token 数和加速比。

    期望 token 数。假设各位置接受率近似独立同分布（i.i.d.）、均为 $\alpha$。每个 draft token 被接受的概率独立为 $\alpha$，因此「连续接受 $k$ 个后首次失败」服从截断几何分布。一轮最多产出 $\gamma + 1$ 个 token（全接受加 bonus）、最少产出 1 个（首轮即拒仍重采样 1 个）。Leviathan et al. 2023 Theorem 3.8 给出期望产出[F5]：

    $$\mathbb{E}[L] = \frac{1 - \alpha^{\gamma+1}}{1 - \alpha}.$$

    这是截断几何级数 $\sum_{k=0}^{\gamma} \alpha^k$ 的闭式。两条边界帮助理解：

    • $\alpha = 1$（draft 与 target 完全一致）：取极限 $\mathbb{E}[L] = \gamma + 1$，每轮必产出 $\gamma + 1$ 个 token（全接受加 bonus）。
    • $\alpha = 0$（draft 永远猜不中）：$\mathbb{E}[L] = 1$，每轮必拒、产出 1 个重采样 token，与纯 target 解码相同。

    中间值：$\alpha = 0.8, \gamma = 5$ 时 $\mathbb{E}[L] = (1 - 0.8^6) / 0.2 = (1 - 0.262) / 0.2 = 3.69$ 个 token / 轮。

    加速比。一轮的成本（以单步 target 调用为 1 单位）为 $\gamma \cdot c + 1$，其中 $c = T_{\text{draft}} / T_{\text{target}}$ 是单步 draft 与单步 target 的墙钟时间比。标准解码产出 1 token 成本为 1。加速比是「标准成本 / 投机成本」：

    $$S = \frac{\mathbb{E}[L]}{1 + \gamma c} = \frac{1 - \alpha^{\gamma+1}}{(1 - \alpha)(1 + \gamma c)}.$$

    代入 Leviathan et al. 2023 报告的 T5-XXL 实验参数[N3, F6]（draft 是 T5-base，约 250M，比 target 11B 小得多，单步成本比 $c = 0.04$；平均接受率 $\alpha \approx 0.8$；草稿长度 $\gamma = 5$）：

    展开：$\alpha=0.8$, $\gamma=5$, $c=0.04$ 的 $\mathbb{E}[L]$ 与 $S$（复算 Leviathan 数字）

    构造示例，数字来自 Leviathan et al. 2023 §4 实验部分 Table 4（T5-base draft、T5-XXL target、EnDe 任务）。$\alpha=0.80$ 取自 temp=0 配置、$\gamma=5$ 取自 temp=1 配置，二者为教学复算的组合，不对应单一实验行。

    期望 token 数：

    $$\mathbb{E}[L] = \frac{1 - 0.8^{6}}{1 - 0.8} = \frac{1 - 0.262144}{0.2} = \frac{0.737856}{0.2} = 3.689 \text{ 个 token / 轮}.$$

    每轮成本：$1 + \gamma c = 1 + 5 \times 0.04 = 1.2$ 个 target 单位。

    加速比：

    $$S = \frac{3.689}{1.2} \approx 3.07 \times.$$

    这与 Leviathan et al. 2023 摘要报告的「T5-XXL 上 2×-3× 加速」一致（$3.07\times$ 接近上界）。

    展开：$\alpha=0.2$, $\gamma=5$, $c=0.04$ 时几乎不加速

    构造示例，用于展示 $\alpha$ 低时加速消失。固定 $c = 0.04$、$\gamma = 5$，把 $\alpha$ 从 0.8 降到 0.2。

    期望 token 数：

    $$\mathbb{E}[L] = \frac{1 - 0.2^{6}}{1 - 0.2} = \frac{1 - 0.000064}{0.8} = \frac{0.999936}{0.8} \approx 1.25 \text{ 个 token / 轮}.$$

    每轮成本仍是 $1 + 5 \times 0.04 = 1.2$ 个 target 单位。

    加速比：

    $$S = \frac{1.25}{1.2} \approx 1.04 \times.$$

    几乎不加速——投机的开销（$\gamma$ 步 draft）几乎抵消了它带来的收益。$\alpha$ 再低就会 $S < 1$，反而变慢。这说明接受率是加速的核心杠杆。

    从公式能读出三种使投机解码「不加速甚至变慢」的条件：

    条件公式表现直觉
    $\alpha$ 太低（draft 猜不准）$1 - \alpha^{\gamma+1} \to 1$，$\mathbb{E}[L] \to 1$几乎每轮首轮即拒，draft 工作白做
    $c$ 太大（draft 接近 target 规模）$1 + \gamma c \to 1 + \gamma$，分母膨胀draft 自身的串行成本抵消了 target 节省
    高负载批处理「空闲算力」消失，验证位置挤占他人算力单流公式 $S$ 不再适用，需看吞吐模型

    第三种是工程中最隐蔽的退化。vLLM 在高查询率批处理下实测出现 1.4×-1.8× 减速[N4]——同一硬件、低负载时加速、高负载时减速，差别只在于「空闲算力」是否存在。这说明投机解码是用空闲算力换延迟的策略，不是无条件加速。

    草稿长度 $\gamma$ 也不是越大越好。增大 $\gamma$ 在分子上多加一项 $\alpha^{\gamma+1}$ 的衰减（边际收益递减），在分母上线性增加 $\gamma c$（成本线性增长）。$\alpha$ 越低、$c$ 越大，最优 $\gamma$ 越小。例如 $\alpha = 0.8, c = 0.04$ 时，把 $S = (1 - \alpha^{\gamma+1}) / [(1-\alpha)(1 + \gamma c)]$ 代入枚举 $\gamma = 5,6,7,8,9,10$ 可得 $S \approx 3.07, 3.19, 3.25, 3.28, 3.28, 3.27$，最优 $\gamma \approx 8$；$\alpha = 0.5$ 时最优 $\gamma$ 显著更小。「猜得更远」不等于「猜得更好」。（最优 $\gamma$ 的选择见 Leviathan et al. 2023 §3.5。）

    本章问题

    1. 写出 $\mathbb{E}[L]$ 与 $S$ 的公式，并解释每个符号（$\alpha, \gamma, c$）。

      解答：$\mathbb{E}[L] = (1-\alpha^{\gamma+1})/(1-\alpha)$，$S = \mathbb{E}[L]/(1+\gamma c)$

      $\mathbb{E}[L]$ 是每轮期望产出 token 数，$S$ 是相对纯 target 解码的加速比。$\alpha$ 为单位置平均接受率，$\gamma$ 为草稿长度，$c$ 为单步 draft 与单步 target 的墙钟时间比。

    2. 给定 $\alpha=0.7, \gamma=4, c=0.1$，手算 $S$。

      解答：$S \approx 1.98\times$

      $\mathbb{E}[L] = (1 - 0.7^5)/(1 - 0.7) = (1 - 0.168)/0.3 \approx 2.77$；每轮成本 $1 + 4 \times 0.1 = 1.4$；$S \approx 2.77 / 1.4 \approx 1.98\times$。

    3. 说出三种使 $S < 1$ 或减速的条件，并指出哪种与单流公式无关。

      解答：$\alpha$ 低、$c$ 大、高负载批处理；第三种与单流公式无关

      其一 $\alpha$ 过低，几乎每轮首轮即拒，draft 工作白做；其二 $c$ 过大，draft 接近 target 规模，自身串行成本抵消节省；其三高负载批处理下「空闲算力」消失——这一种与单流公式 $S$ 无关，是吞吐层面的退化（vLLM 实测 1.4×-1.8× 减速）。

    现在何时加速、何时不加速已清楚——但所有这些数字都假设「接受率 $\alpha$ 是个已知量」。下一章把整条机制跑一遍，让抽象的 $\alpha$、$p$、$q$ 落到具体数字上。

    5. 把机制跑一遍——3 个 token 的手算例子

    构造示例。 这是一个为了手算构造的最小例子，不代表真实模型或工程推荐值。词表缩到 3 个 token $V = \{A, B, C\}$，草稿长度 $\gamma = 3$，前缀固定（省略条件记号）。

    设定。draft 模型自回归采样 3 个 token，每步分布与采样结果如下：

    • $q_1 = (0.5, 0.3, 0.2)$，采样 $x_1 = A$
    • $q_2 = (0.4, 0.4, 0.2)$（给定 $A$），采样 $x_2 = B$
    • $q_3 = (0.2, 0.3, 0.5)$（给定 $A, B$），采样 $x_3 = C$

    target 模型对前缀 + $[A, B, C]$ 做一次前向，得到 4 个位置的分布（最后一个是 bonus 位置）：

    • $p_1 = (0.4, 0.4, 0.2)$
    • $p_2 = (0.3, 0.5, 0.2)$
    • $p_3 = (0.4, 0.4, 0.2)$
    • $p_4 = (0.5, 0.3, 0.2)$（bonus 位置）

    逐位验证。把三个位置上的 $q_i, p_i, x_i$、比值 $p_i(x_i)/q_i(x_i)$、接受概率 $a_i$ 汇总：

    位置draft token$q_i(x_i)$$p_i(x_i)$$p_i(x_i)/q_i(x_i)$接受概率 $a_i$判定
    1$A$$0.5$$0.4$$0.8$$0.8$概率接受（假设接受）
    2$B$$0.4$$0.5$$1.25$$1.0$必接受
    3$C$$0.5$$0.2$$0.4$$0.4$概率接受（假设拒绝）

    本例展示一条具体采样路径：pos 1 接受、pos 2 必接受、pos 3 拒绝。注意「假设接受」「假设拒绝」标明这是这条路径上的随机结果，不是期望——同一设定换一次随机数会得到不同路径。

    残差重采样（pos 3）。在首个拒绝处 $i^\* = 3$，丢弃 $x_3 = C$ 及其后的 draft token（本例无后续），从残差分布重采样：

    $$\max(0, p_3 - q_3) = \big(\max(0, 0.4-0.2),\ \max(0, 0.4-0.3),\ \max(0, 0.2-0.5)\big) = (0.2, 0.1, 0).$$

    归一化常数 $Z = 0.2 + 0.1 + 0 = 0.3$，残差分布

    $$p'_3 = (0.2/0.3,\ 0.1/0.3,\ 0) = (2/3,\ 1/3,\ 0).$$

    从 $p'_3$ 采样——假设采到 $A$（概率 $2/3$）。本轮产出 $[A, B, A]$ 共 3 个 token。无 bonus，因为 pos 3 被拒后停止验证。

    对照单位置证明（「为什么这条规则能保分布」一章）。在 pos 1 上验证 $\Pr[\text{emit } A] = p_1(A) = 0.4$：

    路径 A：$\min(q_1(A), p_1(A)) = \min(0.5, 0.4) = 0.4$。

    路径 B：$\max(0, p_1(A) - q_1(A)) = \max(0, 0.4 - 0.5) = 0$。

    总和：$0.4 + 0 = 0.4 = p_1(A)$ ✓。pos 1 上 $p_1 < q_1$，残差项为 0，全部概率走路径 A——这恰好因为 $p_1(A) < q_1(A)$ 时接受概率 $a = 0.8 < 1$，被「扣下」的部分由残差在别处补回，对 $A$ 本身而言是 0。

    展开：构造示例三个位置的全部接受/拒绝/残差计算

    构造示例。 上面正文只展示了主路径（pos 1 接受、pos 2 必接受、pos 3 拒绝重采样到 $A$）。这里把三个位置的全部计算展开，便于逐行复算。

    pos 1（draft $A$，本路径接受）：

    • $q_1 = (0.5, 0.3, 0.2)$，$p_1 = (0.4, 0.4, 0.2)$
    • $a_1(A) = \min(1, 0.4/0.5) = 0.8$（概率接受）
    • 路径 A 概率：$\min(q_1(A), p_1(A)) = \min(0.5, 0.4) = 0.4$
    • 路径 B 概率：$\max(0, 0.4 - 0.5) = 0$
    • 验证：$\Pr[\text{emit } A] = 0.4 + 0 = 0.4 = p_1(A)$ ✓
    • 同理 $\Pr[\text{emit } B] = \min(0.3, 0.4) + \max(0, 0.4-0.3) = 0.3 + 0.1 = 0.4 = p_1(B)$ ✓
    • 同理 $\Pr[\text{emit } C] = \min(0.2, 0.2) + \max(0, 0.2-0.2) = 0.2 + 0 = 0.2 = p_1(C)$ ✓
    • pos 1 单位置接受率：$\alpha_1 = 0.4 + 0.3 + 0.2 = 0.9$

    pos 2（draft $B$，必接受）：

    • $q_2 = (0.4, 0.4, 0.2)$，$p_2 = (0.3, 0.5, 0.2)$
    • $a_2(B) = \min(1, 0.5/0.4) = \min(1, 1.25) = 1.0$（必接受）
    • 路径 A 概率：$\min(q_2(B), p_2(B)) = \min(0.4, 0.5) = 0.4$
    • 路径 B 概率：$\max(0, 0.5 - 0.4) = 0.1$
    • 验证：$\Pr[\text{emit } B] = 0.4 + 0.1 = 0.5 = p_2(B)$ ✓
    • pos 2 单位置接受率：$\alpha_2 = \min(0.3,0.4)+\min(0.4,0.5)+\min(0.2,0.2) = 0.3+0.4+0.2 = 0.9$

    pos 3（draft $C$，本路径拒绝，重采样到 $A$）：

    • $q_3 = (0.2, 0.3, 0.5)$，$p_3 = (0.4, 0.4, 0.2)$
    • $a_3(C) = \min(1, 0.2/0.5) = 0.4$（概率接受，本路径拒绝）
    • 残差：$\max(0, p_3 - q_3) = (0.2, 0.1, 0)$，$Z = 0.3$，$p'_3 = (2/3, 1/3, 0)$
    • 路径 A 概率（对 $C$）：$\min(q_3(C), p_3(C)) = \min(0.5, 0.2) = 0.2$
    • 路径 B 概率（对 $C$）：$\max(0, 0.2 - 0.5) = 0$（$C$ 在残差中概率为 0，因为 $p_3(C) < q_3(C)$）
    • 验证：$\Pr[\text{emit } C] = 0.2 + 0 = 0.2 = p_3(C)$ ✓
    • 同理 $\Pr[\text{emit } A] = \min(0.2, 0.4) + \max(0, 0.4-0.2) = 0.2 + 0.2 = 0.4 = p_3(A)$ ✓
    • 同理 $\Pr[\text{emit } B] = \min(0.3, 0.4) + \max(0, 0.4-0.3) = 0.3 + 0.1 = 0.4 = p_3(B)$ ✓
    • pos 3 单位置接受率：$\alpha_3 = 0.2 + 0.3 + 0.2 = 0.7$

    对照期望产出（「能快多少」一章）。三个位置的接受率 $(0.9, 0.9, 0.7)$，平均 $\bar{\alpha} = (0.9 + 0.9 + 0.7) / 3 = 2.5 / 3 \approx 0.833$。代入 $\mathbb{E}[L] = (1 - 0.833^4) / (1 - 0.833) \approx (1 - 0.481) / 0.167 \approx 3.11$ 个 token / 轮。本路径产出 3 个 token，与期望 $\approx 3.11$ 一致（具体路径可高于或低于期望）。若假设 pos 3 也接受，本轮会产出 4 个 token（含 bonus），高于期望——这与「期望」是平均值、单次可偏离一致。

    本章问题

    1. 给定 3 个位置上的 $p_i$ 与 $q_i$，逐位算出 $a_i$。

      解答：$a_1 = 0.8$，$a_2 = 1$，$a_3 = 0.4$

      pos 1：$a_1 = \min(1, 0.4/0.5) = 0.8$（概率接受）；pos 2：$a_2 = \min(1, 0.5/0.4) = 1$（必接受）；pos 3：$a_3 = \min(1, 0.2/0.5) = 0.4$（概率接受）。

    2. 在 pos 3 上手算残差分布的归一化。

      解答：残差 $(0.2, 0.1, 0)$，$Z = 0.3$，$p'_3 = (2/3, 1/3, 0)$

      $\max(0, p_3 - q_3) = (\max(0, 0.4-0.2), \max(0, 0.4-0.3), \max(0, 0.2-0.5)) = (0.2, 0.1, 0)$，归一化常数 $Z = 0.3$。$C$ 因 $p_3(C) < q_3(C)$ 残差为 0，不可能被重采样到。

    3. 在 pos 1 上验证单位置输出分布等于 $p_1$。

      解答：三个 token 的采出概率都与 $p_1$ 一致

      $\Pr[\text{emit } A] = \min(0.5, 0.4) + \max(0, 0.4-0.5) = 0.4 + 0 = 0.4 = p_1(A)$；同理 $B$：$0.3 + 0.1 = 0.4 = p_1(B)$；$C$：$0.2 + 0 = 0.2 = p_1(C)$。逐 token 都与 $p_1$ 相等。

    构造示例把机制、证明、加速比公式串通——最后一章把工程实例（K3 与 EAGLE-3）和论文实测做个交代，并说明本页的边界。

    6. 工程实例与边界

    K3 用 EAGLE-3 作为 draft 模型加速推理——EAGLE-3 是一种具体的 draft 架构，本页只引用其作为工程实例，不展开它的内部机制。EAGLE-3 的完整概念页见 EAGLE-3 投机解码 draft 模型。

    两篇奠基论文的实测结果[N1, N2]：

    论文target 模型部署实测加速质量
    Leviathan et al. 2023 (arXiv:2211.17192, ICML 2023 Oral)T5-XXL (11B)单机2×-3×输出与原实现 identical
    Chen et al. 2023 (arXiv:2302.01318)Chinchilla 70B分布式2-2.5×不修改模型、不降采样质量

    两者都强调「不修改模型、不重训练」——投机解码是 off-the-shelf 的推理时优化。两篇论文独立提出相同机制，是这一思路自然成立的标志。

    本页的边界总结：

    • 解决：单流自回归解码的延迟（wall-clock latency per token）。
    • 不解决：吞吐（throughput）——高并发批处理下可能反而降低总吞吐（vLLM 实测高查询率下 1.4×-1.8× 减速）。
    • 需要：target 与 draft 共享 tokenizer；draft 单步成本远小于 target（$c \ll 1$）；批处理规模足够小或专用低负载场景。
    • 不展开：draft 模型的训练/蒸馏方法；EAGLE/Medusa/Lookahead 等具体 draft 架构；分布式部署拓扑；vLLM/TGI 等框架的 API；与量化、剪枝的叠加效果（这些是正交技术，可叠加但不属于本页主题）。

    论断与来源（C）

    [C1] 两篇论文独立提出：Leviathan, Kalman, Matias. arXiv:2211.17192, 提交 2022-11-30，ICML 2023 Oral，命名 "Speculative Decoding"；Chen, Borgeaud, Irving, Lespiau, Sifre, Jumper. arXiv:2302.01318, 提交 2023-02-02，命名 "Speculative Sampling"。两者机制本质相同。来源：两篇 arXiv 摘要与提交历史。

    [C2] 单流解码是内存带宽受限：Leviathan et al. 2023 §1 引言对 "parallel scoring of short continuations" 成本的论证；Chen et al. 2023 摘要 "the latency of parallel scoring of short continuations ... is comparable to that of sampling a single token from the larger target model"。适用条件：batch size 小。

    [C3-C6] Draft-then-Verify 流程、接受规则、残差分布、bonus token：Leviathan et al. 2023 §2 算法描述与 Algorithm 1；Chen et al. 2023 §2 算法描述与 Eq.(2)。残差分布在 $p \leq q$ 处处成立时不被触发，此条件由 $\min(1, p/q) = 1$ 处处成立保证。

    [C7] 贪心退化为 argmax 匹配：Leviathan et al. 2023 §3 末尾对 greedy 的讨论；社区综述（howaiworks.ai）一致复述。

    公式与来源（F）

    [F1] 接受概率 $a(x) = \min(1, p(x)/q(x))$：Leviathan et al. 2023 §2.3 Eq.(1)；Chen et al. 2023 §2.1。边界 $p \geq q \Rightarrow a=1$、$p < q \Rightarrow a=p/q$、$p=0 \Rightarrow a=0$。

    [F2] 残差分布 $p'(x) = \max(0, p(x)-q(x)) / \sum_{x'} \max(0, p(x')-q(x'))$：Leviathan et al. 2023 §2 Algorithm 1 step 5-6；Chen et al. 2023 §2.2 Eq.(2)。

    [F3] 单位置输出分布 $\Pr[\text{emit } x] = \min(q(x), p(x)) + \max(0, p(x)-q(x)) = p(x)$：Leviathan et al. 2023 Appendix A.1（精确性证明）；Chen et al. 2023 §2.3 同结果。推导链见正文与折叠块，每步可手算复算，核心恒等式为 $\min(a,b) + \max(0, b-a) = b$。

    [F4] $\alpha = \sum_x \min(p(x), q(x)) = 1 - \mathrm{TV}(p, q)$：$\alpha$ 定义见 Leviathan et al. 2023 §3.2（Definition 3.1、Corollary 3.6）；TV 关系由 $\min(a,b) = (a+b-|a-b|)/2$ 推出（推导在正文）。

    [F5] $\mathbb{E}[L] = (1 - \alpha^{\gamma+1})/(1 - \alpha)$：Leviathan et al. 2023 §3.3 Theorem 3.8。截断几何级数闭式；i.i.d. 接受率假设。边界 $\alpha=1 \Rightarrow \gamma+1$、$\alpha=0 \Rightarrow 1$。

    [F6] $S = (1 - \alpha^{\gamma+1}) / [(1-\alpha)(1 + \gamma c)]$：Leviathan et al. 2023 §3.3 速度分析；社区综述（howaiworks.ai、aistackinsights.ai）明确给出此式。推导：每轮成本 $\gamma c + 1$、产出 $\mathbb{E}[L]$，$S = \mathbb{E}[L] / (1 + \gamma c)$。

    外部数字与实验条件（N）

    [N1] Leviathan et al. 2023 摘要：T5-XXL (11B) target，2×-3× 加速，输出与标准 T5X 实现完全相同（identical outputs）。来源：arXiv:2211.17192 摘要原文。

    [N2] Chen et al. 2023 摘要：Chinchilla 70B，分布式部署，2-2.5× 加速，"without compromising the sample quality or making modifications to the model itself"。来源：arXiv:2302.01318 摘要原文。

    [N3] Leviathan et al. 2023 §4 实验部分 Table 4：T5-base (约 250M) draft 给 T5-XXL (11B) target 打草稿，temp=0 时 $\alpha = 0.80$（$\gamma=7$）、temp=1 时 $\gamma=5$（$\alpha=0.68$），成本系数 $c = 0.04$。正文教学复算取 $\alpha=0.8, \gamma=5, c=0.04$ 为二者的组合，不对应单一实验行。复算 $S \approx 3.07$，与 [N1] 的 2-3× 范围一致。

    [N4] vLLM 官方博客 2024-10（社区综述 howaiworks.ai 引用）：高查询率批处理下，Llama 3 70B on 4×H100，speculative decoding 出现 1.4×-1.8× 减速。用于支撑工程实例与边界章节的退化讨论。

    构造示例

    本页的教学数字均为人为构造，目的是便于手算：

    • 「为什么串行解码慢」一章的「70B 权重 140GB / HBM 3.35 TB/s / 42ms 理论下限」：教学计算，数字来自 [gpu-execution-model] 页面的 H100 规格（80GB HBM3 @ 3.35 TB/s）与 70B 模型 FP16 权重约 140GB（2 字节/参数 × 70B）的常规换算。42ms 是带宽下限，不是实测单步延迟。
    • 「能快多少」一章的 $\alpha=0.8, \gamma=5, c=0.05$ 手算：数字来自 [N3]（Leviathan 原文实验参数），用于复算 [N1] 的 2-3× 加速。
    • 「能快多少」一章的 $\alpha=0.2$ 反例：纯粹构造，用于展示 $\alpha$ 低时加速消失。固定 $\gamma=5, c=0.05$ 以与正例对照。
    • 「把机制跑一遍」一章的贯穿例子（3 token 词表、$q_i, p_i$ 取一位小数）：纯粹构造，目的是覆盖接受、必接受、拒绝、残差重采样四种情形且残差和为 0.3 易归一化。不代表真实模型分布。
    • 词表 $V = \{A, B, C\}$ 与 $p_i, q_i$ 的具体数字：构造为使单位置证明可在每个 $x \in V$ 上手算验证。

    辅助解释与类比边界

    「为什么串行解码慢」一章的「开车去仓库取货」类比：只解释「读权重」与「算位置」的时间量级差异——开车时间固定、取一件和取 $\gamma+1$ 件开车时间相同。失效边界：不覆盖批量推理下的吞吐竞争（高并发时多个请求抢同一份带宽）；不覆盖流水线并行下的气泡问题；不覆盖 KV cache 读写开销。正式判断以单流带宽分析与「能快多少」一章加速比公式为准。

    「Draft-then-Verify」一章的「target 觉得 draft 高估了就倾向于拒绝」直觉：只帮助理解接受概率 $\min(1, p/q)$ 的方向性。失效边界：不构成保分布的证明（证明在「为什么这条规则能保分布」一章）；不覆盖 $p < q$ 但仍被接受的随机性（概率接受不等于必拒绝）。

    简化条件及其限制

    • i.i.d. 接受率假设（[F5]、[F6]）：实际各位置接受率取决于具体前缀，并非独立同分布。Leviathan et al. 2023 明确这是近似；不影响公式作为期望的近似刻画。可推出：期望 token 数与加速比的近似值。不可推出：单次采样的确切 token 数。
    • 词表缩小到 3 个 token（「把机制跑一遍」一章）：真实模型词表 3-30 万 token，无法手算；本简化是为了展示机制，不改变接受/拒绝规则的数学形式。可推出：规则在 3-token 词表上的行为。不可推出：真实大词表下的接受率（$\alpha$ 需要在真实分布上测量）。
    • 概率取一位小数（「把机制跑一遍」一章）：为了手算方便；真实模型输出多位有效数字。不影响残差归一化的数学过程。
    • 「单次前向传播给 $\gamma+1$ 个位置打分墙钟时间几乎相同」（「为什么串行解码慢」一章）：在 batch size 1、低负载下成立；高负载批处理下不成立（[N4]）。本简化帮助理解硬件前提，但不构成所有场景的加速保证。
    • 未展开 KV cache 的实现细节：假设其已存在。KV cache 是自回归解码的标准优化，与投机解码正交；不展开不影响对投机解码机制的理解。
