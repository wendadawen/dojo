投机解码（Speculative Decoding）

用小 draft 模型快速猜若干个候选 token，大 target 模型一次性并行验证，按修改版拒绝采样接受匹配的、修正不匹配的，在不改变输出分布的前提下减少大模型的串行调用次数。

更新于 2026-08-09 · 主要依据：Leviathan et al. 2023 (arXiv:2211.17192) + Chen et al. 2023 (arXiv:2302.01318)

1. 这个概念是什么

投机解码是一种 LLM 推理加速方法。它用两个模型协同：一个小的 draft 模型 $q$（快但可能不准）自回归地猜 $\gamma$ 个候选 token，一个大的 target 模型 $p$（慢但准，其分布 $p$ 是希望最终采样的目标）对这 $\gamma$ 个候选做一次前向传播并行验证。验证用修改版拒绝采样：每个候选 token 以概率 $\min(1, p/q)$ 接受，首个被拒绝处从残差分布重采样一个 token 并停止，全接受则免费多采一个 bonus token。这样一轮最多产出 $\gamma+1$ 个 token、最少产出 1 个，但只需 1 次大模型调用。

同一机制由两篇论文独立提出：Leviathan, Kalman, Matias（Google，ICML 2023 Oral，命名 "Speculative Decoding"）与 Chen, Borgeaud 等（DeepMind，命名 "Speculative Sampling"）。本文前置概念见 GPU 执行模型（带宽受限）与 标准 Transformer 注意力（因果注意力一次前向出每位置分布）。

2. 为什么需要它

  • 自回归解码串行慢：每生成 1 个 token 要串行调用 1 次大模型，生成 100 个 token 就要 100 次串行调用。
  • 单步解码是内存带宽受限，不是计算受限：每次调用要把全部权重从显存读一遍（如 70B 模型约 140GB），算术运算量相对很低、计算单元大量空闲。把权重读一遍之后，多用它算几个位置的乘积几乎不增加时间。
  • 「算 1 个 token」与「验证 $\gamma+1$ 个 token」墙钟时间几乎相同：Transformer 因果注意力让一次前向传播同时给出序列每个位置的分布。这意味着「核对 $\gamma$ 个候选」几乎免费——前提是有值得核对的候选。
  • 大模型生成中有很多「容易」的 token：括号闭合、常见搭配、复制 prompt 片段等接近确定性，小 draft 模型也能猜对。这些 token 让小模型猜、大模型核对，比让大模型逐个生成更划算。

3. 核心直觉

  • 两阶段：Draft（小模型自回归猜 $\gamma$ 个 token）→ Verify（大模型一次前向并行打分）→ 接受/拒绝/重采样。
  • 接受规则：对每个候选 token $x$，接受概率是 $\min(1, p(x)/q(x))$。若 target 觉得它至少和 draft 一样可能（$p \geq q$）必接受；若 target 觉得 draft 高估了它（$p < q$）以比值 $p/q$ 概率接受。直觉是「target 比 draft 更看好就放心接受，否则按比例接受」。
  • 残差重采样：首个拒绝处丢弃候选及之后所有 draft，从残差分布 $\mathrm{norm}(\max(0, p-q))$ 重采样一个 token 并停止。残差把 target 比 draft「多给」的概率拿出来重分配。
  • Bonus token：若 $\gamma$ 个全接受，target 同一次前向已经给出了第 $\gamma+1$ 个位置的分布，免费多采一个 token。
  • 从不比纯解码产出更少：最差情况是首个候选就被拒，仍从残差重采样出 1 个 token，与纯 target 解码相同——只是浪费了 draft 的工作。

4. 关键结论与边界

  • 输出分布与纯 target 采样完全相同（无损）。这是投机解码区别于量化、剪枝、蒸馏等近似加速的核心。证明：单位置上 $\Pr[\text{emit } x] = \min(q(x), p(x)) + \max(0, p(x)-q(x)) = p(x)$，两条互斥路径（draft 采到且接受 / 拒绝后残差重采样）相加恰好等于 $p(x)$。draft 只影响速度，不影响可能的输出集合。成立条件：使用残差重采样（不是直接从 $p$ 重采样，那会破坏分布）；仅受硬件数值精度影响。
  • 实测加速 2-3×。Leviathan et al. 2023 在 T5-XXL (11B) 上 2×-3×（输出 identical）；Chen et al. 2023 在 Chinchilla 70B 分布式部署上 2-2.5×（不修改模型、不降质量）。K3 用 EAGLE-3 作为 draft 模型（EAGLE-3 概念页）。成立条件：单流低负载、draft 单步成本远小于 target（$c \ll 1$）、target 与 draft 共享 tokenizer。
  • 接受率 $\alpha$ 是加速的核心杠杆。$\alpha = \sum_x \min(p(x), q(x)) = 1 - \mathrm{TV}(p,q)$（总变差距离），draft 越像 target、$\alpha$ 越高。$\alpha \approx 0.8, \gamma=5, c=0.05$ 时加速约 $2.95\times$；$\alpha$ 降到 0.2 时几乎不加速。
  • 不是无条件加速。高负载批处理下「空闲算力」消失，验证 $\gamma+1$ 个位置会挤占本可服务其他请求的算力——vLLM 实测在高查询率下出现 1.4×-1.8× 减速。投机解码是「用空闲算力换延迟」的策略，单流低负载下加速、高并发下可能减速。
