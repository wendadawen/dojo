增量 KV 传输

PD 分离推理中，decode 节点自己 prefix cache 命中的块不再由 prefill 侧全量重传——D 侧把命中块数传回 P 侧，P 侧只发送增量。

更新于 2026-09-03

这是什么

增量 KV 传输（任务语境中称 increase KV：只传「增加部分」的 KV）是 PD 分离推理系统的一项 KV 传输优化：请求头部在 decode 侧本地前缀缓存命中的块，不再由 prefill 侧重传。D 侧把头部连续命中的块数算出来，P 侧发送前从块序列头部切掉这一段，只传输 D 侧没有的增量。

问题从哪来

PD 分离把 prefill 与 decode 放到不同节点，prefill 产出的整条 prompt KV 必须经 RDMA 搬进 decode 侧显存。而 D 侧自己也运行 前缀缓存：系统提示词、多轮对话历史这些共享前缀的 KV 早已在 D 侧显存里。旧逻辑下 P 侧不掌握命中信息，仍把整条 prompt 的 KV 全量传过来——命中块被内容完全相同的块覆写一遍，这部分传输的字节与时间没有任何收益。浪费的根源是信息不对称：D 侧知道命中了什么，P 侧不知道。

核心机制

  • D 侧在本地 prefix cache 中匹配请求前缀，头部连续命中的块数即 num_skip_blocks（前缀匹配从第 0 个 token 起逐 token 精确、按块粒度命中，见 前缀缓存）。
  • num_skip_blocks 随 D 发往 P 的 block_ids 消息传递——命中信息逆着请求方向传回 P 侧。
  • P 侧 worker（执行发送的工作进程）收到后，把 local/remote 两条 block id 列表在同一 skip 偏移处切掉同样长度的头部，只发送剩余部分（块的编号与组织见 PagedAttention）。
  • 同偏移、等长切头是配对不变量：两条列表按位置对应同一条 prompt 的块序列，同步切头使剩余部分的按位对应原样保留。

关键结论与边界

  • 传输量从全部块降到未命中的块，节省比例恰好等于头部命中率；同链路同带宽下，传输时间的节省比例与字节一致。
  • 正确性依赖三个条件：命中块内容与 P 侧将传内容一致（同一前缀、同一模型下 K/V 确定，见 KV cache）；命中发生在头部且对齐块边界；skip 数准确。任一不满足须回退全量传输。
  • 它只省传输，不省 prefill 计算——P 侧是否重算是 P 侧 lookup（省计算线）的事；也不解决 D 侧缓存容量与绝对带宽问题。零命中时不亏不赚，只多一个消息字段。
  • 本页机制为工程实践的行为级描述（无公开论文定位），字段与消息结构以该描述为准；细节与手算传输账见完整说明页。
