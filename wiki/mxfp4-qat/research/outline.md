# MXFP4 量化感知训练 outline：教学大纲

## 页面开头

**钩子**：把一个 670 亿参数级的 MoE 大模型从 BF16 部署换成 4-bit 部署，显存能从 ~118 GB 压到 ~31 GB——但模型从未在 4-bit 下训练过，推理时权重突然"差一点"，质量会掉。怎么让模型在被压到 4-bit 后仍像训练时那样准？

**一句话解释**：MXFP4 量化感知训练（MXFP4 QAT）把权重编码到 4-bit 微缩浮点格式 MXFP4，并在训练的前向就模拟这种量化、反向用直通估计器传梯度，使模型在部署时用真正的 4-bit 权重仍保持训练时的精度。

**要解决的具体问题**：低位宽量化会引入离散误差，若训练时全精度、推理时才量化（PTQ），模型从未见过该误差，质量下降显著；RL 中还会出现 rollout（推理分布）与训练分布的 mismatch。

**学习承诺**（与 scope Q1–Q5 一致，写入 learning-goals 组件）：读完你能回答——为什么 MoE 专家权重是量化首选、能省多少；MXFP4 一个权重怎么编码、为什么共享 scale 比独立 4-bit 强；QAT 前向和反向各做什么、与 PTQ 差别在哪；K3 为什么把 QAT 贯穿 SFT+RL 且 rollout 与训练必须共享量化方案；K3 量化了哪些组件、不量化哪些。

**首个场景**：K3 的 896 个路由专家占参数绝大部分但每 token 只激活 16 个——这是"量化专家收益最大、质量影响最小"的入口。

**前置引用**：量化基础（伪量化、STE 的最小说明）见 `quantization-basics`（占位）；MoE 层结构、router、专家稀疏激活见 [MoE 大模型推理与服务基础](../../wiki/moe-serving/index.html)。

**过渡**：先看清"压什么、压多少"——下一章 S1。

## 章节设计

### S1：把 896 个 MoE 专家压到 4-bit，能省多少显存？

- 主要教学问题：为什么 MoE 模型的专家权重是量化首选，量化到 MXFP4 能省多少
- 对应范围：Q1；C1；N1–N3
- 正文要点：
  - MoE 模型的专家数量多（K3 共 896 路由专家 + 2 共享专家，N1）；每个路由专家是一个 3 投影 FFN（gate/up/down，由 config ignore 列表印证）
  - 稀疏激活只省计算不省显存：每 token 仅 16/896 激活，但全部 896 专家权重必须全量驻留显存（链接 moe-serving）
  - 手算（N3，教学示例）：3 × 7168 × 3072 ≈ 66.06M 每专家；896 × 66.06M ≈ 59.19B；BF16 ~118.38 GB；MXFP4 ~31.44 GB；压缩 ~3.76×
  - 非专家组件（attention、shared expert、router）参数量远小且频繁参与每 token 计算，不是显存瓶颈
- 讲解材料及职责：
  - 数字例子 N3：展示"为什么值得为专家付 QAT 成本"——压缩收益的量级
  - 对照（隐含）：BF16 vs MXFP4 的字节数差异
- 前置知识：moe-serving（链接）；FFN 3 投影结构（moe-serving 已含）
- 完成检查：
  - 给定 K3 的 hidden=7168、intermediate=3072、num_experts=896，估算专家总参数与 BF16/MXFP4 显存
  - 解释"为什么稀疏激活不省显存"
- 过渡：省了显存，但 MXFP4 到底怎么把一个权重压到 4 bit——下一章 S2

### S2：MXFP4 是怎么编码一个权重的

- 主要教学问题：MXFP4 一个权重值怎么存，为什么"32 个一组共享 scale"比"每个值独立 4-bit"表达力强
- 对应范围：Q2；C5、C7、C9；F1、F3；N4、N5；E1
- 正文要点：
  - 块结构：32 个连续权重为一组，共享一个 E8M0 scale（8-bit 无符号指数，$s_b = 2^{e_b}$，范围 $2^{-127}$ 到 $2^{128}$）；每个权重存为 4-bit E2M1 浮点元素（1 符号 + 2 指数 + 1 尾数，bias=1）
  - E2M1 正数可表示正常值集合 {0.5, 0.75, 1.0, 1.5, 2.0, 3.0, 4.0, 6.0}（C9）；元素只承担块内相对精度，动态范围由共享 scale 承担
  - 反量化公式 F1：$\hat{x}_i = s_b \cdot \mathrm{FP4}(q_i)$
  - 有效位宽 F3：$4 + 8/32 = 4.25$ bit/权重；相对 BF16 的理论压缩 $\approx 3.76\times$
  - 为什么共享 scale 比独立 4-bit 强：独立 4-bit 每个值自己管动态范围，范围极窄；共享 scale 把动态范围交给 8-bit scale（覆盖 FP32 量级范围），元素只承担块内相对差异——这正是"4-bit 仍可用"的关键
  - ASCII 图示（C1）：块结构
  - 手算 E1（N5 教学示例，4 元素块教学缩写）：
    - 块 1 = [0.50, -0.25, 1.00, 0.75]，scale 0.25，归一化后均落在 E2M1 可表示值，量化无损
    - 块 2 = [0.30, 0.10, 0.45, 0.20]，含不可表示值，E2M1 最近邻舍入后反量化为 [0.25, 0.125, 0.50, 0.1875]，误差非零
- 讲解材料及职责：
  - 公式 F1：表达反量化关系
  - ASCII 图示：表达块结构（scale + 元素数组）
  - 数字例子 E1：展示量化与反量化算术；正反对照（块 1 无损 vs 块 2 有损）展示误差来源
- 前置知识：无（本章是机制自包含）
- 完成检查：
  - 给定 scale=0.25 与一个 4 元素块，写出归一化、量化、反量化与误差
  - 解释"共享 scale 承担动态范围、元素承担块内相对精度"
  - 估算每权重的有效位宽与相对 BF16 的理论压缩比
- 过渡：块 2 的非零误差正是量化引入的精度损失——下一章 S3 讲 QAT 怎么让模型适应它

### S3：QAT 在前向和反向做了什么，与 PTQ 差在哪

- 主要教学问题：QAT 的前向伪量化与反向 STE 机制；PTQ vs QAT
- 对应范围：Q3；C6；F2；E2；代码 C1
- 正文要点：
  - 量化为什么引入误差（回顾 S2 块 2）：4-bit 离散级粗 + 舍入 → 权重被"四舍五入"到最近 E2M1 值
  - PTQ：训练全程全精度 $w$，推理时才量化为 $\hat{w}$ → 模型从未见过 $\hat{w}$ 与 $w$ 的偏差
  - QAT 前向伪量化：先量化再反量化得到 $\hat{w}$，用 $\hat{w}$（不是 $w$）算前向与损失 $L$；模型每个前向都"看见"该偏差
  - QAT 反向 STE（F2）：$\partial\hat{w}/\partial w \equiv 1$，梯度绕过不可导的量化步骤直传到原始高精度 $w$；权重更新发生在 $w$ 上
  - 手算 E2（N5 教学示例单权重）：$w=0.80$、$s_b=0.25$ → 归一化 3.2 → E2M1 最近邻 3.0 → $\hat{w}=0.75$ → 前向偏差 0.05；上游梯度 $g=1$ → STE 传回 $\partial L/\partial w = 1$
  - 可运行代码 C1：模拟 E2M1 量化、块 1/块 2、单权重 QAT 前向 + STE 反向；正文只放机制说明与结论，代码与输出在折叠块
  - 直觉解释（教学解释，标边界）：把 STE 类比为"梯度把量化算子当作透明的窗户"——只帮助理解"梯度为何能穿过不可导步骤"；失效边界：STE 不保证收敛到量化前最优、不处理梯度 magnitude 失真
  - 误解 4（PTQ 差别不大）：正文对照说明
- 讲解材料及职责：
  - 公式 F2：表达 STE 约束
  - 数字例子 E2：展示单权重 fake-quant + STE 的逐步算术
  - 可运行代码 C1：验证机制可执行，输出与手算一致
  - 教学解释：STE 直觉
- 前置知识：quantization-basics（占位链接，给伪量化与 STE 的最小说明）
- 完成检查：
  - 解释 fake-quant 前向为什么用 $\hat{w}$ 而不是 $w$
  - 解释 STE 为什么能让梯度穿过不可导的量化
  - 给定 $w$ 与 $s_b$，写出 $\hat{w}$ 与 STE 传回的梯度
  - 说出 PTQ 与 QAT 在"训练时是否模拟量化"上的关键差别
- 过渡：QAT 让模型适应量化；但 RL 还多一层"rollout 与训练必须同分布"的要求——下一章 S4

### S4：K3 怎么把 QAT 贯穿 SFT 和 RL，且不产生 train-inference mismatch

- 主要教学问题：K3 把 QAT 贯穿 SFT+RL、rollout 与训练共享量化方案的动机
- 对应范围：Q4；C1、C2、C4；N6
- 正文要点：
  - 内联最小 RL 框架（教学框架，不展开 RL 算法）：RL 中模型边自己生成数据（rollout，即推理）边据此更新参数（训练）；rollout 输出经奖励塑形成为训练 target
  - SFT 阶段做 QAT：模型在监督微调中就适应量化精度损失
  - RL 阶段的 mismatch 风险：若 rollout（推理）用量化方案 A、训练用量化方案 B，则 target 来自分布 A、梯度优化分布 B → train-inference mismatch，可能使 RL 崩坏或收敛到错误方向
  - K3 的解法（C2）：rollout 与训练共享同一 MXFP4（权重）+ MXFP8（激活）量化方案 → 消除 mismatch
  - draft model 一致性（C4）：EAGLE-3 风格 draft 沿用同一 QAT 配置，保证 target 与 draft 的量化行为一致（一句话，不展开 EAGLE-3 / LK loss）
  - 误解 2（QAT 让模型"恢复"精度）：正文对照说明
  - ASCII 图示（C2）：rollout 与训练共享量化方案的循环
- 讲解材料及职责：
  - ASCII 图示 C2：表达 rollout → 训练的循环与"共享量化方案"的位置
  - 教学框架：RL 的最小机制（不展开算法）
- 前置知识：无独立 RL 概念页；内联最小框架
- 完成检查：
  - 解释为什么 RL 中 rollout 与训练量化方案不一致会产生 mismatch
  - 说出 K3 的解法（共享同一量化方案）
  - 解释为什么 SFT 阶段也要做 QAT（不只是 RL）
- 过渡：贯穿 SFT+RL 解决了"训练时模拟量化"；但量化哪些组件、不量化哪些是另一层工程判断——下一章 S5

### S5：K3 量化了哪些组件、不量化哪些，为什么

- 主要教学问题：K3 选择性量化策略与 config.json 证据
- 对应范围：Q5；C3、C8；N1、N4、N6；表格 C3
- 正文要点：
  - 量化对象：MoE 路由专家权重 → MXFP4；专家输入激活 → MXFP8（N6）
  - 非量化对象：attention 投影、latent MoE 投影、共享专家、MoE router、lm_head、vision tower、mm_projector（C3）
  - config.json 证据（C8）：`format: "mxfp4-pack-quantized"`、`group_size: 32`、`num_bits: 4`、`type: "float"`、`strategy: "group"`、`symmetric: true`；`ignore` 列表正则匹配 `self_attn`、`shared_experts`、`mlp.(gate|up|gate_up|down)_proj`、`lm_head`、`vision_tower`、`mm_projector`
  - 动机：路由专家占参数绝大部分（S1 的 59.19B）但稀疏激活（16/896），量化收益最大、对每 token 计算的质量影响相对小；非专家组件频繁参与每 token 计算、对精度更敏感、参数占比小，保持高精度既保质量又几乎不增显存
  - 对照表格 C3：量化对象 vs 非量化对象的组件、格式、动机
