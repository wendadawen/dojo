    把 896 个 MoE 专家压到 4-bit，能省多少显存？

    MoE 模型把 Transformer 层里的 FFN 换成"一排专家加一个 router"。router 为每个 token 只选 top-k 个专家计算，其余专家不计算——这叫稀疏激活。K3 有 896 个路由专家，每个 token 仅激活 16 个（见官方 config.json 的 num_experts_per_token: 16），另有 2 个共享专家处理所有 token。

    稀疏激活只省计算，不省显存。全部 896 个专家的权重必须时刻驻留显存，因为 router 在运行时可能选中任意一个。所以"模型总参数量"和"每个 token 的计算量"在 MoE 里是解耦的：参数随专家数增长，每 token 计算只随激活数 k 增长。这也是为什么 MoE 模型的显存压力远比同等计算量的稠密模型大。

    每个路由专家本身是一个 3 投影 FFN（gate_proj、up_proj、down_proj，投影名与 config.json 量化忽略列表中的 dense FFN 投影同名，但完整路径含 .experts. 段故不匹配该正则，因此专家是被量化的对象）。注意 config 给的 hidden_size = 7168 是模型整体隐藏维度，而路由专家用的是更小的 routed_expert_hidden_size = 3584；moe_intermediate_size = 3072。每个专家约 $3 \times 3584 \times 3072 \approx 33.03\mathrm{M}$ 参数。num_experts = 896 是每层专家数，first_k_dense_replace = 1 表示前 1 层为 dense FFN，所以 num_hidden_layers = 93 层中 92 层是 MoE。总专家参数量约 $896 \times 92 \times 33.03\mathrm{M} \approx 2.71\mathrm{T}$，与 K3 报告"2.8T 总参"一致——专家 dominate 了模型参数。

    BF16 下每参数 2 字节，这些专家权重约 $5.4$ TB。压到 MXFP4（每元素 4 bit、每 32 元素共享 1 字节 scale）后约 $1.44$ TB，压缩约 $3.76\times$。省下来的显存是约 4 TB 的量级——这正是"为什么值得为专家付出 QAT 的训练成本"。

    完整手算：每个专家参数量与 BF16/MXFP4 显存

    教学示例。输入取自官方 config.json：routed_expert_hidden_size = 3584、moe_intermediate_size = 3072、num_experts = 896（每层）、num_hidden_layers = 93、first_k_dense_replace = 1（前 1 层为 dense FFN，其余 92 层为 MoE）。每个路由专家是 3 投影 FFN（gate/up/down，各为 $3584 \times 3072$ 或 $3072 \times 3584$），所以单专家参数量：

    $$3 \times 3584 \times 3072 = 33{,}030{,}144 \approx 33.03\mathrm{M}.$$

    92 个 MoE 层 × 每层 896 个专家 = 82,432 个专家，合计：

    $$82{,}432 \times 33.03\mathrm{M} \approx 2.71\mathrm{T}\ \text{参数}.$$

    BF16（2 字节/参数）显存：$2.71\mathrm{T} \times 2 \approx 5.42$ TB（约 5.4 TB）。

    MXFP4：元素 4 bit = 0.5 字节/参数；共享 E8M0 scale 1 字节/32 参数。两者分别：

    $$\text{元素} = 2.71\mathrm{T} \times 0.5 \approx 1.355\ \text{TB},\qquad \text{scale} = \frac{2.71\mathrm{T}}{32} \times 1 \approx 84.7\ \text{GB} \approx 0.085\ \text{TB},$$

    合计约 $1.44$ TB。压缩比 $5.42 / 1.44 \approx 3.76\times$。

    这是数量级估算，忽略了权重张量的对齐 padding 与 latent MoE 结构的内部细节；用于判断"值得量化"，不作为精确部署数字。每权重的有效位宽 $= 4 + 8/32 = 4.25$ bit，相对 BF16 的 16 bit 理论压缩 $= 16 / 4.25 \approx 3.76\times$，与上面按总字节数算出的结果一致——这是一个交叉验证。

    对照一下：非专家组件（attention 投影、共享专家、router、lm_head）参数量远小于专家参数总量（约 2.71T），而且每个 token 都要计算，既不是显存瓶颈，也不是量化首选。这为后文 S5 "只量化专家"的选择埋下伏笔。

    MXFP4 是怎么编码一个权重的

    先看为什么"每个值独立 4-bit"不够用。一个 4-bit 数最多有 16 个离散级。若每个权重独立用 4-bit，又要同时覆盖从 $0.001$ 到 $10$ 的范围，那相对精度会极差——大值和小值共用同一组离散级，小值几乎无法分辨。

    MXFP4 的做法是把 32 个连续权重组成一个块。块内共享一个 scale $s_b$，它是 8-bit 无符号指数 E8M0，取值 $s_b = 2^{e_b}$，范围从 $2^{-127}$ 到 $2^{128}$——接近 FP32 的动态范围。每个权重自己只存 4-bit 的 E2M1 浮点元素。

    E2M1 编码是"1 符号 + 2 指数 + 1 尾数"（指数 bias 为 1）。它的正数正常可表示值只有 8 个：$\{0.5,\ 0.75,\ 1.0,\ 1.5,\ 2.0,\ 3.0,\ 4.0,\ 6.0\}$，最大可表示幅度是 6。元素只承担块内相对精度，动态范围交给共享 scale——这是"4-bit 仍可用"的关键：整块用 8-bit scale 选对量级，元素只在该量级内分辨相对差异。

    MXFP4 块（块大小 = 32，真实格式；下图为教学缩写 4 元素）
┌────────────────┬──────┬──────┬──────┬──────┬ ┄ ┄ ──┬──────┐
│ 共享 scale s_b │ q_1  │ q_2  │ q_3  │ q_4  │       │ q_32 │
│  E8M0 (8 bit)  │ E2M1 │ E2M1 │ E2M1 │ E2M1 │       │ E2M1 │
│  = 2^e_b       │ 4bit │ 4bit │ 4bit │ 4bit │       │ 4bit │
└────────────────┴──────┴──────┴──────┴──────┴ ┄ ┄ ──┴──────┘
        │           │      │      │      │             │
        └───────────┼──────┼──────┼──────┼─────┄ ┄ ┄ ────┤
                    │      │      │      │             │
                    ▼      ▼      ▼      ▼             ▼
            反量化 x̂_i = s_b · FP4(q_i)  （每个元素乘共享 scale）

存储：1 字节 scale + 32 × 4 bit 元素 = 1 + 16 = 17 字节 / 32 权重
每权重有效位宽 = 4 + 8/32 = 4.25 bit

    反量化把存下来的 4-bit 元素 $q_i$ 还原成近似权重 $\hat{x}_i$：

    $$\hat{x}_i = s_b \cdot \mathrm{FP4}(q_i),\qquad s_b = 2^{e_b}.$$

    这里 $s_b$ 是块共享的 power-of-two scale，$q_i$ 是 E2M1 量化值，$\hat{x}_i$ 是反量化得到的近似权重（不等于原始权重 $x_i$，差值就是量化误差）。每权重的有效位宽约 $4 + 8/32 = 4.25$ bit，相对 BF16 的 16 bit 理论压缩 $\approx 16 / 4.25 \approx 3.76\times$。

    完整手算：两个 4 元素块的量化、反量化与误差

    教学示例。设块共享 scale $s_b = 0.25$，块大小教学缩写为 4（真实为 32）。E2M1 正数可表示值为 $\{0.5, 0.75, 1.0, 1.5, 2.0, 3.0, 4.0, 6.0\}$。

    块 1（恰好都可表示）：原始权重 $[0.50,\ -0.25,\ 1.00,\ 0.75]$。归一化 $x_i / s_b = [2.0,\ -1.0,\ 4.0,\ 3.0]$，全部落在 E2M1 可表示值内，量化无损。存储：1 字节 scale + $4 \times 4$ bit = $1 + 2 = 3$ 字节（BF16 需 8 字节）。反量化：

    $$\hat{x}_i = 0.25 \times [2.0,\ -1.0,\ 4.0,\ 3.0] = [0.50,\ -0.25,\ 1.00,\ 0.75],$$

    误差 $[0,\ 0,\ 0,\ 0]$。

    块 2（含不可表示值）：原始权重 $[0.30,\ 0.10,\ 0.45,\ 0.20]$。归一化 $[1.2,\ 0.4,\ 1.8,\ 0.8]$，含不在 E2M1 可表示集合中的值，按最近邻舍入：

    • $1.2 \to 1.0$（距 1.0 为 0.2，距 1.5 为 0.3，取近）
    • $0.4 \to 0.5$（距 0.5 为 0.1，距 0 为 0.4，距 0.75 为 0.35，取近）
    • $1.8 \to 2.0$（距 2.0 为 0.2，距 1.5 为 0.3，取近）
    • $0.8 \to 0.75$（距 0.75 为 0.05，距 1.0 为 0.2，取近）

    量化值 $q = [1.0,\ 0.5,\ 2.0,\ 0.75]$。反量化：

    $$\hat{x}_i = 0.25 \times [1.0,\ 0.5,\ 2.0,\ 0.75] = [0.25,\ 0.125,\ 0.50,\ 0.1875].$$

    误差 $x_i - \hat{x}_i = [0.05,\ -0.025,\ -0.05,\ 0.0125]$。相对误差分别约 $17\%$、$25\%$、$11\%$、$6\%$。

    块 1 与块 2 的对照展示两件事：块 1 说明"若值恰好可表示，MXFP4 可以无损"；块 2 说明"一旦值落在离散级之间，最近邻舍入就会引入非零误差"——这个误差正是下一章 QAT 要让模型适应的对象。

    块 1 全部无损、块 2 出现最大 $25\%$ 的相对误差——这种"粗离散级 + 舍入"正是 4-bit 量化的精度代价。真实权重分布里，块 2 这种情况占大多数，所以误差不可忽略。

    QAT 在前向和反向做了什么，与 PTQ 差在哪

    S2 块 2 已经显示：4-bit 离散级粗、最近邻舍入会把权重"四舍五入"到最近的 E2M1 值，于是反量化得到的 $\hat{w}$ 不等于原始权重 $w$。这就是量化误差。问题是：训练时用全精度 $w$、推理时才用 $\hat{w}$，模型从未见过这个偏差——质量会掉多少？

    训练后量化（PTQ）就是这种做法：训练全程用全精度 $w$ 算前向和损失，推理时才把 $w$ 量化成 $\hat{w}$ 使用。模型训练时从未见过 $\hat{w}$ 与 $w$ 的偏差，推理时这些偏差对模型来说是分布外的。

    量化感知训练（QAT）反过来：让训练的前向就模拟量化。具体分两步。

    前向伪量化（fake-quant）：先把高精度权重 $w$ 按 MXFP4 规则"量化再反量化"，得到近似权重 $\hat{w}$，用 $\hat{w}$（不是 $w$）算前向和损失 $L$。于是模型每个前向都"看见"了量化偏差——损失是在量化后的权重上算出来的，梯度会反映"量化后还差多少"。

    反向遇到一个麻烦：量化里的"最近邻舍入"对 $w$ 不可导（它是离散的阶梯函数）。直通估计器（STE）的处理是直接令：

    $$\frac{\partial \hat{w}}{\partial w} \equiv 1.$$

    也就是说，把量化算子当作"透明的"——梯度绕过不可导的舍入步骤，原样传回原始高精度权重 $w$。权重更新发生在 $w$ 上，而不是量化后的 $\hat{w}$ 上。这样训练循环是：前向用 $\hat{w}$（看见偏差），反向用 STE 把梯度直传到 $w$，更新 $w$；下一轮前向 $w$ 变了，$\hat{w}$ 也跟着变。

    下面手算单权重的一步。

    完整手算：单权重 QAT 一步（fake-quant 前向 + STE 反向）

    教学示例。设单个权重 $w = 0.80$，所在块的共享 scale $s_b = 0.25$（教学给定；真实由块内最大幅度按 OCP 规则选）。

    前向伪量化：

    • 归一化 $w / s_b = 0.80 / 0.25 = 3.2$。
    • E2M1 最近邻舍入：$3.2$ 距 $3.0$ 为 $0.2$，距 $4.0$ 为 $0.8$，取近，得 $q = 3.0$。
    • 反量化 $\hat{w} = s_b \cdot q = 0.25 \times 3.0 = 0.75$。
    • 前向用 $\hat{w} = 0.75$ 算损失（不是用 $w = 0.80$）。前向偏差 $w - \hat{w} = 0.05$。

    反向 STE：设损失对 $\hat{w}$ 的上游梯度为 $g = 1.0$。STE 约束 $\partial\hat{w}/\partial w \equiv 1$，按链式法则：

    $$\frac{\partial L}{\partial w} = \frac{\partial L}{\partial \hat{w}} \cdot \frac{\partial \hat{w}}{\partial w} = g \cdot 1 = 1.0.$$

    梯度原样传到 $w$。权重更新发生在原始高精度 $w = 0.80$ 上，不发生在量化值 $0.75$ 上。

    对比 PTQ：若用 PTQ，训练时前向直接用 $w = 0.80$，模型从未见过 $0.05$ 这个偏差；推理时才量化为 $\hat{w} = 0.75$，偏差是分布外的。QAT 的每个前向都把 $0.05$ 这个偏差算进损失，权重会朝"在量化后仍能减小损失"的方向调整。

    # 教学示例：MXFP4 的最小量化模拟（E2M1，块大小教学缩写为 4）
E2M1_LEVELS = [0.0, 0.5, 0.75, 1.0, 1.5, 2.0, 3.0, 4.0, 6.0]  # 正数可表示值

def nearest_e2m1(x):
    # 对绝对值量化，保留符号
    sign = 1.0 if x >= 0 else -1.0
    a = abs(x)
    best = min(E2M1_LEVELS, key=lambda v: abs(v - a))
    return sign * best

def mxfp4_quantize(block, scale):
    # 归一化、量化到 E2M1、反量化
    q = [nearest_e2m1(x / scale) for x in block]
    xhat = [scale * v for v in q]
    return q, xhat

def ste_grad(upstream_grad):
    # Straight-Through Estimator：梯度直通
    return upstream_grad

# 块 1：恰好可表示
block1 = [0.50, -0.25, 1.00, 0.75]
q1, xhat1 = mxfp4_quantize(block1, scale=0.25)
print("block1 原值:", block1)
print("block1 量化:", q1)
print("block1 反量化:", xhat1)
print("block1 误差:", [a-b for a,b in zip(block1, xhat1)])

# 块 2：含不可表示值
block2 = [0.30, 0.10, 0.45, 0.20]
q2, xhat2 = mxfp4_quantize(block2, scale=0.25)
print("block2 原值:", block2)
print("block2 量化:", q2)
print("block2 反量化:", xhat2)
print("block2 误差:", [round(a-b, 4) for a,b in zip(block2, xhat2)])

# QAT 单步：fake-quant 前向 + STE 反向
w = 0.80
scale = 0.25
w_norm = w / scale
w_q = nearest_e2m1(w_norm)
w_hat = scale * w_q  # 前向用的"近似权重"
g_upstream = 1.0
g_w = ste_grad(g_upstream)  # STE：梯度直通
print(f"w={w}, 量化后 w_hat={w_hat}, 前向偏差={w - w_hat:.4f}")
print(f"上游梯度 g={g_upstream}, STE 传回 w 的梯度={g_w}")

    观察重点：块 1 误差全零（值恰好可表示）；块 2 误差非零（粗离散级 + 舍入）；单权重 $w=0.80$ 量化后 $\hat{w}=0.75$、前向偏差 $0.05$；STE 把上游梯度 $1.0$ 原样传回 $w$。

    教学简化：本代码用 Python 列表与 min 模拟 E2M1 最近邻，不涉及真实硬件的打包位布局与 scale 选取算法；块大小教学缩写为 4，真实 MXFP4 块为 32。它只验证量化与 STE 的算术，不模拟真实训练的批量张量与梯度反传。

    教学解释。 可以把 STE 暂时理解为"梯度把量化算子当作一扇透明的窗户"——梯度穿过它时数值不变，所以不可导的舍入步骤不会阻断反向传播。这个类比只帮助理解 STE 公式里 $\partial\hat{w}/\partial w \equiv 1$ 这一项的来历。它不保证训练一定收敛到量化前的最优解，也不处理梯度幅度（magnitude）在穿过量化时可能出现的失真；正式判断仍以 STE 约束和损失函数条件为准。

    这里有一个常见误解值得点破："QAT 让模型恢复量化损失的精度"是错的。QAT 不恢复精度——权重仍以 4-bit 部署；QAT 做的是让权重在训练中朝"在 4-bit 下仍能减小损失"的方向调整，从而补偿（部分）精度损失带来的质量下降。补偿多少取决于训练数据与 QAT 配置，不是无损还原。

    另一个常见误解："PTQ 和 QAT 反正都量化，差别不大"是错的。PTQ 训练时从未见过量化误差，推理时量化引入分布外的权重，精度下降通常显著大于 QAT；下一章会看到，RL 中 PTQ 还会引入 rollout 与训练分布的 mismatch。QAT 的核心收益就是"训练时已模拟该误差"。

    K3 怎么把 QAT 贯穿 SFT 和 RL，且不产生 train-inference mismatch

    先给一个最小的 RL 框架（不展开 RL 算法本身）。RL 中模型一边自己生成数据（rollout，即推理），一边据此更新参数（训练）。rollout 的输出经过奖励塑形成为训练 target——也就是"模型在学自己产出的东西"。这个"自产自销"的结构是后面 mismatch 问题的根源。

    SFT 阶段做 QAT 的理由直接来自 S3：监督微调时模型就在 MXFP4 量化下训练，权重朝"量化后仍能减小 SFT 损失"的方向调整。模型在监督信号下就适应了量化精度损失。

    RL 阶段多一层要求。RL 的训练 target 来自 rollout 的输出，而 rollout 本身就是一次推理——也就是说，rollout 用的量化方案决定了 target 来自哪个分布。若 rollout（推理）用量化方案 A、训练用量化方案 B，则：

    • target 来自分布 A（rollout 的量化行为）；
    • 梯度优化分布 B（训练的量化行为）；
    • 两者不一致就是 train-inference mismatch。

    这个 mismatch 在 RL 里尤其致命：RL 的 bootstrap target 依赖 rollout 输出，若 target 与梯度指向不同分布，模型可能朝错误方向收敛，甚至训练崩坏。

    K3 的解法是让 rollout 与训练共享同一套量化方案——MoE 专家权重用 MXFP4、激活用 MXFP8，且 rollout 和训练都用这套。这样 target 与梯度指向同一个分布，mismatch 被消除。下图把这一循环画出来：

    K3 的 RL 循环（rollout 与训练共享同一量化方案）

   ┌─────────────────────────────────────────────────────────┐
   │                   共享量化方案                          │
   │      专家权重 MXFP4   +   激活 MXFP8                    │
   │   （rollout 和训练 都用这一套，不分两套）                │
   └─────────────────────────────────────────────────────────┘
            ▲                                    ▲
            │                                    │
      rollout 推理                          训练更新参数
   （用量化方案生成                          （用量化方案算
     rollout 输出）                            梯度）
            │                                    │

   rollout 输出 ──► 奖励塑形 ──► 训练 target ───┘

    这里也带出 draft model 的一致性问题。K3 用 EAGLE-3 风格的 draft model 做投机解码加速（draft 的具体结构不是本页主题，不展开）。K3 让 draft model 沿用与 target model 相同的 QAT 配置——MoE 专家权重 MXFP4、激活 MXFP8、非专家保持高精度。这样 target 与 draft 的量化行为一致，避免投机解码里 draft 与 target 的数值路径分裂。

    再点破一个误解："QAT 让模型恢复量化精度"是错的（S3 已说过，这里再强调一遍在 RL 语境下的含义）：QAT 不是让 RL 拿回量化前的精度，而是让 rollout 与训练在同一个量化分布上对齐——对齐的是"分布"，不是"精度"。

    K3 量化了哪些组件、不量化哪些，为什么

    把前面几章的结论汇总成一张选择表。K3 不是把整个模型都压到 4-bit，而是选择性量化。表中"latent MoE 投影"指 MoE 层中除路由专家 per-expert 权重外的公共投影部分（如 MoE 层输入/输出的公共线性变换），与路由专家的 per-expert 权重相对——它在每个 token 上都参与计算，属于"公共路径"而非"稀疏激活的专家"。

    组件是否量化格式动机
    MoE 路由专家权重（896 个/层 × 92 层）量化MXFP4占参数绝大部分（约 2.71T），稀疏激活（16/896），量化收益最大、对每 token 计算质量影响相对小
    专家输入激活量化MXFP8激活位宽影响中间计算与显存带宽；8-bit 浮点比 4-bit 对激活更稳
    attention 投影不量化高精度每个 token 都计算，对精度敏感；参数占比小
    latent MoE 投影不量化高精度MoE 层的公共投影部分，频繁参与计算
    共享专家（2 个）不量化高精度处理所有 token，精度敏感；参数占比小
    MoE router不量化高精度路由决定本身是概率/top-k 选择，对数值精度极敏感
    lm_head不量化高精度最终输出 logits，直接决定 token 分布
    vision tower / mm_projector不量化高精度视觉编码器与投影，参数占比小

    这张表的依据不只是 K3 报告的文字描述，还能在官方 config.json 里直接核对。K3 的 quantization_config 字段记录了量化格式与不量化的模块列表。

    来源：HuggingFace moonshotai/Kimi-K3 仓库 config.json，text_config.quantization_config 字段。

    关键字段：format: "mxfp4-pack-quantized" 确认 MXFP4 打包格式；group_size: 32 与 OCP 块大小一致；num_bits: 4、type: "float"、symmetric: true 对应 E2M1 对称浮点；strategy: "group" 表示按组（块）量化。ignore 列表用正则匹配不量化的模块：self_attn（attention）、shared_experts（共享专家）、mlp.(gate|up|gate_up|down)_proj（前 1 层 dense FFN 的投影，first_k_dense_replace = 1）、lm_head、vision_tower、mm_projector。路由专家的权重路径不在 ignore 列表里，所以它们是被量化的对象——这与 K3 报告 §4.1.4 "quantize the MoE expert weights" 的文字描述一致。

    这里要破两个常见误解。

    误解一："MXFP4 就是 4-bit 整数量化"是错的。 MXFP4 元素是 4-bit 浮点（E2M1：1 符号 + 2 指数 + 1 尾数），有独立指数位；4-bit 整数量化的元素是定点整数、没有独立指数位。两者都是 4-bit，但元素编码不同，表达力也不同——这也是 OCP 定义 MXFP4 而不直接用 INT4 的原因。

    误解二："既然 MXFP4 好，应该把所有组件都量化到 4-bit"是错的。 K3 只量化 MoE 专家权重，非专家组件保持高精度。原因就是上表里的"动机"列：非专家频繁参与每 token 计算、对精度更敏感、参数占比小，量化收益不抵质量损失。盲目全量化会破坏 attention 与 router 的数值稳定性。

    教学解释与类比边界

    • "STE 是透明的窗户"（S3 callout）：只帮助理解 STE 公式里 $\partial\hat{w}/\partial w \equiv 1$ 这一项的来历。失效边界：不保证收敛到量化前最优、不处理梯度 magnitude 失真。正式判断以 STE 约束和损失函数条件为准。
    • "共享 scale 承担动态范围、元素承担块内相对精度"（S2）：教学解释，帮助理解"4-bit 为何仍可用"。失效边界：该分工只在块内值幅度相近时有效；若块内同时存在极大与极小值，小值会被大值主导的 scale 挤掉精度——这是 MXFP4 的已知局限，本页不展开。
    • RL 最小框架（S4，"rollout 产出训练 target"）：教学框架，只支撑 mismatch 论证，不展开 RL 算法（PPO 目标、优势函数、KL 散度等）。

    教学简化及其限制

    • 块大小教学缩写为 4（真实为 32）：便于手算，不改变机制。可推出结论：量化与反量化算术、误差来源。不可推出：真实 32 元素块的统计特性、scale 选取的边界情况。
    • scale $s_b$ 教学给定而非推导：本页用"按块内最大幅度选 power-of-two 使归一化值落入 E2M1 表示范围"这一表述，不展开 OCP 规范的精确 floor/ceil 选取算法（避免引入未核对细节）。可推出：反量化算术。不可推出：scale 选取的边界情况与硬件实现。
    • 可运行代码用 Python 列表与 min 模拟 E2M1 最近邻：不涉及真实硬件的打包位布局、不模拟批量张量与梯度反传。可验证：量化/反量化/STE 的算术与手算一致。不可推出：真实训练的数值稳定性与性能。
    • N3 估算忽略对齐 padding 与 latent MoE 内部结构：用于判断"值得量化"的数量级，不作为精确部署数字。
    • 本文不展开 NVFP4（块 16、FP8 scale）与 MXFP4 的精度对比、不展开 OAS/MBS 等 MXFP 精度增强方法——属格式族细化，不影响"K3 用 MXFP4 + QAT"的主线。
