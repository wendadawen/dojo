GLM-5.3-Flash 前向数据流

321.32 B 参数的原生多模态 MoE。45 层文本主干里 34 层是 KDA 线性注意力、11 层是 DSA 稀疏注意力，隐藏状态以 4 路并行残差流前进、由 mHC 超连接在每层两个站点读写，整条主干不含位置编码。

更新于 2026-08-27 · 依据：官方源码 + 真实 checkpoint 张量头 + 实跑算子

本页的结构性结论出自 zai-org/GLM-5.3-Flash 的 config.json 与 transformers 的 models/glm5_next/modeling_glm5_next.py；参数量与张量形状出自该 checkpoint 62 个 safetensors 分片的真实张量头；公式与数据流由官方算子在小随机张量上实跑验证。所有数字均可在 research/ 的脚本与原始输出中复现。

本页只讲这个模型如何组装，各机制本身的原理见对应概念页：线性注意力与delta 规则是 KDA 的基础，KDA给出带遗忘门的完整形式；MLA讲潜向量压缩，DSA讲稀疏选择；DeepSeekMoE讲专家切分与共享专家，辅助损失无关路由讲偏置为何只影响选择；NoPE讲不加位置编码为何仍能区分词序。

2. 整体数据流

一个 token 从词表进入到产出 logits，经过的是「嵌入 → 复制成 4 路 → 45 层 → 4 路取均值 → 归一化 → 输出头」。与常见 Transformer 最不同的两点在图上直接可见：主干携带的不是一条隐藏向量而是 4 条，且 45 层的注意力算子并不同质。

45 层的类型排布

注意力与 FFN 的类型逐层不同，两条条带直接把 layer_types 与 mlp_layer_types 画出来。规律是严格的：层号除以 4 余 3 的层用 DSA，其余用 KDA；前 3 层 FFN 是稠密 MLP，之后全是 MoE。

这个排布用 checkpoint 张量做了交叉验证：34 个层带 self_attn.q_conv1d.weight（KDA 独有的深度卷积），11 个层带 self_attn.kv_a_proj_with_mqa.weight（MLA 独有的潜向量投影），两组层号与 layer_types 逐项一致[C1]。

3. 单层内部数据流

每层的骨架是「两个子层，各配一个 mHC 站点」。与普通 Transformer 的差别在于：残差不是一条相加，而是 4 路先被压成 1 路送进子层，子层输出再按权重分发回 4 路，同时 4 路之间做一次矩阵混合。

代码：单层执行序（对应源码 L1291–1329） 
residual = h                              # [B,S,4,4096]
post, comb, x = attn_hc(h)                # x:[B,S,4096]  post:[B,S,4]  comb:[B,S,4,4]
x = input_layernorm(x)
x = self_attn(x)                          # KDA 或 DSA
h = post.unsqueeze(-1) * x.unsqueeze(-2) + comb.transpose(-1,-2) @ residual

residual = h
post, comb, x = ffn_hc(h)
x = post_attention_layernorm(x)
x = mlp(x)                                # MoE 或 稠密 MLP
h = post.unsqueeze(-1) * x.unsqueeze(-2) + comb.transpose(-1,-2) @ residual

4. mHC：4 路残差流怎么读写

入口处隐藏状态被 unsqueeze(2).expand 复制成 4 路，此时 4 路完全相同，不引入任何参数。分化的机制来自每层两个站点各自独立的 fn 参数：4 路被同一组 $pre$ 压成一路，子层输出再按 4 个不同的 $post$ 分量回写，因此各路此后不再相等。在随机初始化的 8 层模型上前向一次后，4 路与其均值的平均绝对偏差为 $0.48$–$0.54$，可见通路确实生效[N4]；该数值只反映随机权重下的分布，不代表训练后的真实模型。

每个站点用一个 $[24, 16384]$ 的矩阵 fn 把展平的 4 路状态映射成 24 个数，再切成三组。$24=(2+4)\times4$ 正是 $pre$、$post$ 各 4 个、$comb$ 占 $4\times4$：

$comb$ 的产生方式是这个机制里名字带「流形约束」的原因：先对 logits 做 softmax 得到一个非负矩阵，再交替做行归一化与列归一化，把它推向双随机矩阵所在的流形。hc_sinkhorn_iters 为 20，但它不等于「行列各归一化 20 次」：源码先做一次列归一化，再循环 $20-1=19$ 轮「行归一化 + 列归一化」，因此列归一化共 20 次、行归一化 19 次，且最后一步落在列方向。

20 次迭代后只是近似双随机，且两个方向的精度不对称。在官方初始化的随机权重下，列和距 1 的最大偏差是 $1.1\times10^{-6}$，而行和的偏差是 $1.0\times10^{-2}$，差了四个数量级[N5]。偏差的具体数值依赖输入分布，但行列不对称这一方向由源码的迭代顺序决定，不依赖输入：循环体的最后一步是列归一化，所以列方向刚被修正过，行方向则残留误差。

把 hc_mult 设为 1 并让 fn 输出 0，$post$ 变成 $2\sigma(0)=1$、$comb$ 变成 $1\times1$ 矩阵，回写式退化为 $h+f(h)$，实测与普通残差的差距是 $3.8\times10^{-6}$，量级由 hc_eps 决定[N5]。也就是说普通残差是这套机制的一个特例。

代价在激活显存：主干隐藏状态张量放大 4 倍，每 token 从 4096 个元素变成 16384 个。参数代价则很小——全模型两个站点共 45 层合计 35.39 M，占 321.32 B 的 0.011%[N6]。

补充：末端 4 路如何收敛回 1 路

末层输出交给 hc_head，它是无权重的算术均值，实测与 streams.mean(dim=2) 误差为 0，且模块不含任何可学习参数[N5]。官方源码在该类的 docstring 里明确写了这一点与 DeepSeek-V4 的区别（后者是加权收敛）。

5. KDA 层：34 层线性注意力

KDA（Kimi Delta Attention）用一个固定大小的矩阵状态代替随长度增长的KV cache。状态形状是 $[64, 128, 128]$，即每个头维护一个 $128\times128$ 的矩阵，与序列长度无关。

递推公式

核心是带遗忘的 delta 规则。对第 $t$ 个 token，先按通道衰减旧状态，再用「真实值与当前状态预测值之差」做一次修正写入：

$$S_t = \mathrm{diag}(e^{g_t})\,S_{t-1},\qquad \delta_t = \beta_t\bigl(v_t - S_t^{\top}\hat{k}_t\bigr)$$

$$S_t \leftarrow S_t + \hat{k}_t\,\delta_t^{\top},\qquad o_t = S_t^{\top}\hat{q}_t$$

其中 $t = 1,\dots,S$ 逐 token 推进，初值 $S_0 = 0$；下面各式对每个头独立成立。

  • $S_t\in\mathbb{R}^{128\times128}$：该头在第 $t$ 步的状态矩阵，逐头独立
  • $g_t\in\mathbb{R}^{128}$：遗忘门，逐头逐通道取值，恒为负数，故 $e^{g_t}\in(0,1)$ 是衰减因子
  • $\beta_t\in(0,1)$：写入强度，由 $\sigma(W_b x_t)$ 给出，逐头一个标量
  • $\hat{q}_t,\hat{k}_t$：$L_2$ 归一化后的查询与键，$\hat{q}_t$ 另乘 $1/\sqrt{128}$；$v_t$ 不做归一化
  • $\delta_t$：预测残差乘写入强度，这一项使写入具有「纠错」性质，而非简单累加

公式核对方式是独立重写一遍再逐元素比对：按上式手写的实现与官方 kernel 的输出最大绝对误差为 0，终态误差同样为 0[F1]。

遗忘门的实际取值范围

遗忘门有两个分支，取哪个由 gate_lower_bound 决定。本 checkpoint 给的是 $-5.0$（非 None），因此走的是有下界的那支：

$$g = \lambda\cdot\sigma\bigl(e^{A}\odot(W_{f_b}W_{f_a}x + b_{dt})\bigr),\qquad \lambda = -5.0$$

  • $W_{f_a}\in\mathbb{R}^{128\times4096}$ 与 $W_{f_b}\in\mathbb{R}^{8192\times128}$：低秩分解的两级投影，把 4096 维输入压到 128 维再升到 $64\times128$
  • $b_{dt}\in\mathbb{R}^{8192}$：逐通道偏置（checkpoint 中的 dt_bias）
  • $A\in\mathbb{R}^{64}$：逐头的对数尺度参数（A_log），$e^{A}$ 沿通道维广播到 $64\times128$ 后逐元素相乘
  • $\lambda$：gate_lower_bound，取 $-5.0$，决定 $g$ 的下界
  • $\sigma$：sigmoid；$\odot$：逐元素乘

由于 $\sigma(\cdot)\in(0,1)$，$g$ 被限制在 $(-5, 0)$，衰减因子 $e^{g}\in(e^{-5}, 1)\approx(0.0067, 1)$。实测在随机输入下 $g$ 落在 $[-4.02, -0.84]$，衰减因子落在 $[0.018, 0.431]$[N7]。这个下界的作用是防止状态被单步彻底清零。

另一支（gate_lower_bound 为 None 时）用的是 $-e^{A}\cdot\mathrm{softplus}(\cdot)$，无下界。本 checkpoint 不走这支，因此页面上关于取值范围的结论只对 safe 分支成立。

6. DSA 层：11 层稀疏注意力

DSA（DeepSeek Sparse Attention）层的主路是 MLA（Multi-head Latent Attention，多头潜向量注意力）：查询经 1536 维潜向量、键值经 512 维潜向量再展开成 64 个头，这套压缩即 低秩分解的应用。与稠密 MLA 的差别在于多一个轻量 indexer，它先挑出一小批 key，主路只在这批 key 上算注意力。

k-pool：先把 token 打包再打分

indexer 不逐 token 打分，而是先把连续 4 个 token 加权平均压成一个「池」，在池级别打分，选中后再展开回原始 token 下标。这带来两层节省：打分次数降到 $1/4$，而参与注意力的 key 有 2048 的硬上限。

选择数量的换算是 $\text{选中池数} = \min(2048/4,\ \lceil S/4\rceil) = \min(512, \lceil S/4\rceil)$。下表由脚本按真实配置算出[N8]：

展开：把预算缩到 16 观察真实的稀疏选择

真实预算 2048 需要更长的序列才会触发稀疏。把 index_topk 改成 16（仍满足官方要求的「必须能被 index_kpool 整除」），其余结构不变，在 $S=64$ 下就能看到稀疏行为：输出宽度变成 $16+3=19$，第 63 个 query 只可见 16 个 key，稀疏率 25%，选中的原始下标是 [20,21,22,23, 32,33,34,35, 40,41,42,43, 48,49,50,51] —— 正好是 4 个完整的池[N9]。

「总是选尾巴」这个选项的语义并非「末尾 token 一定被选中」，而是「当前那个不完整的池被无条件附上」。尾巴长度是 $\text{可见数} \bmod 4$，所以可见数恰为 4 的倍数时尾巴为空。逐个 query 验证：

打分公式

indexer 的分数是逐头点积经 ReLU 后按头加权求和：

$$\text{score}(t, p) = \sum_{h=1}^{32} w_{t,h}\cdot\mathrm{ReLU}\!\left(\frac{q_{t,h}\cdot \bar{k}_p}{\sqrt{128}}\right),\qquad w_{t,h} = \frac{(W_w x_t)_h}{\sqrt{32}}$$

  • $\bar{k}_p$：第 $p$ 个池的键。池内权重不是固定学出的常数，而是由输入经 index_kpool_compress_gate 投影出的门控分数，加上一个可学习的池内位置偏置 index_kpool_compress_ape，再沿池内 4 个位置做 softmax；该门控逐通道独立（128 维各有一套权重），因此同一个池对不同通道的加权方式不同[F3]
  • $\mathrm{ReLU}$ 使不相关的头贡献为 0，而非负分数相互抵消
  • $W_w\in\mathbb{R}^{32\times4096}$：weights_proj，把输入投影成 32 个逐头权重
  • $1/\sqrt{128}$ 与 $1/\sqrt{32}$ 分别是头维度与头数的缩放，实测值 $0.08838835$ 与 $0.17677670$
  • 不可见的池（越界或违反因果）被填成 dtype 最小值后再取 top-k

跨层共享的能力存在但未启用

源码支持让某些 DSA 层跳过自己的 indexer、直接复用上一层的选择结果（indexer_types 取 shared）。本 checkpoint 的 45 项全是 full，因此 11 个 DSA 层各自打分，无共享[C4]。checkpoint 里恰好有 11 组 indexer 张量，层号为 $3,7,\dots,43$，与推导一致。

7. MoE 路由

42 个 MoE 层的路由沿用 DeepSeek 的 noaux_tc 做法（辅助损失无关路由）（config 里的 topk_method 与 scoring_func 是惰性键[C6]，实际行为在源码里硬编码）：sigmoid 打分、加一个偏置项用于选择、权重取不含偏置的原始分数、归一化后再放大。

$$s_i = \sigma(W_g x),\qquad \mathcal{T} = \operatorname*{top-8}_i\,(s_i + b_i),\qquad w_i = 2.5\cdot\frac{s_i}{\sum_{j\in\mathcal{T}} s_j}\ \ (i\in\mathcal{T})$$

  • $s_i$：第 $i$ 个专家的分数，用 sigmoid 而非 softmax，故各专家分数相互独立
  • $b_i$：e_score_correction_bias，只进入选择，不进入权重
  • $2.5$：routed_scaling_factor；因为先归一化再乘它，每 token 的权重之和恒为 $2.5$ 而不是 $1$

这三点都做了实测核对：独立手写一遍公式，选出的专家索引与官方完全一致、权重最大误差为 0；每 token 权重和实测正好是 $2.5$；用官方（带偏置）选出的索引配上不含偏置的分数算权重，与官方权重误差为 0，确认偏置只影响「选谁」[F2]。

由于 n_group 与 topk_group 都是 1，源码里的分组限制机制退化：实测 score_mask 全为 1，等价于在 288 个专家上做全局 top-8[F2]。

专家内部的 SwiGLU 带一个容易被忽略的细节：swiglu_limit = 10.0 的截断是不对称的。gate 只截上界（$\min$ 侧为 None），up 双侧截断。实测输入 $[-50, -10, 0, 5, 10, 50]$ 时，gate 得到 $[-50,-10,0,5,10,10]$，而 up 得到 $[-10,-10,0,5,10,10]$[F2]。gate 负半轴不截是因为 SiLU 在负半轴本就趋于 0，不会溢出。

8. 位置信息从哪来

整条 45 层文本主干没有位置编码。这不是推测，有三处相互印证的证据[C2]：

  • config.json 里 qk_rope_head_dim = 0
  • 配置类的 validate_architecture() 在 qk_rope_head_dim > 0 时直接抛异常，即 NoPE 是硬约束而非默认值
  • 主干 forward 给每层传的是 position_embeddings=None，DSA 层不调用任何旋转函数

配置里另有一个 mla_use_nope: true，字面与该结论一致，但 transformers 从不读取它[C6]，因此上面三条不依赖它。

那么顺序信息由什么携带？可确认的是两条：KDA 层的状态按 $e^{g_t}$ 逐 token 衰减，天然带先后；KDA 层的深度卷积（kernel 4）提供局部相对位置。DSA 层本身位置无关，依赖上游 KDA 层已注入的信息。

由此可以推断（本页标注为推断，非官方声称）：KDA 层承担了位置编码的职责，这构成对层排布的约束——第 0 层必须是 KDA，且 DSA 层不能连续出现。实际排布（每 4 层中前 3 层 KDA）满足这两点。该推断未在官方材料中找到对应表述。

视觉塔另有独立的二维 RoPE（Glm5NextVisionRotaryEmbedding，$\theta=10000$，按 patch 的高宽位置施加），与文本主干无关。

9. 长上下文下的实际收益

混合架构的目的是让大部分层的状态不随长度增长。两侧的状态构成不同：

  • KDA 层：常数。 循环状态 $[64,128,128]$ 存 fp32（4.00 MiB），深度卷积的历史窗口 $[24576,4]$ 随激活存 bf16（0.19 MiB）。34 层合计 142.38 MiB，与序列长度无关。
  • DSA 层：随 token 线性增长。 每 token 每层要留两份：MLA 潜向量 512 维，以及 indexer 的打分状态 257 维（键 128 + 门控分数 128 + 有效位 1）。后者是解码必需的——每步重建候选池都要用到它，不能不存。合计 769 维，bf16 即 1.502 KiB。

下表与「假设 45 层全是 DSA」的基线对比[N10]：

上下文长度真实混合假想全 DSA节省KDA 常数占比
4,0960.204 GiB0.264 GiB22.89%68.30%
32,7680.655 GiB2.112 GiB68.97%21.22%
131,0722.204 GiB8.448 GiB73.91%6.31%
1,048,57616.661 GiB67.588 GiB75.35%0.83%

节省比例随长度上升并趋近 $1-11/45 = 75.6\%$ 的上限：长度越大，KDA 的常数开销越被摊薄。令两侧相等可解出交叉点 $S = 142.38\ \mathrm{MiB} / (34\times769\times2\ \mathrm{B}) \approx 2855$ token —— 短于此长度时 KDA 的常数状态还没摊平，混合架构反而占用更多。$S=4096$ 已越过该点，故表中首行已经是净节省。

这里有一个容易漏掉的项：把 DSA 侧只按 MLA 潜向量的 512 维计算，会漏掉 indexer 的 257 维打分状态，交叉点被高估为 4288 token，$S=4096$ 那行也会从「节省 22.89%」错算成「多占 3.54%」，结论方向相反。稀疏注意力的显存账必须把选择机制自身的状态计入[N10]。

上表的 MLA 部分按潜向量口径算（每 token 每层 512 维），这是推理框架的做法。官方 transformers 实现走的是另一条路：先 expand_kv 展开成 64 个头再 cache，实测缓存形状为 $[B,64,S,256]$，每 token 每层 32768 个元素即 64 KiB，是潜向量口径的 64 倍[N11]。两个口径差 64 倍，本页长上下文数字用前者；transformers 的展开口径不代表实际部署时的显存占用。

10. FP8 量化的覆盖范围

权重按 $128\times128$ 块量化为 FP8 E4M3，每块一个 fp32 缩放因子。37,338 个 scale 张量全部符合 $\lceil N/128\rceil\times\lceil K/128\rceil$ 的形状，无一例外[C3]。

被量化的范围很有选择性——只有大矩阵乘的权重：routed 专家的三个投影、共享专家、DSA 层的 $q_a$/$q_b$/$kv_a$/$o$ 投影、前 3 层稠密 MLP。保持高精度的包括：

  • 全部 34 个 KDA 层的 $q$/$k$/$v$/$o$ 投影——实测 KDA 层被量化的投影张量数为 0，即 KDA 路径没有任何权重走 FP8（其中卷积核、$A$ 与 $b_{dt}$ 更进一步留在 FP32，见下）
  • DSA 的 kv_b_proj（展开投影）与 indexer 的全部权重
  • 路由器 gate 权重（BF16）与 e_score_correction_bias（FP32）
  • 所有归一化权重、mHC 的 fn（BF16）与 base/scale（FP32）
  • 嵌入、输出头、整个视觉塔

其中四类张量在源码里被显式声明必须留在 fp32（_keep_in_fp32_modules_strict）：e_score_correction_bias、conv1d、dt_bias、A_log。checkpoint 实测这些张量的 dtype 确实全是 F32，与声明一致[C3]。

参数量与磁盘占用不可混用。index.json 的 total_size 是 328,326,771,576 字节（305.78 GiB），按 dtype 逐张量累加字节数与它完全相符；但参数个数是 321.32 B，平均每参数 1.022 字节。拿 total_size 当参数量会高估 2.2%。

11. 多模态：图像与视频共用 token

视觉塔是标准的 ViT 结构，24 层、宽 1024，输出维度 out_hidden_size = 4096 恰等于文本 hidden_size，因此视觉特征可直接替换占位符，无需额外投影层。参数量实测 563,627,008，与 checkpoint 的 visual 命名空间逐字节吻合，差值为 0[N3]。

视觉 token 数的换算是 $\lfloor T\cdot H_p\cdot W_p / 4\rfloor$，其中 $H_p = H/14$。实测 $448\times448$ 图像产生 1024 个 patch、经 $2\times2$ 空间合并后是 256 个视觉 token，与公式一致[N3]：

输入grid $(T,H_p,W_p)$patch 数视觉 token像素/token
$448\times448$ 图像$1\times32\times32$1,024256784
$896\times896$ 图像$1\times64\times64$4,0961,024784
$1344\times1344$ 图像$1\times96\times96$9,2162,304784

视频走的是同一个换算式，只是 $T$ 大于 1；get_video_features 先把 $[T,H_p,W_p]$ 展平成 $T$ 个 $[1,H_p,W_p]$ 再送进视觉塔。需要注意输入帧数与 grid 的 $T$ 不是同一个量：temporal_patch_size 为 2，且帧到 grid 的换算发生在 processor 而非模型代码里，本页的可核对来源不含该逻辑，因此上表末行以 grid 的 $T$ 为输入，不换算帧数[N3]。

与多数视觉语言模型不同的一点：图像与视频共用同一个 token id。配置里虽有 video_token_id = 154855，但掩码判定路径并不使用它，而是靠视频起止标记划出区间：

$$\text{in\_video} = \mathrm{cumsum}(\text{id}=\text{v\_start}) > \mathrm{cumsum}(\text{id}=\text{v\_end})$$

$$\text{image\_mask} = (\text{id}=154854)\wedge\neg\text{in\_video},\qquad \text{video\_mask} = (\text{id}=154854)\wedge\text{in\_video}$$

构造一段含两个图像 token、一个视频区间（内含 3 个 token）、再一个图像 token 的序列，实测得到 3 个图像 token 与 3 个视频 token，划分位置与预期完全一致[N12]。

12. MTP 层

checkpoint 有 46 个层号，第 45 层是多 token 预测层（供投机解码使用），7.43 B 参数。transformers 实现把它显式忽略（_keys_to_ignore_on_load_unexpected 含 layers\.45\.），只构建 45 层主干；MTP 由推理框架单独加载。

它与主干层有三处结构差异。张量清单能确认的是模块的存在与形状，模块用途按 DeepSeek-V3 系 MTP 的公开做法解读，本页标注为推断[C5]：

  • 是 DSA 类型而非 KDA：带 kv_a_proj_with_mqa 与完整 indexer，不带 KDA 的卷积与遗忘门张量
  • 不用 mHC：没有 hc_attn_* / hc_ffn_* 任何张量，走普通残差
  • 独有三个模块：enorm、hnorm 与 eh_proj（形状 $[4096, 8192]$）。8192 是 $2\times4096$，即把「上一步隐藏态」与「下一 token 嵌入」拼接后投影回 4096，这是 DeepSeek-V3 系 MTP 的标准做法；另有 shared_head.norm

它同样带完整的 288 专家 MoE。配置里还有一个 index_share_for_mtp_iteration: true，字面指向「投机解码的多次迭代之间复用 indexer 的选择」，但 transformers 的源码里搜不到这个键，它不被该实现消费[C6]；具体语义需要看推理框架的实现，本页不下结论。

13. 核对方式

本页数字的来源分三层，脚本与原始输出都在 research/ 下。

结构与形状：真实 checkpoint 张量头

用 HTTP Range 请求只读取 62 个 safetensors 分片的 JSON 头（每个约 260 KB），不下载 305 GiB 权重本体，得到 76,108 个张量的名称、形状与 dtype。以此验证从源码推导的每条结构性结论：34/11 的层类型分布、11 组 indexer 的层号、45 层两站点 mHC、每层 288 专家、前 3 层 dense。

这一步还给出一个源码之外的事实：checkpoint 的张量名与 transformers 的模块名不一致。mHC 在 checkpoint 里叫 hc_attn_fn/hc_attn_base/hc_attn_scale，而源码里是 attn_hc.fn/.base/.scale；KDA 的深度卷积在 checkpoint 里拆成 q_conv1d/k_conv1d/v_conv1d 三个 $[8192,1,4]$ 张量，源码里是一个 $[24576,1,4]$ 的 conv1d（$24576 = 3\times8192$，且 groups 等于通道数，故拆分与合并等价）。形状可逐项对上，命名由加载器转换。

公式与数据流：实跑官方算子

321 B 模型无法在单机 CPU 上加载，但公式可以单独验证。做法是从官方 modeling_glm5_next.py 原样抽取第 63–1330 行（RMSNorm 到 DecoderLayer）执行，架构代码一行不改，只把当前 transformers 版本缺失的框架装饰器替换为恒等实现——这些装饰器的官方语义是「装了 kernel hub 就换实现，否则用文件内的 PyTorch 参考实现」，恒等替换后走的正是待验证的参考分支。抽取区间的起止用断言锁定，防止上游文件行号漂移后静默抽错。

在此基础上用真实 config 的维度喂小随机张量：单个 KDA 层与 DSA 层用完整真实维度（隐藏 4096、64 头、128/256 维），端到端前向缩到 8 层、16 专家但保留全部结构特征（4 层一循环的类型交替、前 3 层 dense、4 路残差流），跑通 prefill 加 4 步 decode，全程无 NaN 或 Inf。

两处容易想错的机制

以下两处机制的常见推断与实现不符，实测结论如下：

  • Sinkhorn 的收敛程度：20 次迭代并不足以让 comb 达到机器精度意义上的双随机。行和偏差 $1.0\times10^{-2}$，比列和的 $1.1\times10^{-6}$ 差四个数量级，只能称「近似」。方向性原因是迭代序末尾为列归一化。
  • 「总是选尾巴」的含义：不是「末尾 token 必被选中」，而是「附上当前不完整的池」。尾巴长度为 $\text{可见数} \bmod 4$，可见数为 4 的倍数时尾巴为空。在把 index_topk 缩到 16、$S=64$ 的构造下（真实预算 2048 时 $S=64$ 全部可见，观察不到稀疏），第 63 个 query 的选中集恰好不含下标 63。

此外，复现 mHC 时若只初始化维度 $\ge 2$ 的参数，一维的 base 与 scale（源码用 torch.empty 创建）会保留未初始化内存，4 路残差流将不产生分化。按官方 _init_weights 初始化全部参数是复现该机制的前提。

[N10] 长上下文显存对照表与 4288 token 交叉点。条件与依据：KDA 侧循环状态 $[64,128,128]$ 按 fp32 计——源码调用 update_recurrent_state(last_recurrent_state.to(torch.float32))，显式转 fp32；卷积状态按 $[24576,4]$、bf16 计——cache_utils.py 的 lazy_initialization 用 torch.zeros((*conv_states.shape[:-1], conv_kernel_size), dtype=conv_states.dtype) 分配，宽度等于 conv_kernel_size（即 kernel 值 4，非 $kernel-1$），dtype 随激活。共 34 层。DSA 侧每 token 每层计 769 个元素、bf16：MLA 潜向量 $kv\_lora\_rank + qk\_rope\_head\_dim = 512$，加 indexer 的 packed 状态 $index\_head\_dim\times2+1 = 257$——源码把 cat([k, gate_scores, valid_channel]) 交给 update_indexer 逐 token 累积，get_pooled_states 每步都要读它重建候选池，属解码必需状态。共 11 层。漏掉这 257 维会把交叉点高估为 4288 token 并使 $S=4096$ 行的符号反转。「假想全 DSA」是为算节省比例构造的基线，非真实存在的配置。脚本 p8_longctx.py 节 8.1、8.3。
  11. [N11] transformers 实现的 KV cache 形状为 $[1,64,S,256]$，每 token 每层 32768 个元素。条件：真实 DSA 层，B=1、S=40 prefill 后读取缓存张量形状。这是官方 transformers 的实现口径（expand_kv 后 cache）；推理框架可改为 cache 潜向量，本探针不能证明后者的实现细节。脚本 p2_dsa.py 节 2.3。
  12. [N12] 图像与视频掩码划分。条件：按源码的 get_placeholder_mask 判定式，在构造的 12 token 序列上实测。脚本 p6_vision.py 节 6.4、6.5。
  13. [N13] routed 专家占比与激活率。条件：口径需一致——311.65 B 与 96.99% 的分母是含 MTP 层的 321.32 B；304.41 B 只含主干 42 个 MoE 层；96.98% 与 5.54% 的分母是扣除 MTP 层后的主干 313.89 B。混用分母会得到错误比例。统计脚本为 verify_structure.py 的分组逻辑。

简化条件及其限制

  1. 不加载真实权重。 所有实跑使用随机张量，验证的是公式正确性、形状代数与数据通路，不涉及模型的语义能力。因此本页不含任何关于输出质量、基准分数或数值分布的结论；[N5][N7] 中的取值范围只在对应构造条件下成立。
  2. 端到端前向缩小到 8 层 16 专家。 保留了全部结构特征（层类型 4 层一循环、前 3 层 dense、4 路残差流、indexer 配置、真实隐藏宽度与头维度），因此可支持关于形状与数据通路的结论，不可支持关于参数量或规模效应的结论——后者一律由 checkpoint 张量头统计给出。
  3. 缩小 index_topk 观察稀疏。 真实预算 2048 需要更长序列才能触发稀疏，改用 16 观察机制。这支持关于「选择规则与尾巴语义」的结论，不支持关于「真实模型在长序列上选中哪些 token」的结论。
  4. 长上下文表为公式推算。 未构造 1M 序列，表中数字由每层每 token 占用乘长度得出；每 token 占用的构成（KDA 的两块常数状态、DSA 的潜向量与 indexer 状态）取自源码与 cache 实现，换算式在短序列上经实跑验证。若推理框架采用不同的缓存布局或精度，绝对值与交叉点都会变化，只有节省比例的上限 $1-11/45$ 由层数比例决定、不受布局影响。
  5. 视觉塔 depth 缩至 2 跑通。 patch 到 token 的换算与输出维度不依赖 depth，故这两项结论成立；参数量一项按真实 depth=24 构建模块统计，并与 checkpoint 精确吻合。
  6. Sinkhorn 结论的输入依赖。 双随机偏差量级依赖 fn 的取值分布，本页用官方初始化下的随机权重测得。行列不对称这一方向性结论由迭代顺序决定，不依赖输入；具体偏差数值依赖构造条件。
