# 辅助损失无关路由：教学大纲

## 页面开头

### 钩子场景（30 秒内让读者知道概念解决什么）
"MoE 路由器看到 4 个专家，每次让 token 自己选 top-2。训了几万步，发现专家 0 被选中 90% 的次数，专家 3 一次都没被选中——它根本没在训。传统做法是给损失函数加一个'鼓励均衡'的项，但调这个项的权重 $\alpha$ 是个玄学：太大压住专家特化、损害主任务；太小压不住坍塌。DeepSeek 团队 2024 年 8 月在 arXiv:2408.15664 上提了个绕开损失函数的方案：给每个专家加一个 bias，加到路由分数上只参与'选谁'，不进入'权重多少'，再用一个'过载就减、欠载就增'的固定小步规则在每步训练后更新 bias。"

### 一句话解释
辅助损失无关路由（Auxiliary-Loss-Free Routing）通过给每个专家一个不进梯度的 bias 来调节 top-k 选择，让 MoE 在不写任何辅助损失项的情况下保持专家负载均衡。

### 学习承诺
读完这一页，你应该能够：（Q1）说清 MoE 训练为什么需要负载均衡，传统辅助损失方案为什么有缺陷；（Q2）从公式说明 bias 在前向传播里做什么、不做什么；（Q3）写出 bias 的固定步长 sign 更新规则并解释为什么用 sign；（Q4）手算一个 4 专家 top-2 的完整训练步；（Q5）说明 DeepSeek-V3 中本方法的实际配置与边界。

### 首个具体场景
4 个专家 $N_r=4$、top-2、单 batch 4 个 token 的打分与负载统计——后续章节每次复用都加一层。

### 与第一章的过渡
"先看为什么 MoE 训练不能放任路由器自由选择。"

## 章节 S1：MoE 训练的负载坍塌，与辅助损失方案的两难

- 主要教学问题：MoE 训练时路由器为什么会偏向少数专家？传统辅助损失方案怎么处理？它的代价是什么？
- 对应范围：Q1、C1、C2、F6（点出）。
- 正文要点：
  - 路由坍塌现象：被选中越多的专家梯度越多、特化越强；越被冷落的专家越没机会训；正反馈形成坍塌。
  - 专家并行训练的另一个动机：负载不均 → GPU 忙闲不均 → 训练吞吐下降。
  - 传统辅助损失方案 $L_{bal}=\alpha\sum f_i P_i$ 的写法（只点出，不展开）。
  - $\alpha$ 两难：过大产生干扰梯度损害主任务，过小压不住坍塌。引用原始论文实验对照（baseline α=0.001 与本方法对比，PPL 与 MaxVio 均更优）。
  - "干扰梯度"是什么：辅助损失项的梯度混进主任务梯度，更新方向不再是纯语言建模目标。
- 讲解材料：F6 公式只点出，不展开推导；用一段文字+一个对照表（辅助损失 vs aux-loss-free）。
- 前置知识：首次提到 MoE/router/top-k/expert 时引用 `moe-serving/`；首次提到专家并行同样引用。
- 完成检查：用一句话说明为什么"加 bias 调选择"比"加损失项调梯度"更不容易损害主任务。
- 过渡：本章说明"为什么不能用损失项"；下一章看"不用损失项，bias 怎么把均衡做出来"。

## 章节 S2：bias 加在路由分数上——只管选谁，不管用多少

- 主要教学问题：bias 在前向传播里到底加在哪里、不加在哪里？
- 对应范围：Q2、C3、F1、F2、F3、F5。
- 正文要点：
  - 路由分数 $s_{i,t}=\sigma(u_t^\top e_i)$ 的定义（沿用 `moe-serving/` 里的 router 记号，本页首次出现时给出与 sigmoid 版本对应关系）。
  - 带 bias 的选择规则 F2：$s_{i,t}+b_i\in\mathrm{Topk}$ 决定是否进入；进入则 $g'_{i,t}=s_{i,t}$（原始分数，不含 bias）。
  - 归一化门控 F3：$g_{i,t}=g'_{i,t}/\sum_j g'_{j,t}$；分母只对被选中求和，且不含 $b$。
  - MoE 层输出 F5：shared expert 全激活 + routed expert 按 $g_{i,t}$ 加权。
  - 两个边界检查：
    - 所有 bias 同时加常数 $c$：相对排序不变，top-k 选择不变 → bias 只有相对差异起作用。
    - bias 加在 $s$ 上但不进 $g$：bias 改变"选谁"，不改变"被选中后给多少权重"。
  - 因此 bias 不进计算图、不进反向传播——这就是"loss-free"的来源。
- 讲解材料：F1-F3、F5 公式；两个边界检查的正例对照。
- 前置知识：`moe-serving/` 已讲过 router/top-k，本文只复用符号。
- 完成检查：用一句话说明 bias 加在 $s$ 上但不进 $g$，为什么这就避免了"干扰梯度"。
- 过渡：本章解决"bias 怎么用"；下一章解决"bias 自己怎么被更新"。

## 章节 S3：bias 的固定步长 sign 更新——规则更新，不进梯度

- 主要教学问题：bias 在训练时怎么变？为什么用 sign 而不是用误差幅度？
- 对应范围：Q3、C4、C5、F4。
- 正文要点：
  - 负载统计：$c_i$ 是本步专家 $i$ 收到的 token 数；$\bar c_i=\frac{1}{N_r}\sum_j c_j$ 是平均负载。
  - 偏差 $e_i=\bar c_i-c_i$：正表示专家 $i$ 欠载、负表示过载。
  - 更新规则 F4：$b_i\leftarrow b_i+\gamma\cdot\mathrm{sign}(e_i)$。
    - $e_i>0$（欠载）→ $b_i$ 增大 $\gamma$ → 下一轮更容易进 top-k。
    - $e_i<0$（过载）→ $b_i$ 减小 $\gamma$ → 下一轮更难进 top-k。
    - $e_i=0$ → 不变。
  - 为什么是规则式不是梯度式：bias 不在计算图里，反向传播不会更新它；每步训练结束后单独按规则更新。
  - 为什么用 sign 而不是 $e_i$：
    - sign 让每步走固定小步，单步稳定（不会因一个 batch 偏差大就猛跳）。
    - 代价是丢失幅度信息——差 1 个 token 和差 50 个 token 走的步长一样。
    - 原始论文 Table 3 实验对照：sign 版本与连续幅度版本 PPL 几乎相同（9.50 vs 9.51），故采用更简单的 sign。
  - 因果约束：原始论文强调用历史 batch 的负载更新，避免用到当前序列的 future token 信息。
  - 初始化：$b_i=0$。
- 讲解材料：F4 公式；与"梯度更新"对比的一段说明；变体实验对照表（N5）。
- 前置知识：无新前置。
- 完成检查：写出更新规则；用一句话说明 sign 与 $e_i$ 的权衡。
- 过渡：本章给规则；下一章把规则跑起来。

## 章节 S4：手算一个 4 专家 top-2 的训练步

- 主要教学问题：把 S2、S3 串起来，端到端跑一遍。
- 对应范围：Q4、C3、C4、F2、F3、F4。
- 正文要点：
  - 设置：$N_r=4$、$K_r=2$、初始 $b=(0,0,0,0)$、$\gamma=0.001$、batch 含 4 个 token、教学示例打分。
  - 第一步：4 个 token 各自的 router 打分 → 加 bias（仍为 0）→ 选 top-2 → 给出每个 token 的选择结果。
  - 负载统计：$c_i=$ 每个专家被选中的次数；$\bar c_i=\frac{1}{4}\sum c_j$。
  - 更新：按 F4 算每个专家的 $\mathrm{sign}(\bar c_i-c_i)$，更新 $b_i$。
  - 第二步（用新 bias 重选）：让冷门专家的 $s+b$ 进入 top-k；可看到原本被冷落的专家被拉回。
  - 计算过程保留在折叠块内；正文给出关键数字与结论。
- 讲解材料：表格对照（4 个 token × 4 个专家的打分、两轮选择结果）；折叠块承载逐步代入。
- 前置知识：S2、S3。
- 完成检查：给定新打分，能否写出第二轮 bias 与选择结果。
- 过渡：本章验证机制可用；下一章看它在 DeepSeek-V3 真实配置里如何落地。

## 章节 S5：DeepSeek-V3 中的配置、调度与边界

- 主要教学问题：本方法在真实大模型里怎么用？边界是什么？
- 对应范围：Q5、C5、C6、N1、N2、N3。
- 正文要点：
  - DeepSeek-V3 规模（N1）：256 routed expert + 1 shared，top-8，671B/37B。
  - γ 调度（N2）：前 14.3T token 用 $\gamma=0.001$，最后 500B token 设 $\gamma=0$ 冻结 bias。
  - 序列内均衡（N3、C6）：另加 $\alpha=0.0001$ 的 sequence-wise balance loss；点出公式但不展开推导。
  - 推理阶段：bias 固定不再更新。
  - 边界：
    - 只解决批级均衡，不解决序列内均衡。
    - 不能保证单步完美均衡——sign 走固定小步，需要训练步数积累。
    - 896 专家时 sign 收敛过慢（K3 的发现，引用 `quantile-balancing/`）。
- 讲解材料：γ 调度表；与 K3 改进点对比的一段说明。
- 前置知识：`moe-serving/` 的 DeepSeek-V3 数字、`quantile-balancing/` 的对照。
- 完成检查：用一句话说明为什么最后 500B token 要把 $\gamma$ 设为 0；用一句话说明 aux-loss-free 与 sequence-wise loss 各解决什么。
