    辅助损失无关路由：用 bias 调选谁、不调用多少

    主要依据：Auxiliary-Loss-Free Load Balancing Strategy for Mixture-of-Experts（Wang et al., 2024, arXiv:2408.15664）；DeepSeek-V3 Technical Report（arXiv:2412.19437 §2.1.2, Eq.12-17）。本页所用 $\gamma$ 取值与调度、$\alpha$ 取值、专家数与 top-k 均来自这两份原文。

    MoE 训练里路由器看到 4 个专家、每次让 token 自己选 top-2。训几万步后发现专家 0 被选中 90% 的次数、专家 3 一次都没被选中——它根本没在训。传统做法是给损失函数加一个"鼓励均衡"的项，但项的权重 $\alpha$ 是个玄学：太大压住专家特化、损害主任务；太小压不住坍塌。DeepSeek 团队 2024 年 8 月在 arXiv:2408.15664 上提了个绕开损失函数的方案：给每个专家加一个 bias，加到路由分数上只参与"选谁"，不进入"权重多少"，再用"过载就减、欠载就增"的固定小步规则在每步训练后更新 bias。这就是辅助损失无关路由（Auxiliary-Loss-Free Routing）。

    最容易误解

    • "bias 是模型参数，被反向传播更新" —— bias 不是模型参数，不进计算图，每步训练后由规则式 sign 更新，更新依据是上一批的负载统计。
    • "bias 加到分数上，所以 mixture weight 也含 bias" —— bias 只决定是否进 top-k；进入后门控值取原始分数，归一化分母也不含 bias。
    • "有了 aux-loss-free 就能单步完美均衡" —— sign 走固定小步，需要训练步数积累；某步负载不均是正常的。
    • "aux-loss-free 同时解决序列内均衡" —— 它只看批级负载；序列内均衡由 DeepSeek-V3 另加的 sequence-wise balance loss 处理。

    MoE 训练为什么会负载坍塌——辅助损失方案又卡在哪

    先回顾一下 MoE 是什么、为什么训练时会出问题。MoE（Mixture-of-Experts，专家混合）把 Transformer 层里那个 FFN 换成一排 $N_r$ 个小 FFN（叫 routed expert），再加一个很小的打分器 router。每个 token 到来时，router 给所有专家打分，只让得分最高的 $K_r$ 个（top-k）真正计算这个 token。详细机制见 MoE 大模型推理与服务基础。

    路由器在训练初始时权重是随机的，但只要某几个专家在早期被多选了几次，它们就得到更多梯度、特化得更快，下一轮更容易被选——这是一个正反馈。论文里把这个失效模式叫 路由坍塌（routing collapse）：少数专家包揽绝大多数 token，其余专家一次都不被选中、梯度为零、根本训不动[C1]。在专家并行训练里它还会引发另一个症状：把专家分片到多张 GPU 后，热专家所在那张卡成了瓶颈，其余卡空转，吞吐下降。

    传统做法是给损失函数加一个"鼓励均衡"的辅助项，最经典的形式（Switch Transformer / GShard 一族）写作

    $$L_{bal}=\alpha\sum_{i=1}^{N_r}f_i P_i,$$

    其中 $f_i$ 是专家 $i$ 被选中的频率，$P_i$ 是 router 给它的平均分数，$\alpha$ 是平衡系数。当负载完全均衡时该损失取最小值。问题是 $\alpha$ 难调[C2]：

    • $\alpha$ 过大：辅助损失的梯度混进主任务梯度，扭曲专家特化，损害主任务性能。这种"混进来的梯度"被原文称作 干扰梯度（interference gradients）。
    • $\alpha$ 过小：压不住坍塌，负载依然不均。

    原始论文 Table 2 的实验对照：在 1B / 3B 模型上，辅助损失方案（baseline $\alpha=0.001$）的验证集 perplexity 与 MaxVio（最大负载偏差）均劣于本方法。也就是说"加损失项调梯度"这条路本身就有代价。

    本章说明了辅助损失方案的两难。但均衡不一定非得靠损失项——下一章看 bias 如何把均衡从"损失目标里"挪到"路由选择上"。

    bias 加在路由分数上——只管选谁，不管用多少

    先列出本页要用的符号。令 $u_t$ 是 token $t$ 的输入向量，$e_i$ 是 router 权重的第 $i$ 行（也叫专家 $i$ 的中心向量），$\sigma$ 是 sigmoid 函数 $\sigma(x)=1/(1+e^{-x})$。DeepSeek-V3 把 router 的打分定义为

    $$s_{i,t}=\sigma(u_t^\top e_i).\qquad\text{(F1)}$$

    $s_{i,t}\in(0,1)$ 是 token $t$ 对专家 $i$ 的路由分数。给每个专家再加一个数 $b_i$ 叫 bias，初始 $b_i=0$。bias 加到分数上一起做 top-k 选择：

    $$g'_{i,t}=\begin{cases}s_{i,t}, & s_{i,t}+b_i\in\mathrm{Topk}(\{s_{j,t}+b_j\mid 1\leq j\leq N_r\},K_r)\\[4pt] 0, & \text{otherwise.}\end{cases}\qquad\text{(F2)}$$

    然后对被选中的 $K_r$ 个专家做归一化，得到最终 门控权重：

    $$g_{i,t}=\frac{g'_{i,t}}{\sum_{j=1}^{N_r}g'_{j,t}}.\qquad\text{(F3)}$$

    这里有两件事必须看清楚[C3]：

    1. 选择依据是 $s_{i,t}+b_i$：bias 影响哪个专家进 top-k。
    2. 门控权重取原始 $s_{i,t}$：被选中后 $g'_{i,t}=s_{i,t}$，不含 bias；归一化分母 $\sum_j g'_{j,t}$ 也只对被选中的 $K_r$ 个原始分数求和，不含 bias。

    最后这层 MoE 的输出（沿用 DeepSeekMoE 基本结构，DeepSeek-V3 报告 Eq.12）写作

    $$h_t'=u_t+\sum_{i=1}^{N_s}\mathrm{FFN}_i^{(s)}(u_t)+\sum_{i=1}^{N_r}g_{i,t}\,\mathrm{FFN}_i^{(r)}(u_t),\qquad\text{(F5)}$$

    其中 $\mathrm{FFN}_i^{(s)}$ 是 $N_s$ 个 shared expert（所有 token 都激活），$\mathrm{FFN}_i^{(r)}$ 是 $N_r$ 个 routed expert（只激活 $K_r$ 个，按 $g_{i,t}$ 加权）。shared expert 的角色见 MoE 大模型推理与服务基础。

    用两个边界检查验证 bias 的角色。

    第一，所有 bias 同时加常数 $c$。 此时 $s_{i,t}+b_i+c=(s_{i,t}+b_i)+c$，所有分数同时平移，相对排序不变，top-k 选择不变。也就是说 bias 只有相对差异起作用，整体平移没有效果。

    第二，bias 不进 mixture weight。 $g'_{i,t}=s_{i,t}$ 不含 $b_i$；分母 $\sum_j g'_{j,t}$ 也不含 $b$。所以无论 bias 怎么调，被选中专家之间的相对权重完全由原始分数 $s$ 决定。bias 改变"选谁"，不改变"被选中后给多少权重"。

    因为 bias 不进 $g_{i,t}$，反向传播算 $\partial L/\partial s_{i,t}$ 时不会经过 $b$；$b$ 也不在模型参数列表里。这就是"loss-free"的来源——没有辅助损失项，也没有混进主梯度的额外梯度[C3]。

    本章讲清了 bias 在前向里只调选谁、不进权重。但 bias 自己怎么变——下一章看 sign 规则式更新。

    bias 的固定步长 sign 更新——规则式，不进梯度

    bias 不是模型参数，所以不用梯度更新。它的更新规则由原始论文 Algorithm 1 给出，DeepSeek-V3 上线版本同样采用。

    每一步训练结束后，统计本步每个专家收到的 token 数，记为 负载 $c_i$。再算所有专家的平均负载

    $$\bar c_i=\frac{1}{N_r}\sum_{j=1}^{N_r}c_j.$$

    偏差定义为 $e_i=\bar c_i-c_i$：

    • $e_i>0$ 表示专家 $i$ 收到的 token 少于平均，处于欠载。
    • $e_i<0$ 表示专家 $i$ 收到的 token 多于平均，处于过载。
    • $e_i=0$ 表示恰好平均。

    更新规则写作

    $$b_i\leftarrow b_i+\gamma\cdot\mathrm{sign}(\bar c_i-c_i),\qquad\text{(F4)}$$

    其中 $\mathrm{sign}(x)=+1$ 若 $x>0$，$-1$ 若 $x<0$，$0$ 若 $x=0$；$\gamma$ 是固定步长超参（原始论文记为 $u$，DeepSeek-V3 报告统一记为 $\gamma$，叫 bias update speed）。也就是说：

    • 欠载（$e_i>0$）→ $b_i$ 增大 $\gamma$ → 下一轮 $s_{i,t}+b_i$ 更容易进 top-k → 该专家下一轮更可能被选中。
    • 过载（$e_i<0$）→ $b_i$ 减小 $\gamma$ → 下一轮 $s_{i,t}+b_i$ 更难进 top-k → 该专家下一轮更可能被冷落。
    • 恰好平均 → $b_i$ 不变。

    这里要强调三件事。

    第一，这是规则式更新，不进反向传播。 bias 不在计算图里，$\partial L/\partial b_i$ 不存在。每步训练的反向传播结束后，单独按 F4 用上一批的负载统计调一次 bias。论文里特别强调：用历史 batch 的负载更新，避免用到当前序列的 future token 信息（因果约束，arXiv:2408.15664 §3.2）。

    第二，为什么用 sign 而不是用误差幅度 $e_i$？ 原始论文实验了两种变体：sign 版本 $b_i\leftarrow b_i+\gamma\cdot\mathrm{sign}(e_i)$ 和连续幅度版本 $b_i\leftarrow b_i+\gamma\cdot e_i$。Table 3 报告两者 perplexity 几乎相同（9.50 vs 9.51），MaxVio 也接近（0.044 vs 0.036）。作者最终采用更简单的 sign 版本。sign 的好处是每步走固定小步，单步稳定，不会因一个 batch 偏差大就猛跳；代价是丢失幅度信息——差 1 个 token 和差 50 个 token 走的步长完全一样[C5]。

    第三，初始化 $b_i=0$，靠训练逐步逼近均衡。 由于每步只走 $\gamma$，本方法不保证单步完美均衡——它只是在训练过程中把负载逐步往均衡方向推。这是它的边界，下一章会展开。

  b  # 长度为 N_r 的 bias 向量，初始为 0

核心步骤：
  算平均负载 c_bar ← (1/N_r) * Σ_j c[j]
  对每个专家 i ∈ {1, ..., N_r}：
    算偏差 e_i ← c_bar - c[i]
    算方向 step ← sign(e_i)        # +1, -1 或 0
    更新 bias b[i] ← b[i] + gamma * step

输出：更新后的 b，用于下一步训练的前向路由选择

    注意 sign 与 $\bar c_i-c_i$ 的对应：欠载时 $e_i>0$ → step=+1 → bias 增大；过载时 $e_i<0$ → step=-1 → bias 减小。这一步在反向传播之外发生。

    手算一个 4 专家 top-2 的训练步——把路由与更新串起来

    把前面两章串起来，端到端跑一遍。教学示例。 设 $N_r=4$ 个专家、$K_r=2$、初始 $b=(0,0,0,0)$、$\gamma=0.001$。一个 batch 含 4 个 token，router 给它们的原始分数如下（数字为便于手算构造，不代表真实模型）：

    token \ expert$E_0$$E_1$$E_2$$E_3$
    $t_1$0.300.100.050.60
    $t_2$0.400.200.100.50
    $t_3$0.350.150.200.55
    $t_4$0.250.300.100.45

    第 1 步：首轮路由（bias 全为 0）。 因为 $b=0$，$s_{i,t}+b_i=s_{i,t}$，选每个 token 分数最高的两个：

    token分数排序（高→低）选中（top-2）
    $t_1$0.60 ($E_3$) > 0.30 ($E_0$) > 0.10 ($E_1$) > 0.05 ($E_2$)$E_3, E_0$
    $t_2$0.50 ($E_3$) > 0.40 ($E_0$) > 0.20 ($E_1$) > 0.10 ($E_2$)$E_3, E_0$
    $t_3$0.55 ($E_3$) > 0.35 ($E_0$) > 0.20 ($E_2$) > 0.15 ($E_1$)$E_3, E_0$
    $t_4$0.45 ($E_3$) > 0.30 ($E_1$) > 0.25 ($E_0$) > 0.10 ($E_2$)$E_3, E_1$

    统计负载：$c_0=3$（$t_1,t_2,t_3$ 选了 $E_0$）、$c_1=1$（只有 $t_4$）、$c_2=0$（一个都没选）、$c_3=4$（每个 token 都选）。平均负载 $\bar c_i=(3+1+0+4)/4=2$。偏差 $e_i=\bar c_i-c_i$：$E_0$ 是 $2-3=-1$（过载），$E_1$ 是 $2-1=+1$（欠载），$E_2$ 是 $2-0=+2$（更欠载），$E_3$ 是 $2-4=-2$（更过载）。

    展开：从负载统计到 bias 更新

    对每个专家套 F4：$b_i\leftarrow b_i+\gamma\cdot\mathrm{sign}(e_i)$，$\gamma=0.001$：

    • $E_0$：$e_0=-1$ → $\mathrm{sign}=-1$ → $b_0\leftarrow 0+0.001\times(-1)=-0.001$。
    • $E_1$：$e_1=+1$ → $\mathrm{sign}=+1$ → $b_1\leftarrow 0+0.001\times(+1)=+0.001$。
    • $E_2$：$e_2=+2$ → $\mathrm{sign}=+1$ → $b_2\leftarrow 0+0.001\times(+1)=+0.001$。
    • $E_3$：$e_3=-2$ → $\mathrm{sign}=-1$ → $b_3\leftarrow 0+0.001\times(-1)=-0.001$。

    注意 $E_2$ 与 $E_1$ 偏差相差 1 倍（$+2$ vs $+1$），但走到的步长相同——这是 sign 丢失幅度的直接体现。

    第 2 步：用新 bias 再跑一轮路由。 假设 batch 不变（教学示例，真实训练是下一个 batch），新 bias $b=(-0.001, +0.001, +0.001, -0.001)$。把 $s_{i,t}+b_i$ 列出来：

    token \ expert$E_0$ ($b=-0.001$)$E_1$ ($b=+0.001$)$E_2$ ($b=+0.001$)$E_3$ ($b=-0.001$)
    $t_1$0.2990.1010.0510.599
    $t_2$0.3990.2010.1010.499
    $t_3$0.3490.1510.2010.549
    $t_4$0.2490.3010.1010.449

    对 $t_1,t_2,t_3$，加 bias 后的排序与首轮完全相同（$E_3$ 与 $E_0$ 仍居前二，差 $0.001$ 没改变次序），仍选 $\{E_3,E_0\}$。对 $t_4$，原排序 $E_3(0.45) > E_1(0.30) > E_0(0.25) > E_2(0.10)$；加 bias 后 $E_3(0.449) > E_1(0.301) > E_0(0.249) > E_2(0.101)$，top-2 仍是 $\{E_3,E_1\}$，不变。

    这个例子说明一个关键事实：单步 bias 调整 $\gamma=0.001$ 的影响非常小。在本页的教学数字里，这一步根本没改变选择。要看到选择真的被改写，需要数十甚至数百步累积。这正是下一章要讲的边界：sign 是慢速调度，靠训练步数积累生效。但即便单步没变，bias 已经在朝正确方向走：过载的 $E_0,E_3$ bias 在减小，欠载的 $E_1,E_2$ bias 在增大，若干步后冷门专家会被拉回。

    展开：把 gamma 调大到 0.05，看一步能否改写选择

    保留上面同一 batch，但把 $\gamma$ 设为 $0.05$（仅为教学展示，远大于真实值）。更新后 $b=(-0.05, +0.05, +0.05, -0.05)$，加 bias 后的分数：

    token \ expert$E_0$$E_1$$E_2$$E_3$
    $t_1$0.250.150.100.55
    $t_2$0.350.250.150.45
    $t_3$0.300.200.250.50
    $t_4$0.200.350.150.40

    逐个 token 检查 top-2：$t_1$ 仍是 $\{E_3(0.55), E_0(0.25)\}$；$t_2$ 仍是 $\{E_3(0.45), E_0(0.35)\}$；$t_3$ 仍是 $\{E_3(0.50), E_0(0.30)\}$；$t_4$ 仍是 $\{E_3(0.40), E_1(0.35)\}$。即便 $\gamma$ 调到 0.05，在这个例子中也没改变任何 token 的 top-2——这进一步说明：要改写路由需要 bias 累积到能跨越分数间距的程度，而分数间距通常远大于 $\gamma$。这正是 sign 调度"慢但稳"的特征。

    教学简化：这个对照只为展示 sign 的步长特性，真实训练不会把 $\gamma$ 调到 0.05；那样会震荡。

    • 统计 $c_i$、$\bar c_i$、$e_i$，按 F4 写出每个专家的新 bias。
    • $\gamma=0.001$ 时为什么一轮 bias 更新不一定改变第二轮选择，这反映了 sign 调度的什么特征。

    本章用手算例子验证了 sign 的慢速特征。但手算数字与真实工程差多远——下一章看 DeepSeek-V3 的实际配置与边界。

    DeepSeek-V3 中的配置——调度与边界

    把概念落回真实工程。DeepSeek-V3 技术报告（arXiv:2412.19437）配置如下[N1, N2, N3]：

    • 规模：671B 总参数 / 37B 每 token 激活；每 MoE 层 256 routed expert + 1 shared expert；top-8；61 层中前 3 层稠密、其余 58 层为 MoE。
    • $\gamma$ 调度：前 14.3T token 用 $\gamma=0.001$；最后 500B token 设 $\gamma=0$（冻结 bias）；总训练 14.8T token。
    • 互补损失：$\alpha=0.0001$ 的 sequence-wise balance loss（处理序列内均衡）。
    • bias 的作用范围：bias 仅用于路由选择（top-k 判定），门控权重取原始分数 $s_{i,t}$，不含 bias。

    关于 $\gamma$ 调度[C5, N2]：训练前 14.3T token 用 $\gamma=0.001$ 让 bias 在大量数据上逐步逼近均衡；最后 500B token 把 $\gamma$ 设为 0 冻结 bias。这一调度反映一个事实——训练后期路由已基本稳定，继续更新 bias 反而会干扰最后收敛。$\gamma=0.001$ 这个值在原始 1B / 3B 实验上就被选为最佳（arXiv:2408.15664 §4.3），V3 直接继承。

    关于互补损失[C6, N3, F6]：aux-loss-free 只看批级 $c_i$，但可能出现"一个序列内每个 token 都激活同一组专家"——批级负载看起来均衡，但序列维度并不均衡。DeepSeek-V3 另加一个 sequence-wise balance loss

    $$L_{Bal}=\alpha\sum_{i=1}^{N_r}f_i P_i,\qquad f_i=\frac{N_r}{K_r T}\sum_{t=1}^T\mathbb{1}(s_{i,t}\in\mathrm{Topk}),\quad P_i=\frac{1}{T}\sum_{t=1}^T s'_{i,t},\qquad\text{(F6)}$$

    其中 $T$ 是序列长度，$f_i$ 是序列内专家 $i$ 被选中的频率，$P_i$ 是序列内平均归一化分数，$s'_{i,t}=\frac{s_{i,t}}{\sum_j s_{j,t}}$ 为归一化路由分数（$\sum_j$ 对该序列内全部 routed 专家求和）。$\alpha=0.0001$ 是个小权重——它不是 aux-loss-free 的替代，而是它的补充：aux-loss-free 解决批级，sequence-wise 解决序列内。本页不展开 F6 的推导，只点明它解决什么。

    本方法的边界：

    • 只解决批级负载均衡。序列内均衡由 sequence-wise loss 处理；二者各管一摊。
    • 不保证单步完美均衡。sign 走固定小步 $\gamma=0.001$，需要训练步数积累才能逼近均衡。上一章的手算例子已经显示单步 bias 调整通常不足以改变选择。
    • bias 仅用于路由选择，不进入门控权重。报告强调 bias 只影响 top-k 选择，门控权重取原始分数 $s_{i,t}$ 不含 bias（DeepSeek-V3 报告 §2.1.2）。
    • 专家数极多时 sign 收敛过慢。Kimi K3 把 routed expert 池扩大到 896（top-16）后，sign 丢失幅度信息的缺陷被放大：差 1 个 token 和差 100 个 token 走相同步长，部分专家长期训练不足。Kimi K3 用 Quantile Balancing 替代 sign——它从一次前向的路由分数分位数直接算出下一个 bias，仍属 aux-loss-free 家族（不引入损失项），只换 bias 的更新规则。详见 Quantile Balancing。

    完成本章后，用下面几个问题检查自己是否跟上：

    • 用一句话说明为什么最后 500B token 要把 $\gamma$ 设为 0。
    • aux-loss-free 与 sequence-wise loss 各解决什么，为什么需要二者互补。
    • Kimi K3 为什么要把 sign 换成 Quantile Balancing，sign 在 896 专家时失效的具体原因是什么。

    教学解释与类比边界

    教学解释。 可以把 bias 想成"配额调节阀"：冷门专家的阀往上拧一点、热门专家的阀往下拧一点，每步只拧固定一圈。这个类比只帮助理解"固定步长 + 方向调节"。它不覆盖：bias 不进 mixture weight 的细节（见 F2-F3）；sign 丢失幅度信息的缺陷（见 C5）；bias 仅用于路由选择、不进梯度（见配置章）。正式判断仍以 F2-F4 为准。

    教学简化及其限制

    - 把专家数设为 4、top-k 设为 2、batch 设为 4 token。可推出：F2/F3/F4 的逐步手算。不可推出：真实 256 选 8 规模下的数值行为。
    - F6 只点出公式不展开推导。可推出：aux-loss-free 与 sequence-wise loss 是互补但独立的两件事。不可推出：F6 的完整推导与各项符号的精确含义。
    - bias 更新那章的变体实验对照只列 Table 3 关键数据。可推出：sign 与幅度版本的性能对比结论。不可推出：Table 3 的其他实验设置细节。
    - 配置章中 Kimi K3 的 Quantile Balancing 只引用对比。可推出：sign 在 896 专家时失效、需换更新规则。不可推出：Quantile Balancing 的完整推导。

    回到开篇的五个问题。负载均衡是 MoE 训练的正反馈陷阱，传统辅助损失用 $\alpha$ 调梯度、两难。bias 加在路由分数上只管选谁、不进门控权重，因而不产生干扰梯度。训练时用 sign 走固定小步，单步稳定但丢幅度信息。4 专家 top-2 的手算例子验证了 sign 的慢速特征。DeepSeek-V3 用 $\gamma=0.001$ 训练 14.3T token 后冻结 bias，另加 sequence-wise loss 补序列内均衡；Kimi K3 在 896 专家规模改用 Quantile Balancing。这就是辅助损失无关路由的全貌。
