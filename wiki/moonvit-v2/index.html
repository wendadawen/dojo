    MoonViT-V2：K3 从零训练的视觉编码器

    MoonViT-V2 是 Kimi K3 的视觉编码器，负责把图像和视频的像素变成 LLM 能读的视觉 token。它的核心选择是：不用 SigLIP 这类对比预训练模型做初始化，而是完全从零、用与 LLM 相同的 next-token prediction 目标训练。K3 报告显示，这样训练的编码器梯度更稳，且在视觉评测上匹配 SigLIP 初始化的对照——说明对比预训练作为多模态大模型视觉编码器的初始化，在规模上并非必要。

    主流做法遇到什么问题：SigLIP 初始化为何不稳

    一个多模态大模型要让 LLM 看懂图，得先把像素变成 token。主流做法分两步：先用对比预训练把视觉编码器训练好，再把它的权重作为初始化接入 LLM 联合训练——前提是预训练得到的视觉知识能让模型有个好的起点。K3 报告把这个前提的稳定性问题摆了出来。

    主流用的对比预训练模型代表是 SigLIP（概念页待生成）。它的最小特征是：把图像和文本编码进同一个嵌入空间，训练目标是让配对的图文靠近、不配对的远离。这种对比损失偏向学习"全局语义"——一张图整体在讲什么——而对细粒度的文本与结构线索关注不足。本文只需要这一最小特征来支撑对照，不展开 SigLIP 的训练机制。

    当 SigLIP 初始化的视觉编码器接入 LLM 联合优化时，报告观察到不稳定。具体到 MoonViT-3D——报告里用作对照的视觉编码器变体，用 SigLIP 初始化——它的 vision-tower 梯度范数持续更高，且频繁出现尖峰。

    梯度范数是所有参数梯度组成向量的长度，是一个标量。它持续偏高、反复尖峰，意味着每步更新的方向和幅度在剧烈波动——这是训练不稳定的典型征兆。下图是 K3 报告 Fig.6 的简化对照，展示两条曲线的相对形态（具体小数不引用，只看相对高低与尖峰密度）：

    vision-tower 梯度范数
  │
0.6 ┤  ●·●                     ← MoonViT-3D (SigLIP init.)
    │      · ●    ●                  高、且尖峰频繁
0.4 ┤       ··●·  ·●·●
    │
0.2 ┤ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─  ← MoonViT-V2 (from scratch)
    │                                 全程更低、更平
  0 └──────────────────────────► 训练步 (×10³)

    这条对照直接指向一个问题：预训练权重与 LM 目标在联合优化时"打架"，导致更新剧烈波动。如果初始化本身就是不稳定的来源，那换个初始化方式——或者干脆不要这个预训练初始化——能不能让它稳下来？这正是 MoonViT-V2 要回答的。

    从零训练 + next-token prediction 的方案

    MoonViT-V2 的方案两步：(1) 完全从零初始化——不加载任何预训练视觉权重；(2) 训练目标是 next-token prediction（概念页待生成），即与 LLM 主干同一个语言建模目标：给定已观察的 token 序列，预测下一个 token 是什么。

    next-token prediction 是语言建模的标准目标——模型读一段 token 序列，逐位预测下一个 token。视觉编码器被这个目标训练，意味着它的表征是"为了帮 LLM 预测下一个词"而被塑造的，而不是"为了和某段文本配对"被塑造的。这是它和 SigLIP 对比损失在目标层面的根本区别。

    方案有两个动机，报告将二者并列。

    动机一：训练稳定性。从零初始化消除了"预训练视觉权重与 LM 目标耦合"带来的更新冲突——这正是 S1 观察到的梯度不稳定的来源。Fig.6 的对照已经显示，从零训练的 MoonViT-V2 全程梯度范数更低、尖峰更少。

    动机二：目标对齐。报告原文——next-token prediction 让编码器表征直接被语言建模目标塑造，而对比损失偏向全局语义、不利于细粒度文本和结构线索。换句话说，SigLIP 优化的是"图和文整体配不配"，而 LLM 真正需要的是"图里每个细节如何帮它预测下一个词"。用同一个目标训练编码器，让表征从一开始就对齐它最终的用途。

    把两个方案在三维度上并排看差异：

    维度SigLIP 初始化（MoonViT-3D）从零 + NTP（MoonViT-V2）
    初始化来源对比预训练好的视觉权重从零（无预训练视觉权重）
    训练目标先对比损失、后接入 LM 联合始终是 next-token prediction（与 LLM 同目标）
    表征偏向全局语义细粒度文本与结构线索（被 LM 目标塑造）

    方案定了，但"从零训练"本身容易不稳——没有预训练权重兜底，架构如果不当，从零起步更可能发散。什么样的架构能把从零训练稳住？

    服务稳定性的架构：27 层 ViT、RMSNorm、去 bias

    MoonViT-V2 的架构基础是 ViT（Vision Transformer，概念页待生成）：把图像切成 patch、每个 patch 线性投影成一个向量、送入 transformer 层堆叠。MoonViT-V2 是 ViT 家族的一个具体实例，下面每个数字都来自 HuggingFace 官方 config.json 的 vision_config 字段，可逐项核对。

    config.json 字段值口语名
    vt_num_hidden_layers27层数
    vt_hidden_size1024隐藏维
    qkv_hidden_size1536Q/K/V 投影维
    vt_intermediate_size4096MLP 中间维
    vt_num_attention_heads12注意力头数
    patch_size14patch 像素
    norm_typermsnorm归一化类型
    attn_bias / linear_bias / patch_embed_proj_bias均为 false全部去 bias

    报告说 MoonViT-V2 "roughly 0.4B parameters"。这个数字可以用上面的配置手算核对。每层（无 bias）含 Q、K、V、O 四个注意力投影、两层 MLP、两个 RMSNorm：

    注意力投影（每个 $1024 \times 1536$ 或 $1536 \times 1024$）：

    $$\text{attn} = 4 \times (1024 \times 1536) = 6{,}291{,}456$$

    MLP（fc1 $1024 \times 4096$、fc2 $4096 \times 1024$）：

    $$\text{mlp} = 2 \times (1024 \times 4096) = 8{,}388{,}608$$

    两个 RMSNorm（各仅 $1024$ 个增益、无 bias）：

    $$\text{norms} = 2 \times 1024 = 2{,}048$$

    每层合计：

    $$\text{per layer} = 6{,}291{,}456 + 8{,}388{,}608 + 2{,}048 = 14{,}682{,}112$$

    27 层总计：

    $$27 \times 14{,}682{,}112 = 396{,}417{,}024 \approx 0.40\text{B}$$

    与报告"roughly 0.4B"一致。这里只计了核心 27 层；patch embedding、位置嵌入、投影器是额外的小量，不影响"约 0.4B"的量级。

    补充：用 config.json 数值运行核对参数量与 token 数

    以下代码可独立运行，输入为 config.json 的 vision_config 数值，输出每层分项、27 层总计，以及 3584×3584 输入的 token 变化。它验证的是上文的两个手算。

    # 从 Kimi-K3 官方 config.json vision_config 读取的 MoonViT-V2 参数
hidden = 1024        # vt_hidden_size
qkv = 1536           # qkv_hidden_size (Q/K/V 各投影到此维)
inter = 4096         # vt_intermediate_size (MLP 中间维)
layers = 27          # vt_num_hidden_layers
patch = 14           # patch_size
merge = 2            # merge_kernel_size [2,2]
image_px = 3584

# 每层参数（无 bias：attn_bias/linear_bias/patch_embed_proj_bias 均为 false）
q = hidden * qkv
k = hidden * qkv
v = hidden * qkv
o = qkv * hidden
attn = q + k + v + o

mlp = hidden * inter + inter * hidden  # fc1 + fc2
norms = 2 * hidden  # 两个 RMSNorm，各仅 1024 个增益

per_layer = attn + mlp + norms
total = per_layer * layers

print(f"Q = {q:,}")
print(f"K = {k:,}")
print(f"V = {v:,}")
print(f"O = {o:,}")
print(f"attn/layer = {attn:,}")
print(f"mlp/layer  = {mlp:,}")
print(f"norms/layer= {norms:,}")
print(f"per_layer  = {per_layer:,}")
print(f"total 27L  = {total:,}  (~{total/1e9:.2f}B)")

# token 数
patches_per_side = image_px // patch
tokens = patches_per_side * patches_per_side
after_shuffle = tokens // (merge * merge)
print(f"\n{image_px}x{image_px} / patch {patch} -> {tokens} tokens")
print(f"pixel-shuffle {merge}x{merge} -> {after_shuffle} tokens")

    Q = 1,572,864
K = 1,572,864

O = 1,572,864

    验证的机制：attn/layer、mlp/layer、norms/layer 三项相加得 per_layer，×27 得 total；patches_per_side 平方得 tokens，÷4 得 after_shuffle。对应正文 F1 与 F2 两个手算。

    观察重点：total 的 0.40B 与报告"roughly 0.4B"一致；after_shuffle 的 16384 远小于 1M 上下文，这是 S4 高分辨率可行的前提。

    教学简化：只计核心 27 层（Q/K/V/O + 2 层 MLP + 2 RMSNorm），未计 patch embedding、位置嵌入（divided_fixed，按 height/width/time 分解）、MLP 投影器（patchmergerv2）与最终归一化；这些是额外小量，不计入"约 0.4B"核心量级。真实工程实现还含 flash-attention 等优化，不影响参数计数。

    架构里有两个设计需要单独点出，因为报告明确把它们定位为"服务从零训练稳定性"——不是任意工程惯例。

    第一是 RMSNorm（概念页待生成）：按均方根归一化、仅缩放增益、无 bias。它和 LayerNorm 的差别在于去掉了均值减法和 bias 项，计算更简、参数更少。

    第二是去除所有 bias：linear 和 attention 投影里的可学习加性偏置全部去掉（config 的 attn_bias、linear_bias、patch_embed_proj_bias 均为 false）。

    报告原文把这两条和"从零训练"绑在一起——"a design that further stabilizes the from-scratch optimization above"。也就是说，RMSNorm 和去 bias 不是独立风格选择，而是为了让从零训练更稳而配套的设计。这一点常被误读成"现代 ViT 惯例"，但报告给了明确的目的定位。

    图像/视频共享与高分辨率：分解注意力、时间池化、pixel-shuffle

    架构稳了，但 K3 要的是"原生多模态 + 长上下文"——一套参数同时吃图像和视频，还要在 1M token 上下文内塞下高分辨率。MoonViT-V2 用三个机制回答这个问题。

    机制一：图像与视频共享全部参数。同一套权重处理两种模态，不分成两个编码器。这是沿用 MoonViT-3D 的设计。

    机制二：分解注意力。处理视频时，注意力被拆成两趟（自注意力的最小定义：token 间相互加权聚合，概念页待生成）：

    视频 = T 帧，每帧 H×W 个 patch

帧内空间注意力（一帧内 patch 间）：
  帧 t:  [p1 p2 ... p_(H·W)]  ──相互 attend──►  帧内空间聚合

帧间时间注意力（跨帧、对应空间位置间）：
  位置 (i,j):  f1(i,j)  f2(i,j)  ...  fT(i,j)  ──相互 attend──►  时间聚合

    把空间和时间拆开，避免了"所有帧所有 patch 两两 attend"那种 $O(T^2 \cdot H^2 \cdot W^2)$ 的爆炸式开销。时间池化进一步沿时间维压缩 token，把多帧信息压成更短的序列。

    机制三：pixel-shuffle 2×2 下采样。投影前，把 2×2 的空间邻域搬进通道维：

    2×2 空间邻域 → 通道维              token 数 ÷ 4，通道维 ×4

[A][B]           [A B C D]
[C][D]   ──►     1 个 token

    这是无损重排——它压缩的是序列长度（token 数除以 4），不是信息量；四个邻域 token 的内容被完整保留在通道维里，后续投影再决定如何把它们降维成 LLM 嵌入。别把它误读成"丢信息的有损压缩"。

    把这三个机制放到 3584×3584 这张图上算一遍 token 账。patch 大小为 14：

    $$\frac{3584}{14} = 256 \quad\Rightarrow\quad 256 \times 256 = 65{,}536 \text{ 个 patch token}$$

    pixel-shuffle 2×2 把它压成：

    $$\frac{65{,}536}{4} = 16{,}384 \text{ 个 token}$$

    16,384 远小于 K3 的 1M token 上下文——这就是"3584×3584 在 1M 上下文内可负担"的算术依据。如果没有 pixel-shuffle 这一步压缩，65,536 个 token 会把上下文吃掉一大块，原生多模态的长上下文就难以成立。

    结果与结论：对比预训练初始化是否必要

    方案、架构、token 预算都讲了，最后一个问题：从零训练到底够不够用？

    报告给的答案是：MoonViT-V2 在视觉评测上匹配 SigLIP 初始化的 baseline。原文——"we find MoonViT-V2 matches the SigLIP-initialized baseline across vision evaluations"。报告没有给出逐项分数表，只给了这个定性结论，所以本文不构造任何具体分数数字。

    由此得出报告的核心结论：对比预训练作为多模态大模型视觉编码器的初始化，在规模上并非必要。

    维度SigLIP 初始化（baseline）从零 + NTP（MoonViT-V2）
    训练方式对比预训练 init + LM 联合完全从零、始终 NTP
    训练稳定性梯度范数高、尖峰频繁梯度范数低、更稳
    视觉评测结果baseline匹配 baseline
    结论—对比预训练 init 非必要

    这个结论有明确的边界，不能无限推广。

    边界一：限定场景。结论是"作为多模态大模型视觉编码器的初始化非必要"。它不等于"SigLIP 没用"——SigLIP 作为通用视觉表征模型，在零样本图像分类等任务上仍然有效。把"初始化非必要"扩大成"方法无用"是常见误读。

    边界二：限定规模。报告结论在 K3 的训练规模下成立——主干是约 2.78T 参数的 MoE。在更小规模、或不同主干下，从零训练是否仍能匹配对比初始化，报告没有给出保证。把规模结论外推到任意规模是不成立的。

    核心论断与来源

    • C1（从零训练 + NTP）：K3 报告 §2.4——"we train Kimi K3 vision encoder, MoonViT-V2, entirely from scratch with next-token prediction"。
    • C2（梯度稳定性对照）：K3 报告 §2.4 + Fig.6——"the SigLIP-initialized MoonViT-3D shows persistently higher gradient norms with frequent spikes, while MoonViT-V2 remains stable throughout training"；Fig.6 标题"the from-scratch MoonViT-V2 maintains lower gradient norms with fewer spikes"。
    • C3（目标对齐论断）：K3 报告 §2.4——"Training with next-token prediction also allows the encoder's representations to be shaped directly by the language-modeling objective, rather than by a contrastive loss that favors global semantics over fine-grained textual and structural cues"。
    • C4（架构：27 层、0.4B、RMSNorm、去 bias）：K3 报告 §2.4——"MoonViT-V2 is a 27-layer vision transformer with roughly 0.4B parameters that adopts RMSNorm and removes all bias terms from its linear and attention projections, a design that further stabilizes the from-scratch optimization above"；config.json vision_config：vt_num_hidden_layers=27, norm_type=rmsnorm, attn_bias=false, linear_bias=false, patch_embed_proj_bias=false。
    • C5（共享参数、分解注意力、时间池化）：K3 报告 §2.4——"Images and videos are processed with fully shared parameters, as in MoonViT-3D: attention is factorized into intra-frame spatial and inter-frame temporal passes, and temporal pooling further compresses tokens along the time dimension"。
    • C6（pixel-shuffle 2×2、3584、1M 上下文）：K3 报告 §2.4——"Before projection, a pixel-shuffle operation with 2 × 2 downsampling reduces the number of visual tokens by a factor of four, keeping inputs of up to 3584 × 3584 pixels affordable within the 1M-token context"；config.json vision_config：merge_kernel_size=[2,2], merge_type=sd2_tpool, patch_size=14。
    • C7（匹配 baseline、对比预训练 init 非必要）：K3 报告 §2.4——"we find MoonViT-V2 matches the SigLIP-initialized baseline across vision evaluations, indicating that contrastive pre-training is unnecessary as an initialization for multimodal language models at scale"。
    • C8（视觉通路沿用 K2.5）：K3 报告 §2.4——"This training recipe builds on a vision pathway that follows the overall design of Kimi K2.5: visual inputs are first encoded by MoonViT-V2 and then mapped by a lightweight MLP projector into the LLM"。

    核心公式与来源

    • F1（参数量手算）：由 config.json vision_config（vt_hidden_size=1024, qkv_hidden_size=1536, vt_intermediate_size=4096, vt_num_hidden_layers=27, 全 bias=false）逐项相乘相加得到 27 层 = 396,417,024 ≈ 0.40B，与报告"roughly 0.4B"一致。每层 = 4×(1024×1536) [attn] + 2×(1024×4096) [mlp] + 2×1024 [norms]。
    • F2（token 数手算）：由 config.json（patch_size=14, merge_kernel_size=[2,2]）与报告 3584×3584 推出：3584/14=256 → 256²=65536 → ÷4=16384。与报告"reduces the number of visual tokens by a factor of four"一致。
    • F3（RMSNorm 无 bias）：config.json norm_type=rmsnorm + 报告"adopts RMSNorm and removes all bias terms"。

    外部数字与实验条件

    • N1（梯度范数对照）：K3 报告 Fig.6（§2.4）。实验条件：K3 预训练消融，SigLIP 初始化的对照视觉编码器 MoonViT-3D vs 从零训练的 MoonViT-V2 对照；横轴训练步 ×10³，纵轴 vision-tower 梯度范数。MoonViT-3D 峰值约 0.6、全程更高且尖峰频繁；MoonViT-V2 全程更低更平。本文只引定性结论与量级，不引精确小数。（注：报告未明确二者为同一架构，"同架构"属页面推断，本页不采用。）
    • N2（匹配 baseline）：K3 报告 §2.4——定性结论"matches across vision evaluations"，报告未给逐项分数表。本文不构造具体分数数字。

    教学解释与类比边界

    • "梯度范数持续高且尖峰 = 训练不稳定"是教学解释，只帮助理解 Fig.6 为何被当作稳定性证据。它不覆盖动量优化器、梯度裁剪等工程干预；严格判断仍以优化轨迹与损失曲线为准。
    • "pixel-shuffle 把空间搬进通道、是无损重排"是教学解释，只描述张量重排这一局部操作。它不保证后续投影降维不丢失信息——降维那一步是有损的，但不属于 pixel-shuffle 本身。

    教学简化及其限制

    • 参数量只计核心 27 层（Q/K/V/O + 2 层 MLP + 2 RMSNorm/层），未计 patch embedding、divided_fixed 位置嵌入（按 height/width/time 分解）、MLP 投影器（patchmergerv2）与最终归一化。简化成立条件：这些是相对 0.4B 的小量，不影响量级判断。可推出：报告"约 0.4B"与核心层计算一致。不可推出：MoonViT-V2 的总参数精确等于 396,417,024。
    • SigLIP 只取"对比预训练、图文对齐、偏向全局语义"这一最小特征，不展开 sigmoid 损失推导与 batch 构造。可推出：为何它是"全局语义偏向"的初始化来源。不可推出：SigLIP 的完整训练机制。
    • 分解注意力只讲"拆成帧内空间 + 帧间时间两趟"，不展开两趟的注意力掩码、实现顺序与计算复杂度推导。可推出：为何能避免全对全开销。不可推出：精确的 FLOPs 节省量。
    • 前置概念（ViT、SigLIP、next-token prediction、RMSNorm、自注意力）均按任务约定占位不生成，正文仅给最小定义以支撑阅读，不内联大段背景。可推出：阅读本文所需的最小判断。不可推出：这些概念自身的完整理论。
