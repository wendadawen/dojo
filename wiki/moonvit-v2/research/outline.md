# MoonViT-V2 教学大纲

## 1. 页面开头

钩子场景：K3 是原生多模态——文本、图像、视频在同一个 backbone 的同一个 context 里处理，没有事后的模态对齐阶段。要实现这一点，需要一个视觉编码器把像素变成 LLM 能读的 token。主流做法是用 SigLIP 这类对比预训练好的视觉模型来初始化编码器。K3 的 MoonViT-V2 问了一个问题：这个对比预训练的初始化，真的是必须的吗？

一句话解释：MoonViT-V2 是 K3 的视觉编码器，一个 27 层 ViT，它选择从零训练（next-token prediction）而非 SigLIP 初始化，并在架构上用一组服务"从零训练稳定性"的设计 + token 压缩机制，让原生多模态与长上下文同时可行。

要解决的具体问题：(a) 从零训练为什么比对比预训练初始化更稳定、目标更对齐；(b) 训练具体怎么进行（在哪个阶段、跟谁一起、用什么数据）；(c) 架构如何服务这一选择；(d) 如何用一套参数同时处理图像和视频、并在 1M token 内支持高分辨率；(e) 从零训练是否真的够用。

学习承诺（读完你能回答）：见 scope.md Q1–Q5，对应页面开头 learning-goals 组件。

首个具体场景：以"3584×3584 的一张图"作为贯穿数字场景——它在未压缩时会产生 65536 个 token，这个数字在 S4（参数规模）与 S5（token 预算）中复用并推进。

与第一章过渡：要先看清"主流做法到底出了什么问题"，才能理解 MoonViT-V2 为什么换一条路。

页面开头组件：callout（核心提示）+ learning-goals（Q1–Q5）+ blockquote.meta（主要依据 K3 报告 §2.4/§3.1/§3.3/§5.2.3 + config.json）。不使用 context-box（背景信息并入 callout 与正文）、不使用 misconceptions（误解并入相应章节）。

## 2. 章节设计

### S1：主流做法遇到什么问题——SigLIP 初始化为何不稳

- 主要教学问题：主流多模态 LLM 用 SigLIP 等对比预训练模型初始化视觉编码器，这个"先用对比损失预训练、再接入 LLM 联合优化"的方案，在联合优化时出了什么稳定性问题？
- 对应范围：C2、N1（Fig.6）、辅助内容（SigLIP 最小定义、梯度范数作为稳定性指标）
- 正文要点：
  - 主流做法的最小描述：用对比预训练（如 SigLIP，概念页待生成）得到的视觉编码器权重作为初始化，再接入 LLM 联合训练。SigLIP 的最小特征：把图像与文本编码进同一个嵌入空间，训练目标是让配对的图文靠近、不配对的远离，偏向学习"全局语义"
  - 联合优化出问题：报告观察到 SigLIP 初始化的 MoonViT-3D 在联合训练中"梯度范数持续更高、且频繁尖峰"（C2）
  - 梯度范数为何能反映稳定性：梯度范数是所有参数梯度向量长度的标量；持续高、反复尖峰意味着更新方向与幅度剧烈波动，是训练不稳定的典型征兆（辅助内容，一句话点到）
  - 引用 Fig.6：给出对照图示（简化对照，不引用精确小数，只引定性结论与量级）
- 讲解材料及职责：SVG 图示（Fig.6 的简化对照——两条梯度范数曲线的相对形态）展示"对照现象"；正文文字解释"为什么这是问题"
- 前置知识安排：SigLIP/对比预训练（占位，正文给最小定义"图文对齐嵌入、对比损失偏向全局语义"）；梯度范数（基础统计量，内联一句话定义，不建概念页）
- 完成检查：读者能说出"主流做法的两步"与"Fig.6 显示的稳定性差异"两点
- 过渡：既然 SigLIP 初始化在联合优化时不稳，K3 选择的替代方案是什么？——进入 S2

### S2：从零训练 + next-token prediction 的方案

- 主要教学问题：MoonViT-V2 用什么方案替代 SigLIP 初始化，为什么这个方案应该更稳？
- 对应范围：C1、C3（核心，owns Q1）
- 正文要点：
  - 方案定义：完全从零训练（不加载任何预训练视觉权重），训练目标是 next-token prediction（概念页待生成）——即与 LLM 主干同一个语言建模目标：给定已观察 token，预测下一个 token
  - 动机一（稳定性）：从零初始化消除了"预训练权重与 LM 目标耦合导致的更新冲突"这一来源（C2 的另一面）
  - 动机二（目标对齐）：next-token prediction 让编码器表征直接被语言建模目标塑造；而对比损失偏向全局语义、不利于细粒度文本与结构线索（C3）
  - 对照表：SigLIP 初始化 vs 从零+NTP，在"初始化来源/训练目标/表征偏向"三个维度的差异
- 讲解材料及职责：对照表格（三个维度对照）展示方案差异；正文文字解释"为什么应该更稳"
- 前置知识安排：next-token prediction（占位，正文给最小定义"预测下一个 token 的语言建模目标"）
- 完成检查：读者能说出方案的"两步"（从零 + NTP）与"两个动机"（稳定性 + 目标对齐）
- 过渡：方案定了，训练本身怎么进行——在哪个阶段训、跟谁一起训、用什么数据？——进入 S3

### S3：训练是怎么进行的——接入 LLM 的联合预训练（2026-09-03 修订新增）

- 主要教学问题：MoonViT-V2 的训练具体是怎么进行的——是先单独训好编码器再接入，还是与 LLM 一起训练？用什么数据、系统上怎么跑得动？
- 对应范围：C9、C10、C11、N3、C8（核心，owns Q5）
- 正文要点：
  - 训练形态：K3 采用原生多模态训练策略，语言和视觉从训练一开始就联合优化，无"先训 LLM 再接视觉对齐"的事后阶段（C9）
  - 三层展开：数据层面视觉与文本 token 交织在同一序列；目标层面整条通路共享单一 next-token prediction 损失；参数层面从零初始化的 MoonViT-V2 经 MLP 投影器接在 LLM 前端、与主干一起更新（C9、C8）
  - 训练通路图（SVG）：样本条（图文 token 交织）→ MoonViT-V2（从零初始化）→ MLP 投影器 → LLM 主干 → 单一 NTP 损失 → 梯度反传更新整条通路
  - 呼应 S1：Fig.6 的对照发生在预训练消融里——SigLIP init 与 from scratch 在同样的联合预训练下对照，监控 vision-tower 梯度范数（C2、N1）；比较的是同一联合训练下的两种初始化，不是两种孤立训练方案
  - 训练数据：四大文本域 + 大规模视觉语料；视觉语料六类——图注（captions）、图文交织文档、OCR、感知（perception）、视频、视觉编程数据；沿用 K2.5 分类体系 + 开源集合 + 内部过滤/合成/去重流水线（C10）
  - 两个数据构造细节：坐标监督双格式（绝对 + 归一化 [0,1]，支撑分辨率鲁棒定位）；程序化多模态数据（代码片段与渲染视觉配对，格式含 SVG、3D 资产、网页、游戏、CAD 图纸）（C10）
  - 训练配置（整模级）：Per-Head Muon 优化器 + K2 引入的权重裁剪、QB 负载均衡、余弦调度（1% 线性 warmup）、权重衰减 0.1（N3）；注明报告未单独披露 vision tower 超参
  - 系统支持：大图/长视频拉长 vision encoder 计算时间、跨设备负载不均（C11）；动态上下文并行（大图沿 patch 维切分多设备、gather-KV、CP 组分子组均衡分布）；PP 气泡藏 ViT 计算（K2.5 DEP 基础上分解 ViT 前向/反向，大部分 ViT 计算藏进气泡）
- 讲解材料及职责：训练通路 SVG 图示展示"单一损失联合更新整条通路"；正文文字分层解释形态/数据/配置/系统
- 前置知识安排：上下文并行/流水线并行（内联最小定义：序列分段到多设备并行 / 模型按层切分流水执行）
- 完成检查：读者能说出"从预训练第一步起联合优化、无事后对齐"、"六类视觉语料"、Fig.6 的实验条件、动态 CP 与 PP 气泡两个系统设计
- 过渡：训练形态、数据与系统支持清楚了，但"从零训练"没有预训练权重兜底，架构不当更容易发散——进入 S4

### S4：服务稳定性的架构——27 层 ViT、RMSNorm、去 bias

- 主要教学问题：MoonViT-V2 的架构由哪些组件构成，关键设计如何服务"从零训练更稳定"？
- 对应范围：C4、F1、F3、辅助内容（ViT 最小定义）（核心，owns Q2）
- 正文要点：
  - ViT 最小定义：把图像切成 patch、每个 patch 线性投影成一个向量、送入 transformer 层堆叠（概念页待生成）
  - 可核对数字（来自 config.json）：27 层、隐藏维 1024、QKV 维 1536、MLP 中间维 4096、12 头、patch 14、RMSNorm、所有 bias=false
  - 参数量手算（F1）：每层 Q/K/V/O + 2 层 MLP + 2 RMSNorm ≈ 1468 万；×27 ≈ 3.96 亿 ≈ 0.4B，与报告一致；报告 Table 1 列 ViT 总参数 401M（含核心层外小量），与核心层手算相符
  - RMSNorm 与去 bias 的定位：报告明确将二者列为"进一步稳定从零优化"的设计（C4），不是任意惯例
  - RMSNorm 最小定义：按均方根归一化、仅缩放增益、无 bias（F3）
- 讲解材料及职责：参数量手算（数字例子，展示代入与求和）核对 0.4B；正文文字解释"设计如何服务目标"
- 前置知识安排：ViT（占位，正文给最小定义）；RMSNorm（占位，正文给最小定义）
- 完成检查：读者能列出可核对数字并说出 RMSNorm/去 bias 的稳定化定位
- 过渡：架构稳了，但要原生多模态 + 长上下文，还得让一套参数同时吃图像和视频、并把 token 数压下来——进入 S5

### S5：图像/视频共享与高分辨率——分解注意力、时间池化、pixel-shuffle

- 主要教学问题：MoonViT-V2 如何用一套参数同时处理图像和视频，并在 1M token 内支持高分辨率？
- 对应范围：C5、C6、F2（核心，owns Q3）
- 正文要点：
  - 图像/视频共享参数：同一套权重处理两种模态（C5）
  - 分解注意力：attention 分解为帧内空间（一帧内 patch 间）+ 帧间时间（跨帧对应位置间）两趟（C5）；自注意力最小定义（概念页待生成）：token 间相互加权聚合
  - 时间池化：沿时间维压缩 token（C5）
  - pixel-shuffle 2×2：把 2×2 空间邻域搬进通道维，token 数减 4 倍（C6）——是无损重排，压缩的是序列长度不是信息量
  - token 数手算（F2）：3584×3584 / 14² = 65536 token → pixel-shuffle 后 16384 token，在 1M 上下文内可负担
- 讲解材料及职责：token 数手算（数字例子，展示代入）核对压缩效果；SVG 图示（分解注意力两趟 + pixel-shuffle 搬运）展示结构
- 前置知识安排：自注意力（占位，正文给最小定义"token 间相互加权聚合"）
- 完成检查：读者能手算 3584 输入的 token 变化并说出三个压缩机制各压缩哪个维度
- 过渡：方案、训练与架构都讲了，但到底够不够用？——进入 S6

### S6：结果与结论——对比预训练初始化是否必要

- 主要教学问题：从零训练的 MoonViT-V2 与 SigLIP 初始化 baseline 相比结果如何，说明什么？
- 对应范围：C7、N2（核心，owns Q4）
- 正文要点：
  - 结果：MoonViT-V2 在视觉评测上匹配 SigLIP 初始化的 baseline（C7、N2）；报告未给逐项分数，正文不构造具体数字
  - 结论：对比预训练作为多模态大模型视觉编码器初始化在规模上并非必要（C7）
  - 边界：结论限定于"作为多模态 LM 视觉编码器初始化"这一场景；SigLIP 作为通用视觉表征模型在零样本分类等任务上仍有效（见 scope 误解1）
  - 适用规模：报告结论在 K3 规模（约 2.78T 参数 MoE 主干）下成立；更小规模未保证
- 讲解材料及职责：对照表（MoonViT-V2 vs SigLIP-init baseline 在"训练方式/结果/结论"上的对照）归纳结论
- 前置知识安排：引用 S1 的 SigLIP 占位定义
- 完成检查：读者能说出结果与结论，并说出结论的适用边界
- 过渡：（文末）来源与教学说明
