MoonViT-V2

Kimi K3 的视觉编码器，一个 27 层 ViT，选择从零训练（next-token prediction）而非 SigLIP 对比预训练初始化，从预训练第一步起与 LLM 联合优化，让原生多模态与长上下文同时稳定可行。

更新于 2026-09-03 · 主要依据：K3 报告 §2.4/§3.1/§3.3/§5.2.3 + 官方 config.json

是什么

MoonViT-V2 把图像和视频的像素变成 LLM 能读的视觉 token，是 K3"文本/图像/视频同一 backbone 同一 context"原生多模态架构里的视觉通路。它是一个 27 层、约 0.4B 参数的 Vision Transformer，输出经一个轻量 MLP 投影器映射进 LLM。

为什么需要它

  • 主流多模态 LLM 用 SigLIP 等对比预训练模型初始化视觉编码器，但 K3 报告发现这种初始化在接入 LLM 联合优化时梯度不稳定——SigLIP 初始化的 MoonViT-3D 梯度范数持续更高且频繁尖峰。
  • 对比损失偏向"全局语义"，而 LLM 需要的是细粒度的文本与结构线索——预训练目标和最终用途不对齐。
  • K3 要原生多模态 + 1M token 长上下文，还需要在 token 预算内塞下高分辨率图像与多帧视频，这要求架构层面的 token 压缩设计。

怎么训练

  • 从预训练第一步起联合训练。不是先训好视觉编码器再接入——语言和视觉从训练一开始就联合优化，无事后对齐阶段；视觉与文本 token 交织在同一条序列里，整条通路（编码器、投影器、LLM）共享单一的 next-token prediction 损失。
  • 数据。预训练语料 = 四大文本域 + 大规模视觉语料（图注、图文交织文档、OCR、感知、视频、视觉编程数据六类）；程序化多模态数据把代码与渲染结果配对（SVG、3D 资产、网页、游戏、CAD 图纸）；定位类坐标监督提供绝对与归一化两种格式。
  • 系统。大图与长视频会拉长编码器计算、造成跨设备负载不均——用动态上下文并行（大图沿 patch 维切分多设备）和把 ViT 计算藏进流水线气泡（流水线中设备空闲等待的时段）来应对。优化配置是整模统一的（Per-Head Muon + 权重裁剪、余弦调度、权重衰减 0.1）；vision tower 单独超参报告未披露。

核心直觉

  • 从零 + 同目标。不加载预训练视觉权重，训练目标就是 LLM 的 next-token prediction。编码器表征从一开始就被"帮 LLM 预测下一个词"塑造，而不是被"图文配不配"塑造。
  • 架构服务稳定。报告把 RMSNorm 和"去除所有 bias"明确定位为"进一步稳定从零优化"的设计，不是任意惯例——和从零训练这一选择配套。
  • 一套参数两种模态。图像和视频用同一套权重；视频注意力拆成帧内空间 + 帧间时间两趟，再加时间池化，避免全对全开销爆炸。
  • pixel-shuffle 压 token。投影前把 2×2 空间邻域搬进通道维，token 数除以 4，是无损重排（压序列长度不压信息量）。3584×3584 的图经此一步从 65536 token 压到 16384 token，在 1M 上下文内可负担。

关键结论与边界

  • MoonViT-V2 在视觉评测上匹配 SigLIP 初始化的 baseline；报告据此得出：对比预训练作为多模态大模型视觉编码器初始化，在规模上并非必要。
  • 边界一：结论限定于"作为多模态 LM 视觉编码器初始化"的场景，只评价"要不要用它做初始化"，不评价 SigLIP 自身性能——不等于"SigLIP 没用"。
  • 边界二：结论只在 K3 规模下成立，其主干约 2.78T 参数的 MoE（混合专家）；更小规模或不同主干下不保证。
