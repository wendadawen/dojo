概念快速阅读 · 注意力机制

DeepSeek Sparse Attention（DSA）

用一个廉价打分器挑出最相关的 k 个历史位置，只对它们做完整注意力，把长上下文的主注意力代价从平方降到线性。

更新于 2026-08-12

一句话定位

DeepSeek Sparse Attention（DSA）是一种可训练的细粒度稀疏注意力机制：先用一个成本极低的打分器给历史中每个位置评一个相关性分数，只让分数最高的 $k$ 个位置参与完整的注意力计算。它解决的是长上下文下注意力代价随序列长度平方增长的问题，把主注意力的复杂度从 $O(L^2)$ 降到 $O(Lk)$。

DSA 是随模型发布的架构改动，不是一篇独立论文的主题：它作为 DeepSeek-V3.2-Exp 相对 DeepSeek-V3.1-Terminus 的唯一架构改动被引入，机制描述出自 V3.2-Exp 技术报告与正式版论文 arXiv:2512.02556（后者明确 V3.2 与 V3.2-Exp 架构完全相同，DSA 在其中只占一节）。V3.2-Exp 的标准 benchmark 评测时间为 2025 年 9 月。

为什么需要它

  • 稠密注意力要求每个查询与全部在前位置比对一次，配对数随序列长度平方增长。128K 上下文下这成为主要成本。
  • 生成阶段每产出一个 token 都要把整个 KV cache 读一遍，瓶颈往往在数据搬运而非算力。
  • 滑动窗口这类固定模式稀疏虽然便宜，但窗口外的信息被彻底丢弃，关键信息在远处时失效。
  • 线性注意力换掉了注意力的形式、用固定大小状态替代 KV cache，代价是精确检索能力，属于另一条路线。

核心直觉

  • 打分与读取分离。lightning indexer 只负责给出"谁比谁更值得读"的排序，不参与最终输出的加权。排序对数值误差的容忍度远高于加权求和，因此打分器可以做得比主注意力粗糙得多——头数少（64 对 128）、每头维度低、用 ReLU 而非 softmax、可在 FP8 下计算，且每对 token 只产出一个标量分数、不需要再去加权聚合 value。
  • 选择由内容决定，不由位置决定。被选中的可以是很远的位置，这是 DSA 与滑动窗口的分界线。选中的位置照旧做完整的 softmax 注意力，因此精确检索能力保留。
  • 所有注意力头读同一批位置。候选集跨 query 头共享，原因是 kernel 效率：每个 key-value 条目必须被多个 query 共享，逐头独立选择会产生多套不规则访存模式。DSA 因此实例化在 MLA 的 MQA 模式上。
  • 打分能力是训出来的，不是装上去的。indexer 是新增参数模块，随机初始化时打分无意义。DeepSeek 用两阶段续训：先保持稠密注意力、冻结其他参数，让 indexer 用 KL 散度去拟合主注意力的分布（2.1B token）；再引入 top-k、放开全部参数做稀疏训练（943.7B token）。
  • 省的是计算，不是显存。每个查询选中的位置各不相同，后续 token 可能选到任何历史位置，因此全部 KV 条目仍须保留；indexer 还额外需要自己的一份 key cache。

关键结论与边界

  • 主注意力从 $O(L^2)$ 降到 $O(Lk)$，但整体不是线性。lightning indexer 仍要扫过全部历史位置，复杂度依旧是 $O(L^2)$。论文的论证是 indexer 的单价远低于 V3.1-Terminus 中的 MLA，而不是消掉这个平方项。
  • DSA 不减少 KV cache，反而略有增加。成立条件是把 DSA 单独看待——V3.2 确实省 KV cache，但那是 MLA 低秩压缩的功劳。此结论从两套官方与社区实现推出，论文未以否定句形式声称。
  • 序列长度不超过 $k$ 时 DSA 不产生收益。此时 top-k 选中全部位置、不产生裁剪，indexer 的计算成为纯开销。真实模型中 $k = 2048$。官方为短序列 prefill 专门实现了 masked MHA 模式；vLLM 中当该批 prefill 请求的最大序列长度不超过 index_topk、且未强制走 MQA 时改走稠密路径。
  • 引入 DSA 后未观察到明显性能回退。论文给出三组证据：标准 benchmark（2025 年 9 月，对比 V3.1-Terminus，训练设置严格对齐——正是这种对齐使"差异来自稀疏注意力"的归因成立）、ChatbotArena Elo（2025 年 11 月 10 日，两者相近）、发布后的独立长上下文评测（AA-LCR、Fiction.liveBench）。
  • DSA 不能直接加到未经续训的稠密模型上。943.7B token 的稀疏续训不是可省略的步骤。
