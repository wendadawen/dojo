# DSA 教学大纲

## 1. 页面开头

钩子场景：一个已经读进 128K token 上下文的模型，现在要生成第 128001 个 token。这一步里，注意力必须把这个新 token 的查询与前面 128000 个位置逐一比对——而下一个 token 还要再来一遍。真正被用上的位置有多少？

随后给出：

- 一句话解释：DSA 先用一个廉价打分器给历史每个位置评分，只让分数最高的 k 个位置参与完整注意力，把主注意力的代价从"与长度平方成正比"变成"与长度成正比"。
- 要解决的具体问题：长上下文下稠密注意力的计算量与访存量。
- 学习承诺：列出 Q1–Q5 五个问题。
- 首个具体场景：把 128K 的规模缩到 8 个位置、k=3，作为全文贯穿例子的起点。
- 与第一章的过渡：先说清代价到底长在哪里，才能判断该砍哪一刀。

只使用 scope.md 的内容。不在开头给出任何加速倍数或成本数字。

## 2. 章节设计

### 第 1 章：长上下文里，注意力的代价到底长在哪

- 主要教学问题：为什么长上下文下必须动注意力，代价的结构是什么样的
- 对应范围：Q1、K1、B1
- 正文要点：
  - 稠密注意力中每个 query 与全部在前位置配对，配对数随序列长度平方增长
  - decode 阶段每生成一个 token 都要重读整个 KV cache，这是访存而非算力瓶颈
  - 把 128K 场景缩成 8 位置的贯穿例子，数出配对数
  - FlashAttention 改的是"怎么算"，仍读全部位置；本章要问的是"能不能少读"（B1，消除误解 2）
- 讲解材料及职责：贯穿例子的配对计数（展示平方增长）；一句复杂度表达式（不做推导）
- 前置知识安排：首次依赖稠密注意力，链接 `../standard-attention/index.html`
- 完成检查：读者能说出代价随长度平方增长，且能区分"少算"与"算得更快"
- 过渡：既然要少读，就得先决定读哪些——这就分成两条路

### 第 2 章：两条减负路线，与 DSA 选的那条

- 主要教学问题：可训练稀疏与固定模式稀疏、与线性注意力的区别是什么
- 对应范围：Q1、K2、B2
- 正文要点：
  - 路线一：固定模式（滑动窗口）。便宜，但窗口外信息直接丢失，关键信息在远处时失效
  - 路线二：换掉注意力形式（线性注意力/KDA），用固定大小状态替代 KV cache，代价是精确检索能力
  - DSA 的选择：保留 softmax 注意力，只减少每个 query 实际读取的位置数，且"读哪些"由内容决定、可以选到很远处
  - 在贯穿例子上对比：窗口选最近 3 个，DSA 可能选第 1、2、7 个
- 讲解材料及职责：贯穿例子的三种选择对照（展示"位置决定"与"内容决定"的差别）
- 前置知识安排：链接 `../linear-attention/index.html`、`../kda/index.html`
- 完成检查：读者能说出 DSA 不改注意力形式，只改读取范围，且选择是学出来的
- 过渡："由内容决定读哪些"意味着必须先给每个位置打分——打分器本身不能太贵

### 第 3 章：lightning indexer 如何用极低成本给每个位置打分

- 主要教学问题：index score 怎么算，为什么它比主注意力便宜得多
- 对应范围：Q2、K3、K4、B3、F1、N1、N2、C5、C6
- 正文要点：
  - 打分器的要求：给出相对重要性排序即可，不需要参与最终输出加权，因此可以比主注意力粗糙得多
  - 给出 F1，逐符号解释 $H^I$、$\mathbf{q}^I_{t,j}$、$\mathbf{k}^I_s$、$w^I_{t,j}$、ReLU
  - 在贯穿例子上手算一遍 index score（2 个 indexer 头、8 个位置）
  - 便宜的四个来源：头数少（N1，对比主注意力 128 头）、维度低（N2）、ReLU 而非 softmax（C5，论文只给"吞吐考虑"，进一步解释标为教学解释）、可在 FP8 下计算（C6）
  - 关键限定：便宜不等于复杂度降低，indexer 仍要扫全部位置
- 讲解材料及职责：F1 表达变量关系；手算数字例子展示计算步骤；表格对比 indexer 与主注意力的每对单价构成
- 前置知识安排：链接 `../quantization-basics/index.html`（FP8）
- 完成检查：读者能写出 F1、解释每个符号、说出四个省钱来源，并知道 indexer 复杂度仍是平方
- 过渡：有了分数，接下来是怎么选、以及选完怎么接回注意力

### 第 4 章：top-k 选择，以及候选集为什么必须跨头共享

- 主要教学问题：选择后的注意力如何计算，为什么所有头读同一批位置
- 对应范围：Q3、K5、K6、F2、C4
- 正文要点：
  - 给出 F2，说明 $\mathbf{c}_s$ 是 key-value 条目
  - 在贯穿例子上：按第 3 章算出的分数取 top-3，写出参与注意力的位置集合
  - 实现上是通过掩码达成的：未选中位置置 $-\infty$ 后 softmax（S2 的实现事实），说明这与"只对 top-k 计算"在数学上等价，但真实 kernel 才能拿到性能收益
  - 候选集跨头共享（C4）：kernel 层要求每个 KV 条目被多个 query 共享，逐头独立选择会产生多套不规则访存
  - 因此 DSA 实例化在 MLA 的 MQA 模式上，一个 latent 被该 token 全部 query 头共享
  - 消除误解 5
- 讲解材料及职责：F2 表达关系；贯穿例子推进（从分数到选中集合）；图示展示"每头独立选" vs "共享候选集"的访存差别
- 前置知识安排：链接 `../mla/index.html`、`../mqa-gqa/index.html`
- 完成检查：读者能说出共享候选集的原因是硬件约束，并能说出它与 MQA 模式的关系
- 过渡：indexer 是新增模块，它的打分能力从哪来

### 第 5 章：indexer 的打分能力是训出来的

- 主要教学问题：为什么需要两阶段续训，每阶段在做什么
- 对应范围：Q4、K7、K8、F3、F4、C10、N4–N8
- 正文要点：
  - 起点问题：随机初始化的 indexer 打分无意义，直接 top-k 会切掉真正重要的位置（消除误解 3）
  - dense warm-up：保持稠密注意力、冻结除 indexer 外全部参数；目标分布 $p_{t,:}$ 的构造（主注意力分数跨头求和 + 沿序列 L1 归一化）；给出 F3；规模 N4、N5
  - sparse training：引入 top-k、放开全部参数；给出 F4，强调 KL 只在选中集合上；规模 N6、N7；k=2048（N3）
  - 信号隔离（C10）：indexer 输入 detach，indexer 只由 $\mathcal{L}^I$ 驱动、主模型只由语言建模损失驱动
  - 在贯穿例子上说明 warm-up 的目标分布怎么来（用第 3 章的数字构造一个小规模目标分布对照）
- 讲解材料及职责：F3、F4 表达训练目标；数字例子展示目标分布的归一化步骤；表格列两阶段的差异（是否稠密、冻结范围、KL 作用域、学习率、步数、token 量）
- 前置知识安排：KL 散度在正文用一句给出含义（衡量两个分布的差异，此处让 indexer 的 softmax 分布靠近主注意力的目标分布），不展开推导
- 完成检查：读者能说出两阶段各自的目的、冻结范围和 KL 作用域差别，并能解释为什么不能跳过续训
- 过渡：机制与训练都清楚了，接下来是它在真实推理栈里怎么跑、以及省了什么没省什么

### 第 6 章：工程落地——index kernel、独立 cache 与稀疏 attention 的接法

- 主要教学问题：DSA 在真实推理实现中由哪些部件构成，各自承担什么
- 对应范围：Q2 与 Q3 的工程侧、B4、B5、B6、C6、C12、C13、C14
- 正文要点：
  - 完整前向链路：hidden state → indexer 投影（`wq_b`/`wk` + k_norm）→ 独立 RoPE（C12，非 interleaved）→ Hadamard 变换（C13）→ FP8 量化 → index kernel → top-k → 稀疏 MLA
  - FP8 index kernel 的四步计算链（B5，来自 S2 kernel docstring）：fp8 q@k → ReLU 后乘 q 侧权重 → 沿头维求和 → 乘 k 侧 scale
  - indexer 维护自己的 key cache（FP8 值 + scale），与主 KV cache 相互独立
  - vLLM 中的对应结构：独立 `DeepseekV32IndexerCache`、`topk_indices_buffer`（以 -1 为无效哨兵）
  - DCP 切分下的 top-k 合并（B6、C14）：局部 top-k 必含全局 top-k 的论证，只交换候选而非整行分数
  - 明确标注：C12–C14 来自实现，不是论文声称；C14 来自 vLLM 实现
- 讲解材料及职责：流程图示展示前向链路与两份 cache 的位置；伪代码展示 index kernel 的四步；可运行代码用 numpy 复现 index score + top-k（与第 3、4 章的贯穿例子数字一致，验证手算）
- 前置知识安排：本章不引入新前置概念；FP8 已在第 3 章链接
- 完成检查：读者能画出前向链路、说出两份 cache 各存什么、说出 DCP 合并为何精确
- 过渡：把账算清楚——省了什么、没省什么

### 第 7 章：省了什么、没省什么、什么时候不该用

- 主要教学问题：DSA 的收益边界在哪里
- 对应范围：Q5、K9、K10、K11、C7、C8、C9、C11、N3、N11、E2
- 正文要点：
  - 省了：主注意力从 $O(L^2)$ 到 $O(Lk)$（C7）
  - 没省成线性：indexer 仍 $O(L^2)$，论文的论证是单价远低于 MLA 而非消掉平方项（C7，消除误解 4）
  - 没省显存：KV cache 不减少，且 indexer 额外增加一份 key cache（C9，标注为实现推出的结论，消除误解 1）
  - 失效区间：$L \le k$ 时 top-k 不产生裁剪，此时 indexer 是纯开销；官方为短序列 prefill 实现 masked MHA 模式（C8），vLLM 中对应 `prefill_max_seq_len <= topk_tokens` 走 dense MHA
  - 效果代价：引入 DSA 后未观察到明显性能回退（C11），注明评测时间与对比对象
  - 成本结论的口径（N11、E2）：H800、2 USD/GPU 小时的估算，只取定性结论
  - 适用边界小结（照 scope.md 6 节）
- 讲解材料及职责：表格列"省/不省"两栏；用 k=2048 与不同 L 的对照说明失效区间
- 完成检查：读者能回答 Q5 全部三问（省什么、没省什么、何时不起作用）
- 过渡：无（末章），收束到与相邻方法的定位对照

### 第 8 章：与相邻方法的定位

- 主要教学问题：DSA 在稀疏/高效注意力谱系中的位置
- 对应范围：B7、相邻概念表
- 正文要点：
  - 与 NSA 的关系（B7）：同为可训练稀疏注意力，DSA 论文引用 NSA 来支撑 kernel 层的共享约束；两者是不同设计，DSA 不是 NSA 的重命名
  - 与滑动窗口、线性注意力/KDA、FlashAttention、MLA 的一句话区分（复用第 1、2 章已建立的判据，不重复讲解）
  - DSA 名称歧义澄清：DSA 特指 DeepSeek Sparse Attention，不是"动态稀疏注意力"这类方法的统称
- 讲解材料及职责：一张定位对照表（改的是什么、KV cache 是否减少、是否需要续训）
- 完成检查：读者能在被问到任一相邻方法时说出与 DSA 的关键区别

## 3. 讲解顺序

依赖顺序为：代价结构（第 1 章）→ 路线选择（第 2 章）→ 打分（第 3 章）→ 选择与接回（第 4 章）→ 训练（第 5 章）→ 工程实现（第 6 章）→ 边界（第 7 章）→ 定位（第 8 章）。

先为什么后是什么：第 1、2 章完全不出现 DSA 的公式，只建立"为什么要少读、以及少读有几种做法"。第 3 章才引入 index score。

一次只引入一个新变量：第 3 章只讲打分，不讲选择；第 4 章只讲选择与共享约束，不讲训练；第 5 章只讲训练，不讲 kernel。FP8 在第 3 章仅作为"可以低精度算"的一个理由出现并链接概念页，其计算链推迟到第 6 章。

互相依赖处理：DSA 与 MLA 互相依赖（DSA 实例化在 MLA 上，而理解共享候选集需要 MQA 模式）。处理方式是第 4 章先用"KV 条目被多个 query 共享"这一可观察的访存现象引入，再指向 MLA 概念页，不在本页展开 MLA 机制。

## 4. 贯穿例子

单一贯穿例子：一个 8 位置序列，第 8 个位置是当前 query，$k=3$，indexer 头数 $H^I=2$，indexer 维度 $d^I=2$。全部数字人为构造，标记为教学示例。

- 第 1 章：数出稠密注意力在这个序列上的配对数，与 16 位置对照展示平方增长。
- 第 2 章：同一序列上对比三种选择——滑动窗口取最近 3 个（位置 5、6、7）、DSA 按分数取（位置 1、2、7）、稠密取全部 8 个。此处分数先给结论，第 3 章补计算过程。
- 第 3 章：给出 $\mathbf{q}^I_{8,1}$、$\mathbf{q}^I_{8,2}$、$w^I_{8,1}$、$w^I_{8,2}$ 与 8 个 $\mathbf{k}^I_s$ 的具体数值，逐位置手算 $I_{8,s}$，得到第 2 章使用的分数。此处要出现至少一个 ReLU 把负点积截成 0 的位置，用于展示 ReLU 的作用。
- 第 4 章：对第 3 章的 8 个分数取 top-3，写出选中集合；再展示掩码形式（未选位置置 $-\infty$）。
- 第 5 章：用第 3 章的分数构造 warm-up 的目标分布——给一组假设的主注意力分数，跨头求和后 L1 归一化，与 indexer 的 softmax 分布并列，说明 KL 要拉近的是这两者。
- 第 6 章：可运行代码复现第 3 章的手算与第 4 章的 top-3，输出与手算结果逐位对齐。
- 第 7 章：把 $k=3$ 换成 $k=8$（即 $k \ge L$），展示选择不产生任何裁剪，对应失效区间。

数字规模足够小可全程手算。每章复用时都新增一个概念或计算步骤，不重复展示同一件事。
