IndexPool

IndexPool 是稀疏注意力（先挑少量相关位置再做注意力的方法）的索引器（负责做这个挑选的模块）把相邻索引 key（索引器为每个 token，即文本切出的最小单位，算出的向量）组成固定大小的池，先压缩成池 key（每池索引 key 压成的一个向量）、按池选池，再把选中池还原为 token 索引（缓存槽位编号）的机制。

候选数量带来的开销

稀疏注意力（见 DSA）先用索引器从长上下文里找少量相关位置，再只对这些位置做注意力。上下文越长，这个挑选模块的延迟和内存开销越突出。

IndexPool 是什么

索引 key 是索引器为每个 token 算出的向量。IndexPool 把相邻的这些 key 组成固定大小的池；GLM-5.3-Flash 的池大小 $P$ 取 4，所以每池把 4 个索引 key 向量压成 1 个池 key。

每个 token 的隐藏状态（这一层传给下一层的向量）投影出用于池内加权的门控向量；它和池内位置参数经 softmax（把一组分数变成和为 1 的非负权重的方法）得到池化权重。索引器对池 key 打分和选择，选中池后再还原成其中的 token 索引。IndexPool 降低的是索引器在长上下文里的候选开销，不是主 KV cache（主注意力的键值缓存）本身的大小。

从 key 到 token 索引

先从第一个有效 token（非填充的真实位置）起每 $P$ 个相邻 key 分成一池，$P$ 是池大小；对每池算一个加权池 key。查询（当前要找相关位置的 token 表示）给每个池打分，选出至多 $K/P$ 个分数最高的池，$K$ 是 token 候选预算；把每池的 token 索引（缓存槽位编号）展开还原。GLM-5.3-Flash 开启尾部开关时，序列末尾不足 $P$ 个 token 的不完整池直接作为尾部索引保留。
