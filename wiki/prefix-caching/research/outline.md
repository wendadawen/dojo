# prefix-caching 文章大纲

## 1. 页面开头

- 开篇具体问题：一个对话服务，每条请求都以同一段 200 token 的系统提示词开头，一天收到一百万条请求——这一百万次对同一段话的 prefill 计算，有没有必要做一百多万次？
- 简要解释：前缀缓存把已完成请求的 KV cache 留在显存，后续请求开头 token 序列与之前相同即可直接复用、跳过命中部分的计算。SGLang 的 RadixAttention 用 radix tree 组织；vLLM/Mooncake 用哈希。同义叫法：context caching、prompt caching。
- 核心问题（学习目标 Q1–Q5）。
- 首个示例：两个对话请求（同一 system prompt + 各自消息）在 radix tree 中的匹配（第 2 章展开）。
- 过渡：先确认"什么能复用"。

## 2. 章节设计

### 第 1 章 什么能复用——共享前缀从哪来

- 章节问题：两个请求满足什么条件才能共用一份 KV cache？典型场景有哪些？
- 答案要点：KV cache 只依赖 token 序列（kv-cache 页"与查询无关"结论），开头 token 序列相同 ⇒ 前缀 KV cache 是同一份数据；来源四类——system prompt（全请求共享）、多轮对话历史（新一轮 = 前几轮全部内容 + 新消息，含上轮输出）、few-shot 示例、RAG 文档（同文档多问题）；收益双份：省 prefill 计算 + 省显存（一份缓存多处引用）。精确匹配语义（误解 1 处理）：token 级前缀相同，不是语义相似；编辑历史则断链。
- 正文要点：从 kv-cache 页结论直接推出复用条件；四类场景各一句具体例子；强调"前缀"意味着从头开始相同。
- 表达材料：四类共享来源对照表（组件 14：场景、共享内容、典型长度）。
- 前置知识：kv-cache 页链接（复用条件推导处）。
- 折叠块：无。

### 第 2 章 radix tree——组织与匹配

- 章节问题：缓存的前缀怎么组织，新请求怎么找到最长可复用前缀？
- 答案要点：radix tree = 压缩前缀树，边标变长 token 段；根到节点路径拼接 = 已缓存序列；新请求沿树匹配到最深节点 = 最长命中前缀，其下各页就绪；未命中部分 prefill 并作为新子边插入；SGLang 页 1 token、非连续分页布局（C3、C1/C2）；相比朴素 trie 的压缩收益。构造示例：请求 1（系统提示 S + 消息 m1）与请求 2（S + m2）：请求 1 完成后 S+m1 在树上；请求 2 匹配到 S 分叉点，S 复用，m2 新算并插入。
- 正文要点：先给树结构（结构 B 或 SVG 自绘——radix tree 的分叉是二维结构，建议内联 SVG 画 3 层小树），再走匹配/插入两步；把"分叉点 = 最长公共前缀"说透。
- 表达材料：SVG radix tree 小图（S、S+m1、S+m2 三条路径）；匹配/插入流程（结构 A）。
- 前置知识：paged-attention 页链接（页粒度与块级共享首次使用）。
- 折叠块：展开：三请求（R1=S+m1、R2=S+m2、R3=S'+m3，S' 与 S 不同）逐个走树的完整过程（含 R3 不共享导致根部分叉）。

### 第 3 章 缓存满了怎么办——LRU 逐出与引用计数

- 章节问题：显存装不下所有前缀时，先丢谁？正在使用的怎么办？
- 答案要点：LRU 叶子优先：先逐出最久未用叶子；公共祖先在所有子分支被逐出前一直可用（共享前缀天然长寿，C4）；运行请求保护：节点引用计数为 0 才可逐出（C5）；缓存与运行请求共享内存池——批多则缓存少、批少则缓存多，动态权衡（C5）。生成结果也入缓存（多轮场景的前缀来源，C9）。
- 正文要点：用第 2 章的三请求树演示：m2 分支被逐出时 S 仍留（R1 与未来请求可用）；引用计数在 continuous batching 语境下说明。
- 表达材料：无新图（沿用第 2 章树加逐出标注的文字描述）。
- 折叠块：无（机制简单，正文完整）。

### 第 4 章 命中率——页大小是隐藏的自变量

- 章节问题：同样的共享结构，为什么换个页大小命中率就变了？
- 答案要点：命中按整页计（F1：页命中数 = ⌊共享前缀长/页大小⌋，C8）；构造算例：共享 100 token——页 1 命中 100、页 32 命中 96（3 页）、页 256 命中 0（N3）；Strata 实测：页 512 比页 32 低 2.4% 命中率、吞吐剩 93%（N2，条件 Qwen-14B/H200/LooGLE）；SGLang 取页 1 正为匹配最细（N1）；容量之外的第二决定因素（误解 3 处理）。结尾过渡：命中还要求页"在显存且已就绪"——在 CPU 层的命中需要搬运、生成中的前缀不可复用（delay hit），分层与调度正是 Strata 页主题。
- 正文要点：先给按页匹配规则再算例；把 paged-attention 页的"页大小权衡"与本页"匹配粒度"接上（页大小的第三重身份）。
- 表达材料：命中算例表（页 1/32/256 × 共享 100 token）。
- 折叠块：无。

### 第 5 章 两种实现——radix tree 与哈希

- 章节问题：vLLM/Mooncake 不用树，用什么？各有什么特点？
- 答案要点：哈希链：每页指纹 = hash(token IDs, 前一页指纹)，相同指纹 = 相同前缀页，哈希表定位（C7）；对比（分析性推断标注）：树支持结构化推理（最长前缀匹配、逐出祖先复用），哈希实现简单、指纹可跨节点共享（分布式友好）；LMDeploy 粗粒度 trie 折中；Strata 基于 SGLang 把 RadixTree 扩展为 HiRadixTree（谱系一句 + 链接 Strata 页）。
- 正文要点：哈希机制描述控制在一段；对比明确标注分析性判断。
- 表达材料：两种实现对照表（组件 14：实现、索引结构、匹配方式、代表系统）。
- 折叠块：无。

## 3. 贯穿示例

单一贯穿：系统提示 S（200 token）+ 两条用户消息 m1、m2 的对话服务。第 1 章（S 被百万请求共享的账）→ 第 2 章（S+m1、S+m2 在树上的匹配与插入）→ 第 3 章（m2 分支逐出、S 存活）→ 第 4 章（S 若只有 100 token 与页大小的关系）。200/100 token 为构造数字（便于计算），第 4 章 100 token 算例与 N3 对齐。
