# SFT 内容范围

## 1. 概念含义

- 概念名称：监督微调
- 英文名称：Supervised Fine-Tuning
- 常见缩写：SFT；指令微调（instruction tuning，IT）在多数语境下与之同义（综述 arXiv:2308.10792 脚注 1："supervised fine-tuning (SFT) and instruction tuning (IT) are used interchangeably"）
- 简要定义：在预训练语言模型之上，用人工整理的「指令-回答」标注数据，继续以因果语言模型的下一 token 交叉熵目标做训练，使模型从「续写文本」转变为「遵循指令」。
- 正式定义：对预训练模型 $p_\theta$，SFT 在由 $(x, y)$ 对组成的数据集上继续训练，其中 $x$ 为指令（含上文），$y$ 为期望的回答，训练目标为最大化 $\sum_t \log p_\theta(y_t \mid x, y_{<t})$；常见实现将损失限制在回答 token 上（Llama 2 §3.1："We utilize an autoregressive objective and zero-out the loss on tokens from the user prompt, so as a result, we backpropagate only on answer tokens"）。
- 本文采用的语境：LLM 后训练（post-training）语境下的 SFT，即「预训练之后的指令微调阶段」。

### 概念歧义处理

状态：已裁定。SFT 在非 LLM 领域存在同名缩写（如软件领域 single-file template 等），但与本仓库读者语境无关。LLM 语境下 SFT 主流含义唯一：指令数据上的监督微调。依据：综述 arXiv:2308.10792 摘要与脚注 1 将 SFT 与 instruction tuning 等同使用。

### 包括什么

- SFT 的动机：预训练目标（下一词预测）与用户目标（遵循指令）的错位（综述 §1）
- SFT 的数据形态：(instruction, output) 对及其常见变体（多轮对话样本）
- SFT 的训练目标：因果语言模型交叉熵、teacher forcing、损失只算在回答 token 上的做法与理由（Llama 2 §3.1）
- SFT 在后训练流程中的位置：SFT → RM → 偏好优化（InstructGPT §3.1）
- SFT 的实践规律：数据量与质量（Llama 2 §3.1）、验证损失与实际偏好的背离（InstructGPT §3.5）

每项属于该概念的理由：以上内容直接构成「SFT 是什么、为什么、怎么训、边界在哪」的定义与机制主体。

### 不包括什么

- RLHF / PPO / DPO 的算法机制：属于偏好优化概念，本页只在流程定位层面引用其存在与分工（排除理由：独立概念，机制展开会使本页偏离主线）
- LoRA / 适配器等参数高效微调：SFT 描述的是数据与训练目标，不限定参数更新方式；全参与参数高效均可承载 SFT（排除理由：独立概念）
- 指令数据构造方法（self-instruct、数据清洗流水线、合成数据）：影响数据质量但属于数据工程主题（排除理由：不影响对 SFT 机制本身的理解）
- 多模态 SFT（视觉指令微调）：同一机制在多模态的实例化（排除理由：需要多模态前置知识，超出本页学习目标）
- RLVR / 推理模型后训练：SFT 之后的新范式，本页只在边界处提及（排除理由：独立概念）
- 预训练本身的机制：有独立概念页（见前置知识映射）

### 相邻概念

- 指令微调（instruction tuning）：同义，正文说明术语关系后统一使用 SFT
- 继续预训练（continued pretraining）/ 领域适配微调：同为「预训练后再训练」，但数据是无标注语料而非指令-回答对，目标仍是语言建模而非指令遵循；不纳入本页，只在边界处区分
- RLHF 偏好优化：相邻，见「不包括什么」
- few-shot prompting / 上下文学习：与 SFT 同样服务于「让模型按指令行事」，但不改参数；不纳入本页，动机章节可一句话对比

## 2. 学习目标

### Q1：预训练模型为什么需要 SFT？

- 完成答案：说明预训练的训练目标（在大语料上最小化下一词预测误差）与用户目标（让模型遵循指令、有帮助且安全）存在错位；这个错位导致预训练模型对指令输入的典型反应是「续写」而非「回答」；SFT 用「指令-回答」标注数据直接训练模型产出期望行为，弥合这一差距。
- 为什么是核心目标：不理解目标错位就无法理解 SFT 为什么存在、它在改什么。
- 依赖内容：语言模型预训练与下一 token 预测目标（前置概念页：语言模型预训练）；InstructGPT §3.1、综述 §1 的表述。

### Q2：SFT 的数据和训练目标具体是什么？

- 完成答案：说明 SFT 数据由 (instruction, output) 对组成（含多轮对话形态）；训练沿用因果语言模型的下一 token 交叉熵目标（teacher forcing）；常见实现把损失限制在回答 token 上（对指令部分置零），并说明这样做区分了「条件」与「要学的内容」；给出 SFT 损失公式。
- 为什么是核心目标：这是 SFT 的机制主体，缺它页面只剩名词解释。
- 依赖内容：交叉熵（前置概念页：交叉熵）；语言模型自回归分解（前置概念页：语言模型预训练）；Llama 2 §3.1 loss masking 原文。

### Q3：一条 SFT 训练样本的损失如何手算？

- 完成答案：对一个玩具词表与一条「指令-回答」样本，逐步算出每个回答 token 的交叉熵、整条样本的损失，并对比「不 mask 指令」与「mask 指令」两种做法在数值上的差异。
- 为什么是核心目标：没有可手算的例子，「损失只算在回答上」停留在口诀层面，读者无法把公式和实际计算对上。
- 依赖内容：交叉熵的数值计算（前置概念页：交叉熵）；构造示例。

### Q4：SFT 在后训练流程中处于什么位置，它与偏好优化如何分工？

- 完成答案：说明标准后训练流程为 SFT → 奖励模型 → 偏好优化（InstructGPT 三步法）；SFT 提供「模仿人类示范」的初始策略；偏好优化在 SFT 之上对「同一指令下哪个回答更好」继续优化；说明为什么需要分工：示范数据只能教「像示范的回答」，无法直接表达「多个可接受回答之间的优劣排序」。
- 为什么是核心目标：不定位 SFT 在流程中的位置，读者会把 SFT 误解为对齐的全部或终点。
- 依赖内容：InstructGPT §3.1 Step 1-3、Fig. 2。

### Q5：SFT 有哪些实践边界与常见误解？

- 完成答案：说明并纠正四个点——①SFT 不限定参数更新方式（全参或 LoRA 等均可）；②数据不是越多越好，数万条高质量标注即可达到高质量结果（Llama 2 停止于 27,540 条）；③验证损失过拟合不等于该停止训练（InstructGPT 训 16 epochs，1 epoch 后验证损失过拟合但更多 epoch 提升 RM 分数与人类偏好）；④SFT 后的模型质量可以超过大得多的纯预训练模型（InstructGPT 1.3B 的输出被人类偏好超过 GPT-3 175B——写作时核对原文）。
- 为什么是核心目标：这些是使用 SFT 时最容易做错决策的地方。
- 依赖内容：InstructGPT §3.5、§4 评测表述；Llama 2 §3.1。

## 6. 常见误解和适用边界

### 常见误解

1. 错误理解：SFT 等于全参数微调。正确结论：SFT 刻画的是数据（标注的指令-回答对）与目标（模仿示范的监督损失），参数更新方式可以是全参数，也可以是 LoRA 等参数高效方式。形成原因：主流教程的 SFT 示例默认全参数。影响：Q5。
2. 错误理解：SFT 数据越多效果越好。正确结论：Llama 2 发现数万条量级的高质量标注即可达到高质量结果，并放弃了数百万条第三方示例改用少量自产高质量数据（§3.1 "Quality Is All You Need"）。形成原因：直觉上沿用「预训练数据越多越好」。影响：Q5。
3. 错误理解：验证损失一过拟合就该停。正确结论：InstructGPT 的 SFT 在 1 epoch 后验证损失即过拟合，但训练更多 epoch 同时提升了 RM 分数与人类偏好评分（§3.5）。验证损失与下游偏好不是同一指标。形成原因：把预训练阶段的早停直觉搬到 SFT。影响：Q5。
4. 错误理解：SFT 之后模型只是在「背训练数据」。正确结论：InstructGPT 1.3B SFT 模型的输出被人类偏好于 GPT-3 175B（写作时核对原文位置），说明 SFT 带来的是行为方式的转变而非记忆。影响：Q5。

### 适用边界

- SFT 解决「让模型按指令回答」的对齐入门问题；它不解决「多个可接受回答之间的优劣」这一相对偏好问题——这需要偏好数据与偏好优化（条件：当存在多个质量档次的候选回答且希望模型选更好者时）。
- SFT 的结论依赖「有质量可靠的示范数据」这一条件；示范质量差时模型学到的是差的示范分布（Llama 2 强调质量检查）。
- loss masking 是主流做法（Llama 2 原文支持），但存在不对指令置零的实现选择；本页将 masking 作为「常见做法」陈述并说明其动机，不将其表述为 SFT 定义的必然组成部分。
