KV Cache Layout

KV cache 布局指每一层 key、value 缓存的各个维度在内存里的排列顺序，两种排法记作 NHD 和 HND，区别是序列位置维和头维谁排在前。

缓存里各维怎么排

生成时模型依次产生一个个 token（token 是模型读写文本的最小单位，可以是一个词，也可以是词的一部分）。模型由若干结构相同的层叠成，每层里都有注意力，它把每个位置的输入投影成 query、key 和 value 三个向量（见标准注意力）。每层都把前面位置的 key 和 value 留在显存（GPU 做并行计算时用的内存）里复用，这就是 KV cache。一层的缓存分成若干个页，一页里是一段序列位置，每个位置有一组头（注意力把每个位置的向量分成若干份，每份叫一个头），每个头有一小段向量。布局指的就是这些维度的先后，两种排法各用一串字母表示分给每页的那三维怎么排：NHD 的三个字母依次对应序列位置、头、每头向量，每个位置里各个头相邻；HND 把头排到最前，同一个头在各个位置上的向量相邻。

读一段缓存先读到什么

算注意力要同时用当前位置和缓存里的全部历史位置（见标准注意力）：缓存里的数是连续存放的，一次读进来的是沿某一维相邻的一段，这一段是哪些数由布局决定。NHD 下读到的是同一个位置的各个头，HND 下读到的是同一个头在相邻位置上的向量。

选 NHD 还是 HND

两种布局排的是同样那批数，只是维度换了先后。选 NHD，是因为它和算 key、value 的那步矩阵乘法输出的排列一致，可以直接拿来做缓存，不必转置；选 HND，是因为缓存用低精度格式（每个数占的位数比常规少的浮点格式，例如 fp8）时它对 GPU（做并行计算的处理器）实现更友好。在 fp16（与 fp8 同类、每个数占的位数更多的一种浮点格式）缓存上两种布局看不出明显的性能差别，默认取 NHD。
