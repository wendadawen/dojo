Strata：分层 KV cache 缓存框架

长上下文 LLM 服务把 KV cache 从 CPU 内存搬回 GPU 的带宽利用率只有 22%（GH200 上 5%），74% prefill 时间阻塞在 I/O；Strata 用 GPU-assisted I/O、布局解耦、cache-aware 调度三招回应，对 vLLM+LMCache 同 TTFT 吞吐最高 $5\times$。

arXiv:2508.18572v2 · Xie et al. · OSDI 2026 · 更新于 2026-08-19

研究问题

长上下文 LLM 的 KV cache 装不进 GPU 显存，生产系统把缓存分层到 CPU 内存甚至 SSD。问题出在"搬回来"这一步——把 KV cache 从 CPU 内存搬回 GPU 的带宽利用率低得让人意外（8192 token 加载只达 PCIe 5.0 理论带宽的约 22%，GH200 上低至约 5%），结果 74% 的 prefill 时间阻塞在 I/O 上、吞吐降 4 倍。

主要贡献

  • GPU-assisted I/O：用 CUDA kernel（数千线程各搬一小块）代替 cudaMemcpyAsync，2 block × 1024 thread 配置把 I/O 关进少数 SM、几乎不干扰计算（prefill 损失 <5%），把带宽利用率推回接近理论上限。
  • 布局解耦：GPU 保持 layer-first（计算友好），host 与外部存储用 page-first（传输友好），布局转换由 I/O 线程对偏移多做一次算术完成、几乎零开销；磁盘加载 8192 token 延迟最多降 4 倍。
  • Cache-aware 调度：把 PCIe 带宽当一等资源——transient node 防 delay hit、均衡 batch（load/compute 比例阈值 100）防 loading-bound、bubble filling 用 decode 批填空泡（decode 饱和 HBM 带宽、加载饱和 PCIe 带宽，资源正交）。

方法概述

Strata 基于 SGLang 实现，构建在 SGLang 的 RadixAttention 之上，把 RadixTree 扩展为 HiRadixTree（含 transient node 与跨内存层元数据）。Cache Controller（数据面）管理 GPU HBM、CPU DRAM、External Storage 三层之间的数据流与布局；Scheduler（控制面）组批时考虑带宽资源，按"均衡批 + bubble filling"避免 loading-bound。论文已在某领先 AI 公司生产部署，ROCm 后端兼容 AMD GPU。

关键结论

  • H200 上 LooGLE（长文档问答，avg 输入 21,613 token）端到端：Strata 对 vLLM+LMCache 与 SGLang-HiCache 同 TTFT 吞吐最多 5x（Llama-70B 行），对 TensorRT-LLM 最多 3.75x。
  • 消融：I/O 机制单独最高 2.3x 峰值吞吐、调度单独最高 1.8x（相对 SGLang-HiCache）；低请求率调度收益大、高请求率 I/O 主导。
  • 页大小负担消除：SGLang-HiCache 调到其最优页 512 也只有 Strata-IO 的 93%（命中率低 2.4%）。
  • GH200：I/O 机制把持续带宽从 40 推到 150 GB/s；调度改进是吃满 Grace Hopper 类平台的必要条件——仅有 I/O 不敌 H200 上完整 Strata。
  • 短上下文（ShareGPT）：无退化；底层 SGLang 引擎的 kernel 差异略弱于 vLLM/TensorRT-LLM，Strata 沿用未消除这一差距。

适用边界

方法适用于长上下文 prefill 主导、分层缓存已成必需的负载；实验用 1TB pinned DRAM（GH200 400GB），迁移需相应内存规划。不解决跨实例全局缓存协调（Mooncake/MemServe 方向）、近似/语义缓存（CacheGen/CacheBlend）、模型结构（稀疏注意力）。Disk 未纳入端到端实验（基线对 disk 支持有限）。
