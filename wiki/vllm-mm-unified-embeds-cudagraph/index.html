    多模态统一输入与 cudagraph

    模型 forward 的两个输入分支中，图像特征只能走 embedding；vLLM V1 让多模态模型的全部 token 都先过 embedding 层，图片位置再用 is_multimodal 掩码覆写为 ViT 特征，纯文本 batch 亦走同一路径。格式统一使被捕获的模型主体只有一种输入，decode 命中 FULL 重放，大 prefill 超出捕获尺寸走 eager。

    更新于 2026-08-21 · 类型：源码走读结论（vLLM 0.22.2.dev，Qwen3.5，TP=1）

    1. 问题：两种输入格式与 cudagraph 的固定性矛盾

    被 support_torch_compile 装饰的模型主体（如 Qwen3LLMModel）的 forward 里有一个输入分支：

    if inputs_embeds is not None:
    hidden_states = inputs_embeds            # 分支一：直接使用 embedding
else:
    hidden_states = self.embed_input_ids(input_ids)  # 分支二：token id 过 embedding 层

    而 cudagraph 的特性是捕获的图固定不变：一次捕获录制一段固定的执行流程，之后每次重放的都是这段流程。这带来一个矛盾：图像特征是 ViT 输出的浮点向量，只能以 embedding 形式进入模型，token id 无法承载它；纯文本却天然是 token id。如果两种输入各走各的分支，被捕获的图就有两种形态，管理与调度都会变复杂。

    2. 解法：统一成 inputs_embeds（一个格式，一张图）

    GPUModelRunner._preprocess 的多模态分支（supports_mm_inputs and is_first_rank and not is_encoder_decoder 三个条件：模型支持多模态、流水线第一段、非编解码架构）统一执行如下流程：

    混合 batch（既有纯文本请求又有图片请求）

    没有单独的"纯文本路径"。整个 batch 的所有 token 一起调 embed_input_ids 过 embedding 层，得到每个位置的文本 embedding；随后 _merge_multimodal_embeddings 用 is_multimodal 布尔掩码做一次覆写：inputs_embeds[is_multimodal] = 图像特征。掩码为 True 的位置（图片占位符处）被换成 ViT 特征，为 False 的位置（文本 token）保持原样。输出是一个形状统一的张量，纯文本请求与图片请求的区别只剩"每个位置的 embedding 来自哪里"。

    全纯文本 batch

    同样走这条路径：_execute_mm_encoder 发现没有待编码项直接返回，特征列表为空，embed_input_ids 检测到特征列表为空时跳过覆写、原样返回文本 embedding。也就是说，多模态模型上纯文本请求也承担一次 embedding 层计算——这是格式统一优先于单次计算开销的取舍。

    对比：纯文本模型走 input_ids

    非多模态模型走相反的取舍：_preprocess 的文本分支直接把 token id 作为输入，embedding 层留在模型主体内部。源码注释说明原因：若改用 embedding 输入，embedding 层就无法进入 CUDA graph，性能不划算。纯文本模型没有图像特征要拼，不存在格式统一的压力，自然选择让 embedding 层入图。

    v0 双编译到 v1 单图

    V0 引擎的处理方式是对两种输入各编译一份 CUDA graph（注释原话 "double compiling the CUDA graph, once with input_ids and again with inputs_embeds"）。V1 改为统一 embedding 输入后，只需捕获一种输入格式的图，不再需要双份编译。

    3. prefill 与 decode 的模式差异

    输入格式统一解决的是"图长什么样"；每步用不用 cudagraph、用哪种模式，由 CudagraphDispatcher.dispatch 按 batch 形状查表决定：token 数超出最大捕获尺寸、或该形状没有捕获记录时，返回 NONE（eager 执行）。

    场景batch 特征结果trace 证据
    decode uniform 小批次（每请求 1 token），形状命中捕获记录 FULL 模式重放整个模型主体 19 次 cudagraph replay 全部落在 decode 段
    大 prefill 983 token 单批，超出捕获尺寸上限 NONE，eager 执行 prefill 段（execute_context_1(983)）内 0 次 replay，但可见 dispatch 调用

    配置层面的默认模式是 FULL_AND_PIECEWISE：decode 批次用 FULL，prefill 与混合批次用 PIECEWISE（把注意力等不适合入图的算子留在图外，其余分段捕获）。本例的 983 token prefill 因尺寸超限进一步落到 eager，属于 dispatch 查表的自然结果，而非配置禁用。

    来源与范围说明

    源码定位

    • forward 分支：vllm/model_executor/models/qwen3_vl.py（Qwen3LLMModel forward 的 inputs_embeds 分支；embed_input_ids；support_torch_compile 装饰）
    • 统一输入：vllm/v1/worker/gpu_model_runner.py（_preprocess 多模态分支，3432 起；文本分支注释"not desirable for performance"；v0 双编译注释）
    • 掩码覆写：vllm/model_executor/models/utils.py（_merge_multimodal_embeddings；覆写语句 inputs_embeds[is_multimodal]）
    • dispatch：vllm/v1/cudagraph_dispatcher.py（dispatch；尺寸超限返回 NONE）
    • 模式定义：vllm/config/compilation.py（CUDAGraphMode；FULL_AND_PIECEWISE；模式说明 docstring，590 起）
