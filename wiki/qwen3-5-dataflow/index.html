Qwen3.5-397B-A17B 前向数据流

Qwen3.5 系列首个开源旗舰（2026-02-16，Apache-2.0），原生多模态 MoE 模型，官方博客表述为「Gated DeltaNet + Gated Attention 混合注意力 + 高稀疏 MoE + 多 token 预测」。逐张量累加得总参数 403,397,928,944：语言主干 396.35B、视觉塔 0.46B、MTP 草稿层 6.60B——命名「397B」对应语言主干加视觉塔的 396.80B。60 层按 3:1 交替：45 层 Gated DeltaNet 线性注意力 只保留固定递归状态，15 层真·全注意力（GQA，32 个查询头共享 2 个 KV 头），每层 FFN 均为 512 专家 top-10 加恒激活共享专家，softmax 路由配辅助损失。单 token 激活两种口径分别算得 16.33B（不含词嵌入查表）与 17.35B（含），官方称「17B」。残差是标准单流 pre-norm。视觉侧 27 层 ViT 经 2×2 合并输出 4096 宽，以替换占位符方式融入同一序列。

生成于 2026-08-27 · 依据官方 transformers 实现 + config.json + 真实 checkpoint 张量头 + vLLM MTP 实现 + 本机实测

3. 要点

整体结构：3:1 交替 + 单流残差

  • 沿序列：60 层按 full_attention_interval=4 排布，第 3、7、11…59 层（0 起）为全注意力，其余 45 层为 GDN。真实权重里含 linear_attn.* 的恰好 45 层、含 self_attn.* 的恰好 15 层，层号集合与 config 推导完全一致。
  • 沿深度：残差是标准单流 pre-norm——$x \leftarrow x + \mathrm{Mix}(\mathrm{RMSNorm}(x))$，子层输出直接加回。与 Qwen3.8-Flash-Next 的四条并行残差流（超连接读写）相比，这里没有任何流复制、门控读出或末端收束，残差宽度全程等于 hidden_size=4096。本机缩小模型逐层打点确认：每层输入输出均为 [1,T,4096]，无中间扩宽。
  • 沿宽度：每层 512 个路由专家取 top-10，另有 1 个共享专家恒激活。路由专家占总参数 95.82%（386.55B / 403.40B），每 token 只激活 10/512。
  • 多模态：视觉输入在进入主干前由 27 层 ViT 变成 4096 宽 token，替换序列中的占位符；此后视觉与文本共享全部 60 层（见第 4 节）。

GDN（Gated DeltaNet，45 层）

  • 状态是一个 $d_k \times d_v$ 的矩阵而非增长的 KV 序列。更新规则 $S_t = e^{g_t} S_{t-1} + k_t\big(\beta_t(v_t - S_{t-1}^{\top}k_t)\big)^{\top}$，输出 $o_t = S_t^{\top}q_t / \sqrt{d_k}$。括号里的 $v_t - S_{t-1}^{\top}k_t$ 是「当前值与状态已存内容之差」，即 delta rule 的名称来源。
  • 两个门都由输入投影得到：$\beta_t = \sigma(W_b x_t)$ 控制写入强度，$g_t = -e^{A_{\log}}\,\mathrm{softplus}(W_a x_t + b_{dt})$ 控制遗忘。因 $e^{A_{\log}}>0$ 且 $\mathrm{softplus}>0$，$g_t$ 恒负、$e^{g_t}\in(0,1)$ 必为衰减。本机实测 $g_t$ 落在 $[-63.306, -0.010]$，对应每 token 记忆保留率从 0.990 到接近 0，衰减强度跨四个数量级；$\beta_t$ 范围 $[0.0033, 0.9994]$。
  • 16 键头、64 值头，比值 4，源码用 repeat_interleave 把查询与键各复制 4 份对齐到 64 值头；查询与键在递归前做 L2 归一化。前置 kernel 4 的深度可分离因果卷积作用于整个 QKV 拼接（12288 通道），decode 时必须跨步保留 kernel−1=3 个位置的状态。
  • 两条计算路径等价：prefill 走分块并行、decode 走逐 token 递归。本机在真实头数与头维（16/64 头、128 维、20 个 token）下实测，两者输出最大绝对差 $3.725\times10^{-8}$、末态差 $3.576\times10^{-7}$；2 token 正交键的手算复核（末态 $[[3,5],[7,11]]$）与实跑差 $5.722\times10^{-6}$。
  • 输出门用 silu：递归输出先做逐头 RMSNorm（weight 形状 [128]，全模型 64 个值头共享同一份参数，且以 F32 存储——90 个 F32 张量中的一半），再乘 $\mathrm{silu}(W_z x)$。这一点与 Qwen3.8-Flash-Next 不同：那边 output_gate_type=sigmoid 可配置且 checkpoint 取 sigmoid，这边硬编码 silu。

全注意力层（15 层）：输出门 + QK-norm + 极端 GQA

  • 查询投影自带输出门：q_proj 输出宽度是 $32\times256\times2=16384$，切成查询与门两半；注意力输出先乘 $\sigma(\text{gate})$ 再过 o_proj。每个头每个 token 有独立的标量缩放（共 32×T 个），门在 o_proj 之前。官方博客称这一机制为 Gated Attention。真实权重 q_proj.weight 形状 [16384, 4096] 印证双倍宽度。
  • QK 归一化在 RoPE 之前：查询与键各过一个头维（256）的 RMSNorm，weight 形状 [256]、逐头维共享。本机实测归一化把头的 RMS 从约 63.7 压到约 1（乘 weight 前），消除了头间幅度差异。
  • GQA 压到 2 个 KV 头：32 个查询头分 16 组共享 2 个 KV 头，每 token 每层 KV cache 仅 $2\times2\times256=1024$ 个元素（bf16 下 2048 字节），比无 GQA 压缩 16 倍。本代没有 QSA 索引器——全注意力层的注意力掩码就是纯因果掩码，每个查询看到全部因果可见 token。
  • 部分交错 MRoPE：只旋转 256 维头的前 64 维，32 个频率槽位按 mrope_section=[11,11,10] 以 3 为步长交错分给 T/H/W。本机实测旋转严格保范数（差 $0.00\times10^{0}$），后 192 维原样通过；$\theta=10^7$ 使最低频达 $1.54\times10^{-6}$，支持 262144 位置。槽位排布与 Qwen3.8-Flash-Next 完全一致（详见 MRoPE 概念页）。

MoE 路由：softmax 竞争 + 辅助损失

  • 先全局 softmax 再对选中项重归一化，且重归一化无条件：在全部 512 个专家上做 softmax，取 top-10，再把这 10 个概率除以它们的和。路由器没有 norm_topk_prob 开关（Qwen3.8-Flash-Next 保留了该开关）。本机实测 top-10 原始概率合计仅 $0.17\sim0.24$，重归一化把权重放大约 5 倍，每 token 权重和恒为 1。
  • 均衡靠辅助损失而非推理期修正：router_aux_loss_coef=0.001，负载均衡损失为 $E\sum_i f_i p_i$ 形式（$f_i$ 为专家入选频率、$p_i$ 为 softmax 概率均值）。本机实测随机路由下 6 token 的损失为 0.014310，完全均匀分布下界 0.001000。这与 DeepSeek-V4 / Kimi-K3 的无辅助损失 sigmoid+bias 路由是两条路线——后者推理时用偏置修正负载，前者训练时用梯度拉齐。
  • 共享专家带标量门：共享专家不参与路由，输出乘逐 token 的 sigmoid 标量 $\sigma(W_g x)$ 后与路由结果相加。shared_expert_gate 形状 [1, 4096]。一条 FFN 通路里同时存在三种门：路由权重（top-10 向量）、共享专家门（标量）、注意力输出门（逐头向量）。
  • 激活量：单层 MoE 激活 140,513,280（10 个路由专家 125,829,120 + 共享专家 12,582,912 + 路由器 2,097,152 + 门 4,096），全量 6,442,450,944，激活占 2.18%。60 层路由专家合计 386,547,056,640，与张量头累加精确相等。专家前向为 SwiGLU：gate_up_proj 为打包 3D 张量 [512, 2048, 4096]。

MTP 草稿层：单投影拼接 + 完整 MoE

  • 接入方式：取主干末端的隐状态 $h$ 与当前 token 的词嵌入 $e$，各过独立的 pre_fc_norm RMSNorm 后拼接，经 mtp.fc（[4096, 8192]）投回 4096。拼接顺序是 $[\mathrm{norm}(e);\mathrm{norm}(h)]$，embedding 在前——这一顺序由 vLLM 的 Qwen3NextMultiTokenPredictor.forward 实锤（transformers 不实现 MTP 前向，加载时直接忽略 mtp.*）。本机实测两种拼接顺序的 fc 输出差 9.430，顺序不可交换。
  • 草稿层是主干的同构拷贝：1 层全注意力解码层（双宽 q_proj + QK-norm + GQA + 输出门）加完整 MoE。与主干 15 个全注意力层的 13 个共有模块形状逐一相同；无 GDN——MTP 层 layer_types 只用全注意力。
  • 专家存储布局与主干不同：MTP 的 512 个专家存成 1536 个逐专家独立 gate_proj/up_proj/down_proj 张量，而主干是打包 3D 张量。两者参数量精确相等（每层都是 6,442,450,944），只是布局差异——加载器需要分别处理。
  • 共享词表两头：mtp_use_dedicated_embeddings=false，checkpoint 无 mtp.embed_tokens/mtp.lm_head，草稿层直接复用主干的两头（各 1.02B）。

4. 视觉编码器与多模态融合

视觉侧是一个 27 层的独立 ViT，参数量 456,010,480（0.456B），占全模型 0.113%。作用是把像素变成与语言主干同宽（4096）的 token，之后视觉与文本在同一序列里共享全部 60 层。

4.1 从像素到 patch：一次 3D 卷积

patch_embed 是 Conv3d，kernel 与 stride 都等于 (2, 16, 16)。二者相等意味着每个时空 patch 独立映射、互不重叠，等价于对展平后的 $3\times2\times16\times16=1536$ 维向量做一次线性变换——本机实测两种计算最大差 $0.000\times10^{0}$。真实权重 patch_embed.proj.weight 形状 [1152, 3, 2, 16, 16]，元素数 1,770,624 恰等于 $1152\times1536$。静态图像沿时间维复制到 2 帧以匹配 temporal_patch_size。

4.2 位置信息：可学习方格重采样 + 二维 RoPE

  • 可学习位置嵌入：num_position_embeddings=2304 即 48×48 方格，每格一个 1152 维向量。对每张图按其实际网格做双线性重采样（align_corners=True），本机实测 (14,14)/(28,28)/(42,42)/(33,60) 四种网格的插值权重和均为 1.0，每位置由 4 个网格点混合。位置信息跟随图像真实长宽比，无需 resize。
  • 二维 RoPE：维度参数 $\text{head\_dim}/2 = 72/2 = 36$，频率数 18。每个 patch 带一对 $(h,w)$ 坐标，前 18 对用 h、后 18 对用 w，与自身拼接成 72 维后配对旋转 $(i, i+36)$。本机实测旋转严格保范数（差 $4.77\times10^{-7}$）。语言塔只旋转 1/4 头维（64/256），视觉侧 72 维全部按对参与旋转。

4.4 merger：2×2 空间合并并对齐主干宽度

PatchMerger 把空间上 2×2 相邻的 4 个 patch 拼成 $1152\times4=4608$ 维，经 $4608\to4608\to4096$ 两层投影输出。因为 use_postshuffle_norm=False，LayerNorm 作用在合并前的 1152 维上（真实权重 merger.norm.weight 形状 [1152] 而非 [4608]，直接印证）。输出宽度 4096 与语言主干 hidden_size 相等，这是两侧能直接拼接的前提。视觉 token 数由 $\prod(\text{grid\_thw})/\text{spatial\_merge\_size}^2$ 给出：448² 图 196 个、896² 图 784 个、1344² 图 1,764 个、1080p 图 1,980 个（均本机实算）。

4.5 融合：替换占位符而非拼接

融合用 inputs_embeds.masked_scatter(image_mask, image_embeds)，把序列中 image_token_id=248056（视频 248057）的占位符位置原地替换成视觉特征，序列长度不变，视觉 token 数必须与占位符数严格相等。vision_start_token_id=248053 与 vision_end_token_id=248054 是普通文本 token，不被替换。

4.6 视觉 token 在位置轴上只推进少量位置

语言塔用三维 MRoPE，文本段的三个维度取同一个 arange；视觉段由 get_vision_position_ids 生成 $(T,H,W)$ 三元组。关键规则：图像块结束后位置只推进 $\max(h,w)/\text{merge}$ 而非推进 token 数。本机实测 8 个文本 token 后接 (1,28,28) 图：196 个视觉 token 只让位置推进 14，后续文本从位置 22 开始而非 204。(1,84,84) 图为 1,764 个 token 推进 42，压缩比 42 倍。因此 max_position_embeddings=262144 约束的是位置轴上限而非 token 数上限——序列长度预算与位置轴预算是两笔账。

4.7 视频按时间戳逐帧拆分

Qwen3.5 用时间戳分隔视频：<t1> <vision_start> 帧1 <vision_end> <t2> …。get_rope_index 把一个 (3,8,16) 的视频网格拆成 3 个 (1,8,16) 单帧网格，每帧独立走视觉位置生成并各推进 $\max(h,w)/2$。本机实测 3 帧视频：96 个视觉 token，位置轴推进 24（3×8）；每帧的 T 维恒为该帧起始位置——时间戳本身编码了帧序，帧内 T 退化为常数。若不拆分，T 维才会承载帧号 0,1,2。

6. 核对方式

数字分三类来源，各自的取得方式如下。

结构与维度：用 HTTP Range 请求读取全部 94 个 safetensors 分片的 JSON 文件头（合计 366,184 字节，未下载权重本体），得到 2924 个张量的名称、形状与 dtype。以此交叉验证源码推导：层型分布、q_proj 双宽、GDN 各投影宽度、MoE 打包布局、MTP 结构、视觉塔各模块形状，共 35 项断言全部通过。90 个 F32 张量恰好是 45 个 GDN 层的 A_log 与 norm.weight 各 45 个（dt_bias 为 BF16）。

公式与数值行为：按官方 modeling_qwen3_5.py（含 qwen3_next / qwen3_vl_moe 依赖）逐行语义复现各算子，用真实 config 的头数与头维在随机张量上实跑。已完成的对照包括：GDN 分块与递归等价性（$3.725\times10^{-8}$）与手算复核、门控数值范围、部分 RoPE 保范性、MRoPE 交错槽位归属、路由重归一化与辅助损失、MTP 拼接顺序不可交换性、视觉 Conv3d 与线性变换等价（$0.000\times10^{0}$）、位置网格插值权重和、视觉 RoPE 保范性（$4.77\times10^{-7}$）、视频逐帧位置分配。

端到端数据流：构造保留全部结构特征的等比缩小模型（8 层 = [GDN×3, 全注意力]×2，隐藏维 64，4Q/2KV 头，双宽 q_proj + QK-norm + 输出门，GDN 带 conv 状态维护，8 专家 top-2 加 sigmoid 门控共享专家），跑通整段 prefill 与逐 token decode，两者 logits 最大绝对差 $3.204\times10^{-6}$。逐层形状记录确认残差全程单流 64 宽、GDN 缓存形状恒定、全注意力 KV 随长度增长。

实测脚本与一次性跑完全部脚本的原始输出（392 行）存于 research/ 目录：read_headers.py 读张量头，verify_structure.py 做 35 项结构断言，count_params.py 核算参数量（含视觉分组与含查表激活），fetch_family_configs.py 拉家族六型号对比，probe1~probe7 为各机制的数值验证（GDN / 注意力与 MRoPE / MoE / MTP / 端到端 / 视觉 / 视频位置），vllm-qwen3-next-mtp-reference.py 为 MTP 前向的 vLLM 参考实现快照，measured-output.txt 为原始输出，verify_page_numbers.py 核对页面数字与存档一致。
