Qwen3.8-Flash-Next 前向数据流

Qwen3.8-Flash-Next 是 180B 参数、每 token 激活 6.04B 的多模态 MoE 模型。48 层主干按 3:1 交替：每 4 层中前 3 层是 Gated DeltaNet 线性注意力，只保留一份与序列长度无关的固定状态；第 4 层是 QSA，把每 4 个连续 token 的索引键压成一块，由一个 4 头轻量索引器选出 512 块（合 2048 个 token）参与注意力。残差不是单条通路，而是入口处复制出的 4 条并行流，每个子层前后由低秩门控读出与写回。第 2 层额外注入一张 51.2B 参数的哈希 N-gram 查表，该表只被查询、不参与任何矩阵乘。FFN 全为 512 路由专家 top-10 加 1 个恒激活的共享专家。视觉侧是 27 层独立 ViT，输出经 2×2 合并对齐到主干宽度后，以替换占位符的方式融入同一序列，此后与文本共享全部 48 层。

生成于 2026-08-27 · 依据官方 transformers 实现 + config.json + 真实 checkpoint 张量头与 I64 缓冲真值 + 本机实测

3. 要点

整体结构：3:1 交替 + 四条残差流

  • 沿序列：48 层按 full_attention_interval=4 排布，即第 3、7、11…47 层（0 起）为 QSA，其余 36 层为 GDN。真实权重里含 linear_attn.* 的恰好 36 层、含 self_attn.* 的恰好 12 层，层号与 config 完全一致；12 个 QSA 层每层都带 self_attn.indexer.*，与源码中 Qwen4ExpTextAttention.__init__ 无条件构造索引器的写法对应。
  • 沿深度：入口处 hidden_states.repeat(1, 1, 4) 把 embedding 复制成 4 份，残差流此后全程为 $4\times2560=10240$ 宽。每层内部 attn_hyper_connection 与 mlp_hyper_connection 各调用一次：前者把 4 条流归约成 2560 宽送进子层，后者把子层输出按每条流一个标量写回。子层内部维度不受残差条数影响。末端 hyper_connection_mixer 把 4 条流收回 2560 宽再送 lm_head。
  • 沿宽度：每层 512 个路由专家取 top-10，另有 1 个共享专家恒激活。路由专家占总参数 67.11%（120.80B / 180.00B），但每 token 只激活 10/512。
  • 额外两路：第 1 层前注入 N-gram 查表特征，这是一条与注意力、FFN 并列的独立信息通道，且只出现一次；多模态输入时另有 27 层视觉 ViT 在进入主干前把像素变成同宽的 token，替换序列中的占位符（见第 4 节）。

GDN（Gated DeltaNet，36 层）

  • 状态是一个 $d_k \times d_v$ 的矩阵而非增长的 KV 序列。更新规则为 $S_t = \alpha_t S_{t-1} + k_t\big(\beta_t(v_t - S_{t-1}^{\top}k_t)\big)^{\top}$，输出 $o_t = S_t^{\top}q_t / \sqrt{d_k}$。括号里的 $v_t - S_{t-1}^{\top}k_t$ 是「当前值与状态已存内容之差」，即 delta rule 的名称来源：写入的是增量而非原值。
  • 两个门都由输入投影得到：$\beta_t = \sigma(W_b x_t)$ 控制写入强度，$\alpha_t = \exp(g_t)$ 且 $g_t = -\exp(A_{\log})\,\mathrm{softplus}(W_a x_t + b_{dt})$ 控制遗忘速度。因为 $\exp(A_{\log})>0$ 且 $\mathrm{softplus}>0$，$g_t$ 恒为负，故 $\alpha_t \in (0,1)$ 必然是衰减。本机实测 $g_t$ 落在 $[-63.34, -0.15]$，衰减强度跨三个数量级。
  • 48 个值头、16 个键头，比值 3，源码用 repeat_interleave 把查询与键各复制 3 份对齐到 48 头。查询与键在进入递归前做 L2 归一化，这使 $S_{t-1}^{\top}k_t$ 的量级可控。
  • 两条计算路径等价：prefill 走分块并行、decode 走逐 token 递归。本机在真实头数与头维（48/16 头、128 维、160 个 token）下实测，两者输出最大绝对差 $1.36\times10^{-7}$、末态差 $4.02\times10^{-7}$，确认是同一函数的两种实现。
  • 易被忽略的状态：GDN 前置一个 kernel 为 4 的深度可分离因果卷积。逐 token decode 时必须跨步保留 $\text{kernel}-1=3$ 个位置的通道状态，否则前 3 个历史位置被当作 0。本机对照实测：不保留状态时与 prefill 的最大差为 $8.45\times10^{-1}$，正确维护滑窗后降到 $1.49\times10^{-8}$。

QSA（Qwen Sparse Attention，12 层）

  • 索引器与主注意力分离：索引器有自己的 128 维查询与键，由 index_qk_proj 一次投影出 $(4+1)\times128=640$ 维再切分，与主注意力的 256 维头完全独立。源码强制 indexer_kv_heads=1，即全部 4 个索引查询头共享同一份键。
  • 块压缩是均值池化：每 4 个连续 token 的索引键取算术平均得到一个块表示，再做 RMS 归一化与 RoPE，位置取该块首个 token 的位置。这与 DeepSeek-V4 用数据相关权重加权求和的压缩不同，此处是无参数的固定池化。
  • 块得分先 ReLU 再按头求和：$s_b = \frac{1}{\sqrt{128}}\sum_{h=1}^{4}\mathrm{ReLU}\!\left(q_h \cdot \bar{k}_b\right)$，注意不是 softmax。ReLU 的作用是让单个头的负相关无法抵消其他头的正相关。本机实测：同一输入下 ReLU 求和与直接求和选出的 top-512 块仅重叠 427 个（83.4%），确认这一处非线性实质影响选择结果。
  • 选择粒度是块、代价是有损：取 block_topk $=2048/4=512$ 个块，展开为 2048 个 token；末尾不足 4 个的残块无条件全部保留。本机实测「块内 token 最大得分」与「池化键得分」的相关系数为 0.6449，两者 top-512 块重叠 375 个（73.2%），说明块粒度选择无法完全还原 token 粒度的重要性排序。
  • 可见范围随长度封顶：本机按真实 config 逐位置实测，可见 token 数在 2048 以内时等于因果可见范围（占比 100%），超过后被钉死。位置 4000 时可见 2049 个（51.21%）、位置 8000 时 2049 个（25.61%）、位置 11999 时 2048 个（17.07%）。上界为 $512\times4+3=2051$，与源码分配的张量宽度一致。
  • 输出侧带 sigmoid 门：q_proj 输出宽度是 $24\times256\times2=12288$，切成查询与门两半；注意力输出先乘 $\sigma(\text{gate})$ 再过 o_proj。真实权重 q_proj 形状 [12288, 2560] 印证了这个两倍宽度。
  • 部分 RoPE：partial_rotary_factor=0.25 使旋转只作用于 256 维头的前 64 维，后 192 维原样通过。本机实测前 64 维最大变化 1.7148、后 64 维（索引器头维内）变化恒为 0，且旋转严格保范数（8.370453 到 8.370454）。源码另有约束 $\text{rotary\_dim} \le \text{indexer\_head\_dim}$，即 $64 \le 128$。

Gated Residual（四条并行残差流）

  • 读出：先对 10240 宽的残差做分组 RMS 归一化（每 2560 一组，共 4 组），再经 $10240 \to 320 \to 10240$ 的低秩瓶颈算出每条流每一维的 sigmoid 门，加权后沿流维求均值得到 2560 宽的子层输入。公式为 $\tilde{x} = \frac{1}{4}\sum_{i=1}^{4} \sigma\!\big(W_{up}\,\mathrm{silu}(W_{down}\hat{x}/4)\big)_i \odot \hat{x}_i$，其中 $\hat{x}$ 是归一化后的四条流。
  • 写回：子层输出 $y$（2560 宽）按每条流一个标量放大后加回原四条流：$x_i \leftarrow x_i + \lambda_i y$，其中 $\lambda_i = 2\sigma(W_{inj}\hat{x}/4)_i$。取值范围为 $(0,2)$，且 $W_{inj}$ 零初始化时 $\lambda_i$ 恰为 1，退化成标准恒等残差——本机实测四条流的 $\lambda$ 全为 1.0 验证了这一点。
  • 四条流何时开始分化：入口是纯复制，本机实测第 0 条与第 3 条流完全相同。第一次写回后因 $\lambda_i$ 不同而分化，实测四条流的增量 L2 范数为 51.88 / 52.68 / 52.06 / 49.72，从此各自演化。
  • 末端收束不带注入：hyper_connection_mixer 构造时 use_combine=False，因此没有 block_inject_weight。真实权重印证：该模块只有 hc_norm、input_mix_weight_down、input_mix_weight_up 三个张量，比层内版本少 $4\times4\times2560=40960$ 个参数。
  • 代价：每层两组共 13,209,600 参数，48 层加末端 mixer 合计 640,624,640，占总参数 0.36%。该数字与按张量头分组累加的结果精确相等。

N-gram Embedding（51.2B 哈希查表）

  • 只在一层出现：ple_layer_ids=[2]（1 起），即 0 起的第 1 层。源码另有校验要求该层必须是 GDN 层。真实权重中仅第 1 层含 ple.*，全模型只有这一处。
  • 16 个头，每个头一张独立的质数大小词表：头数为 $(\text{ngram\_size}-1)\times\text{heads\_per\_ngram} = (3-1)\times8 = 16$，前 8 个头处理 bigram、后 8 个处理 trigram。第 $i$ 个头的词表大小是 20,000,000 之后的第 $i+1$ 个质数，依次为 20000003、20000023、20000033、…、20000171。这 16 个数值以 I64 缓冲存在 checkpoint 里，已逐元素核对与源码派生完全一致。
  • 表尺寸完全可复现：16 个质数之和为 320,001,446，按 make_ngram_vocab_size_divisible_by=128 向上对齐得 320,001,536（补 90 行）。真实权重 128 个分片的行数之和恰为 320,001,536，每行 160 维，故表参数量 $320001536 \times 160 = 51{,}200{,}245{,}760$，与张量头累加结果精确相等。用质数作模数是为了让不同头的哈希碰撞模式尽量独立。checkpoint 中的 ngram_heads_offsets 也已核对为这 16 个质数的前缀和。
  • 是哈希而非精确查表：n-gram 的 id 由各位置 token 乘上不同乘子后逐位异或，再对该头的质数取模、加上该头的偏移得到。乘子的派生规则是 $c_j = 2\big(\mathrm{splitmix64}(s_0 + \gamma(j{+}1)) \bmod B\big) + 1$，其中 $s_0 = \text{seed} + 10007\,\ell$、$\gamma$ 为 splitmix64 的黄金比常数、$B = \lfloor\lfloor(2^{63}-1)/V\rfloor/2\rfloor$ 且 $V$ 为词表大小。本机核对 checkpoint 中三个真实乘子（23703573157769、20109073645365、8052911324071）与该公式逐元素一致，并由此确认 config 未显式给出的 seed 即默认值 1234。
  • 乘子的两个设计约束：$2k+1$ 的形式使乘子恒为奇数，因而与 $2^{64}$ 互质、在模 $2^{64}$ 下可逆，不会把不同 token 压到同一乘积；$B$ 的定义则保证 $\text{token\_id} \times c_j$ 不溢出 int64（本机对三个真实乘子逐一验证通过）。本机用真实乘子重算 2000 个位置的 n-gram id，全部落在各自头的 $[\text{offset}, \text{offset}+\text{size})$ 区间内，bigram 与 trigram 头碰撞率均为 0.000%；换 4000 个位置时 bigram 头碰撞率 0.025%。
  • 门控注入：查表得到的 2560 维特征投影出「每条残差流一个键」与「四条流共享的一个值」，键与归一化后的残差流做内积得到门控标量 $g$，再经 $\mathrm{sign}(g)\sqrt{|g|}$ 变换后取 sigmoid。开方压缩大值、放大小值，而 sign 保证不改变正负——本机实测变换前后符号完全一致。
  • 空洞卷积补局部上下文：kernel 4、dilation 等于 ngram_size=3，逐通道作用于 10240 维，感受野覆盖相对位置 $\{-9,-6,-3,0\}$，需保留 $(4-1)\times3=9$ 个位置的状态。
  • 表不参与矩阵乘：每 token 只从 16 个头各取 1 行 160 维，合 2560 个元素（恰等于 ple_embed_dim），bf16 下 5.00 KiB。相对 51.2B 的表体积，单 token 触达比例为 $5\times10^{-6}\%$。config 的并行方案把该表标为 colwise_gather_output，注释说明其体积约 90 GiB，需要单独切分。

MoE 路由

  • 先全局 softmax 再对选中项重归一化：在全部 512 个专家上做 softmax，取 top-10，再把这 10 个概率除以它们的和。本机实测 token 0 的 top-10 原始概率和仅 0.152946，重归一化后为 1.000000。含义是各专家的相对权重来自全局竞争，但最终系数之和恒为 1。
  • 共享专家恒激活且带标量门：共享专家不参与路由，输出乘一个逐 token 的 sigmoid 标量 $\sigma(W_g x)$ 后与路由结果相加。真实权重 shared_expert_gate 形状 [1, 2560]，即每 token 只产生一个标量。
  • 激活比例：单层全量 2,522,810,880 参数，激活 55,380,480，占 2.195%——约等于 $10/512=1.95\%$ 再加上共享专家与路由器。48 层路由专家合计 120,795,955,200，与张量头累加结果精确相等。

两个机制各自贡献不同：层型比例让只有 12/48 层需要存 KV，若 48 层全为 QSA 型，1M 上下文下 KV 将达 96 GiB，实际 24 GiB 即降为 1/4；块选择不减少缓存但限制计算，每个查询实际参与注意力的 token 数被钉死在 2048 上下，与序列长度脱钩。GDN 侧的状态为每层 3.00 MiB 递归状态（fp32，由 mamba_ssm_dtype 指定）加 60.00 KiB 卷积状态，36 层合计 0.108 GiB 且完全不随长度增长。

需要注意 2048 这个预算是 config 的默认取值，块选择只在完整块数超过 512 时才实际生效；上下文短于约 2048 时每个查询仍能看到全部因果可见 token。

4. 视觉编码器与多模态融合

视觉侧是一个 27 层的独立 ViT，参数量 448,931,056（0.449B），只占全模型 0.249%。它的作用是把像素变成与语言主干同宽的 token，之后视觉与文本在同一序列里共享全部 48 层——不存在贯穿深度的独立视觉分支。下面的「视觉编码器」与「多模态融合」两个视图给出完整路径。

4.1 从像素到 patch：一次 3D 卷积

patch_embed 是一个 Conv3d，kernel 与 stride 都等于 $(\text{temporal\_patch\_size}, \text{patch\_size}, \text{patch\_size}) = (2, 16, 16)$。因为二者相等，每个时空 patch 被独立映射、互不重叠，等价于对展平后的 $3\times2\times16\times16 = 1536$ 维向量做一次 $1536 \to 1152$ 的线性变换。真实权重 patch_embed.proj.weight 形状 $[1152, 3, 2, 16, 16]$，元素数 1,769,472 恰等于 $1152 \times 1536$。静态图像沿时间维复制到 2 帧以匹配 temporal_patch_size；视频则每 2 帧合成一个时间 patch。

4.2 位置信息：可学习方格重采样 + 二维 RoPE

视觉侧同时用了两套位置信息，职责不同。

  • 可学习位置嵌入：num_position_embeddings=2304 即一张 $48\times48$ 的方格，每格一个 1152 维向量。对每张图按其实际网格 $(\text{grid\_h}, \text{grid\_w})$ 做双线性重采样（align_corners=True），再与 patch 特征逐元素相加。本机实测 $48\times48 \to 8\times12$ 的重采样输出形状为 $(96, 1152)$，与 patch 数一致。这个设计的意义是位置信息跟随图像真实长宽比，不需要把输入 resize 成固定尺寸。
  • 二维 RoPE：Qwen4ExpVisionRotaryEmbedding 的维度参数是 $\text{head\_dim}/2 = 72/2 = 36$，频率数 18。每个 patch 带一对 $(h, w)$ 坐标，外积展平后得 $2 \times 18 = 36$ 维，再与自身拼接成 72 维，恰好覆盖完整头维。本机实测旋转严格保范数（331.130646 到 331.130829）。这与语言塔的 partial_rotary_factor=0.25 只旋转 1/4 头维形成对照：视觉侧转满，语言侧留 3/4 不转。

4.3 27 层 block：与语言塔的四处差别

视觉 block 是标准 pre-norm 结构：$x \leftarrow x + \mathrm{Attn}(\mathrm{LN}(x))$，$x \leftarrow x + \mathrm{MLP}(\mathrm{LN}(x))$。相对语言主干有四处明显不同，都可由真实权重直接印证。

4.4 merger：2×2 空间合并并对齐语言主干宽度

PatchMerger 把空间上 $2\times2$ 相邻的 4 个 patch 拼成 $1152\times4 = 4608$ 维，经 $4608 \to 4608 \to 2560$ 两层投影输出。因为 use_postshuffle_norm=False，LayerNorm 作用在合并前的 1152 维上，之后才 reshape 成 4608。输出宽度 2560 与语言主干 hidden_size 相等，这是两侧能直接拼接的前提。

4.5 融合：替换占位符而非拼接

融合用 inputs_embeds.masked_scatter(image_mask, image_embeds)，即把序列中 image_token_id=248056（视频为 248057）的占位符位置原地替换成视觉特征，序列长度不变。因此视觉 token 数必须与占位符数严格相等，这个对应关系由 processor 在构造 prompt 时保证。本机构造 4 个占位符的小例子实测：替换后占位符位置为视觉特征、其余位置保持原文本 embedding，序列形状不变。

另有 vision_start_token_id=248053 与 vision_end_token_id=248054 作为视觉块的边界标记，它们是普通文本 token，不被替换。

4.6 视觉 token 在语言侧只推进少量位置

这是容易被忽略的一点。语言塔用三维 MRoPE，文本段的三个维度取同一个 arange；视觉段则由 get_vision_position_ids 生成 $(T, H, W)$ 三元组，$H$ 与 $W$ 各自在 $[\text{start}, \text{start}+\text{llm\_grid}-1]$ 内遍历。关键在于图像块结束后位置只推进 $\max(h, w) / \text{spatial\_merge\_size}$，而不是推进视觉 token 数。

图像 grid视觉 token 数位置轴推进量比值

本机实测一个 $(1,28,28)$ 的图接在 8 个文本 token 之后：196 个视觉 token 的 $T$ 维恒为 8，$H$ 与 $W$ 在 $[8, 21]$ 内遍历，后续文本从位置 22 开始而非 204。含义是一张大图会消耗序列长度（即上下文预算），但在位置编码轴上前进很少，因此 max_position_embeddings=262144 约束的是位置轴上限而非 token 数上限。

4.7 语言塔 MRoPE 的交错排布

语言塔只有 64 维参与旋转（$256 \times 0.25$），对应 32 个频率槽位，需要被 $T/H/W$ 三个维度分摊。mrope_section=[11,11,10] 之和恰为 32。mrope_interleaved=true 时的分配方式是：以 $T$ 维为底，再把 $H$ 覆盖到 slice(1, 33, 3)、$W$ 覆盖到 slice(2, 30, 3)。本机实测得到的槽位归属为：

槽位  0..15 : T H W T H W T H W T H W T H W T
槽位 16..31 : H W T H W T H W T H W T H W T H

各维占用 $T=11$、$H=11$、$W=10$，与 mrope_section 逐项对应。三个维度在全部 32 个槽位上交错分布而非各占一段，这样每个维度都覆盖从低频到高频的完整范围（低频对应长程距离、高频对应近距离）。$W$ 比 $T$ 和 $H$ 少一个槽位，是因为 32 不能被 3 整除。这与 chunked 排布 $[TT\ldots HH\ldots WW\ldots]$ 的差别正是源码 apply_interleaved_mrope 文档字符串所描述的。

5. 核对方式

本页的数字分三类来源，各自的取得方式如下。

结构与维度：用 HTTP Range 请求读取全部 131 个 safetensors 分片的 JSON 文件头（合计 228,712 字节，未下载权重本体），得到 1658 个张量的名称、形状与 dtype。以此交叉验证源码推导：config 声明的层型分布、索引器所在层、N-gram 分片数、超连接模块构成、视觉塔各模块形状均与张量清单逐项吻合。另有 32 项从 config 推导到张量形状的断言全部通过，覆盖 GDN 的 conv_dim 组成、QSA 的两倍宽 q_proj、索引器投影宽度、超连接低秩维度、N-gram 每头维度等；视觉侧另有 14 项独立断言。

公式与数值行为：按官方 modeling_qwen4_exp.py 逐行语义复现各算子，用官方 config 的真实头数与头维在随机张量上实跑。这类验证不需要真实权重——待验证的是计算规则本身，而非某组特定参数下的输出。已完成的对照包括：GDN 分块与递归两条路径的等价性、delta rule 状态更新的小规模手算复核（2 token 正交键，手算末态与实跑差 $3.34\times10^{-6}$）、索引器块选择的逐位置可见数、ReLU 求和与直接求和的选择差异、池化的信息损失、部分 RoPE 的作用范围与保范性、超连接门控取值范围、N-gram 质数表尺寸与碰撞率、路由归一化行为、视觉侧的 patch 投影等价性与位置重采样、视觉 RoPE 的维度构成与保范性、MRoPE 交错槽位归属、视觉 token 计数与位置推进量、masked_scatter 融合行为。

checkpoint 中的缓冲数值：N-gram 的三个 I64 缓冲（layer_multipliers、ngram_heads_vocab_sizes、ngram_heads_offsets，共 35 个 int64）按 data_offsets 用 Range 请求精确下载了 280 字节，与源码派生结果逐元素比对，全部一致。这同时确认了 config 未显式给出的 seed=1234。

端到端数据流：构造一个保留全部结构特征的等比缩小模型（8 层，层型为 GDN、GDN、GDN、QSA 重复两轮，第 1 层带 N-gram 注入，隐藏维 64，4 条残差流，8 专家 top-2 加共享专家），跑通整段 prefill 与逐 token decode。逐层形状记录确认残差流全程 256 宽（即 $4\times64$）、子层内部 64 宽、GDN 缓存为常数形状而 QSA 的 KV 随长度增长。两种模式的 logits 最大绝对差为 $5.36\times10^{-7}$。

两处值得记录的排查过程。其一，缩小模型最初实现时 prefill 与 decode 相差 $4.38\times10^{-1}$；逐项排除后定位到 GDN 前置深度卷积在 decode 时未保留跨步状态，单独写对照脚本确认「每步独立卷积」误差 $8.45\times10^{-1}$、「维护 kernel-1 滑窗」误差 $1.49\times10^{-8}$，修正后复验通过，这也纠正了缓存体积的初次估算（卷积状态需 $\text{kernel}-1=3$ 个位置而非 4 个）。其二，N-gram 乘子的派生公式最初按常见写法推测为 splitmix64(seed + 10007*layer + pos) % vocab_size，与 checkpoint 真实值（23703573157769）差了几个数量级；回读源码 _build_layer_multipliers 才发现三处都不同：splitmix64 的输入是 $s_0 + \gamma(j{+}1)$ 而非 $s_0 + j$、模数是 $\lfloor\lfloor(2^{63}-1)/V\rfloor/2\rfloor$ 而非 $V$、且结果被强制为奇数。这说明凡涉及具体数值的公式都必须与 checkpoint 实值对撞，仅凭源码阅读印象容易出错。

实测脚本与一次性跑完全部脚本的原始输出（1058 行）存于 research/ 目录：read_headers.py 读张量头，verify_structure.py 做结构交叉验证，count_params.py 核算参数量，assert_dims.py 做 config 到张量形状的断言，probe1~probe6 为各机制的数值验证，probe7_ngram_buffers.py 核对 checkpoint 缓冲真值，probe8_vision.py 覆盖视觉塔与 MRoPE，render_check.py 做页面渲染实测，measured-output.txt 为原始输出。
