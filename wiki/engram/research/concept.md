# Engram

- 描述：Engram 是插在 Transformer 少数几层前的一个记忆模块，把每个位置结尾的 n-gram 折叠成规范 id 后用哈希映射成一张静态嵌入表的行号，取回的向量按当前隐状态算出的标量门调制后写回残差流；它与 MoE 的条件计算并列，构成另一条稀疏轴。
- 摘要：MoE 用条件计算稀疏地激活参数，Engram 用条件记忆稀疏地查表取回静态嵌入。它把位置 $t$ 结尾的 $n$ 元 n-gram 折叠成规范 id，用 $K$ 个哈希头映射到素数大小的桶取回向量拼成 $\mathbf{e}_t$，再用当前隐状态 $\mathbf{h}_t$ 与记忆投影出的键做归一化点积、过 $\sigma$ 函数得到标量门 $\alpha_t=\sigma\!\left(\frac{\mathrm{RMSNorm}(\mathbf{h}_t)^{\top}\mathrm{RMSNorm}(\mathbf{k}_t)}{\sqrt{d}}\right)$，调制后的值写回残差流。每 token 取回的行数是常数，表变大不增加每 token 浮点运算量。

## 范围

- 讲：条件记忆与条件计算的分工，以及为什么值得把查表单列成一条轴。
- 讲：检索段——词表压缩、多头哈希与素数大小的桶，一个 n-gram 的行号怎么算出来。
- 讲：融合段——标量门、深度因果卷积、写回残差流，以及多分支主干上的改法。
- 讲：插入层怎么选、组件消融、稀疏预算在专家与记忆之间的分配律，以及表单独放大时的行为。
- 讲：论文报告的效果、机制分析与解释这些结果的实验设置。
- 讲：确定性寻址带来的预取与吞吐实测。
- 讲：DeepSeek-V4.1-Flash 里这个模块的落地配置，以及它与论文写法的差异。
- 不讲：MoE 路由、MLA、超连接、RMSNorm、深度卷积、残差连接等前置机制，各自链接到已有页面。
- 不讲：训练时表怎么分片、All-to-All 怎么通信的实现细节，只在说明确定性寻址的来源时交代一句。
- 不讲：PKM、PEER、RETRO、OverEncoding 等其它记忆方案的逐项对比，只在无限记忆档的对照里提一句。
- 不讲：论文的全部实验表格，只引用能说明结论的几项。
- 不讲：多模态路径的视觉编码与投影，只讲图像片段在 n-gram 和门控上被怎么处理。

## 概览

### 是什么

Engram 是插在 Transformer 少数几层前的一个记忆模块。它把每个位置结尾的局部上下文——最近两三个 token——折叠后用哈希映射成一张大表里的行号，取回几个向量，再用当前隐状态决定这些向量写回多少。表只被查、不参与每 token 的浮点运算。

### 解决什么问题

语言模型要同时做两件事。组合推理要一层层往前算；知识检索比如认出「Diana, Princess of Wales」是一个实体，本身并不需要推理。后一类是局部的、静态的、套话化的，但 Transformer 没有原生的查找原语，只能靠若干层注意力与前馈网络把它重新拼出来。Engram 给这一类工作配一条查表通路，让稀疏参数里的一部分不必用来做动态计算。

### 怎么起作用

每个位置分两段。检索段把原始 token id 按归一化后的文本等价折叠成更少的规范 id，再对每个 n-gram 阶、每个哈希头算一个行号，从素数大小的嵌入表里取回向量，拼成一个记忆向量。融合段用当前隐状态与记忆投影出的键做归一化点积、过 $\sigma$ 函数得到一个 $0$ 到 $1$ 的标量门，门控后的值再经一个短的因果卷积写回主干；主干之后照常做注意力与 MoE。

### 什么时候不成立

- 行号由输入 token 决定，与上下文无关，所以查到的是一份静态先验；它是否与当前语境相符，全靠那个标量门自己判断，门判错时噪声会直接进入残差流。
- 门控需要一份已经聚合了上下文的隐状态，插得太靠前的层拿不到它；插得太靠后又错过了接手局部模式重建的时机，两者只能折中。
- 表越大参数越多，虽然每 token 浮点运算量不变，存储与带宽的代价仍在。把表放到主机内存能撑住容量，代价是取回要多走一跳。
- 论文的效果数字来自它自己的两组小规模实验与一次 27B 预训练，范围和规模都有限。

## 引言

一段文字里出现了「Diana, Princess of Wales」这个实体，它在序列里的最后一个 token 是「Wales」。模型要预测下一个词，得先知道这里说的是谁。论文转引的一项分析把每一层在这个位置上的隐状态解码回文字：第 1、2 层只得到「联合王国里的国家」，第 3 层是「欧洲的国家」，第 4、5 层拼出「威尔士王妃」这个头衔但还不具体，直到第 6 层才出现完整的实体「Diana, Princess of Wales」。同一段文字如果出现在别处，这套拼装还要再来一遍。

论文把这件事算成一次运行时的查表重建：命名实体和固定搭配是静态的局部模式，本来可以一次查表取回，现在却被拆成若干层的注意力和前馈运算。Engram 的做法是给模型补上这条查表通路，把稀疏参数中分给固定知识的那一部分从「参与计算」改成「被查询」。它由此与 [MoE](wiki/deepseek-moe) 形成分工：MoE 稀疏激活参数来做动态计算，Engram 稀疏查表来取回静态记忆。

## 核心问题

### 为什么语言模型需要一条查表的稀疏轴？

解答：语言建模里相当一部分工作是在运行时重建静态查找表，而 Transformer 没有原生的查找原语

命名实体、固定搭配这类局部模式是静态的，用经典 [n-gram](wiki/ngram) 就能捕捉；但标准 Transformer 只能靠若干层注意力和前馈网络把它们重新拼出来，等于把本该留给高层推理的串行深度花在琐碎操作上。论文主张把「稀疏查表取回固定知识」做成与「稀疏激活参数做动态计算」并列的一条轴。完整说明见「语言模型把深度花在重建一张静态查找表上」一章。

### 一个位置的 n-gram 怎么变成表里的行号？

解答：先把 token id 按规范化后的文本折叠，再用多头乘法异或哈希对素数大小的桶取模

原始 token id 先经一个映射 $\mathcal{P}$ 折叠：规范化后文本相同的 token 合并成同一个规范 id，128k 的词表因此少了 23%。每个位置取结尾的 $n$ 元 n-gram，用「当前 token 乘一个乘子、逐个异或更早位置乘上乘子」得到一个整数，再对素数大小的桶取模得到行号；每个阶数配多个哈希头以分散碰撞。完整说明见「一个 n-gram 怎么变成表里的行号」一章。

### 查回来的静态向量，凭什么能融进当前的隐状态？

解答：用当前隐状态与记忆投影出的键算一个标量门，门控后再过一个短卷积写回

取回的向量与上下文无关，可能对不上当前语境。Engram 用已经聚合了上下文的当前隐状态作查询、用记忆投影出的向量作键，做归一化点积得到一个 $0$ 到 $1$ 的标量门；门接近 $0$ 时这份记忆被压掉。门控后的值再过一个核宽 4 的因果卷积扩大感受野，然后残差写回主干。完整说明见「取回的静态向量怎么被当前上下文接受」一章。

### 记忆插在哪一层，稀疏预算里该切多少给它？

解答：位置由早介入与门控精度的取舍定在浅层，预算由一条 U 型曲线定在 MoE 占多数

插得早能更早接手局部模式重建，但早期隐状态还没聚合足够上下文、门控不准；单模块扫描下来第 2 层最好，把同样的预算拆成两个模块放在第 2、6 层成绩更好。参数预算方面，把稀疏参数的约 20%–25% 从专家改分给记忆时验证损失最低，纯 MoE 与几乎全给记忆两端都更差。完整说明见「记忆插在哪一层，稀疏预算怎么分」一章。

### 这条轴换来了什么？

解答：同等参数与算力下各领域基准普遍更好，长上下文的检索提升明显，早期层被免去静态重建

Engram-27B 在 262B token、3.8B 激活参数下与同等参数同等算力的 MoE-27B 相比，MMLU 从 57.4 升到 60.4，BBH 从 50.9 升到 55.9，HumanEval 从 37.8 升到 40.8，长上下文的多查询大海捞针从 84.2 升到 97.0。机制上早期层被免去静态重建，逐层预测更早收敛。完整说明见「这条轴换来了什么」一章。

## 常见误解

- 「Engram 就是文档检索」——键是固定长度的 token n-gram，值是模型自己训练出来的嵌入，没有文档库，也没有语义相似度检索；哈希只决定查哪一行。
- 「表里存的是 n-gram 的出现频率」——存的是可学习向量，频率从未被统计过；哈希决定的只是行号。
- 「条件记忆和条件计算是一回事」——条件计算稀疏地激活参数来做动态运算，条件记忆稀疏地查表取回静态嵌入；论文的分配律正是说两者不能互相替代。
- 「哈希把每个 n-gram 都放进表里，所以不会撞」——直接参数化整个 n-gram 组合空间不可行，才改用哈希；哈希碰撞是这条路固有的，论文的对策是给每个阶数配多个头来分散它，并用门控筛掉取错的值，不是把碰撞消掉。
- 「Engram 只对知识题有用」——涨幅不限于知识类：BBH 加 5.0、ARC-Challenge 加 3.7、DROP 加 3.3，都高于 MMLU 的 3.0 与 MMLU-Pro 的 1.8；代码数学类里 HumanEval 加 3.0 与知识类相当，MBPP 加 1.6、GSM8K 加 2.2、MATH 加 2.4 则低于 MMLU 与 CMMLU 的涨幅。
- 「加了记忆模块，每 token 计算量会涨」——每 token 只取回常数条嵌入，槽位数从 $2.58\times10^5$ 加到 $1.0\times10^7$，每 token 浮点运算量不变。
- 「关掉 Engram 只是掉一点知识题分数」——完全抑制记忆输出后事实知识类只保住 29%–44%，阅读理解类仍保住 81%–93%，两类差得很远。

## 语言模型把深度花在重建一张静态查找表上

语言建模要处理的两类信号质地不同。组合推理要求深的、随上下文变化的计算；而文本里有相当一部分是局部的、静态的、高度套话化的，比如命名实体与固定搭配。经典 n-gram 模型在这类局部依赖上一直有效，说明这些规律本来就可以表示成代价很低的查表。

问题出在标准 Transformer 没有原生的查找原语。它只能靠计算去模拟检索。一个常见的多 token 实体不是一层就能认出来的，实体的内部表示要跨若干层注意力与前馈网络逐步拼装。论文转引的一项分析把「Diana, Princess of Wales」在这个位置上的隐状态逐层解码回文字：

| 层 | 隐状态解码出来的文字 | 原作者的解读 |
|---|---|---|
| 1–2 | 联合王国里的国家 | Wales |
| 3 | 欧洲的国家 | Wales |
| 4 | 女性君主或王后配偶持有的头衔 | 威尔士王妃（不具体） |
| 5 | 给予威尔士亲王（及其后的国王）妻子的头衔 | 威尔士王妃（不具体） |
| 6 | Diana, Princess of Wales (1961–1997)，查尔斯王子的第一任妻子，以美貌与人道工作闻名 | Diana, Princess of Wales |

表中第二列由 PatchScope（把某一层的隐状态解码成文本的工具）自动生成，第三列是转引这项分析的原文作者给出的判断。逐层的推进说明模型是在一层层搭这个表示，而不是一次取回。

论文把这件事概括为：模型在运行时重建一张静态查找表，把本该留给高层推理的串行深度花在琐碎操作上。由此提出的分工是两条稀疏轴——

- 条件计算：稀疏激活一部分参数来处理动态逻辑。这是 [MoE](wiki/deepseek-moe) 已经在做的事。
- 条件记忆：稀疏执行查找，取回固定知识的静态嵌入。

Engram 是后一条轴的一个具体实例。它的做法是把局部上下文的 n-gram 当作查表的键：上下文是局部的、有限的，因此键的空间虽然巨大却是确定的，可以用哈希把它压进一张固定大小的表。

## 一个 n-gram 怎么变成表里的行号

检索段要做两件事：把 token id 折叠成语义密度更高的规范 id，再把 n-gram 映射成表里的行号。两部分做完，一个位置就得到一串可查的行号。

### 词表压缩

标准子分词器的目标是可逆还原，因此会给语义等价的写法分配互不相干的 id：`Apple`、` apple`、`APPLE` 各占一行。对整个 n-gram 空间做哈希时，这种分裂会白白耗掉表容量。论文的做法是先算一个满射 $\mathcal{P}:V\to V'$，按规范化后的文本等价把原始 id 折叠成规范 id：

$$x'_{t}=\mathcal{P}(x_{t})$$

- $x_t$：位置 $t$ 的原始 token id。
- $x'_t$：折叠后的规范 id。
- $\mathcal{P}$：预先算好的满射；多个原始 id 可以映到同一个规范 id。
- $V$：原始词表；$V'$：折叠后的词表。

具体规则在官方实现里写成一条归一化序列：NFKC（一种把兼容字符折成标准写法的 Unicode 规范化形式）、NFD 分解、去掉重音、转小写、把连续空白折成一个空格、去掉首尾空白。中间有一个细节：先把「恰好一个空格」替换成一个私用区字符，等去完首尾空白再换回来，否则这个 token 会在去空白时变成空串，和别的 token 混成同一个键。含替换字符的残缺 UTF-8 字节 token 无法规范化，按原始 token 形式作键。

对 128k 的词表，论文说这一步把有效词表压掉 23%，附录写的整体压缩率是 23.43%。附录列出的合并榜里，排在前面的是把各种空白折成一个键，以及把各种带重音的 `a`、`o`、`e`、`i` 折回各自的基本字母。

压缩之后，位置 $t$ 的后缀 n-gram 定义为

$$g_{t,n}=(x'_{t-n+1},\dots,x'_{t})$$

- $n$：阶数，取 $2$ 到 $N$；$N$ 是最大阶数。
- $g_{t,n}$：以位置 $t$ 结尾、长度 $n$ 的规范 id 序列。

### 多头哈希与素数大小的桶

把所有可能的 n-gram 组合参数化是不可行的：组合数按词表大小的 $n$ 次方增长。Engram 改用哈希。为减轻碰撞，每个阶数 $n$ 配 $K$ 个哈希头，第 $k$ 个头把压缩后的上下文映到嵌入表 $\mathbf{E}_{n,k}$ 的一个行号：

$$z_{t,n,k}\triangleq\varphi_{n,k}(g_{t,n}),\qquad \mathbf{e}_{t,n,k}=\mathbf{E}_{n,k}[z_{t,n,k}]$$

- $\varphi_{n,k}$：第 $n$ 阶第 $k$ 个头的哈希函数。
- $z_{t,n,k}$：算出的行号，取值在 $0$ 到 $M_{n,k}-1$ 之间。
- $M_{n,k}$：表 $\mathbf{E}_{n,k}$ 的行数，取素数。
- $\mathbf{e}_{t,n,k}$：取回的那一行向量。

记忆向量由所有阶数、所有头取回的嵌入拼接而成：

$$\mathbf{e}_{t}\triangleq\mathop{\|}_{n=2}^{N}\mathop{\|}_{k=1}^{K}\mathbf{e}_{t,n,k}$$

- $\|$：向量拼接。
- $\mathbf{e}_t$：位置 $t$ 的记忆向量，长度是「阶数个数 $\times$ 头数 $\times$ 每头维度」。

$\varphi_{n,k}$ 在实现里是乘法异或哈希：当前 token 乘一个乘子，再逐个异或更早位置乘上各自乘子的结果，最后对桶大小取模。乘子每个 (层, 回看距离) 一份，由以层号导出的随机数发生器生成，取奇数。它的量级由「token id 乘上它不溢出 int64」定出：实现先算出一个采样上界「int64 最大值除以压缩词表大小再除以 2」，从这个范围里抽一个整数，再乘 2 加 1 得到乘子。压缩词表取 99092 时，采样上界约 $4.65\times10^{13}$，乘子最大约 $9.3\times10^{13}$。

每个 (阶数, 头) 组合各占一段自己的桶区间，段的长度是这个组合的素数。素数按顺序取，且在整个模型范围内不重复，因此各段互不重叠。取到的局部行号加上该段的偏移量，就得到这一层大表里的全局行号；一层里所有段首尾相接放进同一张表。

### 构造的例子：四个 token 的行号

取压缩后的 id 序列 $(7,3,9,5)$，最大阶数 3，于是要算 2 元和 3 元两种。乘子取 $(3,5,7)$，分别对应回看 0、1、2 个位置；2 元的两个头桶大小取 11 和 13，3 元的两个头取 17 和 19。越出序列开头的位置用填充 id 2 补。

```python
PAD = 2
MULT = (3, 5, 7)                       # 回看 0、1、2 个位置各一个乘子
BUCKETS = {2: (11, 13), 3: (17, 19)}   # 2 元与 3 元各两个头的桶大小（素数）
IDS = (7, 3, 9, 5)                     # 压缩后的 token id 序列，按时间顺序排列

def mix(t, order):
    value = 0
    for k in range(order):
        j = t - k
        token = IDS[j] if j >= 0 else PAD   # 越出序列开头就用填充 id
        product = token * MULT[k]
        value = product if k == 0 else value ^ product
    return value

for t in range(len(IDS)):
    v2, v3 = mix(t, 2), mix(t, 3)
    print(f"位置 {t}：2 元混合值 {v2} 行号 {[v2 % m for m in BUCKETS[2]]}"
          f"｜3 元混合值 {v3} 行号 {[v3 % m for m in BUCKETS[3]]}")
```

```text
位置 0：2 元混合值 31 行号 [9, 5]｜3 元混合值 17 行号 [0, 17]
位置 1：2 元混合值 42 行号 [9, 3]｜3 元混合值 36 行号 [2, 17]
位置 2：2 元混合值 20 行号 [9, 7]｜3 元混合值 37 行号 [3, 18]
位置 3：2 元混合值 34 行号 [1, 8]｜3 元混合值 55 行号 [4, 17]
```

以位置 3 为例。2 元只看位置 3 和它前一个位置：$5\times3=15$，$9\times5=45$，$15\oplus45=34$；对 11 取模得 1，对 13 取模得 8。3 元再异或 $3\times7=21$：$34\oplus21=55$；对 17 取模得 4，对 19 取模得 17。位置 0 没有更早的 token：算 2 元时缺一个回看位置，算 3 元时缺两个，都用填充 id 2 补上。

真实配置里的数字大得多，结构相同。DeepSeek-V4.1-Flash 的最大阶数是 4，8 个头，所以一层里每个位置有 $(4-1)\times8=24$ 个行号。桶大小的搜索起点是 16000000，每头取比它大的下一个未被用过的素数。每层 24 个素数恰好给出该层的总行数：第 2 层 384006168 行，第 15 层 384016682 行，比 $24\times16000000$ 分别多出 6168 行和 16682 行，多出的部分就是「取下一个素数」带来的。两层合计 768022850 行，每行 256 维，乘起来约 $1.97\times10^{11}$ 个参数，与仓库写明的 196B 相符。

## 取回的静态向量怎么被当前上下文接受

检索段取回的嵌入与上下文无关，是一份静态先验。这带来两个问题：它无法随语境调整，而且哈希碰撞与一词多义都会让它带上噪声。融合段要解决的就是「这份记忆此刻该不该用、用多少」。

### 标量门

Engram 借用了注意力的形式：当前隐状态 $\mathbf{h}_t$ 已经通过前面的注意力层聚合了全局上下文，用它作查询；取回的 $\mathbf{e}_t$ 投影出键与值：

$$\mathbf{k}_{t}=\mathbf{W}_{K}\mathbf{e}_{t},\qquad \mathbf{v}_{t}=\mathbf{W}_{V}\mathbf{e}_{t}$$

- $\mathbf{e}_t$：检索段拼出的记忆向量。
- $\mathbf{W}_K,\mathbf{W}_V$：可学习的投影矩阵。
- $\mathbf{k}_t$：键向量，用来和隐状态比对。
- $\mathbf{v}_t$：值向量，也就是被门控之后要写回主干的内容。

门是一个标量，由查询与键的归一化点积经过 $\sigma$ 函数得到：

$$\alpha_{t}=\sigma\!\left(\frac{\mathrm{RMSNorm}(\mathbf{h}_{t})^{\top}\mathrm{RMSNorm}(\mathbf{k}_{t})}{\sqrt{d}}\right)$$

- $\mathbf{h}_t$：位置 $t$ 的当前隐状态。
- $\mathrm{RMSNorm}$：[RMSNorm](wiki/rmsnorm)，在算点积之前分别对查询和键做一次，论文给的理由是保证梯度稳定。
- $d$：隐状态维度；除以 $\sqrt{d}$ 是[自注意力](wiki/standard-attention)里的那步缩放。
- $\sigma$：sigmoid 函数，把结果压进 $0$ 到 $1$。
- $\alpha_t$：标量门。

门控后的值是 $\tilde{\mathbf{v}}_t=\alpha_t\cdot\mathbf{v}_t$。这个门做的是一次对齐检查：取回的记忆和当前上下文矛盾时，点积变小，$\alpha_t$ 趋近 0，这份噪声被压下去；对得上时门才打开。要注意它不是开关：点积为 0 时 $\sigma(0)=0.5$，门只把这份值减半，并不关掉。

论文给的门是归一化点积过 $\sigma$ 函数的形式。两份官方实现在 $\sigma$ 之前都多一步：把点积取绝对值、开方，再带上原来的符号。这保留了「矛盾时压小」的方向，同时把幅度压得更平缓。

### 深度因果卷积

门控之后接一个短的深度因果卷积。论文给的理由是扩大感受野、增加非线性：

$$\mathbf{Y}=\mathrm{SiLU}\!\left(\mathrm{Conv1D}\!\left(\mathrm{RMSNorm}(\tilde{\mathbf{V}})\right)\right)+\tilde{\mathbf{V}}$$

- $\tilde{\mathbf{V}}$：整个序列上门控后的值，形状是「序列长度 $\times$ 维度」。
- $\mathrm{Conv1D}$：一维卷积，核宽 $w=4$，膨胀率为最大 n-gram 阶；[深度卷积](wiki/depthwise-conv)，每个通道只用自己那条通道的邻域，实现里没有逐点卷积那一步。
- $\mathrm{SiLU}$：一种平滑的激活函数。
- $\mathbf{Y}$：这一层的 Engram 输出。

因果指每个位置只看自己和更早的位置，不看后面。卷积参数初始化为零，因此训练刚开始时卷积那一路的输出为零，$\mathbf{Y}=\tilde{\mathbf{V}}$——卷积支路自己是恒等映射，但这份 $\tilde{\mathbf{V}}$ 仍然写回主干。

### 写回主干

Engram 通过[残差连接](wiki/residual-connection)写回主干：

$$\mathbf{H}^{(\ell)}\leftarrow\mathbf{H}^{(\ell)}+\mathbf{Y}$$

- $\mathbf{H}^{(\ell)}$：第 $\ell$ 层的隐状态。
- $\mathbf{Y}$：Engram 的输出。

写完才轮到这一层常规的注意力与前馈（在 MoE 模型里是 MoE 层）。Engram 不插在每一层。

### 多分支主干上的改法

论文的主干不是单路残差，而是把残差流加宽成 $M$ 条并行分支、用可学习的连接权重调制信息流的结构，也就是[超连接](wiki/hyper-connections)。把 Engram 接到这种主干上需要一处结构上的取舍：嵌入表与值投影矩阵在 $M$ 条分支间共享，键投影矩阵每条分支各一份。第 $m$ 条分支的门是

$$\alpha_{t}^{(m)}=\sigma\!\left(\frac{\mathrm{RMSNorm}(\mathbf{h}_{t}^{(m)})^{\top}\mathrm{RMSNorm}(\mathbf{W}_{K}^{(m)}\mathbf{e}_{t})}{\sqrt{d}}\right)$$

- $\mathbf{h}_t^{(m)}$：第 $m$ 条分支在位置 $t$ 的隐状态。
- $\mathbf{W}_K^{(m)}$：第 $m$ 条分支自己的键投影矩阵。
- $\alpha_t^{(m)}$：这一条分支上的标量门。

每条分支用自己的门去乘同一份共享的值向量：$\mathbf{u}_t^{(m)}=\alpha_t^{(m)}\cdot(\mathbf{W}_V\mathbf{e}_t)$。这样一份值投影加 $M$ 份键投影可以融合成一个稠密的 FP8 矩阵乘。论文默认用 $M=4$ 的流形约束超连接。

## 记忆插在哪一层，稀疏预算怎么分

Engram 不插在每一层，插在哪几层与稀疏参数怎么分，是两个分开定的问题。

### 插入层的取舍

消融用的主干是 12 层、3B 的 MoE 模型（0.56B 激活参数），训练 100B token，挂 1.6B 参数的记忆。参考配置用 2 元和 3 元两种 n-gram，插在第 2 层和第 6 层，验证损失 1.768，纯 MoE 基线是 1.808。

把 1.6B 预算集中到一个模块、逐个扫插入层，第 2 层成绩最好（1.770），越往深插越差。这个结果背后是一个取舍：

- 插得早，模块能更早接手局部模式的重建，不必等主干花掉深度去拼装它们。
- 插得晚，隐状态已经通过注意力聚合了足够的全局上下文，门控判断更准；对多分支主干来说，分支的表示也已经分化开，逐分支的门才有可调的对象。

第 2 层是这两条的交点：一轮注意力已经够给出一个可用的 $\mathbf{h}_t$，而位置又足够早，能顶替主干底层的局部聚合。同样的 1.6B 预算如果拆成两个较小的模块、分别放在第 2、6 层，成绩比单模块的最好值再好一点（1.768）——浅的那一个负责早介入，稍深的那一个提供更丰富的上下文门控。论文另外指出，分层放置还对系统有好处：它让存储层级用得更充分。

组件消融从参考配置出发逐个去掉设计。影响最大的是三项：多分支主干上的分支独立融合、上下文感知门控、词表压缩。去掉任何一项都带来最大的退化。深度卷积去掉只有轻微退化，属于可省的一项。固定 1.6B 预算下把容量分给 4 元 n-gram 略差，论文的猜测是它摊薄了更常见的 2 元、3 元模式，同时不排除表更大时高阶 n-gram 会变得有用。

论文的 27B 模型按这套结论把 Engram 插在第 2、15 层，最大 n-gram 阶为 3，8 个头，记忆维度 1280。

### 稀疏预算的 U 型分配律

论文把这个问题写成稀疏分配：总参数量与每 token 浮点运算量都固定，问稀疏参数该怎么切。三个量：

- $P_{\mathrm{tot}}$：总可训练参数量，不含词表嵌入与语言模型头。
- $P_{\mathrm{act}}$：每 token 激活的参数量，决定训练成本。
- $P_{\mathrm{sparse}}\triangleq P_{\mathrm{tot}}-P_{\mathrm{act}}$：不激活的参数，是那份「不花算力」的预算。

对 MoE，未被选中的专家计入 $P_{\mathrm{sparse}}$；对 Engram，每 token 只取回常数条嵌入，因此表变大只增加 $P_{\mathrm{tot}}$，不增加每 token 浮点运算量。分配比 $\rho$ 定义为稀疏预算中分给 MoE 专家的比例：

$$P_{\mathrm{MoE}}^{(\mathrm{sparse})}=\rho\,P_{\mathrm{sparse}},\qquad P_{\mathrm{Engram}}=(1-\rho)\,P_{\mathrm{sparse}}$$

- $\rho$：取值在 $0$ 到 $1$ 之间；$\rho=1$ 就是纯 MoE。
- $P_{\mathrm{MoE}}^{(\mathrm{sparse})}$：分给路由专家的参数。
- $P_{\mathrm{Engram}}$：分给记忆表的参数。

实验在两个算力档上跑，稀疏比都固定在 $P_{\mathrm{tot}}/P_{\mathrm{act}}\approx10$：

| 算力 | 总参数 | 激活参数 | 纯 MoE 基线的专家数 |
|---|---|---|---|
| $2\times10^{20}$ 浮点运算 | 约 5.7B | 568M | 106 |
| $6\times10^{20}$ 浮点运算 | 约 9.9B | 993M | 99 |

结果是一条 U 型曲线。两端都更差，中间有个最优：

- 纯 MoE（$\rho\to100\%$）缺少专管静态模式的记忆，只能靠深度和计算把它们重建出来。
- 几乎全给记忆（$\rho\to0\%$）丢掉了条件计算的能力，需要动态推理的任务变差；记忆替代不了计算。
- 最优落在把约 20%–25% 的稀疏预算改分给 Engram 的位置。9.9B 档上验证损失从 $\rho=100\%$ 的 1.7248 降到 $\rho\approx80\%$ 的 1.7109，差 0.0139。最优位置在两档都落在 $\rho\approx75\%$–$80\%$。

另一个方向的结果是：MoE 的分配压到 $\rho\approx40\%$ 时（5.7B 档剩 46 个专家、9.9B 档剩 43 个），Engram 模型仍与纯 MoE 基线相当——少掉一半多的专家，靠记忆补了回来。

论文在这一节写明的适用范围是「在所考察的尺度内」，两个档位、固定稀疏比是它的考察条件。

### 表单独放大时

既然表不进入每 token 浮点运算量，自然要问它单独放大时表现如何。实验固定一个 3B 主干（568M 激活参数）、训练 100B token，在上面挂 Engram 表，槽位数从 $2.58\times10^5$ 扫到 $1.0\times10^7$，最多加到约 13B 参数。验证损失随槽位数在对数坐标下线性下降，即一条幂律。这条曲线给出的是一个行为可预测的旋钮：加大表继续有收益，且不需要额外算力。

论文拿这个结果与 OverEncoding（把 n-gram 嵌入与词表嵌入求平均的做法）对照：后者也从更大的表获益，但同样的内存预算下 Engram 的扩展潜力大得多。论文同时说明，SCONE 等其它工作以推理为目标、带额外的模块与训练算力，与这里的等算力约束不可比，因此没有纳入对照。

论文 27B 规模的主实验就是从这条分配律出发做的：Engram-27B 由 MoE-27B 改来，把路由专家从 72 减到 55，腾出的参数放进 5.7B 的记忆模块，$\rho=74.3\%$，总参数量维持 26.7B。Engram-40B 保持同样的主干与算力预算，只把记忆扩到 18.5B 参数（总参数 39.5B）。

| RACE-High | 75.4 | 78.2 | +2.8 |
| C3 | 60.1 | 63.6 | +3.5 |
| HumanEval | 37.8 | 40.8 | +3.0 |
| GSM8K | 58.4 | 60.6 | +2.2 |
| MATH | 28.3 | 30.7 | +2.4 |

知识类基准上记忆容量带来提升是预期之内的。论文强调涨幅不限于此：BBH 加 5.0、ARC-Challenge 加 3.7、DROP 加 3.3，都高于 MMLU 的 3.0 与 MMLU-Pro 的 1.8；代码数学类里 HumanEval 加 3.0 与知识类相当，MBPP 加 1.6、GSM8K 加 2.2、MATH 加 2.4 则低于 MMLU 与 CMMLU 的涨幅。语言建模损失也同步下降：Pile 测试集损失从 MoE-27B 的 1.960 降到 Engram-27B 的 1.950，验证损失从 1.634 降到 1.622。论文摘要与 §1 把 MMLU 的涨幅写成 +3.4，§4.2 与 Table 1 都是 +3.0，表中按后者。

Engram-40B 把记忆扩到 18.5B 参数后训练损失继续下降，多数基准也更好，但并非每一项都超过 Engram-27B：HumanEval 从 40.8 退到 38.4，MBPP 从 48.2 退到 46.2，C3 从 63.6 退到 61.8，MATH 从 30.7 微降到 30.6，而 GSM8K 从 60.6 升到 62.6。论文把这一点归因于欠训练：训练末段 Engram-40B 与基线的损失差仍在扩大，说明扩大的记忆容量在当前 token 预算内还没饱和。

### 长上下文

长上下文扩展沿用 DeepSeek-V3 的做法，在预训练之后用 YaRN（一种扩展上下文窗口的方法）做 32768 token 的上下文训练 5000 步、30B token，YaRN 的四个参数取 scale $s=10$、$\alpha=1$、$\beta=32$、缩放因子 $f=0.707$。评估用两个套件：LongPPL（长书本、论文、代码、长思维链上的困惑度）与 RULER（大海捞针、变量追踪等八类）。

比较分两种控制方式。对齐预训练损失时（Engram-27B 的第 46k 步与训练充分的 MoE-27B 第 50k 步损失相同），多查询大海捞针 97.0 对 84.2，变量追踪 87.2 对 77.0。同等算力档（都是 50k 步）下 Engram-27B 的 LongPPL 四项都领先，比如书本上的困惑度 4.14 对 4.38；RULER 里多查询大海捞针 97.0 对 84.2、频繁词提取 99.3 对 73.0、问答 40.5 对 34.5 都更高，只有单针大海捞针一项略低，99.3 对 100.0。更极端的情况下，只用 82% 预训练算力的 Engram-27B（41k 步）在 LongPPL 上与训练充分的基线基本持平——论文 2.92 对 2.91、代码 2.50 对 2.49、长思维链 14.26 对 14.16 三项略高，书本 4.37 对 4.38 反而更低；在 RULER 上八类里有六类更高（多查询大海捞针 89.5 对 84.2、变量追踪 83.2 对 77.0、频繁词提取 99.6 对 73.0、问答 44.0 对 34.5），单针大海捞针与常见词提取两项略低（99.6 对 100.0、3.8 对 4.5）。

论文的解释是：局部依赖被交给查表之后，注意力容量可以腾出来处理全局上下文。这是对结果的解释，不是被单独验证的因果结论。

### 早期层被免掉了什么

论文用两个可解释性工具检查「Engram 是不是等效于加深了网络」。

LogitLens：把每一层的隐状态直接接上最后的语言模型头，得到该层的预测分布，再算它与模型最终输出分布的 KL 散度。这个量衡量一层表示离「可以直接拿来预测」有多远。Engram 两条曲线在早期层都明显低于 MoE 基线，说明特征拼装完成得更快。

CKA（中心化核对齐）：用线性核的 Gram 矩阵比较两层表示的相似度结构，得到一个相似度矩阵。论文在矩阵上定义一个软对齐指数 $a_j$——把与 Engram 第 $j$ 层最相似的前 $k=5$ 个 MoE 层按相似度加权求重心：

$$a_{j}=\frac{\sum_{i\in\mathcal{I}_{j}}S_{i,j}\cdot i}{\sum_{i\in\mathcal{I}_{j}}S_{i,j}},\qquad \mathcal{I}_{j}=\mathop{\mathrm{argtop}k}_{i}(S_{i,j})$$

- $S_{i,j}$：MoE 第 $i$ 层与 Engram 第 $j$ 层的相似度。
- $\mathcal{I}_j$：与第 $j$ 层最相似的前 $k$ 个 MoE 层的下标集合。
- $a_j$：第 $j$ 层对应的「有效 MoE 深度」。

结果是对角线整体上移，$a_j>j$ 在很宽的层范围内成立：Engram-27B 第 5 层形成的表示，最接近 MoE 基线的第 12 层左右。论文据此认为，绕开早期特征拼装之后，Engram 等效于增加了模型的有效深度。

### 哪些能力依赖这份记忆

把记忆的输出在推理时完全抑制掉、主干不动，可以看出各项能力对它的依赖程度。这个设置本身会造成训练与推理不一致，论文因此只分析信噪比最高的两端：

- 事实知识类只保住 29%–44%，TriviaQA 掉到 29%。
- 阅读理解类保住 81%–93%，C3 保住 93%。

这条分界线与设计意图一致：定位在上下文里的问题主要靠注意力，靠记忆的是那些知识本身。

论文还画出了 27B 模型上的门控值热力图。激活集中出现在多 token 命名实体（Alexander the Great、the Milky Way）与固定搭配（By the way、Princess of Wales）上，中文例子里有「四大发明」「张仲景」。由于 Engram 处理的是以当前 token 结尾的后缀 n-gram，某个 token 上门控值高，意味着以它结尾的那个片段被当成静态模式取了出来。模型在每个 token 上共算出 8 个门（4 条分支 $\times$ 2 层），论文说明并非每条分支都能读出这类模式，图里选的是与语义模式匹配最相关的那几条。

## 行号提前算得出来，系统拿它做了什么

MoE 的路由依赖运行时的隐状态，选哪些专家要等算出来才知道。Engram 的行号只由输入 token 决定，在对应的层执行之前就已经全部算好。这个确定性带来两条工程上的后果。

训练时，表本身按模型并行分片到各设备，前向用 All-to-All（一种在设备间全交换数据的集合通信原语）收集被激活的行，反向把梯度分发回去，总容量随加速器数量线性增长。

推理时，既然行号提前已知，系统可以先把嵌入从容量充裕的主机内存异步取回，用前一层的计算掩盖这次传输。表放在越深的层，可用的计算窗口越长；但建模效果偏好早介入，两边的要求相反，位置只能折中。容量还能再往下分一层：自然语言的 n-gram 服从 Zipf 分布，少数模式占掉绝大部分访问，因此可以把常查的嵌入放在 HBM（显卡上的高带宽显存）、次常查的放在主机内存、长尾放在固态硬盘上。

论文在一个基于 nano-vLLM 写的推理原型上量了代价：H800、512 条序列、长度在 100 到 1024 之间均匀分布，把一张 100B 参数的表整个放在主机内存里，插在第二个 Transformer 块，预取与第一个块的计算重叠：

| 主干 | 基线吞吐（token/s） | 加 100B Engram 后 | 变化 |
|---|---|---|---|
| 4B 稠密 | 9031.62 | 8858.28 | 约 −1.9% |
| 8B 稠密 | 6315.52 | 6140.02 | 约 −2.8% |

每步的通信量与被激活的槽位数成正比，而不是与表的总大小成正比——这张表有 100B 参数，每个位置取回的仍是常数条。论文同时说明这是一份保守的下界：实验强制所有取回都走 PCIe，没有用上按频率分层的缓存。

## 真实模型里的 Engram：DeepSeek-V4.1-Flash

论文之外，DeepSeek-V4.1-Flash 的模型仓库里带了这个模块的一份可读实现，可以看出它在真实模型里的样子。这个模型是 552B 主干参数的多模态 MoE，40 层由 20 层因果编码器接 20 层解码器组成，支持最长 100 万 token 的上下文；仓库写明它的 Engram 条件记忆是 196B 参数，按 token 查表稀疏访问。

配置上，Engram 插在第 2 层和第 15 层（配置字段 `engram_layer_ids` 写的是 `[1, 14]`，仓库的层号从 0 开始计数）；最大 n-gram 阶是 4，8 个头，每头 256 维；桶大小的搜索起点是 16000000，压缩后的词表是 99092，用实现里的两个数算，$1-99092/129280\approx23.35\%$，与论文报告的 23.43% 相差不到 0.1 个百分点；表的行数由配置直接给出，第 2 层 384006168 行，第 15 层 384016682 行。

几处与论文式的差异：

- 没有深度卷积，门控后的值直接与门相乘、加回输入。
- 表以 fp8 e4m3 存储并带分块缩放因子，查表时反量化到 bfloat16；行按 rank 分片，多卡时对查得的值做一次 all_reduce 求和。这是把「容量与算力分离」落到张量布局上的做法。
- 键与值由一个共享的线性层一次算出再切开，查询与键各按最后一个维度做一次归一化（两组可学习权重的乘积），点积按官方实现的形式处理（取绝对值、开方、带符号、过 $\sigma$ 函数）。归一化是逐 (token, 分支) 做的，不在分支之间联合。
- 图像片段不参与 n-gram，也不得到 Engram 的贡献，门在这些位置被置零。压缩后的 id 缓存跨 prefill 与 decode 两个阶段保存，因此解码时不必回看历史 token。
- 压缩词表大小对不上训练时的值时，实现在构造阶段直接断言失败；每个哈希乘子都由这个大小导出，对不上会让整张表被重新哈希。

## 什么时候不成立

- 门控是唯一一道闸门。取回的记忆与当前上下文是否相符，全交给那个标量门判断；门判错时噪声直接进入残差流。论文给的对策是让门在矛盾时趋近 0，这是缓解，不是保证。
- 位置只能折中。早插错过门控可用的上下文，晚插错过接手局部重建的时机。消融给出的最优层（第 2 层）来自 12 层 3B 主干上的扫描，换模型规模要重新扫。
- 容量换来的不是免费参数。每 token 浮点运算量确实不随表增长，但存储与带宽的账还在：表要占显存或主机内存，取回时多走一跳。这套账成立的前提是有足够的计算窗口可以掩盖这次传输。
- 哈希碰撞被压低但没有消失。多个头分散了它，撞上时取回的是另一个上下文的嵌入，仍要靠门控筛掉。
- 论文的效果数字有其边界。分配律只在两种算力档、固定稀疏比的条件下考察，论文自己写明的稳定范围是「在所考察的尺度内」。门控可视化是从若干样本里挑出最可读的那几条分支，不是全量统计。
- 规模上还有没到位的地方。Engram-40B 扩大了记忆，但并非每项都超过 Engram-27B，论文归因于训练 token 不足，说明更大的表要配上更多的训练才能兑现。
