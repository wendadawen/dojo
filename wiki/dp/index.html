    Dynamic Programming

    正文 862 字 · 约 3 分钟阅读

    动态规划（DP）既是数学优化方法，也是算法设计方法。它把一个复杂问题递归拆成更简单的子问题，让每个子问题的结果由更小子问题的结果递推得到。

    1. 问题形式与价值函数

    在数学优化语境中，DP 通常把一个长期决策拆成一段时间上的决策步。第 $i$ 步的状态记作 $y$，每个状态的价值记作 $V_i(y)$；$i$ 是时间或阶段编号，$V_i$ 读作“从第 $i$ 阶段的状态 $y$ 开始能取得的值”。最后一个阶段的价值可以直接定义，前一个阶段的价值由后一个阶段的价值和当前收益合成。这样定义后，子问题不是“某一串具体决策”，而是“处在某个状态时余下问题的值”。

    2. Bellman 方程

    状态之间的关系写成 Bellman 方程。优化形式的通用形状是：目标取最大值时，

    阶段编号取 $1,\dots,n$，$n$ 是最后阶段。$$V_i(y) = \max_{a} \{ r_i(y,a) + V_{i+1}(y') \},$$

    其中 $a$ 是当前可选的动作，$r_i(y,a)$ 是在状态 $y$ 做动作 $a$ 的即时收益，$y'$ 是动作 $a$ 使系统进入的新状态。边界是不能再拆的子问题：$V_n(y)$ 是最后时间的价值，直接定义。求解按阶段逆序，先算 $V_n$，再算 $V_{n-1}$，最后 $V_1$ 在初始状态的值就是最优值；把每一步选过的动作记下来，可以从初始状态回溯出决策。

    DP 不只用于求最优值。它能不访问所有方案而计数：状态函数返回方案数，递归到更小子问题时把可行选择的方案数相加，并把结果存表复用。

    3. 自顶向下：记忆化

    自顶向下直接按递归式写函数，同一个状态第一次到达时才算，算完存入表。以后再遇到这个状态，先查表；表中有这个状态就返回，没有才算并把结果写入表。子问题重叠（递归会反复遇到同一批子问题）时，同一状态对应的递归分支收敛到这批已保存的状态，代价从重复遍历变成每个状态最多一次实际计算。

    4. 自底向上：表格与状态顺序

    自底向上不写递归调用，通常按表格形式从较小状态算到较大状态。顺序必须保证算一个状态时，它需要的值已经可用。

    爬楼梯的两种 DP 写法

    设楼梯有 $n$ 级，每次能上一级或两级；状态 $F_n$ 是到达第 $n$ 级的方案数。边界是 $F_0=1$（站地面）和 $F_1=1$（走一级）。对 $n\ge 2$，最后一步只能来自第 $n-1$ 级或第 $n-2$ 级，

    $$F_n = F_{n-1}+F_{n-2}.$$

    1. 记忆化从 $F_5$ 向下请求：$F_5$ 要 $F_4$ 与 $F_3$，$F_4$ 要 $F_3$ 与 $F_2$。第二次遇到 $F_3$ 时直接查表。
    2. 自底向上从 $F_0$ 开始：$F_0=1$，$F_1=1$，$F_2=2$，$F_3=3$，$F_4=5$，$F_5=8$。顺序保证右侧的值先算好。
    3. 这段代码是表格版；若只保留前两项，同一递推也能继续算出后续值。
    F = [0] * 6
F[0], F[1] = 1, 1
for n in range(2, 6):
    F[n] = F[n - 1] + F[n - 2]

print([F[n] for n in range(6)])
    [1, 1, 2, 3, 5, 8]

    5. 复杂度与状态设计

    复杂度取决于状态数量、每个状态需要的转移计算和实现保留的状态；转移指按递推从当前状态进入下一状态并取其值的计算。

    Fibonacci 与鸡蛋掉落的复杂度核对

    Fibonacci 递归 $F_n=F_{n-1}+F_{n-2}$ 的子问题按 $F_0,\dots,F_n$ 计，共 $n+1$ 个状态；若不保存结果，同一子问题会反复展开，形成指数级的递归调用。按序填表后，代价是 $O(n)$。自顶向下版本需要一张大小 $O(n)$ 的表；自底向上版本只保留 $F_{n-1}$ 和 $F_{n-2}$ 两个滚动值，每算出一个新值就更新它们，空间是 $O(1)$。

    鸡蛋掉落问题要求用最少的测试次数，在所有情形下找出临界楼层；状态是剩余蛋数和剩余楼层数。设蛋数为 $n$、楼层数为 $k$。普通递推对每个状态枚举测试楼层，总代价为 $O(nk^2)$。

    6. 适用条件与边界

    DP 成立需要两个条件。第一是最优子结构：优化问题的解能由子问题的最优解合成；计数问题中，相应要求是原问题的方案数能由子状态的方案数合成。第二是子问题重叠：递归解同一个问题时会反复遇到同一批子问题。若子问题互不重叠，策略称为分治。

    不能仅因问题能递归就判定它适合 DP。有些决策问题不能拆成递归子问题；即使形式上能拆，缺少最优子结构或缺少子问题重叠，也不是这里的 DP。
