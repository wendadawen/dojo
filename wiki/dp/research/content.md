# Dynamic Programming

- 描述：动态规划把大问题递归分解成同一批会反复用到的重叠子问题，并保存或按依赖更新子问题的结果来合成原问题的解。
- 摘要：先定义状态并写出它们之间的 Bellman 方程，再让小子问题的值按依赖顺序生成大问题的解；优化问题得到最优解，计数问题得到方案数。
- 主题：算法与数据结构
- 标签：通用概念

## 短页

### 把大问题写成状态上的小问题

动态规划（DP）把原问题拆成子问题，用系统中的状态描述每个子问题。状态附带一个要算的量，常见是价值函数 $V_t(y)$：$V$ 是要算的值，$t$ 是阶段编号，$y$ 是那一阶段的状态。状态之间用递推关系连接，递推就是把一个状态的值写成其他状态的值的式子。
依据：blog/dynamic-programming.md L6-L8；blog/dynamic-programming.md L15-L21

### 保存子问题结果，避免重复计算

原问题的解若能由子问题的最优解合成，这个性质叫最优子结构。当递归会反复遇到同一批子问题时，DP 把每个已算出的结果存起来或按依赖更新，后面直接取用。递归调用树由此压缩成一组只算一次的状态。
依据：blog/dynamic-programming.md L2238-L2240；blog/dynamic-programming.md L2352-L2353

### 按依赖顺序求出状态的值

先写不能再拆的基例，再写状态之间的递推关系，也就是 Bellman 方程。按状态依赖从可用的值开始，用记忆化或自底向上填表求出所有需要的值。记忆化指递归求解时把已算状态的结果存入表并复用；两者遵循同一条递推，但实现和空间占用可能不同。
依据：blog/dynamic-programming.md L17-L23；blog/dynamic-programming.md L2240；blog/dynamic-programming.md L2244-L2245；blog/dynamic-programming.md L2352-L2353

## 长页

动态规划（DP）既是数学优化方法，也是算法设计方法。它把一个复杂问题递归拆成更简单的子问题，让每个子问题的结果由更小子问题的结果递推得到。
依据：blog/dynamic-programming.md L6-L8；blog/dynamic-programming.md L2238-L2240

### 问题形式与价值函数

在数学优化语境中，DP 通常把一个长期决策拆成一段时间上的决策步。第 $i$ 步的状态记作 $y$，每个状态的价值记作 $V_i(y)$；$i$ 是时间或阶段编号，$V_i$ 读作“从第 $i$ 阶段的状态 $y$ 开始能取得的值”。最后一个阶段的价值可以直接定义，前一个阶段的价值由后一个阶段的价值和当前收益合成。这样定义后，子问题不是“某一串具体决策”，而是“处在某个状态时余下问题的值”。
依据：blog/dynamic-programming.md L15-L21

### Bellman 方程

状态之间的关系写成 Bellman 方程。优化形式的通用形状是：目标取最大值时，

阶段编号取 $1,\dots,n$，$n$ 是最后阶段。$$V_i(y) = \max_{a} \{ r_i(y,a) + V_{i+1}(y') \},$$

其中 $a$ 是当前可选的动作，$r_i(y,a)$ 是在状态 $y$ 做动作 $a$ 的即时收益，$y'$ 是动作 $a$ 使系统进入的新状态。边界是不能再拆的子问题：$V_n(y)$ 是最后时间的价值，直接定义。求解按阶段逆序，先算 $V_n$，再算 $V_{n-1}$，最后 $V_1$ 在初始状态的值就是最优值；把每一步选过的动作记下来，可以从初始状态回溯出决策。
依据：blog/dynamic-programming.md L17-L23

DP 不只用于求最优值。它能不访问所有方案而计数：状态函数返回方案数，递归到更小子问题时把可行选择的方案数相加，并把结果存表复用。
依据：blog/dynamic-programming.md L2780；blog/dynamic-programming.md L2806；blog/dynamic-programming.md L2889

### 自顶向下：记忆化

自顶向下直接按递归式写函数，同一个状态第一次到达时才算，算完存入表。以后再遇到这个状态，先查表；表中有这个状态就返回，没有才算并把结果写入表。子问题重叠（递归会反复遇到同一批子问题）时，同一状态对应的递归分支收敛到这批已保存的状态，代价从重复遍历变成每个状态最多一次实际计算。
依据：blog/dynamic-programming.md L2240；blog/dynamic-programming.md L2244；blog/dynamic-programming.md L2349-L2353

### 自底向上：表格与状态顺序

自底向上不写递归调用，通常按表格形式从较小状态算到较大状态。顺序必须保证算一个状态时，它需要的值已经可用。
依据：blog/dynamic-programming.md L2245；blog/dynamic-programming.md L2353-L2362

::: 爬楼梯的两种 DP 写法
设楼梯有 $n$ 级，每次能上一级或两级；状态 $F_n$ 是到达第 $n$ 级的方案数。边界是 $F_0=1$（站地面）和 $F_1=1$（走一级）。对 $n\ge 2$，最后一步只能来自第 $n-1$ 级或第 $n-2$ 级，
依据：自行构造

$$F_n = F_{n-1}+F_{n-2}.$$
依据：自行构造

1. 记忆化从 $F_5$ 向下请求：$F_5$ 要 $F_4$ 与 $F_3$，$F_4$ 要 $F_3$ 与 $F_2$。第二次遇到 $F_3$ 时直接查表。
2. 自底向上从 $F_0$ 开始：$F_0=1$，$F_1=1$，$F_2=2$，$F_3=3$，$F_4=5$，$F_5=8$。顺序保证右侧的值先算好。
3. 这段代码是表格版；若只保留前两项，同一递推也能继续算出后续值。
依据：自行构造

```python
F = [0] * 6
F[0], F[1] = 1, 1
for n in range(2, 6):
    F[n] = F[n - 1] + F[n - 2]

print([F[n] for n in range(6)])
```

```text
[1, 1, 2, 3, 5, 8]
```
依据：自行构造

### 复杂度与状态设计

复杂度取决于状态数量、每个状态需要的转移计算和实现保留的状态；转移指按递推从当前状态进入下一状态并取其值的计算。
依据：自行构造

::: Fibonacci 与鸡蛋掉落的复杂度核对
Fibonacci 递归 $F_n=F_{n-1}+F_{n-2}$ 的子问题按 $F_0,\dots,F_n$ 计，共 $n+1$ 个状态；若不保存结果，同一子问题会反复展开，形成指数级的递归调用。按序填表后，代价是 $O(n)$。自顶向下版本需要一张大小 $O(n)$ 的表；自底向上版本只保留 $F_{n-1}$ 和 $F_{n-2}$ 两个滚动值，每算出一个新值就更新它们，空间是 $O(1)$。
依据：blog/dynamic-programming.md L2331-L2364

鸡蛋掉落问题要求用最少的测试次数，在所有情形下找出临界楼层；状态是剩余蛋数和剩余楼层数。设蛋数为 $n$、楼层数为 $k$。普通递推对每个状态枚举测试楼层，总代价为 $O(nk^2)$。
依据：blog/dynamic-programming.md L3157-L3196
:::

### 适用条件与边界

DP 成立需要两个条件。第一是最优子结构：优化问题的解能由子问题的最优解合成；计数问题中，相应要求是原问题的方案数能由子状态的方案数合成。第二是子问题重叠：递归解同一个问题时会反复遇到同一批子问题。若子问题互不重叠，策略称为分治。
依据：blog/dynamic-programming.md L2238-L2240

不能仅因问题能递归就判定它适合 DP。有些决策问题不能拆成递归子问题；即使形式上能拆，缺少最优子结构或缺少子问题重叠，也不是这里的 DP。
依据：blog/dynamic-programming.md L7；blog/dynamic-programming.md L2238-L2240
