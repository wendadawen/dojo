# ZeroMQ 术语表

全文术语、缩写与符号的统一登记。写作与审查均以此为准；同一对象不得出现第二种称法。

## 概念名称

| 术语 | 首次出现 | 含义与用法约定 |
|---|---|---|
| ZeroMQ | 页面标题、开头 | 概念正式名称。正文统一用 "ZeroMQ"，不用 ØMQ、0MQ 这两种官方等价写法 |
| ZMQ | 页面标题（括注） | ZeroMQ 的常见缩写。只在标题、`zmq_` 函数名与选项名（如 `ZMQ_SNDHWM`）中出现，正文叙述不用 ZMQ 指代概念本身 |
| libzmq | 开头来源摘要 | ZeroMQ 的 C 参考实现库名。引用源码时固定写 libzmq v4.3.5 |
| pyzmq | 开头来源摘要 | ZeroMQ 的 Python 绑定。实测环境固定写 pyzmq 27.1.0 |
| ZMTP | 第 1 章末、第 3 章 | ZeroMQ Message Transport Protocol，ZeroMQ 在面向连接传输上的线协议。首次出现时给出全称 |

## socket 与类型

| 术语 | 首次出现 | 含义与用法约定 |
|---|---|---|
| socket | 第 1 章 | 指 ZeroMQ socket（`zmq_socket()` 创建的消息队列抽象），不是操作系统 socket。首次出现时明确这一区别 |
| 操作系统 socket | 第 1 章 | 指 BSD/POSIX socket。需要与 ZeroMQ socket 对比时使用这个全称，不简写为 socket |
| socket 类型 | 第 2 章 | 创建 socket 时指定的类型，决定其消息传递语义 |
| 对端 | 第 1 章 | 与本 socket 建立了连接的另一个 ZeroMQ socket。统一用"对端"，不用"节点""peer""下游" |
| PUSH / PULL | 第 2 章 | 流水线模式的一对类型。类型名全文大写，不加 `ZMQ_` 前缀（选项名除外） |
| PUB / SUB | 第 4 章 | 发布-订阅模式的一对类型 |
| XPUB / XSUB | 第 2 章对照表 | PUB/SUB 的原始版本，仅在对照表与队列满行为表述中出现，不展开 |
| REQ / REP | 第 2 章对照表 | 请求-应答模式的同步一对 |
| DEALER / ROUTER | 第 2 章对照表 | 请求-应答模式的异步一对 |
| PAIR | 第 2 章对照表 | 独占对模式 |
| 发布者 / 订阅者 | 第 4 章 | 分别指 PUB(或 XPUB) 侧与 SUB(或 XSUB) 侧。需要强调具体类型时直接写类型名 |

## 路由与队列

| 术语 | 首次出现 | 含义与用法约定 |
|---|---|---|
| 出站策略 | 第 2 章 | socket 决定"一条待发消息去往哪个（哪些）对端"的规则 |
| 入站策略 | 第 2 章 | socket 决定"从哪个对端读取下一条消息"的规则 |
| 轮询 | 第 2 章 | round-robin。在可用对端间按顺序逐个分发，一条消息只去一个对端。首次出现时括注英文 |
| 扇出 | 第 2 章 | fan out。一条消息复制到所有（匹配的）对端队列。首次出现时括注英文 |
| 公平队列 | 第 2 章 | fair-queuing。轮流从各对端读取，避免高频对端饿死其他对端。首次出现时括注英文 |
| 可用对端 | 第 2 章 | 出站队列未满的对端。轮询只在可用对端间进行 |
| 路由标识 | 第 4 章 | routing id / identity。ROUTER 为每个对端队列分配的唯一二进制串。全文用"路由标识"，代码与实测输出中保留原文 `routing id` / `Identity` |
| 信封 | 第 4 章 | ROUTER 在消息前附加、或从消息前剥离的标识帧（以及 REQ 的空分隔帧）。统一用"信封"，不用"地址头""前缀帧" |
| 空分隔帧 | 第 4 章 | REQ socket 自动添加在数据帧之前的零长度帧 |
| 队列 | 第 1 章 | socket 在本进程内存中为单个对端维护的消息缓冲区。全文强调其 per-peer 性质，不用"缓冲池""消息池" |
| 双队列 | 第 4 章 | double queue。ROUTER / DEALER / XPUB 为每个对端同时维护的出站与入站两条队列 |
| 高水位 | 第 5 章 | high water mark，缩写 HWM。单个对端队列的消息条数上限。首次出现给出全称与缩写，之后统一用 HWM |
| mute 状态 | 第 5 章 | 队列达到 HWM 后 socket 进入的例外状态。保留英文 mute，因官方文档以此命名，中文无稳定译法 |

## 消息与线格式

| 术语 | 首次出现 | 含义与用法约定 |
|---|---|---|
| 消息 | 开头 | ZeroMQ 的应用级传输单位，由一到多个帧组成，原子交付 |
| 帧 | 第 1 章 | frame / message part。ZeroMQ 的线上传输单位。全文用"帧"，不用"消息段""分片" |
| 多段消息 | 第 3 章 | 由多个帧组成的一条消息 |
| 原子交付 | 第 3 章 | 对端要么收到一条消息的全部帧，要么一个都收不到 |
| greeting | 第 3 章 | ZMTP 连接建立后交换的 64 字节固定结构。保留英文，因规范以此命名 |
| 命令帧 | 第 3 章 | COMMAND 位为 1 的帧，由实现使用，一般不交给应用 |
| 消息帧 | 第 3 章 | COMMAND 位为 0 的帧，承载应用数据 |
| flags 字节 | 第 3 章 | 每帧首部的 1 字节控制位。保留英文 flags，与规范一致 |
| 短帧 / 长帧 | 第 3 章 | 长度字段为 1 字节（体 0–255）/ 8 字节（体 0–2^63−1）的帧 |
| 订阅前缀 | 第 4 章 | SUB 侧设定、由发布端做二进制前缀比较的二进制串 |

## 连接与运行时

| 术语 | 首次出现 | 含义与用法约定 |
|---|---|---|
| 端点 | 第 2 章 | endpoint。`传输://地址` 形式的字符串，如 `tcp://127.0.0.1:5601` |
| bind / connect | 第 2 章 | 保留英文 API 名。全文明确它们只决定谁提供端点地址，不对应服务端/客户端角色 |
| 传输 | 第 2 章 | transport。端点字符串中 `://` 之前的部分。本文涉及 `inproc`、`ipc`、`tcp` |
| inproc | 第 2 章 | 进程内（线程间）传输，不经过 I/O 线程 |
| context | 第 6 章 | ZeroMQ 上下文。持有 I/O 线程池，是 socket 的宿主。保留英文，与 API 一致 |
| I/O 线程 | 第 6 章 | context 线程池中真正执行网络读写的后台线程 |
| slow joiner | 第 6 章 | 订阅在发布端生效前，这段时间内发布的消息对该订阅者不可达的现象。保留英文，社区与官方指南以此命名 |

## 符号与代码约定

| 符号 | 含义 |
|---|---|
| `%xFF` | ZMTP 规范（ABNF）中的单字节十六进制字面量写法，引用规范原文时保留 |
| `0x04` | 正文与代码中描述字节值时的写法。规范引文之外统一用 `0x` 前缀 |
| bit 0 | 最低有效位（最右位）。全文按此约定，与 ZMTP 规范一致 |
| `ZMQ_SNDHWM` / `ZMQ_RCVHWM` | 出站 / 入站高水位选项名。保留大写原名 |
| `ZMQ_ROUTER_MANDATORY` | ROUTER 找不到目标时报错而非静默丢弃的开关 |
| `ZMQ_ROUTING_ID` | 显式指定本 socket 路由标识的选项 |
| `ZMQ_IO_THREADS` | context 的 I/O 线程数选项 |
| `zmq_send()` / `zmq_recv()` | C API 函数名。叙述通用语义时用 C 名；代码示例为 Python，写 `send()` / `recv()` |
| EAGAIN | 非阻塞模式下操作暂时无法完成的 errno |
| EFSM | socket 当前状态不允许该操作的 errno |
| EHOSTUNREACH | 消息无法路由的 errno |
| C1…C18 | 核心论断编号，与 evidence.md 一致 |
| F1、F2 | 线格式编号（greeting 布局、帧头布局） |
| N1…N9 | 实测记录编号 |

## 数值约定

| 数值 | 含义与来源性质 |
|---|---|
| 64 | greeting 的固定字节数（规范值） |
| 10 / 2 / 20 / 1 / 31 | greeting 各字段字节数：签名 / 版本 / 安全机制名 / as-server / 填充（规范值） |
| 1000 | `ZMQ_SNDHWM` / `ZMQ_RCVHWM` 默认值，单位为消息条数（规范值） |
| 1 | `ZMQ_IO_THREADS` 默认值（规范值） |
| 6 个任务 / 3 个 worker | 贯穿示例的构造参数 |
| HWM=5 | 队列实验的构造参数，非工程推荐值 |
| 5 条 / 95 条 / 200 条 | 实测观察值，受 C8"实际容量不保证等于 HWM"约束，不得表述为规格 |
