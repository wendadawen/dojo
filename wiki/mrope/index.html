    MRoPE（多模态旋转位置编码）：把一维位置轴拆成三条分量

    主要依据：Qwen2-VL 论文（arXiv:2409.12191v2）§2.1、§3.3.2；transformers@36deb0b5 的 qwen2_vl 与 qwen4_exp 实现；本机实测。

    一句「请描述这张图」的提示词里，文本 token 一字排开、天然有序；图像 token 却来自一张 $28\times28$ 的网格——排在同一行的两个 patch 相邻，排在同一列的两个 patch 也相邻，把它们拉平塞进一条一维位置轴，这两个方向就再也分不出来了。MRoPE（多模态旋转位置编码）的答案是：把位置编号从一个数变成三个数。旋转本身仍是 RoPE，位置编码家族的背景见位置编码。

    本文的学习路线：先看一维位置轴在多模态下缺什么；再看三个分量怎么取值、三种模态各怎么分配；然后看三条位置轴怎么共用同一组旋转频率（分段与交错两种排布）；最后算一笔「位置轴上的省账」——多模态输入让位置编号走得慢多少，换来什么。

    核心问题

    1. 一维位置编码在多模态输入下遇到什么问题？

      解答：网格没有自然的一维顺序，方向信息丢失

      文本 token 天然排成一列，位置编号依次加一即可；图像 token 排成二维网格、视频再加时间维，拉平进一维轴后「同行相邻」与「同列相邻」的距离变得相同，方向区分丢失。论文的表述是：文本一维而真实世界三维，一维位置嵌入限制对空间与时间动态的建模。论证见「文本有序、图像有格」一章。

    2. 三个分量怎么定义，文本、图像、视频各自怎么分配？

      解答：位置 id 变 $(t,h,w)$ 三元组，三种模态三种规则

      每个 token 的位置 id 从一个数变成时间、高、宽三个数。文本三值相同（退化为 1D-RoPE）；图像 $t$ 恒定、$h/w$ 按网格坐标取值；视频 $t$ 逐帧递增、$h/w$ 每帧重新按网格取值。新模态从前一模态最大位置 id 加一开始。规则与实例见「位置 id 变三元组」一章。

    3. 三个分量怎么共用同一组旋转频率？

      解答：按 mrope_section 配额切槽位，分段或交错两种排布

      头维中参与旋转的维数对应一组频率槽位，mrope_section 给出三个分量的配额（如 $[11,11,10]$）。分段排布让每个分量独占一段连续槽位；交错排布以 3 为步长交替占用，使每个分量都覆盖从低频到高频的完整范围。两种实现都在「一个头维装三条轴」一章。

    4. 为什么 MRoPE 有助于长序列外推？

      解答：图像块只推进 $\max(h,w)/\text{merge}$ 个位置

      一段视觉输入结束后，位置轴的推进量是该图像网格最大边长除以空间合并因子，而不是视觉 token 数——一张 1764 个 token 的图只让位置前进 42。同样长的多模态序列占用的位置 id 范围小得多，推理长度得以超过训练长度。实测与证据见「位置轴上的省账」一章。

    常见误解

    • 「MRoPE 是一种新的旋转公式」——旋转公式与 RoPE 完全相同，变的只是位置 id 从一维变三维、以及频率槽位怎么分给三个分量。
    • 「三个分量各占头维的三分之一」——配额由 mrope_section 决定（如 $[11,11,10]$；以 Qwen3.8-Flash-Next 的 32 个频率槽位计，$W$ 因 32 不被 3 整除而少一档），且存在分段与交错两种排布。
    • 「视觉 token 占多少个序列位置，位置编号就前进多少」——推进量是 $\max(h,w)/\text{merge}$；序列长度预算与位置轴预算是两回事。

    1. 文本有序、图像有格——一维位置轴装不下多模态

    RoPE 给每个 token 一个整数位置 id，token 之间的相对位置决定内积的旋转差。文本串里这件事是自然的：第 5 个词就是位置 5，相邻即距离 1。视觉输入不是这样——编码器输出的是一张网格，ViT 把图像切成 patch 后每个 token 带的是「第几行第几列」，而不是「第几个」。

    把网格拉平成一行会丢什么？同一个 patch 的右邻与下邻，在一维轴上距离都变成 1；「往右 3 个」和「往下 3 个」都变成「往后 3 个」。方向信息在一维轴上不存在，而这恰是空间理解最需要的信息。论文把动机说成一句一般性的话：文本天然一维，真实环境却是三维的，一维位置嵌入显著限制了模型对三维空间与时间动态的建模[C5]。

    本章问题

    1. 一维位置轴具体丢了什么信息？

      解答：网格的方向区分

      二维网格里一个 patch 有右邻和下邻两种「相邻」；拉平后两者在位置轴上的距离同为 1，模型无法从位置编码分辨「向右」与「向下」。同理，「隔 3 行的同行 token」与「隔 3 列的同行 token」距离相同。方向与轴向信息只存在于二维坐标里。

    2. 为什么不干脆给视觉 token 单独做一套二维位置编码？

      解答：文本与视觉要进同一个注意力

      多模态模型把文本与视觉 token 放进同一序列做注意力，位置编码必须同构才能比较。若视觉用二维、文本用一维两套体系，跨模态的相对位置无从定义。MRoPE 的做法是让文本也用三元组（三值相同），统一表示下视觉才自然退化回一维——统一是设计的关键约束，不是多余形式。

    2. 位置 id 变三元组——三种模态的分配规则

    MRoPE 把旋转位置嵌入拆成时间、高、宽三个分量[C1]：每个 token 的位置 id 不再是一个数，而是 $(t,h,w)$ 三元组。三种模态的取值规则[C2, C3, C4]：

    模态时间分量 $t$高分量 $h$宽分量 $w$
    文本三值相同同左同左
    图像恒定（该图起始值）按网格行按网格列
    视频逐帧递增每帧按网格行每帧按网格列

    文本三值相同意味着 MRoPE 在纯文本序列上功能等价于 1D-RoPE[C2]——退化是无损的。视觉段的生成式[F1]（论文正文以图示与文字呈现规则、无显式公式，此处取自官方实现源码）：

    $$T=\mathrm{arange}(t)\cdot\text{interval}+s,\qquad H=\mathrm{arange}(h/\text{merge})+s,\qquad W=\mathrm{arange}(w/\text{merge})+s$$
    • $s$：该视觉块在位置轴上的起始值；$t$ 为时间片数（源码中每 2 帧合成一个时间片），interval 为片间隔（默认取 1）。
    • $h,w$：网格高宽（patch 数）；$\text{merge}=2$ 是空间合并因子——相邻 $2\times2$ 的 patch 已被合并成单个 token，网格坐标相应折半。
    • 图像是单帧（$t=1$），$T$ 退化为常数 $s$；视频 $t>1$ 时 $T$ 逐帧递增，与上表「视频 $t$ 逐帧递增」一行一致。

    跨模态衔接规则：每个模态的位置编号从前一模态最大位置 id 加一开始[C7]。视觉 token 的最大位置 id 是 $s+\max(h,w)/\text{merge}-1$，因此「加一」等价于图像块结束后位置轴推进 $\max(h,w)/\text{merge}$——这条规则的两面在「位置轴上的省账」一章展开。

    构造示例。 序列 = 8 个文本 token + 一张 $(1,28,28)$ 的图（196 个视觉 token）+ 5 个文本 token。视觉段 $\text{merge}=2$ 后网格为 $14\times14$：

    token$t$$h$$w$
    第 1 个文本000
    第 8 个文本777
    视觉 token（首）888
    视觉 token（第 2 个）889
    视觉 token（末）82121
    图后第 1 个文本222222

    视觉段的 $t$ 恒为 8、$h$ 与 $w$ 各自在 $[8,21]$ 内遍历；图后文本从 22 开始——而不是从 $8+196=204$ 开始。这个数字差异就是「位置轴上的省账」一章的主题。

    代码：构造序列的三维位置 id 与推进量（实际运行） 
    S, GH, GW, MERGE = 8, 28, 28, 2

def text_pos(start, n):
    return [(start + i,) * 3 for i in range(n)]

def vision_pos(start, gh, gw, merge=MERGE):
    lh, lw = gh // merge, gw // merge
    return [(start, start + r, start + c)
            for r in range(lh) for c in range(lw)]

vis = vision_pos(S, GH, GW)
advance = max(GH, GW) // MERGE
print(f"视觉 token 数 = {len(vis)}, 推进量 = {advance}")
print(f"视觉段首/末: {vis[0]} {vis[-1]}")
print(f"图后首文本: {text_pos(S + advance, 1)[0]} (而非 {text_pos(S + len(vis), 1)[0]})")

for gh, gw in [(28, 28), (56, 56), (84, 84), (66, 120)]:
    n = (gh // MERGE) * (gw // MERGE)
    print(f"grid (1,{gh},{gw}): {n} 个 token, 推进 {max(gh, gw) // MERGE}")

    预期输出：

    视觉 token 数 = 196, 推进量 = 14
视觉段首/末: (8, 8, 8) (8, 21, 21)
图后首文本: (22, 22, 22) (而非 (204, 204, 204))
grid (1,28,28): 196 个 token, 推进 14
grid (1,56,56): 784 个 token, 推进 28
grid (1,84,84): 1764 个 token, 推进 42
grid (1,66,120): 1980 个 token, 推进 60

    验证的机制：正文三维分配规则（文本退化、图像 $t$ 恒定、$h/w$ 网格遍历）与推进量公式。

    观察重点：196 个视觉 token 只让位置轴前进 14；网格越大，token 数与推进量的差距越大。

    简化条件：网格尺寸与 merge 取真实量级，序列本身为构造；未涉及槽位分配（见「一个头维装三条轴」一章）。

    本章问题

    1. 为什么文本的三值必须相同，而不能让 $h/w$ 闲置为 0？

      解答：退化等价于 1D-RoPE，且跨模态可比

      三值相同时三个分量给出的旋转相位一致，注意力内积与一维 RoPE 完全相同——MRoPE 对纯文本无损。若文本用 0 而视觉用连续坐标，同一序列里文本与视觉的位置刻度不可比，跨模态相对位置失去意义。三值同涨保证了统一刻度。

    2. 视频的 $t$ 分量怎么走？

      解答：逐帧加一，$h/w$ 每帧重来

      视频被视为帧序列：第 $k$ 帧的所有 token 共享 $t=s+k$，帧内 $h/w$ 按该帧网格取值，下一帧 $h/w$ 重新从网格起点遍历。同一帧内空间关系由 $h/w$ 分辨，帧间先后由 $t$ 分辨——这正是把时间与空间拆开的意义。

    3. 一个头维装三条轴——分段与交错两种槽位排布

    「位置 id 变三元组」一章解决了「id 是什么」，这一章解决「id 怎么进旋转」。RoPE 的每个头维中参与旋转的部分对应一组频率，低频对应长程差异、高频对应近距离差异（分层含义见RoPE）。MRoPE 需要把这些频率槽位分给三个分量，配额由 mrope_section 给出。

    Qwen3.8-Flash-Next 的配置：头维 256、只旋转前 64 维（rotary_dim 为 $256\times 0.25$，config 键见数据流页），即 32 个频率槽位，mrope_section $=[11,11,10]$，和恰为 32。两种排布[C8, C9]：

    槽位012345…3031
    交错（qwen4_exp）THWTHW…TH

    交错排布的实现：以 $T$ 维为底，把 $H$ 覆盖到槽位 $\mathrm{slice}(1,33,3)$、$W$ 覆盖到 $\mathrm{slice}(2,30,3)$，其余槽位保持 $T$。本机实测的完整归属[F2]：

    分量占用槽位个数
    $T$0, 3, 6, 9, 12, 15, 18, 21, 24, 27, 3011
    $H$1, 4, 7, 10, 13, 16, 19, 22, 25, 28, 3111
    $W$2, 5, 8, 11, 14, 17, 20, 23, 26, 2910

    三个分量以 3 为步长在全部 32 个槽位上循环，$T$ 与 $H$ 从最高频槽位铺到最低频、$W$ 的槽位从 2 到 29 也近似覆盖整个范围（不含两端点）；$W$ 比 $T$ 和 $H$ 少一个槽位，因为 32 不能被 3 整除。源码文档字符串说明了改动内容：从分段的 $[TTT\ldots HHH\ldots WWW]$ 改为交错的 $[THWTHW\ldots]$，并保持频率连续性。

    分段排布（qwen2_vl 一系实现）是另一种分法：把 cos/sin 沿维度切成三段，每段独占。以 Qwen2-VL 官方模型配置（Qwen2-VL-7B 的 config.json，rope_scaling.mrope_section）为例：mrope_section $=[16,24,24]$，频率槽位共 64 个，$T$ 独占槽位 $[0,15]$（cos/sin 维度 $[0,31]$）、$H$ 独占 $[16,39]$、$W$ 独占 $[40,63]$。源码写法是 mrope_section*2 得 $[32,48,48]$ 后按 i%3 取段[C8]。

    频率槽位的方向需要注意：RoPE 的 inv_freq 随槽位下标递减，槽位 0 是最高频、末位槽位是最低频（分层含义见RoPE）。因此上述分段里 $T$ 独占的是最高频段、$W$ 独占的是最低频段；交错排布则让三个分量都以 3 为步长穿插在从高频到低频的全部槽位上，每个分量都覆盖完整频率范围。分段的代价是每个分量只对自己那段距离尺度有分辨率；交错的代价是配额只能近似均分（$W$ 少一档）。

    补充：为什么 32 个槽位对应 64 个旋转维

    RoPE 的每个频率槽位使用相邻的两个维度（旋转一对坐标），故 64 个旋转维对应 $64/2=32$ 个频率。分段实现里 mrope_section*2 正是把「频率配额」换算成「维度配额」再切 cos/sin 张量。

    本章问题

    1. 交错排布下 $W$ 为什么少一个槽位？

      解答：32 不被 3 整除

      三个分量以 3 为步长循环占用槽位：$T$ 从 0 开始、$H$ 从 1 开始、$W$ 从 2 开始。32 个槽位里 $T$ 落在 $\{0,3,\ldots,30\}$ 共 11 个、$H$ 落在 $\{1,4,\ldots,31\}$ 共 11 个、$W$ 落在 $\{2,5,\ldots,29\}$ 只有 10 个——最后一轮差一个位置。这是整除性的算术结果，不是有意压低 $W$ 的配额。

    2. 分段与交错各用什么换什么？

      解答：分段换可定制配额，交错换全频率覆盖

      分段让每个分量独占连续频率段，配额可以按需倾斜——如 Qwen2-VL 的 $[16,24,24]$ 给 $H$ 与 $W$ 各 24 档、$T$ 只有 16 档；代价是每个分量只覆盖自己那段，段外距离尺度没有分辨率。交错强制三分量共享全部频率范围，任何分量在任何尺度都有一定分辨率；代价是配额只能近似均分、无法倾斜。两种取舍对应两代实现的演进。

    4. 位置轴上的省账——推进量与长序列外推

    回到「位置 id 变三元组」一章结尾的数字：196 个视觉 token 只让位置轴前进 14。规则是图像块结束后位置轴推进 $\max(h,w)/\text{merge}$，而非推进 token 数[C10]。规模越大省得越多（下表为本机实测[N3, N4]）：

    图像 grid视觉 token 数位置推进量比值
    $(1,28,28)$1961414.0 倍
    $(1,56,56)$7842828.0 倍
    $(1,84,84)$1,7644242.0 倍
    $(1,66,120)$1,9806033.0 倍

    于是多模态序列有两笔独立的预算：序列长度（token 数）决定注意力与缓存的规模，位置轴（id 范围）决定位置编码的覆盖。$\text{max\_position\_embeddings}$ 约束的是后者。以 Qwen3.8-Flash-Next 为例（config 的 max_position_embeddings 为 262144，见数据流页），同样 262144 的位置上限，纯文本最多 26 万多个 token；穿插图像时，token 数可以远超位置范围——因为图像块的位置消耗按网格边长而非 token 数计。

    论文把这归为 MRoPE 的实际收益：M-RoPE 降低了图像与视频的位置 id 取值，使模型能在推理时外推到更长序列[C6]。两个支撑数字[N1, N2]：其一，Qwen2-1.5B + ViT-L 骨干的消融显示 M-RoPE 在多数基准上优于 1D-RoPE、视频基准提升最明显（如 NextQA 46.0 对 43.9、STAR 57.9 对 55.5；个别基准如 RWQ、InfoVQA 小幅下降），论文的措辞是「更好的整体表现，尤其视频基准」；其二，训练时每个视频最多 16K token，推理到 80K token 仍保持性能（Figure 5 语境为 Qwen2-VL-72B 在 Video-MME 中等时长视频）。

    回到贯穿示例收尾：8 个文本 + 一张 $(1,28,28)$ 图 + 5 个文本的序列，token 数 209，而位置轴只用到 $22+5-1=26$。若把这张图换成 $(1,84,84)$，token 数变 1777，位置轴仍是 $8+42+5-1=54$——序列长了一处，位置轴几乎没动。这就是「位置轴预算」视角的全部含义。Qwen3.8-Flash-Next 的完整配置与上下文占比实测见Qwen3.8-Flash-Next 前向数据流。

    本章问题

    1. 「前一模态最大位置 id 加一」和「推进 $\max(h,w)/\text{merge}$」是什么关系？

      解答：同一规则的两种表述

      视觉 token 的 $h/w$ 各自从起始值 $s$ 遍历到 $s+\text{边长}/\text{merge}-1$，$t$ 恒为 $s$，因此块内最大位置 id 是 $s+\max(h,w)/\text{merge}-1$；「下一个模态从最大 id 加一开始」即从 $s+\max(h,w)/\text{merge}$ 开始。论文用前一种表述，实现源码算后一种，数值相同。

    2. 为什么位置 id 走得慢就能外推？

      解答：位置编码的训练范围决定了外推的软上限

      RoPE 的每个频率在训练中只见过一定范围内的位置差；推理位置差远超训练范围时，高频分量的相位进入未见过区域，注意力质量下降。多模态序列的位置 id 范围被压小后，同样的「训练时见过的最大位置」能覆盖更多的实际 token——16K 训练、80K 推理的收益即来自这类压缩。位置编码本身的外推还有专门方法（如 YaRN），属另一主题。
