## 最后一批改动核对

核对通过（改后）。最后一批改动为：删「为什么需要专门的通信内核」节点并并入两处；新增「与计算重叠的延迟收尾」与「DeepEP 只管搬运」两小节；combine 口径改为「求和送回」；「接收数怎么定」只留高吞吐口径、依据补 legacy L171；「接收 hook」删「节点内 NVLink 协议」括号；「通信占多少 SM」删版本对比、标折叠；各节点依据行号对齐。

仲裁逐条核对后指出四处，均已改：

- 「DeepEP 只管搬运」原写「重叠调度都不在库里」，与 sources 相反（legacy L11「a hook-based communication-computation overlapping method」、README L283-L289 的延迟收尾都是库提供的重叠机制）。改为「库提供延迟收尾、事件等重叠机制，怎么排布由调用方安排」，删去「重叠调度不在库里」。
- 「固定槽位布局」原保留「用每专家计数标有效范围」，与第 2 轮裁定（每专家计数只留在「接收侧要什么布局」）冲突。已删，该节只留「按最大容量预留」与布局形状折叠。
- 「接收 hook」删句后遗留的依据 legacy L298 悬空。已去掉该依据。
- 「适用条件与边界」缺 README L332-L337（负载不均的冗余与重路由由调用方做）；「通信占多少 SM」缺 group-limited 限制（ep.py L456）。均已补，并明确 group-limited gate 下解析式不适用。

仲裁另指出：短页标题原「跨卡收发对内核的要求」仍含歧义词「内核」，已改为「跨卡收发难在哪」。仲裁总答：除上述一处新问题（已改）外，其余改动与 sources 及前两轮裁定一致，未引入新的「必须改」问题。大纲阶段结束。
