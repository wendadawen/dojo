读者：全部成立（术语分批讲，见下）。

- dispatch/combine、MoE、专家、专家并行（EP）、rank、隐藏维：开头各用一句定义；开头预算 550 → 250。
- 路由、门控、top-K：放在「从路由到发送计划」开头一句。
- all-to-all、SM：在「通用集合通信库缺什么」开头各一句。
- prefill/decode：在「高吞吐内核」章首一句，指推理两个阶段。
- NVLink、RDMA、节点：在「两段转发」开头各一句。
- CUDA graph、接收数同步：在「不用 CPU 等接收数」开头一句。
- V1 版本：在「通信占多少 SM」开头一句说明；只保留各自考据得出的说法。
- 短页三节：各自在节内用一句带过 MoE/专家/EP/rank/card、all-to-all/SM、RDMA/prefill/decode/hook/槽位，或在节内先讲清。

对照资料：

- 四类缺陷：部分成立。「要 CPU 等接收数」有 legacy L225 出处；「占 SM」有 README L39 出处；「载荷是 FP8 等低精度」有 README L3 出处；「按专家分组的接收布局」有 README L162 + ep.py L47-L52（库给出每本地专家接收计数，供专家计算核定位）出处。改法：把「不知按专家分组」「不给分组布局」两句合并、改写为「通用 all-to-all 只按 rank 收发，接收侧收不到每个本地专家各有多少 token 的计数」，「载荷非标准低精度」改为「dispatch 常要 FP8 等低精度载荷」；三类都补上出处，不删节点。
