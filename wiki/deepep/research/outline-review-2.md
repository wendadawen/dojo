## 处理

读者：全部成立。

- token：开头定义清单补「token（词元）」；短页第 1 节内补一句。
- Hopper：边界节一句说明它是某一代 NVIDIA GPU。

对照资料：

- 解析式 SM 的条件：成立。该节补「按均衡门控假设给出；group-limited gate 下不适用」。
- 「所有 rank 都走 RDMA」：成立。改为「跨节点走纯 RDMA（节点内另支持 NVLink 协议）」，删「所有…都」。
- 「通用集合通信库缺什么」：成立（该节点改写，见下）。三条里「占 SM」有 README L39，「载荷 FP8」有 README L3，「接收侧要按本地专家计数」有 README L162 与 ep.py L47-L52；但「通用库缺什么」这个因果，sources 没有拿通用库做过比较，属自编。改法：节点改名为「为什么需要专门的通信内核」，只陈述 DeepEP 内核对外提供什么（接收侧给出每本地专家的接收计数供计算核分段、dispatch 支持 FP8 低精度、搬运占用 GPU SMs），不写「通用库做不到」的因果。短页第 2 节同样改，不写「现成库搬不好」。

篇幅与冗余：全部成立。

- 重复：成立。接收侧分组与每专家计数只留「接收侧要什么布局」一处；「固定槽位布局」只留「按配置最大容量预留」与布局形状折叠。
- 「通信占多少 SM」的版本对比：成立。删 V1 查表与 V2 对比，只留「搬运占用 SM、与专家计算争抢；SM 数可按带宽模型解析算出（假设均衡门控）」。
- 「代价」表与条件：成立。测试条件、两张带宽/延迟表都折进折叠块。

连带（作者据本轮意见一并处理）：把涉及 V1/V2 版本对比的措辞从各节点删去，机制按概念本身写，不按版本分章；「不用 CPU 等接收数」改为写当前接口的两种取数方式（要精确接收数时 CPU 同步、decode 时按配置容量预留并用每专家计数定位），依据改到 README L162 与 ep.py L617-L624，不再依赖 V1 文档。
