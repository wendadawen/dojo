    MQA 与 GQA：用共享 K/V 头压缩自回归推理的 KV cache

    主要依据：Shazeer 2019, "Fast Transformer Decoding: One Write-Head is All You Need", arXiv:1911.02150, §3 多查询注意力定义、§3.1 性能分析与"减 h 倍"结论；Ainslie 2023, "GQA: Training Generalized Multi-Query Transformer Models from Multi-Head Checkpoints", EMNLP 2023, arXiv:2305.13245, §2 分组查询注意力、§2.1 uptraining 转换方法、Table 1 实验、Figure 6 折中点选择。

    自回归推理每生成一个 token，都要从 HBM 把整个 KV cache 搬一遍——$h=128$ 头、$d_k=128$ 维、$n=4096$ 长、$l=80$ 层的真实规模量级示例，单条请求的 KV cache 约 21.5 GB（fp16）。搬运量随头数 $h$ 与序列长度 $n$ 线性增长，GPU 在等数据而非算。MQA（Shazeer 2019）让所有 query 头共享一组 K/V 把 cache 减到 1/h，GQA（Ainslie 2023）在 MHA 与 MQA 之间插值、选定 $G=8$ 作折中点——两者都走"共享头"这条路压缩 cache。MQA/GQA 是 MLA（低秩压缩）的前置，但不展开 MLA 压缩公式、Flash Attention 的 IO 实现与 Linear Attention 的核分解。要回答的问题是：共享头如何压缩 cache、代价是什么、与走低秩压缩的 MLA 有何根本区别。

    核心问题

    1. 为什么标准 MHA 在自回归推理时受内存带宽限制——KV cache 如何随头数 h 与序列长度 n 增长？

      解答：每步全量加载 KV cache，带宽成为瓶颈

      自回归解码每生成一个 token，都要把之前所有 token 的 K/V 从 HBM 加载一遍。MHA 每 token 每 layer 缓存 $2 h d_k$ 个元素，随头数 $h$、序列长度 $n$、层数 $l$ 线性增长（真实规模下单条请求约 21.5 GB）；内存访问/算术比值 $\Theta(n/d + 1/b)$ 在 $n$ 接近 $d$ 或 batch 小时接近 1，GPU 在等数据而非算。完整论证见"为什么 MHA 推理受内存带宽限制"一章。

    2. MQA 如何通过共享一组 K/V 把 cache 减到 1/h，代价是什么（质量下降、训练不稳定）？

      解答：去掉 K/V 头维度，减少 $h$ 倍但有质量代价

      MQA 把 $P^K,P^V$ 的头维度去掉，全模型只保留一组 K 和一组 V，每 token 每 layer 的 cache 从 $2 h d_k$ 降到 $2 d_k$，恰好减少 $h$ 倍。代价是质量轻微下降，且大模型与长输入任务上微调可能出现训练不稳定。完整论证见"MQA——所有 query 头共享一组 K/V"一章。

    3. GQA 如何在 MHA 与 MQA 之间插值，uptraining 如何从已有 MHA 检查点得到 GQA，G=8 为什么是折中点？

      解答：$G$ 是谱上旋钮，uptraining 两步升级已有检查点

      GQA 把 query 头分成 $G$ 组、每组共享一组 K/V，cache 为 $2 G d_k$；$G=h$ 即 MHA、$G=1$ 即 MQA。uptraining 分两步：把 $h$ 个 K/V 投影按组均值池化为 $G$ 个，再用原预训练计算量的 5% 继续预训练。T5-XXL 上 GQA-8 质量 47.1 接近 MHA 47.2、推理 0.28s 接近 MQA 0.24s，故 $G=8$ 是质量与速度的折中点。完整论证见"GQA——在 MHA 与 MQA 之间插值"一章。

    4. 手算 4 头 MHA / 2 组 GQA / 1 组 MQA 的每 token KV cache，并说明三者的连续谱关系。

      解答：512 / 256 / 128 元素，K/V 头数的连续谱

      固定 $d_k=64$：MHA 每 token $2\times 4\times 64=512$ 元素，GQA-2 为 $256$，MQA 为 $128$。三者是 K/V 头数从 $h$ 到 1 的连续谱上的点，$G$ 是旋钮，每减一个 K/V 头 cache 减少 $2 d_k$，线性下降无突变。完整论证见"手算对比"一章。

    5. MQA/GQA（共享头）与 MLA（低秩压缩）的根本区别是什么，二者之间是怎样的前置关系？

      解答：共享头缓存完整 head 向量，MLA 缓存低维潜向量

      MQA/GQA 共享头：被缓存的每个 K/V 仍是完整 $d_k$ 维 head 向量，只是份数从 $h$ 减到 $G$ 或 1。MLA 低秩压缩：不共享头，把所有头的 K/V 联合压成 $d_c$ 维潜向量，推理时再上投影重建，cache 为 $(d_c + d_h^R)$。机制完全不同；理解 cache 的来源与共享头的质量代价，才能理解 MLA 压缩的对象及其另辟路线的原因。完整论证见"边界与后续"一章。

    最容易误解

    • 以为 "Multi-Query" 是"增加 query 头"——正确：query 头数量与 MHA 一样多（都是 h），"multi" 修饰 query 头保持多头不变；MQA 减的是 K/V 头数（h → 1），不是增加 query 头
    • 以为 MQA/GQA 减少的是计算量（FLOPS）——正确：主要减的是自回归推理时每步从 HBM 加载 KV cache 的数据量与显存占用（内存带宽与容量）；每个 query 头仍要做一次 $q\cdot k$ 与 $\sum v$，算术强度反而提升
    • 以为 GQA 与 MQA 是并列的两个改进——正确：GQA 是 MHA（$G=h$）与 MQA（$G=1$）的插值，MQA 是 GQA 的一个端点（$G=1$），不是并列关系
    • 以为 MLA 就是 GQA 的极端（头数减到很低）——正确：MLA 不共享头，而是把所有头的 K/V 联合压成低维潜向量 $c_t^{KV}$ 再用上投影重建；共享头缓存的仍是完整 $d_k$ 维 head 向量，低秩压缩缓存的是所有 head 信息的低维潜表示，机制完全不同

    1. 为什么 MHA 推理受内存带宽限制——KV cache 如何随头数与序列长度增长

    训练 Transformer 时，整个序列并行送入模型，所有位置的 K/V 一次性算出，GPU 的并行算力得到充分利用。但自回归推理（生成式解码）完全不同：生成第 1 个 token 时只知道输入 prompt；生成第 2 个 token 时才知道第 1 个 token；每生成一个新 token，都要重新对"之前所有 token"做一次注意力。

    更关键的是：每生成一个 token，都需要从 GPU 的高带宽显存（HBM）中加载之前所有 token 的 K 和 V——这部分缓存被称为 KV cache。它有多大？

    KV cache 的来源是标准多头注意力（MHA）的投影机制——此处不重复推导，详见 标准 Transformer 注意力。MHA 下每个 token 在每层要为每个头存一份 K（$d_k$ 维）和一份 V（$d_k$ 维），所以：

    $$\text{KV cache}_{\text{MHA}} = 2\,h\,d_k\quad\text{（每 token 每 layer 的元素数）}$$[F1]

    说明：Shazeer 2019 区分 key 维度 $d_k$ 与 value 维度 $d_v$，但实践沿用 Vaswani 2017 设定 $d_v = d_k$，故此处 cache 公式统一记 $d_k$（K、V 各一份，每份 $d_k$ 元素）。

    $n$ 个 token、$l$ 层时总元素数为 $2 h d_k n l$。逐项含义：

    符号含义对 cache 的贡献
    $h$注意力头数线性：头越多，每 token 要存的 K/V 份数越多
    $d_k$每个 head 的 key/value 维度线性：每份 K/V 的元素数
    $n$已生成的序列长度线性：token 越多，cache 累积越大
    $l$Transformer 层数线性：每层各自存一份 KV cache
    常数 2K 和 V 各一份固定

    取 $h=4,d_k=64,l=1,n=10$ 这类小配置，可以手算验证上面的公式。

    构造示例。 设 $h=4$（4 个注意力头）、$d_k=64$（每头 64 维）、$l=1$（1 层）、$n=10$（10 个 token）。数字为便于手算构造，不代表真实模型规模。

    MHA 每 token 每 layer 的 KV cache 元素数：

    $$2\times h\times d_k = 2\times 4\times 64 = 512\text{ 元素/token}.$$

    10 个 token 1 层共 $512\times 10 = 5120$ 元素。用 fp16（每元素 2 字节）存储为 $5120\times 2 = 10240$ 字节 $\approx 10$ KB。这个量级在小配置下无足轻重——但推广到真实规模（$h=128,d_k=128,l=80,n=4096$）时 MHA cache 约 21.5 GB（fp16，$2\times128\times128\times4096\times80\times2\approx 2.15\times10^{10}$ 字节），单条请求就占满可观显存。

    Shazeer 2019 §2.4.1 的性能分析指出，incremental MHA 每步解码的"内存访问量 / 算术运算量"比值随：

    $$\Theta\!\left(\frac{n}{d} + \frac{1}{b}\right)$$[F5]

    增长，其中 $n$ 是当前序列长度、$d$ 是模型维度、$b$ 是 batch size。当 $n$ 接近 $d$ 或 batch $b$ 小时，这个比值接近 1——意味着每做一次运算就要搬一字节数据，GPU 在等内存而非算。现代 GPU 的算力增长（V100→A100→H100，FP32 从 15.7→19.5→67 TFLOPS，约 4.3 倍）快于内存带宽增长（900→2039→3352 GB/s，约 3.7 倍），这个剪刀差让带宽瓶颈随硬件演进越来越严重。[N6]

    补充：roofline 模型与"算术强度"的含义

    算术强度（arithmetic intensity）指每字节数据对应的浮点运算次数（FLOP/byte）。GPU 的峰值算力与内存带宽之比给出一个"脊点"——算术强度低于脊点时程序受带宽限制（GPU 在等数据），高于脊点时受算力限制（GPU 在满载计算）。自回归解码每步加载整个 KV cache 却只做一次注意力，算术强度极低，落在带宽受限区。增大 batch $b$ 可摊薄固定开销（对应 $1/b$ 项减小），但当 $n/d$ 主导时只能靠减少 cache 本身——这正是 MQA/GQA 的切入点。以上为通用背景知识，用于建立直觉，不是上述论文的原文结论。

    本章的结论：自回归推理时 MHA 的瓶颈是 内存带宽（每步加载 KV cache）而非 算力，而 KV cache 随头数 $h$ 与序列长度 $n$ 线性增长。减少 K/V 的份数（每头一份，即 $\Theta(n/d + 1/b)$ 中 $n/d$ 项的系数为 1）就能等比例减少每步搬运的数据量——这是 MQA 与 GQA 的共同切入点。[C1]

    本章问题

    1. 写出 MHA 每 token 每 layer 的 KV cache 公式，并说出每项含义。

      解答：$2 h d_k$，头数与维度各贡献一个线性因子

      公式为 $2 h d_k$：每个头存一份 K（$d_k$ 维）和一份 V（$d_k$ 维），常数 2 即 K、V 各一份；$h$ 个头、$n$ 个 token、$l$ 层时总量为 $2 h d_k n l$，四项均为线性贡献。

    2. 自回归推理的瓶颈在哪里？算出 $h=4,d_k=64,l=1,n=10$ 下 MHA 的 cache 元素数。

      解答：瓶颈是内存带宽，手算得每 token 512 元素

      瓶颈在内存带宽而非算力：每步解码都要把整个 KV cache 从 HBM 加载一遍，内存访问/算术比值 $\Theta(n/d + 1/b)$ 在 $n$ 接近 $d$ 或 batch 小时接近 1。手算：每 token 每 layer $2\times 4\times 64=512$ 元素，10 个 token 1 层共 $5120$ 元素，fp16 约 10 KB。

    3. 性能比值 $\Theta(n/d + 1/b)$ 中 $n/d$ 项的系数是什么？MQA 把它变成什么？

      解答：MHA 下系数为 1，MQA 减为 $1/h$

      MHA 下 $n/d$ 项的系数为 1——每个头都要加载自己的 K/V，MHA 的比值为 $\Theta(n/d + 1/b)$。MQA 共享 K/V 后该项减为 $1/h$，即 $n/d \to n/(dh)$，MQA 的比值为 $\Theta(1/d + n/(dh) + 1/b)$；把头数从 $h$ 减到 $G$ 或 1 能按同一因子减少该项的内存搬运量。这是 MQA 与 GQA 的共同切入点；当 $1/b$ 项主导时应增大 batch 而非改注意力。

    瓶颈来自每头一份 K 和 V 的全量加载；MQA 的切入点是把 K/V 的份数直接降到 1，所有 query 头共享一组。

    2. MQA——所有 query 头共享一组 K/V，cache 减到 1/h

    Shazeer 2019 §3 提出 Multi-Query Attention（MQA），核心改动一句话："the different heads share a single set of keys and values"（所有不同的头共享同一组 K 和 V）。query 头仍然保持多头（$h$ 个），但 K/V 投影去掉头维度，全模型只有一组 K 和一组 V。[C3]

    回顾 MHA 的投影张量形状（Shazeer 2019 的 einsum 记法）：$P^Q\in\mathbb{R}^{h\times d\times d_k}$、$P^K\in\mathbb{R}^{h\times d\times d_k}$、$P^V\in\mathbb{R}^{h\times d\times d_v}$、$P^O\in\mathbb{R}^{h\times d\times d_v}$——四个投影都有头维度 $h$。MQA 把 $P^K$、$P^V$ 的头维度去掉：

    投影MHA 形状MQA 形状区别
    $P^Q$（query 投影）$\mathbb{R}^{h\times d\times d_k}$$\mathbb{R}^{h\times d\times d_k}$不变，query 头保持多头
    $P^K$（key 投影）$\mathbb{R}^{h\times d\times d_k}$$\mathbb{R}^{d\times d_k}$去掉头维度，全模型一组
    $P^V$（value 投影）$\mathbb{R}^{h\times d\times d_v}$$\mathbb{R}^{d\times d_v}$去掉头维度，全模型一组
    $P^O$（输出投影）$\mathbb{R}^{h\times d\times d_v}$$\mathbb{R}^{h\times d\times d_v}$不变，仍按多头汇聚

    因为全模型只有一组 K 和一组 V，每 token 每 layer 的 KV cache 从 $2 h d_k$ 降到 $2 d_k$：

    $$\text{KV cache}_{\text{MQA}} = 2\,d_k\quad\text{（每 token 每 layer）}$$[F2]

    减少倍数正好是 $h$。Shazeer 2019 §3.1 给出 MQA 的比值 $\Theta(1/d + n/(dh) + 1/b)$，并直接给出分析结论："We have reduced the offensive n/d by a factor of h"——把性能比值 $\Theta(n/d + 1/b)$ 里的 $n/d$ 项减为 $1/h$（$n/d \to n/(dh)$）。[C2, C4]

    构造示例（续）。 沿用上面的 $h=4,d_k=64,l=1,n=10$。MQA 每 token 每 layer 的 cache：

    $$2\times d_k = 2\times 64 = 128\text{ 元素/token}.$$

    10 个 token 1 层共 $128\times 10 = 1280$ 元素，fp16 为 $2560$ 字节 $\approx 2.5$ KB。与前面 MHA 的手算（5120 元素、10 KB）对照，减少 4 倍——正好是头数 $h=4$。

    代价。Shazeer 2019 abstract 报告 MQA "incur only minor quality degradation from the baseline"——质量轻微下降。Ainslie 2023 进一步在 §1 与 Appendix A 指出：MQA 在大模型与长输入任务上 "can lead to quality degradation"，且 "can lead to training instability during fine-tuning"——训练不稳定。质量代价的来源在概念上可理解：MHA 的设计目标是让不同头关注不同子空间（Vaswani 2017 §3.2.2），共享 K/V 把所有头的"键空间"与"值空间"压成一份，query 头虽然仍能学不同的"提问方式"，但能检索的内容被压缩到一个子空间。[C5, N1]

    补充：MQA 在工程实现上的"广播"问题

    标准注意力 kernel（如 FlashAttention）通常假设 Q、K、V 的头维度一致。MQA 下 K/V 只有 1 组而 Q 有 $h$ 组，直接实现要么把 K/V 在头维度上广播 $h$ 份（额外内存开销，抵消 cache 收益），要么修改 kernel 让多个 query 头内联复用同一组 K/V。后者是生产实现的正确做法，但属 GPU 工程细节，此处不展开。这一组描述为工程实现层面的推断，不是上述论文的结论。

    本章问题

    1. 写出 MQA 的 $P^K$ 形状，并与 MHA 对比。

      解答：去掉头维度，全模型一组

      MQA 的 $P^K\in\mathbb{R}^{d\times d_k}$，没有头维度，全模型只有一组 K 投影（$P^V$ 同理为 $\mathbb{R}^{d\times d_v}$）；MHA 的 $P^K\in\mathbb{R}^{h\times d\times d_k}$，每头一组。$P^Q$ 与 $P^O$ 保持头维度不变——query 头仍是 $h$ 个。

    2. 算出 $h=4,d_k=64$ 下 MQA 每 token 的 cache，并说出减少倍数。

      解答：128 元素，减少 $h=4$ 倍

      每 token 每 layer 为 $2 d_k=2\times 64=128$ 元素，10 个 token 1 层共 1280 元素（fp16 约 2.5 KB）。与 MHA 的 5120 元素相比减少 4 倍，正好等于头数 $h$。

    3. MQA 的代价是什么？Shazeer 2019 §3.1 的分析结论是什么？

      解答：质量与稳定性代价，$n/d$ 项减为 $1/h$

      代价：Shazeer 2019 abstract 报告质量轻微下降（"minor quality degradation"）；Ainslie 2023 进一步指出大模型与长输入任务上可能质量退化、微调训练不稳定。分析结论：共享 K/V 把性能比值 $\Theta(n/d + 1/b)$ 中 $n/d$ 项的系数减为 $1/h$，等比例降低每步解码的内存搬运量。

    MQA 直接砍到 1 组，质量有代价；GQA 在 MHA 与 MQA 之间插值，给出减得更少的中间点。

    3. GQA——在 MHA 与 MQA 之间插值，G=8 是折中点

    Ainslie 2023 §2 提出 Grouped-Query Attention（GQA），核心改动一句话："Grouped-query attention divides query heads into G groups, each of which shares a single key head and value head."（把 query 头分成 G 组，每组共享一组 K/V）。$P^K,P^V\in\mathbb{R}^{G\times d\times d_k}$——头维度从 $h$ 变成 $G$，介于 MHA（$h$）与 MQA（$1$）之间。

    关键性质：$G=h$ 等价于 MHA，$G=1$ 等价于 MQA。GQA 是 MHA 与 MQA 的插值，$G$ 是谱上的旋钮。

    $$\text{KV cache}_{\text{GQA}} = 2\,G\,d_k\quad\text{（每 token 每 layer）}$$[F3, C6]

    构造示例（续）。 沿用上面的 $h=4,d_k=64,l=1,n=10$，取 $G=2$（GQA-2）。每 token 每 layer 的 cache：

    $$2\times G\times d_k = 2\times 2\times 64 = 256\text{ 元素/token}.$$

    10 个 token 1 层共 $256\times 10 = 2560$ 元素，fp16 为 $5120$ 字节 $\approx 5$ KB。介于 MHA（5120 元素、10 KB）与 MQA（1280 元素、2.5 KB）之间——$G=2$ 把 cache 减半（相比 MHA），保留了两份 K/V 头的表达力。

    uptraining：从已有 MHA 检查点升级到 GQA。Ainslie 2023 §2.1 与 §3.1 给出两步配方，让已有 MHA 模型不必从头重训：[C7, N4]

    1. 检查点转换：把 MHA 检查点里 $h$ 个 K/V 投影矩阵按组均值池化（mean pooling）为 $G$ 个。Ainslie 2023 §2.1 报告均值池化优于"选第一个头"或"随机初始化"；§3.3（Figure 4）给出理由——"the degree to which information is preserved from the pre-trained model"，即保留的预训练信息越多效果越好。
    2. 继续预训练：用原预训练计算量的 $\alpha$ 比例继续训练，论文取 $\alpha=0.05$（5%）。Ainslie 2023 §3.3（Figure 5）报告 T5-XXL 规模下 5% uptraining 已显著提升质量，10% 后收益递减；§3.1 给出总开销约 600 TPUv3 chip-days。
    补充：uptraining 转换方法与 $\alpha$ 的消融细节

    转换方法消融（Ainslie 2023 Figure 4）：均值池化 > 选第一个头 > 随机初始化，按"保留预训练信息的程度"排序。

    $\alpha$ 影响消融（Ainslie 2023 Figure 5）：GQA 在转换后（$\alpha=0\%$）即可达到合理性能；MQA 需要 uptraining 才能用；$\alpha=5\%$ 带来显著提升，$\alpha=10\%$ 后收益递减。

    训练稳定性（Ainslie 2023 Appendix A）："multi-query attention can lead to training instability during fine-tuning, in particular combined with long input tasks... Uptrained grouped-query attention models, however, appear to be stable." MQA 训练不稳定，GQA 则稳定——这是 GQA 的一部分动机。

    实验结论。Ainslie 2023 Table 1 在 T5-XXL 上的实验数据（每 TPUv4 chip 的推理时间与多任务平均质量）：

    模型K/V 头数推理时间（s/样本）平均质量对比

    MHA-XXLh1.5147.2大模型基线

    GQA-8-XXL 质量 47.1 接近 MHA-XXL 47.2（差 0.1），推理 0.28s 接近 MQA-XXL 0.24s（慢 0.04s）——Ainslie 2023 abstract 称 "Uptrained GQA achieves quality close to multi-head attention with comparable speed to MQA"。G=8 是 Figure 6 消融后选定的折中点，论文称其为 favorable middle ground——从 G=1（MQA）到 G=8 推理开销适度增加，继续增大 G 收益递减。[C8, N2, N3]

    本章问题

    1. 写出 GQA 的 cache 公式，并说出 $G$ 的两个端点各等价于什么。

      解答：$2 G d_k$，两端为 MHA 与 MQA

      GQA 每 token 每 layer 的 cache 为 $2 G d_k$：$G=h$ 时每头独立 K/V，等价于 MHA；$G=1$ 时全模型一组 K/V，等价于 MQA。$G$ 是连续谱上的旋钮，只能取 $[1,h]$ 内的整数。

    2. uptraining 分哪两步？GQA 相比 MQA 有什么额外好处？

      解答：均值池化 + 5% 继续预训练，训练更稳定

      第一步把 MHA 检查点里 $h$ 个 K/V 投影矩阵按组均值池化为 $G$ 个（优于选第一个头或随机初始化，保留的预训练信息更多）；第二步用原预训练计算量的 $\alpha=5\%$ 继续预训练。额外好处是训练稳定：Ainslie 2023 Appendix A 报告 MQA 微调可能不稳定，uptrained GQA 则稳定。

    3. GQA-8 在 T5-XXL 上的实验结论是什么？

      解答：质量接近 MHA，速度接近 MQA

      Ainslie 2023 Table 1：GQA-8-XXL 质量 47.1，接近 MHA-XXL 的 47.2（差 0.1）；推理 0.28 s/样本，接近 MQA-XXL 的 0.24 s，约为 MHA-XXL 1.51 s 的 5.4 倍速度。$G=8$ 是 Figure 6 消融后选定的折中点。

    三种机制的 cache 公式已分别给出；把它们并排放到手算里，连续谱关系随之显形。

    4. 手算对比——4 头 MHA / 2 组 GQA / 1 组 MQA 的 KV cache 连续谱

    把前面三次手算合并成一张表，固定 $h=4,d_k=64,l=1,n=10$ 的教学数字：

    机制K/V 头数每 token cache（元素）10 token cache（元素）10 token fp16（字节）
    MHA$h=4$$2\times 4\times 64 = 512$$5120$$10240$（$\approx 10$ KB）
    GQA-2$G=2$$2\times 2\times 64 = 256$$2560$$5120$（$\approx 5$ KB）
    MQA$1$$2\times 1\times 64 = 128$$1280$$2560$（$\approx 2.5$ KB）

    每减一个 K/V 头，每 token cache 减 $2 d_k = 128$ 元素。从 MHA（4 头）到 GQA-2（2 头）减 256，从 GQA-2 到 MQA（1 头）再减 128——线性下降，没有突变。

    连续谱关系：MHA、GQA、MQA 不是三个独立机制，而是 K/V 头数从 $h$ 到 $1$ 的连续谱上的三个点。GQA 的 $G$ 是谱上的旋钮——$G=h$ 端是 MHA（每头独立 K/V、质量最高、cache 最大），$G=1$ 端是 MQA（全共享、cache 最小、质量略降），中间任意 $G$ 都是有效插值。选哪个 $G$ 是质量与速度的工程权衡，Ainslie 2023 在 T5-XXL 上选定 $G=8$。

    补充：推广到真实规模的量级感

    构造示例。 设真实规模 $h=128,d_k=128,l=80,n=4096$（fp16，每元素 2 字节）：

    机制每 token cache（元素）总 cache（元素）fp16 字节
    MHA$2\times 128\times 128 = 32768$$32768\times 4096\times 80 \approx 1.07\times 10^{10}$$\approx 21.5$ GB
    GQA-8$2\times 8\times 128 = 2048$$\approx 6.71\times 10^{8}$$\approx 1.34$ GB
    MQA$2\times 1\times 128 = 256$$\approx 8.39\times 10^{7}$$\approx 168$ MB

    MHA 单条请求的 KV cache 约 21.5 GB，在长序列与多并发下会迅速占满单卡显存——这就是长上下文模型的核心瓶颈。GQA-8 把它压到 1.34 GB，MQA 压到 168 MB。数字为教学推算，真实工程还需考虑 batch、框架开销与 PagedAttention 分页。

    本章问题

    1. 算出 $h=4,d_k=64,l=1,n=10$ 下 MHA / GQA-2 / MQA 的每 token cache，并说出每减一个 K/V 头 cache 减多少。

      解答：512 / 256 / 128 元素，每头 $2 d_k$

      MHA 为 $2\times 4\times 64=512$、GQA-2 为 $2\times 2\times 64=256$、MQA 为 $2\times 1\times 64=128$ 元素/token。每减一个 K/V 头，每 token cache 减少 $2 d_k=128$ 元素——少存一份 K 和一份 V，线性下降、无突变。

    2. 连续谱的旋钮是什么？两端分别是什么？

      解答：$G$ 是旋钮，两端为 MHA 与 MQA

      旋钮是 K/V 头数 $G$：$G=h$ 端是 MHA（每头独立 K/V、质量最高、cache 最大），$G=1$ 端是 MQA（全共享、cache 最小、质量略降），中间任意整数 $G$ 都是有效插值。选哪个 $G$ 是质量与速度的工程权衡。

    3. 真实规模 $h=128$ 下 MHA 与 MQA 的 cache 量级差是多少？

      解答：约 128 倍，即头数 $h$ 倍

      $h=128,d_k=128,l=80,n=4096$（fp16）下：MHA 约 21.5 GB、GQA-8 约 1.34 GB、MQA 约 168 MB。MHA 与 MQA 相差约 128 倍，即 $h$ 倍；数字为构造推算，真实工程还需考虑 batch、框架开销与 PagedAttention 分页。

    以上都是"共享头"这一条路；MLA 走的是另一条路——压缩 K/V 本身。

    5. 边界与后续——MQA/GQA 不解决什么，与 MLA 的根本区别

    MQA/GQA 不解决什么。两者减的是 KV cache 的头数系数，不解决注意力本身的 $O(n^2)$ 算力——每个 query 头仍要对全部前序 token 做 softmax 加权和，$QK^\top$ 仍是 $n\times n$ 矩阵。它们也不解决训练时的激活内存，也不引入位置信息（位置仍需 RoPE 等外接编码）。当 $h=1$（本来就是单头）时 MQA 与 MHA 完全相同、无收益；当 batch $b$ 极大使 $1/b$ 项主导 $\Theta(n/d+1/b)$ 时，减 $n/d$ 项的收益被稀释（这时应增大 batch 而非改注意力）。

    与 MLA 的根本区别。DeepSeek-V2 §2.1.4 Table 1 把四种机制的每 token 每 layer cache 并排：

    机制KV 头数每 token 每 layer cache压缩思路
    MHA$h$$2 h d_k$不压缩（基线）
    GQA$G$$2 G d_k$共享头：少存几份完整 head
    MQA$1$$2 d_k$共享头极端：所有头共用一份
    MLA—$(d_c + d_h^R)$低秩压缩：所有 head 的 K/V 压成 $d_c$ 维潜向量

    MLA 行来源：DeepSeek-V2 §2.1.4 Table 1；MLA 的完整机制见 MLA。$d_c$ 为压缩潜维度、$d_h^R$ 为解耦 RoPE 维度，此处只引公式对照不展开机制。

    关键区别在 压缩思路 一列：

    • MQA/GQA（共享头）：被缓存的每个 K/V 仍是完整的 $d_k$ 维 head 向量，只是份数从 $h$ 降到 $G$ 或 $1$。是"少存几份完整 head"。
    • MLA（低秩压缩）：不共享头。把所有头的 K/V 联合压成一个 $d_c$ 维潜向量 $c_t^{KV}$，推理时再用学习到的上投影为每个头重建 K/V。是"把所有 head 信息压到一个低维潜向量"。

    两者目标相同（减 KV cache），但机制完全不同。DeepSeek-V2 配置下（$n_h=128,d_h=128,d_c=512,d_h^R=64$）MLA cache = 576 元素/token/layer，比 MHA 的 $2\times 128\times 128=32768$ 小得多（约 1/57）；注意 MLA(576) 反而大于 MQA(256)，MLA 的优势是相比 MHA/GQA 基线在更小 cache 下保质量，而 MQA 质量略低于 MHA（DeepSeek-V2 abstract 报告 MLA 减少 93.3% KV cache，对比对象是 DeepSeek 67B 的 GQA 基线）。[C9, F4, N5]

    与 MLA 的前置关系。理解了"KV cache 来自每头一份 K 和 V"（MHA 章节）才能理解 MLA 在压缩什么——它压缩的正是这"每头一份 K 和 V"的联合表示。理解了"共享头有质量代价"（MQA 章节）才能理解 MLA 为什么另起一条路——不共享头、用低秩压缩保留各头独立性，从而在更小 cache 下保住质量。MLA 的完整压缩公式、矩阵吸收与解耦 RoPE 见 MLA。

    本章问题

    1. MQA/GQA 不解决哪两类问题？

      解答：$O(n^2)$ 算力与位置信息

      两者只减 KV cache 的头数系数，不解决注意力本身的 $O(n^2)$ 算力——每个 query 头仍要对全部前序 token 做 softmax 加权和，$QK^\top$ 仍是 $n\times n$ 矩阵（算力瓶颈由 Flash 或 Linear Attention 处理）。也不引入位置信息，位置仍需 RoPE 等外接编码。此外 $h=1$ 时无收益，batch 极大使 $1/b$ 项主导时收益被稀释。

    2. 共享头与低秩压缩的机制区别是什么？写出四种机制的 cache 公式。

      解答：少存几份完整 head 与压成低维潜向量之别

      共享头（MQA/GQA）被缓存的每个 K/V 仍是完整 $d_k$ 维 head 向量，只是份数减少；低秩压缩（MLA）把所有头的 K/V 联合压成 $d_c$ 维潜向量，推理时再上投影重建。四种机制的每 token 每 layer cache：MHA $2 h d_k$、GQA $2 G d_k$、MQA $2 d_k$、MLA $(d_c + d_h^R)$。

    3. MQA/GQA 与 MLA 之间是怎样的前置关系？

      解答：先明确压缩对象与共享头代价

      其一，理解"KV cache 来自每头一份 K 和 V"才能理解 MLA 在压缩什么——它压缩的正是这"每头一份 K 和 V"的联合表示。其二，理解"共享头有质量代价"才能理解 MLA 为什么另起一条路——不共享头、用低秩压缩保留各头独立性，在更小 cache 下保住质量。MLA 的完整机制见 MLA。

    回顾五个核心问题：MHA 推理受内存带宽限制，因为每步要从 HBM 加载随 $h$ 与 $n$ 线性增长的 KV cache；MQA 共享一组 K/V 把 cache 减到 1/h，代价是质量下降与训练不稳定；GQA 在 MHA 与 MQA 间插值，uptraining 以 5% 算力从 MHA 检查点升级，$G=8$ 是质量与速度的折中点；三种机制在 K/V 头数从 $h$ 到 1 的连续谱上，每减一个头 cache 减 $2 d_k$；MQA/GQA 走共享头路线，MLA 走低秩压缩路线，机制完全不同——理解了共享头及其代价，才能理解 MLA 为什么另起一条路。

    辅助解释与类比边界

    • "共享头是少存几份完整 head，低秩压缩是把所有 head 信息压成低维潜向量"：用于区分 MQA/GQA 与 MLA。失效边界：这只是压缩思路的直觉区分，不覆盖 MLA 的矩阵吸收、解耦 RoPE 等机制细节；正式判断以 DeepSeek-V2 §2.1.2 的压缩公式为准。
    • "G 是谱上旋钮"：用于建立 MHA→GQA→MQA 的连续谱直觉。失效边界：$G$ 只能在 $[1,h]$ 取整数，不是任意实数；且 $G$ 的选择影响质量与速度的权衡，不是"越大越好"或"越小越好"。

    简化条件及其限制

    • 手算例子用 $h=4,d_k=64,l=1,n=10$。可推出：三种机制的 cache 元素数与连续谱关系。不可推出：真实模型的 cache 量级、batch 与框架开销、PagedAttention 分页；折叠块给出真实规模推算作量级感补充。
    • 不展开 Shazeer 2019 性能比值的完整推导，只引 $\Theta(n/d+1/b)$ 结论与"减 h 倍"的分析结果。可推出：减 $h$ 能等比例减带宽开销。不可推出：roofline 模型的完整推导、GPU 算力与带宽的具体对比推导；MHA 章节折叠块给出 roofline 直觉补充。
    • 不展开 uptraining 的消融细节，只引两步配方与 $\alpha=5\%$。可推出：uptraining 能从已有 MHA 检查点低成本得到 GQA。不可推出：Figure 4 三种转换方法的详细对比、Figure 5 的 $\alpha$ 影响曲线、Appendix A 的训练稳定性分析；GQA 章节折叠块给出关键结论补充。
    • 不展开 MLA 机制，只引 cache 公式对照与"低秩压缩 vs 共享头"的思路区别。可推出：MQA/GQA 与 MLA 是两条不同的压缩路线。不可推出：MLA 的压缩公式 $c_t^{KV}=W^{DKV}h_t$、矩阵吸收 $W^{UK}$ 吸进 $W^Q$、解耦 RoPE；由 MLA 页面展开。
    • 不引用 Shazeer 2019 的具体速度倍数，只引 abstract 的定性结论"much faster"。可推出：MQA 显著加速解码。不可推出：具体 BLEU 与速度倍数；二手转述数字存在失真风险，不引用。
