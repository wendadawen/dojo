注意力汇聚点（Attention Sink）

自回归模型会把多余的注意力「倾倒」到少数位置上——通常是序列开头。这些位置不是信息中心，而是 softmax 归一化必需的去处；淘汰缓存时把它们一起删掉，模型会直接崩溃。

更新于 2026-09-10

问题背景

长对话推理通常只保留最近一段窗口的 KV 缓存。一个自然的做法是把更早的缓存全部淘汰，包括序列最开始那几个 token。但实测发现：这样做的模型在序列超过缓存规模后会突然崩溃，困惑度从个位数涨到数千；只要把最前面的 4 个位置留下，困惑度就回到同一水平。要理解这件事，需要先理解注意力权重是怎么被分配的。

核心机制

  1. 现象：除最底部两层外，模型在各层各头持续把大量注意力分给初始位置。把最初 4 个 token 换成换行符后模型仍显著依赖它们，说明起作用的是绝对位置而非内容。
  2. 成因：softmax 的每一项都严格大于零、且权重之和恒为 1，模型必须把注意力分配完。当当前 token 自身信息已足够时，多余的权重需要一个去处；初始位置对所有后续 query 可见，最容易被训练成这个角色。
  3. 形态一：把少数初始位置的 KV 留在缓存里（实测 4 个足够），与滚动窗口拼成缓存。代价是占用缓存槽位。
  4. 形态二：给每个注意力头一个可学习标量，只加在 softmax 分母上。DeepSeek-V4.1-Flash 采用这一形态，真实 checkpoint 中该参数覆盖 40 个主干层与 3 个 MTP 层，每层每头一个标量，不占用任何缓存。
  5. 量级：汇聚点占分母的份额为 $e^{\text{sink}}/(W+e^{\text{sink}})$。窗口 $W=128$ 时，标量从 0 增到 5，份额从 0.78% 升到 53.69%——它不是可以忽略的常数项。

关键结论与边界

  • 任何「只保留最近窗口」的淘汰策略都必须额外保住汇聚点，否则崩溃是立即发生的。成立条件：softmax 注意力 + 自回归模型。
  • 汇聚点只影响归一化，不携带内容：它没有值向量可供输出，一行里所有可见槽位都无效时输出全零。成立条件：分母构造如实现所定义。
  • 保住汇聚点解决的是稳定性，不是能力：它不扩展上下文窗口、不增强长程记忆。成立条件：被淘汰的历史信息不会因为保留了 sink 而恢复。
  • 可学习标量的取值由训练决定，本页不声称某个具体取值；checkpoint 头只提供参数形状。

前置概念

  • 标准注意力：softmax 归一化是汇聚点成因所在。
  • KV cache：淘汰策略与汇聚点的冲突在这里发生。
  • 滑动窗口注意力：只保留最近窗口的策略正是必须处理汇聚点的场景。
