    注意力汇聚点（Attention Sink）：被注意力倾倒的位置，以及为什么不能丢掉它

    主要依据：StreamingLLM（Xiao et al., arXiv:2309.17453）§3 与 Table 1–3；DeepSeek-V4.1-Flash 官方参考实现 official/inference/kernel.py（稀疏注意力分母）、official/inference/model.py（attn_sink 参数）与真实 checkpoint 分片头。解析解与参数形状的复算脚本见文末来源说明。

    本页讨论的汇聚点是注意力分配的去处，不是「重要的位置」。它有两种落地形态：把少数初始位置的 KV 留在缓存里，或给每个注意力头一个只进分母的可学习标量。DeepSeek-V4.1-Flash 用后一种。

    核心问题

    1. 注意力汇聚点是什么现象？它与语义有关吗？

      解答：序列开头的少数位置被大量注意力「倾倒」，起作用的是绝对位置而非语义

      除最底部两层外，模型在各层各头都持续把大量注意力分给初始位置。把最初 4 个 token 替换成换行符后，模型仍显著依赖它们，说明它依赖的是这些位置「在所有 query 的可见范围内」这一属性，而不是它们的内容。因此「注意力分数高」不等于「信息重要」。完整观察与实验见第 1 章。

    2. 为什么模型需要这样一个「倾倒」位置？

      解答：softmax 要求权重非零且和为 1，注意力必须分配完

      softmax 把每个可见槽位的分数变成非零权重、并要求它们和为 1，因此模型不能「什么都不看」。当当前 token 自身信息已足够时，多余的权重需要一个去处，而初始位置对所有后续位置可见、最容易被训练成这个去处。把它们的 KV 移除，等于从分母里抽掉一大块，注意力分布随之显著偏移、输出崩溃。完整推导见第 2 章。

    3. 两种实现形态各怎么做？区别在哪？

      解答：留住真实位置，或用一个只进分母的可学习标量

      StreamingLLM 的做法是在滚动窗口之外额外保留 4 个初始位置的 KV，两部分拼成缓存。DeepSeek-V4.1-Flash 的做法是给每个注意力头一个可学习标量，只加在 softmax 分母上，不占用任何缓存槽位；真实 checkpoint 中该参数出现在 40 个主干层与 3 个 MTP 层，形状 $[64]$（每头一个）。前者占用缓存、后者不占，这是两者最重要的区别。完整机制见第 3 章。

    4. 它对缓存策略与推理有什么约束？

      解答：任何淘汰策略都必须保住汇聚点，且它的份额可能过半

      只保留最近窗口、把开头位置一起丢掉的策略会让模型崩溃，必须额外保住汇聚点。参数化 sink 免除了这项缓存负担。它的注意力份额随 logit 增大而快速上升：在 128 个可见槽位分数均为 0 的构造情形下，logit 取 0、2、5、8 分别占分母的 0.78%、5.46%、53.69%、95.88%，因此它不是数值上的微调。但汇聚点不扩展上下文窗口、不增强长程记忆。完整边界见第 4 章。

    常见误解

    • 「汇聚点是模型学到的『句首重要』」——把最初 4 个 token 换成换行符后模型仍依赖它们，起作用的是绝对位置。
    • 「汇聚点就是注意力分数最高的位置」——它是被「倾倒」的位置；分数高不代表信息重要，移除它会破坏归一化。
    • 「保留 sink 就能无限流式」——保留 sink 只解决崩溃问题，不扩展上下文窗口、不增强长程记忆。
    • 「可学习 sink 与保留初始位置是同一件事」——前者是加在分母上的标量、不占缓存；后者是把真实位置的 KV 留在缓存里。

    1. 现象：开头的位置拿到远超其重要性的注意力

    先看观察到的事实。StreamingLLM 在多个自回归语言模型上发现：除最底部两层外，模型在各层各头都持续把大量注意力分给序列最前面的少数位置[C1]。这些位置在语义上往往无关紧要（可能只是一段提示的开头），却拿到了远超其内容的注意力份额。

    更关键的是语义无关性的实验：把最初 4 个 token 全部替换成换行符，模型仍然显著强调这些位置；把这 4 个换行符位置作为初始位置保留时，困惑度恢复到与保留原始 4 个 token 相当的水平（5.60 对 5.40）[C1, N1]。这说明模型依赖的是「这些位置在最前面、对所有后续 query 都可见」这一属性，而不是它们的具体内容。

    解读它预测什么实测结果
    「开头很重要」（语义解读）换掉开头内容后依赖应消失换成换行符后仍被依赖，不成立
    「开头是个去处」（位置解读）换内容不影响，换位置才会与实测一致

    因此本页把「注意力分数高」与「信息重要」明确分开：前者说明模型在这个位置分配了权重，后者要看这个位置的内容是否影响输出。汇聚点属于前者。

    本章问题

    1. 为什么说汇聚点的作用是「位置」而不是「内容」？

      解答：把内容换成换行符后依赖仍然存在，说明起作用的是位置属性

      实验把最初 4 个 token 的内容替换为换行符，模型仍然显著强调这些位置，且把这 4 个换行符位置作为初始位置保留时，困惑度（5.60）与保留原始 4 个 token（5.40）相当。如果模型依赖的是内容（比如「开头这句话很重要」），换掉内容后依赖应当消失。依赖仍在，说明模型利用的是「这些位置在序列最前面、对所有后续位置可见」这一结构性属性。

    2. 注意力分数高的位置一定重要吗？

      解答：不一定，汇聚点就是反例

      注意力分数只说明权重被分配到哪里，不说明该位置的信息对输出有多少贡献。汇聚点是典型的反例：分数很高、内容可以随意替换。判断一个位置是否重要，要看它的内容变化是否影响输出，而不是看它的分数高低。

    2. 成因：softmax 必须把注意力分配完

    为什么模型会形成这样一个去处？原因在 softmax 的归一化约束[C2]。注意力对每个 query 都会把可见槽位的分数变成一组非零权重，并要求它们和为 1：

    $$o = \frac{\sum_{t\in\mathcal{T}} e^{\,q\cdot k_t/\sqrt{d}}\,v_t}{\sum_{t\in\mathcal{T}} e^{\,q\cdot k_t/\sqrt{d}}}$$
    • $q$：当前 query；$k_t, v_t$：第 $t$ 个可见槽位的键与值；
    • $d$：注意力头维；$\mathcal{T}$：可见槽位集合；
    • $o$：注意力层的输出，是可见槽位值向量的加权平均；
    • 分母：可见槽位指数之和，softmax 的归一化因子。

    这个式子有一个常被忽略的后果：分母是「可见槽位指数之和」，指数函数的值恒大于零，因此[C2]

    • 每个可见槽位都会拿到非零权重，模型不能「什么都不看」；
    • 权重必须加起来等于 1，多出来的注意力必须有地方去。

    当当前 token 自身的信息已经足够支撑预测时，模型仍要把注意力分配完，于是需要一个「倾倒」的位置。序列最前面的位置最适合充当这个角色：它对所有后续 query 都可见，因此几乎所有 query 都能稳定地往它上面分配权重，训练时最容易被固化成这个功能[C2]。反过来，一旦把这些位置的 KV 从缓存里删掉，分母就少了这一大块，注意力分布会显著偏离正常推理时的样子，模型输出随之崩溃[C2]。

    补充：为什么「必须分配完」会导致崩溃而不只是输出变差

    softmax 的输出是权重，权重之和恒为 1。若把分母里占比很大的一项拿掉，剩下的每一项权重会被重新放大（因为总和仍要归一到 1），于是原本只占很小份额的槽位突然获得大得多的权重，注意力的分布形状被整体改写。这就是「删掉一个几乎不携带信息的位置，却让输出崩掉」的原因：受影响的是归一化结构，不是那一个位置的信息量。

    本章问题

    1. 如果模型「不需要」看任何历史，能不能让注意力权重全为零？

      解答：不能，softmax 的指数函数恒大于零

      softmax 的每一项是 $e^{s_i}/\sum_j e^{s_j}$，指数函数的值恒大于零，因此每一项都严格大于零、不可能为零。即使某个槽位的分数远低于其他槽位，它也只是权重很小，而不是没有权重。所以模型必须把全部注意力权重分配出去，这正是需要「汇聚点」的根本原因。

    2. 为什么是序列最前面的位置，而不是中间某个位置？

      解答：因为它们对所有后续 query 都可见

      在因果掩码下，位置 $i$ 的 query 只能看到位置 $\le i$ 的内容。序列最前面的位置对所有后续 query 都可见，因此任何一个 query 都能稳定地往它们上面分配权重；中间位置只对一部分 query 可见，无法承担这个全局角色。这也是「初始位置更容易被训练成汇聚点」的原因。

    3. 两种做法：留下位置，或留一个参数

    知道成因之后，做法就分成两条路：要么在缓存里真的留住那几个位置，要么用一个不占缓存的参数替代它们的作用。

    3.1 形态一：保留初始位置的 KV

    StreamingLLM 走的是第一条路：在滚动窗口之外额外保留 4 个初始位置的 KV，与最近的窗口拼成缓存[C3]。论文实测保留 4 个初始位置一般就足够，继续增加收益递减[C3, N2]。这条路线还改变了位置口径：把缓存内的位置重新编号，而不是使用它们在原文中的下标。论文把这一点写成关键设计——它决定模型看到的是「缓存内的相对距离」，而不是原文中的绝对距离[C3]。

    代价是明确的：缓存里必须一直留着那几个槽位，且它们的 KV 需要按原样保存。

    3.2 形态二：每个头一个可学习标量

    另一条路是把这个「去处」参数化。DeepSeek-V4.1-Flash 的每个注意力头都有一个可学习的标量，它不来自任何 token，而是直接加在 softmax 分母上[C4, F1]：

    $$o = \frac{\sum_{t\in\mathcal{T}} e^{\,q\cdot k_t/\sqrt{d}\,-\,m}\,v_t}{\sum_{t\in\mathcal{T}} e^{\,q\cdot k_t/\sqrt{d}\,-\,m} + e^{\,\text{sink}-m}},\qquad m=\max_{t\in\mathcal{T}}\frac{q\cdot k_t}{\sqrt{d}}$$
    • $\text{sink}$：该头可学习的汇聚点标量，作为 logit 使用；
    • $m$：可见槽位分数的行最大值，用于数值稳定；它不含汇聚点项；
    • 分子与分母中可见槽位的指数项都减同一个 $m$：这是在线 softmax 的数值稳定写法，公共因子 $e^{-m}$ 在分子分母间约掉，不改变结果；
    • 分母第二项 $e^{\text{sink}-m}$：汇聚点提供的「去处」，与可见槽位的权重加在一起做归一化；它与可见槽位项共享同一个 $m$。

    式中 $q$、$k_t$、$v_t$、$d$、$\mathcal{T}$ 与 $o$ 的含义见第 2 章的符号表。

    这个形态有两个可直接核对的性质：汇聚点只出现在分母（分子不变），且它不参与行最大值的计算。真实 checkpoint 中，该参数出现在全部 40 个主干层与 3 个 MTP 层，每层形状 $[64]$——即每个注意力头一个 fp32 标量[C4, N4]。因为它是参数而不是某个位置的 KV，缓存里不需要为它留任何槽位。

    构造示例：取 $q=0$（因此所有可见槽位分数为 0、$m=0$）、两个可见槽位、值分别为 $v_1$ 与 $v_2$。分母是 $2 + e^{\text{sink}}$，分子是 $v_1 + v_2$，所以输出是 $(v_1+v_2)/(2+e^{\text{sink}})$。实测（语义复现的稀疏注意力实现）与解析解逐元素差为 0：

    • $\text{sink}=-\infty$：输出 $(v_1+v_2)/2$，等价于没有汇聚点；
    • $\text{sink}=0$：输出 $(v_1+v_2)/3$，汇聚点吃掉三分之一的权重；
    • $\text{sink}=2$：输出 $(v_1+v_2)/(2+e^2) \approx (v_1+v_2)/9.39$。

    另有一个边界：如果某行的可见槽位全部无效（索引为 $-1$），行最大值被替换为一个极小的有限值，汇聚点项因此变成无穷大，而分子为 0，最终输出全零——汇聚点不会「救回」一个没有任何可见槽位的 query。

    本章问题

    1. 为什么可学习标量能替代「保留几个初始位置」？

      解答：它提供了同样的「去处」，但不依赖任何 token

      两种做法的共同作用是在 softmax 分母里提供一个不携带信息的份额：初始位置是真实 token，靠「对所有 query 可见」获得这个角色；可学习标量则直接以参数形式加在分母上。因此后者不需要在缓存里保留任何位置，也不受位置编码口径影响。代价是它必须通过训练学到合适的量级。一个直接对照：用可学习 sink token 训练的 160M 模型，只需 1 个 sink 配 1023 个近期位置即可把困惑度压到 18.01；未做该训练的模型即使保留 2 个初始位置也只有 18.05——差别就在于前者不需要靠真实位置来充当这个角色[N3]。

    2. 汇聚点项为什么不能计入 softmax 的行最大值？

      解答：行最大值只用于数值稳定，实现在累积循环之后单独把 sink 项加入分母

      在线 softmax 用行最大值 $m$ 把指数项缩放到安全范围。分子分母同时乘 $e^{-m}$，所以 $m$ 取任何与槽位分数同尺度的值都不改变结果——对 $m$ 做公共平移只会让分子分母同时缩放，比值不变，因此「把 sink 计入 $m$ 会改变相对权重」并不成立。更直接的理由是分子与分母共用同一个最终行最大值：内核在累积循环里用 $e^{m_{\text{prev}}-m_{\text{cur}}}$ 逐块缩放已累积的分子与指数和，循环结束后再把 $e^{\text{sink}-m}$ 加到分母上[C4, C5]。无论 $m$ 取可见槽位最大值还是含 sink 的值，它同时出现在分子与分母的公共因子里，比值不变。真实原因因此不在数学必要性，而在实现结构：行最大值因此只可能来自可见槽位，汇聚点从未进入最大值归约；这个选择来自实现结构，不是数学上的必要条件。

    3. 某一行没有任何可见槽位时，汇聚点会不会提供输出？

      解答：不会，输出全零

      当一行的可见槽位全部无效时，分子为 0；同时行最大值被替换成一个极小的有限值，使得汇聚点项变成无穷大，分母为无穷大。0 除以无穷大等于 0，因此输出全零。这说明汇聚点提供的是「份额」而不是「内容」——它没有可输出的值向量，只影响归一化。

    4. 对缓存与推理意味着什么

    把前几章的结论合起来，可以得到三条对推理实现有直接影响的判断。

    4.1 淘汰策略必须保住汇聚点

    任何「只保留最近 $W$ 个位置」的缓存策略都要额外处理汇聚点[C2, C3]。纯窗口（丢弃初始位置）在序列长度超过缓存后会让困惑度从个位数涨到数千，而保留 4 个初始位置即可恢复到同一水平[N1]。这条约束在流式推理里尤其重要：缓存淘汰是常态操作，一旦把汇聚点淘汰掉，崩溃是立即发生的。

    4.2 汇聚点的份额可能过半

    汇聚点不是数值上的小修正。在 $W$ 个可见槽位分数均为 0（即 $m=0$）的构造情形下，它在分母中的份额是[F2]：

    $$\text{share} = \frac{e^{\text{sink}}}{W + e^{\text{sink}}}$$
    • $\text{sink}$：该头的汇聚点标量（作为 logit）；
    • $W$：可见槽位个数（窗口场景下即窗口大小）；
    • $\text{share}$：汇聚点占分母的比例，其余 $1-\text{share}$ 由可见槽位分摊。

    取 $W=128$（DeepSeek-V4.1-Flash 的窗口大小）、$W$ 个可见槽位分数均为 0（$m=0$，于是每个可见槽位的指数项都是 1）这一构造假设时，份额 $\text{share}=e^{\text{sink}}/(W+e^{\text{sink}})$ 随 $\text{sink}$ 单调上升：$\text{sink}=0$ 时为 0.78%、$\text{sink}=2$ 时 5.46%、$\text{sink}=5$ 时 53.69%、$\text{sink}=8$ 时 95.88%[N5]。取值越大份额越接近 1 但永远取不到 1。真实取值由训练决定，本页未读取真实权重数值。

    代码：份额随汇聚点标量的变化 
    import math

W = 128                       # 可见槽位个数（等于窗口大小）
for sink in (0.0, 2.0, 5.0, 8.0):
    share = math.exp(sink) / (W + math.exp(sink))
    print(f"sink={sink:>4}: 份额 {share:.4f} = {share * 100:.2f}%")

    预期输出：

    sink= 0.0: 份额 0.0078 = 0.78%
sink= 2.0: 份额 0.0546 = 5.46%
sink= 5.0: 份额 0.5369 = 53.69%
sink= 8.0: 份额 0.9588 = 95.88%

    验证的机制：第 4.2 节的份额公式 $\text{share}=e^{\text{sink}}/(W+e^{\text{sink}})$，即分母中汇聚点项与可见槽位项的相对大小。

    观察重点：份额对标量高度敏感——从 0 到 5（相差 5 个 logit 单位）份额就从不足 1% 升到超过一半。这说明汇聚点参数决定了「多少注意力被倒掉」，而不是一个可以忽略的常数项。

    简化条件：假设所有可见槽位分数均为 0（因此 $m=0$、它们的指数项都是 1）。实际分数分布下，可见槽位项的和对份额影响很大，真实份额会随 query 变化。若可见槽位分数同为 $s$ 而非 0，按公式份额是 $e^{\text{sink}-s}/(W+e^{\text{sink}-s})$，取值随 $m$ 所在尺度平移——因此本页统一取 $m=0$ 的构造口径。

    4.3 边界：汇聚点不是长程记忆

    需要明确的是，保住汇聚点解决的是稳定性，不是能力。论文明确说明：这类做法不扩展模型的上下文窗口，也不增强长程记忆[C6]。被汇聚点吃掉的注意力份额不携带被淘汰的历史信息；要真正「记得更远」，需要窗口之外的另一路可见性（例如压缩后的全局 KV）[C4]。

    本章问题

    1. 为什么「只保留最近窗口」会让模型崩溃，而不是慢慢变差？

      解答：被移除的份额会被重新分摊给剩下的槽位，注意力分布被整体改写

      softmax 的权重之和恒为 1。移除汇聚点后，分母少了一大块，剩下的可见槽位为了把总和补回 1，各自权重被放大，原本只占很小份额的位置突然变得重要。这不是「少了一点信息」，而是分布形状的改变，因此表现为突然崩溃而不是平滑退化。实测上，纯窗口配置的困惑度是数千，而保留 4 个初始位置后回到个位数。

    2. 可学习标量的大小有什么约束吗？

      解答：没有本页可声称的先验约束，由训练决定，但份额对其高度敏感

      标量作为 logit 使用，它的取值决定份额 $e^{\text{sink}}/(W+e^{\text{sink}})$。由于该函数在 0 到 8 的区间内从 0.78% 涨到 95.88%，取值对注意力分布影响很大，因此它必须是训练出来的、而不是人工设定的常数。本页不声称某个具体取值是正确取值：checkpoint 头只给出参数形状（每头一个 fp32 标量），未读取权重数值。

    辅助解释与类比边界

    本页的辅助解释是「注意力必须分配完、需要一个去处」这一归一化约束本身。边界：它不说明汇聚点携带信息——汇聚点没有值向量可供输出，整行无效时输出全零；也不说明它能提供长程记忆。

    简化条件及其限制

    • 份额表假设所有可见槽位分数均为 0（$m=0$），只用于说明量级；实际份额随 query 的分数分布变化。
    • 解析解用单头、4 维的构造张量，验证的是分母构成，不含真实头维、量化与数值稳定实现细节。
    • 论文的困惑度数字按原值登记（不同模型、不同数据集），本页不重跑实验，也不据此比较模型质量。
    • 本页不评估可学习汇聚点对模型质量的净影响；checkpoint 头只提供参数形状，未读取权重数值。
