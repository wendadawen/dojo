NoPE · 无位置编码

NoPE 是在 Transformer 注意力计算中完全不施加任何显式位置编码的做法——不加位置嵌入、不加距离偏置、不旋转 query/key，让位置信息由因果掩码等结构隐式提供。

更新于 2026-08-09

是什么

位置编码（概念页待生成）是让注意力感知 token 顺序的显式机制，主流方案分三类：绝对位置编码给输入加位置嵌入、相对位置编码给注意力分数加距离偏置、RoPE（概念页待生成）旋转 query/key。NoPE 这三类操作都不做——它是位置编码方案集合中"什么都不做"的那个选项，而不是一种新的编码方式。

为什么需要它

  • 显式位置编码常带有与训练长度绑定的参数，外推到更长序列时需要插值或重缩放（如调整 RoPE 频率基数或用 YaRN），调参麻烦且未必有效。
  • NoPE 论文发现，最常用的位置编码方法（ALiBi、RoPE、APE）在长度泛化任务上并不适合外推。
  • NoPE 在推理与数学任务的长度泛化上优于这些显式方法，且不引入额外计算开销。

核心直觉

  • 注意力本身只做内容匹配：query 和 key 越像权重越高，它不直接关心 token 在第几位。
  • 因果掩码（概念页待生成）是位置信号的来源：decoder-only 中位置 t 只能看到前 t 个 token，每个位置可见的 token 集合不同，于是不同位置的输出不同——位置被结构隐式编码，不需要人工注入。
  • 双向注意力 + 无位置编码会失效：如果每个位置都能看到全部 token 且没有任何位置信息，交换顺序后每个位置输出不变（排列等变），模型无法区分词序。NoPE 能工作依赖因果掩码这个前提。
  • NoPE 不是"不能编码位置"：理论上 NoPE 能表示绝对和相对位置编码；用 SGD 训练时，它学到的注意力模式主要类似 T5 的相对位置编码——模型自己学出了一套近似相对 PE 的模式。

关键结论与边界

  • NoPE 在 decoder-only 上成立：隐式位置信号依赖因果掩码。在双向（非因果）注意力中，无位置编码会排列等变、无法区分顺序——这是 NoPE 的主要边界。成立条件：因果注意力。
  • Kimi K3 把 NoPE 用在所有 MLA 层：位置信息由相邻 KDA（KDA，已有概念页）层的循环门控与衰减机制隐式提供，MLA 只负责全局内容交互。这使得 K3 直接外推到 1M token 上下文，无需调整 RoPE 或 YaRN。成立条件：K3 的"NoPE MLA + 提供位置的 KDA"混合架构，不是纯 NoPE 堆叠。
  • "用 NoPE"不等于"没有位置信息"：K3 只是不在 MLA 层显式注入位置编码，整个模型仍有位置感知能力，只是由 KDA 隐式提供。
