DeepSeek-V4.1-Flash

一个 552B 主干加 196B Engram 参数、支持 1M 上下文的多模态 MoE 模型，核心设计目标是压榨长上下文推理的 KV 缓存与 prefill 成本：每 token 只占 890 字节全局 KV 缓存。

更新于 2026-09-10

问题背景

长上下文推理最贵的两项是 KV 缓存与 prefill 计算。序列涨到百万级时，若每个 token 都按标准注意力保存完整的键值，缓存体积会远超单卡显存；而 prefill 阶段要逐层处理全部输入，计算量也随长度增长。DeepSeek-V4.1-Flash 的设计目标就是把这两项同时压下去，把每 token 的全局 KV 缓存压到 890 字节。

核心机制

  1. 压缩把条目数降下来：每 $r$ 个 token 池化成一条键值条目，池化权重是组内 softmax 门控（逐通道可学习），不是平均；条目的位置编码取组起点 $j\cdot r$。压缩比为 2 的层每两个 token 一条，压缩比为 1 的层不做池化。
  2. 跨层共享把份数降下来：主干 40 层分成四组，每组只由第一个层生产一份主 KV，其余层读取。全模型只有层 2、8、14、20 四个 source 层真正产生主 KV，因此主 KV 的总量按四份折算，而不是四十份。
  3. FP4 把每条条目压小：主 KV 以 MXFP4 存储，512 维的数值部分占 256 字节，每 16 个通道一个 E4M3 缩放因子再占 32 字节，一条条目 288 字节。索引器另有 128 维的键，每条 68 字节。三项合起来，主 KV 720 字节加索引器 K 170 字节等于 890 字节/token。
  4. 解码器的全局 KV 由编码器末层投影：40 层被划成 20 层因果编码器与 20 层解码器，解码器各层的全局 KV 来自编码器末层隐状态 $H_{L/2}$ 的投影。既然这些键值在编码器跑完时就已确定，prefill 阶段只需要跑编码器半栈；滑动窗口 KV 依赖本层隐状态，不适用这条结论。
  5. 可见集由窗口与压缩条目拼成：每个 query 能看到本层窗口内最多 128 个原始位置，加上索引器选出的至多 512 个压缩条目。索引器先做块级筛选、再用候选池选 Top-512；尚未生成完的压缩条目在打分阶段就被排除。

关键结论与边界

  • 890 字节是压缩、共享、FP4 三件事叠加的结果，不能归因于其中任何一项：主 KV 720 字节、索引器 K 170 字节是两项独立开销。成立条件：1M 上下文、序列长度远大于窗口；若不做跨层共享，主 KV 一项就是 8352 字节/token。
  • prefill 8B 与 decode 16B 是每 token 激活参数量的口径，不是结构裁剪：decode 阶段仍要跑满 40 层。8B 之所以小，是因为 prefill 只需编码器就能拿到解码器所需的全局 KV。成立条件：报告口径不含嵌入层与输出头（各 0.6619B）。
  • Engram 与 DSpark 都不改变 890 字节的账：前者不产生键值、只把查表结果写回残差流；后者是草稿头，复用主干层的注意力输入。两个模块影响的是激活参数（Engram 每层 157.33M 稠密投影）与解码吞吐（DSpark 每块 5 个草稿位置）。
  • 本页区分「报告的设计描述」与「参考实现的实际行为」：报告描述的 prefill 半栈跳过、SWA 有界重放、持久化 1/8 属服务实现或训练结论，本页只登记宣称与成立条件，不给推导。

前置概念

  • KV cache：缓存哪些张量、为什么随序列长度增长。
  • MLA：在每 token 内部的维度上压缩键值，与本文的跨 token 池化方向不同。
  • MXFP4 量化：4 位浮点与逐 16 通道缩放因子的格式来源。
  • 滑动窗口注意力：窗口内的原始 KV 与它的环形缓冲。
  • 跨层 KV 复用：多个层共用一份全局 KV 的机制。
  • 稀疏注意力与索引器：用轻量打分选 Top-K 再算注意力的基本形态。
  • 注意力汇聚点：只进 softmax 分母的可学习标量。
  • 超连接、DeepSeek MoE、n-gram 哈希查表、推测解码：第 4、5 章激活参数与附加模块的前置。
