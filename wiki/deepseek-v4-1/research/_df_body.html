DeepSeek-V4.1-Flash 前向数据流

DeepSeek-V4.1-Flash 是 552B 主干加 196B Engram 参数、原生支持 1M 上下文的多模态 MoE 模型。40 层主干按 Causal Encoder–Decoder 切成两半：前 20 层是因果编码器，后 20 层是解码器，解码器的全局 KV 不由本层隐状态产生，而由编码器末层隐状态投影而来——配合解码器滑动窗口的有界重放，prefill 阶段因此可以止于半栈。全局 KV 由 CSA2（Compressed Sparse Attention 2，压缩稀疏注意力第 2 版）管理：每 $r$ 个 token 池化成一条压缩条目、同压缩比的层跨层共享、再由索引器从至多 512 个条目里稀疏选择；主 KV 以 FP4 存储（每条目 288 字节），窗口 KV 保持 FP8。每 token 全局 KV 缓存 890 字节。另有两个不改变缓存账的模块：Engram 哈希查表（插在层 1、14）与 DSpark 块式推测解码（3 个 MTP 块）。

3. 要点

整体结构：两半 + 四个缓存生产者

  • 沿深度：40 层被切成前 20 层编码器（层 0–19）与后 20 层解码器（层 20–39）。解码器的全局 KV 不由各自隐状态产生，而由编码器末层隐状态 $H_{L/2}$ 投影得到；与跨层共享结合后只有层 20（解码器的 Full 层）执行这次投影。因此 prefill 跑完编码器就已拿到解码器所需的全局 KV。
  • 沿缓存：全模型只有 4 个层生产主 KV——层 2、8、14、20，对应压缩比 2、2、2、1。其余压缩层读同组 source 层的缓存，因此主 KV 的份数是 4 而非 40。这一项与压缩比、FP4 一起把每 token 缓存压到 890 字节。
  • 前两层只有窗口：层 0、1 的压缩比为 0（compress_ratios 前两位），不复用也不生产全局 KV，只有滑动窗口注意力。
  • 沿宽度：每层 384 个路由专家取 top-6，另加 1 个共享专家恒激活；专家中间维 2304。路由专家占层参数量的绝大部分，但每 token 只动用其中 6 个。
  • 两条附加路径：Engram 在层 1、14 把 n-gram 哈希查表结果写进残差流（不产生缓存）；DSpark 用层 37、38、39 的注意力输入驱动 3 个草稿块（不改变主干缓存）。

注意力：单 KV 头 + 低秩投影 + 8 组输出

  • 查询侧：wq_a 把 5120 维压到 1280 维低秩，q_norm 归一化后再由 wq_b 展开成 $64 \times 512$ 维（64 个头、头维 512）。
  • 键值侧：只有 1 个 KV 头、头维 512，由 wkv 一次投影得到，经 kv_norm 归一化。多头查询共享同一份键值——这是把 KV 宽度压到 512 维的关键。
  • 输出侧：$64 \times 512 = 32768$ 维，先按 8 组各降到 1024 维（wo_a），再拼回 5120 维（wo_b）。o_groups=8 与 o_lora_rank=1024 是官方配置取值；分组的设计动机未在来源中说明，此处只陈述分组这一事实与其形状。
  • 位置：只旋转头维的末尾 64 维（源码用 x[..., -rd:] 切片，rd = rope_head_dim = 64）。频率表按层选择，不是按路径分：层 0、1（compress_ratio=0）用 base 10000 且关闭 YaRN；层 2–39（compress_ratio>0）用 base 160000 且开启 YaRN，该层的查询、窗口 KV 与压缩条目共用同一份频率表（model.py L680–687 按层分支，L706、L758、L772 三处调用同一个 freqs_cis）。

可见集：窗口 128 个位置 + Top-512 压缩条目

  • 每个 query 能看到本层窗口内最多 128 个原始位置（FP8 存储），加上该层所属压缩比组中由索引器选出的至多 512 个压缩条目。
  • 压缩条目按组编号，组 $j$ 覆盖 token $[jr,(j+1)r)$，位置取 $j\cdot r$；只有整组出现后条目才可达，可达条数是 $\lfloor(i+1)/r\rfloor$。
  • 解码器还有一级候选池：建池层（层 20）按块打分选出 2048 个块、每块 8 个位置，共 16384 个候选；后续 Reindex 层只在这个池内选 Top-512。

4. CED：解码器的全局 KV 从哪里来

报告对这一段给出的形式是 $C_l = H_{L/2}W_l^{KV}$、$Z_l = H_{L/2}W_l^{Z}$（$l > L/2$）：解码器各层的键值条目由编码器末层隐状态投影得到，投影权重逐层不同。共享的是输入 $H_{L/2}$，不是投影结果。

与跨层共享结合后还有一层收窄：真正执行这次投影的只有被指派为 Full 模式的解码器层。本模型的配置里这个层是层 20，参考实现中的表现是「层 20 的压缩器读取它自己的注意力输入」，而第 20 层的注意力输入正是第 19 层的输出，与公式里的 $H_{L/2}$ 对上。

滑动窗口 KV 不能一起省。窗口 KV 是最近位置的原始精度副本，必须由本层经过完整计算后的隐状态生成；第 $l$ 层的窗口 KV 需要第 $l$ 层的隐状态，而后者要等第 $l-1$ 层算完，这条依赖链无法用「读编码器输出」替代。服务端的替代办法是有界重放：只重算最后 $n_{\text{win}}$ 个位置，因为更早的位置已滑出可见集。参考实现中不含该分支，它属服务实现。

5. 稀疏选择：从打分到槽位

选择的输入是「全部因果可见的压缩条目」，输出是每个 query 的 Top-512 下标。三步：

  • 打分：索引器用 32 个头对条目打分，每头的贡献是 $\mathrm{ReLU}(q_h\cdot k_j)$ 再乘该头权重，按头求和。
  • 块级筛选：把位置切成大小 8 的块，块分取块内最大索引分，从建池层（层 20）选出 2048 个块。最新块只填了一部分，会被钉住以免被更早的完整块压过。
  • 位置级选择：候选池内的 16384 个位置按索引分取前 512，与窗口槽位拼进同一次稀疏注意力调用。

不可达的条目（编号不小于 $\lfloor(i+1)/r\rfloor$）在打分阶段就被置为 $-\infty$。注意力本身对选中槽位做加权求和，并把每头一个可学习的汇聚点标量加在分母上——汇聚点只进分母、不参与取最大值，也不携带值向量。

三种层模式决定了「谁算、谁复用」：Full 层自算主 KV、索引器 K 与 Top-K；Reindex 层复用最近的主 KV 与索引器 K，但自己重算 Top-K（在候选池内）；Reuse 层连 Top-K 一起复用，不算索引分。模式由配置静态决定。

6. Engram 与 DSpark

Engram 插在层 1 与层 14。它从当前位置往前取长度 2、3、4 的连续片段，各用 8 个哈希函数映射到嵌入表下标，共 24 个下标（每 token 取回 $24\times256=6144$ 个表元素）；取回的向量经一个稠密投影写回残差流，写入强度由「流与查表结果的归一化点积取绝对值开方、保留符号后过 sigmoid」的门控决定。两层嵌入表合计约 196B 参数，但每 token 只取回六千多个元素；真正计入激活的是那个稠密投影，每层 157.33M。

DSpark 是块式推测解码的草稿头：3 个 MTP 块，每块一次前向产出 5 个草稿位置。输入取主干层 37、38、39 的注意力输入，先在超连接副本维取均值，再把三层结果沿特征维拼接（main_proj.weight 形状 [5120, 15360] 即此）。草稿块自身是 MoE 结构，128 个专家取 top-3；末块另带 Markov 头（秩 256）与置信头，用于决定接受几个草稿。它不产生主干缓存，只提高 decode 吞吐。

7. 核对方式

结构与形状：用 HTTP Range 请求读取全部 48 个 safetensors 分片的 JSON 头（未下载权重本体），得到 96085 个张量的名称、形状与 dtype。以此交叉验证配置与源码推断：层数、专家数、各模块形状、MTP 张量数。

公式与数值行为：按官方实现逐行语义复现各算子，用官方配置的真实维度在随机张量上实跑。已完成对照包括压缩器池化（与独立重实现逐位一致）、Sinkhorn 迭代（float64 最大差 8.9e-08）、路由打分（indices 完全一致、权重最大差 0）、RoPE 频率、稀疏注意力（与解析解逐元素差 0）、FP4 量化误差。

缓存与激活账：verify_cache_size.py 按配置与源码常量推出每 token 890 字节；verify_active_params.py 用真实张量头加配置专家数算得半栈 7.8929B / 7.5758B，并由 verify_halfstack_diff.py 分解两者差额。

端到端数据流：构造等比缩小但保留全部结构特征的模型（dim 64、7 层），跑通 prefill 与逐 token decode。由此复现并定位了参考实现的一处行为：压缩比大于 1 的层在解码步的组未填满时读到其他层发布的索引键。

实测脚本与原始输出存档于 wiki/deepseek-v4-1/research/；形状明细见 ckpt/verify_dataflow_shapes.out。
