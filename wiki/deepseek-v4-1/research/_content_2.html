3. 一个 query 看到哪些位置——窗口、压缩条目与两级筛选

第 1 章算出缓存里有什么，第 2 章说明这些条目由谁产生。两者都还没回答一个更直接的问题：给定层号和 query 位置，这次注意力到底把哪些键值取出来算？这一章把「哪些位置可见」与「可见的位置里选哪些」分开说——前者是规则，后者是打分结果。

3.1 可见集由两部分拼成

全局 KV 是压缩摘要，粒度粗；只靠它，模型对最近几个 token 的分辨能力会被池化抹平。所以每层的可见集由两部分拼成：

  • 窗口部分：本层滑动窗口内的原始 KV，最多 $n_{\text{win}}=128$ 个位置。这部分未压缩、保持 FP8，位置编码用原序列下标（见 滑动窗口注意力）。
  • 压缩部分：该层所属压缩比组的压缩条目中被索引器选中的 Top-$K$ 个，$K=512$。条目按组编号，第 $j$ 组覆盖 token $[jr,(j+1)r)$，位置编码取 $j\cdot r$（见 RoPE）。

这些取值全部来自官方配置，并与真实张量头的形状一致：窗口 128、索引 Top-512、候选 $2048\times8=16384$、索引头 $32\times128$、KV 头 $1\times512$[N4]。

两部分的槽位在下标空间里用同一个索引表表示：窗口部分按位置索引，压缩部分按条目编号索引。它们拼进同一次稀疏注意力调用，也就是说 softmax 在两部分槽位的并集上做一次归一化，而不是分别算两次再合并[C2]。这一点在 3.5 节的公式里会看得更清楚。

3.2 可达条目数：整组出现过才算

压缩条目不是想用就有。一个条目由 $r$ 个 token 池化而来，只有这 $r$ 个 token 都出现之后，条目才存在。于是「编号 $j$ 的条目是否可达」有明确判据：整组覆盖的最后一个位置 $(j+1)r-1$ 必须不超过当前 query 位置 $i$。

把这条判据写成条目数[F3]：

$$n_{\text{reach}}(i) = \left\lfloor \frac{i+1}{r}\right\rfloor \quad(\text{prefill}),\qquad n_{\text{reach}}(s) = \left\lfloor \frac{s+1}{r}\right\rfloor \quad(\text{decode})$$
  • $i$：query 在序列中的位置（0 起）；
  • $s$：解码步编号；
  • $r$：该层的压缩比；
  • $n_{\text{reach}}$：从条目 0 起连续可达的条目条数。编号不小于该值的条目在打分阶段被置为 $-\infty$，不参与竞争。

用本页贯穿的算例核算。该算例追踪位置 $i=4999$ 的 query 在层 2 与层 20 上的开销与可见范围（下称穿越示例）：在压缩比 $r=2$ 的层上，它的可达条目数是 $\lfloor 5000/2\rfloor = 2500$ 条，覆盖 token $0$ 到 $4999$——正好是它能看到的全部历史。同一条 query 在压缩比 $r=1$ 的层上，可达 5000 条。这也解释了为什么压缩比 1 的层更贵：它保留的位置更细。

可达性判据对 prefill 与 decode 两种形态都成立，实测在等比缩小模型上逐位置一致[N7]。

注意判据是「整组出现」而不是「组首出现」。位置 $i=4$、$r=2$ 时，组 2 覆盖 token $[4,5]$，它的组首 $4$ 已经出现，但组尾 $5$ 还没出现，因此该组尚不可达，可达数是 $\lfloor 5/2\rfloor = 2$ 而不是 3。把判据写成「组首出现」会把一条凭空多出的条目算进可见集。

展开：可达条目数的枚举核对（构造示例）

构造示例（用 $r=2$ 的小规模序列，便于手算）。逐位置列出「按整组出现」判据枚举到的条目数，与公式对比：

query 位置 $i$已完成的组枚举条目数$\lfloor (i+1)/2\rfloor$
0无（组 0 覆盖 0–1，组尾未出现）00
1组 011
2组 011
3组 0、组 122
4组 0、组 122

公式与枚举逐行一致。位置 $i=0$ 时没有任何条目可达——它只能看窗口里的内容，这与「序列第一个 token 没有历史可压缩」的直觉吻合。第 3.4 节的代码会把这个核对扩展到更大的规模。

3.3 两级筛选：先在块级别缩范围，再在位置级别选 Top-512

可达条目随上下文线性增长：1M 上下文、压缩比 2 时约 50 万条，而 $K$ 只有 512。要选得准，直接对全部可达条目逐条打分当然可以，但解码时每个 query 都重算一遍代价不小。分层稀疏索引器的做法是把选择拆成两级[C7]。索引器本身是稀疏注意力的旁路打分模块，其中「用轻量打分选 Top-K 再算注意力」这一基本形态见 稀疏注意力与索引器；本页只讲这一模型在它之上加的两级筛选：

  1. 块级：把位置切成大小 8 的块，块分取块内最大的索引分[F4]。建池层为每个 query 选出 2048 个块。
  2. 位置级：这些块覆盖的位置构成候选池，$2048 \times 8 = 16384$ 个候选位置；后续层只在这个池内选 Top-512。

在长上下文下，第二级的搜索范围从随上下文线性增长的「全部可达条目」变为固定的 16384 个候选位置，每次选择的代价因此与上下文长度无关。缩减倍数随上下文增长：1M 上下文、$r=2$ 时约为 30 倍。短上下文下可达条目本身少于 16384，候选池不起缩减作用。两级用的是同一套索引分——每个 query 对每条压缩条目的打分 $\sum_h w_{q,h}\mathrm{ReLU}(q_h\cdot k_j)$[F2]，区别只在聚合粒度。

有一个边界要单独说明：最新块通常只填了一部分（query 自己所在的位置还没凑满 8 个），若按常规打分，它的块分可能被更早的完整块压过而落选，从而让 query 看不到自己最近的历史。实现对此的处理是把最新块钉住：无论分数高低都保留在候选池内[C7]。

3.4 三模式：谁算主 KV、谁算 Top-K

到这里还有一个问题：如果每一层都要自己算主 KV、自己算索引分，第 1 章说的「只有 4 个层生产主 KV」就不成立了。实际上每个压缩比大于 0 的层静态属于三种模式之一，区别在于主 KV 与索引选择各由谁做[C2]：

模式主 KV 与索引器 KTop-K 选择
Full自己算自己算，并建立候选池
Reindex复用最近一份自己算（在候选池内）
Reuse复用最近一份复用最新的选择，不算索引分

三种模式由配置静态决定，不是运行时按内容切换。实测得到的分工是 Full 层为 2、8、14、20，Reindex 层为 24、28、32、36，其余 30 个压缩层为 Reuse；层 0、1 没有全局 KV，属于纯滑动窗口层。Full 层恰好就是第 1 章说的四个 source 层——这不是巧合：只有自己算主 KV 的层才有索引器 K 可以发布，其余层的索引器只能读别人的[C2]。

「Reuse」这个名字容易引起误解：它复用的是选择结果，不是可见集。不同压缩比组的主 KV 不同，条目编号与位置的换算关系也不同，跨组不能共用选择。因此复用的前提是同一份主 KV——这也是为什么共享发生在同压缩比的组内（见 跨层 KV 复用）。

补充：参考实现在组未填满时的一个已实测行为

参考实现里「发布索引器 K」这一步挂在「本层自己拥有主 KV 且本次前向产出了主 KV」的条件分支内，而「读取索引器 K」是无条件执行的。压缩比大于 1 的层在解码步中每隔 $r$ 步才产出一次主 KV，于是存在若干步它读到的是上一次的前向中最后发布者的缓存——在真实配置下是压缩比为 1 的层 20[C10]。

本机实测在缩小模型上复现了这一点：偶数解码步层 2 读到的键与层 4 的缓存一致，奇数步读到自己的。这条记录只描述该参考实现的行为，用于说明「prefill 与 decode 的选择结果可以不同」，不外推到服务实现，也不影响可见性规则本身——可达性判据对两种形态都成立。

3.5 选中的槽位怎么参与计算

可见集和选择都定了，最后一步是注意力本身。稀疏注意力只对选中的槽位做加权求和，并把每头一个可学习的汇聚点标量加在分母上[F8]：

$$o = \frac{\sum_{t\in\mathcal{T}} e^{\,q\cdot k_t/\sqrt{d}\,-\,m}\,v_t}{\sum_{t\in\mathcal{T}} e^{\,q\cdot k_t/\sqrt{d}\,-\,m} + e^{\,\text{sink}-m}},\qquad m = \max_{t\in\mathcal{T}}\frac{q\cdot k_t}{\sqrt{d}}$$
  • $\mathcal{T}$：本次选中的槽位集合，含窗口槽位与压缩条目槽位；
  • $q, k_t, v_t$：query、第 $t$ 个槽位的键与值；
  • $d$：注意力头维；
  • $\text{sink}$：该头可学习的汇聚点标量，作为 logit 使用；
  • $m$：选中槽位分数的行最大值，用于数值稳定；分子分母共享同一个 $m$；
  • $o$：该头的输出。

三点值得单独指出。第一，$m$ 只由选中槽位的分数取得，汇聚点不参与取最大值；分子分母同时乘 $e^{-m}$，所以 $m$ 的取值不改变结果，它只是数值稳定手段。第二，汇聚点只出现在分母：它提供一个「倾倒注意力」的去处，本身不携带任何值向量，因此不影响分子（详见 注意力汇聚点）。第三，索引为 $-1$ 的占位槽位在分子分母都不贡献——它们既不被取值，也不进入指数和。

窗口槽位与压缩槽位在这里合流：$\mathcal{T}$ 是两者的并集，softmax 在并集上做一次归一化。这也意味着窗口位置与压缩条目在竞争同一份注意力预算，而窗口并没有被赋予额外权重——谁的分高谁拿得多。

3.6 可达性与 Top-K 语义的复算

下面这段代码验证两件事：可达条目数公式与「整组出现」的枚举判据一致；以及不可达条目被置为 $-\infty$ 之后，Top-$K$ 选择不会把它们选进来。

代码：可达条目数与 Top-K 选择的语义复算 
"""复算两个机制：压缩条目可达数、Top-K 选择语义。纯 Python，无第三方依赖。"""


def reachable_formula(i, r):
    """F3 公式：floor((i+1)/r)"""
    return (i + 1) // r


def reachable_bruteforce(i, r):
    """按「整组出现」逐组枚举：组 j 覆盖 [jr, (j+1)r)，组尾 <= i 才算可达"""
    count = 0
    j = 0
    while (j + 1) * r - 1 <= i:
        count += 1
        j += 1
    return count


print("== 1. 可达条目数：公式 vs 枚举 ==")
bad = 0
for r in (1, 2, 4):
    for i in range(0, 200):
        if reachable_formula(i, r) != reachable_bruteforce(i, r):
            bad += 1
            print(f"  不符: i={i} r={r}")
print(f"  r in (1,2,4), i in 0..199 全部比对：不符 {bad} 处")

for (i, r) in ((4999, 2), (4999, 1), (4, 2)):
    n = reachable_formula(i, r)
    print(f"  i={i} r={r}: 可达 {n} 条（覆盖 token 0..{n * r - 1}）")

print()
print("== 2. Top-K 选择：不可达条目置 -inf ==")
NEG = float("-inf")
n_entries, r, i, K = 12, 2, 9, 4
n_reach = reachable_formula(i, r)
raw = [3.0, 1.0, 4.0, 1.5, 2.0, 0.5, 2.5, 3.5, 0.8, 1.2, 2.2, 0.9]

naive_order = sorted(range(n_entries), key=lambda j: (-raw[j], j))
masked = [raw[j] if j < n_reach else NEG for j in range(n_entries)]
masked_order = sorted(range(n_entries), key=lambda j: (-masked[j], j))

print(f"  槽位总数 {n_entries}，可达 {n_reach} 条，K={K}")
print(f"  全部槽位分数  : {raw}")
print(f"  未屏蔽时前 {K} 名: {sorted(naive_order[:K])}  <- 含未完成组的槽位")
print(f"  屏蔽后前 {K} 名  : {sorted(masked_order[:K])}")
print(f"  屏蔽后选中项全在可达范围内: "
      f"{all(j < n_reach for j in masked_order[:K])}")

预期输出：

== 1. 可达条目数：公式 vs 枚举 ==
  r in (1,2,4), i in 0..199 全部比对：不符 0 处
  i=4999 r=2: 可达 2500 条（覆盖 token 0..4999）
  i=4999 r=1: 可达 5000 条（覆盖 token 0..4999）
  i=4 r=2: 可达 2 条（覆盖 token 0..3）

== 2. Top-K 选择：不可达条目置 -inf ==
  槽位总数 12，可达 5 条，K=4
  全部槽位分数  : [3.0, 1.0, 4.0, 1.5, 2.0, 0.5, 2.5, 3.5, 0.8, 1.2, 2.2, 0.9]
  未屏蔽时前 4 名: [0, 2, 6, 7]  <- 含未完成组的槽位
  屏蔽后前 4 名  : [0, 2, 3, 4]
  屏蔽后选中项全在可达范围内: True

验证的机制：第一段对应 3.2 节的可达性公式——$\lfloor(i+1)/r\rfloor$ 与「整组出现」的逐组枚举在 $r\in\{1,2,4\}$、$i\in[0,200)$ 上完全一致；其中 $i=4999$ 的两行就是穿越示例里的 2500 与 5000。第二段对应 3.3 节的选择语义：同一个分数列表，屏蔽不可达条目前后选出的 Top-4 不同。

观察重点：看第二段两组结果的差别。不屏蔽时前 4 名是槽位 0、2、6、7——槽位 6、7 属于尚未完成的组，它们凭分数 2.5 与 3.5 挤进了名单，而 3.5 甚至是全场最高分之一。屏蔽后前 4 名变成 0、2、3、4，全部落在可达的 0–4 之内。这说明「置 $-\infty$」不是可有可无的收尾：没有它，未生成的条目会参与竞争并被选中，注意力就会读到并不存在的槽位。第一段则说明公式与逐组枚举没有边界偏差，$i=4$、$r=2$ 这一行尤其要看清——它给的是 2 条（覆盖 token 0–3），组 2 因为组尾 5 尚未出现而不可达。

简化条件：示例用纯 Python 列表模拟索引分与选择，未包含真实实现中的分块量化、张量并行切分与候选池掩码；3.3 节的块级聚合也未涉及，代码只覆盖位置级的可达性与选择。它验证的是规则，不是性能。

本章问题

  1. 压缩比 2 的层上，位置 4999 的 query 能看到多少个压缩条目？公式里为什么是 $\lfloor(i+1)/r\rfloor$ 而不是 $\lfloor i/r\rfloor+1$？

    解答：2500 条；判据是「整组出现」，组尾不超过 query 位置才算可达

    位置 $i=4999$、$r=2$ 时 $\lfloor 5000/2\rfloor=2500$ 条，覆盖 token 0 到 4999，正好是全部历史。

    两个式子的差别在边界：$\lfloor i/r\rfloor+1$ 等价于「组首出现即可达」，而 $\lfloor(i+1)/r\rfloor$ 要求「组尾也出现」。用 $i=4$、$r=2$ 检验：组 2 覆盖 token 4–5，组首 4 已出现但组尾 5 是未来，因此该组尚未完成池化、条目不存在。前者给 3 条，后者给 2 条——正确答案是 2 条。只有当 $i$ 恰好是组尾（$i+1$ 被 $r$ 整除）时两个式子才相等，所以边界上的差别容易在实际使用中被忽略。

  2. 候选池起什么作用？为什么最新块要被「钉住」？

    解答：把 Top-512 的搜索范围从随上下文增长的条目数变为固定 16384 个候选；不钉住最新块会让 query 看不到自己最近的历史

    可达条目随上下文线性增长（1M 上下文、压缩比 2 时约 50 万条），而 $K$ 只有 512。分层索引器先用块级打分（块分取块内最大值）从建池层选出 2048 个块，块内 8 个位置构成 16384 个候选位置，后续层只在这个池内搜索 Top-512。这样每次选择不必重扫全部可达条目。

    最新块只有部分位置被填充，按常规打分它的块分（块内最大值）虽不至于为零，但若按平均或按「完整块才入选」处理，它很容易落选，导致 query 看不到紧邻自己的那几个位置。钉住最新块保证这部分历史一定进入候选池。这一机制只在解码器使用，编码器层不做候选限制。

  3. 为什么 prefill 和 decode 的选择结果可能不同，但可见性规则相同？

    解答：可见性由「组是否完成」决定，两种形态用同一判据；选择结果取决于索引分，而参考实现在某些解码步读到了别的层的索引键

    可达性判据是「整组覆盖的最后一个位置不超过当前 query」，prefill 的 $\lfloor(i+1)/r\rfloor$ 与 decode 的 $\lfloor(s+1)/r\rfloor$ 是同一判据在两种形态下的写法，实测逐位置一致。

    选择结果则取决于索引分，而索引分来自索引器。参考实现中「发布索引器 K」挂在条件分支内、「读取索引器 K」无条件执行，压缩比大于 1 的层在解码步的组未填满时读到的是上一次前向最后发布者的缓存（真实配置下为层 20），因此同一位置在 prefill 与 decode 下可能得到不同的 Top-K。这条差异是参考实现的已实测行为，只说明「选择结果不保证逐位一致」，不改变可见性规则，也不外推到服务实现。
