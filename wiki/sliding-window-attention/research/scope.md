# 滑动窗口注意力（SWA）内容范围

## 2.1 概念含义

- **名称**：滑动窗口注意力 / Sliding Window Attention（SWA），也称局部窗口注意力（local/windowed attention）
- **简要定义**：让每个 query 只关注序列中最近 $W$ 个位置的注意力变体，把每层的注意力代价从与序列长度平方相关降为线性，并让 KV cache 大小与序列长度无关。
- **正式定义**：第 $k$ 层位置 $i$ 的隐状态 $h_i$ 只关注上一层中位置落在 $[i-W, i]$ 的隐状态；窗口固定、随位置滑动。因逐层堆叠，信息每层最多前移 $W$，$k$ 层后 $h_i$ 可间接访问输入层距离至多 $k\times W$ 的 token <sup>[C1]</sup>。推理时窗口 KV 用环形缓冲存储，位置 $i$ 的键值写入槽位 $i \bmod W$，因此缓存大小固定为 $W$ 条、不随序列增长 <sup>[C2]</sup>。
- **本文采用的语境**：以 Mistral 7B 论文给出的形式（固定窗口 + 环形缓冲）为一般定义；以 DeepSeek-V4.1-Flash 的实现（$W=128$、窗口 KV 为 FP8、与压缩全局 KV 拼接）作为当代实例。
- **包括什么**：可见集规则、复杂度与缓存账、层堆叠感受野、环形缓冲的索引与位置编码
- **不包括什么**：全局 KV 压缩（属 CSA2）、注意力汇聚点的机制细节（另有专页）、具体 kernel 实现（FlashAttention 的窗口分块）
- **相邻概念**：因果掩码（限制"不看未来"，窗口进一步限制"不看太远"）；稀疏注意力（按分数挑位置，而窗口按距离取固定数量）

## 2.2 学习目标

### Q1：滑动窗口注意力把 query 的可见集限制成了什么？
- 完成答案：只保留上一层中位置在 $[i-W, i]$ 的隐状态，即"最近 $W$ 个位置"；序列开头不足 $W$ 个时只看到已存在的部分（实现上用 $-1$ 槽位占位，不参与打分）。
- 为什么是核心目标：可见集是理解后续一切账（复杂度、缓存、感受野）的起点。
- 依赖内容：因果掩码、标准注意力。

### Q2：它省下多少计算与显存？
- 完成答案：每层打分次数从 $N^2$ 降为 $N\cdot W$（$N=1$M、$W=128$ 时少 8192 倍）；KV cache 固定为 $W$ 条，$W=128$、$512$ 维、FP8 时每层 64 KiB，40 层共 2.50 MiB，与序列长度无关。
- 为什么是核心目标：这是 SWA 被采用的全部理由，也是"窗口单独够不够"的前提。
- 依赖内容：注意力打分次数的计数方式、KV cache 的字节构成。

### Q3：层堆叠能补回多少"看得远"的能力？什么时候不够？
- 完成答案：信息每层最多前移 $W$，$k$ 层后感受野约 $k\times W$；V4.1-Flash 主干 40 层即 5120 个 token，只占 1M 上下文的 0.49%，因此单靠窗口无法覆盖长上下文，需要另加全局 KV（V4.1 用压缩的全局 KV 补这一段）。
- 为什么是核心目标：把"窗口注意力"与"长上下文"的关系说清，避免误以为窗口能替代全局注意力。
- 依赖内容：Q1、Q2 的结论；层间信息传播。

### Q4：环形缓冲怎么做到缓存不随长度增长？位置编码怎么处理？
- 完成答案：位置 $i$ 的键值写入槽位 $i \bmod W$，位置超过 $W$ 后覆盖最旧的一条；prefill 时每个 query 各自算出一行可见槽位（含 $-1$ 占位），decode 时单个 query 看到整个环（按最旧到最新列出）。V4.1 的 RoPE 使用原序列位置（prefill 取 `freqs_cis[start:start+seqlen]`，decode 取 `freqs_cis[start]`），因此窗口内相对距离不超过 $W$；作为对照，StreamingLLM 为把初始 sink token 塞进缓存，改用"缓存内位置"。
- 为什么是核心目标：环形缓冲是 SWA 能落地的关键工程件，索引规则错一位就会静默改变可见集。
- 依赖内容：RoPE 与相对位置；注意力掩码。

## 2.3 内容分级

**核心内容**：可见集规则（Q1）；复杂度与缓存账（Q2）；感受野 $k\times W$（Q3）；环形缓冲索引与位置处理（Q4）
**辅助内容**：窗口失效现象与注意力汇聚点（服务于 Q3 的边界）；V4.1 与 Mistral 的窗口取值对照
**扩展内容**：其他局部注意力形式（Longformer 的 dilated window 等）——排除，不影响四个目标

## 2.6 常见误解和适用边界

| 错误理解 | 正确结论 | 形成原因 |
|---|---|---|
| "窗口注意力等价于把长文本截断成 W 个 token" | 每个 query 的窗口不同且随位置滑动，位置 $i$ 仍能通过层堆叠间接访问 $i-kW$ 处的信息 | 把"窗口"理解成"只看一段固定文本" |
| "窗口注意力能替代全局注意力做长上下文" | 感受野只有 $k\times W$，V4.1 的 40 层是 5120 个 token，仅占 1M 的 0.49% | 忽略层堆叠的线性增长上限 |
| "环形缓冲会丢信息，所以窗口注意力不可靠" | 覆盖的是"超出窗口的最旧位置"，那些位置本就不在可见集内；但若把 sink token 也覆盖掉，模型会崩（见注意力汇聚点） | 混淆"窗口外"与"sink" |
| "decode 时 query 看到的槽位顺序与 prefill 不同，所以结果会不同" | 槽位顺序不同但集合相同；稀疏注意力对槽位独立处理，顺序不影响结果（实测 300 步位置集合完全一致） | 把顺序当成语义 |

**适用边界**：窗口取值 $W$ 决定单层可见距离；序列长度小于 $W$ 时窗口不产生任何截断（此时与全注意力等价）。本页的字节账按单序列、单层窗口 KV 计算，不含压缩全局 KV 与索引器缓存。
