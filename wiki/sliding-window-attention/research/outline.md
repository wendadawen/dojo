# 滑动窗口注意力 文章大纲

## 4.1 页面开头

**具体问题**：一个 100 万 token 的请求，如果每个 token 都要回头看之前所有 token，缓存会涨到几百 GiB。滑动窗口注意力把每个 query 的可见范围砍到最近 $W$ 个位置——代价是"看不远"，靠层堆叠一层层接力补回来。本文回答：窗口限制了什么、省下多少、接力能补多远、环形缓冲怎么做到缓存不随长度增长。

**组件**：`blockquote.meta`、`callout-blue`（范围与口径）、`learning-goals`（4 条）、`misconceptions`（4 条）。

## 4.2 章节设计

### 第 1 章 窗口把可见集切成"最近 $W$ 个位置"

- **章节问题**：滑动窗口注意力把 query 的可见集限制成了什么？
- **完成答案要点**：位置 $i$ 只关注上一层位置在 $[i-W, i]$ 的隐状态；序列开头不足 $W$ 时只看到已存在的部分，实现上用 $-1$ 槽位占位、不参与打分；与因果掩码的区别是"因果管方向、窗口管距离"。
- **对应范围**：Q1；C1、C4；F2
- **正文要点**：可见集的定义；与全注意力的对照（同样一个 query，可见槽位数从 $i+1$ 变成 $\min(i+1, W)$）；实现里窗口槽位与压缩槽位拼进同一次注意力调用（引 V4.1 实例，细节指向 CSA2 主题）
- **材料**：对照表格（全注意力 vs 窗口的可见集与代价）；`details` 补充 $-1$ 槽位语义
- **前置知识**：标准注意力、因果掩码
- **本章问题**：2 条

### 第 2 章 省下的是打分次数与缓存字节

- **章节问题**：窗口化省下多少计算与显存？
- **完成答案要点**：每层打分次数从 $N^2$ 降到 $N\cdot W$（$N=1$M、$W=128$ 时少 8192 倍）；KV cache 固定 $W$ 条，V4.1 中每层 64 KiB、40 层 2.50 MiB，与序列长度无关；窗口 KV 保持 FP8 是因为它对量化更敏感。
- **对应范围**：Q2；C2、C4；F3；N2、N5
- **正文要点**：打分次数的计数；环形缓冲把缓存变成常量（"缓存不再增长"的含义）；精度选择
- **材料**：表格（$N=4096/131072/1048576$ 的打分次数对照）；`details` 展开 64 KiB 与 2.50 MiB 的加总
- **前置知识**：KV cache
- **本章问题**：2 条

### 第 3 章 层堆叠接力：感受野 $k\times W$ 与它的天花板

- **章节问题**：层堆叠能补回多少"看得远"的能力？什么时候不够？
- **完成答案要点**：信息每层最多前移 $W$，$k$ 层后约 $k\times W$；V4.1 主干 40 层即 5120 个 token，占 1M 上下文的 0.49%，因此窗口之外必须另加全局可见性；只用窗口（丢弃初始 token）会让模型崩，原因是初始 token 承担注意力汇聚点。
- **对应范围**：Q3；C1、C3；F1；N1、N3、N4、N6
- **正文要点**：逐层前移的机制；5120 与 1M 的落差；窗口失效的两种情形（窗口外无信息 / 移除 sink）
- **材料**：结构图（层堆叠接力）；`details` 补充 StreamingLLM 的 PPL 对照数字
- **前置知识**：注意力汇聚点（递归生成页）
- **本章问题**：2 条

### 第 4 章 环形缓冲：槽位、覆盖与位置编码

- **章节问题**：环形缓冲怎么做到缓存不随长度增长？位置编码怎么处理？
- **完成答案要点**：位置 $i$ 的键值写入槽位 $i \bmod W$，超过 $W$ 后覆盖最旧；prefill 每个 query 各算一行可见槽位，decode 单个 query 看到整个环（最旧到最新列出），两者映射回的位置集合实测完全一致；V4.1 的 RoPE 用原序列位置，窗口内相对距离不超过 $W$。
- **对应范围**：Q4；C2、C5；F2；N7
- **正文要点**：槽位映射与覆盖；两种索引形态及其实测等价；位置口径（V4.1 用原位置，StreamingLLM 为 sink 用缓存内位置）
- **材料**：公式 F2；可运行代码（环形缓冲槽位映射，含真实输出）；`details` 补充 decode 槽位列表的生成规则
- **前置知识**：RoPE、KV cache
- **本章问题**：2 条

## 4.3 讲解顺序

第 1 章先定可见集，第 2 章算代价（依赖第 1 章的"每个 query 只看 $W$ 个"），第 3 章处理"看不远"的后果并引出全局 KV 与 sink（依赖前两章），第 4 章回到实现（依赖第 2 章的常量缓存结论）。第 3 章开头用一句说明从"省了多少"转到"代价是什么"。

## 4.4 贯穿示例

**场景**：$W=128$、主干 40 层、上下文 1M 的模型里，追踪位置 4999 的 query。

1. 第 1 章：它在第 $k$ 层只看到上一层位置 4872–4999（最多 128 个）
2. 第 2 章：为它算一次注意力只需 128 次打分（全注意力要 5000 次）；缓存侧 128 槽固定
3. 第 3 章：它能间接看到输入层 4999 − 40×128 = 4999 − 5120 < 0，即整段都在感受野内；但若上下文是 1M，位置 999999 的 query 只能间接看到 994879 之后的内容
4. 第 4 章：它的 KV 写入槽位 4999 mod 128 = 7
