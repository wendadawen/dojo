滑动窗口注意力（SWA）

让每个 query 只关注最近 $W$ 个位置的注意力变体：用固定的环形缓冲把 KV cache 变成常量，把每层注意力代价从与序列长度平方相关降为线性。

更新于 2026-09-10

问题背景

标准注意力里，位置 $i$ 的 query 要看到从序列开头到 $i$ 的全部位置。这带来两个随序列长度增长的代价：每层的注意力打分次数约为 $N^2$（$N$ 为序列长度），KV cache 要保存 $N$ 条键值。上下文从几千涨到百万级时，缓存体积会超过单卡显存，计算量也同步膨胀。滑动窗口注意力把每个 query 的可见范围截断到最近 $W$ 个位置，让这两项代价都不再随长度增长。

核心机制

  1. 可见集被切成「最近 $W$ 个位置」：位置 $i$ 只关注上一层最近 $W$ 个位置，即 $[i-W+1, i]$（来源论文写作 $[i-W, i]$，实现取最近 $W$ 个）。因果掩码管「不看未来」，窗口管「不看太远」，两者叠加；序列短于窗口时窗口不起作用。
  2. 代价从平方降到线性：每层打分次数从约 $N^2$ 变成约 $N\cdot W$，倍数正好是 $N/W$。DeepSeek-V4.1-Flash 取 $W=128$，在 1M 上下文下少 8192 倍。
  3. KV cache 变成常量：窗口 KV 用环形缓冲存储，位置 $i$ 写入槽位 $i \bmod W$，超过 $W$ 后覆盖最旧的一条。该模型每层 64 KiB、主干 40 层共 2.50 MiB（另有 3 个草稿层各一份同尺寸缓存），与序列长度无关。
  4. 层堆叠把窗口接力成感受野：信息每层最多前移 $W$，$k$ 层后约 $k\times W$。40 层、$W=128$ 即 5120 个 token，只占 1M 上下文的 0.49%，所以窗口之外还需要另一路全局可见性。
  5. 索引分两种形态：prefill 时每个 query 各得一行可见槽位（不足处填 $-1$），decode 时唯一的 query 看到整个环；两者映射回的位置集合相同。位置编码用原序列下标，不用槽位下标。

关键结论与边界

  • 窗口不是「把文本截断成一段」：每个位置的窗口都不同且随位置滑动，远处信息仍能经层堆叠间接到达，但保真度随距离下降。成立条件：窗口逐层固定、层间串联。
  • 单靠窗口做不了长上下文：感受野上限是 $k\times W$，DeepSeek-V4.1-Flash 只有 5120 个 token。成立条件：$k$ 与 $W$ 均为有限值，长上下文的其余部分必须由另一路全局可见性补足。
  • 只保留窗口、把序列开头的位置一起丢弃会让模型崩溃，因为开头位置承担注意力汇聚点的角色。成立条件：自回归模型 + softmax 归一化；保留少量开头位置即可恢复。
  • 缓存常量性与序列长度无关这一点只对窗口 KV 成立，不含压缩后的全局 KV 与索引器缓存；「40 层 2.50 MiB」也不含 3 个草稿层的同类缓存。

前置概念

  • 标准注意力：窗口注意力只改变可见集，打分与加权方式不变。
  • 因果掩码：与窗口互补，共同定义可见集。
  • KV cache：环形缓冲是它的固定容量变体。
  • RoPE：位置口径的选择（原序列位置 vs 缓存内位置）依赖它。
  • 注意力汇聚点：解释为什么不能把序列开头的位置一起丢掉。
