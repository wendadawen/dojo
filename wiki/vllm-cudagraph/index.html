torch.compile 图捕获与 CUDA Graph

torch.compile 通过 TorchDynamo 将前向计算捕获为计算图、再由 Inductor 编译为 GPU kernel 以提升推理性能；图捕获阶段的约束决定了哪些代码可被编译，解码阶段则由 CUDA Graph 录制一次、逐批重放。

更新于 2026-08-06 · 类型：代码机制

1. torch.compile 的两阶段流程

PyTorch 默认的 forward() 以逐行解释方式执行：每一条 Python 语句对应一次算子（kernel）提交，中间结果写入显存、再由后续算子读回，解释器与 kernel 启动存在固定开销。torch.compile 通过将计算整体化为可复用编译产物来消除这部分开销，分为两个阶段：

  1. 图捕获（graph capture）：由 TorchDynamo 在运行前向时，将 Python 层调用逐条转换为一张计算图（graph），图中节点对应算子。
  2. 图编译（graph compilation）：由后端将计算图翻译为可执行的 GPU kernel。torch.compile 的默认后端为 Inductor（PyTorch 官方内置），其通过代码生成以 Triton 语言产出 kernel，再编译为 CUDA 机器码。产物除 kernel 外，还包括调用它们的执行计划，整体封装为可复用的编译函数，此后推理直接执行该产物、不再逐行解释。

2. Dynamo 图捕获的处理边界

图捕获要求计算中的每个可追踪节点都能映射为图算子，或可被安全地 graph break（跳出图、回落到 Python 执行）。Dynamo 对代码类型的处理方式如下：

代码类型Dynamo 处理方式结果
张量运算（torch.add、torch.matmul）映射为图节点正常编译
Python 原生控制流（if、for、len）graph break，回落到 Python 执行可继续，性能下降
C 扩展（如 hashlib.sha1）无追踪规则，标记为 skipped 并抛异常图捕获中断

graph break 是软性失效：图在该位置断开、控制流回落 Python，执行仍可继续；而 C 扩展被标记为 skipped 时是硬性失败，Dynamo 直接抛出 Unsupported 异常终止捕获。

C 扩展指通过 CPython C API 编译为共享库（.so）供 Python 调用的函数。这类函数对 Dynamo 而言是黑盒——既无法映射为图节点，也无 graph break 的兜底规则，因此捕获失败。典型报错信息为：Dynamo does not know how to trace the builtin _hashlib.openssl_sha1.

3. CUDA Graph 的录制与重放

即便 kernel 已编译完成，每次推理仍由 CPU 逐个向 GPU 提交 kernel，每次提交存在固定延迟（CPU 到 GPU 的命令下发开销）。CUDA Graph 将完整的 GPU 执行序列——包括 kernel 顺序、各 kernel 参数、输入输出内存地址及数据搬运操作——一次性录制（capture）为一张图，此后 CPU 仅需一次命令即可整张重放（replay），从而消除逐个下发的开销。

  • 适用阶段：主要用于解码（decode）阶段。decode 每步仅生成一个 token，kernel 单次计算量小但数量多，CPU 逐个下发开销占比较高，且计算形状相对稳定，适合录制；而预填充（prefill）单次处理大量 token、计算形状动态变化，不适用于固定形状的图录制。
  • 开销特征：录制开销较大（需逐次执行、记录地址与依赖、分配内存池，量级可达几十至数百毫秒），因此只执行一次并复用；重放开销极小。
  • 显存代价：除图本身（每张数十至数百 MB）外，还须预留固定地址的内存池（memory pool），按最大容量预留、即使未用满也不释放，因此显存占用随捕获图数量线性增长，vLLM 通过限制捕获图数量控制显存。
  • 核心约束：录制时地址被固化，重放阶段输入输出内存地址不可改变，故数据须存放于预分配的固定内存池中（如 vLLM 的 KV cache 缓冲区即为此设计）。

4. 捕获尺寸的确定

CUDA Graph 捕获的尺寸以解码阶段的总 token 数为单位。decode 中每个请求每步仅产生一个 token，故总 token 数近似等于并发请求数（num_seqs，即 batch size）；seq_len 在 decode 中恒定，不参与尺寸组合。

默认捕获尺寸按 [1, 2, 4] + list(range(8, 256, 8)) + list(range(256, max, 16)) 生成，最大捕获尺寸默认取 min(max_num_seqs * 2, 512)。实际请求数不落在合法捕获尺寸上时，按邻近的合法尺寸向上补齐（padding）。
