主要依据：YOCO（Sun et al., arXiv:2405.05254v2）§2、Eq.(2)、Table 1–3；DeepSeek-V4.1-Flash 技术报告 §2.2、§2.3.1；官方推理配置与参考实现（inference/config.json、inference/model.py）。共享关系的运行期实测见文末来源说明。

本页讨论的复用对象是全局 KV——覆盖整段上下文的那部分条目。每层自己的滑动窗口 KV 仍按层保存，不在复用范围内。这一点是理解"省了多少"的关键。

核心问题

  1. 多层共用的那份 KV 是从哪一层来的？

    解答：下段末层隐状态投影而来，上段各层不再自算全局 KV

    把层分成下段（自解码器）与上段（交叉解码器）。下段逐层计算，其末层隐状态 $X^{L/2}$ 经投影得到唯一的全局键值 $\hat K = \mathrm{LN}(X^{L/2})W_K$、$\hat V = \mathrm{LN}(X^{L/2})W_V$；上段各层通过交叉注意力复用它，不再从本层隐状态生成全局 KV。因此全局 KV 的份数从"每层一份"变成"每段一份"。完整机制见第 1 章。

  2. 这样能省下多少缓存与计算？

    解答：缓存复杂度从 $\mathcal{O}(LND)$ 降到 $\mathcal{O}((N+L)D)$，prefill 可提前退出

    全局 KV 的份数与层数无关，缓存复杂度中的层维度被消掉：$\mathcal{O}(LND) \to \mathcal{O}((N+L)D)$，论文称约省 $L$ 倍缓存。prefill 阶段上段不必为每个位置计算全局 KV，可以在进入上段前提前退出，计算复杂度从 $\mathcal{O}(LN^2D)$ 降到 $\mathcal{O}(LND)$。"只缓存一次"严格指全局 KV，局部窗口 KV 仍按层存在。完整账目见第 2 章。

  3. "共享 KV"与"复用索引"是同一件事吗？

    解答：不是，前者共享条目、后者共享选择结果

    共享 KV 是让多层读同一份 KV 条目；复用索引是让多层沿用同一份 Top-K 选择。DeepSeek-V4.1-Flash 的 CSA2 把两者解耦成三种模式：Full（自算 KV 与索引）、Reindex（复用 KV、自算索引）、Reuse（两者都复用）。因此"复用索引"不等于"看到一样的东西"——各层的 query 与本层窗口 KV 仍不同，选出的位置也可能不同。完整对照见第 3 章。

  4. 复用的前提是什么？为什么不能所有层共用一份？

    解答：同组压缩比必须一致；不同压缩比的组各有一份

    共用一份 KV 要求同组层的压缩比相同——条目覆盖的 token 数不同就无法共用。实测 DeepSeek-V4.1-Flash 的共享分组是层 2–7、8–13、14–19、20–39，source 层分别是 2、8、14、20，每个压缩层读到的 cache 都来自组内 source 层。代价是上段各层不再有各自的全局 KV，表达能力损失由训练补偿。完整前提与边界见第 4 章。

常见误解

  • 「跨层复用就是所有层共用一份 KV」——是"同组共用一份"；不同压缩比的组各有一份，实测有 4 个 source 层。
  • 「复用索引与复用 KV 总是一起发生」——CSA2 把两者解耦：Reindex 层复用 KV 但自算索引。
  • 「复用了 KV，所有层看到的内容就一样了」——各层仍用自己的 query 与本层窗口 KV，只是全局部分来自同一份条目。
  • 「复用后缓存复杂度是常数」——被消掉的是层维度，全局 KV 仍随序列长度增长；局部窗口 KV 也仍按层存在。

1. 复用的是哪一层的 KV

标准 Transformer 的每一层都要为整段上下文各存一份 KV，层数越多，缓存越大。跨层 KV 复用的思路是：不让每层各自从本层隐状态生成全局 KV，而是让上段各层统一使用下段产出的那一份。

YOCO 把这个结构写成 decoder-decoder[C1]：$L$ 层中前 $L/2$ 层是自解码器，其余是交叉解码器。自解码器逐层计算，它的末层输出 $X^{L/2}$ 被投影成全局键值[F1]：

$$\hat K = \mathrm{LN}(X^{L/2})\,W_K,\qquad \hat V = \mathrm{LN}(X^{L/2})\,W_V$$
  • $X^{L/2}$：自解码器末层的隐状态（整段上下文的摘要）；
  • $W_K, W_V \in \mathbb{R}^{d\times d}$：可学习的投影权重；
  • $\hat K, \hat V$：被上段所有层复用的全局键与值；
  • $\mathrm{LN}$：层归一化。

关键在于：$\hat K, \hat V$ 只算一次，上段各层不再为全局部分做投影。但它们仍然保留自己的 query 与局部（窗口）KV——复用的只是全局部分。

本章问题

  1. 为什么让上段复用下段的 KV 不会破坏因果性？

    解答：$X^{L/2}$ 本身已经是因果编码的结果

    下段是标准的因果注意力堆叠，$X^{L/2}$ 中位置 $i$ 的向量只包含位置 $\le i$ 的信息。上段各层用这份 KV 做交叉注意力时，位置 $i$ 的 query 读取的是 $X^{L/2}$ 中位置 $\le i$ 的投影结果，因此仍然看不到未来。若下段换成双向注意力，这条就不成立——因果性来自下段的因果结构，而不是复用本身。

  2. 上段各层是不是就"没有自己的 KV"了？

    解答：只缺全局 KV，各层仍有自己的窗口 KV

    复用的对象是全局 KV（覆盖整段上下文的那部分）。上段每层仍从本层隐状态计算自己的滑动窗口 KV，用于关注最近一段位置；这部分没有共享。因此准确的说法是"全局 KV 每段一份，局部 KV 每层一份"。YOCO 论文也明确说明"只缓存一次"严格指全局 KV。

2. 省下多少：层维度被消掉

复用的直接后果是缓存里不再有"每层一份"这个维度。YOCO 给出的复杂度对照是[C2][F2]：

$$\text{标准 Transformer: }\mathcal{O}(LND)\qquad\text{跨层复用: }\mathcal{O}((N+L)D)$$
  • $N$：序列长度；$L$：层数；$D$：隐藏维；
  • 标准式中的 $LND$ 表示"每层、每位置、每维"都有一份缓存；
  • 复用式中的 $N D$ 是那份全局 KV，$L D$ 是各层局部缓存的常量部分。

当 $N$ 远大于 $L$ 时（长序列），$\mathcal{O}((N+L)D)$ 与 $\mathcal{O}(ND)$ 同阶，也就是说全局 KV 的份数从 $L$ 份降到 1 份。论文据此给出"约省 $L$ 倍缓存"的结论[C2]。

prefill 侧还有一笔账：既然上段复用了下段的输出，prefill 阶段就可以在进入上段之前提前退出[C3]。计算复杂度由 $\mathcal{O}(LN^2D)$ 降到 $\mathcal{O}(LND)$，论文称至少省一半的层计算[F3]。DeepSeek-V4.1-Flash 的报告也采用同一说法，称 CED 让 prefill 计算接近减半[N4]。

补充：跨层复用与 MLA、压缩注意力的分工

三者削减的是不同维度，可以叠加：MLA 把每个 token 的 KV 从"多头 × 头维"压成一条低维潜向量，削减的是每 token 的宽度；压缩注意力把每 $r$ 个 token 池化成一条条目，削减的是token 方向；跨层复用让多层共用一份全局 KV，削减的是层方向。DeepSeek-V4.1-Flash 同时用了后两者（压缩比 2/1 的压缩条目 + 按 ratio 分组共享），因此它的每 token 缓存才能降到 890 字节。

本章问题

  1. "只缓存一次"这个说法准确吗？

    解答：只对全局 KV 成立，局部缓存仍按层存在

    论文自己在脚注里限定了这个说法：严格来说自解码器也需要保存一定量的缓存，只是它的规模被限制在常数（例如窗口大小），在长序列下相对全局缓存可以忽略。因此准确表述是"全局 KV 只存一份"。如果把局部窗口 KV 也算进来，缓存总量仍随层数增长——只是每层的那一份大小固定，不随序列增长。

  2. 序列很短的时候，跨层复用还有收益吗？

    解答：收益有限，因为局部缓存与全局缓存体量相当

    缓存复杂度的对照式是 $\mathcal{O}(LND)$ 对 $\mathcal{O}((N+L)D)$，其中复用式保留了 $LD$ 这一项（各层局部缓存的常量部分）。当 $N$ 与 $L$ 同量级时，$LD$ 与 $ND$ 相当，复用的收益不明显；$N \gg L$ 的长序列下 $LD$ 可忽略，收益才显现。计算侧的提前退出收益与序列长度无关，但短序列本来 prefill 就便宜。

3. 两级复用：共享 KV 与复用索引

"跨层复用"在实践中分成两件可以独立开关的事，这一点容易被混为一谈：

  • 共享 KV：让多层读同一份 KV 条目——省的是缓存。
  • 复用索引：让多层沿用同一份 Top-K 选择结果——省的是打分计算。

DeepSeek-V4.1-Flash 的 CSA2 把两者解耦，并据此把层分成三种模式[C4]：

模式主 KV 与索引器 KTop-K 索引省下什么
Full自己计算并发布自己产出——（生产层）
Reindex复用最近的生产层自己产出（重打分）缓存
Reuse复用最近的生产层复用最近的产出缓存与打分计算

关键在于：复用索引不等于看到一样的东西。索引是"对某一份 KV 打分后选出的位置"，因此它必须与它评分的那份 KV 配套；而每个层仍然有自己的 query 与本层窗口 KV，所以即便索引相同，各层最终的注意力输出也不同。Reindex 模式存在的意义正是：在保持 KV 共享的同时，允许各层重新打分、选出不同的位置[C4]。

本章问题

  1. 为什么 Reindex 层要"复用 KV 却重新打分"？

    解答：让不同层可以选到不同位置，同时不重复存 KV

    如果所有层都复用同一份 Top-K，那么深层的稀疏选择与浅层完全一致，表达能力受限。Reindex 层保留 KV 共享（省缓存），但用自己的 query 对这份 KV 重新打分并选出新的 Top-K，于是选择可以逐层变化。它付出的是索引器的打分计算，省下的是 KV 存储。

  2. 两层如果复用了同一份 Top-K，它们的注意力输出会一样吗？

    解答：不一样，query 与本层窗口 KV 都不同

    复用索引只决定"看哪些全局位置"，各层仍用自己的 query 对这些位置做注意力，且各自还有本层的滑动窗口 KV 参与。因此即便选中的位置集合完全相同，各层的输出也不同。把"选择相同"当成"计算相同"是常见误解。

4. 前提与边界：同组才能共用

共用一份 KV 不是无条件的。最直接的前提是同组层的压缩比一致：一个压缩条目覆盖 $r$ 个 token，$r$ 不同的层无法共用同一批条目[C6]。因此"共享"实际发生在按压缩比划分的组内，组内由一个 source 层负责生产、其余层读取。

补充：运行期怎么确认"谁读了谁的 cache"

做法是把每层的 KV cache 张量按对象标识登记成"属主 → 层号"的表，然后在注意力前向里记录"本次读到的 cache 属于哪个层"。这样得到的是运行期的实际归属关系，而不是从配置推断的关系。实测输出：每个压缩层读到的 cache 都来自其组内 source 层，源层读到自己刚发布的 cache。

代价方面，上段各层不再拥有各自的全局 KV，这意味着它们的全局可见性是"共享的"，表达能力损失需要在训练中补偿。此外，序列很短时（$N$ 与 $L$ 同量级）局部缓存的常量项与全局项体量相当，复用的收益不明显。

本章问题

  1. 为什么不同压缩比的层不能共用一份 KV？

    解答：条目覆盖的 token 数不同，位置对应关系无法对齐

    压缩比 $r$ 决定一条条目覆盖 $r$ 个 token，也决定条目编号与位置的换算关系（第 $j$ 条对应位置 $j\cdot r$ 起的一段）。$r$ 不同的层对"第 $j$ 条"指向的上下文范围不同，共用同一批条目会让某一层的可见范围错位。因此共享被限制在同压缩比的组内，不同组各有一份。

  2. 复用会不会让模型"记住"得更少？

    解答：全局可见性被共享，但可见范围不变，代价在表达能力

    复用的不是"可见范围"，而是"用于全局注意力的那份条目的来源"。上段各层仍然能看到同样的全局位置集合（由 Top-K 选择决定），只是这些位置对应的 KV 条目来自下段末层隐状态的投影，而不是各层自己的隐状态。因此代价是各层失去了"用自己的隐状态表示全局上下文"的能力，需要训练补偿；这不等同于上下文变短。

辅助解释与类比边界

「整栋楼共用一套供水」是辅助解释：说明份数从"每层一口井"变成"每组一套"。边界：它只覆盖全局 KV，每层仍需自己的"局部水管"（窗口 KV）；也不说明复用对质量没有代价。
