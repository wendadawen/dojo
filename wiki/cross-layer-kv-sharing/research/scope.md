# 跨层 KV 复用（cross-layer KV sharing）内容范围

## 2.1 概念含义

- **名称**：跨层 KV 复用 / cross-layer KV sharing（相关名称：KV 跨层共享、跨层 KV cache 复用；代表性工作 YOCO、CLA、IndexCache）
- **简要定义**：让多个层共享同一份全局 KV 条目，而不是每层各自从本层隐状态算一份，从而把 KV cache 的层维度消掉。
- **正式定义**：把 $L$ 层 Transformer 分成两段，下段（自解码器）逐层计算并把最后输出 $X^{L/2}$ 投影成唯一一份全局 KV；上段（交叉解码器）的各层不再从本层隐状态生成 KV，而是直接使用这一份，通过交叉注意力读取<sup>[C1]</sup>。YOCO 给出的一般形式是 $\hat K = \mathrm{LN}(X^{L/2})W_K$、$\hat V = \mathrm{LN}(X^{L/2})W_V$<sup>[F1]</sup>。因此每层只需维护自己的一段局部（窗口）KV，全局 KV 只存一份。
- **本文采用的语境**：以 YOCO 的 decoder-decoder 形式为一般定义；以 DeepSeek-V4.1-Flash 的 CSA2 为实例——它把"主 KV 与索引器 K 共享"和"Top-K 索引复用"两件事解耦，并在运行期按 ratio 分组共享<sup>[C2][C3]</sup>。
- **包括什么**：复用对象（哪一层的 KV）、缓存复杂度账、共享与索引复用两级的区别、分组前提与运行期证据
- **不包括什么**：压缩条目本身怎么算（属压缩注意力）；具体 kernel 融合实现；训练时的稳定性处理
- **相邻概念**：MLA（在"每 token 维内"压缩，不跨层）；压缩注意力（在"跨 token"方向池化）；KV cache 分层/offload（不改计算图，只搬存储）

## 2.2 学习目标

### Q1：复用的是哪一层的 KV？为什么这样就能少存？
- 完成答案：上段各层不再从本层隐状态生成全局 KV，而是统一使用下段最后一层隐状态 $X^{L/2}$ 投影出的那一份；因此全局 KV 的份数从"每层一份"变成"每段一份"。参考实现里这条表现为"某个层计算出的 KV cache 被同组后续层读取"。
- 为什么是核心目标：复用对象决定了缓存账与质量代价。
- 依赖内容：注意力与 KV cache 的基本形态、隐状态与层间依赖。

### Q2：省下多少？
- 完成答案：KV cache 的层维度被消掉，复杂度从 $\mathcal{O}(LND)$ 降到 $\mathcal{O}((N+L)D)$（$N$ 序列长度、$L$ 层数、$D$ 维度）；由于上段不必为 prefill 的每个位置都算全局 KV，prefill 阶段可以提前退出，计算复杂度从 $\mathcal{O}(LN^2D)$ 降到 $\mathcal{O}(LND)$，理论上至少省一半的层计算。
- 为什么是核心目标：这是跨层复用被采用的理由，也是与压缩注意力的分工所在（一个消层维度、一个消 token 维度）。
- 依赖内容：Q1；KV cache 的字节构成。

### Q3："共享 KV"与"复用索引"有什么区别？
- 完成答案：共享 KV 是让多层读同一份 KV 条目；复用索引是让多层沿用同一份 Top-K 选择结果。CSA2 把两者解耦成三种模式：Full（自算 KV 与索引）、Reindex（复用 KV、自算索引）、Reuse（两者都复用）。因此"复用索引"并不等于"看到一样的东西"——索引必须与它评分的那份 KV 配套。
- 为什么是核心目标：这两个概念经常被混为一谈，而它们的节省对象与约束都不同。
- 依赖内容：Q1；稀疏注意力的 Top-K 选择。

### Q4：复用的前提与代价是什么？
- 完成答案：前提是同组层的压缩比一致（否则共用一份 KV 无意义）；跨组的 KV 不能互相复用（不同 ratio 的条目覆盖的 token 数不同）。代价是表达能力：上段各层不再有各自的全局 KV，质量由训练补偿。运行期实测显示 DeepSeek-V4.1-Flash 的共享分组是层 2–7、8–13、14–19、20–39，每个压缩层读到的 cache 都来自组内 source 层。
- 为什么是核心目标：把"能省"与"不能随便省"一起说清。
- 依赖内容：Q1–Q3。

## 2.6 常见误解和适用边界

| 错误理解 | 正确结论 | 形成原因 |
|---|---|---|
| "跨层复用就是所有层共用一份 KV" | 是"同组共用一份"；不同压缩比的组各有一份，实测分组为 2–7 / 8–13 / 14–19 / 20–39 | 忽略分组前提 |
| "复用索引 = 复用 KV，两者总是一起" | CSA2 把两者解耦：Reindex 层复用 KV 但自算索引，Reuse 层两者都复用 | 把两级复用当成一件事 |
| "复用了 KV，所有层看到的内容就一样了" | 各层仍用自己的 query 和本层窗口 KV，只是全局部分来自同一份条目；索引不同则选中的位置也不同 | 混淆"KV 来源"与"可见集" |
| "复用后缓存复杂度是常数" | 全局 KV 降到与层数无关，但局部窗口 KV 仍按层存在（每层一段常量大小的环）；YOCO 用"once"特指全局 KV | 忽略局部 KV 的存在 |

**适用边界**：复用要求同组层的压缩比一致、且组内存在一个负责生产的层；序列很短（$N$ 与窗口同量级）时，局部 KV 与全局 KV 体量相当，复用的收益主要体现在长序列。
