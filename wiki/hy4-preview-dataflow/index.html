    Hy4-Preview 前向数据流

    Hy4-Preview 是腾讯混元开源的 770B MoE 模型（huggingface.co/tencent/Hy4-preview，config 中 model_type 为 hy_v4）。78 层主干全部是 DSA 稀疏注意力：每层一个 32 头、头维 128 的轻量索引器为每个查询选出最多 2048 个 token，其中 21 个 full 层自行选择，其余 57 层直接复用前一个 full 层的结果。注意力本体是 MLA 潜向量形式（$q$ 低秩 2048，KV 潜向量 $512{+}64$，头维 $192{+}64$、值维 256），每个头带一个可学习 sink，输出乘逐元素 sigmoid 门。残差流在入口复制为 4 条，每个子层前后由 iHC 的 pre/post 门控读出与写回，末端由 hc_head 收束。FFN 首层 dense、其余 77 层为 256 路由专家 top-8 加 1 个恒激活共享专家。另含 1 层无 iHC 的 MTP 草稿层。

    生成于 2026-09-09 · 依据官方 transformers 实现 + config.json + 真实 checkpoint 张量头与小张量实值 + 本机实测

    3. 要点

    整体结构：78 层全 DSA + 首层 dense

    • 没有满注意力层：layer_types 全部为 deepseek_sparse_attention，每层都带 MLA 投影与 DSA 索引（full 或 shared）。稀疏性不靠「部分层用满注意力」实现，而是每层都先选 top-2048 再做注意力。
    • 唯一例外在第 0 层 FFN：首层是中间维 18432 的 dense SwiGLU（参数量 339,738,624），其余 77 层为 MoE。张量头印证：仅首层含 mlp.gate_proj，其余层含 mlp.experts.*。
    • 索引层的节奏：full 索引层是 0, 1, 5, 9, …, 77——第 0 与第 1 层相邻且都 full，此后每 4 层一个；2–4 复用 1，6–8 复用 5，……，74–76 复用 73，最后第 77 层重新自选。等比缩小模型上实测：shared 层的 top-k 输出与它复用的 full 层逐位相等（torch.equal 为 True）。
    • 激活比例：每层 MoE 激活 8/256 = 3.1% 的路由专家；单层激活 341,311,744 参数（含路由器与共享专家）。路由专家合计 744.10B，占总参数 95.40%。

    iHC：四条残差流的读出与写回

    • 入口复制：embedding 经 unsqueeze(2).expand(-1,-1,4,-1) 变成 $[B,T,4,6144]$，四条流初始完全相同。等比缩小模型实测：第 0 层输入处四条流与 embeddings 逐位相等。
    • pre 门控读出：把四条流展平成 24576 维，先算 $g = W_{fn}\,\mathrm{flat}(x) \cdot \mathrm{rsqrt}\big(\overline{\mathrm{flat}(x)^2} + \epsilon\big)$（$W_{fn}\in\mathbb{R}^{8\times24576}$，前 4 行给 pre、后 4 行给 post），再混合 $$\tilde{x} = \sum_{i=1}^{4}\Big(\sigma\big(g_i^{pre} s_{pre} + b_i^{pre}\big) + \epsilon\Big)\, x_i$$ 全程强制 fp32。初始化使 $b^{pre}=-\log 3$、$s=0.01$，故初始 pre 门 $\approx\sigma(-\log 3)=0.25$——等比缩小模型实测 pre 门 min 0.2491 / max 0.2511 / mean 0.2500，与理论值吻合。
    • post 门控写回：子层输出 $y$ 按每条流一个标量外积写回 $$x_i \leftarrow x_i + \Big(2.0\cdot\sigma\big(g_i^{post} s_{post} + b_i^{post}\big) + \epsilon\Big)\, y$$ 初始 post 门 $=2\,\sigma(0)=1.0$，即标准恒等残差——实测 min 0.9975 / max 1.0029 / mean 0.9999。
    • 末端收束顺序：先 hc_head（4 条流加权求和，单一 $s$ 标量与 4 维 $b$，初始门同样 $\approx0.25$，实测 mean 0.2499），再过共享 RMSNorm，最后 lm_head。hc_head 的参数（hc_head_fn [4, 24576]、hc_head_base [4]、hc_head_scale [1]）全模型只有一份。
    • 真实权重的门控参数已显著训练：按 data_offsets 精确下载的 F32 小张量显示，第 0 层 attn 的 hc_base 前 4 个（pre 半区）为 $[-0.886, -0.879, -0.718, -0.910]$，仍围绕初始值 $-\log 3\approx-1.099$；后 4 个（post 半区）为 $[-1.518, -1.418, -1.398, -0.486]$，从初始 0 大幅移出。而最后一层（77）的 post 半区为 $[0.012, 0.003, 0.012, 0.208]$，几乎保持初值——门控的训练强度沿深度差异很大。hc_scale 同样分化：第 0 层 attn $[0.250, 0.0058]$，第 77 层 $[0.258, 0.184]$。hc_head 的 base 为 $[-1.144, -1.151, -1.212, -0.972]$、scale 0.105（初始 0.01，放大十倍）。
    • 半区归属的独立印证：checkpoint 中 hc_base 前 4 个围绕 $-\log3$、后 4 个围绕 0，与源码初始化「前半 pre、后半 post」的切分顺序一一对应——这是除源码之外的第二重证据。

    DSA 索引器：fp32 打分、ReLU、跨层复用

    • 独立的轻量投影：查询走 $W_{q\_a}\to\mathrm{RMSNorm}\to W_{wq\_b}$（2048 $\to$ $32\times128$），复用主注意力的 q_a 通道但 wq_b 独立；键走 $W_{wk}$（6144 $\to$ 128）加 LayerNorm。键只有一个头，32 个查询头共享。
    • 头内切分是「过 + 旋转」：每头 128 维切 [64 维过 | 64 维旋转]，与主 MLA 的 [192 nope | 64 rope] 同构，旋转部分都占头维的尾部。
    • 打分公式（全程 fp32，含 ReLU）： $$\text{index\_score}_{s,t} = \sum_{h=1}^{32} \frac{(W_{proj}x_s)_h}{\sqrt{32}}\cdot\frac{1}{\sqrt{128}}\cdot \mathrm{ReLU}\big(q_{s,h}\cdot k_t\big)$$ 其中 $W_{proj}$ 是 weights_proj（6144 → 32）。ReLU 让单个头的负相关无法抵消其他头的正相关。等比缩小模型实测：头分数矩阵中精确为 0 的比例 47.8%，聚合分数中正数占 23.4%。
    • top-k 取 min(2048, 可见长度)：短序列时退化为全可见，不发生稀疏化。因果性通过给不可见位置加 $-\infty$ 掩码保证，因此 top-k 不会选出未来 token。
    • 跨层复用零成本：shared 层的 indexer 为 None（等比模型实测 layer2.self_attn.indexer is None 为 True），直接用 DecoderLayer 向上传递的 prev_topk_indices。57 个 shared 层的索引计算量与缓存都省掉。
    • 手工复算对撞：用独立实现的 RoPE 与打分公式复算第 1 层索引分数，top-16 集合与官方实现完全一致（等比模型 24 token 场景）。

    MLA 注意力：潜向量展开 + sink + 逐元素门

    • 查询低秩：$q = W_{qb}\,\mathrm{RMSNorm}(W_{qa}x)\in\mathbb{R}^{64\times256}$，每头切 [192 nope | 64 rope]。
    • KV 潜向量：$c = W_{kva}x\in\mathbb{R}^{576}$（512 潜 + 64 rope），展开 $W_{kvb}\,\mathrm{RMSNorm}(c_{[:512]})$ 得每头 [192 nope | 256 v]，rope 部分 64 维所有头共享同一份。
    • logits 与稀疏掩码：$\mathrm{logits} = qk^\top/\sqrt{256}$（缩放因子 $=qk\_head\_dim^{-1/2}=0.0625$），再叠加因果掩码与索引器 top-k 掩码（非选中位置填 dtype 最小值）。
    • sink 只进分母：每头一个可学习标量 $s_h$ 拼到 logits 行尾， $$P = \mathrm{softmax}\big([\,\mathrm{logits}-\max;\; s_h-\max\,]\big)[\,:\,:\,T\,]$$ 输出丢掉 sink 列，行和小于 1，缺口就是 sink 吸收的概率质量。初始 $s_h=0$ 时它不是常数 1 的等价物——等比缩小模型实测（24 token、随机权重）：sink 吸收质量 min 0.059 / mean 0.121 / max 0.502，即 sink 为零时仍平均吃掉 12% 的注意力质量。真实权重的 sink 已大幅训练：第 0 层均值 0.384（范围 $[-6.54, 3.18]$）、第 40 层 0.666、第 77 层 $-0.022$。
    • 逐元素 sigmoid 门：注意力输出先乘 $\sigma(W_g x)$（$64\times256$ 维独立门）再过 o_proj。等比模型实测门值 min 0.389 / max 0.615 / mean 0.500。注意这是逐元素门，不是每头一个标量——linear_gate.weight [16384, 6144] 印证输出宽度 $64\times256$。
    • 全链路对撞：q/kv 投影、展开、掩码、sink softmax、门、o_proj 的独立复算与官方实现输出最大绝对差 0（等比模型）；eager 返回的注意力概率矩阵也逐位一致。

    MoE：sigmoid 路由 + 偏置选择 + 2.827 放大

    • 路由打分用 sigmoid 而非 softmax：$p = \sigma(W_r x)$（fp32 计算），256 个分数各自独立、不互斥。选择时用 $p + b$（$b$ 即 e_score_correction_bias，aux-loss-free 式的平衡偏置）取 top-8，权重则从原始 $p$ 中 gather。
    • 归一化后整体放大：$w_j = p_{(j)}\big/\textstyle\sum_{j'} p_{(j')} \times 2.827$。等比模型实测（运行前把偏置置为非零以行使选择路径）：token 5 的 top-8 归一化权重和精确等于 1.000000，乘 2.827 后各权重在 0.33–0.37 之间。
    • 分组路由存在但退化：n_group=1、topk_group=1 时组掩码覆盖全部专家，分组限制不起作用，代码等价于无组直接 top-8。
    • SwiGLU 截断只给路由专家：$\mathrm{silu}(\min(g,10))\cdot\mathrm{clip}(u,-10,10)$。单元实测：gate 输入 20 被截到 10（$\mathrm{silu}(10)\times(-7)=-69.9968$）、$-20$ 不动（silu 自带抑制）、up 的 $\pm7$ 不动（在限内）。共享专家与首层 dense FFN 无此截断。
    • 共享专家无门控：输出直接与路由结果相加，没有 Qwen 系的 shared_expert_gate 标量门。共享专家与单个路由专家同构（中间维 2048）。
    • 对撞：路由全链路 + 逐 token 专家复算 + 共享专家，与官方批量实现输出最大绝对差 $7.3\times10^{-10}$（fp32 舍入量级）。
    • 真实权重的偏置形态：第 1 层 e_score_correction_bias 范围 $[-0.0967, 0.0323]$、均值 $4\times10^{-8}$（近零）、中位数 0.0013；第 40 层中位数 0.0074；第 77 层 0.0064——围绕零小幅摆动的平衡偏置形态。

    prefill 与 decode 的等价性

    索引器在 prefill（一次算整段）与 decode（逐 token 增量）下应当给出相同的 top-k。等比缩小模型（47 token）上的五步证据链：

    论断实测结果
    因果下三角内注意力输出一致（fp32 口径）1128 个条目中 5 个不等，最大绝对差 $1.16\times10^{-9}$，相对差 $2.7\times10^{-8}$
    同一分数张量、仅候选宽度不同的 top-k 对比47 列 vs 48 列（多一列精确 0 分），47 个查询中恰 1 个发散
    发散位置的分数两侧分数均精确等于 0.0（ReLU 产生大量并列零分）
    破坏并列后是否一致每列加 $10^{-9}$ 扰动后 top-16 集合完全一致（True）
    关闭稀疏化（topk $\ge$ 长度）logits 最大绝对差 $3.6\times10^{-7}$（纯 fp32 舍入）

    结论：机制上 prefill 与 decode 等价；观察到的差异全部源于「ReLU 的精确零分在 top-k 边界并列 + torch.topk 的并列选择依赖张量宽度」这一固有数值特性，而非实现缺陷。

    KV cache 的两种口径

    MLA 的潜向量给了两种缓存口径，体积差 56.89 倍（主 cache，按真实 config 实算；容量均按 1M = $2^{20}$ token 与二进制单位 KiB/MiB/GiB/TiB 换算）：

    口径每 token 每层78 层合计1M 上下文（线性估算）
    transformers eager：展开 K/V64 头 × (256 + 256) = 32768 元素 = 65536 B4.88 MiB约 4.88 TiB（不可用）
    vLLM：潜向量 MQA512 + 64 = 576 元素 = 1152 B，另 64 个 per-head sink 常驻87.8 KiB约 87.8 GiB

    索引器缓存独立于主 cache：21 个 full 层各存每 token 128 维索引键（vLLM 用 FP8 存储并按 128 值一组附带 scale，约 2772 B/token；transformers eager 为 BF16，5376 B/token），shared 层不缓存。1M 上下文下索引器缓存约 2.7–5.3 GiB。

    4. 实现对照：同一 checkpoint 的三种消费方式

    Hy4-Preview 的发布 checkpoint、transformers 参考实现与 vLLM/SGLang 部署实现之间存在两处容易踩坑的不一致，本节逐项给出证据。

    RoPE 布局：checkpoint 是交错式，transformers 参考实现是半分式

    「旋转维内部如何配对」有两种约定：交错式（相邻两维 $(x_{2i}, x_{2i+1})$ 组成复数，DeepSeek 血统的 Megatron 训练布局）与半分式（前半与后半配对，即 rotate_half，Llama 系约定）。两种配对对同一份权重互斥。各实现的取值为：

    实现Rope 配对方式证据位置
    vLLM hy_v4（官方部署路径）主 MLA 与索引器两处均交错（is_neox_style=False）vllm/models/hy_v4/nvidia/attention.py，两处构造显式设 False，注释标明「Checkpoint (PTM) layout」
    SGLang交错（rope_interleave=True、indexer_rope_interleave=True）python/sglang/srt/configs/hy_v4.py；另有 python/sglang/srt/models/hunyuan_v4.py 的 permute_hyv4_indexer_weight 把索引器每头后 64 维旋转块挪到头前部（这是头内块顺序置换，与配对方式无关）
    transformers hy_v4 参考实现半分式（rotate_half）modeling_hy_v4.py 的 apply_rotary_pos_emb
    transformers deepseek_v2（血统参照）交错（view_as_complex 相邻配对）modeling_deepseek_v2.py 的 apply_rotary_emb

    三方一致的部署实现（vLLM、SGLang）都按交错消费这份 checkpoint，且 hub 官方 README 的部署指引只覆盖这两者；transformers 的 hy_v4 参考实现用半分式，与 checkpoint 的实际布局不匹配，直接加载需要先做旋转维的权重置换——hub 仓库没有提供该转换脚本。DeepSeek 系参考实现（deepseek_v2）用交错，说明半分式是 hy_v4 参考实现的偏离而非血统传统。

    本节的证据性质是源码与张量结构级的交叉核对（三个实现的 RoPE 应用代码 + checkpoint 张量布局），不是端到端数值对撞——后者需要在部署框架里跑真实权重，本机不可行。结论按「官方部署路径的实现一致性」给出。

    checkpoint 是 vLLM 命名的 inner 格式

    • 命名一一对应 vLLM：张量名如 hc_attn_layer.hc_pre.hc_fn、self_attn.learnable_sink_param、self_attn.linear_gate.weight、mlp.experts.gate_up_proj（3D 融合、无 .weight 后缀）与 vLLM 模块命名一一对应；vLLM 的 load_weights 直接按此命名加载。transformers 期望的命名（attn_hc.*、sinks、gate_proj 等）与之不同。
    • 只有 hc_pre、没有 hc_post：checkpoint 中每个 iHC 模块只有一组 hc_pre.{hc_fn[8,24576], hc_base[8], hc_scale[2]}。结构上这是自洽的：pre 与 post 两套门控由同一模块计算——hc_fn 的 8 行中前 4 行算 pre logits、后 4 行算 post logits，hc_base 的 8 个元素与 hc_scale 的 2 个元素同样按前后半区分属 pre/post。
    • hub 的微调补丁只做改名：仓库内的 finetune/llama_factory_support/hy_v4_patches.py 只执行 mlp.router.gate. → mlp.gate. 之类的键名映射与专家权重融合，不含任何 RoPE 置换。
    • F32 小张量是运行时精度的实存证据：626 个 F32 张量恰为 iHC 门控、主干 sink、主干路由偏置与 hc_head——对应 transformers _keep_in_fp32_modules_strict 清单的核心项，但 k_norm 与 lm_head 在文件中仍是 BF16，即「fp32 计算」发生在加载后而非存储时。

    5. MTP 草稿层

    MTP（multi-token prediction）层是主干的旁路：输入是「下一个 token 的 embedding」与「主干末态隐藏」，输出走自己的一个 block 后复用主干 lm_head 给出草稿 logits。

    • 融合入口：$x = W_{eh}\,\big[\mathrm{enorm}(e);\ \mathrm{hnorm}(h)\big]$，其中 $e$ 是 token embedding、$h$ 是主干最后隐藏态，eh_proj [6144, 12288] 把拼接后的 12288 维投回 6144。
    • 块内是单流残差：$x' = x + \mathrm{Attn}(\mathrm{LN}(x))$、$x'' = x' + \mathrm{MoE}(\mathrm{LN}(x'))$，没有 iHC 的多流与门控。checkpoint 佐证：mtp_layers.0.* 的 27 个张量中不含任何 hc 参数；vLLM 构造时同样显式 enable_ihc = False。
    • 自带 full 索引器：MTP 层有完整的 self_attn.indexer.*（wq_b [4096, 2048]、wk [128, 6144]、weights_proj [32, 6144]），不依赖主干的 top-k。等比缩小模型实测：MTP 块选出的 top-k 与主干第 1 层不同（独立选择）。
    • 结构同构但有差异：注意力侧同样有 sink 与逐元素门（learnable_sink_param、linear_gate），MoE 同为 256+1 top-8；但 sink 与路由偏置在文件中存 BF16（主干为 F32）。真实权重形态佐证 MTP 确实训练过：MTP 层 sink 实值均值 0.950（范围 $[-2.375, 2.922]$，源码初始化为 0）、路由偏置中位数 0.00737，均明显偏离初始化。
    • 收尾：final_layernorm 后接主干 lm_head——checkpoint 中 MTP 无自己的输出头，vLLM 加载时把主干 lm_head.weight 映射为 MTP 的 shared head。等比模型实测两者 data_ptr 相同（同一份权重对象）。
    • decode 场景的边界处理：vLLM 实现在位置 0 处把输入 embedding 置零（此时还没有可用的「下一个 token」），主干隐藏态承担全部信息。

    6. 核对方式

    本页数字分四类来源，各自的取得方式如下。

    结构与维度：用 HTTP Range 请求读取全部 131 个 safetensors 分片的 JSON 文件头，得到 2006 个张量的名称、形状与 dtype，与 config 及源码推导交叉验证（层数与层型、索引层分布、MoE 形状、iHC 参数形状、MTP 构成、F32 清单等）。

    公式与数值行为：把官方 modeling_hy_v4.py 原样 exec（架构代码零改动，仅以等义桩替换 transformers 框架侧装饰器），构造保留全部结构特征的等比缩小模型（10 层、隐藏维 512、8 头、16 专家 top-8、4 条流、24 token），用 forward hook 捕获官方实现的中间张量，再以独立手写公式复算对撞。iHC 混合与门控、索引器打分与 top-k、MLA 全链路（含 sink softmax 与门）、MoE 路由与专家、dense FFN 均逐张量对撞通过（最大差 0 至 $7.3\times10^{-10}$）；prefill/decode 等价性以五步证据链闭合。MTP 按官方 vLLM 实现的语义拼装缩小版跑通。

    checkpoint 小张量实值：按 data_offsets 用 Range 请求精确下载 sink、路由偏置、hc_base / hc_scale、hc_head、k_norm 等小张量（F32 与 BF16 均按位模式正确解码），覆盖第 0 / 40 / 77 层与 MTP 层。

    参数量：2006 个张量头逐一累加得总量与分组；单 token 激活按结构规则（78 组注意力、21 个 full 索引器、77 层 top-8 + 共享、首层 dense）累加，各分组数字与张量头独立核对一致。
