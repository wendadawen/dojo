# 因果掩码（Causal Mask）教学大纲

## 1. 页面开头

**钩子问题**：Transformer 的 decoder 在训练时一次喂入整句"我 爱 自 然 语 言"，可位置 3 的表示凭什么不能偷看位置 4 的"然"？如果它能看到未来，训练时岂不是在抄答案？

**一句话解释**：因果掩码（Causal Mask）是 decoder 自注意力里的遮挡规则——位置 $t$ 只能 attend 到位置 $1..t$，看不到未来 token；实现上把注意力分数矩阵的严格上三角置 $-\infty$，softmax 后未来位置权重为 $0$。

**要解决的具体问题**：这条规则为什么需要、如何机械地落地、能否手算验证、在训练和推理中形态有何不同、它的边界在哪里、为什么它还是 NoPE 能隐式编码位置的结构前提。

**学习承诺**（与 scope.md 学习目标一致，组件 03 learning-goals）：读完本页，你应该能够回答 Q1–Q5（见学习目标列表）。

**首个具体场景**：三个 token，注意力分数全为 $0$（softmax 均匀），值 $v_1=1,v_2=2,v_3=3$。施加因果掩码后，位置 1、2、3 的输出会是什么？这贯穿全文（S3 手算、S5 双向对照）。

**过渡**：先看清"为什么 decoder 必须挡住未来"，才能理解因果掩码要解决什么。

**组件分配**：01 callout（钩子提示）、03 learning-goals、04 misconceptions（因果掩码 ≠ 填充掩码 ≠ NoPE，三条常见误解）、05 blockquote.meta（主要依据摘要）。

## 2. 章节设计

### S1：因果掩码是什么规则，解决什么问题

- 主要教学问题：decoder 自注意力为什么必须挡住未来？因果掩码的规则一句话是什么？
- 对应范围：核心内容（Q1）；C1、C4。
- 正文要点：
  - 自回归生成的最小定义：逐 token 预测下一个 token，每步只依赖已生成的前缀（自回归生成概念页占位——本页给最小定义）。
  - 标准注意力（前置概念页 `wiki/standard-attention/` 链接）本身是"内容匹配"——query 与每个 key 算相似度，不关心位置先后。如果直接用在 decoder 上，位置 $t$ 的 query 会和位置 $t+1,t+2,\dots$ 的 key 算出非零分数——未来信息泄漏进位置 $t$ 的表示。
  - 后果：训练时位置 $t$ 的预测（应只依赖 $1..t$）实际依赖了 $t+1,t+2,\dots$（"抄答案"），模型学不到合理的逐 token 预测。
  - 因果掩码的规则（一句话）：位置 $t$ 只能 attend 到位置 $1..t$；看不到未来 token。
  - 明确边界（为 Q5 铺垫）：因果掩码只用在 decoder 自注意力；encoder 用双向注意力，每个位置看全部输入（不加因果掩码）。
- 讲解材料及职责：
  - 一段教学解释（A10）：用"位置 3 不能偷看位置 4"说明信息泄漏问题，标记为教学解释，失效边界回到论文 §3.2.3。
  - 对照表（组件 14）：encoder 自注意力 vs decoder 自注意力（注意力方向、是否加因果掩码、典型用途），划清边界不展开。
- 前置知识安排：标准注意力（`../../wiki/standard-attention/index.html`，已有）；自回归生成（占位最小定义）。
- 完成检查：读者能说出"位置 $t\to1..t$"规则、能说出"不掩则未来信息泄漏"、能从对照表指出 decoder 才用因果掩码。
- 过渡：规则清楚了，怎么落到可执行的计算上？下一章讲机制。

### S2：因果掩码如何机械地实现——上三角 $-\infty$ 与 softmax 归零

- 主要教学问题：规则"位置 $t\to1..t$"怎么变成注意力计算里的一个具体操作？
- 对应范围：核心内容（Q2）；C2、C3、F1。
- 正文要点：
  - 因果掩码 $M$ 的构造：$n\times n$ 矩阵，严格上三角（$j>i$）为 $-\infty$，对角线及以下（$j\le i$）为 $0$。
  - 核心公式（F1）：$\operatorname{Attention}(Q,K,V)=\operatorname{softmax}(QK^\top/\sqrt{d_k}+M)V$。说明 $QK^\top/\sqrt{d_k}$ 是标准注意力的分数（前置概念已讲），$+M$ 是因果掩码这一步。
  - 为什么是 $-\infty$：softmax 中 $e^{-\infty}=0$，被掩位置权重为 $0$；可见位置权重重新归一化到和为 $1$（softmax 分母只对未归零项求和）。
  - 关键澄清：掩码施加在 softmax 的输入（分数）上，不是施加在 softmax 的输出（权重）上——后者无法保证权重恰好为 $0$、且和为 $1$。
  - 浮点实现备注：精确 $-\infty$ 在数学上是极限，工程实现中可用足够大的负数（如 $-10^5$）或框架提供的 `-inf` 达到同样效果（权重在浮点精度下恰好为 $0$）；本文手算用 $-\infty$ 表达数学含义。
- 讲解材料及职责：
  - 公式（A2，F1）：因果掩码注意力的完整式，逐项定义符号 $Q,K,V,\sqrt{d_k},M$。
  - 公式（A2，C2 推论）：softmax 归零的验证——$e^{-\infty}=0$，分母只含可见项，权重重归一化。
  - ASCII 图示（组件 13）：$3\times3$ 掩码矩阵 $M$ 的形状（上三角 $-\infty$、对角线及以下 $0$）。
- 前置知识安排：引用 S1 的标准注意力链接；softmax 的归一化性质由标准注意力页覆盖。
- 完成检查：读者能写出 $M$ 的形式、能说出公式 $\operatorname{softmax}(QK^\top/\sqrt{d_k}+M)V$、能解释"为什么 $-\infty$ 让权重恰好为 $0$"。
- 过渡：机制讲清了，但没算过一遍。下一章手算 $3$-token 例子。

### S3：手算 $3$-token 例子——掩码、softmax 归零、重归一化

- 主要教学问题：给定一个具体注意力分数矩阵，施加因果掩码后 softmax 权重和输出到底怎么变？
- 对应范围：核心内容（Q3）；F2。
- 正文要点：
  - 构造示例设定：$3$ 个 token，单头，注意力分数 $s_{t,j}=q_t^\top k_j/\sqrt{d_k}$ 全为 $0$（即 softmax 在不掩时均匀分布），值 $v_1=1,v_2=2,v_3=3$。说明构造目的——分数均匀让 softmax 手算最简，掩码的效果直接体现为"可见项重归一化"。
  - 不掩时（双向对照，为 S5 铺垫）：每行 softmax$([0,0,0])=[1/3,1/3,1/3]$，输出均为 $(1+2+3)/3=2$。
  - 施加掩码 $M$ 后：分数矩阵变为 $[[0,-\infty,-\infty],[0,0,-\infty],[0,0,0]]$。
  - 逐行 softmax（正文展示位置 1，完整三位置放折叠块）：
    - 位置 1：softmax$([0,-\infty,-\infty])=[1,0,0]$，输出 $=v_1=1$。
  - 结论（正文给出）：位置 2 输出 $1.5$、位置 3 输出 $2$（完整计算在折叠块）；未来位置权重为 $0$，可见位置权重重归一化到和为 $1$。
  - 与不掩对照：不掩时三位置输出均为 $2$（相同，无法区分位置）；掩码后输出 $1,1.5,2$（不同，位置可区分）——为 S5 的 NoPE 联系铺垫。
- 讲解材料及职责：
  - 数值示例（A4，正文展示位置 1 + 结论，完整三位置 + 双向对照放折叠块 10）：构造数据、代入、中间结果、最终结果，标记为构造示例。
  - 可运行代码（A7，折叠块 12）：Python（仅 `math`）实现 $3$-token 因果掩码 softmax，输出真实运行结果，验证手算。代码与公式变量同名映射。
- 前置知识安排：引用 S2 的公式 F1、F2。
- 完成检查：读者能手算位置 2 的 softmax（$[1/2,1/2,0]$）与输出（$1.5$），并说出"未来权重为 $0$、可见重归一化"。
- 过渡：机制与手算都验证了。但训练和推理中掩码的形态不同——下一章讲。

### S4：训练时并行、推理时 KV-cache 隐含

- 主要教学问题：因果掩码在训练和推理中分别怎么用？为什么推理时不必每步重建 $n\times n$ 掩码矩阵？
- 对应范围：核心内容（Q4）；C4、C5。
- 正文要点：
  - 训练时（并行形态）：一次喂入整条目标序列（如"我 爱 自 然 语 言"），用单个 $n\times n$ 因果掩码 $M$ 一次并行算出所有位置的表示——每个位置只看前缀（掩码保证），但全部位置一步算完。这是 decoder 训练能并行（顺序操作 $O(1)$）的关键，相对 RNN 逐位置串行（顺序操作 $O(n)$）。
  - 推理时（KV-cache 形态）：逐 token 生成，每生成一个 token 把它的 key/value 追加到 KV-cache（KV-cache 概念页占位——本页给最小定义"缓存过去 token 的 key/value，新 query 直接复用"）。下一个 query 只与 cache 中已有的（过去的）key/value 交互——cache 里没有未来 token，"看不到未来"由 cache 的内容范围天然保证。
  - 关键澄清（误解二）：推理时无需显式构造 $n\times n$ 上三角掩码矩阵；掩码的约束由 KV-cache 的增长方式隐含。训练时才需要显式 $M$（因为一次性喂入整条序列，必须用掩码区分可见与不可见）。
  - 为什么训练要并行：相对 RNN 的 $O(n)$ 顺序步骤，自注意力 + 因果掩码让训练的顺序步骤降到 $O(1)$，充分发挥 GPU 并行算力（论文 §3.2.4）。
- 讲解材料及职责：
  - ASCII 图示（组件 13）：训练时整条序列 + 显式 $M$ 并行；推理时 KV-cache 逐 token 增长、cache 内只有过去。
- 前置知识安排：引用 S1 的自回归生成最小定义；KV-cache 占位最小定义。
- 完成检查：读者能说出"训练用显式掩码并行、推理用 KV-cache 隐含"，并解释推理时为何不必重建掩码矩阵。
- 过渡：最后看因果掩码的边界与深层作用——它为什么是 NoPE 的结构前提。

### S5：边界与 NoPE 的结构前提

- 主要教学问题：因果掩码的边界在哪里？为什么它还是 NoPE 能隐式编码位置的结构前提？
- 对应范围：核心内容（Q5）；C6、C7。
- 正文要点：
  - 边界一（encoder vs decoder，复用 S1 对照表）：encoder 双向注意力不加因果掩码（每个位置看全部输入，构建完整上下文）；decoder 因果注意力加掩码（保留自回归）。在 encoder 加掩码会破坏双向上下文建模；在 decoder 不加掩码会信息泄漏。
  - 边界二（与填充掩码正交）：填充掩码屏蔽"填充 token"（与是否有效 token 有关），因果掩码屏蔽"未来位置"（与位置先后有关）。两者目的不同、可叠加为同一 `attn_mask` 张量。
  - 深层作用（NoPE 结构前提，C6）：在没有位置编码的双向注意力中，交换输入顺序会让每个位置的输出也作同样交换（排列等变——排列等变概念页占位，本页给最小定义"交换输入顺序时每个位置的输出不变"），无法区分"甲乙"和"乙甲"。因果掩码使位置 $t$ 的可见集合恰为 $\{1,\dots,t\}$，不同位置可见集合不同，打破排列对称性——即使不加任何显式位置编码（NoPE），不同位置的注意力输出也会不同，位置被结构隐式提供。
  - 复用 S3 例子验证：S3 中不掩（双向）三位置输出均为 $2$（相同，无法区分位置）；掩码（因果）后输出 $1,1.5,2$（不同，位置可区分）——这正是因果掩码打破排列对称性的可手算验证。
  - 与 NoPE 的关系澄清（误解四）：因果掩码是注意力分数上的遮挡规则；NoPE 是"不施加任何显式位置编码"的选择。因果掩码是 NoPE 能工作的结构前提之一，但两者不是一回事——因果掩码在加显式位置编码的 decoder 里也照常使用。NoPE 完整论证见 `wiki/nope/`。
- 讲解材料及职责：
  - 对照表（组件 14，复用 S1 的 encoder/decoder 表并扩展一列"是否打破排列对称性"）。
  - 复用 S3 手算结论：双向输出全 $2$、因果输出 $1,1.5,2$。
- 前置知识安排：引用 S3 例子；NoPE（`../../wiki/nope/index.html`，已有）；排列等变（占位最小定义）。
- 完成检查：读者能说出三条边界（encoder vs decoder、填充掩码正交、NoPE 关系）、能解释因果掩码如何打破排列对称性。
- 过渡：（文末章节）来源与范围说明。

## 4. 贯穿例子

**贯穿问题**：三个 token，注意力分数全为 $0$（softmax 均匀），值 $v_1=1,v_2=2,v_3=3$。施加因果掩码后，位置 1、2、3 的输出会是什么？

- S3：手算因果掩码下三位置的 softmax 权重与输出（$1,1.5,2$）；并对照不掩（双向）时三位置输出均为 $2$。这是核心机制的可手算验证。
- S5：复用 S3 的对照（双向输出全 $2$ → 无法区分位置；因果输出 $1,1.5,2$ → 可区分位置），说明因果掩码打破排列对称性，是 NoPE 的结构前提。

数字足够小可手算（分数全 $0$ 让 softmax 在可见项上均匀，$e^{-\infty}=0$ 无需计算器，值 $1,2,3$ 的加权平均为整数或简单小数）。
