FlashKDA 与 KDA Context Parallelism

让 KDA 的串行递归状态在 GPU 和多设备上高效跑起来的四套方案，分别针对训练/prefill、长 prefill、跨设备、投机解码。

主要依据：Kimi K3 Technical Report §5.1.1、§5.1.2、§5.4.2

1. 这个概念是什么

KDA（Kimi Delta Attention）把 softmax 注意力随序列长度增长的 KV cache 压成了固定大小的递归状态 $S_t$，省了显存，但状态必须一步一步串行更新（$S_t$ 依赖 $S_{t-1}$）。这和 GPU 偏好宽而均匀的并行相冲突——GPU 有上百块 SM 想同时干活，串行依赖却让它们排队等。本文讲解 K3 报告为这个冲突设计的四套方案，每个执行 regime 一套。KDA 的递归机制本身见 KDA 概念页，GPU 的 SM/CTA/warp 见 GPU 执行模型页。

2. 为什么需要它

  • 训练和 prefill 里 SM 空转：chunkwise 形式 chunk 内并行、chunk 间串行传状态，两阶段交替时多数 SM 闲着等少数 SM 推状态。
  • 长 prefill 下纯 TP 填不满 SM：Tensor Parallelism 切 head 不缩短序列方向的递归，每个 rank 只持少量 head，132 块 SM 大部分空闲。
  • 跨设备时线性注意力的"求和"对 KDA 不成立：vanilla 线性注意力递归是纯加性，各 rank 本地状态可直接求和；KDA 的 delta rule 有矩阵 $M_t$ 作用于入状态，本地段效果依赖入状态，不能直接求和。
  • 投机解码拒绝 draft token 时状态无法回滚：解码每步原地更新状态，MTP 投机解码若拒绝部分 draft token，状态已越过最后接受 token，无法平凡回到正确位置。

3. 核心直觉

  • FlashKDA 的重叠：把工作拆成 chunk 内 token 维度并行（token-parallel）和 head 维度递归（head-parallel）两部分，各自独立调度。算一个 chunk 的内部计算时，同时传另一些 head 的状态——两阶段不再交替等待，而是流水线重叠。不同 head 的状态递归互相独立，是重叠能成立的前提。
  • 设备内 CP 的"段转移可独立计算"：KDA 的状态转移是线性的——一段 token 对状态的效果可以分解成"作用于入状态的部分"+"从零生成的部分"，不依赖入状态就能预先算好，之后精确合并。所以能把一条长序列切到单 rank 的多块 SM 上并行算段转移，再合并恢复每段入状态，且不需要跨设备通信。
  • KCP 的 $M+\tilde S$ 分解：每段效果 = "入状态要经过的累积变换 $M$"（本地 token 的 $M$ 连乘）+ "本地自己从零生成的状态 $\tilde S$"。两者都可在入状态可用前本地算出，各 rank 一次 all-gather 交换这两个片段，再用 prefix scan 从零状态起依次重组出入状态。
  • 解码缓存投影输入而非状态：任意接受前缀后的状态由 draft token 的投影输入（$q,k,v,\beta,\alpha$ 等几个向量）完全决定，而投影输入比状态（$d_k\times d_v$ 矩阵）小得多。只缓存投影输入，在片上重跑递归重建接受 token 的状态，就能回滚——既支持回滚又不让状态流量爆炸。

4. 关键结论与边界

  • KCP 通信量与序列长度无关：交换的是固定大小的状态（约 32KB，config.json），不是随序列长度增长的 KV block。这是 KCP 相对 softmax CP（如 Ring Attention）的核心优势。成立条件：KDA 递归成立、状态固定大小。
  • $M+\tilde S$ 分解依赖 KDA 递归的线性性：$M_t$ 和加性项可分离，段转移才可独立于入状态计算。若递归非线性使段转移不可分离，KCP 和设备内 CP 的分解都不成立。
  • 投影缓存不离开 decode 阶段：投机解码的回滚机制被完全封装在 decode kernel 内部，前缀缓存和 prefill–decode 分离（PD 分离）与非投机服务使用相同载荷，不污染上层服务架构。成立条件：KDA 更新确定性（给定相同输入序列状态唯一）。
  • 四 regime 各有专门方案，不可混用：FlashKDA 解 chunk 间空隙（训练/prefill），设备内 CP 解单 rank SM 没填满（长 prefill），KCP 解跨设备（序列超单卡），投影缓存解解码回滚。设备内 CP 无跨设备通信、KCP 需一次 all-gather，两者层次不同。
