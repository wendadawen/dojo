# PCP 与 DCP 文章大纲

## 1. 页面开头

- 开场场景：一个 agent 请求带着约 100 万 token 的输入（代码仓、对话历史、工具调用轨迹）进入推理引擎。对用户这是一次请求，对引擎是两个阶段：prefill 要把这 100 万 token 全部算一遍，用户等着第一个字出来（TTFT）；decode 每步只生成一个新 token，却要背着全部历史的 KV cache 走，显存被一条条请求吃满，新的请求进不来。
- 随后给出概念简释：把这条长序列沿 token 维切到多张卡上——prefill 阶段切计算（PCP），decode 阶段切 KV cache（DCP）。
- 学习目标（核心问题，5 条，见 scope.md Q1–Q5）。
- 首个示例：贯穿构造模型（见第 4 节）在开头不出现，页面开头只用真实尺度场景；构造模型在第 2 章引入。
- 过渡到第 1 章：两阶段的瓶颈具体差在哪，为什么不能用同一种切法。

组件安排：blockquote.meta（主要依据：vLLM 官方文档与 2026-08 官方博客）→ 引言段 → learning-goals（核心问题 5 条，每条配解答折叠块）→ misconceptions（3 条：M1、M2、M3）→ 正文。

### 第 1 章 长请求的两副面孔——prefill 撞算力，decode 撞显存

- 章节问题（本章问题块，2 题）：
  1. 为什么 prefill 的压力主要落在计算时间（TTFT）上，而 decode 的压力主要落在 KV cache 容量上？
     - 答案要点：prefill 一次处理全部输入 token，attention 计算量随长度平方增长，算力是瓶颈，用户感知 TTFT；decode 每步只算一个新 token 的 QKV 投影（计算量小），但每步要读全部历史 KV，容量决定能同时装多少条请求，并发上限决定吞吐。
  2. chunked prefill 同样处理长 prompt，它和 PCP 有什么区别？
     - 答案要点：chunked prefill 按时间把长 prefill 切成多个 step 串行执行（同一批卡，避免长请求独占机器），不增加每步的并行度；PCP 按空间把序列切到多卡同时算，一步内多卡并行。一个切时间轴，一个切空间轴，可同时使用。
- 对应范围：C1、C2、C3。
- 正文要点：
  - 两阶段的计算形状对比（输入全部 token vs 每步 1 个 token；读 KV 的量）。
  - TTFT 与"KV 容量 → 并发上限 → 吞吐"两条因果链。
  - CP 的定义：沿序列（token）维切分。两阶段 SLO 不同 → 分化出 PCP 与 DCP。
  - chunked prefill 对比（链接已有页），说明 PCP 不是"把 chunked prefill 换个名字"。
- 表达材料及职责：
  - 结构图（组件 13 结构 B，阶段堆叠）：一个请求的 prefill / decode 两阶段的计算与存储画像。职责：让"两副面孔"一眼可见。
  - 无公式（本章定性）。
- 前置知识安排：KV cache（首次提及时链接 `../kv-cache/index.html`）、标准注意力（`../standard-attention/index.html`）、chunked prefill（`../chunked-prefill/index.html`）。

### 第 2 章 张量并行沿注意力头切 KV cache，切到头就没得切了

- 章节问题（3 题）：
  1. TP 下 KV cache 怎么按头分片？$t \le H$ 与 $t > H$ 两种情况每卡各存多少？
     - 答案要点：$H$ 个 KV 头分给 $t$ 张卡。$t \le H$：每卡 $H/t$ 个头，无重复。$t > H$：头不够分，每个头复制到多张卡，每卡至少 1 个头，KV cache 总副本数 $t/H$ 份。
  2. 为什么 MLA 的 KV cache 在 TP 下是完整复制到每张卡？
     - 答案要点：MLA 把 K/V 压成跨全部 query 头共享的低秩潜向量，没有"多个头"可分，有效 KV 头数为 1；TP 对它是 $t > 1 = H$ 的极端情形，重复因子 $t$。
  3. "重复因子 $t/H$"怎么来的，它决定什么？
     - 答案要点：$H \times T$ 条 KV 条目在 $t$ 张卡上、每卡至少 1 个头约束下的最少总副本数即 $t/H$；它决定 dcp 的有效上限（$d = t/H$ 时重复恰好降为 1）和 DCP 能释放的显存量。
- 对应范围：C4、C5、F1、F2。
- 正文要点：
  - TP 对注意力权重的切法回顾（一句话 + 链接 model-parallelism），引出"KV cache 也跟着按头切"。
  - F1 条目数、F2 重复因子；$t \le H$ / $t > H$ 两段。
  - GQA 头数少（Qwen3-235B 的 4 个）、MLA 有效单头——现代模型恰恰在压缩头数，head 维天花板越来越低。
  - 贯穿构造模型首次出场（见第 4 节）：手算 4 卡下 4 份完整副本。
  - 澄清 M4：TP 超过 $H$ 后 TP 本身没有失效，权重照切，只是 KV 部分开始重复。
  - 章末过渡：head 维切到头了，但还有一整个 token 维没动过——下一章沿它切。
- 表达材料及职责：
  - 手算表格（组件 14）：贯穿构造模型在 tp=4 下每卡存什么、总副本数。职责：把"重复"变成可数的东西。
  - 结构图（组件 13 SVG）：4 张卡各持完整 latent KV（重复）与头数足够时各持一部分（无重复）的对比。职责：直观展示两种情形。
- 前置知识安排：model-parallelism、mqa-gqa、mla（各自首次依赖处链接）。

### 第 3 章 DCP——沿 token 维切 KV cache，用通信换显存

- 章节问题（4 题）：
  1. DCP 怎么把 KV cache 分到 $d$ 张卡？为什么交错分配而不是连续块？
     - 答案要点：组内每卡存 $1/d$ 的 token 位置，token $i$ 存到 rank $i \bmod d$。decode 中 KV 逐 token 增长：连续块会把新 token 全压到负责尾部的卡，其余卡不动，负载越走越斜；交错让新 token 轮流落到各卡，增长均匀，且任意 token 的归属由位置直接算出。
  2. decode 一步的通信流程是什么？为什么 query 的 all-gather 是便宜的？
     - 答案要点：AllGather Q → 各卡对本地 KV 切片算 attention（得部分输出与本地 LSE）→ AllGather 部分输出与 LSE、按 LSE 加权合并、ReduceScatter 取回各自 head 切片。query 每步只有一个 token（或很少几个），张量小，all-gather 开销小。
  3. LSE 合并怎么做？为什么合并后与整卡计算完全一致？
     - 答案要点：$o = \sum_r e^{l_r} o_r / \sum_r e^{l_r}$；$e^{l_r} o_r$ 恰是该卡全部 token 的 $e^{s_i} v_i$ 加权和、$e^{l_r}$ 恰是该卡 $e^{s_i}$ 之和，合并即全局 softmax 分子分母的分组求和，是恒等式不是近似。手算与代码均验证。
  4. DCP 的收益链路和代价各是什么？
     - 答案要点：收益链：重复消除 → 单卡 KV 占用降 → 可容纳请求多 → batch 大 → 吞吐高（attention 阶段按序列分片、FFN 阶段同一批 GPU 重组为全池摊薄权重加载）。代价：每步 decode 多组内通信；dcp 越大通信越多；互联差或上下文短时可能负收益。
- 对应范围：C3、C6、C7、C11、C12、C13、C15、C16、F3、N1、N2。
- 正文要点：
  - 3.1 切法与交错分配：C13 的"按 token 位置分片"概念 + C11 的交错落位实现，说明博客连续区间是示意、实现交错，两者关系讲清（防"矛盾"困惑）。手算归属表（T=8、d=4）。
  - 3.2 每步通信流程：C12 三步节奏；query 为何 all-gather、为何便宜。流程图。
  - 3.3 LSE 合并与等价性：F3 公式、符号、手算验证（局部计算示例）；可运行代码验证等价性。MLA 路径（k_up）与 GQA 路径（tensor_broadcast）一句话各到位（C15，细节进折叠块）。
  - 3.4 收益与代价：C16 的两阶段复用、N1/N2 实测数字、代价与负收益边界。a2a 后端与 q_replicate（C14、N4）进折叠块。
- 表达材料及职责：
  - 手算归属表（组件 14）：T=8、d=4 时 token 0–7 的卡归属。职责：交错规则可复算。
  - 流程图（组件 13 结构 A，顺序流程）：AllGather Q → 本地 attention → LSE 合并 → ReduceScatter。职责：通信节奏一眼可见。
  - LSE 手算（计算示例，正文表格摘要 + 折叠块完整展开）：2 卡 4 token 标量分数。职责：验证等价性。
  - 可运行代码（组件 12，折叠块）：同一例子用 Python 复算，断言合并 = 全局。职责：机制可执行验证。
  - 补充折叠块（组件 09）：a2a 后端与 q_replicate；MLA/GQA 路径细节。
- 前置知识安排：gpu-communication（AllGather/ReduceScatter 首次出现处链接）。

### 第 4 章 PCP——把长 prompt 的计算摊到多卡

- 章节问题（3 题）：
  1. PCP 的两种策略分别适用什么场景？
     - 答案要点：partial-Q/full-KV——序列中等长、全量 K/V 放得下时，AllGather 聚齐 K/V，各卡算自己段 query 的 attention 输出；partial-Q/partial-KV——序列长到放不下全量 K/V 时，各卡只留自己段，用 ring attention 逐块收发 K/V。
  2. causal mask 为什么造成 prefill 负载不均？$2N$ 配对切分怎么解决？
     - 答案要点：第 $j$ 块的 query 要 attend 第 $0..j$ 块的 KV，计算量随 $j$ 递增；顺序等分时靠后的卡拿到最重的段。把序列切成 $2N$ 块、rank $i$ 取第 $i$ 与第 $2N-1-i$ 块，负载 $(i+1) + (2N-i) = 2N+1$（单位 $b^2$）与 $i$ 无关，恒定均衡。
  3. PCP 与 DCP 在资源占用上的本质区别是什么？
     - 答案要点：PCP 扩展 world size（设备数变为 TP × PCP），代价是更多卡；DCP 不扩展（复用 TP rank），代价是每步通信。一个是花硬件买延迟，一个是花通信买显存。
- 对应范围：C17、C18、C19、F4。
- 正文要点：
  - prefill 计算形状回顾（第 1 章结论衔接）：计算量随长度增长 → TTFT。
  - 切分方式与两种策略（C17），ring attention 只交代角色不展开（链接 S6）。
  - causal 负载不均的推导与手算（F4）：8 块 4 卡，顺序连续切 vs 首尾配对，最慢卡负载 15 vs 9。
  - 配对切分作为 vLLM RFC 描述的设计呈现（C18 措辞注意）。
  - PCP 扩展 world size（C19）；PCP 现状：仍在开发（C21）。
  - PCP vs DCP 对照表收尾。
- 表达材料及职责：
  - 手算表格（组件 14）：8 块 4 卡两种切法的每卡负载对照。职责：负载不均与配对均衡可复算。
  - 结构图（组件 13 SVG）：8 块序列、4 卡的顺序切与配对切的归属示意（块编号标在卡上）。职责：配对关系可视化。
  - 对照表格（组件 14）：PCP vs DCP（目标、切的对象、卡数、代价、现状）。
- 前置知识安排：causal-mask（首次依赖处链接）。

### 第 5 章 组合与选型——先加 tp，再加 dcp

- 章节问题（3 题）：
  1. dcp 怎么选值？三个官方部署各取多少？
     - 答案要点：先把 tp 加到性能满意，再取 dcp 消重复；有效范围 $[1, t/H]$，源码校验 $t \bmod d = 0$。DeepSeek-R1（H=1）tp8 → dcp8；Kimi-K2 tp16 → dcp16 全消或 dcp8 留 2 倍（通信留在节点内）；Qwen3-235B（H=4）tp8 → dcp2。
  2. PCP/DCP 与 PD 分离是什么关系？
     - 答案要点：不同维度。PD 分离决定 prefill/decode 跑在哪个 GPU 池（部署维度）；PCP/DCP 决定池内一条长请求怎么跨卡（执行维度）。可组合；vLLM 正在加固 DCP 在分离式部署中的支持。
  3. 什么时候 DCP 反而不划算？
     - 答案要点：上下文短、单卡 KV 无压力（$t \le H$ 无重复可消）；或卡间互联带宽低，每步通信的延迟超过显存收益；或请求并发低、吞吐不构成目标。这些场景直接用 TP 更简单。
- 对应范围：C8、C9、C10、C20、C22、N3。
- 正文要点：
  - 官方建议与取值逻辑（C20、C8）；源码约束（C9、C10）以"MLA 用 $t \bmod d$、GQA 用 $(t/H) \bmod d$"呈现，与 $[1, t/H]$ 的关系讲清（推荐范围 vs 硬校验两层）。
  - 三个 case study 表格（N3）。
  - 与 PD 分离辨析（C22，M2 的正式处理位置）；链接 ppd-disaggregation（论文页）作延伸。
  - 负收益边界（Q3 第 4 问的正式收束）；M1 的正式处理位置（"吞吐 3 倍"≠"单请求快 3 倍"，引 N1 的并发从 64 到 512）。
  - PCP 组合约束：PCP 不支持 DP、PCP>1 时 dcp 取值集合（C9），作为折叠块或简短段落。
- 表达材料及职责：
  - case study 表格（组件 14）：模型 / H / tp / 重复 / dcp / 效果。
  - 无新公式。

## 4. 贯穿示例与局部计算示例

贯穿构造模型（第 2 章引入，第 3 章复用）：

- 构造设定：一个 MLA 式极小模型——有效 KV 头数 $H=1$（每 token 每层只有一份潜向量 KV），上下文 $T=8$ 个 token，部署 tp=4。
- 第 2 章用法：TP 下每卡持有全部 8 个 token 的 KV，总副本 4 份（重复因子 $t/H=4$）。
- 第 3 章用法：dcp=4 时 token $i$ 存到 rank $i \bmod 4$，每卡 2 个 token，总副本 1 份；重复全部消除的临界点正是 $d = t/H = 4$。
- 数字足够小可手算；每次复用增加一层（先算重复、再算消除）。

局部计算示例一（第 3 章，LSE 合并等价性）：

- 构造：2 张卡、4 个历史 token、1 个 query、标量分数。卡 0 存 token 1、3（分数 $s_1=1, s_3=3$），卡 1 存 token 2、4（$s_2=2, s_4=4$）；$v_1=1, v_2=0, v_3=0, v_4=1$。
- 手算：全局输出 $= (e^1 + e^4)/(e^1+e^2+e^3+e^4) \approx 0.676$；卡 0 本地 $o_0 \approx 0.119$、$l_0 = \ln(e^1+e^3)$，卡 1 本地 $o_1 \approx 0.881$、$l_1 = \ln(e^2+e^4)$；合并 $= (e^{l_0} o_0 + e^{l_1} o_1)/(e^{l_0}+e^{l_1})$，数值回到全局值。
- 服务目标：Q3 第 3 问（等价性）。同一组数字交给可运行代码复算。

局部计算示例二（第 4 章，causal 配对负载）：

- 构造：8 个等长块、4 张卡，第 $j$ 块负载 $j+1$（单位 $b^2$）。
- 手算：顺序连续切（卡 $i$ 拿块 $2i, 2i+1$）负载 $3,7,11,15$；首尾配对（卡 $i$ 拿块 $i$ 与块 $7-i$）负载全部 $=9$；总负载同為 36，最慢卡从 15 降到 9。
- 服务目标：Q4 第 2 问（配对切分）。

真实尺度参照（非构造）：1M token agent 输入（第 1 章场景）、Kimi K2.6 / 8×B200 实测（第 3 章，N1/N2）、三个官方 case（第 5 章，N3）。
