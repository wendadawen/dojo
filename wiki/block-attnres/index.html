    Block AttnRes：把深度方向的等权累加换成块级注意力检索

    主要依据：Kimi K3 Technical Report §2.2 Eq.(8)(9)(10)（2026-07-28）；HuggingFace 官方 config.json（attn_res_block_size=12、num_hidden_layers=93）。K3 加权三次的具体位置参考 K3 前向数据流 note 对官方源码 modeling_kimi_linear.py 的核对（2026-08-07 修订）。

    K3 主干 93 层，标准残差把所有前层输出以系数 1 累加进同一个流——第 1 层 embedding 在第 93 层只占 1/93，且无法被后续层按内容找回。Block AttnRes 把它当作深度方向的 RNN 瓶颈：每层用可学习 pseudo-query 对"embedding + 此前块级快照 + 当前块 partial sum"做 softmax 加权检索，把送入归一化的输入从"当前残差流"替换为"attention 检索结果"。它不取消标准残差（K3 仍逐层累加 attention 与 MLP 输出），而是在其上叠加块级加权选择，与 token 方向的 attention、channel 方向的 MoE 同级，构成 K3 的三维信息流。本文依赖前置概念残差连接，只使用其结论；softmax 与 RMSNorm 作为公式零件使用，不展开为独立概念页。本文要回答：Full AttnRes 的公式是什么、Block AttnRes 如何把内存从 $O(Ld)$ 降到 $O(Nd)$、K3 的 8 块×12 层配置与加权三次的具体位置、以及 softmax kernel 中 RMSNorm 的作用。

    核心问题

    1. 标准残差在深度方向上为什么是瓶颈？AttnRes 用什么思路替代？

      解答：标准残差把所有前层输出以系数 1 累加进同一残差流，早期信息被层层稀释且无法按内容找回；AttnRes 用 softmax 加权检索替代等权累加。

      标准残差展开后 $h_L=h_1+\sum_{l=1}^{L-1}F_l(h_l)$，第 1 层 embedding 在第 $L$ 层只占 $1/L$ 份额，后续层只能被动接收累加好的结果，与 RNN 把历史压进单个 hidden state 是同一种瓶颈。AttnRes 让每层用可学习 pseudo-query 对前序表征做 attention，按内容分配权重。完整论证见「1. 标准残差在深度上的瓶颈——为什么需要 AttnRes」。

    2. Full AttnRes 的公式是什么？pseudo-query、keys/values、softmax kernel 各代表什么？

      解答：候选 $k_i=v_i$ 取 embedding 与此前各层输出，权重由 softmax kernel $\phi(q_l,k_i)=\exp(q_l^\top\mathrm{RMSNorm}(k_i))$ 归一化得到，输出为候选的加权求和。

      pseudo-query $q_l=w_l$ 是层自带、不依赖输入的可学习参数向量；keys 与 values 同源，被检索的对象就是被加权求和的对象；softmax kernel 输出正数供归一化，其中的 RMSNorm 防止大幅值 key 主导权重。公式对应 K3 报告 §2.2 Eq.(8)(9)。完整论证见「2. Full AttnRes 的公式——pseudo-query 如何检索前序层」。

    3. Block AttnRes 如何分块、块内求和、块间 attention？内存从 $O(Ld)$ 降到 $O(Nd)$ 的来源是什么？

      解答：把 $L$ 层分为 $N$ 块，块内输出求和成单表征，attention 只作用于块级表征；需保留的表征从 $L$ 个层输出降为 $N$ 个块表征，内存即从 $O(Ld)$ 降为 $O(Nd)$。

      候选集合为历史块快照加上当前块 partial sum（块的第一层除外）。跨 pipeline stage 的通信量随需保留的表征数同比例下降，这是 K3 采用块级形式的直接原因。完整论证见「3. Block AttnRes 的分块与块间 attention——把内存从 $O(Ld)$ 降到 $O(Nd)$」。

    4. K3 的具体配置是什么——8 块×12 层、9 个候选来源、加权三次的位置在哪里？

      解答：K3 主干 93 层按 block size 12 分 8 块（最后一块 9 层），加 embedding 共 9 个块级表征；加权位置为每层 attention 前、MLP 前各一次，模型末尾 final norm 前一次。

      9 个候选是最后一个 block 内 $i\ge 2$ 层的最大候选数（8 个块快照加当前流），其他层的候选数更少。三次加权使用三套独立参数；具体位置与参数字段名来自源码核对，属间接证据。完整论证见「4. K3 的具体配置——8 块×12 层、9 个候选、加权三次」。

    5. softmax kernel 为什么用 $\exp(q^\top\mathrm{RMSNorm}(k))$？RMSNorm 防大值主导的具体含义和边界？

      解答：不加 RMSNorm 时大幅值 key 的内积被幅值放大，softmax 权重几乎集中在该 key；RMSNorm 把 key 缩放到单位均方根，使权重只由方向决定。

      「防大值主导」的含义是消除幅值对权重的影响，让 pseudo-query 按方向选择来源。边界有两条：所有 key 方向接近时 softmax 仍接近均匀，RMSNorm 不能凭空创造选择性；RMSNorm 不防止 $\exp$ 溢出，需工程上的减最大值配合。完整论证见「5. softmax kernel 中的 RMSNorm——为什么不能直接用内积」。

    1. 标准残差在深度上的瓶颈——为什么需要 AttnRes

    标准残差连接（前置概念页）的形式是 $h_{l+1}=h_l+F_l(h_l)$：把第 $l$ 层的输入 $h_l$ 直接加到该层变换 $F_l$ 的输出上。展开 $L$ 层后，第 $L$ 层的残差流是

    $$h_L = h_1 + \sum_{l=1}^{L-1} F_l(h_l).$$

    所有前层的输出以系数 1 累加进同一个流 $h_L$——这就是"等权累加"。它有一个直接后果：深网络中，早期信息会被层层稀释或覆盖。$h_1$ 在 $h_L$ 中只占 $1/L$ 的份额（如果后续 $F_l$ 不特意放大它），而且无法被后续层"按内容找回"——后续层只能被动接收累加好的 $h_l$，没有机制让它回看某一层在 $h_l$ 中的具体贡献。

    K3 报告 §2.2 把这个瓶颈类比为 RNN 在时间维度的瓶颈：

    "Standard residual connections compress all prior information into a single state $h_l$ over depth — a bottleneck reminiscent of RNNs over time."（K3 报告 §2.2）

    RNN 把所有历史时间步压进一个 hidden state，深网络的标准残差在深度维度做同样的事。Transformer 用 attention 解决了 RNN 在时间维度的瓶颈——让每个位置选择性访问所有前序位置；AttnRes 把同样的思路用到深度维度：让每层选择性访问所有前序层的输出，而不是被动接收累加好的 $h_l$。

    标准残差（等权累加，RNN-over-depth 瓶颈）
    $h_1$→ $F_1$→ $F_2$→ $F_3$→ …→ $F_{L-1}$→ $F_L$→ $h_L$ ↓ ↓ ↓ ↓ ↓ ↓ ↓ 等权累加：$h_1$ 与所有 $F_l$ 的输出以系数 1 压进同一个 $h_L$——所有历史挤在单个残差流里
    问题：第 $L$ 层只能看到「累加好的过去」，无法按内容回看某一层。
    AttnRes（沿深度做 attention）
    $h_1$→ $F_1$→ $F_2$→ $F_3$→ …→ $F_{L-1}$→ $F_L$（当前层） ↓ ↓ ↓ ↓ ↓ ↓ 候选 0（$h_1$） 候选 1（$f_1$） 候选 2（$f_2$） 候选 3（$f_3$） … 候选 $L{-}1$（$f_{L-1}$） pseudo-query $q_L$ 用 attention 检索全部候选，按内容分配权重 $\alpha_{i\to L}$
    第 $L$ 层用 pseudo-query $q_L$ 主动检索此前所有层输出，按内容分配权重。

    这里的关键转换是：把"沿深度做累加"替换为"沿深度做 attention"。机制细节由下一章的公式给出。先用一个对照表固定两者的区别：

    维度标准残差AttnRes
    历史如何进入当前层所有前层输出以系数 1 累加进 $h_l$每层用 softmax 权重对前层输出加权求和
    权重来源固定为 1（等权）层 $l$ 自带的可学习 pseudo-query $q_l$ 与 key 内积决定
    能否按内容回看不能——只能接收累加好的 $h_l$能——pseudo-query 按方向选择要回看哪些层
    深度方向类比RNN（历史压进 hidden state）self-attention（每个位置检索所有前序位置）

    需要强调的是：AttnRes 替代的是"等权累加"这个聚合方式"，不是取消标准残差本身。K3 仍逐层累加 attention 与 MLP 的输出（保留标准残差的梯度流动性质，见前置概念页）；AttnRes 是叠加在等权累加之上的"块级加权选择"，把送入归一化的输入从"当前残差流"替换为"用 attention 检索块级历史表征得到的结果"。这个区分是本文最常见的误解之一，后面 K3 具体配置一章会再用 K3 的实际配置印证。[C1]

    为了后续手算，先固定构造示例的小网络：$L=6$ 层、$d=2$、embedding $h_1=[1,0]$，各层输出 $f_1=[0,1]$、$f_2=[1,1]$、$f_3=[0.5,0.5]$、$f_4=[1,0.5]$、$f_5=[0.5,1]$、$f_6=[1,1]$（教学构造，不代表真实模型参数）。Full AttnRes 公式一章用它算第 6 层，Block AttnRes 分块一章升级为分 3 块。

    本章问题

    1. 用一句话说明标准残差在深度上的瓶颈与 RNN 瓶颈的类比关系。

      解答：标准残差把所有前层输出以系数 1 累加进单个残差流，早期信息被层层稀释且无法按内容找回，这与 RNN 把所有历史时间步压进单个 hidden state 是同一种瓶颈，只是维度从时间换成了深度。

      类比的边界：RNN 的 hidden state 是按时间步更新的动态状态，残差流 $h_l$ 是按层累加的静态求和，两者数学性质不同。正式判断以 $h_L=h_1+\sum_{l=1}^{L-1}F_l(h_l)$ 为准。

    2. AttnRes 用什么思路替代等权累加？它替代的是"等权累加方式"还是"标准残差本身"？

      解答：AttnRes 用 softmax 加权检索替代等权累加——每层用可学习 pseudo-query 对前序表征做 attention、按内容分配权重，而非固定系数 1。

      它替代的只是"等权累加"这一聚合方式，即把送入归一化的输入从当前残差流换成 attention 检索结果，不取消标准残差本身：K3 仍逐层累加 attention 与 MLP 的输出，保留残差的梯度流动性质。

    2. Full AttnRes 的公式——pseudo-query 如何检索前序层

    Full AttnRes 对每层 $l$ 定义一个层自带的可学习 pseudo-query $q_l=w_l\in\mathbb{R}^d$。它叫"pseudo"是因为它不依赖该层输入（与标准 attention 中 $Q=W_Q x$ 不同），就是一个层参数向量。keys 与 values 取自此前的层输出（K3 报告 §2.2 Eq.(8)）[C2, F1]：

    $$k_i = v_i = \begin{cases} h_1 & i = 0 \\ f_i(h_i) & 1 \le i \le l-1 \end{cases}$$

    其中 $h_1$ 是 token embedding（始终作为候选来源，$i=0$），$f_i(h_i)$ 是第 $i$ 层的输出。注意 $k_i=v_i$：key 与 value 同源，被检索的对象就是被加权求和的对象。

    权重与输出按 Eq.(9) 计算[C2, F2]：

    $$\phi(q_l, k_i) = \exp\!\bigl(q_l^\top \mathrm{RMSNorm}(k_i)\bigr),\qquad \alpha_{i\to l} = \frac{\phi(q_l, k_i)}{\sum_{j=0}^{l-1} \phi(q_l, k_j)},\qquad h_l = \sum_{i=0}^{l-1} \alpha_{i\to l}\, v_i.$$

    逐项解释：

    • $q_l=w_l\in\mathbb{R}^d$：层 $l$ 自带的可学习 pseudo-query，是参数向量，不依赖 $h_l$。
    • $k_i$：第 $i$ 个来源的 key。$i=0$ 时为 embedding $h_1$；$i\ge 1$ 时为第 $i$ 层输出 $f_i(h_i)$。
    • $v_i$：第 $i$ 个来源的 value，与 $k_i$ 同源。
    • $\mathrm{RMSNorm}(k_i)$：对 key 按均方根归一化，最小说明见下文。
    • $\phi(q_l, k_i)$：softmax kernel，输出正数供 softmax 归一化。
    • $\alpha_{i\to l}$：层 $l$ 对来源 $i$ 的 attention 权重，所有 $\alpha_{i\to l}$ 之和为 1。
    • $h_l$：层 $l$ 的输出（这里指 AttnRes 加权后的结果，会送入后续归一化与子层）。

    RMSNorm 最小说明。RMSNorm 把向量按其均方根归一化（Zhang & Sennrich 2019，K3 报告引用 [148]）[F5]：

    $$\mathrm{RMSNorm}(x) = \frac{x}{\sqrt{\tfrac{1}{d}\sum_{j=1}^d x_j^2 + \epsilon}} \approx \frac{x}{\|x\|_2 / \sqrt d}.$$

    忽略小常数 $\epsilon$，RMSNorm 等价于"把向量缩放到均方根为 1"——也就是只用方向、不用幅值。本文只需要这个结论，不展开推导。RMSNorm 在 kernel 中的作用留给 softmax kernel 中的 RMSNorm 一章详细讨论；本章先把它当作"对 key 做归一化"的零件接受。

    用两个快速检查验证公式。第一，若所有 key 方向相同（如 $k_i=c_i\cdot u$ 对某个单位向量 $u$），则 $\mathrm{RMSNorm}(k_i)=\sqrt d\cdot u$ 对所有 $i$ 相同，$\alpha_{i\to l}=1/l$——权重均匀，pseudo-query 失去选择性。第二，若 pseudo-query $q_l$ 与某个 key $k_j$ 方向高度一致而与其他 key 正交，则 $\alpha_{j\to l}\to 1$——权重集中在该 key。这两个边界说明：AttnRes 的"选择性"来自 key 之间的方向差异，与幅值无关（因为 RMSNorm 已去掉幅值）。

    现在用构造示例手算第 6 层。为了先把 attention 检索的本质讲清，本节暂时不加 RMSNorm（即用 $\phi(q,k)=\exp(q^\top k)$），softmax kernel 中的 RMSNorm 一章再加 RMSNorm 重算并对比。

    构造示例。 $L=6$、$d=2$。对第 6 层，候选 = $[h_1, f_1, f_2, f_3, f_4, f_5]$ = 6 个。设 $q_6=[0.5, 0.5]$。内积 $q_6^\top k_i$ 分别为 $0.5, 0.5, 1.0, 0.5, 0.75, 0.75$；softmax 后权重约为 $0.139, 0.139, 0.228, 0.139, 0.178, 0.178$；加权求和得 $h_6\approx[0.703, 0.703]$。权重最大的是 $f_2$（0.228），因为 $f_2=[1,1]$ 与 $q_6=[0.5,0.5]$ 方向最一致。完整计算过程见下方折叠块。

    展开：Full AttnRes 第 6 层的完整手算（6 个候选，不加 RMSNorm）

    构造示例。 输入：$q_6=[0.5, 0.5]$，6 个候选 $k_i=v_i$ 为

    • $k_0=h_1=[1, 0]$
    • $k_1=f_1=[0, 1]$
    • $k_2=f_2=[1, 1]$
    • $k_3=f_3=[0.5, 0.5]$
    • $k_4=f_4=[1, 0.5]$
    • $k_5=f_5=[0.5, 1]$

    第一步，算内积 $q_6^\top k_i = 0.5\cdot k_{i,0} + 0.5\cdot k_{i,1}$：

    • $q_6^\top k_0 = 0.5\cdot 1 + 0.5\cdot 0 = 0.5$
    • $q_6^\top k_1 = 0.5\cdot 0 + 0.5\cdot 1 = 0.5$
    • $q_6^\top k_2 = 0.5\cdot 1 + 0.5\cdot 1 = 1.0$
    • $q_6^\top k_3 = 0.5\cdot 0.5 + 0.5\cdot 0.5 = 0.5$
    • $q_6^\top k_4 = 0.5\cdot 1 + 0.5\cdot 0.5 = 0.75$
    • $q_6^\top k_5 = 0.5\cdot 0.5 + 0.5\cdot 1 = 0.75$

    第二步，取 exp（保留 4 位小数）：

    • $\exp(0.5)\approx 1.6487$（$k_0, k_1, k_3$ 三个相同）
    • $\exp(1.0)\approx 2.7183$（$k_2$）
    • $\exp(0.75)\approx 2.1170$（$k_4, k_5$ 两个相同）

    第三步，求和与归一化。$\sum_j \phi(q_6, k_j) = 3\times 1.6487 + 2.7183 + 2\times 2.1170 = 11.8984$。权重：

    • $\alpha_{0\to 6} = 1.6487/11.8984 \approx 0.1386$
    • $\alpha_{1\to 6} = 1.6487/11.8984 \approx 0.1386$
    • $\alpha_{2\to 6} = 2.7183/11.8984 \approx 0.2284$
    • $\alpha_{3\to 6} = 1.6487/11.8984 \approx 0.1386$
    • $\alpha_{4\to 6} = 2.1170/11.8984 \approx 0.1779$
    • $\alpha_{5\to 6} = 2.1170/11.8984 \approx 0.1779$

    第四步，加权求和 $h_6 = \sum_i \alpha_{i\to 6}\, v_i$。逐项：

    • $0.1386\cdot [1,0] = [0.1386, 0]$
    • $0.1386\cdot [0,1] = [0, 0.1386]$
    • $0.2284\cdot [1,1] = [0.2284, 0.2284]$
    • $0.1386\cdot [0.5,0.5] = [0.0693, 0.0693]$
    • $0.1779\cdot [1,0.5] = [0.1779, 0.0890]$
    • $0.1779\cdot [0.5,1] = [0.0890, 0.1779]$

    求和：$h_6[0] = 0.1386+0+0.2284+0.0693+0.1779+0.0890 = 0.7032$；$h_6[1] = 0+0.1386+0.2284+0.0693+0.0890+0.1779 = 0.7032$。所以 $h_6\approx [0.703, 0.703]$。

    权重最大的是 $k_2=f_2=[1,1]$（0.228），因为 $f_2$ 与 $q_6=[0.5,0.5]$ 方向最一致。权重最小的是 $k_0, k_1, k_3$（各 0.139），因为它们与 $q_6$ 的内积较小。注意本例没有用 RMSNorm，所以 $f_2=[1,1]$ 的幅值 $\sqrt 2\approx 1.41$ 也放大了它的权重——softmax kernel 中的 RMSNorm 一章会用 RMSNorm 修正这一点。

    这个例子里权重分布比较均匀（最大 0.228、最小 0.139），因为 6 个候选的方向差异不大。但要注意：如果某个候选的幅值远大于其他（比如 $f_2=[10,10]$ 而其他不变），即使方向相近，它的内积也会被幅值放大，softmax 后权重几乎集中在它身上——等于"屏蔽"了其他来源。这个现象叫"大值主导 softmax"，是 softmax kernel 中的 RMSNorm 一章要解决的问题。先用一个补充推导固定这个观察。

    补充：softmax 对大值的敏感性

    设两个 key $k_1, k_2$，pseudo-query $q$。softmax 权重比为

    $$\frac{\alpha_1}{\alpha_2} = \frac{\exp(q^\top k_1)}{\exp(q^\top k_2)} = \exp\!\bigl(q^\top(k_1 - k_2)\bigr).$$

    若 $k_1 = c\cdot u$、$k_2 = u$（$u$ 为单位向量，$c>1$ 为标量放大因子），且 $q$ 与 $u$ 方向一致（$q = \|q\|\cdot u$），则

    $$\frac{\alpha_1}{\alpha_2} = \exp\!\bigl(\|q\|\cdot u^\top (c-1)u\bigr) = \exp\!\bigl((c-1)\|q\|\bigr).$$

    取 $\|q\|=1$、$c=5$，则 $\alpha_1/\alpha_2 = \exp(4)\approx 54.6$——$k_1$ 的权重是 $k_2$ 的 54 倍，softmax 几乎把所有权重给了 $k_1$。这就是"大值主导"：当某个 key 的幅值远大于其他、且方向与 pseudo-query 一致时，softmax 失去选择性。

    这个推导假设 key 没有归一化。softmax kernel 中的 RMSNorm 一章会看到，把 key 先做 RMSNorm（缩放到单位均方根）后再内积，幅值差异被消除，权重只由方向决定。

    Full AttnRes 公式成立[C3]，但它的开销是 $O(Ld)$ 内存——需要保留所有 $L$ 个层输出供后续层检索。K3 主干 93 层、$d=7168$，这个内存（含跨 pipeline stage 通信）是实际瓶颈。

    本章给出了 Full AttnRes 的公式与 pseudo-query 检索机制。但 $O(Ld)$ 内存是实际瓶颈——下一章讲 Block AttnRes 如何分块把内存降到 $O(Nd)$。

    本章问题

    1. 写出 Full AttnRes 的权重公式 $\alpha_{i\to l}$，并说明 $q_l$、$k_i$、$v_i$、$\alpha_{i\to l}$ 各代表什么。

      解答：$\alpha_{i\to l}=\phi(q_l,k_i)\big/\sum_{j=0}^{l-1}\phi(q_l,k_j)$，其中 $\phi(q_l,k_i)=\exp(q_l^\top\mathrm{RMSNorm}(k_i))$。

      $q_l=w_l\in\mathbb{R}^d$ 是层 $l$ 自带的可学习 pseudo-query，不依赖该层输入；$k_i=v_i$ 是第 $i$ 个来源的 key 与 value，$i=0$ 时为 embedding $h_1$，$i\ge 1$ 时为第 $i$ 层输出 $f_i(h_i)$，key 与 value 同源；$\alpha_{i\to l}$ 是层 $l$ 对来源 $i$ 的 attention 权重，全部权重之和为 1。公式来自 K3 报告 §2.2 Eq.(8)(9)。

    2. pseudo-query $q_l=w_l$ 与标准 attention 中 $Q=W_Q x$ 的关键区别是什么？

      解答：关键区别是是否依赖输入——pseudo-query 是层自带的参数向量，对该层任何输入都相同；$Q=W_Q x$ 由当前输入线性变换得到，随输入变化。

      因此 AttnRes 每层的检索方向是训练学出的固定偏好，而标准 attention 的查询内容随输入动态变化。这也让 pseudo-query 无需随输入重新计算，是该机制开销较低的原因之一。

    3. 在 $d=2$、3 个候选 $k_0=[1,0]$、$k_1=[0,1]$、$k_2=[1,1]$、$q=[0.5,0.5]$ 的小例子里手算 softmax 权重（暂不加 RMSNorm）。

      解答：内积为 $0.5$、$0.5$、$1.0$，softmax 权重约为 $0.274$、$0.274$、$0.452$，$k_2$ 权重最大。

      取 exp 得 $1.6487$、$1.6487$、$2.7183$，和为 $6.0157$；归一化得 $\alpha_0\approx 0.274$、$\alpha_1\approx 0.274$、$\alpha_2\approx 0.452$。$k_2=[1,1]$ 与 $q=[0.5,0.5]$ 方向最一致，因此权重最大。注意本例未加 RMSNorm，K3 实际 kernel 始终含 RMSNorm（Eq.(9)）。

    3. Block AttnRes 的分块与块间 attention——把内存从 $O(Ld)$ 降到 $O(Nd)$

    Full AttnRes 的开销有两部分：$O(L^2 d)$ 算力（每层对所有前序层做 attention，共 $L$ 层）与 $O(Ld)$ 内存（保留所有 $L$ 个层输出）。K3 报告 §2.2 指出网络深度 $L<100$ 时算力可承受，实际瓶颈是内存与跨 pipeline stage 通信：

    "Since network depth is modest ($L < 100$), the $O(L^2 d)$ arithmetic of this full form is affordable; the practical overhead is the $O(Ld)$ memory (and cross-stage communication under pipeline parallelism) for keeping all layer outputs alive."（K3 报告 §2.2）

    Block AttnRes 的思路是：把 $L$ 层划分为 $N$ 个 block、每个 block $S=L/N$ 层，block 内的层输出先求和成单表征，attention 只作用在 block 级表征上。这样需要保留的来源从 $L$ 个层输出降到 $N$ 个 block 级表征。

    块内求和（K3 报告 §2.2 Eq.(10) 上方文字）[F3]。设 block $n$ 的层索引集合为 $B_n$，block $n$ 的完整求和为

    $$b_n = \sum_{j\in B_n} f_j(h_j),\qquad b_0 = h_1.$$

    其中 $b_0=h_1$ 是 token embedding，始终作为候选来源。再定义 block $n$ 内前 $i$ 层的 partial sum（部分和）：

    $$b_n^i = \sum_{\substack{j\in B_n \\ j \le i}} f_j(h_j).$$

    $b_n^i$ 表示"当前 block 内已经累加到第 $i$ 层的部分和"——它是 block 内的"当前流"，与历史 block 的完整快照 $b_1, \dots, b_{n-1}$ 一起作为候选。

    候选集合（K3 报告 §2.2 Eq.(10)）[C4, F4]。对 block $n$ 的第 $i$ 层，候选集合按层在 block 中的位置分两种情况：

    $$V = \begin{cases} [b_0, b_1, \dots, b_{n-1}]^\top & i = 1\ (\text{block } n\text{ 的第一层}) \\ [b_0, b_1, \dots, b_{n-1}, b_n^{i-1}]^\top & i \ge 2\ (\text{block } n\text{ 的后续层}) \end{cases}$$

    两种情况的差别是：block 的第一层（$i=1$）还没有"当前流"（block 内尚未累加任何输出），候选只有 $n$ 个历史 block 表征；后续层（$i\ge 2$）多一个当前 block 的 partial sum $b_n^{i-1}$，候选共 $n+1$ 个。attention 仍按 Eq.(8)(9) 计算，但作用在 block 级表征上。

    Full AttnRes（每层对此前所有层输出做 attention）
    层 1→ 层 2→ 层 3→ 层 4→ 层 5→ 层 6→ … ↓ ↓ ↓ ↓ ↓ ↓ 候选 0 候选 1 候选 2 候选 3 候选 4 候选 5
    层 6 的候选 = 6 个层输出（含 embedding）。内存 $O(Ld)$：需保留全部 $L$ 个层输出。
    Block AttnRes（块内求和，块间 attention）
    block 1（层 1-2） $f_1+f_2$ ↓ $b_1$
    →
    block 2（层 3-4） $f_3+f_4$ ↓ $b_2$
    →
    block 3（层 5-6） $f_5+f_6$ ↓ $b_3^i$（partial sum）
    对 block 3 第 2 层（$i=2$）：候选 = $[\,b_0,\ b_1,\ b_2,\ b_3^1\,]$，共 4 个。内存 $O(Nd)$：只保留 $N$ 个 block 级表征 + 当前 partial sum。

    内存对比[C5]。Full AttnRes 需要保留 $L$ 个层输出（$O(Ld)$ 内存），且在 pipeline parallelism 下要在 stage 之间传递这些层输出。Block AttnRes 只需保留 $N$ 个 block 级表征（$O(Nd)$ 内存），跨 stage 通信量同比例下降。K3 报告 §2.2 原文："Under Block AttnRes, memory and communication overhead drop from $O(Ld)$ to $O(Nd)$."

    需要强调的一个细节：候选数随 block index 增长。对 block $n$ 的第 $i\ge 2$ 层，候选数为 $n+1$（$n$ 个历史 block 表征 + 当前 partial sum）。最大候选数出现在最后一个 block 的 $i\ge 2$ 层，为 $N+1$。这个细节在 K3 具体配置一章看 K3 的实际参数时会变得关键——K3 的"9 个候选来源"正是最后一个 block 内 $i\ge 2$ 层的最大候选数。

    现在用构造示例手算 Block AttnRes 版本。把 $L=6$ 层分 3 块、每块 2 层：block 1 = layer 1-2、block 2 = layer 3-4、block 3 = layer 5-6。块内求和：$b_0=h_1=[1,0]$、$b_1=f_1+f_2=[0,1]+[1,1]=[1,2]$、$b_2=f_3+f_4=[0.5,0.5]+[1,0.5]=[1.5,1]$。对 block 3 第 2 层（即 layer 6），候选 = $[b_0, b_1, b_2, b_3^1]$，其中 $b_3^1=f_5=[0.5,1]$，共 4 个候选。用 $q_6=[0.5,0.5]$（暂时不加 RMSNorm），权重约为 $[0.14, 0.38, 0.30, 0.18]$，加权求和得 $h_6\approx[1.059, 1.241]$。完整计算见下方折叠块。

    展开：Block AttnRes 对 block 3 第 2 层的完整手算（4 个候选，不加 RMSNorm）

    构造示例。 输入：$q_6=[0.5, 0.5]$，4 个候选 $k_i=v_i$ 为

    • $k_0=b_0=h_1=[1, 0]$
    • $k_1=b_1=f_1+f_2=[1, 2]$
    • $k_2=b_2=f_3+f_4=[1.5, 1]$
    • $k_3=b_3^1=f_5=[0.5, 1]$

    第一步，算内积 $q_6^\top k_i$：

    • $q_6^\top k_0 = 0.5\cdot 1 + 0.5\cdot 0 = 0.5$
    • $q_6^\top k_1 = 0.5\cdot 1 + 0.5\cdot 2 = 1.5$
    • $q_6^\top k_2 = 0.5\cdot 1.5 + 0.5\cdot 1 = 1.25$
    • $q_6^\top k_3 = 0.5\cdot 0.5 + 0.5\cdot 1 = 0.75$

    第二步，取 exp：$\exp(0.5)\approx 1.6487$、$\exp(1.5)\approx 4.4817$、$\exp(1.25)\approx 3.4903$、$\exp(0.75)\approx 2.1170$。

    第三步，求和与归一化。$\sum_j \phi = 1.6487+4.4817+3.4903+2.1170 = 11.7377$。权重：

    • $\alpha_0 = 1.6487/11.7377 \approx 0.1405$
    • $\alpha_1 = 4.4817/11.7377 \approx 0.3818$
    • $\alpha_2 = 3.4903/11.7377 \approx 0.2974$
    • $\alpha_3 = 2.1170/11.7377 \approx 0.1804$

    第四步，加权求和 $h_6 = \sum_i \alpha_i v_i$。逐项：

    • $0.1405\cdot [1,0] = [0.1405, 0]$
    • $0.3818\cdot [1,2] = [0.3818, 0.7636]$
    • $0.2974\cdot [1.5,1] = [0.4461, 0.2974]$
    • $0.1804\cdot [0.5,1] = [0.0902, 0.1804]$

    求和：$h_6[0] = 0.1405+0.3818+0.4461+0.0902 = 1.0586$；$h_6[1] = 0+0.7636+0.2974+0.1804 = 1.2414$。所以 $h_6\approx [1.059, 1.241]$。

    权重最大的是 $k_1=b_1=[1,2]$（0.382），远高于其他候选。这里要注意：$b_1$ 的幅值 $\sqrt{1+4}=\sqrt 5\approx 2.24$ 是 4 个候选中最大的，它的内积 $1.5$ 也最大——但这并不全是"方向与 $q_6$ 一致"的功劳，而是部分由幅值放大带来。softmax kernel 中的 RMSNorm 一章会看到，加 RMSNorm 后 $b_1$ 的权重会从 0.38 降到 0.26，权重分布更均匀。

    对比 Full AttnRes 公式一章的版本（6 个候选、$h_6\approx[0.703, 0.703]$）：Block AttnRes 用 4 个候选得到 $h_6\approx[1.059, 1.241]$，候选数减少 1/3，但结果不同——因为块内求和 $b_n=f_{2n-1}+f_{2n}$ 改变了 key 的方向与幅值。这是 Block AttnRes 的代价：用块内求和换内存，损失了"逐层精确检索"的能力。K3 报告 §2.2 的经验结论是 $N\approx 8$ 时这个损失可接受（见 K3 具体配置一章）[C6]。

    代码：Block AttnRes 前向计算的伪代码 
    输入：
  L 层主干，分为 N 个 block、每 block S=L/N 层
  embedding h_1 ∈ R^d
  每层变换 f_l（含 attention 子层与 MLP 子层）
  每层 pseudo-query q_l = w_l ∈ R^d（可学习参数）
状态：
  block_snapshots ← [h_1]           # b_0 = embedding，始终在列表里
  current_partial ← 0向量 ∈ R^d     # 当前 block 内的 partial sum，初始为 0
  h ← h_1                            # 当前残差流
对 n 从 1 到 N：                       # 遍历每个 block
  current_partial ← 0向量             # 进入新 block 时重置 partial sum
  对 i 从 1 到 S_n：                  # 遍历 block 内的层（S_n 为该 block 层数）
    l ← (n-1)*S + i                   # 全局层索引
    # 第一步：确定候选集合
    if i == 1:
      candidates ← block_snapshots    # [b_0, b_1, ..., b_{n-1}]
    else:
      candidates ← block_snapshots + [current_partial]  # 加上当前 partial sum
    # 第二步：用 pseudo-query q_l 对 candidates 做 attention（Eq.8-9）
    keys ← candidates                 # k_i = v_i
    normed_keys ← [RMSNorm(k) for k in keys]
    scores ← [exp(q_l · k) for k in normed_keys]
    weights ← scores / sum(scores)    # α_{i→l}
    attn_output ← sum(weights[i] * candidates[i] for i in range(len(candidates)))
    # 第三步：用 attn_output 作为送入归一化的输入（替代当前残差流 h）
    h_norm ← RMSNorm(attn_output)
    attn_out ← attention_sublayer(h_norm)    # KDA 或 Gated MLA
    h ← h + attn_out                         # 标准残差累加仍保留
    # MLP 前再做一次 AttnRes（用另一套参数，伪代码省略重复）
    ...                                       # 同上三步，但用 mlp_res 参数
    mlp_out ← mlp_sublayer(...)
    h ← h + mlp_out
    current_partial ← current_partial + f_l(h_l)  # 更新 partial sum
  # block 结束时把 current_partial 存入 block_snapshots
  block_snapshots.append(current_partial)    # 现在 block_snapshots = [b_0, ..., b_n]
# 模型末尾 final norm 前再做一次 output AttnRes
output ← output_attnres(block_snapshots + [h])  # 用 output_attn_res 参数
final_hidden ← RMSNorm(output)
输出：final_hidden

    伪代码展示三个关键点：(1) 候选集合随 block index 增长，block $n$ 的第 $i\ge 2$ 层有 $n+1$ 个候选；(2) AttnRes 替代的是"送入归一化的输入"，标准残差累加 $h\leftarrow h+\text{attn\_out}$ 仍保留；(3) 每层 attention 前、MLP 前各加权一次（两套独立参数），模型末尾 final norm 前第三次。注意伪代码省略了 K3 的实际工程细节（如 online softmax、TP/SP 通信），只展示机制本身。

    本章问题

    1. Block AttnRes 的分块方式与块内求和 $b_n$ 的定义是什么？$b_0$ 有什么特殊之处？

      解答：把 $L$ 层划分为 $N$ 个 block、每 block $S=L/N$ 层；块内求和 $b_n=\sum_{j\in B_n}f_j(h_j)$，即 block $n$ 内所有层输出之和。

      $b_0=h_1$ 是 token embedding，特殊之处在于它不是任何 block 的求和结果，但始终作为候选来源占据 $i=0$ 的位置。块内还维护 partial sum $b_n^i$（block $n$ 内前 $i$ 层之和），作为当前流参与候选。

    2. 对 block $n$ 的第 $i$ 层，候选集合有哪两种情况？最大候选数是多少？

      解答：$i=1$（block 第一层）时候选为 $[b_0,b_1,\dots,b_{n-1}]$ 共 $n$ 个；$i\ge 2$ 时候选为 $[b_0,b_1,\dots,b_{n-1},b_n^{i-1}]$ 共 $n+1$ 个，多出的 $b_n^{i-1}$ 是当前块的 partial sum。

      最大候选数出现在最后一个 block 的 $i\ge 2$ 层，为 $N+1$。候选数随 block index 增长，K3 的"9 个候选来源"正是 $N=8$ 时的最大值。

    3. 内存从 $O(Ld)$ 降到 $O(Nd)$ 的来源是什么？

      解答：来源是块内求和把"需保留供检索的表征"从 $L$ 个层输出压缩为 $N$ 个 block 级表征。

      Full AttnRes 需保留全部 $L$ 个层输出（$O(Ld)$ 内存），且在 pipeline 并行下要在 stage 之间传递这些输出；Block AttnRes 只需保留 $N$ 个 block 表征加当前 partial sum（$O(Nd)$ 内存），跨 stage 通信量同比例下降。算力 $O(L^2 d)$ 在 $L<100$ 时本就可承受，内存才是实际瓶颈。

    4. K3 的具体配置——8 块×12 层、9 个候选、加权三次

    K3 主干 93 层（69 KDA + 24 MLA，K3 报告 Table 1），按 HuggingFace 官方 config.json 中 attn_res_block_size=12 划分为 8 个 block：前 7 个各 12 层、第 8 个 9 层（$93 = 7\times 12 + 9$，最后一个为 partial block）。加上 embedding 共 9 个 block 级表征[C6, C9, N1]。K3 报告 §2.2 原文：

    "Empirically, $N\approx 8$ recovers most of the benefit across model scales [58]; for Kimi K3, we partition its layers into 8 blocks with 12-layer size, giving a partial final block and 9 total blocks when counting the embedding layer."（K3 报告 §2.2）

    $N\approx 8$ 的最优性是经验结论，来自 K3 报告 §2.2 对原 AttnRes preprint [58] 的转述[C6, N2]。K3 的 8 块×12 层配置本身由 config.json 直接确认（attn_res_block_size=12、num_hidden_layers=93）；最后一个 block 为 9 层由 $93=7\times 12+9$ 直接给出[C9, N1]。

    9 个候选来源的构成。对最后一个 block（block 8）的 $i\ge 2$ 层，候选集合为 $[b_0, b_1, \dots, b_7, b_8^{i-1}]$，共 9 个：

    • $b_0$：token embedding（始终作为候选，$i=0$ 的特殊位置）
    • $b_1, \dots, b_7$：前 7 个完整 block 的块内求和（每个 = 12 层输出之和）
    • $b_8^{i-1}$：当前 partial block（block 8，9 层）的前 $i-1$ 层 partial sum，即"当前流"

    "9 个候选来源（8 块快照 + 当前流）"这个说法对应的就是这个视角：8 个块快照（$b_0$ 即 embedding + $b_1\dots b_7$）+ 当前流（$b_8^{i-1}$）。注意这是最后一个 block 内 $i\ge 2$ 层的视角——其他 block 的层候选数更少（如 block 1 的 $i\ge 2$ 层只有 $[b_0, b_1^{i-1}]$ 共 2 个候选）。K3 报告 §2.2 以最大候选数 9 描述该配置；具体槽位分配的实现细节（预分配与屏蔽策略）属于工程实现，K3 报告未展开，本文不推测。

    embedding $h_1$ ↓ $b_0$（快照）

    …

    加权三次的位置。K3 在每个 attention 子层前与每个 MLP（Stable LatentMoE）子层前各做一次 AttnRes 加权，模型末尾 final norm 前再做第三次。三次使用三套独立的可学习参数：

    • MLP 前：用 mlp_res_norm / mlp_res_proj 参数

    本章问题

    1. K3 主干层数、block 数、block size、最后一个 block 的层数各是多少？9 个候选来源由什么构成？

      解答：主干 93 层（69 KDA + 24 MLA），block size 12，分为 8 个 block：前 7 个各 12 层、最后一个 9 层（$93=7\times 12+9$，partial block）。

      9 个候选来源 = embedding $b_0$ + 前 7 个完整 block 的块内求和 $b_1\dots b_7$ + 当前 partial block 的 partial sum $b_8^{i-1}$，即"8 块快照 + 当前流"，对应最后一个 block 内 $i\ge 2$ 层的候选集合。来源为 K3 报告 §2.2 与 HuggingFace 官方 config.json。

    2. K3 加权三次的具体位置在哪里？哪些位置来自 K3 报告原文确认，哪些来自源码核对？

      解答：三次位置为每个 attention 子层前一次、每个 MLP 子层前一次（两套独立参数）、模型末尾 final norm 前一次（output AttnRes 聚合所有 block 表征）。

      证据层级：K3 报告原文只确认"each module 各加权一次 + 末尾聚合"；具体三次位置与参数字段名（self_attention_res_norm 等）来自 K3 前向数据流 note 对官方源码 modeling_kimi_linear.py 的核对，本页未直接复核源码，标注为间接证据。

    3. "9 个候选来源"对应哪个 block 的哪一层？为什么不是所有层都有 9 个候选？

      解答：对应最后一个 block（block 8）内 $i\ge 2$ 的层——此时历史快照最多（$b_0$ 到 $b_7$ 共 8 个）且已存在当前 partial sum $b_8^{i-1}$，合计 9 个。

      候选数随 block index 增长：block 1 的 $i\ge 2$ 层只有 $[b_0, b_1^{i-1}]$ 共 2 个候选；每个 block 的第一层（$i=1$）还没有当前流，比同 block 的后续层少一个候选。9 是最大候选数而非固定值。

    5. softmax kernel 中的 RMSNorm——为什么不能直接用内积

    Full AttnRes 公式一章暂时跳过了 RMSNorm，用 $\phi(q,k)=\exp(q^\top k)$ 手算了 Full AttnRes 与 Block AttnRes 的权重。本章解释为什么 kernel 里要加 RMSNorm——也就是 $\phi(q,k)=\exp(q^\top\mathrm{RMSNorm}(k))$ 中 RMSNorm 的作用[C3]。

    不加 RMSNorm 的问题。若直接用 $\exp(q^\top k)$，key 的幅值会进入内积。不同层的输出 $f_i(h_i)$ 幅值可能差异很大——某些层经过 attention 或 MLP 后输出模长很大，某些层很小。pseudo-query $q_l$ 与大幅值 key 的内积 $q_l^\top k_i$ 会远大于与其他 key 的内积，softmax 后权重几乎集中在该 key，等于"屏蔽"了其他来源。这与 AttnRes 的设计意图相悖——AttnRes 要让每层按内容（方向）选择来源，而不是按幅值选择。

    Block AttnRes 分块一章的例子已经展示了这个现象：$b_1=[1,2]$ 的幅值 $\sqrt 5\approx 2.24$ 是 4 个候选中最大的，它的内积 $1.5$ 也最大，softmax 后权重 0.382 远高于其他候选。但 $b_1$ 的方向 $[1,2]/\sqrt 5\approx [0.447, 0.894]$ 与 $q_6=[0.5,0.5]$ 的方向 $[0.707, 0.707]$ 其实并不算最一致——$b_2=[1.5,1]$ 的方向 $[0.832, 0.555]$ 与 $q_6$ 更接近。也就是说，$b_1$ 的高权重部分来自幅值放大，不全是方向选择。

    RMSNorm 的作用。把每个 key 先做 RMSNorm（缩放到均方根为 1，等价于只用方向、不用幅值），再与 pseudo-query 内积，权重就只由方向决定：

    $$\phi(q_l, k_i) = \exp\!\bigl(q_l^\top \mathrm{RMSNorm}(k_i)\bigr),\qquad \mathrm{RMSNorm}(k_i) \approx \frac{k_i}{\|k_i\|_2 / \sqrt d}.$$

    K3 报告 §2.2 原文："the RMSNorm prevents layers with large-magnitude outputs from dominating the weights." RMSNorm 把所有 key 缩放到相同幅值（均方根为 1），pseudo-query 按方向而非幅值选择来源，权重更平滑。

    两个失效边界。第一，若所有 key 方向接近（即使幅值差异大），RMSNorm 后方向仍接近，softmax 仍接近均匀——RMSNorm 不能凭空创造选择性。第二，RMSNorm 不保证 $\exp$ 不溢出：若 $q_l$ 与某个归一化后的 key 内积很大（如 $q_l$ 本身幅值很大且方向一致），$\exp$ 仍可能溢出。工程实现通常在 softmax 前减去最大值（即 $\phi(q,k)=\exp(q^\top\mathrm{RMSNorm}(k)-m)$，$m$ 为 batch 内最大值），这是 softmax 的标准数值稳定技术，不属于 RMSNorm 的职责。

    现在用 Block AttnRes 分块一章的例子加 RMSNorm 重算，对比权重分布的变化。4 个候选 $b_0=[1,0]$、$b_1=[1,2]$、$b_2=[1.5,1]$、$b_3^1=[0.5,1]$，$q_6=[0.5,0.5]$。RMSNorm 后再内积，权重从"不加 RMSNorm 时的 $[0.14, 0.38, 0.30, 0.18]$"变为"加 RMSNorm 后的 $[0.21, 0.26, 0.27, 0.26]$"。$b_1$ 的权重从 0.38 降到 0.26，权重更均匀——因为 $b_1$ 的高权重部分来自幅值放大，RMSNorm 把这部分去掉了。完整计算见下方折叠块。

    展开：同一例子在"不加 RMSNorm"与"加 RMSNorm"两种情况下的权重对比

    构造示例。 沿用 Block AttnRes 分块一章的例子：4 个候选 $b_0=[1,0]$、$b_1=[1,2]$、$b_2=[1.5,1]$、$b_3^1=[0.5,1]$，$q_6=[0.5,0.5]$，$d=2$，$\sqrt d=\sqrt 2\approx 1.4142$。

    情况 A：不加 RMSNorm（Block AttnRes 分块一章已算）。内积 $q_6^\top k_i = [0.5, 1.5, 1.25, 0.75]$，softmax 权重 $\approx [0.1405, 0.3818, 0.2974, 0.1804]$，加权求和得 $h_6\approx [1.059, 1.241]$。

    情况 B：加 RMSNorm。先对每个 key 算 RMSNorm：

    • $\|b_0\|_2 = \sqrt{1+0} = 1$；$\mathrm{RMSNorm}(b_0) = [1,0]/(1/1.4142) = [1.4142, 0]$
    • $\|b_1\|_2 = \sqrt{1+4} = \sqrt 5 \approx 2.2361$；$\mathrm{RMSNorm}(b_1) = [1,2]/(2.2361/1.4142) = [1,2]/1.5811 \approx [0.6325, 1.2649]$
    • $\|b_2\|_2 = \sqrt{2.25+1} = \sqrt{3.25} \approx 1.8028$；$\mathrm{RMSNorm}(b_2) = [1.5,1]/(1.8028/1.4142) = [1.5,1]/1.2748 \approx [1.1767, 0.7845]$
    • $\|b_3^1\|_2 = \sqrt{0.25+1} = \sqrt{1.25} \approx 1.1180$；$\mathrm{RMSNorm}(b_3^1) = [0.5,1]/(1.1180/1.4142) = [0.5,1]/0.7906 \approx [0.6325, 1.2649]$

    验证：每个 RMSNorm 后的向量均方根应为 1。如 $\mathrm{RMSNorm}(b_1)=[0.6325, 1.2649]$，$\sqrt{(0.6325^2+1.2649^2)/2}=\sqrt{(0.4+1.6)/2}=\sqrt 1=1$。✓

    第二步，算内积 $q_6^\top \mathrm{RMSNorm}(k_i)$：

    • $q_6^\top \mathrm{RMSNorm}(b_0) = 0.5\cdot 1.4142 + 0.5\cdot 0 = 0.7071$
    • $q_6^\top \mathrm{RMSNorm}(b_1) = 0.5\cdot 0.6325 + 0.5\cdot 1.2649 = 0.9487$
    • $q_6^\top \mathrm{RMSNorm}(b_2) = 0.5\cdot 1.1767 + 0.5\cdot 0.7845 = 0.9806$
    • $q_6^\top \mathrm{RMSNorm}(b_3^1) = 0.5\cdot 0.6325 + 0.5\cdot 1.2649 = 0.9487$

    第三步，取 exp 与归一化。$\exp(0.7071)\approx 2.0281$、$\exp(0.9487)\approx 2.5822$、$\exp(0.9806)\approx 2.6658$、$\exp(0.9487)\approx 2.5822$。$\sum = 2.0281+2.5822+2.6658+2.5822 = 9.8583$。权重：

    • $\alpha_0 = 2.0281/9.8583 \approx 0.2058$
    • $\alpha_1 = 2.5822/9.8583 \approx 0.2620$
    • $\alpha_2 = 2.6658/9.8583 \approx 0.2704$
    • $\alpha_3 = 2.5822/9.8583 \approx 0.2620$

    第四步，加权求和（value 仍是原始 $b$，RMSNorm 只用在 key 上）：

    • $0.2058\cdot [1,0] = [0.2058, 0]$
    • $0.2620\cdot [1,2] = [0.2620, 0.5240]$
    • $0.2704\cdot [1.5,1] = [0.4056, 0.2704]$
    • $0.2620\cdot [0.5,1] = [0.1310, 0.2620]$

    求和：$h_6[0] = 0.2058+0.2620+0.4056+0.1310 = 1.0044$；$h_6[1] = 0+0.5240+0.2704+0.2620 = 1.0564$。所以加 RMSNorm 后 $h_6\approx [1.004, 1.056]$。

    关键观察：$b_1$ 在不加 RMSNorm 时权重最大（0.382），但它的幅值也最大（2.24）——它的权重部分由幅值放大带来。加 RMSNorm 后 $b_1$ 权重降到 0.262，与其他候选接近；权重最大变成 $b_2$（0.270），因为 $b_2$ 的方向 $[0.832, 0.555]$ 与 $q_6=[0.5,0.5]$ 的方向 $[0.707, 0.707]$ 最一致。这就是 RMSNorm 的作用：把"按幅值选择"换成"按方向选择"，权重更平滑。注意 value 仍是原始 $b$（RMSNorm 只用在 key 上），所以 $h_6$ 的幅值仍受 $b_1$ 的大幅值影响——RMSNorm 改变的是权重分配，不是 value 的尺度。

    补充：softmax 大值敏感性的形式化

    设两个 key $k_1, k_2$，pseudo-query $q$。softmax 权重比为

    $$\frac{\alpha_1}{\alpha_2} = \frac{\exp(q^\top k_1)}{\exp(q^\top k_2)} = \exp\!\bigl(q^\top(k_1 - k_2)\bigr).$$

    指数函数对差异高度敏感：$q^\top(k_1-k_2)=2$ 时 $\alpha_1/\alpha_2\approx 7.4$；$q^\top(k_1-k_2)=5$ 时 $\alpha_1/\alpha_2\approx 148$。这意味着 key 之间小的内积差异会被指数放大成大的权重差异。

    若 $k_1 = c\cdot u$、$k_2 = u$（$u$ 为单位向量，$c>1$ 为幅值放大因子），且 $q$ 与 $u$ 方向一致（$q=\|q\|\cdot u$），则

    $$\frac{\alpha_1}{\alpha_2} = \exp\!\bigl(\|q\|\cdot(c-1)\bigr).$$

    取 $\|q\|=1$、$c=5$，则 $\alpha_1/\alpha_2 = \exp(4)\approx 54.6$——$k_1$ 权重是 $k_2$ 的 54 倍。加 RMSNorm 后 $k_1, k_2$ 都被缩放到均方根 1，$c$ 被消去，$\alpha_1/\alpha_2 = \exp(0) = 1$——权重均匀。这就是 RMSNorm 防大值主导的数学机制。

    边界：若 $q$ 与 $u$ 不完全一致（$q^\top u < \|q\|$），RMSNorm 后权重比仍由方向决定，但不会归零。若所有 key 方向相同，RMSNorm 后所有 key 相同，softmax 完全均匀——RMSNorm 不能凭空创造选择性。

    本章问题

    1. 不加 RMSNorm 时，大 key 为什么会主导 softmax？

      解答：softmax 权重比 $\alpha_1/\alpha_2=\exp(q^\top(k_1-k_2))$，指数函数把 key 之间的内积差异放大为权重差异，幅值大的 key 内积也大，权重几乎全部分配给它。

      量化地看：内积差 2 时权重比约 7.4 倍，差 5 时约 148 倍；若 $k_1=c\cdot u$（$c=5$）且方向与 $q$ 一致，权重比达 $\exp((c-1)\|q\|)\approx 54.6$。此时 softmax 失去按内容选择的能力，等于屏蔽了其他来源。

    2. RMSNorm 改变了 key 的什么、不改变什么？value 是否受 RMSNorm 影响？

      解答：RMSNorm 把 key 缩放到单位均方根，改变的是进入内积的幅值，不改变方向；value 不受影响——加权求和仍使用原始候选。

      因此权重的分配从"按幅值与方向"变为"只按方向"，但输出 $h_l$ 的幅值仍受大候选 value 的影响：RMSNorm 改变的是权重分配方式，不是 value 的尺度。

    3. RMSNorm 的两个失效边界是什么？

      解答：其一，若所有 key 方向接近，RMSNorm 后方向仍接近，softmax 仍接近均匀——RMSNorm 不能凭空创造选择性；其二，RMSNorm 不保证 $\exp$ 不溢出。

      第二条边界的细节：若 pseudo-query 本身幅值很大且与归一化后的 key 方向一致，指数仍可能溢出；工程实现通常在 softmax 前减去最大值，这是 softmax 的标准数值稳定技术，不属于 RMSNorm 的职责。

    • softmax 大值敏感性推导（Full AttnRes 公式一章末尾与 RMSNorm 一章折叠块）：教学推导，用 $k_1=c\cdot u$、$k_2=u$ 的简化模型说明大 key 主导 softmax 的数学机制。

    辅助解释与类比边界

    • "深度方向的 RNN 瓶颈"类比（标准残差瓶颈一章）：把标准残差的等权累加类比为 RNN 把所有历史压进 hidden state。这个类比只解释"所有历史被压成单一流"的结构相似性，不覆盖 RNN 的梯度问题、不覆盖 Transformer attention 的完整机制。失效边界：RNN 的 hidden state 是按时间步更新的动态状态，标准残差的 $h_l$ 是按层累加的静态求和，两者数学性质不同。正式判断以 $h_L=h_1+\sum_l F_l(h_l)$ 为准。
    • "沿深度做 attention"类比（标准残差瓶颈一章）：把 AttnRes 类比为序列方向的 self-attention 用到深度维度。这个类比只解释"用 softmax 加权替代等权累加"的思路，不覆盖 self-attention 的位置编码、causal mask、多头等机制。失效边界：序列 attention 的 key/value 来自同一层不同位置，AttnRes 的 key/value 来自不同层同一位置；序列 attention 的 $Q$ 依赖输入，AttnRes 的 $q_l=w_l$ 不依赖输入。正式判断以 Eq.(8)(9) 为准。
    • "按方向而非幅值选择"解释（RMSNorm 一章）：把 RMSNorm 的作用解释为"让 pseudo-query 按方向选择来源"。这个解释只适用于 key 之间幅值差异大的情况；若 key 幅值接近，RMSNorm 几乎不改变结果。失效边界：RMSNorm 不创造方向差异，只去掉幅值差异；若所有 key 方向相同，RMSNorm 后 softmax 仍均匀。正式判断以 $\phi(q,k)=\exp(q^\top\mathrm{RMSNorm}(k))$ 为准。

    简化条件及其限制

    • Full AttnRes 与 Block AttnRes 手算暂时不加 RMSNorm。简化做法：先用 $\phi(q,k)=\exp(q^\top k)$ 手算，RMSNorm 一章再加 RMSNorm 重算对比。可推出：attention 检索的本质是 softmax 加权。不可推出：真实 K3 的权重分布——K3 实际 kernel 始终含 RMSNorm（Eq.9），不存在"不加 RMSNorm"的版本。
    • 小例子用 $d=2$。简化做法：用 $d=2$ 让 4-6 个候选的 softmax 与 RMSNorm 都能逐位手算。可推出：RMSNorm 的"按方向选择"性质。不可推出：$d=7168$ 时的具体数字——真实 K3 的 $\sqrt{7168}\approx 84.7$，机制相同但数字不直观，RMSNorm 的性质与 $d$ 无关。
    • 伪代码省略工程细节。简化做法：伪代码只展示 Block AttnRes 的分块、候选、attention 三步循环。可推出：Block AttnRes 的数学定义与数据流。不可推出：K3 的实际 kernel 实现——K3 的 Block AttnRes kernel 是两阶段 schedule（inter-block + intra-block，见 §5.4.2）、含 online softmax 与 TP/SP 通信，工程优化改变吞吐与显存，不改变数学定义。
    • softmax 与 RMSNorm 不展开为独立概念页。简化做法：两者在本文中只作为公式零件使用，给最小说明。可推出：AttnRes 公式的理解。不可推出：softmax 的变体、RMSNorm 的推导与工程实现——读者可参考 Goodfellow et al. 2016 §6.2.2（softmax）与 Zhang & Sennrich 2019（RMSNorm）。
