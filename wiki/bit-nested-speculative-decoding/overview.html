Bit-Nested Speculative Decoding

位嵌套自投机解码用同一份模型位表示支持草稿和目标：草稿是先猜后续 token 的低开销模型，目标验证这些候选；先量化出 W4 基底，再用残差补成 W8 目标，草稿只读基底，目标读基底加残差。

一个 8-bit 表示里的 W4/W8 两个视图

每个权重（模型里的可学参数）的实数值先量化（舍到少数整数码）成 4 位基底；4 位残差补它的误差，合成 8 位目标。W4 和 W8 指每个权重分别存 4 位、8 位整数代码的两种视图。位嵌套自投机解码就用同一份模型位表示支持两个模型角色。

投机解码让一个低开销的草稿模型先猜几个 token（模型处理文本的最小单位），再由一个目标模型验证。位嵌套自投机解码的草稿由目标模型自身导出，不用另一份草稿模型。

省草稿存储，也不把目标压到 W4

只用一份低精度表示能省存储，但最终模型能力也被压到低精度；额外保留低精度草稿又会和目标权重、KV cache 共同占用内存。KV cache 是生成时保存历史 key 和 value 的缓存，key 用来和当前位置比较，value 用来加权求和。位嵌套先建一个 W4 草稿基底，再用残差恢复 W8 目标，因此既不用多存一份草稿，也不把验证时的目标停在 W4。

先建 W4，补残差成 W8，按平面读

构造时先做等价旋转（保持模型函数不变的变换），再用 GPTQ（一种训练后量化算法）建 128 个连续权重一组的 W4 基底并固定；残差按基底缩放的 $1/16$ 编码，合成码为 $16q_4+q_r$。基底码和残差码分别连续打包成两个 4-bit 位平面；草稿只读基底平面，目标模型读两个平面。KV cache 按 BitNest 策略，短上下文（输入 token 序列长度短）中草稿和验证都读 KV8（8 位 key/value 视图），长上下文草稿读 KV4（4 位 key/value 视图）、验证读 KV8。草稿猜出候选后，目标模型仍按投机解码的规则验证。
