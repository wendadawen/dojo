DCP

DCP（解码上下文并行，decode context parallelism）把解码时不断增长的 KV cache（键和值，每个 token 算出的两个向量）沿 token（模型处理文本的最小单位）位置维切到多张卡上分片存放，每张卡只保留一段，用更小的缓存占用换取更大的批和更高的吞吐。

每张卡只留一段 KV cache

解码（decode）是模型逐 token 生成、每步都要读全部历史 KV 的阶段。解码上下文并行（DCP）把这份 KV cache 沿 token 位置维切到多张卡，每张卡只存一段，缓存占用随卡数下降。

头维切到头就只剩重复

KV cache 起初沿注意力头（注意力让每个 token 和已有的 token 比对、按相关度加权取值，头是其中负责一组键和值的单元，模型有若干个）分配：普通张量并行把缓存沿头切开，每张卡拿一组头。头数由模型结构定死，是能分给一张卡的最小单位，切到每卡一个头就到上限。分组查询注意力（GQA）和多头潜在注意力（MLA）的 KV 头都很少，张量并行度超过头数后，多出来的卡只能拿同一组头的重复副本。重复副本占走显存（GPU 的内存），能同时服务的请求数就被压低。

聚查询、算部分注意力、按 LSE 合并

每张卡只存一段 KV，解码一步里新 token 的查询（query，注意力和历史比对用的向量）却要和全部历史键（key）打分，所以先把完整的查询聚到每张卡，各卡在本地切片上算出一份部分注意力和它的 LSE（log-sum-exp，记这一份部分结果总权重的对数值），再用 LSE 给各份结果加权合并，得到和一张卡直接算全部键一致的结果。
