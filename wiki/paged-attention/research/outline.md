# paged-attention 文章大纲

## 1. 页面开头

- 开篇具体问题：KV cache 动态增长（kv-cache 页结论），那显存怎么分给每个请求？按最大长度预留——一个 2048 上限的请求只生成 100 token，其余 1948 token 的空间白占；按需增长——又要在连续显存里挪动。vLLM 给的答案借自操作系统：分页。
- 简要解释：PagedAttention 把 KV cache 切成固定 token 数的页，页可以放在显存任何位置，用页表维护逻辑顺序；显存浪费从最高约 80% 降到接近零。
- 核心问题（学习目标 Q1–Q4）。
- 首个示例：两个请求 A（上限 2048、实际 100 token）与 B（上限 512、实际 500 token）在连续预留方案下的浪费账（第 1 章展开）。
- 过渡：先算清旧方案到底浪费在哪。

## 2. 章节设计

### 第 1 章 连续预留的三类浪费

- 章节问题：按最大长度预分配连续显存，浪费从哪来、有多大？
- 答案要点：三类浪费——预留槽（为未来 token 保留未用）、内部碎片（实际 < 最大）、外部碎片（预留大小不一，分配器切出用不掉的空洞）（C1）；实测既有系统 KV cache 显存只有 20.4%–38.2% 存了实际 token 状态（C2、N1）；浪费直接压低可并发批大小（显存是批大小上限，vLLM §1 论证）。构造示例手算：A 浪费 2048−100=1948 token 槽位（内部碎片+预留）、B 基本用满；二者尺寸不同还造成外部碎片。
- 正文要点：把 kv-cache 页的"动态增长"结论作为前提；三类浪费逐个定义并落到 A/B 例子上；结尾指出"浪费的不是显存本身而是并发能力"。
- 表达材料：A/B 浪费账手算（数值示例）；三类浪费对照表（组件 14：类型、发生时机、能否回收）。
- 前置知识：kv-cache 页链接（开篇"动态增长"处）。
- 折叠块：展开：A/B 例子的完整浪费计算（含预留/内部/外部三部分逐项数字，标注构造）。

### 第 2 章 分页机制——块、块表与按需分配

- 章节问题：分页怎么把三类浪费消掉？
- 答案要点：KV cache 切成固定 token 数的块（页）；逻辑顺序连续、物理位置任意；块表映射逻辑块号→物理块号，注意力 kernel 按块表取块（C3、C5）；按需分配（写满一块才申请新块）把内部碎片压到每请求最后一块（C6、推断标注"平均半块"）；所有块同大小 → 任何空闲块可用 → 外部碎片消除（C4）；块粒度共享使同请求分支与跨请求共享成为可能（C4，一句指向 prefix-caching 页）。注意力数学不变，变的是存储布局（误解 1 处理）。
- 正文要点：先给"逻辑/物理分离"的结构（可用一个 HTML 结构图），再逐一对回第 1 章三类浪费说明如何消除；OS 类比用论文原话（块-页、token-字节、请求-进程），标注为类比。
- 表达材料：结构 B 层级图或结构 A 流程图（token 流 → 写满当前页 → 查块表 → 分配新物理块）；A/B 例子重算（分页后 A 只占 7 页（页 16）+ 半页浪费）。
- 折叠块：展开：A/B 例子在页 16 下的新账（7 页 × 16 = 112 槽、内部碎片 12 token、无外部碎片）。

### 第 3 章 页间不连续——为显存设计，被传输惩罚

- 章节问题：为显存管理而生的分页，在什么场景下变成了缺点？
- 答案要点：页很小（TensorRT-LLM 32、vLLM 16、SGLang 1，C7、N2）——小页服务显存利用率与缓存匹配粒度；序列数据因此散布在大量不连续页中，页内连续、页间不连续（C8）；GPU 内计算无碍（kernel 按块表逐块取），跨内存层搬运时每次只能传一页（KB–MB 级），小传输打不满 PCIe（N4：8192 token 仅 22% 带宽，引用 Strata 实测）；"分页不解决容量"边界（误解 4）：利用率 ≠ 容量，放不下仍需分层或逐出。过渡：分层缓存的传输瓶颈正是 Strata 页主题（链接）。
- 正文要点：用 A/B 例子换成 20,000 token 文档量化"625 页、页 4 MB（页 32）"（N3）；强调页间不连续与页大小是两个独立维度（不连续性来自布局、传输大小来自页大小）。
- 表达材料：页大小换算表（页 1/16/32 → 每页字节，Llama-3.1-8B 128 KB/token）。
- 前置知识：gpu-communication 页链接（PCIe 带宽语境首次出现时）。
- 折叠块：补充：vLLM CUDA GPU 页大小上限 32 的出处与"页大小可配置"说明（Strata §3.1 引 vLLM 文档）。

### 第 4 章 页大小怎么选——一个没有免费午餐的旋钮

- 章节问题：小页与大页各自的收益与代价是什么，为什么没有普适最优？
- 答案要点：小页——内部碎片小、按页匹配的前缀缓存粒度细（命中率高）、显存利用率高；大页——块表短、间接寻址与元数据开销低、跨层传输单位大（C7 论述 + 推断：匹配粒度结论）；三系统默认值不同本身就是权衡证据（N2）；页大小选择留给部署者，Strata 的 GPU-assisted I/O 让传输效率对页大小不敏感从而免调参（一句带过 + 链接 Strata 页，标注该页实验支撑）。
- 正文要点：以"旋钮"框架收束四个目标；给出三系统默认值表；结尾一句通向 prefix-caching（页粒度匹配的机制）与 Strata（传输效率）。
- 表达材料：权衡对照表（组件 14：维度、小页、大页）。
- 折叠块：无。
