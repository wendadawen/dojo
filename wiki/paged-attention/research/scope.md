# paged-attention 内容范围

## 1. 概念歧义处理

PagedAttention：vLLM（SOSP 2023, Kwon et al.）提出的 KV cache 分页管理机制（注意力算法在分页/非连续内存上运行）。与操作系统"分页"（虚拟内存页）是类比关系而非同一对象；与 GPU 硬件页表无关。同名风险：TensorRT-LLM 等引擎把自己的 KV cache 分页实现也统称 paged attention（Strata 论文即把"当前系统采用 PagedAttention"作为通用事实引用）。处理：已裁定——本页讲机制本身（固定大小块 + 非连续存储 + 块表映射，源自 vLLM 论文），并把"各引擎的分页实现"作为该机制的采用情况提及（页大小各异：TensorRT-LLM 32、vLLM 16、SGLang 1，引 Strata 论文 §2.2）。

## 2. 概念含义

- 名称：PagedAttention（分页注意力）；分页 KV cache 管理
- 简要定义：把每个请求的 KV cache 切成固定 token 数的页，页在显存中不必连续，用页表把逻辑顺序映射到物理位置——用操作系统的分页思想管理 KV cache。
- 正式定义（与 vLLM 论文一致）：受虚拟内存与分页启发的注意力算法：将请求的 KV cache 划分为块（block/page），每块存放固定数量 token 的 key/value；块不必连续存储，可像 OS 分页一样灵活管理（vLLM §2 "PagedAttention divides the request's KV cache into blocks, each of which can contain the attention keys and values of a fixed number of tokens... the blocks for the KV cache are not necessarily stored in contiguous space"）。
- 本文语境：GPU 显存内的 KV cache 存储管理。
- 包括：连续预留的三类浪费；分页机制（块、块表、逻辑/物理分离）；按需分配与块级共享；内部碎片残留；页大小的影响与各系统取值；分页对跨内存层数据搬运的影响（一句话引出 Strata 的问题域）。
- 不包括：跨请求前缀复用的匹配与逐出（prefix-caching 页）；CPU/SSD 分层缓存（Strata 页范围）；vLLM 的调度器/抢占/并行策略（另一层机制）；copy-on-write 共享的分支解码细节（vLLM 论文有 beam search 共享，本页以一句"块级共享使同请求分支与跨请求共享成为可能"带过，深入归 prefix-caching 页）。
- 相邻概念：OS 虚拟内存分页（类比来源，页-字节、进程-请求的对应是论文原文类比）；显存碎片的外部/内部碎片术语（借自 OS）；prefix caching（建立在页粒度上的跨请求复用）。

## 3. 学习目标

### Q1：连续预留为什么浪费，浪费多少？

- 完成答案：既有系统（vLLM 之前）为每个请求按最大可能长度预留连续显存，产生三类浪费：预留槽（为未来 token 保留）、内部碎片（实际长度 < 最大长度，按最大长度分配的剩余）、外部碎片（各请求预留大小不一，分配器（如 buddy allocator）切出的空洞）。实测既有系统只有 20.4%–38.2% 的 KV cache 显存真正存了 token 状态（vLLM 论文 Figure 2 profiling）。浪费直接限制并发批大小。
- 为什么核心：分页的全部动机。
- 依赖内容：kv-cache 页（KV cache 是什么、动态增长）。

### Q2：分页机制怎么做——块、块表、非连续存储？

- 完成答案：KV cache 划分为固定大小块（每块固定 token 数）；逻辑上序列的 token 顺序连续，物理上块放在显存任意空闲位置；每请求一张块表（block table）记录逻辑块号到物理块号的映射；注意力 kernel 读块表取数。分配按需进行：token 写满一块才分配下一块。因所有块同大小，外部碎片消失（任何空闲块可用）；内部碎片只剩每请求最后一块的平均半块。
- 为什么核心：机制本体。
- 依赖内容：Q1、kv-cache 页。

### Q3：分页带来了什么新问题？

- 完成答案：为显存管理而设计的页很小（TensorRT-LLM 32、vLLM 16、SGLang 1 token），一个序列的 KV cache 散布在大量不连续的页中；页内数据连续、页间不连续。GPU 内计算无碍（kernel 按块表逐块取），但跨内存层（CPU↔GPU）搬运时每次传输只能按页进行，KB 级小传输无法打满 PCIe 带宽——这是分层缓存的传输瓶颈来源（Strata 页主题，本页以一段过渡）。另注意：分页解决的是显存浪费，不解决显存容量本身（放不下还是要分层/逐出）。
- 为什么核心：理解"为什么页不能任意加大"以及分页设计的边界；直接衔接 Strata 页动机。
- 依赖内容：Q2、gpu-communication 页（互联带宽概念，可选）。

### Q4：页大小怎么选——小页与大页的权衡？

- 完成答案：小页的好处——内存利用率高（内部碎片 ≤ 半页）、按页匹配的前缀缓存粒度细（命中率高）；大页的好处——块表更短、元数据与间接寻址开销低、跨层传输单位大（高效）。各系统默认值：TensorRT-LLM 32、vLLM 16（CUDA GPU 上限 32）、SGLang 1。页大小是"显存效率/缓存粒度"与"传输效率/管理开销"的权衡，没有普适最优；Strata 的 GPU-assisted I/O 让传输效率对页大小不敏感（一句带过，链接 Strata 页）。
- 为什么核心：页大小是后续两页（prefix-caching 的命中率、Strata 的传输）反复出现的自变量。
- 依赖内容：Q2、Q3。

## 7. 常见误解和适用边界

误解：

1. "PagedAttention 是新的注意力数学"——注意力计算本身不变，变的是 KV cache 的存储布局与 kernel 取数方式（在非连续块上执行同样的注意力）。影响 Q2。
2. "分页消除了所有浪费"——外部碎片消除，内部碎片残留（每请求最后一块平均浪费半页）；页越小内部碎片越少但不是零。影响 Q2。
3. "页越大越好（传输快）"——大页降低按页匹配的缓存粒度、提高内部碎片与预留浪费（半页变大），传输收益换来缓存损失；这是 Strata 页动机的权衡，本页 Q4 给框架。影响 Q3、Q4。
4. "分页让显存够用了"——分页提高利用率（限制并发数的浪费减少），不增加容量；长上下文缓存仍会超出显存，需要分层（Strata 页）或逐出。影响 Q3。

适用边界：机制针对显存内 KV cache 的组织；结论（近零浪费）指 KV cache 部分而非整个显存；页大小默认值是各引擎实现选择（可配置），非算法要求；分页与连续批处理、张量并行兼容（vLLM 论文 §4）。

## 8. 论断分级

- 文献已有结论：三类浪费与 20.4%–38.2%（vLLM 论文 §3、Figure 2/3）；分页机制与块表、按需分配、外部碎片消除、内部碎片≤半块、块级共享（vLLM 论文 §2/§4）；页大小取值 TensorRT-LLM 32 / vLLM 16 / SGLang 1、每 token 十几 KB 到几 MB（Strata 论文 §2.2）；分页导致数据碎片化、小传输无法打满 PCIe（Strata 论文 §1/§3.1，作为后果引用）。
- 基于证据的推断："内部碎片平均半页/请求"（vLLM 原文 "at most one block"，平均值是均匀假设下的推断，标注）；"大页降低按页匹配的缓存命中率"由匹配机制直接得出（Strata 论文实验证实，页内引用其结论但不复制实验）。
