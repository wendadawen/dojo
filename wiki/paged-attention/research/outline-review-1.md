## 处理

读者：

- 开头补链接 `[标准注意力](wiki/standard-attention)`（该页存在，讲的是标准注意力本身）。成立，采纳。
- 开头先交代生成的两阶段（预填、逐个解码）。成立：main.tex LLM Service 正是讲这个，属基线外、要一段才讲清，但在 LLM serving 语境里是必须的铺垫，放进开头一句话交代，纳入开头依据。采纳。
- 删去「可按层、按头各成一块」。成立：这是实现细节、非核心机制，删掉同时去掉未解释的「层」「头」。采纳。
- token 解释。成立：参照 KV cache 页，短页本节与长页开头各用一句「token 是被处理的最小文本单位」。采纳。

对照资料：

- 「浪费只剩末块」位置错。成立：原文在「Decoding with」节（main.tex L226）。该句被篇幅审查者判为与「一个序列从头生成」重复，合并处理：概念只留在「一个序列从头生成」节，依据指 main.tex Decoding with；「省下多少显存」节删去该句，只留数字。采纳。
- 「随块大小择一」位置错。成立：原文在「Comparing Recomputation and Swapping」（main.tex L479）。依据改指该节，并补限定「还取决于 CPU 与 GPU 之间的带宽和 GPU 的算力」（main.tex L319）。采纳。
- 「要自写读块内核」依据缺。成立：原文在「Kernel-level Optimization」（main.tex L358-L362）。依据补该节。采纳。
- 另：审查者指出 main.tex 行号整体偏移约 8 行。核实属实（我此前按拼接输出计数）。全部 main.tex 依据改用章节标题定位，不再用行号。采纳。

篇幅与冗余：

- 开头写具体机制：成立。开头改为只作一句总览（是什么、为什么、大概怎么做），不写「块可不连续、按块算」等机制，预算 550 → 450。采纳。
- 20.4% 两处重复：成立。数字只留「省下多少显存」节的 20.4% - 38.2%，「连续存法浪费在哪里」只说「有效内存很低」。采纳。
- 核心机制节预算小于背景节：成立。重排预算：「显存」300 → 250、「连续存法」350 → 250（去掉数字后本就该短）、「切块」200 → 300、「一个序列从头生成」250 → 300。核心机制节现在不低于背景节。采纳。
- 「浪费限于一个块内」与「浪费只剩末块」重复：与对照资料的合并处理一致，概念只留「一个序列从头生成」一处。采纳。
- 短页 §3 讲两件事：成立。删去引用计数与写时复制，「怎么做」只讲切块与块表按需分配（浪费限于最后一个块）。共享只在长页讲。采纳。

改后预算：长页 450+250+250+300+320+300+300+320+280+280+300 = 3350；短页 300+330+320 = 950。大纲检查通过。
