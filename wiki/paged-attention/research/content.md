# PagedAttention

- 描述：PagedAttention 是一种注意力算法，把每个序列的键、值切成固定 token 数的块存在不连续显存里，按块计算注意力，使 KV cache 能按需分配、跨序列共享，减少显存浪费。
- 摘要：把序列的 KV cache 切成固定大小的块，块可存放在不连续的显存里，注意力按块逐块计算；像操作系统的分页一样按需分配、用块表映射逻辑块到物理块，并允许序列之间共享块，减少显存浪费。
- 主题：推理系统, 内存与缓存
- 标签：推理加速

## 短页

### 切成块

token 是模型处理文本的最小单位；大语言模型一次处理一条序列，也就是一串陆续出现的 token，生成时一次只输出一个 token。每个新 token 都要用到它前面所有位置的键和值（键、值由注意力产出，注意力让序列里各位置互相取信息，见[标准注意力](wiki/standard-attention)），这些留下来的键、值就是 [KV cache](wiki/kv-cache)。PagedAttention 把每个序列的 KV cache 切成固定 token 数的块，每块装固定数量 token 的键和值；块与块之间不必相邻，可以散在显存各处。注意力也不再假定键、值是连续的一整段，而是按块逐块取、逐块算。
依据：paper/src-v1/main.tex L40-L48；paper/src-v1/main.tex L86-L109；paper/src-v1/main.tex L175-L184

### 按最长预留，留下大片空闲

现有系统把每个请求的 KV cache 放在连续的一段显存里，并按这个请求可能的最大长度一次预留好，因为实际要生成多长事先并不知道。预留出来还没用到的位置、请求比上限短而多留出来的部分、分配器切出的再也拼不起来的空隙，这三类浪费让真正存 token 状态的显存只剩很小一部分，实测可以低到 20.4%。而且每个序列各占一段连续的显存，多个序列没法指向同一份键、值，也就没法共享。这些浪费占住了显存，能同时处理的请求数因此受限，吞吐也随之受限。
依据：paper/src-v1/intro.tex L37-L62；paper/src-v1/intro.tex L57；paper/src-v1/main.tex L149-L166

### 切成块，用块表按需取用

每块配一块物理显存，再用一张块表把逻辑块映射到物理块、并记下这块已经填了几个位置。新 token 的键、值先填进最后一个没填满的逻辑块，填满了才分配新的逻辑块和物理块。一个序列没填满的只剩最后一块，显存不必按最大长度预留，按实际用量分配。不同序列之间还能共用块：让多个序列的逻辑块指向同一批物理块，用引用计数记着有几处指向它；要改一块被多个序列共用的块时，先复制出一份再改，这一步叫写时复制。
依据：paper/src-v1/main.tex L198-L213；paper/src-v1/main.tex L207-L237；paper/src-v1/main.tex L251-L255

## 长页

大语言模型一次只生成一个 token——token 是模型读写文本的最小单位，可以是一个词，也可以是词的一部分；一串 token 构成一条序列。每生成一个 token 都要用到它前面所有位置的键和值。一个请求分两步：先把输入的提示整段算一遍，这一步叫预填；再逐个生成后面的 token，这一步叫解码。算提示时得到的每个位置的键、值，后面每一步都要再用，把这些键、值留在显存里复用，就是 [KV cache](wiki/kv-cache)；键和值由注意力产出（注意力让一条序列里各位置互相取信息，见[标准注意力](wiki/standard-attention)）。
依据：paper/src-v1/main.tex L86-L109

每个请求的 KV cache 随生成不断长大，长度事先不知道。PagedAttention 把每个序列的 KV cache 切成固定 token 数的块，块之间不要求连续存放，显存可以按实际用量分配；注意力也相应改成按块来算。它借用了操作系统里虚拟内存和分页的做法：把显存切成固定大小的物理块，用「一个请求的逻辑块映射到物理块」的办法来管理。因为能按块共享，KV cache 还能在同一个请求的多个输出之间、以及不同请求之间共用，进一步压低显存占用。
依据：paper/src-v1/main.tex L40-L48；paper/src-v1/main.tex L198-L226；paper/src-v1/intro.tex L42

### 显存里装得下多少请求

模型推理时，权重在服务全程常驻显存；每个请求另占一份动态的 KV cache，随生成增长或收缩；此外还有少量临时张量，算完即弃。以 13B 参数（B 表示十亿）的模型为例，约 65% 的显存留给权重，接近 30% 给请求的 KV cache 这类动态状态，剩下的很小一部分给临时张量。权重是固定的、临时张量占比很小，所以能同时处理多少个请求，主要看 KV cache 能容纳多少，服务的吞吐因此受显存容量限制。
依据：paper/src-v1/main.tex L134-L137；paper/src-v1/intro.tex L30-L42

而且照目前的趋势，GPU 的算力增长快于显存容量的增长。
依据：paper/src-v1/main.tex L140

### 连续存法浪费在哪里

现有系统把每个请求的 KV cache 存成一段连续内存，并且按这个请求可能的最大长度一次性预留：生成多长事先不知道，只能按上限留。由此带来三类浪费：一是为将来 token 预留的槽位，在整个请求的生命周期里占着位置，别的请求用不上；二是内部碎片，请求实际长度短于最大长度，多留的部分要等请求结束才发现用不上；三是外部碎片，不同请求预留的大小不同，分配器切出来的空隙再也合不上、用不上。实测中，真正存 token 状态的显存最低只有 20.4%。连续存法也使共享无法进行：多个序列的 KV cache 各占一段连续的显存，没法指向同一份键、值。用内存压实整理碎片也不现实，KV cache 太大，整体搬移一遍代价过高。
依据：paper/src-v1/main.tex L149-L166；paper/src-v1/intro.tex L52-L62；paper/src-v1/intro.tex L57

### 把每个序列的 KV cache 切成块

PagedAttention 把每个序列的 KV cache 切成一块块，每块装固定数量 token 的键和值，这个数量叫块大小，记作 $b$。块与块之间不要求存在连续的显存里，可以分散存放。取某一块时，把它的键向量按列排成一个矩阵 $K_j$、值向量按列排成 $V_j$，下标 $j$ 是块的编号，从 1 起数。每一块只覆盖序列的一段位置，整条序列的键、值由若干块拼起来。切块只是重新组织了键、值在显存里的位置，它们本身没有变。
依据：paper/src-v1/main.tex L175-L178

#### 在块上算注意力

标准注意力里，位置 $i$ 的查询和它前面所有位置的键逐个点积，点积先除以 $\sqrt{d}$ 再取 SoftMax（每个分数取指数后除以指数之和）；$d$ 是查询、键向量的维度，除以 $\sqrt{d}$ 的缩放见[标准注意力](wiki/standard-attention)。按块算时把每个块内的键一起处理：

$$A_{ij} = \frac{\exp(q_i^\top K_j / \sqrt{d})}{\sum_{t=1}^{\lceil i/b \rceil}\exp(q_i^\top K_t / \sqrt{d})\,\mathbf{1}}, \qquad o_i = \sum_{j=1}^{\lceil i/b \rceil} V_j A_{ij}^\top$$

$q_i$ 是位置 $i$ 的查询向量，$d$ 是它的维度，$K_j$ 是第 $j$ 块的键矩阵，$V_j$ 是第 $j$ 块的值矩阵，$A_{ij}$ 是位置 $i$ 对第 $j$ 块内各个键归一化后的权重行，$\exp$ 是指数函数，$\mathbf{1}$ 是分量全为 1 的列向量：指数作用在向量上得到的是长度为块大小 $b$ 的行向量，乘上 $\mathbf{1}$ 就把这一块内各个位置的权重相加，$\lceil i/b \rceil$ 是位置 $i$ 之前（含位置 $i$）一共用到几块。分母对位置 $i$ 前面的所有块求和，所以归一化是跨块的；输出 $o_i$ 则把各块的 $V_j$ 乘上对应的权重行再累加。
依据：paper/src-v1/main.tex L178-L182

### KV cache 管理器

服务系统用一个 KV cache 管理器管显存，它的思路来自操作系统的虚拟内存：显存先切成固定大小的物理块，块好比内存页，token 好比字节，一个请求好比一个进程。一个请求的 KV cache 用一串逻辑块表示，随着新 token 生成，逻辑块从左往右填，最后一块没填满的位置留给后续生成。管理器维护一张块表，把每个逻辑块映射到某个物理块，并记下这块已经填了几个位置。逻辑块和物理块分开后，显存按实际用量分配，不必按最大长度一次留足，避免了为将来 token 预留槽位和外部碎片。
依据：paper/src-v1/main.tex L198-L205；paper/src-v1/intro.tex L64-L70

### 一个序列从头生成，块怎么变

一个请求的 KV cache 预填阶段把整段提示算完，得到每个位置的键和值，把它们填进逻辑块；接着每解码一步生成一个新 token，把它的键和值写进最后那个未填满的逻辑块，并把块表的已填位置加一；直到这一块填满，才分配一个新的逻辑块和一个新的物理块。任何时刻没填满的只可能是最后一个块，请求一结束，它的物理块随即回收、交给别的请求。
依据：paper/src-v1/main.tex L207-L237

::: 块大小 4、提示 7 个 token 的一次生成
依据：paper/src-v1/main.tex L207-L237

1. 提示有 7 个 token。预填阶段算完这 7 个位置，得到它们的键和值，填进两个逻辑块：逻辑块 1 放前 4 个，逻辑块 2 放后面的 3 个，逻辑块 2 还空一个位置。
2. 管理器为逻辑块 1 分配物理块 7、为逻辑块 2 分配物理块 1，把这两条映射记进块表；比如逻辑块 2 记着「对应物理块 1、已填 3 个位置」。
3. 第一个解码步生成一个新 token，它的键和值写进逻辑块 2 空着的位置，块表里逻辑块 2 的已填位置由 3 变成 4。
4. 再解码一步时逻辑块 2 已满，这时才分配一个新的逻辑块和一个新的物理块（比如物理块 3），存下新 token 的键和值，并在块表里补一条映射。
依据：paper/src-v1/main.tex L207-L237

### 多个序列共用块

一个请求里的多个输出序列，提示部分完全一样，各自的逻辑块可以指向同一批物理块，共享的物理块用一个引用计数记着被几处指向。要往一块被多处共用的块里写时，不能就地改，先分配一个新物理块、把旧块的内容复制过去，再把引用计数减一，之后的新内容落到新块，这一步按块进行，叫写时复制。服务方预先算好并缓存起来的一段共享前缀，也按同样方式让各请求指向它的物理块，只对用户各自不同的部分另外计算。这套逻辑块到物理块的映射对上层的模型和解码过程是隐藏的：处理时只看到每个序列的一串物理块号，不必知道哪些序列之间共享，所以采用不同解码方式的请求可以混在同一批里处理。
依据：paper/src-v1/main.tex L251-L309

### 显存不够时怎么办

请求量超过系统容量时，先来先服务：先到的先处理，抢占时最晚到的先被换出。换出以序列为单位整体进行，一个序列的块要么全换出去、要么都不换；同一请求里共享着块的多个序列也一起被抢占或恢复。恢复被换出的序列有交换和重算两条路。交换是把它的块复制到 CPU 内存，需要时再换回显存，换出的块数不会超过显存里 KV cache 的块数，所以 CPU 上的交换空间是有上界的。重算是不存换出的块，等这个序列重新调度时再算一遍，把已经生成的 token 连同原提示当成一段新的提示，一次算出所有位置的键和值，重算的耗时可能低于原来逐字生成。两条路选哪条要看块大小：块很小时交换会拆成很多次小传输、用不满带宽，此时重算开销更低；块较大时交换开销更低；具体还取决于 CPU 内存与显存之间的带宽和 GPU 的算力。
依据：paper/src-v1/main.tex L303-L319；paper/src-v1/main.tex L471-L482

### 省下多少显存、快多少

同一提示生成多个输出（并行采样）时，多个输出共用提示的块，省下的显存按被跳过的块数占全部块数的比例算；请求的输入输出长度分布（轨迹）不同，省下的比例也不同。显存省下后，能放进更多请求，吞吐随之上升。
依据：paper/src-v1/main.tex L226；paper/src-v1/eval.tex L140-L141；paper/src-v1/intro.tex L75

### 适用条件与边界

分页给注意力加了一层间接：内核（在 GPU 上执行的一段计算程序）要按块表去取不连续的块，还要处理长度不一的序列，这使注意力内核本身比高度优化的常规实现慢 20% - 26%；不过内核只影响注意力这一步，端到端仍然更快。块大小要折中：太小，读写和计算 KV cache 时用不满 GPU 的并行度；太大，内部碎片变多、能共享的机会变少；短序列多的负载里块越大越不利，实际默认取 16。因为引入了按块读取的访存方式，已有的注意力实现不能直接使用，要自己写读块的内核，常见做法是把块的读写和注意力融进同一个内核，减少内存间接带来的开销。虚拟内存和分页只适合「输出长度事先不定、性能受显存容量限制」这类负载；张量形状固定的训练、或本来就受算力限制的推理，引入这层间接可能反而更慢。它和 [FlashAttention](wiki/flash-attention) 容易混：FlashAttention 分块是为了把中间结果留在片上的高速存储里、少读写慢速显存，PagedAttention 分块是为了让 KV cache 能按需分配、跨序列共享。
