    本章给出三维度框架与 K2→K3 的参数变化。但每个维度的机制还需展开——下一章讲序列维度的 KDA+MLA 混合。

    序列维度——KDA + 混合注意力

    K3 的序列维度设计是 3:1 混合注意力：每个 block 含 3 层 Kimi Delta Attention（KDA） + 1 层 Gated MLA，骨干末尾额外加 1 层 MLA（§2.1）[C3]。93 层中共 69 层 KDA + 24 层 MLA[N2]。

    KDA 用固定大小递归状态替代增长的 KV cache，提供高效的长序列 token 混合——它的核心是 channel-wise forget gate + delta rule（KDA 概念页已讲清完整机制，包括 lower-bounded decay 和 full-rank gate）。MLA 用低秩潜在向量压缩 KV，在周期性层提供不受限的全局 token 间注意力（MLA 概念页已讲清低秩压缩机制）。

    为什么是 3:1 而非全 KDA 或全 MLA？两者职责分离：

    • KDA（69层）：提供位置敏感、近因感知的序列混合。递归状态固定大小，长序列推理时 KV cache 不增长，但全局信息会被衰减压缩。
    • MLA（24层）：提供不受限的全局内容交互。KV cache 随序列增长但被低秩压缩，每 4 层出现一次，让信息能在全局范围被重新审视。

    这种混合让 K3 训练上下文从 K2 的 128K 扩展到 1M（8×，Table 1）。关键在于 MLA 层使用 NoPE（No Position Encoding）——不施加任何显式位置编码（§2.1.2，config.json mla_use_nope=true）。KDA 通过递归门控和衰减机制隐式编码位置，MLA 不需要额外的位置编码。这意味着扩展上下文长度时无需修改位置编码参数（如 RoPE rescaling 或 YaRN），模型直接外推到 1M token（§3.4）。

    末尾的额外 MLA 层（第 93 层）保证最终输出经过全局注意力——论文 §2.1 说"the final layer always performs global attention"。config.json 的 full_attn_layers 列表确认：24 个 MLA 层包括 23 个周期性的（第 4, 8, 12, ..., 92 层）和 1 个末尾的（第 93 层）。

    补充：config.json 层配置完整列表（69 KDA + 24 MLA = 93）

    full_attn_layers（MLA，24个）：4, 8, 12, 16, 20, 24, 28, 32, 36, 40, 44, 48, 52, 56, 60, 64, 68, 72, 76, 80, 84, 88, 92, 93

    每 3 个 KDA 一组，对应一个 block 的前 3 层。层号从 1 开始（layer 0 是 dense 层，first_k_dense_replace=1）。

    教学示例。一个 token 在序列维度的处理——进入 block 后，前 3 层 KDA 把历史信息累加到固定递归状态中（状态不随序列增长），第 4 层 MLA 用全局注意力重新审视所有 token 的内容。这个"3 层局部 + 1 层全局"的节奏在 23 个 block 中重复，最后第 93 层 MLA 做最终全局汇聚。

    • 为什么不全用 KDA。（KDA 的递归状态会衰减压缩全局信息，需要 MLA 周期性提供全局注意力。）
    • 为什么不全用 MLA。（MLA 的 KV cache 随序列增长，1M 上下文不可负担；KDA 固定状态大小。）
    • NoPE 如何让 K3 免去位置编码外推。（KDA 隐式编码位置，MLA 不需要显式位置编码，扩展上下文时无需 RoPE rescaling。）

    本章讲序列维度的 KDA+MLA 混合。但 93 层深网络如何避免信息稀释——下一章讲深度维度的 Block AttnRes。

    深度维度——Block AttnRes

    93 层比 K2 的 61 层多了 52%（Table 1）。标准残差连接把所有先前信息压缩到单个状态 h_l——论文 §2.2 把这比作"RNN 在时间上的瓶颈"。93 层的深度下，早期信息会被逐层稀释。

    Attention Residuals（AttnRes）的思路是把注意力的方法论从序列维度用到深度维度：每层用可学习伪查询 q_l = w_l 对所有前层输出做选择性检索，而非均匀累加（§2.2 Eq.8-9）。Block AttnRes 概念页已讲清完整机制，包括 pseudo-query、softmax kernel 和 online softmax 合并。

    全 AttnRes 的 O(L²d) 算术在 L < 100 时可负担，但 O(Ld) 内存和流水线通信开销大（要保存所有层输出）。Block AttnRes 将 93 层分为 8 个 block（7 个 12 层完整 block + 1 个 9 层部分 block = 93 层，block size = 12，config.json attn_res_block_size=12），块内层输出求和为单个表示，跨 block 做全注意力。开销从 O(Ld) 降到 O(Nd)（N=8），论文 §2.2 引 [57] 称"N ≈ 8 recovers most of the benefit across model scales"。

    补充：93 层如何分为 8 个 block（含部分末尾 block）

    93 / 12 = 7.75，即 7 个完整 12 层 block（层 1-12, 13-24, ..., 73-84）+ 1 个 9 层部分 block（层 85-93）。论文 §2.2 说"giving a partial final block and 9 total blocks when counting the embedding layer"——embedding 层 b_0 始终作为 AttnRes 的源，加上 8 个内容 block，共 9 个。

    注意：block 划分是针对 AttnRes 的跨层检索结构，与 KDA/MLA 的 4 层混合 block 不同。AttnRes block 每 12 层一个检索边界，KDA/MLA 每 4 层一个注意力类型切换。

    代价与边界：Block AttnRes 只在跨 block 时做选择性检索，块内层仍走标准残差——信息在 12 层的块内仍有稀释，只是每 12 层有一次跨 block 的"信息重置"。论文 §2.2 引 [57] 给出 N≈8 在多模型规模下够用的经验结论[C4]，但未提供 K3 规模下不同 block size 的消融实验。

    教学示例。一个 token 在深度维度的处理——在 block 内的 12 层中，信息通过标准残差逐层传递；当进入新 block 的第一层时，该层可以"回头看"前 7 个 block 的汇总表示和 embedding，选择性检索需要的信息。这让 93 层深网络不会因为层数多而丢失早期信息。

    完成本节后，用下面几个问题检查自己是否跟上：

    • 标准残差连接在深网络中的瓶颈是什么。（所有信息压缩到单个状态，类似 RNN，早期信息被稀释。）
    • Block AttnRes 把开销从 O(Ld) 降到 O(Nd)，N 是什么。（block 数 = 8。）
    • 块内层还能做跨层检索吗。（不能，块内走标准残差；只有跨 block 时才做全注意力。）

    本章讲深度维度的 Block AttnRes。但 896 专家的极端稀疏如何保持训练稳定——下一章讲宽度维度的 Stable LatentMoE。

    宽度维度——Stable LatentMoE

    K3 的宽度维度设计是 Stable LatentMoE：896 个路由专家 top-16 激活 + 2 个共享专家，稀疏度 56×（896/16，即每 56 个路由专家中激活 1 个，§2.3，config.json num_experts=896, num_experts_per_token=16, num_shared_experts=2）[C5]。相比 K2 的 384 专家 top-8，专家池扩大 2.33×，激活专家扩大 2×。

    LatentMoE 分离全宽共享专家（始终激活，处理通用变换）与紧凑潜在空间（宽度 ℓ=3584）路由专家，使扩展专家池可负担——路由专家在潜在空间操作而非全宽 d=7168，通信和权重量不随路由数线性增长。

    但 56× 稀疏度放大两个失效模式（§2.3）：

    1. 激活爆炸：路由路径 W↓ → gated FFN → W↑ 近四连矩阵乘，在 2.8T 规模产生内部激活爆炸。
    2. 负载失衡：平衡近 10³ 专家的负载超出 auxiliary-loss-free bias 更新的适用范围（§2.3.3 说"Maintaining balanced loads becomes more challenging as LatentMoE increases the routed expert pool to 896"）。

    Stable LatentMoE 用三件稳定化分别解决这两个问题：

    稳定化 1 — RMSNorm（解决激活爆炸）：在路由专家聚合后、上投影 W↑ 前插入 RMSNorm（§2.3.1 Eq.11，config.json latent_moe_use_norm=true）。这降低路由分支对尺度变化的敏感度，在与全宽共享分支合并前先归一化。Stable LatentMoE 概念页已讲清此机制。

    稳定化 2 — SiTU-GLU（解决激活爆炸）：用 Sigmoid Tanh Unit GLU 替换 SwiGLU。SwiGLU 的两个乘法因子都无界，大坐标重合时产生激活异常值。SiTU-GLU 用 softcap(x, β) = β tanh(x/β) 约束两个因子，输出界 |f| ≤ β₁β₂ = 100（β₁=4, β₂=25，§2.3.2 Eq.12，config.json activation_situ_beta=4.0, activation_situ_linear_beta=25.0），同时保留原点附近 Swish 的线性响应。SiTU-GLU 概念页已讲清局部展开和输出界推导。

    稳定化 3 — Quantile Balancing（解决负载失衡）：从 router score 分位数直接设定每个专家 bias，使每专家恰好获得目标负载 q = mk/n（§2.3.3 Eq.14）。相比 DeepSeek-V3 的固定步长 sign 更新（需要学习率 γ 且在 896 专家下收敛慢），QB 跳到对偶问题的精确坐标最小值，无需学习率超参，几步内均衡。Quantile Balancing 概念页已讲清对偶推导和直方图估计。

    三件稳定化的分工：RMSNorm 和 SiTU-GLU 解决激活爆炸（稳定化 1+2），QB 解决负载失衡（稳定化 3）[C6]。论文 §2.3 只描述组合效果，未提供 896 专家规模下移除单个稳定化的消融实验。三件稳定化作用于不同失效路径：RMSNorm 降低尺度敏感性、SiTU-GLU 约束激活上界、QB 保证负载均衡。

    教学示例。一个 token 在宽度维度的处理——经过注意力层后，token 被投影到 3584 维潜在空间，router（sigmoid 激活）选出 16 个路由专家；16 个专家在潜在空间各自变换后加权聚合，经 RMSNorm 归一化，再由 W↑ 升回 7168 维，最后与 2 个共享专家的全宽输出相加。

    完成本节后，用下面几个问题检查自己是否跟上：

    • 896 专家 top-16 的稀疏度是多少。（56× = 896/16。）
    • 三件稳定化各解决哪个失效模式。（RMSNorm+SiTU-GLU → 激活爆炸；QB → 负载失衡。）
    • 为什么 LatentMoE 能负担 896 专家。（路由专家在 3584 维潜在空间操作，不占全宽 7168 维；共享专家保持全宽路径。）

    本章讲宽度维度的 Stable LatentMoE。但 K3 是原生多模态模型，视觉如何接入——下一章讲原生视觉 MoonViT-V2。

    原生视觉——MoonViT-V2

    K3 是原生多模态模型：文本、图像、视频由单一共享骨干处理，没有事后模态对齐阶段（§2.4）。视觉编码器 MoonViT-V2 是一个 27 层、约 0.4B 参数的 ViT（config.json vt_num_hidden_layers=27），采用 RMSNorm 并移除所有 bias[C13]。

    K3 视觉设计的关键 departure 是从零训练视觉编码器，而非像 K2.5 那样从 SigLIP 对比预训练模型初始化（§2.4）。动机是训练稳定性：当预训练编码器附加到 LLM 时，联合优化变得不稳定——SigLIP 初始化的 MoonViT-3D 梯度范数持续偏高且频繁尖峰，而从零训练的 MoonViT-V2 全程稳定（Fig.6）。

    另一个好处是表示塑造：用 next-token prediction 训练让编码器表示直接由语言建模目标塑造，而非由偏好全局语义的对比损失塑造。论文 §2.4 的发现是"contrastive pre-training is unnecessary as an initialization for multimodal language models at scale"——MoonViT-V2 在视觉评估上匹配 SigLIP 初始化基线。MoonViT-V2 概念页已讲清架构细节（时空因子化、pixel-shuffle 下采样、temporal pooling）。

    完成本节后，用下面几个问题检查自己是否跟上：

    • 为什么从零训练比 SigLIP 初始化更稳定。（预训练编码器附加到 LLM 后联合优化不稳定，梯度尖峰频繁。）
    • 对比预训练对大规模多模态语言模型不是必要的初始化这个发现的意义是什么。（挑战了 SigLIP 初始化是必要前提的主流做法。）

    本章讲原生视觉 MoonViT-V2。但架构之外，训练方法如何支撑 2.5× 效率——下一章讲训练数据、scaling law、Muon 与长上下文扩展。

    训练——数据、scaling law、Muon、长上下文扩展

    约 2.5× scaling efficiency 是架构、数据、训练配方共同作用的结果。本节回答这些训练方法如何共同支撑这一效率。

    数据与 scaling law

    预训练数据覆盖四类文本域——Web Text、Code、Mathematics、Knowledge——加上大规模视觉语料（captions、图文交错、OCR、感知（perception）、视频、视觉编程数据，§3.1）。每个域用规则启发式、分类器质量评分和去重过滤，域特定采样率由小模型消融确定。知识数学语料用风格和视角多样 prompting 重述（rephrasing recipe，继承 K2）。

    Scaling law 研究（§3.2）独立搜索了 cosine decay 和 WSD（Warmup Stable Decay）各自的最优超参——论文发现两者最优 peak learning rate 和 batch size 差异很大，用共享超参比较不公平。在各自最优设置下，cosine decay 始终达到更低 final loss（§3.2）[C8]。据此 K3 采用 cosine + 1% linear warmup + weight decay 0.1（§3.3）。Fig.7 的 scaling-law 曲线显示 K3 达到 K2 相同 validation loss 所需 FLOPs 减半多，即约 2.5× 效率[N5]。

    Per-Head Muon

    K3 继承 K2 的 Muon 优化器用于矩阵参数，并改进为 per-head 变体（§2.5）：对 Q/K/V 投影矩阵，按头维度切分动量矩阵，每个头的块分别做 Newton-Schulz 正交化，而非对整个投影矩阵做全矩阵正交化。直觉是：全矩阵正交化把所有头当作一个耦合块，大梯度/动量尺度的头主导共享更新方向，小尺度头更新不足；per-head 正交化均衡跨头更新尺度。Per-Head Muon 概念页已讲清完整机制。

    长上下文扩展

    K3 支持最多 1M token 上下文（§3.4）。由于使用 NoPE，模型直接外推到 1M 无需位置编码修改[C9]。训练采用四阶段渐进课程，窗口依次为 8K → 64K → 256K → 1M：

    • 预训练阶段：8K → 64K
    • cooldown 阶段：256K → 1M

    将昂贵的长序列计算集中在总训练预算的小部分，保持课程经济性的同时让模型逐步适应更长的依赖。长上下文数据经过专门清洗（exact/fuzzy 去重、视频帧感知哈希、质量过滤、结构验证），并通过排列和拼接多模态文档合成需要关注完整 1M 上下文才能解决的任务（§3.4）。

    论文用 collectively 描述 2.5× 的来源，未分解架构、数据、训练各贡献多少[N5]。Table 1 量化了架构变化（61→93 层，MLA→混合，SwiGLU→SiTU-GLU，384→896 专家），数据只定性描述为 refined 未给量化指标。论文未提供移除单个改进的消融，因此各因素的相对贡献未能从论文核实。

    后训练——SFT→RL→MOPD 三阶段、QAT、EAGLE

    K3 的后训练遵循三阶段范式（§4.1）：SFT 建立冷启动能力 → RL 发展多域多努力级别专家 → MOPD 蒸馏整合为统一模型[C10]。

    SFT（§4.1.1）扩展了 K2/K2.5 的 SFT 数据集，大幅增加复杂 agentic 轨迹覆盖。用前代 Kimi 模型合成数据轨迹，经多阶段验证和人工标注。所有数据用 XTML chat template（附录 F）序列化。

    RL（§4.1.2）跨三域 × 三努力级别：三域 = (i) 通用任务、(ii) 通用智能体、(iii) 编程智能体；三努力 = {low, high, max}。交叉得到 9 个专家模型。RL 用 partial rollout（部分轨迹完成即优化）减少长尾延迟，配合可恢复沙箱基础设施（§5.3.2）。reasoning effort 通过 per-problem budget control 实现：超预算轨迹得 -1 奖励。

    MOPD（§4.1.3，Multi-Teacher On-Policy Distillation）将九个域×努力专家整合为统一模型。对给定域 d 和努力 e，由对应教师 π_teacher 指导学生 π_θ，per-token OPD reward 用 stop-gradient + clip 约束（Eq.15）。MOPD 的核心是在策略蒸馏，学生模型在自己生成的轨迹上学习，教师提供 dense reward 信号，整合多个专家能力到一个模型。完整机制见 MOPD 概念页。

    QAT（§4.1.4）从 SFT 阶段开始贯穿整个后训练，MXFP4 权重 + MXFP8 激活，只量化 MoE 专家权重（注意力、共享专家、latent MoE 投影（W↓/W↑）、MoE router、lm_head、视觉塔、多模态投影器保持高精度，config.json quantization_config.ignore 确认）[C11]。RL 时 rollout 和训练共享同一量化方案，消除训练-推理失配。MXFP4 QAT 概念页已讲清量化机制。

    EAGLE-3 draft model（§4.1.4）：K3 预训练时有一个 MTP（Multi-Token Prediction）层，结构匹配 backbone block。EAGLE-3 的 draft model 是单层 decoder，结构匹配 MTP 层，因此 K3 把预训练 MTP 层微调为 EAGLE-3 风格 draft model（target model 冻结，只更新 draft 层和 feature-fusion 投影）。draft 输入融合低/中/高层特征（第 1、4、最终 AttnRes block 的输出），训练时展开 7 步。直接优化 LK loss（Eq.16，接受率的负对数）而非 KL 代理。EAGLE-3 是投机解码方法，小模型先草拟 token，大模型批量验证，加速推理；K3 用 MTP 层改造而非从零训练 draft model。完整机制见 EAGLE-3 概念页。

    基础设施——3T 训练 + 1M RL + 推理

    K3 面临三个罕见地同时出现的系统挑战：混合 KDA 注意力、3T 级稀疏多模态训练、百万 token 智能体工作负载（§5）。本节简述各类基础设施创新，完整工程细节是独立工作。

    KDA 系统协同

    FlashKDA（§5.1.1）是 CUTLASS 的 chunkwise 融合内核，重叠 chunk 内计算与跨 chunk 状态传播，优于 Triton 参考实现。KCP（KDA Context Parallelism）（§5.1.2）解决跨设备上下文并行：KDA 的 delta rule 应用 token 相关矩阵 M_t 到传入状态，简单求和不够（与 vanilla linear attention 不同）；KCP 把每段效果分解为"对传入状态的累积转移"和"从零生成的局部状态"，两个量本地可算，通过固定大小 all-gather 交换，prefix scan 恢复各 rank 传入状态。完整机制见 FlashKDA 与 KCP 概念页。

    MoonEP：完美均衡专家并行

    MoonEP（§5.2.1）实现完美负载均衡的专家并行：每 rank 恰好收到 S×K token，计算形状静态已知。关键证明：E/R 个 redundant expert 总是够用（附录 E 定理 1），且这个上界基本紧。零拷贝通信（planning kernel 预计算目的地，token 直接发送到远程 rank 的专家分组位置）。静态形状消除每层 MoE host 同步。完整机制见 MoonEP 概念页。

    1M 智能体 RL 系统

    RL 系统采用 co-located 训练（每实验几百 GPU）+ partial rollout（§5.3.1）。关键创新：外部 KV cache 池（把可复用前缀写回 CPU DRAM，KDA 状态与 MLA KV cache 一起 offload/prefetch）和 AgentENV microVM 沙箱（§5.3.2，基于 Firecracker，支持增量 checkpoint/resume，checkpoint 延迟低至 133ms，pause/resume/fork/snapshot 操作，6.5× 内存超分）。训练期间共创建 51,219,741 个沙箱（跨 1,505,678 个镜像）。

    推理服务

    推理服务（§5.4）解决混合 KDA-MLA 的双缓存管理：KDA 递归状态（固定大小）与 MLA KV cache（随序列增长）共享分页池，prefix cache 在 512-token 粒度匹配（§5.4.1 Fig.12）。高性能内核优化 KDA 解码（replay 机制处理投机解码回滚）、Block AttnRes（SP+side stream）、Stable LatentMoE（WarpDecode token-centric）。Fleet 级调度用 cache-aware affinity scheduling 和 budget-based admission control。更多 GPU 执行背景见 GPU 执行模型。

    完成本节后，用下面几个问题检查自己是否跟上：

    • 三类基础设施各解决什么挑战。（KDA 系统→线性注意力并行；MoonEP→专家负载均衡；RL 系统→长轨迹状态管理。）
    • KCP 与普通 linear attention 上下文并行有何不同。（KDA 的 delta rule 需要分解为累积转移+局部状态，不能简单求和。）

    独立评价——系统性设计、开源里程碑与边界

    本章是本文对 K3 的独立评价，内容属于解读者判断而非论文结论。

    优点

    三维度信息流的系统性设计是 K3 最突出的贡献。KDA（序列）、AttnRes（深度）、Stable LatentMoE（宽度）不是三个独立改进拼凑，而是互相支撑的系统：KDA 让长序列可负担，才敢把层数推到 93（需要 AttnRes 防稀释）；AttnRes 让深网络可行，才敢把专家扩到 896（需要 Stable LatentMoE 防爆炸）。这种系统性在开源模型中罕见，通常只在闭源大厂的全栈工作中看到。

    开源 3T 级的里程碑。K3 是首个开放权重的 3T 级模型（§8），在开源生态多停留在 1T 级时把规模推到新前沿。WebDev Arena #1/99 是首个开源模型登顶，具有象征意义。

    训练-部署协同。QAT 从 SFT 贯穿 RL，EAGLE draft model 复用 MTP 层——部署效率不是事后优化，而是从训练阶段就考虑的设计。这反映了对"训练效率 ≠ 部署效率"的清醒认识。

    基础设施工程深度。FlashKDA/KCP、MoonEP、AgentENV 的设计都基于严格的理论分析（MoonEP 的 E/R 上界证明、KCP 的 delta rule 分解），不是经验性调优。

    局限

    研究级推理仍落后。CritPt 23.4 落后三个闭源模型，HLE-Full 43.5/56.0 落后 Fable 5 的 53.3/63.0。论文 §6.1.4 自己承认"research-level reasoning remains a key direction for improvement"。这表明 K3 的优势在工程化和 agentic 能力，而非最硬的推理。

    benchmark harness 差异使绝对分数需谨慎。Terminal-Bench 官方 88.3 vs AA 报更低分数、Fable 5 含 fallback、GPT-5.6 Sol 含 cyberguard——直接比分数可能误导。论文 §6.1.3 明确 Terminal-Bench 报 best across harnesses[N6]，因此 K3 的编程分数包含 harness 选择的影响，纯模型能力差距与 Table 2 显示的可能不同。

    2.5× scaling efficiency 未分解单因素。论文只给 collectively 的 2.5×，未分解架构/数据/训练各贡献多少[N5]。这使得其他团队难以判断哪些改进值得复用。

    视觉"从零训练匹配 SigLIP"的结论依赖特定规模。论文 §2.4 的结论基于 K3 的 2.8T 规模，未在更小规模下验证，SigLIP 初始化的优势是否在更小规模下保持，未能从论文核实[C13]。

    适用场景与位置

    什么情况下值得用 K3：长上下文 agentic 任务（1M 上下文 + partial rollout）、成本敏感部署（BrowseComp $2.03/任务）、开源研究（完整权重可复现）、需要原生视觉的任务（非事后对齐）。

    什么情况下不适合：需要最强研究级推理（CritPt/HLE 场景应选 Fable 5 或 GPT-5.6 Sol）、需要闭源模型的 cyberguard/fallback 安全层。

    与相邻工作的位置：K3 是 K2 的直接升级（Table 1 量化了每个维度变化）。在架构路线上，KDA+MLA 混合注意力是与纯注意力（GPT/Claude）不同的路线——用线性注意力承担大部分序列混合，softmax 注意力只周期性出现。Stable LatentMoE 的 LatentMoE 路线（潜在空间路由）与传统全宽 MoE 路线也不同。这些选择是否成为主流有待后续工作验证。

    回到学习目标：K3 用 KDA+MLA 3:1 混合同时获得长序列效率与全局注意力（序列维度）[C3]，Block AttnRes 让 93 层深网络跨 block 选择性检索前层表示（深度维度）[C4]，Stable LatentMoE 用 RMSNorm+SiTU-GLU+QB 三件稳定化在 896 专家、56× 稀疏度下保持训练稳定（宽度维度）[C5, C6]。三维度互相支撑，配合训练与基础设施创新，共同支撑约 2.5× scaling 效率[C7]。K3 落后 Claude Fable 5 和 GPT-5.6 Sol，但持续优于 Opus 4.8、GPT-5.5 和开源 GLM-5.2[C12]，是首个开放权重的 3T 级模型。
