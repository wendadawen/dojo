    Kimi K3：三维度扩展信息流的开源 3T 级（2.78T 参数）模型

    论文：Kimi K3: Open Frontier Intelligence

    作者：Kimi Team（Moonshot AI）

    发表：arXiv 预印本，arXiv:2607.24653v2，2026-08-07

    链接：arxiv.org/abs/2607.24653

    代码：huggingface.co/moonshotai/Kimi-K3 · github.com/MoonshotAI/Kimi-K3

    2.8 万亿参数、104B 激活、1M token 上下文——Kimi K3 把开源模型的规模推到新前沿[C1]。但 K3 的核心问题不是把模型做大，而是如何在万亿参数下让信息高效流动。论文把这个问题分解为三个互补维度：序列长度（token 间混合）、网络深度（层间信息传递）、模型宽度（通道间混合）[C2]。K3 的架构设计围绕这三个维度展开——KDA+MLA 混合注意力管序列，Block AttnRes 管深度，Stable LatentMoE 管宽度——并由训练与基础设施支撑约 2.5× scaling 效率[C7]。

    核心问题

    1. K3 为什么用 KDA+MLA 3:1 混合注意力，它如何同时获得长序列效率和全局注意力。

      解答：KDA 管效率、MLA 管全局，3:1 分工让 1M 上下文可负担

      KDA 用固定大小的递归状态做序列混合，长序列推理时缓存不增长，但全局信息会被衰减压缩；MLA 用低秩压缩的 KV 提供不受限的全局注意力，但缓存随序列增长。每 4 层中 3 层 KDA 加 1 层 MLA，让大部分序列混合由线性注意力承担、全局交互周期性重置，训练上下文因此从 128K 扩展到 1M。完整论证见「2. 序列维度——KDA + 混合注意力」。

    2. Block AttnRes 如何让 93 层深网络避免信息稀释，代价与边界是什么。

      解答：每层对块级表征做选择性检索，代价是候选粒度降为块级

      标准残差把所有前层信息压进单个状态，93 层深度下早期信息逐层稀释。Block AttnRes 把 93 层分为 8 个 block：每层用可学习伪查询对「embedding ＋此前各 block 的汇总表示 ＋当前 block 的 partial sum」做选择性检索（当前 block 的 partial sum 从块内第 2 层起计入候选），跨层检索开销随 block 数而非层数增长。相对全 AttnRes，代价是把候选粒度从单层输出降为块级表征、块内单层输出不再可被单独检索，且论文未提供 K3 规模下不同 block size 的消融。完整论证见「3. 深度维度——Block AttnRes」。

    3. Stable LatentMoE 如何在 896 专家、56× 稀疏度下保持训练稳定，三件稳定化各解决什么。

      解答：RMSNorm 与 SiTU-GLU 治激活爆炸，Quantile Balancing 治负载失衡

      56× 稀疏度放大两个失效模式：激活爆炸与负载失衡。RMSNorm 在路由专家聚合后、升投影前归一化，SiTU-GLU 用有界激活约束 GLU 的两个乘法因子，两者共同解决激活爆炸；Quantile Balancing 从 router score 分位数直接设定每个专家的 bias，解决负载失衡。完整论证见「4. 宽度维度——Stable LatentMoE」。

    4. K3 的训练方法如何共同支撑约 2.5× scaling 效率。

      解答：架构、数据与训练配方的联合效果，未分解单因素

      2.5× 指在 OOD（分布外）验证 loss 上达到 K2 相同水平所需 FLOPs 减半多；OOD loss 用训练分布外的留出数据评估，衡量泛化而非记忆。论文用 collectively 一词，将其归因于 KDA+AttnRes+LatentMoE 架构、四域数据配方、cosine decay、Per-Head Muon、NoPE 外推与四阶段上下文扩展的共同作用，未提供移除单个改进的消融。见「6. 训练——数据、scaling law、Muon、长上下文扩展」。

    5. K3 的性能定位与边界，相对 Claude Fable 5、GPT-5.6 Sol 和前代 K2 的位置。

      解答：落后最强闭源、总体优于第二梯队，短板在研究级推理

      K3 落后 Claude Fable 5 和 GPT-5.6 Sol，总体优于 Opus 4.8、GPT-5.5 与开源 GLM-5.2，研究级推理（CritPt、HLE-Full）是例外；相对 K2 是全维度升级（总参数 2.78T、激活 104.2B、上下文 1M）。短板在研究级推理（CritPt、HLE-Full），优势在 agentic 与编程落地。完整数据见「9. 性能与评价」，独立判断见「10. 独立评价——系统性设计、开源里程碑与边界」。

    1. 三维度信息流——K3 架构总览

    K3 的架构围绕一个核心问题设计：如何让信息在万亿参数模型中高效流动。论文 §2 把这个问题分解为三个互补维度——序列长度（token 间混合）、网络深度（层间信息传递）、模型宽度（通道间混合）。这不是简单地把模型做大，而是系统性地重新设计每个维度的信息流机制。

    本章问题

    1. 用 Table 1 的数据说明 K3 的总参数和激活参数分别是 K2 的几倍。

      解答：总参约 2.67×，激活约 3.20×

      总参数 2.78T 对 1.04T 约 2.67×，激活参数 104.2B 对 32.6B 约 3.20×。激活增长快于总参，说明每 token 动用的计算占比更高。

    2. 三个维度分别指什么，各对应哪个机制。

      解答：序列对应 KDA+MLA，深度对应 AttnRes，宽度对应 Stable LatentMoE

      序列维度（token 间混合）由 KDA+MLA 混合注意力承担；深度维度（层间信息传递）由 Block AttnRes 承担；宽度维度（通道间混合）由 Stable LatentMoE 承担。

    3. 2.5× scaling efficiency 衡量的是什么。

      解答：OOD 验证 loss 上的训练效率

      指在 OOD 验证 loss 上达到 K2 相同水平所需 FLOPs 减半多，是训练效率指标而非 benchmark 性能倍数；论文将其归因于架构、数据与训练配方的联合效果。

    三维度框架与 K2→K3 的参数变化如上；序列维度的机制决定了 1M 上下文能否负担，也是最先展开的维度。

    2. 序列维度——KDA + 混合注意力

    K3 的序列维度设计是 3:1 混合注意力：每个 block 含 3 层 Kimi Delta Attention（KDA） + 1 层 Gated MLA，骨干末尾额外加 1 层 MLA（§2.1）[C3]。93 层中共 69 层 KDA + 24 层 MLA[N2]。

    KDA 用固定大小递归状态替代增长的 KV cache，提供高效的长序列 token 混合——它的核心是 channel-wise forget gate + delta rule（KDA 概念页已讲清完整机制，包括 lower-bounded decay 和 full-rank gate）[F1, F2]。MLA 用低秩潜在向量压缩 KV，在周期性层提供不受限的全局 token 间注意力（MLA 概念页已讲清低秩压缩机制）。

    为什么是 3:1 而非全 KDA 或全 MLA？两者职责分离：

    • KDA（69层）：提供位置敏感、近因感知的序列混合。递归状态固定大小，长序列推理时 KV cache 不增长，但全局信息会被衰减压缩。
    • MLA（24层）：提供不受限的全局内容交互。KV cache 随序列增长但被低秩压缩，每 4 层出现一次，让信息能在全局范围被重新审视。

    这种混合让 K3 训练上下文从 K2 的 128K 扩展到 1M（8×，Table 1）。关键在于 MLA 层使用 NoPE（No Position Encoding）——不施加任何显式位置编码（§2.1.2，config.json mla_use_nope=true）。KDA 通过递归门控和衰减机制隐式编码位置，MLA 不需要额外的位置编码。这意味着扩展上下文长度时无需修改位置编码参数（如 RoPE rescaling 或 YaRN），模型直接外推到 1M token（§3.4）。

    末尾的额外 MLA 层（第 93 层）保证最终输出经过全局注意力——论文 §2.1 说"the final layer always performs global attention"。config.json 的 full_attn_layers 列表确认：24 个 MLA 层包括 23 个周期性的（第 4, 8, 12, ..., 92 层）和 1 个末尾的（第 93 层）。

    补充：config.json 层配置完整列表（69 KDA + 24 MLA = 93）

    full_attn_layers（MLA，24个）：4, 8, 12, 16, 20, 24, 28, 32, 36, 40, 44, 48, 52, 56, 60, 64, 68, 72, 76, 80, 84, 88, 92, 93

    其中 4, 8, ..., 92 是 23 个周期性 MLA 层（每 block 第 4 层），93 是末尾额外 MLA 层。

    kda_layers（KDA，69个）：1, 2, 3, 5, 6, 7, 9, 10, 11, 13, 14, 15, 17, 18, 19, 21, 22, 23, 25, 26, 27, 29, 30, 31, 33, 34, 35, 37, 38, 39, 41, 42, 43, 45, 46, 47, 49, 50, 51, 53, 54, 55, 57, 58, 59, 61, 62, 63, 65, 66, 67, 69, 70, 71, 73, 74, 75, 77, 78, 79, 81, 82, 83, 85, 86, 87, 89, 90, 91

    每 3 个 KDA 一组，对应一个 block 的前 3 层。层号从 1 开始（0-indexed 的 layer 0，即 1-indexed 位置 1，FFN 为 dense 而非 MoE，注意力仍为 KDA；first_k_dense_replace=1）。

    一个 token 在序列维度的处理——进入 block 后，前 3 层 KDA 把历史信息累加到固定递归状态中（状态不随序列增长），第 4 层 MLA 用全局注意力重新审视所有 token 的内容。这个"3 层局部 + 1 层全局"的节奏在 23 个 block 中重复，最后第 93 层 MLA 做最终全局汇聚。

    本章问题

    1. 为什么不全用 KDA。

      解答：递归状态会衰减压缩全局信息

      KDA 的递归状态固定大小，长序列推理开销不增长，但全局信息会被衰减机制压缩。需要 MLA 每 4 层提供一次不受限的全局注意力，让信息在全局范围被重新审视。

    2. 为什么不全用 MLA。

      解答：KV cache 随序列增长，1M 上下文不可负担

      MLA 的 KV cache 虽经低秩压缩仍随序列长度增长，1M token 下不可负担。KDA 递归状态固定大小，承担大部分序列混合（69 层对 24 层），长上下文才可负担。

    3. NoPE 如何让 K3 免去位置编码外推。

      解答：KDA 隐式编码位置，MLA 无显式位置编码

      KDA 通过递归门控和衰减机制隐式编码位置，MLA 层不施加任何显式位置编码。因此扩展上下文长度时无需修改位置编码参数（如 RoPE rescaling 或 YaRN），模型直接外推到 1M token。

    序列混合解决了 token 间的信息流动，93 层深网络的信息稀释则由 Block AttnRes 处理。

    3. 深度维度——Block AttnRes

    93 层比 K2 的 61 层多了 52%（Table 1）。标准残差连接把所有先前信息压缩到单个状态 h_l——论文 §2.2 把这比作"RNN 在时间上的瓶颈"。93 层的深度下，早期信息会被逐层稀释。

    Attention Residuals（AttnRes）的思路是把注意力的方法论从序列维度用到深度维度：每层用可学习伪查询 $q_l = w_l$ 对所有前层输出做选择性检索，而非均匀累加（§2.2 Eq.8-10）[F3]。Block AttnRes 概念页已讲清完整机制，包括 pseudo-query、softmax kernel 和 online softmax 合并。

    全 AttnRes 的 $O(L^2d)$ 算术在 $L < 100$ 时可负担，但 $O(Ld)$ 内存和流水线通信开销大（要保存所有层输出）。Block AttnRes 将 93 层分为 8 个 block（7 个 12 层完整 block + 1 个 9 层部分 block = 93 层，block size = 12，config.json attn_res_block_size=12），块内层输出求和为单个表示，跨 block 做全注意力。开销从 $O(Ld)$ 降到 $O(Nd)$（N=8），论文 §2.2 引 [60] 称"$N \approx 8$ recovers most of the benefit across model scales"。

    补充：93 层如何分为 8 个 block（含部分末尾 block）

    93 / 12 = 7.75，即 7 个完整 12 层 block（层 1-12, 13-24, ..., 73-84）+ 1 个 9 层部分 block（层 85-93）。论文 §2.2 说"giving a partial final block and 9 total blocks when counting the embedding layer"——embedding 层 b_0 始终作为 AttnRes 的源，加上 8 个内容 block，共 9 个。

    block 划分针对 AttnRes 的跨层检索结构，与 KDA/MLA 的 4 层混合 block 不同。AttnRes block 每 12 层一个检索边界，KDA/MLA 每 4 层一个注意力类型切换。

    代价与边界：块内 12 层中每一层的输入都是对「embedding ＋此前各 block 汇总表示 ＋当前 block partial sum」的 softmax 加权检索（当前 block partial sum 从块内第 2 层起计入候选）——即每层都能跨 block 检索前序表示。相对全 AttnRes，Block AttnRes 的代价是把候选粒度从单层输出降为块级表征、块内单层输出不再可被单独检索。论文 §2.2 引 [60] 给出 $N \approx 8$ 在多模型规模下够用的经验结论[C4]，但未提供 K3 规模下不同 block size 的消融实验。

    一个 token 在深度维度的处理——block 内的 12 层中，每一层都"回头看"embedding 与此前各 block 的汇总表示，按内容选择性检索需要的信息；从块内第 2 层起，当前 block 已累加的 partial sum 也加入候选。这让 93 层深网络不会因为层数多而丢失早期信息。

    本章问题

    1. 标准残差连接在深网络中的瓶颈是什么。

      解答：所有信息压缩到单个状态，类似 RNN

      标准残差把所有先前层的输出压缩进单个残差状态逐层传递，论文称之为"RNN 在时间上的瓶颈"。93 层深度下，早期信息被逐层稀释。

    2. Block AttnRes 把开销从 $O(Ld)$ 降到 $O(Nd)$，N 是什么。

      解答：N 是 block 数，K3 取 8

      N 是 AttnRes 的 block 数：7 个 12 层完整 block 加 1 个 9 层部分 block 共 8 个。块内层输出求和为单个表示，跨 block 才做全注意力，因此跨层检索的内存与通信随 block 数而非层数增长。

    3. 块内层还能做跨层检索吗。

      解答：能，每层的候选含全部前序 block 汇总表示

      能。块内 12 层中每一层的输入都是对「embedding ＋此前各 block 汇总表示 ＋当前 block partial sum」的 softmax 加权检索，当前 block partial sum 从块内第 2 层起计入候选。相对全 AttnRes，Block AttnRes 的差别只是候选粒度降为块级表征、块内单层输出不再可被单独检索，而非块内层无法检索前序块。

    深度维度控制层间信息传递，宽度维度的 896 专家稀疏则依赖 Stable LatentMoE 的稳定化机制。

    4. 宽度维度——Stable LatentMoE

    K3 的宽度维度设计是 Stable LatentMoE：896 个路由专家 top-16 激活 + 2 个共享专家，稀疏度 56×（896/16，即每 56 个路由专家中激活 1 个，§2.3，config.json num_experts=896, num_experts_per_token=16, num_shared_experts=2）[C5]。相比 K2 的 384 专家 top-8，专家池扩大 2.33×，激活专家扩大 2×。

    LatentMoE 分离全宽共享专家（始终激活，处理通用变换）与紧凑潜在空间（宽度 $\ell=3584$）路由专家，使扩展专家池可负担——路由专家在潜在空间操作而非全宽 d=7168，通信和权重量不随路由数线性增长。

    但 56× 稀疏度放大两个失效模式（§2.3）：

    1. 激活爆炸：路由路径 W↓ → gated FFN → W↑ 近四连矩阵乘，在 2.8T 规模产生内部激活爆炸。
    2. 负载失衡：平衡近 $10^3$ 专家的负载超出 auxiliary-loss-free bias 更新的适用范围（§2.3.3 说"Maintaining balanced loads becomes more challenging as LatentMoE increases the routed expert pool to 896"）。

    Stable LatentMoE 用三件稳定化分别解决这两个问题：

    稳定化 1 — RMSNorm（解决激活爆炸）：在路由专家聚合后、上投影 W↑ 前插入 RMSNorm（§2.3.1 Eq.11，config.json latent_moe_use_norm=true）[F4]。这降低路由分支对尺度变化的敏感度，在与全宽共享分支合并前先归一化。Stable LatentMoE 概念页已讲清此机制。

    稳定化 2 — SiTU-GLU（解决激活爆炸）：用 Sigmoid Tanh Unit GLU 替换 SwiGLU。SwiGLU 的两个乘法因子都无界，大坐标重合时产生激活异常值。SiTU-GLU 用 $\text{softcap}(x, \beta) = \beta \tanh(x/\beta)$ 约束两个因子，输出界 $|f| \le \beta_1\beta_2 = 100$（$\beta_1=4$、$\beta_2=25$，§2.3.2 Eq.12，config.json activation_situ_beta=4.0, activation_situ_linear_beta=25.0）[F5]，同时保留原点附近 Swish 的线性响应。SiTU-GLU 概念页已讲清局部展开和输出界推导。

    稳定化 3 — Quantile Balancing（解决负载失衡）：从 router score 分位数直接设定每个专家 bias，使每专家恰好获得目标负载 $q = mk/n$（§2.3.3 Eq.14）[F6]。相比固定步长 sign 更新（§2.3.3 引 [27]，需要学习率 $\gamma$ 且在 896 专家下收敛慢），QB 跳到对偶问题的精确坐标最小值，无需学习率超参，几步内均衡。Quantile Balancing 概念页已讲清对偶推导和直方图估计。

    三件稳定化的分工：RMSNorm 和 SiTU-GLU 解决激活爆炸（稳定化 1+2），QB 解决负载失衡（稳定化 3）[C6]。论文 §2.3 只描述组合效果，未提供 896 专家规模下移除单个稳定化的消融实验。三件稳定化作用于不同失效路径：RMSNorm 降低尺度敏感性、SiTU-GLU 约束激活上界、QB 保证负载均衡。

    一个 token 在宽度维度的处理——经过注意力层后，token 被投影到 3584 维潜在空间，router（sigmoid 激活）选出 16 个路由专家；16 个专家在潜在空间各自变换后加权聚合，经 RMSNorm 归一化，再由 W↑ 升回 7168 维，最后与 2 个共享专家的全宽输出相加。

    本章问题

    1. 896 专家 top-16 的稀疏度是多少。

      解答：56×

      896 个路由专家中每 token 激活 16 个，即 896/16 = 56，每 56 个路由专家中激活 1 个。相比 K2 的 384 专家 top-8（48×），稀疏度进一步提高。

    2. 三件稳定化各解决哪个失效模式。

      解答：RMSNorm 与 SiTU-GLU 治激活爆炸，QB 治负载失衡

      RMSNorm 在路由专家聚合后、上投影前归一化，降低路由分支对尺度变化的敏感度；SiTU-GLU 约束 GLU 两个乘法因子的输出上界——两者共同解决激活爆炸。Quantile Balancing 从 router score 分位数直接设定专家 bias，解决负载失衡。

    3. 为什么 LatentMoE 能负担 896 专家。

      解答：路由专家在潜在空间操作，不占全宽

      路由专家在 3584 维潜在空间操作而非全宽 7168 维，通信和权重量不随路由专家数线性增长；2 个共享专家保持全宽路径，承担通用变换。

    架构之外，K3 的原生视觉由 MoonViT-V2 编码器接入共享骨干。

    5. 原生视觉——MoonViT-V2

    K3 是原生多模态模型：文本、图像、视频由单一共享骨干处理，没有事后模态对齐阶段（§2.4）。视觉编码器 MoonViT-V2 是一个 27 层、约 0.4B 参数的 ViT（config.json vt_num_hidden_layers=27），采用 RMSNorm 并移除所有 bias[C14]。

    K3 视觉设计的关键 departure 是从零训练视觉编码器，而非像 K2.5 那样从 SigLIP 对比预训练模型初始化（§2.4）。动机是训练稳定性：当预训练编码器附加到 LLM 时，联合优化变得不稳定——SigLIP 初始化的 MoonViT-3D 梯度范数持续偏高且频繁尖峰，而从零训练的 MoonViT-V2 全程稳定（Fig.6）。

    另一个好处是表示塑造：用 next-token prediction 训练让编码器表示直接由语言建模目标塑造，而非由偏好全局语义的对比损失塑造。论文 §2.4 的发现是"contrastive pre-training is unnecessary as an initialization for multimodal language models at scale"——MoonViT-V2 在视觉评估上匹配 SigLIP 初始化基线。MoonViT-V2 概念页已讲清架构细节（时空因子化、pixel-shuffle 下采样、temporal pooling）。

    本章问题

    1. 为什么从零训练比 SigLIP 初始化更稳定。

      解答：预训练编码器与 LLM 联合优化不稳定

      预训练编码器附加到 LLM 后联合优化变得不稳定：SigLIP 初始化的 MoonViT-3D 梯度范数持续偏高且频繁尖峰，从零训练的 MoonViT-V2 全程稳定（Fig.6）。

    2. "对比预训练对大规模多模态语言模型不是必要的初始化"这一发现的意义是什么。

      解答：挑战 SigLIP 初始化是必要前提的主流做法

      该发现表明在 K3 的规模下，用 next-token prediction 训练足以让编码器表示由语言建模目标直接塑造，并匹配 SigLIP 对比初始化基线，对比预训练不再是多模态语言模型的必要前提。结论依赖 2.8T 规模，更小规模未验证。

    视觉与架构之外，约 2.5× 效率还依赖训练数据、scaling law、Muon 与长上下文扩展。

    6. 训练——数据、scaling law、Muon、长上下文扩展

    约 2.5× scaling efficiency 是架构、数据、训练配方共同作用的结果，训练侧的支撑来自数据配方、scaling law、优化器与长上下文扩展。

    6.1 数据与 scaling law

    预训练数据覆盖四类文本域——Web Text、Code、Mathematics、Knowledge——加上大规模视觉语料（captions、图文交错、OCR、感知（perception）、视频、视觉编程数据，§3.1）。每个域用规则启发式、分类器质量评分和去重过滤，域特定采样率由小模型消融确定。知识数学语料用风格和视角多样 prompting 重述（rephrasing recipe，继承 K2）。

    Scaling law 研究（§3.2）独立搜索了 cosine decay 和 WSD（Warmup Stable Decay）各自的最优超参——论文发现两者最优 peak learning rate 和 batch size 差异很大，用共享超参比较不公平。在各自最优设置下，cosine decay 始终达到更低 final loss（§3.2）[C8]。据此 K3 采用 cosine + 1% linear warmup + weight decay 0.1（§3.3）。Fig.7 的 scaling-law 曲线显示 K3 达到 K2 相同 validation loss 所需 FLOPs 减半多，即约 2.5× 效率[N3]。

    6.2 Per-Head Muon

    K3 继承 K2 的 Muon 优化器用于矩阵参数，并改进为 per-head 变体（§2.5）：对 Q/K/V 投影矩阵，按头维度切分动量矩阵，每个头的块分别做 Newton-Schulz 正交化，而非对整个投影矩阵做全矩阵正交化。直觉是：全矩阵正交化把所有头当作一个耦合块，大梯度/动量尺度的头主导共享更新方向，小尺度头更新不足；per-head 正交化均衡跨头更新尺度。Per-Head Muon 概念页已讲清完整机制。

    6.3 长上下文扩展

    K3 支持最多 1M token 上下文（§3.4）。由于使用 NoPE，模型直接外推到 1M 无需位置编码修改[C9]。训练采用四阶段渐进课程，窗口依次为 8K → 64K → 256K → 1M：

    • 预训练阶段：8K → 64K
    • cooldown 阶段：256K → 1M

    将昂贵的长序列计算集中在总训练预算的小部分，保持课程经济性的同时让模型逐步适应更长的依赖。长上下文数据经过专门清洗（exact/fuzzy 去重、视频帧感知哈希、质量过滤、结构验证），并通过排列和拼接多模态文档合成需要关注完整 1M 上下文才能解决的任务（§3.4）。

    论文用 collectively 描述 2.5× 的来源，未分解架构、数据、训练各贡献多少[N3]。Table 1 量化了架构变化（61→93 层，MLA→混合，SwiGLU→SiTU-GLU，384→896 专家），数据只定性描述为 refined 未给量化指标。论文未提供移除单个改进的消融，因此各因素的相对贡献未能从论文核实。

    本章问题

    1. 列出支撑 2.5× 的训练因素。

      解答：架构、数据、优化与上下文扩展的联合作用

      架构侧 KDA+AttnRes+LatentMoE；数据侧四类文本域加视觉语料的域特定配方；优化侧 cosine decay 与 Per-Head Muon；上下文侧 NoPE 外推与四阶段渐进扩展。论文以 collectively 描述其联合效果，未分解各因素贡献。

    2. 为什么 cosine decay 和 WSD 需要独立搜索超参再比较。

      解答：两者最优超参差异大，共享超参比较不公平

      两者的最优 peak learning rate 和 batch size 差异很大，用共享超参会偏袒其中一方。在各自最优设置下比较，cosine decay 始终达到更低 final loss，K3 据此采用 cosine 加 1% linear warmup。

    3. NoPE 如何省去位置编码外推。

      解答：KDA 隐式编码位置，MLA 无显式位置编码

      KDA 通过递归门控与衰减隐式编码位置，MLA 层不施加显式位置编码，因此上下文从 256K 扩展到 1M 无需 RoPE rescaling 或 YaRN 之类的修改。

    预训练之外，后训练（SFT→RL→MOPD 三阶段、QAT、EAGLE）塑造 K3 的最终能力。

    7. 后训练——SFT→RL→MOPD 三阶段、QAT、EAGLE

    K3 的后训练遵循三阶段范式（§4.1）：监督微调（SFT）建立冷启动能力 → 强化学习（RL）发展多域多努力级别专家 → MOPD 蒸馏整合为统一模型[C10]。

    SFT（§4.1.1）扩展了 K2/K2.5 的 SFT 数据集，大幅增加复杂 agentic 轨迹覆盖。用前代 Kimi 模型合成数据轨迹，经多阶段验证和人工标注。所有数据用 XTML chat template（附录 F）序列化。

    RL（§4.1.2）跨三域 × 三努力级别：三域 = (i) 通用任务、(ii) 通用智能体、(iii) 编程智能体；三努力 = {low, high, max}。交叉得到 9 个专家模型。RL 用 partial rollout（部分轨迹完成即优化）减少长尾延迟，配合可恢复沙箱基础设施（§5.3.2）。reasoning effort 通过 per-problem budget control 实现：超预算轨迹得 -1 奖励。

    MOPD（§4.1.3，Multi-Teacher On-Policy Distillation）将九个域×努力专家整合为统一模型。对给定域 d 和努力 e，由对应教师 $\pi_{\text{teacher}}$ 指导学生 $\pi_\theta$，per-token OPD reward 用 stop-gradient + clip 约束（Eq.15）[F7]。MOPD 的核心是在策略蒸馏，学生模型在自己生成的轨迹上学习，教师提供 dense reward 信号，整合多个专家能力到一个模型。完整机制见 MOPD 概念页。

    QAT（量化感知训练，Quantization-Aware Training）（§4.1.4）从 SFT 阶段开始贯穿整个后训练，MXFP4 权重 + MXFP8 激活，只量化 MoE 专家权重（论文 §4.1.4 列出的高精度项为注意力投影、latent MoE 投影（W↓/W↑）、共享专家与 MoE router；config.json quantization_config.ignore 另将 lm_head、视觉塔、多模态投影器列入 ignore）[C11]。RL 时 rollout 和训练共享同一量化方案，消除训练-推理失配。MXFP4 QAT 概念页已讲清量化机制。

    EAGLE-3 draft model（§4.1.4）：K3 预训练时有一个 MTP（Multi-Token Prediction）层，结构匹配 backbone block。EAGLE-3 的 draft model 是单层 decoder，结构匹配 MTP 层，因此 K3 把预训练 MTP 层微调为 EAGLE-3 风格 draft model（target model 冻结，只更新 draft 层和 feature-fusion 投影）。draft 输入融合低/中/高层特征（第 1、4、最终 AttnRes block 的输出），训练时展开 7 步。直接优化 LK loss（Eq.16，接受率的负对数）[F8]而非 KL 代理。EAGLE-3 是投机解码方法，小模型先草拟 token，大模型批量验证，加速推理；K3 用 MTP 层改造而非从零训练 draft model。完整机制见 EAGLE-3 概念页。

    本章问题

    1. 三阶段后训练各做什么。

      解答：SFT 冷启动，RL 练专家，MOPD 整合

      SFT 用扩展的 agentic 轨迹数据建立冷启动能力；RL 跨三域三努力级别训练专家模型并用 partial rollout 控制长尾延迟；MOPD 用在策略蒸馏把九个专家整合为统一模型，教师提供 dense reward 信号。

    2. QAT 为什么从 SFT 阶段开始。

      解答：让模型全程适应量化并消除训练-推理失配

      从 SFT 开始贯穿整个后训练，模型在 MXFP4 权重加 MXFP8 激活下学习；RL 时 rollout 和训练共享同一量化方案，消除训练-推理失配。

    3. 9 个专家模型是怎么来的。

      解答：3 域 × 3 努力级别

      三域（通用任务、通用智能体、编程智能体）与三努力级别（low、high、max）交叉得到 9 个组合，每个组合训练一个专家模型，最后由 MOPD 蒸馏整合。

    后训练依赖 3T 训练与 1M RL 的系统支撑，基础设施是下一层。

    8. 基础设施——3T 训练 + 1M RL + 推理

    K3 面临三个罕见地同时出现的系统挑战：混合 KDA 注意力、3T 级稀疏多模态训练、百万 token 智能体工作负载（§5）。基础设施按 KDA 系统、专家并行、RL 系统与推理服务四类展开，完整工程细节是独立工作。

    8.1 KDA 系统协同

    FlashKDA（§5.1.1）是 CUTLASS 的 chunkwise 融合内核，重叠 chunk 内计算与跨 chunk 状态传播，优于 Triton 参考实现。KCP（KDA Context Parallelism）（§5.1.2）解决跨设备上下文并行：KDA 的 delta rule 应用 token 相关矩阵 M_t 到传入状态，简单求和不够（与 vanilla linear attention 不同）；KCP 把每段效果分解为"对传入状态的累积转移"和"从零生成的局部状态"，两个量本地可算，通过固定大小 all-gather 交换，prefix scan 恢复各 rank 传入状态。完整机制见 FlashKDA 与 KCP 概念页。

    8.2 MoonEP：完美均衡专家并行

    MoonEP（§5.2.1）实现完美负载均衡的专家并行：每 rank 恰好收到 S×K 个 token（S=序列长度，K=每 token 激活专家数=16），计算形状静态已知。关键证明：E/R 个 redundant expert 总是够用（附录 E 定理 1），且这个上界基本紧。零拷贝通信（planning kernel 预计算目的地，token 直接发送到远程 rank 的专家分组位置）。静态形状消除每层 MoE host 同步。完整机制见 MoonEP 概念页。

    8.3 1M 智能体 RL 系统

    RL 系统采用 co-located 训练（每实验几百 GPU）+ partial rollout（§5.3.1）。关键创新：外部 KV cache 池（把可复用前缀写回 CPU DRAM，KDA 状态与 MLA KV cache 一起 offload/prefetch）和 AgentENV microVM 沙箱（§5.3.2，基于 Firecracker，支持增量 checkpoint/resume，checkpoint 延迟低至 133ms，pause/resume/fork/snapshot 操作，6.5× 内存超分）。训练与评估期间共创建 51,219,741 个沙箱（跨 1,505,678 个镜像）。

    8.4 推理服务

    推理服务（§5.4）解决混合 KDA-MLA 的双缓存管理：KDA 递归状态（固定大小）与 MLA KV cache（随序列增长）共享分页池，prefix cache 在 512-token 粒度匹配（§5.4.1 Fig.12）。高性能内核优化 KDA 解码（replay 机制处理投机解码回滚）、Block AttnRes（SP+side stream）、Stable LatentMoE（WarpDecode token-centric）。Fleet 级调度用 cache-aware affinity scheduling 和 budget-based admission control。更多 GPU 执行背景见 GPU 执行模型。

    本章问题

    1. 三类基础设施各解决什么挑战。

      解答：KDA 系统管线性注意力并行，MoonEP 管专家均衡，RL 系统管长轨迹状态

      KDA 系统协同（FlashKDA、KCP）解决 chunkwise 融合与跨设备上下文并行；MoonEP 解决专家并行的完美负载均衡与零拷贝通信；1M RL 系统解决可复用前缀的 KV cache 池化与沙箱 checkpoint/resume。

    2. KCP 与普通 linear attention 上下文并行有何不同。

      解答：delta rule 的效果不能简单求和，需分解为转移与局部状态

      KDA 的 delta rule 要把 token 相关矩阵应用到传入状态，各段效果不能像 vanilla linear attention 那样简单求和。KCP 把每段效果分解为"对传入状态的累积转移"和"从零生成的局部状态"，两个量本地可算，经固定大小 all-gather 交换后用 prefix scan 恢复各 rank 的传入状态。

    架构、训练与基础设施的最终效果体现在 benchmark 与成本效率上。

    10. 独立评价——系统性设计、开源里程碑与边界

    以下评价属于解读者判断，而非论文结论。

    10.1 优点

    三维度信息流的系统性设计是 K3 最突出的贡献。KDA（序列）、AttnRes（深度）、Stable LatentMoE（宽度）不是三个独立改进拼凑，而是互相支撑的系统：KDA 让长序列可负担，才敢把层数推到 93（需要 AttnRes 防稀释）；AttnRes 让深网络可行，才敢把专家扩到 896（需要 Stable LatentMoE 防爆炸）。这种系统性在开源模型中罕见，通常只在闭源大厂的全栈工作中看到。

    开源 3T 级的里程碑。K3 是首个开放权重的 3T 级模型（§8），在开源生态多停留在 1T 级时把规模推到新前沿。WebDev Arena #1/99 是首个开源模型登顶，具有象征意义。

    训练-部署协同。QAT 从 SFT 贯穿 RL，EAGLE draft model 复用 MTP 层——部署效率不是事后优化，而是从训练阶段就纳入的设计。

    基础设施工程深度。FlashKDA/KCP、MoonEP、AgentENV 的设计都基于严格的理论分析（MoonEP 的 E/R 上界证明、KCP 的 delta rule 分解），不是经验性调优。

    10.2 局限

    研究级推理仍落后。CritPt 23.4 落后三个闭源模型，HLE-Full 43.5/56.0 落后 Fable 5 的 53.3/63.0。论文 §6.1.4 自己承认"research-level reasoning remains a key direction for improvement"。这表明 K3 的优势在工程化和 agentic 能力，而非最硬的推理。

    benchmark harness 差异使绝对分数需谨慎。Terminal-Bench 的官方 88.3 是 best across harnesses、Fable 5 含 fallback、GPT-5.6 Sol 含 cyberguard——直接比分数可能误导。论文 §6.1.3 明确 Terminal-Bench 报 best across harnesses[N4]，因此 K3 的编程分数包含 harness 选择的影响，纯模型能力差距与 Table 2 显示的可能不同。

    2.5× scaling efficiency 未分解单因素。论文只给 collectively 的 2.5×，未分解架构/数据/训练各贡献多少[N3]。这使得其他团队难以判断哪些改进值得复用。

    视觉"从零训练匹配 SigLIP"的结论依赖特定规模。论文 §2.4 的结论基于 K3 的 2.8T 规模，未在更小规模下验证，SigLIP 初始化的优势是否在更小规模下保持，未能从论文核实[C13]。

    10.3 适用条件与位置

    什么情况下值得用 K3：长上下文 agentic 任务（1M 上下文 + partial rollout）、成本敏感部署（BrowseComp $2.03/任务）、开源研究（完整权重可复现）、需要原生视觉的任务（非事后对齐）。

    什么情况下不适合：需要最强研究级推理（CritPt/HLE 这类任务应选 Fable 5 或 GPT-5.6 Sol）、需要闭源模型的 cyberguard/fallback 安全层。

    与相邻工作的位置：K3 是 K2 的直接升级（Table 1 量化了每个维度变化）。在架构路线上，KDA+MLA 混合注意力是与纯注意力（GPT/Claude）不同的路线——用线性注意力承担大部分序列混合，softmax 注意力只周期性出现。Stable LatentMoE 的 LatentMoE 路线（潜在空间路由）与传统全宽 MoE 路线也不同。这些选择是否成为主流有待后续工作验证。

    回到核心问题：K3 用 KDA+MLA 3:1 混合同时获得长序列效率与全局注意力（序列维度）[C3]，Block AttnRes 让 93 层深网络跨 block 选择性检索前层表示（深度维度）[C4]，Stable LatentMoE 用 RMSNorm+SiTU-GLU+QB 三件稳定化在 896 专家、56× 稀疏度下保持训练稳定（宽度维度）[C5, C6]。三维度互相支撑，配合训练与基础设施创新，共同支撑约 2.5× scaling 效率[C7]。K3 落后 Claude Fable 5 和 GPT-5.6 Sol，但总体优于 Opus 4.8、GPT-5.5 和开源 GLM-5.2，研究级推理（CritPt、HLE-Full）为例外[C12]，是首个开放权重的 3T 级模型。

    本章问题

    1. K3 最突出的贡献是什么。

      解答：三维度信息流的系统性设计

      KDA（序列）、AttnRes（深度）、Stable LatentMoE（宽度）互相支撑而非独立拼凑：KDA 让长序列可负担才敢加深到 93 层，AttnRes 让深网络可行才敢扩到 896 专家。这种系统性设计在开源模型中罕见，加上首个开放权重的 3T 级规模，构成主要贡献。

    2. 论文承认或可核实的主要局限有哪些。

      解答：研究级推理、harness 条件、未分解的 2.5×、规模依赖

      研究级推理仍落后（CritPt 23.4、HLE-Full 43.5/56.0）；benchmark harness 差异使绝对分数需谨慎；2.5× 效率只有 collectively 结论未分解单因素；"从零训练匹配 SigLIP"的结论依赖 2.8T 规模，更小规模未验证。

    3. 什么条件下适合用 K3，什么条件下不适合。

      解答：长上下文 agentic 与成本敏感条件适合，最硬推理不适合

      适合：长上下文 agentic 任务（1M 上下文加 partial rollout）、成本敏感部署、开源研究、需要原生视觉的任务。不适合：需要最强研究级推理的用途（应选 Fable 5 或 GPT-5.6 Sol）、需要闭源模型 cyberguard/fallback 安全层的用途。
