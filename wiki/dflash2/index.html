    DFlash 2：第二代块扩散草稿器（路径选择器 + 两抽头卷积）

    主要依据：Inco AI, "DFlash 2: Keep Drafting Parallel", 2026-08-18（https://inco.ai/blog/dflash2/，全文快照已存）；Hugging Face 模型卡 incoai/Qwen3.8-27B-DFlash2 的 README（YAML license 字段 apache-2.0）；DFlash 论文（Chen, Liang, Liu, ICML 2026, arXiv:2602.06036v2）作为基础设施层（DFlash 论文解析）。来源编号见文末来源与范围说明。

    DFlash 的草稿块一次前向就写完，但块内各位置是「各写各的」——每个位置独立挑自己最可能的 token，两个相邻位置可能挑出同一个词（stutter），验证时整块被截断。DFlash 2 是 2026-08-18 Inco AI 发布的第二代草稿器：不放弃并行，把「挑」和「稳」分开修——加一个路径选择器把「独立 top-1」的失败串成连贯路径，加一个两抽头动态卷积把块末端的准确率衰减补上来。两个组件总共 +1.3% 循环延迟，换来 16–25% 的接受长度提升。

    DFlash 2 不是一篇新论文、不是新独立语言模型——它是一份草稿器的工程迭代，由博客 + 两份开源草稿模型权重（Qwen3.8-27B-DFlash2、Muse-Glimmer-30B-DFlash2）发布；它构建在 DFlash 的单步并行起草之上，加两个轻量组件修复 DFlash 剩下的两个问题。以下按这两个组件的机制、证据和边界展开，DFlash 自身的 KV 注入、单步起草、训练方法见 DFlash 论文解析，块扩散范式本身见 块扩散。

    前置概念：投机解码（draft-verify 循环与接受长度的定义）、DFlash（单步并行起草、KV 注入、训练设计）。

    核心问题

    1. DFlash 2 是什么、以什么形态发布、要修 DFlash 的哪两个问题？

      解答：草稿器的产品迭代（博客+模型）；DFlash 剩选择空间未用与后缀衰减两个问题

      DFlash 2 是 Inco AI 2026-08-18 发布的第二代块扩散草稿器，发布物是博客 + 两份 HF 草稿模型权重（Qwen3.8-27B-DFlash2、Muse-Glimmer-30B-DFlash2；两款草稿器许可均为 Apache 2.0）[C1, C2]，不是独立语言模型[C2]，没有独立论文（官方引用为指向博客的 @misc）。DFlash 剩下的两个问题：①块内各位置独立预测导致连贯性差（首位 top-1 正确率 85.4%，但正确 token 99.5% 在 top-16 内——纯选择空间[C4]）；②后缀衰减——块末端准确率下降，oracle 也从 99.5% 衰减到 87.8%，是骨干问题而非选择问题[C7]。两个问题分别指向选择侧修复（路径选择器）和骨干侧修复（卷积）。详见「1. 两个剩余问题——候选池里有答案、块末端在漏气」。

    2. 路径选择器怎么从候选池串出连贯路径？打分什么、为什么便宜？

      解答：相邻对打分 $S_t(a,b)=U_t(b)+\langle A(a)\odot H(h_t),B(b)\rangle$；全并行、串行只在最后走路径

      每位置保留 top-16 候选；对每个相邻候选对 $(a,b)$ 打分 $S_t(a,b)=U_t(b)+\langle A(a)\odot H(h_t),B(b)\rangle$[F1, C6]：第一项是 DFlash 自身对 $b$ 的 logit，第二项是 256 维嵌入在上下文门 $H(h_t)$ 下的低秩双线性匹配。打分全并行完成，串行工作只有最后沿预计算分数走贪心（或采样）路径[C6]。拒绝采样恢复 target 精确分布（无损）[C3, C6]。开销 +2.0M 参数、+0.6% 循环延迟；对比 DSpark 修正头（+77.8M、+9.6%）参数少约 40×、延迟开销低 16×[N1]。详见「2. 路径选择器——在候选之间打分，而不是重新预测」。

    3. 后缀衰减为什么是局部问题，两抽头卷积怎么修？

      解答：块内依赖主要是相邻短程；两抽头卷积 $\mathrm{Conv}_k(x)_t=k_{t,0}\odot x_t+k_{t,1}\odot x_{t-1}$ 让当前位置看到前一位，首位读已验证 token

      证据链——3L/5L/15L DFlash 在首位几乎相同（85.21/85.39/86.42%）、沿块逐渐拉开（末位 64.97/72.86/78.73%），深度帮助后段但无差别[C8, N3]；块内注意力份额从第 1 层约 30% 掉到第 5 层约 8%，且集中于少数头——注意力的两份工作（读上下文 vs 建块内依赖）失衡[C9]。修法：在每层每个 attention 与 FFN 子层前后插两抽头动态深度卷积 $\mathrm{Conv}_k(x)_t=k_{t,0}\odot x_t+k_{t,1}\odot x_{t-1}$[F2, C10]，系数由学习基核+当前隐状态的小修正组成（每 16 通道共享一个修正）；首位读上一个已验证 token 的表示[C10]。+16.5M 参数（3%）、+0.7% 循环延迟；五层+卷积接近十五层效果，第 4–5 层块内注意力平均份额从 9.4% 降到 0.5%[C11, N3]。详见「3. 两抽头卷积——给块末端补上「看见前一位」的通道」。

    4. 两个组件合起来收益多少、开销多大？

      解答：Qwen3.5-4B 均值 5.97 vs 4.92（+21%），三个目标模型一致领先；合计 +1.3% 延迟

      Qwen3.5-4B（thinking 开启、T=1.0、top-p 0.95、top-k 20、presence penalty 1.5、无损拒绝采样）五项基准平均接受长度：DFlash 2 为 5.97，DFlash 4.92（+21%/+1.05 token）、DSpark 5.49、MTP（multi-token prediction，模型内置的多 token 预测路径）4.54；逐基准全面领先[N4]。Qwen3.8-27B（块 8）均值 4.80 vs MTP 4.28、DSpark 3.62[N6]；Muse Glimmer（块 16）5.70 vs 官方 DFlash 4.44、DSpark 4.48[N7]。MATH-500 逐位置条件接受率：DFlash 2 稳在约 86% 到末位，各基线末位低 6–9 个百分点[N5]。两个组件合计 +1.3% 循环延迟（选择器 +0.6% + 卷积 +0.7%）[C12]。详见「4. 组合效果——每次验证多一个 token 的账」。

    5. 端到端吞吐多少、什么条件下收益趋近 1？

      解答：Qwen3.8-27B SGLang H200 并发 1 为 2.67–3.43×；并发 32 对话类缩到 1.01×（MTP 甚至 <1）

      Qwen3.8-27B + SGLang + 单卡 H200 + FA3 + 块 8（每步 7 草稿 token）+ Qwen3.8 推荐采样：并发 1 为 2.67–3.43×、并发 8 为 2.27–2.85×、并发 32 为 1.01–1.45×[N8]。MTP 同条件并发 32 时部分任务 <1（MT-Bench 0.77×、MATH-500 0.94×）[N8]。Muse Glimmer 区间 3.1–4.6×[N9]。结论：低并发结构化任务收益最大，高并发对话类收益趋近 1；高并发收益缩水的机制——批处理填满空闲算力后草稿不再搭空闲周期，错误草稿变成挤占算力的浪费（分析性推断）[C14]。vLLM 与 llama.cpp 的 DFlash 2 支持位于 PR 分支（vLLM #52816、llama.cpp #27342）[C16]，不是稳定版本。详见「5. 端到端与边界——哪里收益趋近 1」。

    1. 两个剩余问题——候选池里有答案、块末端在漏气

    DFlash 的块扩散草稿器一次前向写出整块——但每位置独立挑自己最可能的 token，没有「这块要读起来像一句话」的全局协调。这一设计取舍换来并行性（见 DFlash 论文解析的「推理管线——KV 注入与单步并行起草」章），代价是块内不连贯。DFlash 2 诊断出两个独立问题，分别用不同组件修：

    问题一：选择空间未被利用。五层 Qwen3-4B DFlash 在 GSM8K 上、给定前文全对时，块内逐位置的「top-1 正确率」Recall@1 与「top-16 命中率」Recall@16 表现如下[C4, N2]：

    块内位置0123456
    Recall@1（top-1 正确率）85.4%80.3%79.4%78.3%77.5%75.9%72.9%
    Recall@16（top-16 命中率）99.5%97.3%94.8%92.6%90.8%89.4%87.8%

    读法：top-1 选对的概率约 73–85%，但正确 token 几乎都在 top-16 里（87.8–99.5%）。oracle（总是从 top-16 中选对）能把接受长度从 4.27 提到 6.79[N2]——纯选择空间就有约 1.6× token 的余量。问题不在「模型不知道正确答案」，而在「怎么从候选里串出一条连贯的路径」。DFlash 2 用「路径选择器」修这件事：保持每位置多候选、只打分不预测，沿相邻对分数走路径。

    问题二：后缀衰减是骨干问题。注意上表的 Recall@16 同样在沿块下降——从 99.5% 掉到 87.8%[C4, N2]。oracle 也会衰减，说明候选池本身在后段变差，选择器修不了[C7]。进一步看层数对照：3L/5L/15L DFlash 在首位几乎相同（85.21/85.39/86.42%）、沿块逐渐拉开（末位 64.97/72.86/78.73%）[C8, N3]。深度帮助后段但无差别：15 层 3× 参数、+15.2% 循环延迟才有 78.73% 末位。诊断是 attention 同时承担两份工作（读上文 + 建模块内依赖），块内依赖被欠配——块内注意力份额从第 1 层 30% 掉到第 5 层 8%，且集中于少数头[C9]。DFlash 2 用「两抽头动态卷积」修这件事：在 attention 与 FFN 子层前后插一个只覆盖「当前位 + 前一位」的局部算子，把建模块内依赖的工作从 attention 抽出来。

    选择空间未用Recall@1 85.4% vs Recall@16 99.5%；oracle 4.27→6.79选择侧（候选池没坏）『路径选择器——在候选之间打分，而不是重新预测』
    后缀衰减Recall@16 也沿块下降；oracle 衰减；15 层加深度才显著补骨干侧（候选池本身变差）『两抽头卷积——给块末端补上「看见前一位」的通道』

    贯穿示例用 3 位置 × top-2 候选的构造网格，演示两个问题在最小例子中的形态（构造数据，token 内容与分数均为人为设定）。表中「DFlash 独立 top-1」列的数字为 $U_t$（draft 自身的 logit），「路径选择器输出」列的数字为 $S_t$（含相邻对双线性项）；两列不是同一个量（一列为 $U_t$、一列为含相邻对双线性项的 $S_t$），不对数值作横向比较（分解见 2.4 节）。

    独立 top-1 输出「decoding decoding parallel」——「decoding」重复出现，被目标模型验证时很可能因为 stutter 在位置 2 被截断。路径选择器输出「decoding is parallel」——连贯句。第二个问题（块末端衰减）在这个三位置例子里尚不明显，但在更长的块或更靠后的位置就会浮现：真实数据里位置 1、2 的 Recall@1 已从首位下降（80.3%/79.4% vs 85.4%，见 N2），说明后段候选池本身在变差——靠选择器救不回来。

    本章问题

    1. DFlash 的选择空间证据是什么？oracle 差距多大？

      解答：Recall@1 85.4% vs Recall@16 99.5%（首位）；oracle 4.27→6.79（GSM8K 接受长度）

      五层 Qwen3-4B DFlash 在 GSM8K、条件于前文全对时，逐位置 Recall@1 从 85.4%（首位）衰减到 72.9%（位置 6），Recall@16 从 99.5% 衰减到 87.8%[C4, N2]。oracle（从 top-16 中总选对）能把接受长度从 4.27 提到 6.79——约 1.6× token 的选择空间余量[N2]。

    2. 后缀衰减为什么选择器修不了？

      解答：Recall@16 也衰减；oracle 自身从 99.5% 掉到 87.8%——候选池本身在后段变差

      候选池本身在后段变差：oracle（总能从 top-16 选对）也只从首位 99.5% 衰减到末位 87.8%[C7, N2]。选择器只在给定候选池里挑路径——候选池坏到一定程度，挑得再准也没用。诊断因此指向骨干：attention 同时承担读上文和建模块内依赖两份工作，块内依赖被欠配[C9]。修法必须改骨干，不在选择侧（见『两抽头卷积——给块末端补上「看见前一位」的通道』）。

    2. 路径选择器——在候选之间打分，而不是重新预测

    路径选择器回答「top-1 选错时，怎么从 top-16 里串出一条连贯路径」。设计原则是「选比预测便宜」[C5]：作者论证候选的适配主要取决于前一个 token（局部性），给相邻对打分就够，不需要重新预测。

    2.1 打分公式

    每位置保留 top-16 候选；对每个相邻候选对 $(a,b)$ 打分[F1, C6]：

    $$S_t(a,b)=U_t(b)+\langle A(a)\odot H(h_t),B(b)\rangle.$$
    • $a$：前一位置的候选（位置 $t-1$ 的 top-16 之一）。
    • $b$：当前位置的候选（位置 $t$ 的 top-16 之一）。
    • $U_t(b)$：DFlash 自身对 $b$ 的 logit——「draft 模型独自有多想选 $b$」。
    • $A(\cdot)$、$B(\cdot)$：每 token 的 256 维紧凑嵌入（$a$ 侧/ $b$ 侧分别投影）。
    • $H(h_t)$：上下文门（决定 256 维匹配的哪些维度算数）。
    • $\odot$：按元素乘积（element-wise product）。
    • $\langle\cdot,\cdot\rangle$：内积。

    第二项本质上是一个低秩双线性注意力：$a$ 与 $b$ 各自的 256 维嵌入在上下文门 $H(h_t)$ 加权后做内积——衡量「给定上下文 $h_t$，$b$ 接 $a$ 有多自然」。两项加起来既保留 draft 自身对 $b$ 的偏好，又显式校准相邻的连贯性。

    2.2 全并行、串行只在最后

    所有相邻对、跨所有位置的打分一次前向算完——不需要额外骨干或 LM head 前向[C6]。唯一串行工作是沿预计算分数从最后已验证 token 出发走路径：贪心每步取最高分后继，采样按分数分布取，拒绝采样恢复 target 精确分布（保证输出分布与 target 一致——即 投机解码 的无损性）[C3, C6]。

    2.3 与 DSpark 修正头的对比

    DSpark（相近路线）用「串行修正头」为每个位置改写一次完整的词表分布——开销大、串行多。DFlash 2 选择器的关键论据是：选择可以全并行，只有走路径是串行的；走路径每步前进一个位置，长度随块大小线性增长（此点为由机制直接得出的推断），所以「选比预测便宜」[N1]。数字对比：

    方法新增参数循环延迟接受长度（T=0 / T=1）
    DFlash 基线——4.27 / 3.78
    DFlash + DSpark 修正头+77.8M+9.6%4.49 / 4.08
    DFlash + 路径选择器（不含卷积）+2.0M+0.6%4.61 / 4.25

    参数约为 1/40，延迟开销约为 1/16，接受长度还更高[N1]。即使如此，距离 oracle 6.79 仍有空间（4.61 vs 6.79）——「选」的上限是候选池本身，候选池好坏取决于骨干（见『3. 两抽头卷积——给块末端补上「看见前一位」的通道』）。完整 DFlash 2 另含两抽头卷积（+16.5M 参数、+0.7% 延迟，合计 +1.3% 延迟；详见『4. 组合效果——每次验证多一个 token 的账』）。

    2.4 一个最小例子：3 位置 × top-2 的分数与走路径

    构造示例——3 个位置，每位置 top-2 候选，假设每对的分数为（人为构造，便于演示 $S_t$ 的两个成分）：

    位置 $t$候选 $b$$U_t(b)$说明
    1decoding / learning0.85 / 0.10首位 decoding 占绝对优势
    2decoding / is0.55 / 0.40第二位 logit 上 decoding 仍高，独立 top-1 会重选 decoding 造成 stutter
    3parallel / now0.80 / 0.18第三位 parallel 占绝对优势

    相邻对分数 $S_t(a,b)$（构造数据，用于辅助理解路径选择的工作方式，不代表实测）：

    前驱 $a$当前 $b$$S_t(a,b)$走法
    decodingdecoding0.25（$U_2=0.55$ + 低双线性 $-0.30$）stutter 被压低
    decodingis0.60（$U_2=0.40$ + 高双线性 $+0.20$）连贯
    isparallel0.85（$U_3=0.80$ + 中双线性 $+0.05$）连贯
    isnow0.20（$U_3=0.18$ + 中双线性 $+0.02$）不取

    从最后已验证 token 出发贪心走路径（bonus 即验证顺带产出的下一 token；本节不区分验证 bonus 与拒绝修正 token 的来源）：

    • 位置 1：取 $U_1$ 最高的 decoding（$U_1=0.85$；本例未设定已验证前缀，首位按 $U_1$ 选取；实际机制中首位的前驱是最后已验证 token，见 2.2 节）。
    • 位置 2：$S_2(\text{decoding},\text{decoding})=0.25$ vs $S_2(\text{decoding},\text{is})=0.60$ → 选 is。
    • 位置 3：$S_3(\text{is},\text{parallel})=0.85$ vs $S_3(\text{is},\text{now})=0.20$ → 选 parallel。

    路径选择器输出「decoding is parallel」；DFlash 独立 top-1 输出「decoding decoding parallel」——后者在位置 2 出现 stutter，被目标模型验证时很可能截断。这是选择器价值的最直接展示：不重新预测，只在已有候选里串路径，开销只有 +2.0M 参数、+0.6% 延迟。构造示例中的 token 内容与分数为人为设定，不属于任何实测数据。

    本章问题

    1. 打分公式各项是什么？为什么全并行？

      解答：$S_t(a,b)=U_t(b)+\langle A(a)\odot H(h_t),B(b)\rangle$；一次前向算完所有相邻对，无额外骨干或 LM head

      公式 $S_t(a,b)=U_t(b)+\langle A(a)\odot H(h_t),B(b)\rangle$[F1, C6]：$U_t(b)$ 是 DFlash 自身对 $b$ 的 logit（draft 自己的偏好），第二项是 256 维嵌入在上下文门 $H(h_t)$ 下的低秩双线性匹配（衡量「$b$ 接 $a$ 有多自然」）。打分全并行：所有相邻对、所有位置一次前向算完，不需要额外骨干或 LM head 前向[C6]。唯一串行工作是最后沿分数走路径；走路径每步前进一个位置，长度随块大小线性增长（由机制得出的推断）。

    2. 与 DSpark 修正头比，路径选择器便宜在哪？收益多少？

      解答：参数 1/40、延迟开销 1/16；T=0 接受长度 4.61 vs 4.49、DFlash 基线 4.27

      DSpark 修正头需要为每位置改写一次完整词表分布（串行、参数多），DFlash 2 选择器只对相邻对打分（并行、参数少）。五层 Qwen3-4B GSM8K：DFlash 2 +2.0M 参数、+0.6% 延迟，T=0 接受长度 4.61；DSpark 修正头 +77.8M、+9.6%、4.49；DFlash 基线 4.27。参数约为 1/40，延迟开销约为 1/16，接受长度还更高[N1]。注意：4.61 距 oracle 6.79 仍有空间——选择上限取决于候选池本身，需要『3. 两抽头卷积——给块末端补上「看见前一位」的通道』修骨干。

    3. 两抽头卷积——给块末端补上「看见前一位」的通道

    路径选择器修了「挑不准」，但「候选池本身在后段变差」是骨干问题，需要在 attention 与 FFN 之外加一个专门负责「建模块内依赖」的局部算子——这就是两抽头动态卷积。

    3.1 后缀衰减的证据链

    选择器修不了后缀衰减的根因是 候选池坏到一定程度。证据链：

    • 深度帮助后段但无差别[C8, N3]。3L/5L/15L DFlash 在首位几乎相同（85.21/85.39/86.42%），沿块逐渐拉开（末位 64.97/72.86/78.73%）。15 层比 5 层在末位多约 5.9 点，但用了 3× 参数和 +15.2% 循环延迟——为了末段好一点，整个网络都加了容量。
    • 注意力的两份工作失衡[C9]。attention 同时负责「读上文」与「建模块内依赖」。块内注意力份额从第 1 层约 30% 掉到第 5 层约 8%，且集中于少数头——后面几层把几乎所有注意力都放到读上文上，块内依赖被欠配。

    诊断：块内依赖本来就主要是相邻短程（块大小 4–16，依赖主要在邻接位置），但 attention 的全局工作被过载了。修法是把「建模块内依赖」从 attention 抽出来，用一个轻量局部算子专职。

    3.2 两抽头动态深度卷积

    卷积定义[F2, C10]：

    $$\operatorname{Conv}_k(x)_t=k_{t,0}\odot x_t+k_{t,1}\odot x_{t-1}.$$
    • $x_t$：当前位置的隐藏态。
    • $x_{t-1}$：前一位的隐藏态（首位取上一个已验证 token 的表示[C10]）。
    • $k_{t,0}$、$k_{t,1}$：动态系数，组合自「学习基核」与「当前隐状态的小修正」；每 16 通道共享一个修正[C10]。

    只在当前位和前一位上各做一个抽头——「两抽头」得名于此。卷积 块内局部、无状态，不改动 attention、LM head 或验证流程[C10]，可作为子层前后的预处理/后处理模块插入。

    补充：与「15 层 DFlash」的对照说明了什么

    15 层 DFlash 比 5L 在首位只高 1.0 点（86.42 vs 85.39），在末位高 5.9 点（78.73 vs 72.86）——深度带来的容量提升几乎全给到了后段[N3]。但 15 层用了 3× 参数和 +15.2% 循环延迟，相当于「在首位与中段白白加了一堆容量」来换「末段好 6 个点」。5L+conv 用 +3% 参数、+0.7% 延迟换到末段 77.61%（离 15L 的 78.73 只差 1.1 点），首位几乎不损（85.83 vs 85.39）。这是「针对性小算子」设计的直接证据——卷积不与 attention 抢首位工作，专补末段被欠配的依赖。

    本章问题

    1. 后缀衰减为什么是局部问题？证据链是什么？

      解答：3/5/15L 首位几乎相同沿块拉开；块内注意力份额 30%→8%——后段依赖主要是相邻短程，但 attention 抢着读上文

      3L/5L/15L DFlash 在首位几乎相同（85.21/85.39/86.42%）、沿块逐渐拉开（末位 64.97/72.86/78.73%）[C8, N3]——深度只在后段起明显作用。块内注意力份额从第 1 层 30% 掉到第 5 层 8%，且集中于少数头[C9]——attention 把几乎所有注意力放到读上文，建模块内依赖被欠配。块大小 4–16，依赖主要是相邻短程，应该用局部算子专门处理，而不是让 attention 兼顾。

    2. 卷积公式怎么运作？为什么首位要读已验证 token？

      解答：$\mathrm{Conv}_k(x)_t=k_{t,0}\odot x_t+k_{t,1}\odot x_{t-1}$，当前位置和前一位各一抽头；首位 $x_{t-1}$ 是上周期目标 token

      公式 $\mathrm{Conv}_k(x)_t=k_{t,0}\odot x_t+k_{t,1}\odot x_{t-1}$[F2, C10]：每个位置取两个抽头——当前位 $x_t$ 和前一位 $x_{t-1}$，各乘一个动态系数 $k_{t,0}$、$k_{t,1}$。系数由学习基核+当前隐状态小修正组成，每 16 通道共享一个修正。首位没有同块内的「前一位」——所以 $x_{t-1}$ 改成读上一个已验证 token 的表示[C10]，与推理时「以上周期目标模型产出为锚」一致。卷积块内局部、无状态，插在 attention 与 FFN 子层前后，不改 LM head 或验证流程[C10]。

    5.2 高并发收益缩水的机制

    为什么加速随并发下降？投机解码的加速来自「草稿 + 验证搭在目标模型一次前向的空闲算力上」——单请求时 GPU 大半空闲，草稿-验证是白赚的。批处理把空闲填满后，草稿-验证不再「免费」：错误草稿变成挤占有效请求算力的浪费。模型卡的并发 32 一行逐任务给出倍数（MT-Bench 1.01×、HumanEval 1.16×、GSM8K 1.45×——任务越开放、缩短越厉害），但未在博客中给出因果分析。本节对该方向性事实给出机制解释，明确标注为分析性推断[C14]。

    5.3 部署注意事项

    适用判断：

    • 低并发结构化任务（数学、代码）收益最大（3×+）。
    • 高并发对话类（MT-Bench 类）收益趋近 1，但至少不亏（DFlash 2 vs MTP）。
    • 需要为每个目标模型训练配套草稿器（不是通用插件）——当前已发布 Qwen3.8-27B、Muse Glimmer 两款[C13]。
    • 引擎支持状态：SGLang 可直接运行（博客以 git main 源码方式安装）；oMLX（Apple Silicon 端）在博客 Run It Now 中给出安装说明；vLLM 与 llama.cpp 的 DFlash 2 支持位于 PR 分支（vLLM PR #52816、llama.cpp PR #27342）[C16]。
    • 数字环境：吞吐数字来自单卡 H200 的模型卡自测，接受长度数字来自博客自测（未注明硬件）；允许来源中未见第三方独立复现。

    生态一句：DFlash（一代）已集成 SGLang、vLLM、TensorRT-LLM、llama.cpp；Inco AI 宣称 Hugging Face 下载超 350 万次（2026-08）、NVIDIA 在 Blackwell 上测得最高 15×、Google 在 TPU 上 3×[C15]。这些数字属厂商自测，非第三方独立复现，仅作背景。

    辅助解释与类比边界

    「选比预测便宜」的说法用于解释路径选择器相对 DSpark 修正头的成本优势（参数 1/40、延迟 1/16、接受长度更高）。该说法只解释「打分并行、走路径串行」这层结构对成本的贡献，不覆盖完整草稿器的端到端开销（prefill、KV 注入、目标模型验证等仍按各自方式计）。正式判断仍以 N1 的实测数字为准。「针对性小算子替代全面加深」用于解释两抽头卷积相对 15 层 DFlash 的设计选择（参数 3% vs 3×、延迟 0.7% vs 15.2%、末位 Recall 77.61% vs 78.73%）。该说法只解释「卷积专门修后段」这一层设计意图，不覆盖完整骨干的容量配置（5 层是经验最优，论文另有层数消融）。

    简化条件及其限制

    ①所有接受长度数字依赖特定的采样配置（温度、top-p、top-k、presence penalty、reasoning effort）。这些参数对接受长度有显著影响——例如 Qwen3.5-4B 的数字是在 thinking 开启、presence penalty 1.5、推荐采样下得到；其他采样配置下的接受长度需自行测试。②吞吐数字全部来自单卡 H200 与 SGLang 后端；其他显卡、vLLM、llama.cpp 的实际吞吐会因 batch 调度与 overlap 实现差异而不同。③DFlash 2 路径选择器与卷积组件在 vLLM 与 llama.cpp 上的实现尚处 PR 阶段（vLLM #52816、llama.cpp #27342），未经充分稳定性测试。④构造示例中的 token 内容与分数为人为设定，仅用于演示两个组件的工作方式；任何在真实模型上的行为需直接看 N 编号引用的实测数据。⑤HF 模型卡 N8 的并发表是厂商自测，允许来源中未见第三方独立复现。⑥本页面所有「分析性推断」均已显式标注为推断，不当作论文事实呈现。
