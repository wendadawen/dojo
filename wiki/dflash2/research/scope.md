# DFlash 2 内容范围

## 1. 概念歧义处理

「DFlash 2」歧义状态：已裁定。

- 指称：Inco AI 于 2026-08-18 发布的第二代投机解码草稿器（drafter）技术与配套模型，非独立语言模型、非论文。
- 与「DFlash」（Z Lab 论文，ICML 2026，../dflash/index.html）的关系：同一设计谱系的工程迭代；DFlash 2 无独立论文，一手来源为 Inco AI 官方博客（https://inco.ai/blog/dflash2/，2026-08-18）与 Hugging Face 模型卡（incoai/Qwen3.8-27B-DFlash2、incoai/Muse-Glimmer-30B-DFlash2，2026-08 版本）。
- 裁定依据：官方引用格式即指向博客的 `@misc` 条目；模型卡声明「It is not a standalone language model」。页面在开头显式说明该发布形态，避免读者按论文页预期。

## 2. 概念含义

- 概念名称：DFlash 2；发布方 Inco AI。
- 简要定义：在 DFlash「一次前向并行预测整块」设计上增加两个轻量组件（路径选择器 + 两抽头动态卷积）的第二代块扩散草稿器，每次验证多产出约 20% token、仅增加约 1% 循环延迟，输出与目标模型逐字节一致（无损）。
- 正式定义（与官方博客一致）：block-diffusion drafter——整块单次前向预测、每位置保留 top 候选、轻量选择器从中串一条连贯路径、骨干中的两抽头动态卷积抑制块末端衰减；greedy 输出与 target 完全一致、采样保持 target 分布。
- 本文语境：以两个新增组件的机制与证据为主体；DFlash 基础机制（KV 注入、单步起草、训练）不在本页展开，链接论文页。
- 包括：
  - 两个待修问题的证据（选择空间：Recall@1 vs Recall@16；后缀衰减：oracle 亦衰减）。
  - 路径选择器机制（候选保留、相邻对打分公式、贪心/采样走路径、无损性）。
  - 两抽头动态卷积机制（公式、首位读已验证 token、与加层的对比）。
  - 组合效果数字（Qwen3.5-4B / Qwen3.8-27B / Muse Glimmer 三组接受长度；+1.3% 延迟）。
  - 端到端吞吐与并发边界（模型卡并发×任务表）。
  - 发布形态与可用引擎（SGLang / vLLM PR 分支 / llama.cpp PR / oMLX）。
- 不包括：
  - DFlash 的 KV 注入与训练方法——论文页职责。
  - DSpark / Domino 的修正头机制细节——只作为对比基准引用其数字。
  - MTP 机制——只作为对比基准（Qwen3.8 原生 MTP 路径）。
  - Canon Layers / Dynamic Short Convolutions 的完整理论——卷积设计仅引用为灵感来源。
  - 生态与商务信息（下载量、NVIDIA/Google 宣称数字、招聘）——一句带过并标注厂商宣称，不展开。
- 相邻概念：
  - DFlash（前置）：块扩散草稿器的第一代与基础设施。
  - DSpark / Domino：用串行修正头买连贯性的相邻路线（本页对比其数字与开销）。
  - MTP：target 模型原生多 token 预测路径（对比基准）。

## 3. 学习目标

### Q1：DFlash 2 是什么、以什么形态发布、要修 DFlash 的哪两个问题

- 完成答案：DFlash 2 是 Inco AI 2026-08-18 发布的第二代块扩散草稿器（模型 + 博客 + 模型卡，无论文）。DFlash 剩余两个问题：①块内各位置独立预测、互不连贯（首位 top-1 正确率 85.4%，但正确 token 99.5% 在 top-16 内——纯选择空间）；②后缀衰减——块末端准确率下降（连 oracle 从 99.5% 衰减到 87.8%，是骨干问题、选择器修不了）。
- 依赖内容：DFlash 页（单步并行预测、KV 注入结论）。
- 为什么核心：定位不清会把本页当论文页读、或把两个组件混为一谈。

### Q2：路径选择器怎么从候选池串出连贯路径——打分什么、为什么便宜

- 完成答案：每位置保留 top-16 候选；对每个相邻候选对 $(a,b)$ 打分 $S_t(a,b)=U_t(b)+\langle A(a)\odot H(h_t),B(b)\rangle$：第一项是 DFlash 自身对 $b$ 的 logit，第二项是 256 维嵌入在上下文门 $H(h_t)$ 下的低秩双线性匹配。打分全部并行、无额外骨干或 LM head 前向；唯一串行工作是最后沿预计算分数走贪心（或采样）路径；拒绝采样恢复 target 精确分布。开销 +2.0M 参数、+0.6% 循环延迟；对比 DSpark 修正头（+77.8M、+9.6%）参数少约 40×、延迟开销低 16×，T=0 接受长度 4.61 vs 4.49（DFlash 基线 4.27）。
- 依赖内容：Q1、DFlash 页。
- 为什么核心：这是 DFlash 2 的第一个机制支柱，「选择比预测便宜」是其核心论证。

### Q3：后缀衰减为什么是局部问题、两抽头卷积怎么修

- 完成答案：证据链——三层/五层/十五层 DFlash 在首位几乎相同、沿块逐渐拉开（深度帮助后段但 indiscriminate，15 层 +15.2% 延迟）；块内注意力份额从第 1 层 30% 掉到第 5 层 8% 且集中于少数头。诊断：注意力的两份工作（读上下文、建模块内依赖）中后者被欠配，而块内依赖本就主要是相邻短程。修法：每个 attention 与 FFN 子层前后插两抽头动态深度卷积 $\mathrm{Conv}_k(x)_t=k_{t,0}\odot x_t+k_{t,1}\odot x_{t-1}$（系数=学习基核+当前隐状态的小修正、每 16 通道共享一个修正）；首位读上一个已验证 token 的表示。+16.5M 参数（3%）、+0.7% 延迟，五层+卷积接近十五层效果；第 4–5 层块内注意力平均份额从 9.4% 降到 0.5%（卷积接管局部工作）。
- 依赖内容：Q1、标准注意力页（子层结构）。
- 为什么核心：第二个机制支柱，展示「针对性小算子替代全面加深」的设计逻辑。

### Q4：两个组件合起来收益多少、开销多大

- 完成答案：Qwen3.5-4B（thinking 开启、T=1.0、top-p 0.95、top-k 20、presence penalty 1.5、无损拒绝采样）五项基准平均接受长度：DFlash 2 为 5.97，对 DFlash 4.92 提升 21%（+1.05 token）、对 DSpark 5.49 提升 0.48、对 MTP 4.54；逐基准全面领先。合计开销 +1.3% 循环延迟。Qwen3.8-27B（块 8）：DFlash 2 均值 4.80 vs MTP 4.28、DSpark 3.62；Muse Glimmer（块 16）：5.70 vs 官方 DFlash 4.44、DSpark 4.48。MATH-500 逐位置条件接受率：DFlash 2 稳在约 86% 到末位，各基线末位低 6–9 个百分点。
- 依赖内容：Q2、Q3。
- 为什么核心：机制是否值得，由组合数字与开销共同回答。

### Q5：端到端吞吐多少、什么条件下收益趋近 1

- 完成答案：Qwen3.8-27B + SGLang、单卡 H200、FA3、块 8（每步 7 个草稿 token）、官方推荐采样：batch 1 吞吐 2.67–3.43×；并发 8 为 2.27–2.85×；并发 32 时 GSM8K 1.45×、MT-Bench 1.01×（MTP 同条件 1.04–0.77×，部分低于 1）。Muse Glimmer 为 3.1–4.6×。结论条件：低并发结构化任务收益最大；高并发对话任务收益趋近 1，此时验证与起草不再搭在空闲算力上（分析性推断，标注）。vLLM 与 llama.cpp 支持尚在 PR 分支。
- 依赖内容：Q4、投机解码页。
- 为什么核心：部署判断需要诚实边界；模型卡自己公布了 1.01× 的格子。

## 7. 常见误解和适用边界

- 误解一：「DFlash 2 是新论文/新模型」。正确结论：草稿器（drafter）的产品迭代，发布物是博客 + 两份草稿模型权重 + 引擎适配；它不是独立语言模型（模型卡原话）。影响 Q1。
- 误解二：「最高 3.4× 是普适加速」。正确结论：3.43× 是 batch 1 GSM8K 的格子；并发 32 对话 1.01×、MTP 同条件最低 0.77×。引用数字必须带并发与任务。影响 Q5。
- 误解三：「选择器在逐 token 生成」。正确结论：所有相邻对打分一次并行完成，串行部分只有最后沿分数走路径（O(块长) 的轻量遍历）；这正是它比 DSpark 修正头便宜 16× 的原因。影响 Q2。
- 误解四：「卷积等于加深网络」。正确结论：两抽头卷积是插在子层前后的局部无状态算子，只覆盖「当前位+前一位」短程依赖；加深是全局容量提升（15 层 +15.2% 延迟），卷积是针对性修补（+0.7%）。影响 Q3。
- 误解五：「选择器能修后缀衰减」。正确结论：oracle（完美选择）也从 99.5% 衰减到 87.8%——候选池本身在后段枯竭，是骨干问题，只有卷积（骨干侧）能修。影响 Q1–Q3 的分界。
- 适用边界：收益依赖低并发与结构化输出；高并发对话趋近 1；需要为每个 target 配套训练 drafter；vLLM/llama.cpp 集成在 PR 分支（未进稳定版本）；所有数字来自厂商自测（SGLang + H200/B200 环境）。
