# MOPD 教学大纲（outline.md）

## 1. 页面开头

**钩子问题**：训练好九个各有专长的专家模型后，能不能不部署九份、只部署一份就把它们的能力都装进去？直接把九组权重平均行不行？

**一句话解释**：MOPD 让一个统一的学生模型自己生成 token，由对应领域和努力程度的专家教师逐 token 给出对数概率比作为稠密奖励，在已有 RL 框架里把九个专家的能力合并进单一模型。

**要解决的具体问题**：多个专项专家分别部署成本高、能力不共享；简单合并权重不可行；需要一个能复用已有 RL 基础设施的合并方法。

**学习承诺**（与 scope.md Q1–Q5 一致）：
- 说明为什么要把九个专家合成一个统一模型
- 解释 Eq.15 每个符号在做什么，手算正/负奖励
- 说明裁剪和停梯度各自解决什么问题
- 说明九个教师如何轮流指导、稠密奖励如何接入 RL 框架
- 说明 MOPD 不能做什么

**首个具体场景**：用三 token 词表 {A, B, C} 的最小例子展示"学生采样一个 token，教师给该 token 的概率 vs 学生的概率"如何变成一个带符号的奖励标量。

**与第一章的过渡**：先看为什么需要合并（S1），再看合并具体怎么做（S2）。

## 2. 章节设计

### S1：为什么要把九个专家合成一个统一模型

- **主要教学问题**：九个专家分别部署有什么成本？为什么不直接平均权重？合并进一个条件化学生如何同时解决成本和能力整合？
- **对应范围**：Q1；C1、C2、A3（误解 M1）。
- **正文要点**：
  - 9 个专家 = 3 领域 × 3 努力程度的构成（C1）
  - 分别部署的成本：服务多份模型、显存翻倍、用户/路由需选择专家、能力不共享
  - 简单平均权重不可行的直觉解释（不同专家在不同数据分布上训练，参数空间无对应）
  - 合并方案：统一学生 $\pi_\theta$ 把努力程度 $e$ 作为条件输入，在同一组参数里表达多努力程度（C2）
  - 澄清误解 M1：MOPD 不训练这九个专家，专家由上游 RL 训练（C7）
- **讲解材料及职责**：
  - context-box：给出"9 个专家 = 3 领域 × 3 努力程度"的结构化背景（C1、N1、N2）
  - 对照表格：分别部署九份 vs 合并为一个条件化学生（C2）
  - blockquote.meta：标注主要依据（K3 §4.1.3）
- **前置知识安排**：无新前置依赖（动机层面）。
- **完成检查**：
  - 说出 9 个专家的两两构成维度
  - 说明简单平均权重为什么不可行
  - 说明条件化学生如何用一组参数表达多努力程度
- **过渡**：知道了"要合并"，下一章看"怎么合并"——学生自己走，教师逐 token 打分。

### S2：学生自己生成的 token，由教师逐个打分

- **主要教学问题**：学生采样的 token 如何变成一个带符号的奖励标量？Eq.15 里每个符号在做什么？
- **对应范围**：Q2；C3、C4、F1、F2、A1（与 off-policy 蒸馏对比）。
- **正文要点**：
  - on-policy 的含义：学生自己生成 $y_t$（不是教师生成），教师只读不写
  - 与标准 off-policy 知识蒸馏的对比：谁生成轨迹、奖励是否稠密（A1，最小衔接，前置页占位）
  - 引入 per-token OPD 奖励公式 Eq.15（F1）
  - 逐符号解释：$y_t$、$x$、$y_{<t}$、$e$、$d$、$\pi_{\text{teacher}}^{(d,e)}$、$\pi_\theta$、$\log$ 比值、$\text{sg}$、$\text{clip}$、$R_{\max}$（C3、C4）
  - 对数比值分解 F2：$\log\pi_{\text{teacher}}-\log\pi_\theta$；解释"教师比学生更认可该 token 时比值为正"
  - 策略梯度的最小衔接（前置 RLHF/策略梯度页占位）：奖励作为常数乘子，推动 $\log\pi_\theta(y_t)$ 上升或下降
  - 手算例子（教学示例，三 token 词表）：
    - 学生概率 (A,B,C)=(0.5,0.3,0.2)，教师概率 (0.7,0.2,0.1)
    - 学生采样 A：比值 $\log(0.7/0.5)\approx+0.336$，正奖励→增加 $\log\pi_\theta(A)$
    - 学生采样 B：$\log(0.2/0.3)\approx-0.405$，负奖励→减小 $\log\pi_\theta(B)$
    - 学生采样 C：$\log(0.1/0.2)\approx-0.693$，负奖励→减小 $\log\pi_\theta(C)$
    - 结论：学生分布向教师分布靠拢
- **讲解材料及职责**：
  - 公式（Eq.15）表达变量关系
  - 数字例子展示计算步骤和正负方向
  - ASCII 图示：学生采样→教师打分→奖励回传的循环结构
- **前置知识安排**：知识蒸馏（占位）、策略梯度/RLHF（占位）首次依赖处给出占位链接与最小衔接。
- **完成检查**：
  - 说出 Eq.15 每个符号的含义
  - 说明为什么对数比值能表达"教师更认可"
  - 手算学生概率 (0.6,0.4)、教师概率 (0.3,0.7) 时学生采样第一个 token 的奖励符号
- **过渡**：奖励公式有了，但里面有两个工程选择（裁剪、停梯度）没解释——下一章看它们各自解决什么。

### S3：裁剪和停梯度让奖励信号稳定可控

- **主要教学问题**：$\text{sg}$ 和 $\text{clip}$ 各自解决什么问题，去掉会怎样？
- **对应范围**：Q3；C4、C5、误解 M2、误解 M3。
- **正文要点**：
  - $\text{sg}$ 的作用（C5）：把整个对数比值当作常数，教师冻结，奖励不参与求导；梯度只通过策略梯度项 $\nabla\log\pi_\theta(y_t)$ 流动
  - 澄清误解 M2："教师梯度回传"是错的，sg 阻断了这条路
  - $\text{clip}$ 的作用（C4）：当学生几乎不采样某 token 但教师高概率时，对数比值会非常大（如 $\log(0.9/0.01)\approx 4.50$），裁剪到 $[-R_{\max},R_{\max}]$ 防止单步更新被极端信号主导
  - 澄清误解 M3：clip 裁剪的是作为奖励信号的对数比值（advantage 副本），不直接限制实际概率比；学生参数更新后概率比可以超过该区间
  - 手算例子（教学示例）：学生 $\pi_\theta(A)=0.01$，教师 $\pi_{\text{teacher}}(A)=0.9$，比较 $R_{\max}=5$（不裁剪，$r\approx 4.50$）与 $R_{\max}=3$（裁剪到 3）的差异
  - 双面性：裁剪在限制极端信号的同时也压掉了部分高信息量的偏差（边界，为 S5 铺垫）
- **讲解材料及职责**：
  - 公式（裁剪的边界代入）展示 $R_{\max}$ 取值对结果的影响
  - 数字例子对照（同一比值、两个 $R_{\max}$）
- **前置知识安排**：策略梯度（占位）已在 S2 引入，本节复用其最小衔接。
- **完成检查**：
  - 说明 sg 阻断了哪条梯度路径
  - 说明 clip 裁剪的是奖励信号还是实际概率比
  - 给出一个"裁剪改变了奖励值"的具体数值情形
- **过渡**：单个 token 的奖励公式和它的稳定化都清楚了——下一章看九个教师如何轮流指导同一个学生。

### S4：九个教师按领域和努力程度轮流指导

- **主要教学问题**：训练样本如何选定教师？学生如何条件化？稠密奖励为什么能像普通奖励一样接入 RL 框架？
- **对应范围**：Q4；C2、C7、C8、A2（与 RLHF 对比）。
- **正文要点**：
  - $(d,e)$ 路由：训练样本携带领域 $d$ 和努力程度 $e$ 标签，选定对应教师 $\pi_{\text{teacher}}^{(d,e)}$（C2）
  - 学生条件化：$\pi_\theta(y_t\mid e,x,y_{<t})$ 把 $e$ 作为输入，同一组参数表达多努力程度
  - 与 RLHF 的对比（A2，最小衔接，前置页占位）：RLHF 用奖励模型给（通常稀疏的）奖励，MOPD 用教师给 per-token 稠密奖励；奖励来源和粒度不同，但都作为策略梯度的 advantage 输入
  - 稠密奖励接入 RL 框架（C8）：per-token 奖励是 RL 框架的标准输入，不需要为蒸馏单独造一套训练栈
  - 复用 partial rollout：稠密奖励不改变轨迹生成与暂停机制，天然兼容长程任务的 partial rollout（C5）
  - 复用 per-token 正则化（K2.5 算法）：稠密奖励可作为该算法的输入，其正则化处理高度陈旧数据（最小衔接，不展开算法内部）
- **讲解材料及职责**：
  - ASCII 图示：9 个教师按 $(d,e)$ 路由到同一学生的训练循环
  - 对照表格：MOPD vs RLHF（奖励来源、粒度、是否需要单独训练栈）
- **前置知识安排**：RLHF（占位）首次依赖处给出占位链接与最小衔接。
- **完成检查**：
  - 说出训练样本如何选定教师
  - 说明学生如何用一组参数表达多努力程度
  - 说明稠密奖励为什么不需要单独训练栈
- **过渡**：机制和集成都清楚了——最后一章看 MOPD 的能力边界。

### S5：MOPD 能做什么、不能做什么

- **主要教学问题**：MOPD 的边界在哪？top-k 是否更好？
- **对应范围**：Q5；C6、C7、误解 M4、裁剪双面性。
- **正文要点**：
  - 必须先有训练好的 9 个教师：MOPD 是两阶段流程的第二阶段（C7），不能凭空产生新能力
  - 学生质量以教师为上限：教师提供奖励信号，学生向教师靠拢，不能显著超越教师
  - top-k 蒸馏无优势（C6、误解 M4）：K3 实验显示 top-k 在收敛速度和最终性能上都没有明显优势；不引用任何具体数值
  - 裁剪的双面性：$R_{\max}$ 在限制极端信号的同时也压掉了部分高信息量偏差
  - 适用条件复述：存在已训练 $(d,e)$ 专家；样本可路由；学生能条件化
- **讲解材料及职责**：
  - 对照表格：MOPD 能做 vs 不能做
- **前置知识安排**：无新前置。
- **完成检查**：
  - 说出 MOPD 是两阶段流程的哪一阶段
  - 说明学生质量为什么以教师为上限
  - 说出 top-k 的实验结论方向（不引用具体数值）
- **过渡**：无（文末章）。
