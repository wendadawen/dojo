MOPD（多教师在线策略蒸馏）

把多个已训练好的专项专家教师的能力合并进一个统一学生模型：学生自己生成 token，对应教师逐 token 用对数概率比作为稠密奖励指导学生更新，整个奖励信号复用已有 RL 框架。

更新于 2026-08-09 · 主要依据 Kimi K3 技术报告 §4.1.3

1. 为什么需要它

  • K3 用 RL 训练了 9 个专项专家（3 领域 × 3 努力程度），分别部署要服务九份模型、需要路由、九种能力不共享。
  • 简单平均九组权重不可行——不同专家在不同数据分布下训练，参数空间没有对应，平均后互相抵消。
  • 需要一个能复用已有 RL 基础设施（partial rollout、per-token 正则化等）的合并方法，而不是为蒸馏另造一套训练栈。

2. 核心直觉

  • 学生自己走，教师逐 token 打分：训练轨迹由学生当前策略生成（这是"on-policy"的来源），教师只读学生写下的 token 并给出评价，不重写答案。这样学生在自己真实会进入的状态上学习，避免"只学教师走过的路"的暴露偏差。
  • 对数概率比就是奖励：教师分给某 token 的概率高于学生时，对数比值为正；低于学生时为负。这个带符号的标量直接作为策略梯度的 advantage——正奖励让学生增加该 token 的概率，负奖励让学生减小它。学生分布逐步向教师靠拢。
  • 九个教师按 (领域, 努力程度) 轮流指导：每条训练样本携带领域 d 和努力程度 e 两个标签，训练时按 (d, e) 选出九个教师中对应的那一个。学生条件化于 e（努力程度）但不条件化于 d，从公式形式 $\pi_\theta(y_t\mid e,x,y_{<t})$ 不含 d 可以推断部署时只需用户指定努力程度、不需要领域路由器（注意这是基于公式形式的推断，K3 报告未明文陈述该部署设计意图）。
  • 稠密奖励无缝接入 RL 框架：per-token 奖励是 RL 框架的标准输入，所以 partial rollout、per-token 正则化等已有组件可以原样复用，不需要为蒸馏单独造训练栈。

3. 关键结论与边界

  • 两阶段流程的第二阶段：9 个专家必须先由 RL 训练好并冻结，MOPD 是其后的合并阶段。它不能凭空产生教师没有的新能力。
  • 学生质量以教师为上限：奖励信号推动学生向教师靠拢，但学生不会显著超越教师。要超越教师需要的是真正的 RL 探索（带任务奖励），不是蒸馏。
  • 裁剪和停梯度是稳定性的关键：停梯度 sg 把对数比值当常数，梯度只走策略梯度项（教师不回传梯度）；裁剪 clip 把极端奖励信号限制在 $[-R_{\max}, R_{\max}]$，防止单步更新被极端 token 主导。裁剪的是奖励信号本身，不是实际概率比。
  • top-k 蒸馏无优势：K3 还实验了更精细的 top-k 蒸馏目标，但在收敛速度和最终性能上都没有明显优势——per-token 对数比值已经抓住了关键信号。这个结论只针对 K3 的设置（报告未给出具体数值）。
