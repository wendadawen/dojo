# 计划文件

`research/dataflow.md` 先写页面信息、资料、前提和 `config.json` 面板，然后每张图各写一节。生成器直接读这份文件生成页面，页面上的文字都要先在这里写好。

## 页面信息

```markdown
# <模型名>

- 描述：<一句话，纯文本>
- 摘要：<首页卡片上的一两句>
- 主题：<从固定大类里选，逗号分隔>

## 资料

- <源码：仓库、版本、文件>
- <config.json：从哪里取的>
- <权重文件头：从哪里取的>
- <论文或技术报告>

## 前提

- <推理还是训练>
- <加载精度>
- <注意力实现>
- <缓存>
- <输入，如传了哪些、有没有 padding>

## config.json

| 组 | 名字 | 值 |
|---|---|---|
| <分组> | <配置名> | <值> |
```

## 每张图

```markdown
## <类名>.forward（<源码文件>:<起始行>-<结束行>）

### 节点

| id | 类型 | 第一行 | 第二行 | 第三行 | 源码 |
|---|---|---|---|---|---|
| <id> | 算子 | <源码里的调用> | <形状变化> | <权重、配置、公式或说明> | <文件>:<行> |
| <id> | 张量 | <变量名> | <数据类型和形状> | <运行时维度的字母含义，没有就空着> | <文件>:<行> |
| <id> | 缓存 | <变量名> | <存的是什么> | <怎么写、怎么读> | <文件>:<行> |

### 连线

- <id> → <id>
- <id> → <id>：<线上的字>
- <id> 点开 → <另一张图的标题>

### 面板

| 组 | 名字 | 值 |
|---|---|---|
| 公式 | <名字> | $<公式>$，<每个符号是什么> |
| 配置 | <配置名> | <值> |
```

## 写法

- 描述和摘要写这个模型的前向在算什么。描述、摘要和前提都不写页面怎么组织，例如「本页共有 N 张图」「下面先看第一张」。
- 前提只定一条主路径，写明这条路径是什么。前提里的每一条都是这次前向的计算条件（输入、精度、走哪条分支）。
- 同一张图里不要把互斥的两条分支各画一遍（例如 prefill 和 decode）。前提之外的分支不画，也不在节点里逐个说明。
- 差别只影响缓存怎么写时，写在缓存节点的第三行，不写在算子上。算子只写这次前向实际做的那一步。
- 前提由生成器显示在 `config.json` 面板顶部，不必再写进配置表。
- 不把 `if`、比较和 `for` 本身画成节点。选中的那条计算直接画出来。
- 资料只写仓库、版本和文件路径，不写本机路径。拿不到权重文件头时，在资料一节写明形状来自 `config.json` 和源码里的构造函数，并写明未经权重头复核。`sources/` 下只放这两样：`config.json` 副本，拿得到权重形状时再加 `shapes.json`。源码不拷贝。
- 第一张图是整个模型，从输入画到输出。
- 结构相同的层画成一个节点，第一行写 `<层数> × <类名>`，各层的差异写在第三行。
- 前向用到的、模型源码里自己定义的类，每个都画一张，用到它的节点都点开到这张图。哪些类单独成图按这一条判断，类的名单不写进前提。PyTorch 自带的模块（如 `nn.Linear`）和普通函数不单画。
- 源码文件名和行号只写在标题和「源码」列里，给审查者核对用；节点的三行和面板里不写。
- id 用英文，同一张图里不重复。不同图里同一个 id 指同一个量。不是同一个量就换一个 id。
- 类型有三种：算子、张量、缓存。算子和张量交替出现。算子只有一个输出时，后面接一个张量；有多个输出时，下游用到的每个输出各接一个张量，没用到的写在算子第三行。缓存不参与这组交替，按读写接在对应的算子旁边。形状相同、总是一起用的一对量可以合成一个张量节点。合成后的节点第二行写数据类型和形状，个数写在形状后面，如 `bf16 [B, T, d] × 2`。
- 算子：第一行是源码里的调用或表达式。合并的层节点第一行不按这条，按上面「结构相同的层」那一条，写 `<层数> × <类名>`。第二行是形状怎么变。第三行这一格里写权重名和形状、用到的配置、公式或一句说明，可以写两三句，单元格里用 `<br>` 换行。
- 张量：第一行是源码里的变量名，没有变量名就写产生它的表达式；第二行是数据类型和形状，维度写 config 里的数字。运行时才知道的维度用字母。B 是批大小，T 是序列长度。另用别的字母时，在它第一次出现的节点第三行写明含义。同一种维度全文只用一个字母。
- 缓存画成圆柱，放在数据流中间：写进去的张量连到它，读出来的张量从它连出。读写发生在被合并成一个节点的那些层内部时，连线接到这个层节点。
- 名字照源码写，不用推理框架里的类名，也不自己起名。源码里这个量叫什么，节点和公式里就写什么。
- 用到的张量都要连线。作为参数传进算子的，在这个张量和该算子之间连线。算子只用到某个张量的形状或 dtype、没有把这个张量传进去时，也连一条线到这个算子，线上写明用了什么。
- 配置只写用到的，值照抄 `config.json`；用的是代码默认值的，注明「默认值」。
- 公式用 `$...$` 写。公式里的每个符号都要说明是什么，写在公式后面，如「$y=Wx$，$y$ 是输出，$W$ 是权重，$x$ 是输入」。同一个符号不能同时指源码里两段不同的量。符号说明接在公式后面，写在面板表的「值」列。
- 表格单元格里的竖线写成 `\|`，绝对值写成 `\lvert ... \rvert`。
