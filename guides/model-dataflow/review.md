# 审查

## 每轮怎么审

1. 派 20 个没参与写 `research/dataflow.md` 的审查者，彼此看不到对方的结果。用独立的 `tclaude -p` 进程，不用当前会话里的子代理。20 个一次全部放进后台，不要分批 `wait`。每条命令用 `perl -e 'alarm 1200; exec @ARGV'` 包住，到 20 分钟自己停。审查者禁止改文件，`--disallowedTools` 只列 `Edit Write NotebookEdit`。
2. 20 个审查者拿到同样的东西：`dataflow.md`、`guides/model-dataflow.md`、`guides/model-dataflow/plan.md` 和本文件。资料按 `dataflow.md` 里「资料」一节自己去取。不给作者的推理过程，也不给之前几轮的审查结果。
3. 每个审查者自己读资料，核对 `dataflow.md` 的全部内容：
   - 在「前提」这条路径上，源码里的每一步都画了，没有画源码里没有的；
   - 节点的名字、形状、源码位置对得上；
   - 连线接的是真正产生这个数据的节点；
   - 公式和配置值对；
   - 措辞通顺，没有歧义。
4. 每个问题写清位置、问题、依据（源码哪一行或资料哪一处）、改成什么，并标明是事实错误还是措辞。
5. 每个审查者最多等 20 分钟，由第 1 条的命令到时自己停。到时还没返回的，审查记录里写「超时，未计入」。进程还在跑时，不要因为输出还少就停掉。进程已经退出、没有写出结论的，这一席没有结论。20 个都没写出结论，或返回的人少到看不出有没有事实错误，才重派这一轮。不为了补齐人数重派。派之前的检查见 model-dataflow.md 第 3 步，没通过就回到第 2 步改完再派，不算重派。

## 什么时候通过

事实错误是：和源码或资料对不上，前提那条路径上漏了一步或多画了一步，连线接错，公式或数字算错，同一页前后矛盾。下面几种都算多画了一步：前提里写了不止一条路径；把 `if`、比较、`for` 画成节点；在算子或公式里写前提之外的分支。只影响缓存怎么写的差别，按 plan.md 写在缓存节点的第三行，不算多画。算子第二行没有写出源码里那一步对形状的改变，算漏了一步。公式里同一个符号对应源码里不同的量，算公式算错。不同图里同一个 id 指了不同的量，也算事实错误。

返回了结果的审查者都没有事实错误，这一轮就通过。返回的人少到看不出有没有事实错误时，按第 5 条重派，不按本条通过。措辞问题记下来，作者按类扫一遍，不为此再开一轮。

有事实错误的，作者对照源码改完，把改法写进审查记录，然后生成页面。改的时候以源码为准，不照搬审查者写的改法。审查结论已经返回、并据此改完的计划，不再为复核另开一轮。整条路径重画时回到 model-dataflow.md 第 2 步重写计划，再按第 3 步重新派一轮。除了这种整条重画，重派只用于第 5 条说的结论不够。

## 怎么改

- 先判断每个问题属于哪一类（如公式符号没说明、同类节点写法不一致），把全文同类的地方一次改完，不只改被指出的那一处。
- 新写进去的内容和初稿一样，对照源码核实。
- 生成页面前，描述、摘要或前提里如果还在讲页面怎么组织，先按 plan.md 改掉。
- 改完用 model-dataflow.md 第 3 步那条命令再查一遍源码位置，然后生成页面。

## 审查记录

每轮一个文件 `research/review-{轮次}.md`，从 1 开始编号：

```markdown
# 第 N 轮

## 审查者 1

- 事实错误｜位置｜问题｜依据｜改成什么
- 措辞｜位置｜问题｜依据｜改成什么

## 审查者 2

……

## 审查者 20

## 修改

- 每个事实错误怎么改的
- 措辞按哪几类扫过
```

没有问题的审查者写「无」。超时停掉的写「超时，未计入」。
