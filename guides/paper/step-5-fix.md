# 阶段 5：修复、复验与发布

本阶段根据 `research/review.md` 修复页面，由原审查者对修复点复验；发布条件满足后自动发布。

## 1. 输入与自动处置

```text
wiki/<name>/
├── index.html
└── research/
    └── review.md
```

开始处理前核对 `review.md` 每个问题的级别、位置、问题、修法齐全，并按结论自动路由：

- `进入修复`：继续本阶段
- `需改变研究范围`：自动返回阶段 1，并重新执行阶段 1–5
- `需改变教学大纲`：自动返回阶段 2，并重新执行阶段 2–5
- `自动流程失败`：停止且不发布

## 2. 修复

- 按阻断、重要、轻微的顺序处理；同一根因导致的多个问题可以合并修改，但不合并或删除原问题行
- 每条问题修复后，在该行回填：`修复：已改，<一句话说明改动>`；决定不修的轻微问题回填：`修复：不修，遗留，<接受理由>`
- 修复不得引入范围外的新核心内容；发现新的范围问题时自动返回阶段 1，发现新的大纲问题时自动返回阶段 2
- 修改涉及论文数字或论断时，重新对照原文核对定位；涉及声称可运行的代码时，重新执行并核对输出；修改完成后运行一次 `.dojo/scripts/validate.py`

## 3. 复验与失败条件

将全部已修复问题交回原审查者复验。优先恢复同一审查上下文；无法恢复时用全新独立上下文，并把 `review.md` 作为其输入。

审查者按任务包的复验规则逐条回填“复验”字段。修复者不回填“复验”字段。

局部修复最多 2 轮。第二轮后仍有未关闭的阻断或重要问题时，标记为 `自动流程失败`，停止且不发布。

## 4. 自动发布条件

以下条件必须全部满足：

- 独立审查有效，阻断和重要问题全部关闭
- 遗留轻微问题逐项写明接受理由
- `.dojo/scripts/validate.py` 退出码为 0
- 每个声称可运行的代码块已重跑，实际结果与页面描述一致
- 关键论断和数字已重新对照固定版本的论文原文
- `content.json` 中条目 ID 和路径无重复，目标页面存在

## 5. 发布

发布条件满足后自动执行：

1. 更新仓库根目录的 `content.json`
2. 从仓库根目录运行 `python3 .dojo/scripts/generate_index.py`，检查命令成功退出
3. 检查首页条目标题、描述和链接目标，从首页实际打开论文页确认正常加载
4. 只删除本次运行在明确临时目录中创建的 PDF、TeX 源码和图片源文件；不得删除用户提供的原始输入
5. 将发布结果追加到 `review.md` 末尾：

```markdown
## 发布记录

- 最终页面版本：<commit 或工作树哈希>
- content.json 更新：<条目 id>
- generate_index.py：退出码 0
- 首页检查：<条目、链接和页面加载的实际结果>
- 时间：<日期和时间>
```

任一发布条件不满足时不得更新 `content.json` 或首页。
