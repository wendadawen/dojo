# Paper 阶段 3：质检

由独立子代理审查初稿，修复并复验，通过后发布。本阶段只发现和修复问题，不改变已确定的范围与大纲。

## 1. 独立审查

审查者为未参与初稿生成、未参与当前轮次修复的全新上下文，输入只有 `index.html`、`overview.html`、论文原文和本文件。审查子代理必须使用当前环境可用的强推理模型，不得使用轻量模型——弱模型作为审查者难以发现生成者的错误，审查会形同虚设。

无法创建独立上下文的子代理时，流程失败且不发布。

派发方式：为审查者开启全新会话或子代理（使用支持独立上下文的子代理/子任务机制），首条消息给出：

1. 本文件路径 `guides/paper/check.md`
2. 待审论文目录名
3. 论文原文的获取方式
4. 一句话指令：执行本文件的审查任务包，只读取允许的输入文件

编排者不得向审查上下文转发作者的推理记录、修复意图或研究产物。审查期间编排者不改动两份文档。

审查分两段，顺序执行：

段 A 盲读：扮演完全小白读者，按页面顺序阅读，记录理解主线上的卡点。判断依据只能是页面实际提供的信息，不用自身领域知识替页面补全。记录首次出现但无法解释的术语、使用前没有讲解的基础知识、不知道解决什么问题的公式、推理跳步、例子输入未说明变化、折叠块收起后无法理解的位置、可能形成错误结论的类比、不知道为什么继续的章节切换。

段 B 对照原文：通读论文原文，逐条核对页面表述与原文一致性。核查项：

1. 数字与论断：核心论断逐条对照原文，检查表述是否一致、是否扩大原文结论、实验条件是否随数字给出
2. 实验覆盖：纳入范围的实验对比基线是否完整呈现，论文中影响结论解读的实验限制是否被省略
3. 公式与推导：复算核心公式、推导关键步骤和数字例子；符号首次出现处是否有定义、全文含义是否一致
4. 可运行代码：每个声称可运行的代码块提取并实际执行，核对输出与页面描述；涉及网络、凭据、文件删除或长时间训练的代码改为静态审查并记录原因
5. 事实与推断：论文事实是否有可定位的原文依据；解读者推断是否明确标记；评价章节是否越界写成论文结论
6. 原图：与正文对应、Figure 编号准确、解释段如实描述
7. 前置知识引用：概念页链接有效、页面存在、链接层级正确；缺失的概念页有占位提示
8. 教学简化：省略、理想化是否说明，是否导致核心结论失真；类比是否只解释已声明的局部关系
9. 页面功能：公式渲染、折叠交互、目录锚点（浏览器实际打开为准；机械项以 validate.py 结果为准）

## 2. 分级问题

产物写入 `research/review.md`，每个问题一行，格式：级别、来源、位置、问题、修法、修复、复验。

- 阻断：导致核心结论错误、页面无法使用或完全小白无法继续理解。方法定义或核心机制与原文不符；核心公式、推导、数字或代码行为错误；原文不支持页面的关键论断；基线选择性呈现；教学简化导致核心结论失真；正文主线只能依靠展开折叠块才能成立
- 重要：不会立即使核心结论失效，但造成明显误解、认知跳步或重要内容缺失。术语首现解释不足；推导省略关键步骤；章节顺序使读者依赖未讲解内容；重要适用条件或误解未说明；实验数字缺少关键条件；事实与推断混淆
- 轻微：不影响核心正确性和主线理解，但降低阅读质量或维护性

严重度由问题对核心问题回答、与原文一致性和阅读连续性的影响决定，不由修改工作量决定。

## 3. 修复与复验

修复者逐条处理问题并在 review.md 回填修复字段。修复遵循最小化原则：只改问题点及受其直接影响的引用位置，不顺手重构、不引入新内容、不合并或删除原问题行。修改涉及论文数字或论断时重新对照原文；涉及代码时重新执行；修改完成后运行一次 validate.py。

将全部已修复问题交回原审查者复验，回填复验字段。复验只检查修复点本身及直接影响的引用位置；结论写通过或失败（一句话原因）；失败时追加轮次痕迹。局部修复最多 2 轮，第二轮后仍有未关闭的阻断或重要问题时，流程失败且不发布。

需要改变研究范围或教学大纲的问题，不逐条修复，返回规划阶段重新执行。

## 4. 发布门控

以下条件必须全部满足：

- 独立审查有效，阻断和重要问题全部关闭
- 遗留轻微问题逐项写明接受理由
- `.dojo/scripts/validate.py` 退出码为 0
- 每个声称可运行的代码块已重跑，实际结果与页面描述一致
- 关键论断和数字已重新对照固定版本的论文原文
- content.json 中条目 ID 和路径无重复，目标页面存在
- overview.html 存在且与 index.html 互相链接；概念页引用链接全部有效或已标注占位

满足后自动执行：更新 `content.json`，运行 `python3 .dojo/scripts/generate_index.py`，从首页实际打开论文页确认正常加载，只删除本次运行在明确临时目录中创建的临时文件，将发布结果追加到 review.md 末尾。任一条件不满足时不得更新 content.json 或首页。

## 5. 审查任务包

以下内容原样提供给审查子代理：

审查对象只有 `wiki/<name>/index.html`、`wiki/<name>/overview.html` 和论文原文。禁止读取 `research/` 目录、仓库中其他页面、修改两份文档。

段 A 按上述盲读规则执行；段 B 按上述对照核查项执行。

产物写入 `wiki/<name>/research/review.md`：

```markdown
# <论文短名>独立审查

- 审查者：独立上下文（AI 模拟 / 真实目标读者）
- 页面版本：<index.html 工作树哈希>
- 论文版本：<arXiv 版本号或会议版标识>
- 时间：<日期和时间>

## 问题

- [阻断·盲读] <位置>：<问题>：<修法> ｜ 修复： ｜ 复验：
- [重要·技术] <位置>：<问题>：<修法> ｜ 修复： ｜ 复验：
- [轻微·盲读] <位置>：<问题>：<修法> ｜ 修复： ｜ 复验：

## 结论

- 统计：阻断 X / 重要 Y / 轻微 Z
- 处置：进入修复 / 需改变研究范围（说明） / 需改变教学大纲（说明） / 可发布 / 自动流程失败（说明）
```

每个问题一行；级别与来源标头齐全；位置和问题具体到章节或元素；修法必须是可检查的要求，不写"不够清晰""建议补充"一类无法复验的意见。需要改变范围或大纲的问题不逐条列出，在结论的处置项中说明。

审查者是 AI 时，盲读属于小白视角模拟审查，可作为可读性质量信号，但不单独证明页面已被真实小白理解。
