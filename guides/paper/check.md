# 论文页质检

质检用于核对论文解析的正确性、完整性和可读性，不改变已经确定的内容范围和文章大纲。

## 1. 审查轮次与独立性

执行三轮全量审查。每轮由一个独立上下文的审查者完成，审查者未参与写作，也未参与前序轮次的审查与修复。

每轮派发一个新的子代理作为审查者，首条消息只给出：待审页面路径、论文原文的获取方式、本质检规范的路径，以及一句指令——按本规范审查，只读取规范允许的输入。不得向审查者转发写作过程的推理记录、修复意图或规划产物。

当前环境无法派发子代理时，说明当前执行者本身就是子代理，此时不得由写作者自审代替。把审查责任交回编排者：向上层返回页面已完成写作、待独立审查的状态，由编排者派发独立审查者完成三轮审查。返回状态时列出页面路径、论文原文获取方式和已完成的机械验证结果。

每轮审查者仅使用以下材料：

- `wiki/<name>/index.html`
- `wiki/<name>/overview.html`
- 固定版本的论文原文
- 页面明确引用的其他来源
- 本质检规范

审查者不读取 `research/` 中的规划、修复记录和前序审查结果。

## 2. 审查内容

### 2.1 可读性审查

从页面开头到结尾按顺序完整阅读全文，包括折叠块内容。不得用关键词检索抽查代替阅读；检索只用于核对编号、链接、占位符一类机械项。检查：

- 术语是否在首次使用时解释
- 前置知识是否在依赖前给出
- 公式是否说明用途、符号和运算范围
- 推导是否缺少关键步骤
- 示例是否说明输入、变化项和结果含义
- 折叠内容收起后，正文是否仍能建立完整结论
- 类比是否可能产生错误结论
- 章节之间是否存在明确的逻辑衔接
- 核心问题是否都由正文章节完整回答
- 页面级「核心问题」与每个章节的「本章问题」是否每题都有解答折叠块，答案是否独立可读

### 2.2 原文与技术审查

逐条对照固定版本论文，检查：

每条来源论断按以下方式核对，不接受只看页面自身表述：

1. 打开来源，定位到页面标注的位置（章节号、公式号、表号、图号、引文编号或源码路径与行号）。
2. 确认该位置的实际内容支持页面的表述，而不只是编号存在或主题相近。
3. 在审查记录中写下该位置的原文片段或关键数值，作为核对依据；无法给出片段的条目视为未核对。
4. 定位不到、内容不符或来源本身不支持该论断时，删除该论断及其推论，或降级为明确标注的推断；不得改写成模糊表述保留原意。

页面出现的机制描述、归因和引文编号都属于来源论断，包括对某方法作用、动机或效果的陈述。无来源支持的机制描述按上一条处理。

1. **论断与数字**：核心论断、实验数字和成立条件与原文一致。
2. **实验覆盖**：纳入范围的实验与基线完整，没有选择性省略影响结论的结果。
3. **公式与推导**：核心公式、关键推导和数值示例可以复算；符号含义全文一致。
4. **代码**：声称可运行的代码实际执行并核对输出；无法执行时记录原因并改为静态审查。
5. **事实与推断**：论文事实、外部事实和解读判断明确区分。
6. **不确定信息**：版本差异、实现差异和未确认事项具有明确处理结果。
7. **原图**：Figure 编号、图中内容和正文解释相互对应。
8. **页面链接**：前置概念链接有效；缺失页面有明确占位。
9. **简化条件**：省略和理想化条件已说明，且不改变核心结论。
10. **页面功能**：公式渲染、折叠交互、目录锚点和本地资源正常。
11. **公式书写**：数学符号全部由 KaTeX 渲染，标题、summary、正文、列表和表格中无 Unicode 数学字符直接出现；同一变量全页写法一致。
12. **图示**：自绘结构图为 HTML 结构或内联 SVG，无等宽字符框线图；图内公式写在 `<foreignObject>` 中并由 KaTeX 渲染，`<text>` 内无 ASCII 近似写法；图在明暗主题与窄屏下均可读，标签不压线不重叠，节点与箭头含义已定义。
13. **问题块**：页面级「核心问题」与章节级「本章问题」命名正确；两级问题都有解答折叠块，答案独立可读且与正文结论一致；核心问题的答案指明了完整论证所在章节。
14. **格式一致性**：符合 `guides/concept/style-guide.md` 中适用于论文页的规则。

## 3. 问题分级

每轮结果写入 `research/review-{轮次}.md`，每个问题单独记录：

```text
级别｜来源｜位置｜问题｜引文依据｜修复要求｜修复结果｜复验结果
```

引文依据一栏填写核对时看到的原文片段或关键数值。可读性类问题无对应来源时填写"不适用"。

- **阻断**：方法、公式、实验结论或代码行为错误；原文不支持关键论断；页面无法使用。
- **重要**：不会直接推翻核心结论，但会形成明显误解、推理跳步、实验条件缺失或事实与推断混淆。
- **轻微**：不影响正确性和主线理解，但降低表达质量或维护性。

严重度按问题对核心问题、原文一致性和阅读连续性的影响确定，不按修改工作量确定。

## 4. 修复与复验

- 每轮审查完成后逐条修复，并在对应记录中填写修复和复验结果。
- 修改范围限于问题位置及直接受影响的引用位置。
- 论文数字和论断修改后重新对照原文。
- 代码修改后重新运行。
- 每轮修复完成后运行 `.dojo/scripts/validate.py`。
- 下一轮从修复后的完整页面重新开始审查。
- 需要改变范围或大纲的问题返回规划文件处理。

三轮完成后，阻断和重要问题必须全部关闭。仍未解决的阻断问题最多允许两次追加修复；超过限制则停止发布。

## 5. 发布条件

以下条件全部满足后方可发布：

- 三轮审查均已完成，且每轮均由未参与写作的独立审查者执行
- 每条来源论断都有引文依据记录；无法核对的论断已删除或已降级为标注的推断
- 所有阻断和重要问题均已关闭
- 遗留轻微问题具有明确的接受理由
- `.dojo/scripts/validate.py` 返回成功（含数学字符与结构图检查）
- 页面级「核心问题」与每个章节的「本章问题」均有解答折叠块，无只列问题未作答的情况
- 数学符号全部使用 LaTeX 书写，自绘结构图为 HTML 或内联 SVG
- 可运行代码的结果与页面描述一致
- 关键论断和数字已重新核对固定版本论文
- 页面 `<head>` 包含有效的纯文本 `description`、可渲染 `dojo:summary`、`dojo:type=paper`、`dojo:topics`、`dojo:tag`
- `overview.html` 与 `index.html` 相互链接
- 页面引用的概念链接有效，或具有明确占位
- 递归生成的前置概念页已完成各自质检

发布结果记录在最后一轮审查文件中。首页目录和关系图由 GitHub Pages 构建自动更新。

## 6. 审查记录模板

```markdown
# <论文短名>审查记录（第 N 轮）

- 页面版本：<index.html 工作树哈希>
- 论文版本：<arXiv 版本号或会议版标识>
- 审查时间：<日期和时间>
- 审查者：<独立子代理 / 编排者派发的独立审查者>
- 已完整阅读章节：<按顺序列出本轮读完的章节标题>

## 问题

- [阻断·可读性] <位置>：<问题>｜引文依据：不适用｜修复要求：<要求>｜修复：｜复验：
- [重要·技术] <位置>：<问题>｜引文依据：<原文片段或数值>｜修复要求：<要求>｜修复：｜复验：
- [轻微·格式] <位置>：<问题>｜引文依据：不适用｜修复要求：<要求>｜修复：｜复验：

## 结论

- 统计：阻断 X / 重要 Y / 轻微 Z
- 处置：修复 / 返回规划 / 可发布 / 停止发布
```

问题描述和修复要求必须能够复验，不使用“表达不够清晰”“建议补充”等无法判定完成状态的表述。
