# 论文页写作

按规划产物生成完整 HTML 初稿。落实规划中的内容设计，不重新决定内容范围或文章结构；技术正确性和可读性由后续质检确认。

## 1. 输入与写作边界

输入为 `research/` 下的 scope.md、evidence.md、outline.md、glossary.md，以及外壳 `.dojo/templates/paper/index.html` 和组件库 `.dojo/templates/paper/components.html`。输入缺失或规划完成条件未满足时，不得开始写作。不得参考 `wiki/` 下已有页面的写作风格。

必须按 outline.md 落实：页面开头、章节标题和顺序、各章职责、前置知识引用位置、贯穿示例的推进、表达材料及职责、原图选择、正文与折叠块分工、误解和边界的处理位置。

不得自行增删或重排核心章节、增加新的核心问题、更换贯穿示例、改变前置知识映射、把正文必要内容移入折叠块、使用证据不足或无法消歧的论断。

写作中发现缺口时停止相关部分：缺少核心事实、证据或结构时返回规划文件修正；局部连接句、符号说明和计算细节可直接补充。不得用范围外的新内容填补缺口。

## 2. 创建页面

产出以下文档：

```text
wiki/<name>/
├── index.html        # 完整解析（Pages 构建自动发现）
├── overview.html     # 概览
└── research/
    └── draft-check.md
```

```bash
mkdir -p wiki/<name>/research
cp .dojo/templates/paper/index.html wiki/<name>/index.html
cp .dojo/templates/paper/overview.html wiki/<name>/overview.html
```

完整解析外壳提供全部样式、本地 KaTeX/Prism 资源、通用交互和 `<!-- @content -->` 内容插入标记。按 outline.md 从组件库选择组件，复制到插入标记处并替换【…】占位符。大纲未选择的组件不得加入页面。本地资源路径相对于页面解析（`wiki/<name>/` 下的页面引用 `../../libs/`）。

论文 PDF 与 TeX 源码只作临时材料，用完删除，不入库；页面在元信息中给出论文链接。

## 3. 概览

按 overview 模板生成概览文档，写入 `overview.html` 的 `<!-- @content -->` 标记处：

1. 定位摘要：这篇论文做了什么
2. 主要贡献：2–4 项，每项说明相对已有方法的变化
3. 方法概述：概括主要机制，不展开公式与推导
4. 关键结论：最重要的 2–4 个数字或判断，附成立条件

概览面向不了解该领域的读者：首次出现的前置概念给出概念页链接（与完整解析同一份映射），不展开背景。概览不包含公式推导、不包含计算示例、不包含完整实验表格。涉及论文数字时必须与 evidence.md 一致，不确定的标注。

## 4. 写作规则

### 4.1 无领域背景读者

- 正文首次依赖前置概念时给出概念页链接；递归深度上限外登记的缺失概念页放占位提示，正文保留阅读所需的最小衔接，不内联大段背景讲解
- 术语首次出现时给出继续阅读所需的含义和职责，缩写给出全称，与 glossary.md 一致
- 同一段首次引入多个新概念时拆分推进；贯穿示例每次出现时复用已知输入并增加一个新步骤或结论

### 4.2 公式

数学变量、希腊字母、上下标、运算符和关系符一律写为 `$...$` 或 `$$...$$` 交给 KaTeX 渲染，h1/h2/h3、summary、正文、列表项和表格单元格同等适用，不使用 Unicode 数学字符替代（如 `θ_i`、`α_t`、`Σ`、`∂`、`xᵢ`）；同一变量全页保持同一种写法。代码块内的字符按代码原样保留。

公式出现前说明它要解决的问题；出现后解释每个首次出现的符号、下标、范围和运算，以及各部分职责；至少给出一个边界、对称、不变量或简单代入检查。公式依据必须是已确认的 F/C 编号、由已确认公式直接推出的中间式，或明确标记的构造示例。

### 4.3 推导

开始前写明推导目标、已知条件和要得到的结论；一步只完成一个主要变换，关键变换说明使用的规则；不使用"显然""容易得到"代替关键步骤；结论随符号或边界变化时分情况讨论；结束后回到本章问题说明结果解释了什么、不能推出什么。解释核心机制的关键步骤必须留在正文。

### 4.4 数值示例

说明要验证的具体问题；使用能够复算的输入；展示代入、中间结果和最终结果；方向或条件影响结论时提供正反对照。人为设置的数字标记为构造示例并说明构造目的，不得表述为论文的实验数据；论文实验数字引用 N 编号和实验条件。

### 4.5 伪代码与可运行代码

伪代码标明"伪代码"，写清输入、可变状态、核心步骤、输出及与正文公式变量的对应关系；存在循环时写明循环范围和停止条件；不得用 `train()`、`optimize()` 一类未展开步骤替代本节要解释的机制；使用 `language-text` 标记，不标记为可运行语言。

可运行代码包含所有导入、最小输入、变量定义、核心计算和输出语句；核心变量应能映射到正文公式。所有声称可运行的代码必须实际执行，运行失败时不得保留"可运行"声明；运行记录写入 `draft-check.md`。代码后说明验证的机制、简化内容和与真实工程实现的差异。

### 4.6 论文事实、分析性判断与构造示例

- 论文事实：论文陈述的定义、机制、实验数字和结论，附相邻原文定位（§X / Eq.(X) / Table X）或 C/F/N 编号。evidence.md 中不存在的新外部事实必须先补充来源，不能直接写入正文
- 分析性判断：评价和超出原文原句的推理，随文标明或集中在方法评价章节
- 构造示例：人为设置的数字、场景、简化模型和代码输入标记为构造示例并说明构造目的
- 辅助解释：类比、直觉描述标明信息职责及适用边界，不写成论文中的直接结论；类比只解释已声明的局部关系，不能替代正式定义

### 4.7 图示

自绘结构图使用 HTML 结构或内联 SVG（组件库结构 A 表示顺序流程，结构 B 表示层级或阶段堆叠；二维几何、角度、曲线或坐标关系使用内联 SVG），不使用等宽字符拼出的框线图。内联 SVG 设置 viewBox，内部元素使用 `dg-box`、`dg-line`、`dg-accent` 类以跟随明暗主题，不写死颜色值。 SVG 的 `<text>` 使用普通标识，不写 `$...$`（KaTeX 不渲染 SVG 文本），需要公式时放在图注或正文中。每个节点写明输入或计算对象，循环写明返回位置和停止条件；节点与箭头含义在正文或图注中定义。图定位结构，公式负责精确计算。

### 4.8 原图

每张原图按引导句、图片、解释段组织：引导句指出需要关注的结构或数据；解释段如实描述图中内容，说明它支撑哪个结论，不夸大图中信息；图片上方或解释段开头标注原文 Figure 编号。原图用 `python3 .dojo/scripts/img_to_b64.py <图片文件>` 转 base64 内联，不引用临时文件路径。获取途径按 evidence.md 记录的优先级。

### 4.9 正文与折叠块

正文保留核心问题所需的定义、机制和结论，前置概念页链接，会改变结论的条件和限制，必要推导步骤，必要代码观察结果，贯穿示例的关键推进，关键实验数字及其设置。折叠块前说明它补充哪个已陈述结论，折叠块后恢复正文主线；正文不得引用只有展开后才能看到的新结论。折叠块全部收起时，页面仍须完整回答所有核心问题。

### 4.10 问题块

页面开头问题块的 h2 固定为「核心问题」，列出全文负责回答的问题；每个正文章节末尾 h3 固定为「本章问题」，列出该章负责回答的问题。两级都不使用其他措辞。

章节级问题必须作答：每个问题下方紧跟一个 `<details>` 折叠块给出完整答案，summary 前缀固定为 `解答：`。答案独立成段，给出结论、必要推理和成立条件，不依赖读者回看正文即可读懂；只列问题而不作答不允许发布。页面级「核心问题」由正文各章及其解答共同覆盖，不在开头作答。

### 4.11 HTML 要求

页面只有一个主标题 `<h1 class="title">`；标题层级不跳跃；纳入目录的标题显式设置稳定且唯一的 id；代码语言类名与实际语言一致；标签正确闭合；清除全部【…】占位符、`<!-- @content -->` 标记、组件标记和组件说明注释。页面末尾设来源与范围说明，列明核心论断与原文定位、论文事实与分析性判断的区分、构造示例与简化条件及其限制。

## 5. draft-check.md

一页检查记录，全部来自实际检查或运行，不使用推测性记录：

```markdown
# <论文短名>初稿检查

- 输入版本：scope / evidence / outline / glossary 的状态
- 大纲落实：章节、核心问题、前置知识、贯穿示例、误解和边界、评价章节、过渡（逐项一行）
- 代码运行：每个代码块一行——运行命令、退出码、实际输出与页面描述一致；无代码时写明"无可运行代码"
- 原图：每张图一行——原文 Figure 编号、获取途径、浏览器中实际显示正常
- 机械检查：python3 .dojo/scripts/validate.py <页面路径> 的命令和结果
- 公式渲染与交互：浏览器打开后的实际检查结果
- 写作偏差：无 / 偏差内容及处理方式（返回规划 / 局部修正）
```

draft-check.md 是过程记录，不得在其中填写"审查通过"。

## 6. 完成条件

- 输入产物齐全；大纲的全部章节、核心问题、前置知识和验证项均已落实
- 论文事实附原文定位；分析性判断、构造示例和辅助解释均已标记；C/F/N 引用与 evidence.md 一致
- 所有声称可运行的代码已实际执行，输出与页面说明一致
- 原图均已内联并标注 Figure 编号，浏览器中实际显示正常
- 占位符、组件标记和写作注释已清除
- `.dojo/scripts/validate.py` 通过（含数学字符与结构图检查）；公式渲染和页面交互已在浏览器中实际检查
- 全部数学符号使用 LaTeX 书写，自绘结构图为 HTML 或内联 SVG
- 每个章节的「本章问题」均有解答折叠块，答案独立可读
- 折叠块全部收起时正文仍能回答全部核心问题
- draft-check.md 已填写
