# 阶段 3：生成初稿

本阶段依据研究范围和教学大纲生成完整 HTML 初稿。作者落实阶段 2 的教学设计并完成基础可用性检查，不重新决定内容范围或文章结构，不作技术正确性和小白可读性的最终结论（由阶段 4 产生）。

读者默认是完全小白。正文不得要求读者在页面之外补充理解核心问题所需的基础知识。

---

## 1. 输入与输入门槛

```text
wiki/<name>/research/
├── scope.md
├── evidence.md
└── outline.md

.dojo/templates/paper/index.html        # 页面外壳
.dojo/templates/paper/components.html   # 组件库
```

输入产物缺失或研究结束条件未满足时，不得开始写作。不得参考 `wiki/` 或 `wiki/` 下已有页面的写作风格或章节结构。

---

## 2. 产物

```text
wiki/<name>/
├── index.html
└── research/
    └── draft-check.md   # 一页检查记录
```

---

## 3. 写作边界

必须按照 `outline.md` 落实：页面开头、章节标题和顺序、每章主要教学任务、基础知识讲解位置、贯穿例子的推进、讲解材料及职责、原图选择、正文与折叠块分工、常见误解和适用边界的处理位置、每章完成检查和过渡。

不得自行：增删或重排核心章节；增加新的核心问题或核心内容；把已排除内容重新加入；更换贯穿例子；改变基础知识安排；把正文必要内容移动到折叠块；使用证据不足或无法消歧的论断。

写作中发现缺口时停止相关部分写作：缺少核心定义、事实、公式或证据返回阶段 1；章节目标、顺序或教学依赖无法成立返回阶段 2；仅需补充不改变大纲的连接句、符号说明或局部计算时在本阶段补充。不得用范围外的新内容填补缺口。

---

## 4. 创建页面

```bash
mkdir -p wiki/<name>/research
cp .dojo/templates/paper/index.html wiki/<name>/index.html
```

外壳提供全部样式、本地 KaTeX/Prism 资源、通用交互和 `<!-- @content -->` 内容插入标记。页面内容由作者按 `outline.md` 从 `.dojo/templates/paper/components.html` 选择组件，复制到插入标记处并替换【…】占位符。大纲未选择的组件不得加入页面。本地资源路径必须相对于页面位置解析（`wiki/<name>/` 下的页面引用 `../../libs/`）。

论文 PDF 与 TeX 源码只作临时材料：图片内联完成后删除临时文件，不提交仓库；页面在论文元信息中给出论文链接。

---

## 5. 写作规则

### 5.1 完全小白规则

- 正文首次依赖某项基础知识前，必须完成大纲规定的讲解，使读者能够完成对应的解释、判断或计算；不得设置页面外前置知识列表
- 术语首次出现时给出继续阅读所需的含义和职责，缩写同时给出全称，不得用更多未解释术语构成循环定义
- 同一段首次引入多个新概念时拆分推进；贯穿例子每次出现时复用已知输入并增加一个新步骤或结论

### 5.2 公式

公式出现前说明它要解决的问题；出现后解释每个首次出现的符号、下标、范围和运算，以及各部分的职责；至少给出一个边界、对称、不变量或简单代入检查。公式依据必须是已确认的 F/C 编号、由已确认公式直接推出的中间式，或明确标记的教学构造。

### 5.3 推导

开始前写明推导目标、已知条件和要得到的结论；一步只完成一个主要变换，关键变换说明使用的规则；不使用"显然""容易得到"代替关键步骤；结论随符号或边界变化时分情况讨论；结束后回到本章问题说明结果解释了什么、不能推出什么。负责解释核心机制的关键步骤必须留在正文。

### 5.4 数字例子

说明要验证的具体问题；使用能够复算的输入；展示代入、中间结果和最终结果；方向或条件影响结论时提供正反对照。人为设置的数字在例子开头标记为"教学示例"并说明构造目的，不得表述为论文的实验数据；论文实验数字引用 N 编号和实验条件。

### 5.5 伪代码与可运行代码

伪代码标明"伪代码"，写清输入、可变状态、核心步骤、输出及与正文公式变量的对应关系；存在循环时写明循环范围和停止条件；不得用 `train()`、`optimize()` 等黑箱步骤替代本节要解释的机制；使用 `language-text` 标记，不冒充可运行语言。

可运行代码包含所有导入、最小输入、变量定义、核心计算和输出语句；公式中的核心变量应能映射到代码变量；不得使用高级接口隐藏当前章节要解释的机制。所有声称可运行的代码必须实际执行，运行失败时不得保留"可运行"声明；运行记录写入 `draft-check.md`。代码后说明验证的机制、为教学省略的内容和与真实工程实现的差异。

### 5.6 论文事实、解读者推断与教学构造

- 论文事实：论文陈述的定义、机制、实验数字和结论，附相邻原文定位（§X / Eq.(X) / Table X）或 C/F/N 对应关系；`evidence.md` 中不存在的新外部事实不得依靠训练记忆补写，发现此类需求时返回阶段 1
- 解读者推断：解读者的判断、评价和超出原文原句的推理，随文标明或集中在独立评价章节；独立评价章节的内容全部为解读者推断，不写成论文结论
- 教学构造：人为设置的数字、场景、简化模型和代码输入标记为"教学示例"并说明构造目的
- 教学解释：类比、直觉描述标明教学职责及适用边界，不写成论文中的直接结论；类比只解释已声明的局部关系，不能替代正式定义

### 5.7 原图

每张原图按"引导句 → 图片 → 解释段"组织：引导句说明看什么；解释段如实描述图中内容，说明它支撑哪个结论，不夸大图中信息；图片上方或解释段开头标注原文 Figure 编号。

原图用 `python3 .dojo/scripts/img_to_b64.py <图片文件>` 转 base64 内联，不引用临时文件路径。获取途径按 `evidence.md` 记录的优先级：TeX 源码 `figs/` > 官方仓库 > arXiv HTML > PDF 截图（最后手段）。原图仅作个人学习用途的论文解读配图。

### 5.8 正文与折叠块

正文保留：核心问题所需的定义、机制和结论；后文依赖的基础知识；会改变结论的条件和限制；必要推导步骤；必要代码观察结果；贯穿例子的关键推进；关键实验数字及其设置。折叠块前说明它补充哪个已陈述结论，折叠块后恢复正文主线；正文不得引用只有展开后才能看到的新结论。折叠块全部收起时，页面仍须完整回答所有核心问题。

### 5.9 HTML 要求

页面只有一个主标题 `<h1 class="title">`；标题层级不跳跃；所有纳入目录的标题显式设置稳定且唯一的 `id`；代码语言类名与实际语言一致；标签正确闭合；清除全部【…】占位符、`<!-- @content -->` 标记、组件标记和组件说明注释。页面末尾设"来源与教学说明"，列明核心论断与原文定位、核心公式与原文定位、外部数字与实验条件、原图与原文 Figure 编号对应、论文事实与解读者推断的区分说明、教学示例、教学解释和类比边界、教学简化及其限制。

## 6. `draft-check.md`

一页检查记录，全部来自实际检查或运行，不使用"应该通过"一类推测性记录：

```markdown
# <论文短名>初稿检查

- 输入版本：scope.md / evidence.md / outline.md 的 commit 或工作树哈希
- 大纲落实：章节、核心问题、基础知识、贯穿例子、误解和边界、独立评价、过渡均已落实（逐项一行）
- 代码运行：每个代码块一行——运行命令、退出码、实际输出与页面描述一致；无代码时写明"无可运行代码"
- 原图：每张图一行——原文 Figure 编号、获取途径、浏览器中实际显示正常
- 机械检查：python3 .dojo/scripts/validate.py <页面路径> 的命令和结果
- 公式渲染与交互：浏览器打开后的实际检查结果
- 写作偏差：无 / 偏差内容及处理方式（返回阶段 1 / 返回阶段 2 / 局部修正）
```

`draft-check.md` 是过程记录，作者不得在其中填写"技术审查通过"或"小白审查通过"。

---

## 7. 初稿完成条件

- 输入产物齐全；大纲的全部章节、核心问题、基础知识、完成检查和过渡均已落实
- 论文事实附原文定位；解读者推断、教学构造和教学解释均已标记；C/F/N 引用与 `evidence.md` 一致
- 所有声称可运行的代码已实际执行，输出与页面说明一致
- 原图均已内联并标注原文 Figure 编号，浏览器中实际显示正常
- 占位符、组件标记和写作注释已清除
- `.dojo/scripts/validate.py` 通过；公式渲染和页面交互已在浏览器中实际检查
- 折叠块全部收起时正文仍能回答全部核心问题
- `draft-check.md` 已填写
