# 阶段 1：精读与范围

本阶段确定论文解读页的内容范围和事实依据，不设计章节，不决定讲解顺序，不选择贯穿例子，不写 HTML。

读者默认是完全小白，不具备该论文所属领域的基础知识。

---

## 1. 输入与歧义处理

常规输入只有论文链接或 PDF 文件。开始精读前，先获取并固定论文版本：arXiv 论文优先下载 TeX 源码包并确认版本号（v1、v2……），有正式会议版时以会议版为准；无法获取 TeX 源码时用 `pdftotext` 提取 PDF 文本。后续全部论断定位以固定下来的版本为准。

开始精读前，判断是否存在会改变论文定位或主要结论的歧义：论文版本间实质差异（数字、结论不同）、方法名与其他工作同名、论文预印本与会议版内容不一致。

歧义处理状态分为：**已裁定**（正式会议版优先；无正式版本时采用最新可核实版本并记录依据）、**并列呈现**（版本差异与核心问题有关，正文中明确区分）、**无法消歧**（现有可靠信息不足，且不同选择会改变论文定位或主要结论）。存在"无法消歧"状态时，流程失败且不发布。

论文有官方代码仓库时，固定到具体版本或 commit 浏览核心文件，用于核对实现机制；代码只作证据，不构成页面必须覆盖的内容。

---

## 2. 产物

```text
wiki/<name>/research/
├── scope.md        # 内容范围
└── evidence.md     # 核心论断与证据的对应关系
```

`scope.md` 记录讲什么，`evidence.md` 记录核心论断的依据。两者都不预先确定章节结构、讲解顺序或贯穿例子。

---

## 3. `scope.md` 要求

### 3.1 论文定位

- 论文标题、作者、单位、会议或期刊、年份、论文链接、代码仓库链接（如有）
- 一句话说明：论文用 X 解决了 Y 问题，不承担完整教学任务
- 贡献表述：论文宣称的贡献，与原文 abstract 或 contribution 段落一致，不依靠训练记忆补写
- 论文做了什么：每项说明为什么属于本文贡献
- 论文没做什么：容易被误认属于本文贡献的内容，每项说明排除依据（如论文明确声明的 future work、只在附录提及未验证的方向）
- 相邻工作：容易混淆的方法，记录关键区别及是否纳入本页范围
- 版本歧义及处理状态

### 3.2 核心问题

列出 3–5 个读者读完后必须能够回答的核心问题。每个核心问题包括：

```markdown
### Q1：<具体问题>

- 完成答案：读者最终应能说明的内容
- 为什么是核心问题：不理解它会缺失哪部分对论文的理解
- 依赖内容：回答该问题需要哪些定义、机制、实验结论或基础知识
```

核心问题能用完整句子回答，直接对应论文的动机、机制、实验结论或边界，彼此职责不重复。不合格的核心问题示例："这篇论文讲了什么？"（范围过大）、"论文有哪些公式？"（把材料形式误当成学习目标）。

### 3.3 内容分级

- **核心内容**：缺少后会导致至少一个核心问题无法完整回答。每项记录对应的核心问题和必须讲清的结论
- **辅助内容**：不直接构成核心答案，但能消除关键理解障碍或澄清常见误解。每项记录它服务的核心内容或误解
- **扩展内容**：与论文相关但不影响核心问题回答的内容（如次要消融、附录细节、额外基线），每项标记"纳入本页范围"或"排除出本页范围"

内容分级只确定是否属于本页范围及其作用，不决定放正文还是折叠块，不决定使用哪种讲解材料。

### 3.4 基础知识

读者默认不具备领域基础知识，理解核心问题所需的知识不得列为页面外前置条件。每项基础知识记录：

- 被哪些核心内容依赖
- 读者继续阅读前需要能够完成的解释、判断或计算
- 需要讲清的范围和不需要展开的范围

基础知识只讲到支撑后续推理所需的程度，不扩展成另一篇完整概念页。

### 3.5 明确不展开的内容

列出本页不展开的内容，每项说明与论文的关系和不展开的原因。合理原因包括：不影响核心问题回答、属于另一独立工作、只影响工程规模。不得仅写"篇幅有限"。

### 3.6 常见误解和适用边界

每个常见误解记录：

```markdown
### M1：<错误理解>

- 错误理解：读者可能形成的具体判断
- 正确结论：可以直接检查的纠正
- 形成原因：论文表述、数字呈现方式、类比或简化容易导致该误解的原因
- 影响：该误解会使哪个核心问题回答错误
```

论文解读特有的常见误解来源：把论文声称的改进当成无条件成立；把相对提升当成绝对数值；把特定实验设置下的结论推广到未覆盖场景；把解读者推断当成论文结论。

适用边界记录：方法解决什么问题、不解决什么问题、结论成立需要哪些条件（数据规模、模型规模、硬件、任务类型）、条件不满足时会发生什么、实验未覆盖哪些场景。

误解和边界必须具体。例如，"接受率提升 12.4%"应继续写明：该数字来自哪个实验设置、对比哪个基线、不意味着所有任务上都有同样提升。

## 4. `evidence.md` 要求

### 4.1 覆盖范围

证据编号（C 论断 / F 公式 / N 数字）只覆盖**核心内容**：核心问题完成答案直接依赖的论断、方法定义、主要机制、核心公式、关键数字、误解纠正结论、会改变适用边界的事实。辅助和扩展内容的事实不需编号，但正文中仍须附原文定位。

主实验结论性数字和关键消融数字必须编号为 N 类核心论断；凡纳入页面范围的实验对比，其基线不得选择性记录——论文表格中列入对比的基线方法，进入页面的必须完整覆盖。

### 4.2 来源选择

| 论断类型 | 首选证据 |
|---|---|
| 方法定义、算法步骤、论文结论、实验数字 | 固定版本的论文原文（§X / Eq.(X) / Table X / Figure X） |
| 论文未写清的实现机制和超参数 | 固定版本或 commit 的官方源码 |
| 预备知识的定义和定理 | 权威教材、原始论文 |
| 相关工作对比结论 | 被对比工作的原始论文，不只引用本文转述 |

源码事实固定到版本或 commit。一般教程、博客、聚合文章仅用于辅助定位，不作为核心论断的唯一依据。

### 4.3 记录格式

来源记录以固定版本的论文为主源，外部来源逐条记录：编号、标题、作者或维护方、年份或版本、URL、具体定位。

每个核心论断记录：

```markdown
## C1：<核心论断>

- 类型：定义 / 公式 / 机制 / 数字 / 实现 / 边界
- 对应范围：Q1、核心内容 K1、误解 M1
- 论断内容：可以被证实或证伪的完整句子
- 证据：论文 §3.2，Eq.(4)；或 S1，第 3 节
- 适用条件：结论成立的条件（实验设置、数据、模型规模）
- 置信状态：已确认 / 存在冲突 / 证据不足
```

"论文提出了 HSD"不是合格论断；"论文 Eq.(4) 用 capped prefix ratio 限制重复记账"才可核查。

### 4.4 冲突与不足

版本间数字不一致、论文公式与官方实现不一致、论文数字缺少实验条件时，不得静默选择一个结论。记录冲突双方、可能原因和处理状态。核心论断、核心公式或关键数字处于"存在冲突"或"证据不足"状态时，不得进入阶段 2。

### 4.5 原图候选

精读时记录可能用于教学的原文图：编号 P1……、原文 Figure 编号、图中内容一句话、可服务的核心内容或教学点、获取途径（TeX 源码 `figs/` > 官方仓库 > arXiv HTML > PDF 截图，截图是最后手段）。本清单只记录候选，选哪张、放哪里由阶段 2 决定。

---

## 5. 研究结束条件

- `scope.md` 和 `evidence.md` 已创建，论文版本已固定并记录
- 已列出 3–5 个互不重复的核心问题，每个问题都有书面完成答案
- 每项核心内容都对应至少一个核心问题；每项基础知识都写明被谁依赖、需要讲到什么程度
- 每个常见误解都有错误理解、正确结论和证据
- 核心论断、核心公式和关键数字均已编号并处于"已确认"状态；纳入范围的实验基线完整
- 原图候选清单已记录
- 不存在影响论文定位、核心问题或主要结论的"无法消歧"项
- 研究产物未包含章节结构、讲解顺序或贯穿例子等阶段 2 决策
