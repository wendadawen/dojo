# 计划

写 `wiki/<name>/research/dataflow.md`。这份文件先写页面信息、资料、前提和 `config.json` 面板，然后每张图各写一节。生成器直接读它生成页面，页面上的文字都要先在这里写好。

## 每张图

```markdown

### 节点

| id | 类型 | 第一行 | 第二行 | 第三行 | 源码 |
|---|---|---|---|---|---|
| <id> | 算子 | <源码里的调用> | <原来的形状 → 变完的形状> | | <文件>:<行> |
| <id> | 张量 | <变量名> | <数据类型和形状> | <运行时维度的字母含义，没有就空着> | <文件>:<行> |
| <id> | 缓存 | <变量名> | <存的是什么> | <怎么写、怎么读> | <文件>:<行> |

### 连线

- <id> → <id>
- <id> → <id>：<线上的字>
- <id> 点开 → <另一张图的标题>

### 折叠

| id | 名字 | 内容 |
|---|---|---|
| <算子 id> | 公式 | $<公式>$，<每个符号是什么> |

### 面板

| 组 | 名字 | 值 |
|---|---|---|

| 配置 | <配置名> | <值> |
```

## 怎么写

- 描述和摘要写这个模型的前向在算什么。第一张图的面板最上面写一组「介绍」：先说这是什么模型（哪一家、什么类型、主干参数量、每个 token 激活多少、上下文多长），再说这套前向的主要构成（注意力、前馈、附带的模块），最后一句说这一页画的是哪一次前向。数字都出自官方资料。
- 前提只定一条主路径，写明这条路径是什么。前提里的每一条都是这次前向的计算条件（输入、精度、走哪条分支）。一次前向实际走到几个分支，就把这几个分支都画在同一张图里，不为每个分支各开一张图。一张图覆盖多个层、各层走的分支不同时，在前提里写清这张图覆盖哪几层、各跑哪一支。
- 前提由生成器显示在 `config.json` 面板顶部。配置表写用到的配置值，值照抄 `config.json`；是代码默认值的注明「默认值」；源码在运行时改写过的，写 config.json 里的原值并注明运行值。
- 同一个类被多处实例化、参数不同时（如同一个 FFN 类既做稠密层又做 MoE 的共享专家），在图里注明两种实例化的差别，别只按一种写。
- 第一张图是整个模型，从输入画到输出。哪些类单独成图：**属于这个模型的模块画，通用基础层不画**。带模型名的前缀一律画（`HYV4Model`、`Qwen2Attention`）；类名通用但有自己的计算的也画（`Indexer`、`Compressor`、`Gate`、`MoE`、`Engram`）；只是把通用算子套在权重上的基础层不画——`Linear`、`ColumnParallelLinear`、`RowParallelLinear`、`RMSNorm`、`Embedding`、`PatchEmbed`、通用 SwiGLU 的 MLP，以及 PyTorch 自带的模块（如 `nn.Linear`）。不画成图的类写在使用它们的节点上。
- 结构相同的层画成一个节点，第一行写 `<层数> × <类名>`，各层的差异写在这个节点折叠的说明里。
- 节点是算子、张量或缓存。算子和张量交替出现；算子只有一个输出时后面接一个张量，有多个输出时下游用到的每个输出各接一个张量，没用到的写在折叠的说明里。缓存不参与这组交替，按读写接在对应的算子旁边。形状相同、总是一起用的一对量可以合成一个张量节点，个数写在形状后面，如 `bf16 [B, T, d] × 2`。
- 一个节点一步。源码一行里套了几层类调用，拆开、一步一个节点（`self.kv_norm(self.wkv(x))` 是两步，`self.w2(F.gelu(self.w1(x)))` 是 `w1` 与 `w2` 两步）。普通函数和方法（`flatten`、`view`、`gelu`、`silu`、`mean`）不跟类调用拆开，跟它作用的那个值留在同一个节点里。残差相加这类算式（`x + self.attn(self.norm1(x))`）把 `+` 单独画成一个节点。拆出来的中间量源码里没有名字，自己起一个，写在前一个张量节点的第一行。
- 算子：第一行是源码里的调用或表达式，写这一个节点做的这一步。合并的层节点第一行写 `<层数> × <类名>`。第二行是形状怎么变，写成「原来的形状 → 变完的形状」，箭头两边都写上完整的形状，不写「同形状」「—」这类占位。第三行留空。折叠写「公式」和「说明」。每个算子尽量写公式，公式只含这个算子自己的计算，符号用源码里这一行已有的变量名和权重名。同一个符号不能同时指源码里两段不同的量。说明放权重形状、配置，以及这个算子要交代的一句话。
- 张量：第一行是源码里的变量名，没有变量名就写产生它的表达式；第二行是数据类型和形状，维度写 config 里的数字，运行时才知道的维度用字母。B 是批大小，T 是序列长度。另用别的字母时，在它第一次出现的节点第三行写明含义；同一种维度全文只用一个字母。一次前向返回的多个值合成一个节点时，第二行写各返回值的形状，写不下就在第三行列出。同一个量在流程里被重新赋值（如 `residual = x`、`x = x + 1`）时，画一个节点，在第三行注明这一步把它变成了什么。
- 缓存画成圆柱，放在数据流中间：写进去的张量连到它，读出来的张量从它连出。第二行写存的是什么，第三行写怎么写、怎么读。
- 点开只连这个节点真的执行过的类：节点里调用过某个要成图的类，就点开到那张图；只取它的权重或形状、没调用它的，不点开（如 `woa = self.wo_a.weight.view(...)` 不点开 `ColumnParallelLinear`）。一个节点只留一条点开，同一个节点调了两个要成图的类时，留折叠里引用的那一条。
- 名字照源码写。源码里这个量叫什么，节点和公式里就写什么。用到的张量都要连线；算子只用到某个张量的形状或 dtype、没把它传进去时，也连一条线到这个算子，线上写明用了什么。
- 两个类重名时（不同文件里都有 `Block`、`Attention`），图标题带模块前缀区分，如 `vision.Block`、`vision.Attention`。
- 算子里直接用到的量都画成节点，不管它是不是权重：`self.weight * x` 里的 `self.weight`、路由的修正偏置、注意力汇点都画。张量的第一行照源码写——是变量名就写变量名，是产生它的表达式就写表达式。只取某个张量的形状或 dtype、没把它当数据用的，不画节点，连一条线到用它的算子并在线上写明。
- 运行时才知道的维度字母，除了在张量第三行说明，也要在前提或面板里交代一次。
- 折叠里的公式写这个算子自己的计算。调用一个成图的类时，被调类的算式在那张图里，折叠里写调用即可；被调的类没有单独的图（基础层不成图）时，在这个折叠里把这次调用的算式写出来。
- 折叠只挂在算子上，名字写「公式」或「说明」，点算子右上角的标记打开。折叠里只引用同图已经画出的张量；同一个源码调用不要在一处画成算子、又在折叠里展开一遍。
- 整张图才用到、对不上单个算子的式子写在面板。面板可以分组：第一张图有「介绍」。
- id 用英文，同一张图里不重复。不同图里同一个 id 指同一个量；不是同一个量就换一个 id。上一个图的输出进到下一个图，这个输入节点用产出它的那个 id，别改名。同一个类里局部重名的量（如各图的 `x`、`norm`）按模块起前缀区分。
- 前提锁定的那条分支，别处不再出现别的分支：算子、公式、说明里都不写前提之外的分支。
- 源码文件名和行号写在标题和「源码」列，给审查者核对，生成器不会写进页面。节点的三行、折叠和面板写计算内容。
- 表格单元格里的竖线写成 `\|`，绝对值写成 `\lvert ... \rvert`；单元格里用 `<br>` 换行。

写完运行 `python3 .dojo/scripts/dataflow/build_page.py wiki/<name>/research/dataflow.md`，报错就改，直到没有报错，再审计划。
