# 计划

写 `wiki/<name>/research/dataflow.md`。生成器直接读它生成页面，页面上的文字都要先在这里写好。

## 怎么写

- 第一张图是整个模型，从输入画到输出。属于这个模型的模块各画一张图：带模型名前缀的（`HYV4Model`、`Qwen2Attention`）画；类名通用但有自己的计算的（`Indexer`、`Compressor`、`Gate`、`MoE`、`Engram`）画；只是把通用算子套在权重上的基础层不画（`Linear`、`ColumnParallelLinear`、`RowParallelLinear`、`RMSNorm`、`Embedding`、`ParallelEmbedding`、`PatchEmbed`、`MLP`、`ParallelHead`，以及 PyTorch 自带的模块）——清单以 `build_page.py` 的 `GENERIC_CLASSES` 为准，脚本会核。白名单以外的通用层（`Conv2d`、`LayerNorm` 这类）按「只是套通用算子」处理，不单独成图。不画成图的类写在使用它们的节点上，用到有图的类的节点都点开过去。
- 一个节点一步。一步是一个动作——算一次打分、写一次缓存、做一次真正的数值计算，各是一步（纯换形状/dtype 的步骤见下一条，不单独成节点）。源码里相邻的几步各画成一个节点，也别把几步并进一个节点：`F.gelu(self.w1(x))` 是一步（一次前馈里套了层激活，不拆）；`kv.unflatten(...)` 与 `(kv * score.softmax(dim=2)).sum(dim=2)` 是两次不同的动作，拆成两个节点。残差相加这类算式把 `+` 单独画成一个节点。拆出来的中间量源码里没有名字，写产生它的表达式（同张量第一行的写法）。
- 结构相同的层画成一个节点，第一行写 `<层数> × <类名>`，各层的差异写在它的折叠说明里。同一个类被多处实例化、参数不同时，注明差别。
- 前提只定一条路径，写明这次前向的计算条件（输入、精度、走哪条分支）。一次前向走到几个分支就画在同一张图里，不为一支单开一张图；一张图覆盖多层、各层分支不同时，前提里写清哪几层跑哪一支。
- 只换形状、换 dtype、切一段的步骤（`reshape`、`view`、`chunk`、`float()`、`.to(dtype)`、`arange`、纯切片）不单独成节点，写进它服务的那一步的折叠里。例外：切出多段、或展开成独立一维、且下游把它当数据用的（如 `kv.split` 切出 key 与 value、`kv.unflatten` 展开成多头），单独成一个算子节点，第二行写变完的形状。
- 节点是算子、张量或缓存，算子和张量交替。算子只有一个输出时后面接一个张量，有多个输出时下游用到的每个输出各接一个张量，没用到的写进折叠说明。缓存按读写接在对应的算子旁边；第二行沿用同一套字母（容量维写清它是容量、不是本次的 `$B$`）。跨层共享的缓存（某几层写、其余层读）画出读写两侧的边，写明哪几层写、哪几层读。形状相同、总是一起用的一对量合成一个节点，个数写在形状后面。
- 算子里直接用到的量都画成节点，不管它是不是权重；只取某个张量的形状或 dtype、没当数据用的不画，连一条线到用它的算子，线上写明用了什么。用到的张量都要连线。
- 名字照源码写。调用的类有图的点开到那张图；只取它的权重或形状、没调用它的不点开。一个节点只留一条点开。两个类重名时图标题带模块前缀（`vision.Block`）。
- 运行时才知道的维度字母（`B`、`T`、`r`、`S` 这类），在它第一次出现的节点上写明含义（张量写第三行，算子写在线上的字或折叠里）。**跨图的同一个字母必须指同一种维度；指两回事就换一个字母**（与「式子里的量都取短符号」一条同一口径）。
- 折叠挂在算子上，三栏：公式、符号、说明。公式写这个算子自己的计算，同一符号不能指两段不同的量；调用的类有图的写调用即可，不成图的（基础层）把这次调用的算式写出来。符号栏列式子里的符号各是什么、源码里叫什么，一个一行。说明栏写权重形状、配置和要交代的话。折叠里只引用同图已经画出的张量，同一个源码调用不要在两处画。
- 套了几层变形的公式（如 RoPE 的 `flatten(view_as_real(view_as_complex(x)))`）不照抄源码，写成读者看得懂的形式（「末 64 维乘一个旋转因子」）；源码那一行写进「符号」栏末尾（说明栏拒收带运算符的式子）。
- 式子里的量都取短符号，照数学惯例：标量斜体小写（`$c$`、`$n$`、`$w$`），矩阵粗体大写（`$\mathbf{K}$`、`$\mathbf{C}$`），索引用下标，函数名正体（`$\mathrm{split}$`）。源码里那个长名字（`window_kv_cache`、`seqlen`）不进式子，写进「符号」栏。符号含义和源码名都在「符号」栏交代；**全页一个符号只指一个量**，两张图里是两回事就换一个字母（如窗口 KV 用 `$\mathbf{K}$`、压缩器的 kv 用 `$\mathbf{U}$`）。
- 面板的「公式」组每条只放**一个式子**，配一句它在算什么（一句话，30 字内，如「查词嵌入」）。一段流水线有好几个式子就分成几条，一条一个；一条里不写「再 …」这种接续。符号明细和推导放进折叠。
- id 用英文。同一张图里不重复；不同图里同一个 id 指同一个量，不是同一个量就换一个 id；上一个图的输出进到下一个图，沿用产它的那个 id。同一个类里局部重名的量按模块起前缀。
- 前提锁定的那条分支之外的分支不写：算子、公式、说明里都不出现。
- 源码文件名和行号写在标题和「源码」列，给审查者核对，生成器不写进页面。

## 每张图

```markdown
## <类名>.forward（<源码文件>:<起始行>-<结束行>）

### 节点

| id | 类型 | 第一行 | 第二行 | 第三行 | 源码 |
|---|---|---|---|---|---|
| <id> | 算子 | <这一步在源码里的调用> | <原来的形状 → 变完的形状> | | <文件>:<行> |
| <id> | 张量 | <源码里的变量名，没有就写产生它的表达式> | <数据类型和形状> | <运行时维度的字母含义，没有就空着> | <文件>:<行> |
| <id> | 缓存 | <源码里的变量名> | <存的是什么> | <怎么写、怎么读> | <文件>:<行> |

### 连线

- <id> → <id>
- <id> → <id>：<线上的字>
- <id> 点开 → <另一张图的标题>

### 折叠

| id | 名字 | 内容 |
|---|---|---|
| <算子 id> | 公式 | $<公式>$ |
| <算子 id> | 符号 | <式子里的符号各是什么，源码里叫什么；一个一行，用 <br> 隔开> |
| <算子 id> | 说明 | <权重形状、配置，或要交代的一句话> |

### 面板

| 组 | 名字 | 值 |
|---|---|---|
| 介绍 | <名字> | <几句话，只写在第一张图：先说这是什么模型（哪一家、类型、主干参数量、每 token 激活量、上下文多长），再说这次前向在算什么> |
| 公式 | <名字> | $<一个式子>$<br><一句它在算什么，不超过 30 字。几个式子分几行 |
| 配置 | <配置名> | <用到的配置值> |
```

表格单元格里的竖线写成 `\|`，绝对值写成 `\lvert ... \rvert`，用 `<br>` 换行。
