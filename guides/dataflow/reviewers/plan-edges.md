# 连线与结构审查者

你审一份数据流计划文件 `dataflow.md`，只回答「连线接得对不对、页面结构自不自洽」。

## 拿到什么

- `dataflow.md`
- 源码（按计划文件「资料」一节自己去取）

## 核这几件事

1. 每条连线接的是真正产生这个数据的节点，方向对。
2. 用到的张量都连了线。作为参数传进算子的要连；算子只用到某个张量的形状或 dtype、没把它传进去时，也要连一条线并在线上写明用了什么。
3. 缓存按读写接在对应的算子旁边；读写发生在被合并成一个节点的层内部时，连线接到这个层节点。
4. 图标题撞名：两个类短名相同（如都叫 `Block`）时，撞名的那几个标题要彼此可区分——至少一个带模块前缀（示范页是 `vision.Block` 对主干 `Block`）。都带前缀最简单；只要点开按名字匹配不会都命中第一张就行。这条靠人看。
5. ※ 机械已核（build_page.py 会直接报错），不用人查：点开的目标是不是某张图的标题、**同一张图里**一个节点有没有挂两条点开（第二条会覆盖第一条，脚本报错）。同一个 id 在不同图里各挂一条点开脚本不拦，但同一 id 跨图指同一个量、点开目标该一致，这条靠人看。你要看的是**点开连得对不对**：点开只连这个节点真的执行过的类：只取某个类的权重或形状、没调用它的，点开过去算事实错误（如 `woa = self.wo_a.weight.view(...)` 只取权重、不调 `forward`，不该点开那个类）。源码里的类是别的东西（如 `nn.LayerNorm`）却点开到某张自绘图，也算事实错误。
6. ※ 机械已核（build_page.py 会直接报错），不用人查：同一张图里 id 是否重复、跨图同一个**张量** id 的形状是否一致。你要看的是**同一个 id 在不同图里指的是不是同一个量**（算子和缓存的 id 脚本不比形状）：一个图的输出进到下一个图，这个输入节点用产出它的那个 id，改名了算事实错误。同一个类里局部重名的量（如各图的 `x`、`norm`）没有按模块加前缀而撞了 id，也要指出。
7. 算子有多个输出时，下游用到的每个输出各接一个张量，没用到的写进折叠的说明。
8. 算子与张量交替。例外有三类：① 多个返回值汇到一个张量（返回值元组节点，如 `oids`、`logits`、`mh` 各自连到 `tret`）；② 算子只用某个张量的形状或 dtype、没把它当数据用（连一条线，线上写明，如 `mx → mout：dtype 与 shape`）；③ 被并入上游算子的纯整形/dtype 步骤留下的直连（如 `mxf → y：view`）。除此之外，算子直接连算子仍算错。违反的逐条指出。（缓存不算，按读写接在算子旁边。）
9. 算子第一行里出现的每个参数，都有对应的输入连线（传进来的张量、或线上注明只用了形状/dtype 的量）；一个参数写成两个输入、或同一个量连了两遍，也算错。
10. 折叠里只引用同图已经画出的张量。同一个源码调用在一处画成算子、又在折叠里展开一遍，算错。

## 返回

每个问题一行：`事实错误｜位置｜问题｜依据｜改成什么`（写法类问题把类别写成「写法」）。位置写到图名和节点 id。依据写源码文件与行号。没有问题写「无」。
