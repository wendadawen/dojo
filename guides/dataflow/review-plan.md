# 审计划

`dataflow.md` 写完、`build_page.py` 跑过没有报错，并且源码位置回查通过之后审。

先运行：

    python3 .dojo/scripts/dataflow/check_source.py <name>.md --source-root <源码目录>

回查「源码」列指的行不是空行或注释、且含节点名。通过后再派 5 个子代理，一次全部派出。它们没参与写这份计划，彼此看不到对方的结果，只返回结论，不改任何文件。每个审查者的提示词在 `guides/dataflow/reviewers/` 下，派的时候把对应文件的全文交给它，再附上输入。

## 谁审什么

| 审查者 | 提示词 | 拿到什么 |
|---|---|---|
| 路径覆盖 | `plan-source.md` | `dataflow.md`、源码 |
| 节点与形状 | `plan-nodes.md` | `dataflow.md`、源码 |
| 连线与结构 | `plan-edges.md` | `dataflow.md`、源码 |
| 公式与面板 | `plan-formulas.md` | `dataflow.md`、源码 |
| 读者与措辞 | `plan-reader.md` | 只给 `dataflow.md` |

## 什么算「必须改」

- **事实错误**：和源码或资料对不上。前提那条路径上漏了一步或多画了一步；连线接错；节点名字、形状、源码位置不对；公式或数字算错；同一页前后矛盾。
- **写法**：形状箭头只写一边；算子第三行没清空；折叠挂在张量上；折叠名字不对；节点 id 在同一张图里重复，或不同图里同一个 id 指了不同的量；面板里对不上单个算子的式子写错。
- **措辞**：通顺、有歧义、术语不统一、介绍没写。

多画了一步是指：前提里写了不止一条路径，把 `if`、比较或 `for` 画成了节点，或者算子或公式里写了前提之外的分支。

每个问题一行：`类别｜位置｜问题｜依据｜改法`，依据只能是源码哪一行或资料哪一处。没有问题写「无」。

## 一轮怎么走

1. 5 个审查者全面审，每轮都从头审，不是只看上一轮改的地方。
2. 作者核实每一条，成立的改 `dataflow.md`，不成立的写出理由。
3. 两个审查者对同一处意见相反时，交给仲裁，见下。
4. 改完重新运行 `build_page.py` 和 `check_source.py`，通过后再派下一轮，5 个审查者重新派。派的时候在每个审查者的输入末尾附一份「已裁定，不要再提」清单：前几轮仲裁裁定「不必改」的意见，以及作者核实后确认资料里没有、不补的点，每条写一句话加理由。审查者不得再提清单里的问题。已经改过的问题不放进清单，改动要重新审。
5. 一轮里 5 个审查者都没有「必须改」的问题，并且作者没有未处理的问题，通过。

## 仲裁

冲突时以源码为准。最多 5 轮，5 轮后还有争议，剩下所有没处理完的意见全部交仲裁。

仲裁是一个独立子代理，拿到 `dataflow.md`、这条意见的原文和作者的理由、`guides/dataflow.md`，按 `guides/dataflow/plan.md` 的「怎么写」判。它只回答：

- 对每一条意见：「必须改」或「不必改」。
- 依据：只能引源码的具体位置或 `guides/dataflow/plan.md` 的条文。引不出依据的，一律「不必改」。
- 它只裁已有的意见，不提新意见，不写内容，不改计划。

判「必须改」的条目，作者改完后，仲裁再核对这次改动是否符合它的裁定，不符合就重改。

**最后一批改动也要核对。** 到了轮数上限，最后一轮之后作者做的所有修改，无论是仲裁判「必须改」的，还是作者自己判成立的，都要交仲裁核对一次。核对只回答两件事：这些改动有没有引入源码里没有的内容、漏步或多步、接错线；有没有违背前几轮的裁定。它不全面重审，也不提新意见。核对通过，计划通过；不通过的，作者只改被指出的地方，再核对一次。

## 记录

每轮写 `wiki/<name>/research/review-<轮次>.md`，轮次从 1 开始，按审查者分节写他们的问题，最后一节「修改」写每个问题怎么处理的，仲裁的结论也写在里面。

```markdown
# 第 N 轮

源码位置核查通过：<节点数> 个节点。有结论的席位 <n> 个。

## 审查者 1

- 事实错误｜位置｜问题｜依据｜改成什么

## 审查者 2

……

## 修改

- 每个事实错误怎么改的
- 措辞按哪几类扫过
```

没有问题的审查者写「无」。结束这一轮时还没返回、或返回了没写结论的，写「未计入」；有结论的席位少于 4 个，或不足以判断有没有事实错误时，5 席全部重派，轮次号不变。
