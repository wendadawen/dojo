# 前向数据流

适用于把模型的逐层前向路径写成可查的页面：每个模块的输入输出、张量形状、关键公式，以及这些数字的出处。

本流程与 `guides/note.md` 分开：note 只归档已经确认的结论，本流程要做的是一层层把路径推出来，期间会产生新的推导与新的实测，属于生产而不是归档。

## 目标

生成 `wiki/<name>/index.html`，读者能顺着它把一次前向从输入走到输出，并在任意一个模块上查到形状、公式和依据。

本流程产出**单文档**，不生成 `overview.html`——数据流要顺着读，概览页会把路径截断。

## 材料

写之前先取得三类材料，缺哪类就说明缺哪类：

- 官方配置（`config.json` 一类）：层数、隐藏维、专家数、比例表等结构参数的正本
- 官方源码：模块的实际执行路径、张量维度、算子的调用顺序
- 权重索引或检查点头：确认某一层实际存在哪些张量、它们的形状

配置与源码对不上时，以源码为准并在页面里写明分歧；二者都支持的结论才算已确认。

## 内容

- 按执行顺序组织，不按论文的章节顺序。每一段是「上一步的输出经过什么变成下一步的输入」。
- 每个模块标注：输入形状、输出形状、关键参数、主要步骤。形状用 `$...$` 写成张量记号。
- 关键算子给出公式，并说明公式里的下标与形状怎样对应。
- 压缩、共享、分块一类的机制，要说明它作用在哪一维、压缩比从哪来、解压或还原发生在哪一步。
- 同一份数据被多路复用时，画出它的流经路径，不要只写「被 N 处使用」。

## 实测

页面上的数字分两类，必须分开陈述：

- 从官方材料读到的（报告、配置、源码）：注明位置
- 本机跑出来的（脚本、形状 dump、数值对照）：注明脚本与结论

本机实测要做交叉断言，不能只跑一遍就写：结构参数与官方配置对、张量形状与权重索引对、算子语义与源码对。三者不一致时先查清楚再写。

实测脚本与运行输出不随仓库分发，清单记在 `research/measured.md`；页面正文引用实测结论时写清「实测得到」而不是指向已移除的文件路径。

## 视图

数据流页允许用交互视图承载多条路径（编码器/解码器、不同压缩模式、prefill/decode 等）。

- 每个视图只表达一条完整路径，视图之间不共用中间状态。
- 交互只在降低阅读成本时使用；默认视图必须是首屏可读的主干。
- 脚本失效时页面仍要能读：视图内容写在 HTML 里，脚本只负责切换显隐。
- 视图切换不能改变页面正文的结论，正文在任何视图下都成立。

## 事实核查

- 形状、层数、比例、超参在写入前用官方配置或源码复核。
- 数值结论实际跑过再写；跑不了就标为未核实。
- 从报告读到的数字标注报告的节次或行号。

## 表述

与 concept 页同一套规范，另加：

- 不写「本页将展示」「下面我们来看」一类的引导语，直接进入路径。
- 不把调试过程写进正文；只留结论与依据。
- 图的标题说明它表达什么关系，不复述正文。

## 发布前检查

- 每个形状都能在源码或权重索引里找到对应。
- 每个实测数字注明了脚本与运行条件。
- 交互视图在无脚本时仍可读。
- 含图或公式的页面在无头浏览器实测过渲染。
- `.dojo/scripts/validate.py <页面路径>` 通过。

## 发布

使用 `.dojo/templates/dataflow/index.html`，替换全部占位符和 `<!-- @content -->`，样式引用 `../../libs/dojo-dataflow.css`，本页特有的视图样式写在页内 `<style>` 里。
