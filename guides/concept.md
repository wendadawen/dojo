# Concept：把技术概念变成可浏览的学习页面

当用户说“学习/讲清楚某个概念”并希望留下一篇页面时，执行本场景。

## 目标

产出一篇从“为什么需要它”出发、逐步建立机制理解的 HTML 页面。不是术语百科，也不是资料拼贴。

## 执行

1. 明确概念的边界：它是什么、不是什么、解决什么问题。
2. 阅读 `guides/concept/_flow.md`，完整执行它指向的五阶段流程。
3. 先讲为什么，再讲是什么；从最小必要前置知识开始，一次只引入一个新变量。
4. 核心机制至少包含一个可手算的例子；代码只有在能帮助理解且实际跑通时才加入。
5. 事实、公式与机制必须核对可靠来源；不确定就明确说明。
6. 完成独立审查、修复和机械验证后，才更新 `content.json` 与首页。

## 交付

- `wiki/<name>/index.html`
- 更新后的 `content.json` 和 `index.html`
- 对用户只说明：生成位置、读完能回答的问题、验证结果。

不要自动 commit、push 或部署。
