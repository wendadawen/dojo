# 技术概念页面

适用于需要生成技术概念说明页面的任务。

## 目标

生成一篇面向无领域背景读者的完整说明页面和一篇概览页面。完整页面从问题背景进入定义与机制；前置知识引用已有概念页，缺失时递归生成，最大递归深度为 2。

## 执行

1. 明确概念的边界：它是什么、不是什么、解决什么问题；处理名称歧义。
2. 依次执行规划、写作和质检规范：`guides/concept/plan.md` → `guides/concept/write.md` → `guides/concept/check.md`。
3. 先说明问题背景，再给出定义；新概念按依赖顺序引入，避免在同一段集中增加多个未定义术语。
4. 核心机制至少包含一个可手算的例子；代码只有在能帮助理解且实际跑通时才加入。
5. 事实、公式与机制必须核对可靠来源；不确定就明确说明。
6. 前置概念缺失时按同一规范递归生成；递归深度最多 2 层，更深层仅记录缺口。
7. 质检的三轮审查必须由未参与写作的独立审查者执行。无法派发子代理时，向上层返回待独立审查状态，由编排者派发审查者，不得自审代替。
8. 完成独立审查、修复和机械验证后，确认页面 head 中的首页元数据已替换完成；首页由 GitHub Pages 构建自动发现。

## 交付

- `wiki/<name>/index.html`（完整说明，Pages 构建自动发现）
- `wiki/<name>/overview.html`（概览）
- 页面 head 中完整的首页元数据
- 交付说明仅包含生成位置、页面入口、学习目标、验证结果、已知边界和递归生成的前置概念页。
