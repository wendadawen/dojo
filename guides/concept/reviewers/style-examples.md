# 文风例子库

文风审查者只报能对上本库某一类坏句式的具体句子。对不上的不报，和反例同类的不报。

每类写「坏句子 → 为什么坏 → 改后」。句子取自仓库历史里真实删掉的句子和审查报出的句子。新发现的坏句式，读到一处就补一条，同类近似的合并，总数保持在 30 条以内。

## 坏句式

**1. 讲页面自己，预告结构**

- 「本文要回答：Full AttnRes 的公式是什么、Block AttnRes 如何把内存从 $O(Ld)$ 降到 $O(Nd)$……」→ 在介绍这一页，没有讲概念 → 删掉，直接讲。
- 「这个确定性带来两条工程上的后果。」→ 只预告后面有几条 → 删掉，直接写两条。
- 「Engram 不插在每一层。插在哪几层，与稀疏参数怎么分给记忆和专家，是两个分开定的问题。」→ 预告下文要讲什么 → 删掉。

**2. 带读者走流程，指向别处**

- 「下面先看 MHA 下 KV cache 是怎么来的——这能让本页看清楚 MLA 到底压缩了什么。」→ 在说本页的安排 → 直接写 MHA 下 KV cache 怎么来。
- 「先看注意力计算到底依赖哪些数据。」→ 带路词，没有信息 → 直接写依赖的数据。
- 「这个区分是本文最常见的误解之一，后面……一章会再用……印证。」→ 指向后文，没有当下的内容 → 删掉。

**3. 声明范围和依赖，免责**

- 「本文依赖前置概念残差连接，只使用其结论；softmax 与 RMSNorm 作为公式零件使用，不展开为独立概念页。」→ 在交代写法，不是概念内容 → 需要的词在第一次出现时解释或链接，其余删掉。
- 「可推出：AttnRes 公式的理解。不可推出：softmax 的变体、RMSNorm 的推导。」→ 审计腔，不是讲概念 → 删掉。
- 「其解析页将从本页的概念出发，本页到此为止。」→ 讲页面之间的关系 → 删掉。

**4. 对读者说话，祈使，设问**

- 「如果你让一个标准 Transformer 写一本 50 万字的长篇小说，它在生成第 30 万个字时……」→ 对读者讲话的场景铺垫 → 直接写 $n$ 个 token 时的计算量。
- 「但请记住『负载可能不均』，下一章它会在服务侧以另一种形式出现。」→ 祈使加预告 → 删掉。
- 「模型会算了、权重铺开了、通信也藏住了。现在换到用户视角：你发出一句话……中间到底发生了什么？」→ 自问自答的转场 → 删掉，直接写这一步发生什么。

**5. 过渡句和承接句**

- 「Engram 接的就是这类工作。」→ 只承接上一句，没有信息 → 删掉，下一句主语直接写 Engram。
- 「融合段要回答的是：这份记忆此刻该不该用、用多少。」→ 替下文设问 → 删掉。

**6. 段尾的总结和升华**

- 「这等于把本该留给高层推理的深度花在重建一张静态查找表上。」→ 对上一句的评价式总结，没有新信息 → 删掉。
- 「容量换来的不是免费参数。」→ 口号式的收尾，下面两句才有信息 → 删掉。
- 「位置只能折中。插得早，……；插得晚，……」→ 把前文已讲的两端权衡压成口号再讲一遍 → 删掉。

**7. 评价词和空泛修饰**

- 「非常强大」「十分关键」「巧妙地」「优雅」「不可忽视」→ 只有评价，没有信息 → 删掉，或换成具体的量。

## 反例：看着像，其实正常

这些句子不要报。

1. 「表只被查，不参与每个 token 的浮点运算。」——短句，是事实，不是口号。
2. 「不缓存时生成 $n$ 个 token 需要约 $n^2/2$ 组 K/V 计算，缓存后降为 $n$ 组。」——因果关系加具体的量。
3. 「MoE 是把前馈层换成多个并行的专家子网络、每个 token 只激活其中几个的结构，见 [DeepSeekMoE](wiki/deepseek-moe)。」——一句话解释基线外的词，并链接前置概念，不是在讲页面安排。
4. 「设每个表有 7 行，三个 token 依次为……」——在例子里交代设定，是例子本身。
5. 「公式适用于标准 MHA/GQA 结构；滑动窗口、稀疏注意力、MLA 不在其内。」——在「适用条件与边界」里写这个概念的边界，不是免责。
6. 「$\alpha_t\in(0,1)$，点积为 0 时门为 0.5。」——对一个量的取值给出结论。
7. 「所以」「因此」「于是」连接的句子——只要后一句是前一句的结果，不算过渡句。
8. 一章开头一句话点明这一章讲的这件事（例如「检索段把 token 序列变成表里的向量」）——点明对象不是预告结构；判断线是这句话本身有没有讲出内容。
