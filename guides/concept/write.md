# Concept 阶段 2：生产

按规划产物生成完整 HTML 初稿。落实规划阶段的教学设计，不重新决定内容范围或文章结构，不作技术正确性和小白可读性的最终结论（由质检阶段产生）。

## 1. 输入与写作边界

输入为 `research/` 下的 scope.md、evidence.md、outline.md、glossary.md，外壳 `.dojo/templates/concept/index.html` 和组件库 `.dojo/templates/concept/components.html`，局部写法参考 `guides/concept/content-examples.md`。输入缺失或规划完成条件未满足时，不得开始写作。不得参考 `wiki/` 下已有页面的写作风格。

必须按 outline.md 落实：页面开头、章节标题和顺序、每章教学任务、前置知识引用位置、贯穿例子的推进、讲解材料及职责、正文与折叠块分工、误解和边界的处理位置。

不得自行增删或重排核心章节、增加新的学习目标、更换贯穿例子、改变前置知识映射、把正文必要内容移入折叠块、使用证据不足或无法消歧的论断。

写作中发现缺口时停止相关部分写作：缺核心事实或证据返回规划阶段；大纲无法成立返回规划阶段；仅需补充不改变大纲的连接句、符号说明或局部计算时在本阶段补充。不得用范围外的新内容填补缺口。

## 2. 创建页面

本阶段产出两份文档：

```text
wiki/<name>/
├── index.html        # 深度教学页（首页登记）
├── overview.html     # 快速阅读（5 分钟扫读）
└── research/
    └── draft-check.md
```

```bash
mkdir -p wiki/<name>/research
cp .dojo/templates/concept/index.html wiki/<name>/index.html
cp .dojo/templates/concept/overview.html wiki/<name>/overview.html
```

深度教学页外壳提供全部样式、本地 KaTeX/Prism 资源、通用交互和 `<!-- @content -->` 内容插入标记。按 outline.md 从组件库选择组件，复制到插入标记处并替换【…】占位符。大纲未选择的组件不得加入页面。本地资源路径相对于页面解析（`wiki/<name>/` 下的页面引用 `../../libs/`）。

## 3. 快速阅读

按 overview 模板生成快速阅读文档，写入 `overview.html` 的 `<!-- @content -->` 标记处。内容结构固定，5 分钟内可扫读：

1. 一句话定位：这个概念是什么、解决什么问题
2. 为什么需要它：2–4 点，说明概念存在的动机
3. 核心直觉：3–5 点，用通俗语言说清机制层面，不展开公式与推导
4. 关键结论与边界：最重要的 2–4 个判断，附成立条件

快速阅读面向不了解该领域的读者：首次出现的前置概念给出概念页链接（与深度教学页同一份映射），不展开背景。快速阅读不包含公式推导、不包含手算例子。涉及数字时必须与 evidence.md 一致，不确定的标注。

## 4. 写作规则

### 4.1 完全小白

- 正文首次依赖前置概念时给出概念页链接；前置概念页缺失（第 3 层起的登记项）时放占位提示，正文保留阅读所需的最小衔接，不内联大段背景讲解
- 术语首次出现时给出继续阅读所需的含义和职责，缩写给出全称，与 glossary.md 一致
- 同一段首次引入多个新概念时拆分推进；贯穿例子每次出现时复用已知输入并增加一个新步骤或结论
- 先讲为什么需要它，再讲是什么；一次只引入一个新变量

### 4.2 公式

公式出现前说明它要解决的问题；出现后解释每个首次出现的符号、下标、范围和运算，以及各部分职责；至少给出一个边界、对称、不变量或简单代入检查。公式依据必须是已确认的 F/C 编号、由已确认公式直接推出的中间式，或明确标记的教学构造。承担学习目标答案的公式配"补充推导"折叠块，给出从已知条件到结论的关键步骤；大纲明确不展开推导的，在公式后用一句话说明理由。

### 4.3 推导

开始前写明推导目标、已知条件和要得到的结论；一步只完成一个主要变换，关键变换说明使用的规则；不使用"显然""容易得到"代替关键步骤；结论随符号或边界变化时分情况讨论；结束后回到本章问题说明结果解释了什么、不能推出什么。解释核心机制的关键步骤必须留在正文。

### 4.4 数字例子

说明要验证的具体问题；使用能够复算的输入；展示代入、中间结果和最终结果；方向或条件影响结论时提供正反对照。人为设置的数字标记为教学示例并说明构造目的，不得表述为来源的实验数据；外部事实数字引用 N 编号和来源条件。

### 4.5 伪代码与可运行代码

伪代码标明"伪代码"，写清输入、可变状态、核心步骤、输出及与正文公式变量的对应关系；存在循环时写明循环范围和停止条件；不得用 `train()`、`optimize()` 一类黑箱步骤替代本节要解释的机制；使用 `language-text` 标记，不冒充可运行语言。

可运行代码包含所有导入、最小输入、变量定义、核心计算和输出语句；核心变量应能映射到正文公式。所有声称可运行的代码必须实际执行，运行失败时不得保留"可运行"声明；运行记录写入 `draft-check.md`。代码后说明验证的机制、为教学省略的内容和与真实工程实现的差异。完整代码与预期输出放 `code-details` 折叠块，正文只保留机制说明、变量映射和运行结果的结论性要点。

### 4.6 来源事实、教学构造与教学解释

- 来源事实：外部可核查事实附相邻来源或 C/F/N 对应关系。evidence.md 中不存在的新外部事实不得依靠训练记忆补写，发现此类需求时返回规划阶段
- 教学构造：人为设置的数字、场景、简化模型和代码输入标记为教学示例并说明构造目的
- 教学解释：类比、直觉描述和超出来源原句的推断标明教学职责及适用边界，不写成来源中的直接结论；类比只解释已声明的局部关系，不能替代正式定义

### 4.7 正文与折叠块

正文保留：学习目标所需的定义、机制和结论；前置概念页链接；会改变结论的条件和限制；必要推导步骤；必要代码观察结果；贯穿例子的关键推进。折叠块前说明它补充哪个已陈述结论，折叠块后恢复正文主线；正文不得引用只有展开后才能看到的新结论。折叠块全部收起时，页面仍须完整回答所有学习目标。

### 4.8 HTML 要求

页面只有一个主标题 `<h1 class="title">`；标题层级不跳跃；纳入目录的标题显式设置稳定且唯一的 id；代码语言类名与实际语言一致；标签正确闭合；清除全部【…】占位符、`<!-- @content -->` 标记、组件标记和组件说明注释。页面末尾设来源与教学说明，列明核心论断与来源、核心公式与来源、外部数字与条件、教学示例、教学解释和类比边界、教学简化及其限制。

### 4.9 术语与记号纪律

非中文词（含 actor、minibatch、early stopping、Adam 一类工程词和算法简称）首次出现时必须带中文译名或内联解释；无通行译名的给一句话职责说明。同一对象全文使用单一记号，不在不同位置为同一对象引入多种写法；对数一律写明自然对数（$\ln$ 或"log 以 e 为底"）。章节 id 使用英文小写短横线的语义命名，与章节标题对应。

### 4.10 学习目标闭环

写作完成后逐题核对学习目标：每个目标是否有正文章节完整回答、完成答案是否与 scope.md 一致、是否被折叠块独占。缺口返回规划阶段补齐。

## 5. draft-check.md

一页检查记录，全部来自实际检查或运行，不使用推测性记录：

```markdown
# <概念名>初稿检查

- 输入版本：scope / evidence / outline / glossary 的状态
- 大纲落实：章节、学习目标、前置知识、贯穿例子、误解和边界、过渡（逐项一行）
- 学习目标闭环：每个目标逐题核对结果
- 代码运行：每个代码块一行——运行命令、退出码、实际输出与页面描述一致；无代码时写明"无可运行代码"
- 机械检查：python3 .dojo/scripts/validate.py <页面路径> 的命令和结果
- 公式渲染与交互：浏览器打开后的实际检查结果
- 写作偏差：无 / 偏差内容及处理方式（返回规划 / 局部修正）
```

draft-check.md 是过程记录，不得在其中填写"审查通过"。

## 6. 完成条件

- 输入产物齐全；大纲的全部章节、学习目标、前置知识、完成检查和过渡均已落实
- 学习目标闭环：全部目标由正文章节完整回答
- 来源事实附来源定位；教学构造和教学解释均已标记；C/F/N 引用与 evidence.md 一致
- 所有声称可运行的代码已实际执行，输出与页面说明一致
- 非中文词首现处均有译名或解释；同一对象全文单一记号；章节 id 为语义命名
- 占位符、组件标记和写作注释已清除
- `.dojo/scripts/validate.py` 通过；公式渲染和页面交互已在浏览器中实际检查
- 折叠块全部收起时正文仍能回答全部学习目标
- draft-check.md 已填写
