# Concept 阶段 2：生产

按规划产物生成完整 HTML 初稿。落实规划阶段的教学设计，不重新决定内容范围或文章结构，不作技术正确性和小白可读性的最终结论（由质检阶段产生）。

## 1. 输入与写作边界

输入为 `research/` 下的 scope.md、evidence.md、outline.md、glossary.md，外壳 `.dojo/templates/concept/index.html` 和组件库 `.dojo/templates/concept/components.html`，正文写法参考 `guides/concept/content-examples.md`，格式规范遵循 `guides/concept/style-guide.md`。输入缺失或规划完成条件未满足时，不得开始写作。不得参考 `wiki/` 下已有页面的写作风格。

必须按 outline.md 落实：页面开头、章节标题和顺序、每章教学任务、前置知识引用位置、教学示例的推进、讲解材料及职责、正文与折叠块分工、误解和边界的处理位置。

不得自行增删或重排核心章节、增加新的学习目标、更换教学示例、改变前置知识映射、把正文必要内容移入折叠块、使用证据不足或无法消歧的论断。

写作中发现缺口时停止相关部分写作：缺核心事实或证据返回规划阶段；大纲无法成立返回规划阶段；仅需补充不改变大纲的连接句、符号说明或局部计算时在本阶段补充。不得用范围外的新内容填补缺口。

## 2. 创建页面

本阶段产出两份文档：

```text
wiki/<name>/
├── index.html        # 深度教学页（首页登记）
├── overview.html     # 快速阅读（5 分钟扫读）
└── research/
    └── draft-check.md
```

```bash
mkdir -p wiki/<name>/research
cp .dojo/templates/concept/index.html wiki/<name>/index.html
cp .dojo/templates/concept/overview.html wiki/<name>/overview.html
```

深度教学页外壳提供全部样式、本地 KaTeX/Prism 资源、通用交互和 `<!-- @content -->` 内容插入标记。按 outline.md 从组件库选择组件，复制到插入标记处并替换【…】占位符。大纲未选择的组件不得加入页面。本地资源路径相对于页面解析（`wiki/<name>/` 下的页面引用 `../../libs/`）。

## 3. 写作规范

正文写作的唯一质量正本是 `guides/concept/content-examples.md`。写作每类内容前先读对应小节：

- 概念首次解释、公式、推导、数字例子：A1–A4
- 图示、伪代码、可运行代码：A5–A7
- 正文与折叠块、章节组织与过渡：A8–A9
- 事实、教学示例与教学解释：A10
- 相邻材料如何串联：B 衔接示范
- 页面开头学习目标、前置知识引用：C 新结构示例

写作规则：

- 正文首次依赖前置概念时给出概念页链接；递归深度上限外登记的缺失概念页放占位提示，正文保留阅读所需的最小衔接，不内联大段背景讲解
- 先讲为什么需要它，再讲是什么；一次只引入一个新变量
- 核心机制至少包含一个可手算的数字例子；代码只有在能帮助理解且实际跑通时才加入
- 来源事实附来源定位或 C/F/N 编号；教学构造标记为教学示例；教学解释标明职责与边界；教学简化不得省略关键构成要素

## 4. 快速阅读

按 overview 模板生成快速阅读文档，写入 `overview.html` 的 `<!-- @content -->` 标记处。内容结构固定，5 分钟内可扫读：

1. 一句话定位：这个概念是什么、解决什么问题
2. 为什么需要它：2–4 点，说明概念存在的动机
3. 核心直觉：3–5 点，用通俗语言说清机制层面，不展开公式与推导
4. 关键结论与边界：最重要的 2–4 个判断，附成立条件

快速阅读面向不了解该领域的读者：首次出现的前置概念给出概念页链接（与深度教学页同一份映射），不展开背景。快速阅读不包含公式推导、不包含手算例子。涉及数字时必须与 evidence.md 一致，不确定的标注。

## 5. 学习目标闭环

写作完成后逐题核对学习目标：每个目标是否有正文章节完整回答、完成答案是否与 scope.md 一致、是否被折叠块独占。缺口返回规划阶段补齐。

## 6. draft-check.md

一页检查记录，全部来自实际检查或运行，不使用推测性记录：

```markdown
# <概念名>初稿检查

- 输入版本：scope / evidence / outline / glossary 的状态
- 大纲落实：章节、学习目标、前置知识、贯穿例子、误解和边界、过渡（逐项一行）
- 学习目标闭环：每个目标逐题核对结果
- 代码运行：每个代码块一行——运行命令、退出码、实际输出与页面描述一致；无代码时写明"无可运行代码"
- 机械检查：python3 .dojo/scripts/validate.py <页面路径> 的命令和结果
- 公式渲染与交互：浏览器打开后的实际检查结果
- 写作偏差：无 / 偏差内容及处理方式（返回规划 / 局部修正）
```

draft-check.md 是过程记录，不得在其中填写"审查通过"。

## 7. 完成条件

- 输入产物齐全；大纲的全部章节、学习目标、前置知识、完成检查和过渡均已落实
- 学习目标闭环：全部目标由正文章节完整回答
- 来源事实附来源定位；教学构造和教学解释均已标记；C/F/N 引用与 evidence.md 一致
- 所有声称可运行的代码已实际执行，输出与页面说明一致
- 占位符、组件标记和写作注释已清除
- `.dojo/scripts/validate.py` 通过；公式渲染和页面交互已在浏览器中实际检查
- 折叠块全部收起时正文仍能回答全部学习目标
- draft-check.md 已填写
