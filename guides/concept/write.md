# 概念页写作

按规划产物生成完整 HTML 初稿。落实规划中的内容设计，不重新决定内容范围或文章结构；技术正确性和可读性由后续质检确认。

## 1. 输入与写作边界

输入为 `research/` 下的 scope.md、evidence.md、outline.md、glossary.md，外壳 `.dojo/templates/concept/index.html` 和组件库 `.dojo/templates/concept/components.html`，正文写法参考 `guides/concept/content-examples.md`，格式规范遵循 `guides/concept/style-guide.md`。输入缺失或规划完成条件未满足时，不得开始写作。不得参考 `wiki/` 下已有页面的写作风格。

必须按 outline.md 落实：页面开头、章节标题和顺序、各章职责、前置知识引用位置、构造示例的推进、表达材料及职责、正文与折叠块分工、误解和边界的处理位置。

不得自行增删或重排核心章节、增加新的学习目标、更换构造示例、改变前置知识映射、把正文必要内容移入折叠块、使用证据不足或无法消歧的论断。

写作中发现缺口时停止相关部分：缺少核心事实、证据或结构时返回规划文件修正；局部连接句、符号说明和计算细节可直接补充。不得用范围外的新内容填补缺口。

## 2. 创建页面

产出以下文档：

```text
wiki/<name>/
├── index.html        # 完整说明页（Pages 构建自动发现）
├── overview.html     # 概览
└── research/
    └── draft-check.md
```

```bash
mkdir -p wiki/<name>/research
cp .dojo/templates/concept/index.html wiki/<name>/index.html
cp .dojo/templates/concept/overview.html wiki/<name>/overview.html
```

完整说明页外壳提供全部样式、本地 KaTeX/Prism 资源、通用交互和 `<!-- @content -->` 内容插入标记。按 outline.md 从组件库选择组件，复制到插入标记处并替换【…】占位符。大纲未选择的组件不得加入页面。本地资源路径相对于页面解析（`wiki/<name>/` 下的页面引用 `../../libs/`）。

## 3. 写作规范

正文写作参考 `guides/concept/content-examples.md`。各类内容对应小节如下：

- 概念首次解释、公式、推导、数值示例：A1–A4
- 图示、伪代码、可运行代码：A5–A7
- 正文与折叠块、章节组织与过渡：A8–A9
- 事实、构造示例与辅助解释：A10
- 相邻材料如何串联：B 衔接示范
- 页面开头学习目标、前置知识引用：C 新结构示例

写作规则：

- 正文首次依赖前置概念时给出概念页链接；递归深度上限外登记的缺失概念页放占位提示，正文保留阅读所需的最小衔接，不内联大段背景讲解
- 按知识依赖组织章节，避免集中引入多个未定义概念
- 核心机制至少包含一个可手算的数值示例；代码只有在能帮助理解且实际跑通时才加入
- 来源事实附来源定位或 C/F/N 编号；人为数据标记为构造示例；辅助解释标明职责与边界；简化条件不得省略关键构成要素
- 数学符号一律写为 `$...$` 或 `$$...$$` 交给 KaTeX 渲染，标题、summary、正文、列表和表格同等适用，不使用 Unicode 数学字符替代
- 结构图使用 HTML 结构或内联 SVG，不使用等宽字符拼出的框线图
- 页面开头问题块 h2 固定为「核心问题」；每个正文章节末尾 h3 固定为「本章问题」。两级问题都必须作答：每个问题下方紧跟折叠块给出完整答案，核心问题的答案给出结论与关键机制并指明完整论证所在章节

## 4. 概览

按 overview 模板生成概览文档，写入 `overview.html` 的 `<!-- @content -->` 标记处：

1. 定位摘要：这个概念是什么、解决什么问题
2. 问题背景：说明概念出现的原因
3. 核心机制：3–5 点，使用清晰的技术语言概括机制，不展开公式与推导
4. 关键结论与边界：最重要的 2–4 个判断，附成立条件

概览面向不了解该领域的读者：首次出现的前置概念给出概念页链接（与完整说明页同一份映射），不展开背景。概览不包含公式推导、不包含计算示例。涉及数字时必须与 evidence.md 一致，不确定的标注。

## 5. 目标覆盖检查

写作完成后逐题核对学习目标：每个目标是否有正文章节完整回答、完成答案是否与 scope.md 一致、是否被折叠块独占。缺口返回规划阶段补齐。

同时核对问题块：页面级「核心问题」与每个章节的「本章问题」是否每题都有对应解答折叠块，答案是否独立可读、是否与正文结论一致。存在未作答的问题时补齐后才进入质检。

## 6. draft-check.md

一页检查记录，全部来自实际检查或运行，不使用推测性记录：

```markdown
# <概念名>初稿检查

- 输入版本：scope / evidence / outline / glossary 的状态
- 大纲落实：章节、学习目标、前置知识、贯穿示例、误解和边界、过渡（逐项一行）
- 目标覆盖检查：每个目标逐题核对结果
- 代码运行：每个代码块一行——运行命令、退出码、实际输出与页面描述一致；无代码时写明"无可运行代码"
- 机械检查：python3 .dojo/scripts/validate.py <页面路径> 的命令和结果
- 公式渲染与交互：浏览器打开后的实际检查结果
- 写作偏差：无 / 偏差内容及处理方式（返回规划 / 局部修正）
```

draft-check.md 是过程记录，不得在其中填写"审查通过"。

## 7. 完成条件

- 输入产物齐全；大纲的全部章节、学习目标、前置知识和验证项均已落实
- 目标覆盖检查：全部目标由正文章节完整回答
- 来源事实附来源定位；构造示例和辅助解释均已标记；C/F/N 引用与 evidence.md 一致
- 所有声称可运行的代码已实际执行，输出与页面说明一致
- 占位符、组件标记和写作注释已清除
- `.dojo/scripts/validate.py` 通过（含数学字符与结构图检查）；公式渲染和页面交互已在浏览器中实际检查
- 全部数学符号使用 LaTeX 书写，结构图为 HTML 或内联 SVG；图内公式写在 `<foreignObject>` 中，已在浏览器确认渲染正常且标签无重叠
- 页面级「核心问题」与每个章节的「本章问题」均有解答折叠块，答案独立可读
- 折叠块全部收起时正文仍能回答全部学习目标
- draft-check.md 已填写
- 写作阶段的自查不计入质检轮次；进入质检时把页面交给独立审查者，不以自查结果替代独立审查
