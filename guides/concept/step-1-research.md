# 阶段 1：研究范围

本阶段确定概念页的内容范围和事实依据，不设计章节，不决定讲解顺序，不选择贯穿例子，不写 HTML。

读者默认是完全小白，不具备该概念及其所属领域的基础知识。

---

## 1. 输入与歧义处理

常规输入只有概念名称。开始研究前，先判断名称是否存在会改变核心定义或研究方向的歧义（同名缩写、不同领域同名概念、同一术语在不同论文中的不同含义）。

歧义处理状态分为：**已裁定**（有权威或主流含义时采用该含义并记录依据）、**并列呈现**（不同含义都与核心问题有关，正文中明确区分）、**无法消歧**（现有可靠信息不足，且不同选择会改变核心定义或主要结论）。存在"无法消歧"状态时，流程失败且不发布。

---

## 2. 产物

```text
wiki/<name>/research/
├── scope.md        # 内容范围
└── evidence.md     # 核心论断与证据的对应关系
```

`scope.md` 记录讲什么，`evidence.md` 记录核心论断的依据。两者都不预先确定章节结构、讲解顺序或贯穿例子。

---

## 3. `scope.md` 要求

### 3.1 概念含义

- 概念名称、英文名称和常见缩写
- 一句话定义：说明概念做什么，不承担完整教学任务
- 正式定义：与权威来源一致，不依靠训练记忆补写
- 本文采用的语境
- 包括什么：每项说明为什么属于该概念
- 不包括什么：容易被误认属于本概念的内容，每项说明排除理由
- 相邻概念：容易混淆的概念，记录关键区别及是否纳入本页范围
- 概念歧义及处理状态

### 3.2 核心问题

列出 3–5 个读者读完后必须能够回答的核心问题。每个核心问题包括：

```markdown
### Q1：<具体问题>

- 完成答案：读者最终应能说明的内容
- 为什么是核心问题：不理解它会缺失哪部分概念理解
- 依赖内容：回答该问题需要哪些定义、机制或基础知识
```

核心问题能用完整句子回答，直接对应概念的定义、动机、机制或边界，彼此职责不重复。不合格的核心问题示例："什么是 PPO？"（范围过大）、"PPO 有哪些公式？"（把材料形式误当成学习目标）。

### 3.3 内容分级

- **核心内容**：缺少后会导致至少一个核心问题无法完整回答。每项记录对应的核心问题和必须讲清的结论
- **辅助内容**：不直接构成核心答案，但能消除关键理解障碍或澄清常见误解。每项记录它服务的核心内容或误解
- **扩展内容**：与概念相关但不影响核心问题回答的内容，每项标记"纳入本页范围"或"排除出本页范围"

内容分级只确定是否属于本页范围及其作用，不决定放正文还是折叠块，不决定使用哪种讲解材料。

### 3.4 基础知识

读者默认不具备领域基础知识，理解核心问题所需的知识不得列为页面外前置条件。每项基础知识记录：

- 被哪些核心内容依赖
- 读者继续阅读前需要能够完成的解释、判断或计算
- 需要讲清的范围和不需要展开的范围

基础知识只讲到支撑后续推理所需的程度，不扩展成另一篇完整概念页。

### 3.5 明确不展开的内容

列出本页不展开的内容，每项说明与概念的关系和不展开的原因。合理原因包括：不影响核心问题回答、属于另一独立概念、只影响工程规模。不得仅写"篇幅有限"。

### 3.6 常见误解和适用边界

每个常见误解记录：

```markdown
### M1：<错误理解>

- 错误理解：读者可能形成的具体判断
- 正确结论：可以直接检查的纠正
- 形成原因：哪些术语、公式、类比或简化容易导致该误解
- 影响：该误解会使哪个核心问题回答错误
```

适用边界记录：概念解决什么问题、不解决什么问题、结论成立需要哪些条件、条件不满足时会发生什么。

误解和边界必须具体。例如，"clip 不是硬约束"应继续写明：它裁剪的是代理目标中使用的概率比副本，不会直接把实际概率比限制在固定区间。

---

## 4. `evidence.md` 要求

### 4.1 覆盖范围

证据编号（C 论断 / F 公式 / N 数字）只覆盖**核心内容**：核心问题完成答案直接依赖的论断、核心定义、主要机制、核心公式、关键数字、误解纠正结论、会改变适用边界的事实。辅助和扩展内容的事实不需编号，但正文中仍须附来源。

### 4.2 来源选择

| 论断类型 | 首选证据 |
|---|---|
| 原始算法、方法定义、论文结论 | 原始论文、标准、正式技术报告 |
| 通行数学定义和基础定理 | 权威教材、学术专著、同行评审综述 |
| 当前 API、默认值和配置行为 | 对应版本的官方文档或官方源码 |
| 具体实现机制和调用路径 | 固定版本或 commit 的官方源码 |

源码事实固定到版本或 commit。一般教程、论坛、聚合文章仅用于辅助定位，不作为核心论断的唯一依据。

### 4.3 记录格式

每条来源记录：编号、标题、作者或维护方、年份或版本、URL、具体定位（章节、公式、页码、文件路径）。

每个核心论断记录：

```markdown
## C1：<核心论断>

- 类型：定义 / 公式 / 机制 / 数字 / 实现 / 边界
- 对应范围：Q1、核心内容 K1、误解 M1
- 论断内容：可以被证实或证伪的完整句子
- 证据：S1，第 3 节，公式（7）
- 适用条件：结论成立的条件
- 置信状态：已确认 / 存在冲突 / 证据不足
```

"论文 S1 介绍了 PPO"不是合格论断；"论文 S1 的公式（7）使用裁剪概率比构造代理目标"才可核查。

### 4.4 冲突与不足

不同来源对核心定义不一致、论文公式与官方实现不一致、数字缺少实验条件时，不得静默选择一个结论。记录冲突双方、可能原因和处理状态。核心论断、核心公式或关键数字处于"存在冲突"或"证据不足"状态时，研究结束条件不满足，不得进入阶段 2。

---

## 5. 研究结束条件

- `scope.md` 和 `evidence.md` 已创建
- 已列出 3–5 个互不重复的核心问题，每个问题都有书面完成答案
- 每项核心内容都对应至少一个核心问题；每项基础知识都写明被谁依赖、需要讲到什么程度
- 每个常见误解都有错误理解、正确结论和证据
- 核心论断、核心公式和关键数字均已编号并处于"已确认"状态
- 不存在影响核心定义、核心问题或主要结论的"无法消歧"项
- 研究产物未包含章节结构、讲解顺序或贯穿例子等阶段 2 决策

以上条件全部满足后自动进入阶段 2；无法满足硬性条件时，流程失败且不发布。
