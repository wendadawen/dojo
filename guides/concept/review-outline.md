# 审大纲

大纲写完、机械检查通过后审。派 3 个子代理，一次全部派出。它们没参与写这份大纲，彼此看不到对方的结果，只返回结论，不改任何文件。每个审查者的提示词在 `guides/concept/reviewers/` 下，派的时候把对应文件的全文交给它，再附上输入。

## 谁审什么

| 审查者 | 提示词 | 拿到什么 |
|---|---|---|
| 读者 | `outline-reader.md` | 只给 `outline.md`，不给 sources |
| 对照资料 | `outline-sources.md` | `outline.md`、`sources/` |
| 篇幅与冗余 | `outline-size.md` | `outline.md` |

读者不看 sources，是为了让他按真实读者的疑问去读，而不是按资料的结构去读。

## 什么算「必须改」

只有这三类，其余都不算：

- **资料里没有**：大纲里写了 sources 里找不到的内容。
- **遗漏关键内容**：读者学会这个概念必须知道、资料里有，大纲没有。
- **顺序错乱**：读者读到某一节时，需要的前置内容还没出现。

「想看更多」「可以再详细一点」不算。

每个问题一行：`类别｜位置｜问题｜依据｜改法`。没有问题写「无」。

## 一轮怎么走

1. 3 个审查者全面审，每轮都从头审，不是只看上一轮改的地方。
2. 作者核实每一条，成立的改大纲，不成立的写出理由。
3. 两个审查者对同一节点意见相反时（比如一个要补一节、一个要删它），交给仲裁，见下。
4. 改完重新运行大纲检查，再派下一轮，3 个审查者重新派。
5. 一轮里 3 个审查者都没有「必须改」的问题，并且作者没有未处理的问题，通过。

## 仲裁

冲突时字数预算优先：除非意见指出「关键内容完全缺失」，否则不为了补内容而突破预算。

连续 3 轮还有争议，剩下所有没处理完的意见，全部交仲裁。

仲裁是一个独立子代理，拿到 `outline.md`、这条意见的原文和作者的理由、`guides/concept.md`。它只回答：

- 对每一条意见：「必须改」或「不必改」。
- 依据：只能引 sources 里的具体位置或 `guides/concept.md` 的条文。引不出依据的，一律「不必改」。
- 它只裁已有的意见，不提新意见，不写内容，不改大纲。

判「必须改」的条目，作者改完后，仲裁再核对这次改动是否符合它的裁定，不符合就重改。核对只看这几条，不再全面重审。核对通过，大纲通过。

## 记录

每轮写 `wiki/<name>/research/outline-review-<轮次>.md`，轮次从 1 开始，按审查者分节写他们的问题，最后一节「处理」写每个问题怎么处理的，仲裁的结论也写在里面。
