# 收集

只做一件事：把这个概念的官方资料收到 `wiki/<name>/research/sources/`。不分析，不判断哪份有用，收完再说。

## 收什么

只收原作者或维护方发的资料，第三方一律不收：

- 论文：只收提出这个概念的那一篇。引用它、改进它、综述它的后续论文不收。
- 官方文档、官方仓库、原作者或维护方发的技术博客。

没有这个概念的原始资料的，停下来告诉用户，不要用第三方资料凑数。名字有多个含义、从用户的话里定不下来时，先问用户指哪一个。

## 怎么存

- 论文：存 PDF 和 LaTeX 源码（有的话），记版本号（如 v1、v2）。
- 仓库：clone 整个仓库，记 commit 号。
- 博客和文档：存网址，同时存一份纯文本快照，内容改版或下线后仍能对上。

`sources/` 整体不进 git，只提交 `sources/index.md`。

## index.md

`sources/index.md` 每份资料一行：

```markdown
- <文件或目录名>｜<类型：论文/仓库/文档/博客>｜<来源链接>｜<版本或 commit>｜<取回日期>｜<一句话说明它讲什么>
```

后面的审查者要读 sources，所以审查必须在存着 sources 的这台机器上做完。换机器要靠 `index.md` 里的版本重新收集。
