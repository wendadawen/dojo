# Note：把学过的内容沉淀成笔记

当用户明确说“整理、留档、记下来、存成笔记”时执行本场景。不在每次学习后自动留档。

## 定位

从已有学习材料沉淀可浏览的 HTML 笔记，写入 `wiki/<name>/index.html`。覆盖三类内容：

- 对话总结：一次 explain / pr 对话中弄懂的内容
- 源码与代码：读源码、读 PR 得到的理解与发现
- 经验与零散：踩过的坑、清单、工具用法、调研结果

概念与机制的系统讲解走 `guides/concept.md`，论文精读走 `guides/paper.md`，不重复覆盖。判断规则：用户想轻量留档时用本场景；想系统完整讲解时用 concept / paper。

## 形式

页面结构不固定，根据内容类型选择合适骨架，需要什么结构就用什么结构：

- 对话总结：问题 → 理解 → 要点 → 未解决 → 来源
- 源码解读：背景 → 关键代码路径 → 机制 → 取舍
- 经验清单：场景 → 做法 → 原因 → 避坑

## 生成规则

- 以 `.dojo/templates/note/index.html` 为外壳，将正文写入 `<!-- @content -->` 标记处，替换全部【…】占位符。
- 页面脱离对话后仍可读懂；不转录聊天记录，不补写用户没学过的内容。
- 涉及代码时保留文件路径、符号名和行号。
- 事实核查（强制）：
  - 禁止凭记忆断言。讲代码、API、库/框架行为、数值时不得仅凭记忆下结论。
  - 能查必须查。环境具备读文件或联网能力时，实际查证后再写；本地有源码就查源码（带路径与行号），查不到就搜索官方文档或网页。
  - 代码必须运行。声称可运行的代码实际执行核对；无法运行就标注“未运行”并说明原因。
  - 查不到必须声明。明确写“未核实/不确定”，不用“大概、应该”一带而过。
  - 来源与推断分离。关键论断注明依据；没有依据的一律标注为“推断”。
- 运行 `.dojo/scripts/validate.py <页面路径>`；通过后在 `content.json` 的 `notes` 分区登记，并运行 `.dojo/scripts/generate_index.py`。
- 对用户说明生成位置、笔记覆盖范围和未解决项。

不自动 commit、push 或部署。
