# 学习记录归档

适用于将已经确认的材料、结论、代码机制或工程经验整理为独立页面。只有收到明确归档要求时才执行。

## 目标

生成一篇可独立阅读的学习记录，写入 `wiki/<name>/index.html`。

## 范围与结构

- 每篇记录只处理一个中心结论。
- 基础定义位于首次使用之前，内容按依赖关系排列。
- 同一主题集中在一个章节。
- 结构无法承载内容时，先调整结构，再写正文。

## 内容边界

- 只记录已经验证的事实和明确确认的判断。
- 推测、评价和建议必须有依据，并标注其性质。
- 通用机制优先；实现特例和边界条件保持必要篇幅。
- 机制说明应覆盖输入、状态、关键参数、主要步骤和输出。
- 内部环境信息不写入页面。

## 事实核查

- 代码、API、库行为和数值在写入前重新核对源码或官方文档。
- 可运行代码实际执行并核对输出。
- 无法核实的内容标记为“未核实”或“推断”。
- 关键论断注明来源。

## 表述

- 标题短、主题式；导语概括关键机制与结论。
- 使用正式书面语，删除会话指代、临场评价和口语化过渡。
- 正文直接陈述内容。
- 代码引用标注文件与函数即可。

## 图示

- 使用内联 SVG，不使用 ASCII 字符图。
- 图内公式与代码标识符用 foreignObject 承载。
- 每张图只表达一个关系。
- 图示无法降低理解成本时，改用表格或文字。

## 发布前检查

- 正文没有会话指代或交流记录式表述。
- 标题和导语职责不同。
- 每个章节只承担一个主题。
- 每条事实有来源支撑，或已标记为推断。
- 图示只表达一个关系。
- 含图或公式的页面在无头浏览器实测过渲染。
- `.dojo/scripts/validate.py <页面路径>` 通过。

## 发布

使用 `.dojo/templates/note/index.html`，替换全部占位符和 `<!-- @content -->`。页面元数据包括纯文本 `description`、可含 `$...$` 公式的 `dojo:summary`、类型、主题和标签。
