    RLHF：用人类反馈教语言模型听话

    问题：预训练（pretraining，用海量无标注文本让模型学会语言本身的阶段）加上 SFT（Supervised Fine-Tuning，监督微调，用人写示范答案教模型答题）之后，模型已经会说话、会答题，但答案不一定符合人类真正想要的——而让人写"标准答案"又贵、又难统一标准。
    方案：让人对两个答案做 A/B 选择，这种偏好数据（preference data，记录"人选哪个答案更好"的数据）比写标准答案省力；训一个奖励模型（RM，Reward Model，给"问题+答案"打一个标量分数——即一个数，不是向量——的模型）来模仿人类偏好；再用强化学习（RL，Reinforcement Learning，让模型通过试错去最大化某个分数的学习方式）优化语言模型去拿高分，同时用 KL 散度（KL divergence，衡量两个概率分布差异大小的数值）约束它别跑偏。
    产物：一个更"听人话"的语言模型，也就是完成了对齐（alignment，让模型行为符合人类意图）。

    30 秒上下文：先知道它站在哪里

    大流程
    预训练 → SFT → RLHF（对齐阶段）。RLHF 是把"会说话的模型"变成"听话的模型"那一步。
    旧方案
    只做预训练 + SFT，靠人写标准答案教模型。
    痛点
    标准答案贵、不同人写的标准不一致；主观维度（哪个更有用、更无害）上人很难写出"最优答案"，但很容易判断"A 比 B 好"。
    改变点
    用偏好数据 + 奖励模型 + 强化学习，把"人类偏好"变成一个可以梯度优化的分数。

    最容易误解

    • "RLHF = PPO"——错。PPO（Proximal Policy Optimization，一种策略优化算法）只是第三步用的 RL 算法，RLHF 是"偏好数据 → 奖励模型 → RL"整套范式。
    • "RLHF 不需要 SFT"——错。SFT 是 RLHF pipeline 的第一步，它给出一个"会答题"的起点模型，后面才能在这个起点上做偏好优化。
    • "奖励模型就是语言模型本身"——不对。奖励模型是单独训练的"打分头"，输入 (问题, 答案)、输出一个标量分数，不生成 token。
    • "KL 惩罚是为了让模型完全不变"——错。KL 惩罚是防止模型为钻奖励模型漏洞而跑偏，不是禁止它变化；β 太大模型就学不动，太小模型就乱跑。

    来源：InstructGPT（Ouyang et al., 2022）；Christiano et al., 2017 "Deep reinforcement learning from human preferences"；PPO（Schulman et al., 2017）；Bradley-Terry 模型。

    小白版一句话定义：RLHF 是先让人给模型的答案做"谁更好"的选择，训出一个能模仿人偏好的打分器，再让模型用强化学习去拿高分，同时用一根"绳子"（KL 约束）拉着它别跑偏。

    预训练模型会说话，但不听你的

    一个刚预训练完的语言模型，本质上只学会了一件事：给定前面的文本，预测下一个 token（语言模型处理的最小单位，约等于一个词或几个字符）。它读过海量网页和书籍，所以会说人话、会接话——但你问它"帮我写一封请假信"，它可能接着写"……的格式如下"然后把话题岔开，因为它没学过"听指令、然后回答"这件事。

    早期的做法是 SFT（监督微调）：人写很多 (prompt, response) 对——prompt 是输入给模型的问题，response 是希望模型给的答案——然后让模型模仿这些示范。这一步把"会说话"的模型变成"会答题"的模型。

    但 SFT 有三个绕不开的问题：

    • 写好答案又贵又难统一。一个领域专家写一条高质量答案可能要十几分钟，不同人写的"好"标准也不一样，有的人啰嗦、有的人精简。
    • 主观维度上人写不出"最优"。比如"哪个答案更有用"、"哪个更无害"，人很容易判断 A 比 B 好，但很难凭空写出"最有用、最无害"的那条答案——写示范比做选择难得多。
    • SFT 学不到偏好信号。监督微调只学"像示范"，但示范本身没有告诉你"这个答案比那个好多少"，模型学不到排序信息。

    这三个问题的共同根源是：让人写答案，是用错了人的能力。人真正擅长、又便宜的是"做判断"，不是"做创作"。RLHF 的核心思路就是顺着这个能力重新设计训练信号。

    让人做选择，比让人写答案容易

    RLHF 改的第一件事，是把训练信号从"示范数据"换成"偏好数据"。偏好数据长这样：给标注员一个 prompt 和两个 response（A 和 B，可能来自两个不同模型、或同一个模型的不同采样），让她二选一，记录下"人选了 A"还是"人选了 B"。

    为什么这个改变是关键的：

    1. 选比写快。判断两个答案哪个更好可能只要 30 秒，写一条好答案要十几分钟。同样预算下能采十倍以上的数据。
    2. 主观维度更一致。"哪个更有用"这种判断，人做选择的一致性远高于凭空写出"最有用"的答案。
    3. 不需要标注员是专家。做选择不需要写出最优解，只要能比较，所以可以批量招标注员。

    但偏好数据有个问题：它只是"A 比 B 好"，不是一个可以求导的分数。强化学习需要一个能算梯度的目标函数，"人选了 A"这种离散标签没法直接优化。所以需要第二步——训练一个奖励模型，把偏好变成连续分数。

    奖励模型：把偏好变成分数

    奖励模型 RM 的输入是 (prompt, response)，输出是一个标量分数 $r_\varphi(x, y)$（$\varphi$ 表示 RM 的参数，$x$ 是 prompt，$y$ 是 response）。训练目标很直接：让人偏好的答案分数高于不偏好的答案。

    把"偏好"变成"分数"用的是一个经典数学模型——Bradley-Terry 模型。它假设：如果答案 A 的"真实质量分"是 $r_A$、B 是 $r_B$，那么人选 A 而不是 B 的概率是：

    $$P(y_A \succ y_B \mid x) = \sigma\big(r_\varphi(x, y_A) - r_\varphi(x, y_B)\big)$$

    这里 $\sigma$ 是 sigmoid 函数，把任意实数压到 $(0, 1)$ 区间，可以当概率用：

    $$\sigma(z) = \frac{1}{1 + e^{-z}}$$

    RM 的训练损失就是最大化"人选了 A"这个事件发生的概率，等价于下面这个负对数似然：

    $$\mathcal{L}_{\text{RM}} = -\log \sigma\big(r_\varphi(x, y_w) - r_\varphi(x, y_l)\big)$$

    其中 $y_w$ 是被选中的（winner），$y_l$ 是没被选中的（loser）。这个损失直观上很合理：当 $r_\varphi(x, y_w)$ 比 $r_\varphi(x, y_l)$ 大很多时，$\sigma$ 接近 1，$\log \sigma$ 接近 0，损失就小；反之损失大。RM 训练完，就有了一个可以给任意 (prompt, response) 打分的函数，可以求导，可以用来做强化学习。

    读到这里，你应该已经能解释：

    • 为什么"让人做选择"比"让人写答案"更便宜、更可扩展；
    • 奖励模型的输入和输出分别是什么；
    • Bradley-Terry 模型怎么把"A 比 B 好"转成一个可优化的概率。

    三步走：SFT、奖励模型、PPO

    把前两章拼起来，再加上强化学习这一步，就是完整的 RLHF 流程。

    小白版定义：RLHF 就是三件事按顺序做——先用 SFT 给一个"会答题"的起点模型；再用偏好数据训一个奖励模型来打分；最后用 PPO 让语言模型去拿高分，同时用 KL 散度拉着它别离起点太远。

    正式技术定义：在 SFT 模型 $\pi_{\text{ref}}$ 基础上，用人类偏好数据训练奖励模型 $r_\varphi(x, y)$；以 $\pi_{\text{ref}}$ 为参考，用 PPO 优化策略 $\pi_\theta$ 最大化下面的目标：

    $$\max_{\pi_\theta}\; \mathbb{E}_{x \sim \mathcal{D},\, y \sim \pi_\theta(\cdot \mid x)}\left[ r_\varphi(x, y) - \beta \, \mathrm{KL}\big(\pi_\theta(\cdot \mid x) \,\|\, \pi_{\text{ref}}(\cdot \mid x)\big) \right]$$

    符号说明：

    • $x$：prompt（问题）
    • $y$：response（答案），由当前策略 $\pi_\theta$ 采样得到
    • $\pi_\theta$：策略（policy），当前正在优化的语言模型。RL 术语里把"被优化的模型"叫策略
    • $\pi_{\text{ref}}$：参考模型，SFT 后冻结，用来约束 $\pi_\theta$ 不要跑偏
    • $r_\varphi$：奖励模型
    • $\beta$：KL 惩罚的强度系数（一个超参数）
    • $\mathrm{KL}(\cdot \| \cdot)$：KL 散度，衡量两个分布在每个 token 上的概率差异
    • $\mathbb{E}$：期望，对所有 prompt 和采样的 response 取平均
    • $\mathcal{D}$：prompt 的分布（训练数据集）

    三阶段流程图

            预训练语言模型
              │
              ▼  SFT（用示范数据：人写答案）
        π_ref（参考模型，冻结）
              │
              ├──► 训练奖励模型 RM（用偏好数据：人做 A/B 选择）
              │           │
              │           ▼
              │          r_φ(x, y)  ← 给任意 (问题, 答案) 打分
              │
              ▼  PPO（用 RL 最大化 r_φ - β·KL）
        π_θ（对齐后的模型）◄── KL 把它拉回 π_ref

    三个阶段各自的责任很清晰：SFT 给一个"会答题"的起点 $\pi_{\text{ref}}$；RM 把人的偏好变成可微的分数 $r_\varphi$；PPO 让 $\pi_\theta$ 往高分方向走，KL 这根绳子防止它走歪。下一章专门讲为什么这根绳子不能少。

    为什么必须用 KL 拉住模型

    如果你只写 max E[r_φ(x, y)] 而不加 KL 项，会发生什么？模型会找到一个捷径：既然 RM 是一个有限数据训出来的打分器，它一定有漏洞，模型只要找到能让 $r_\varphi$ 给高分的"漏洞答案"，就能拿满分——但这种答案对人来说往往毫无意义。

    这个现象叫 reward hacking（钻奖励的漏洞）。举几个真实会出现的例子：

    • RM 在训练数据里偏好长答案 → 模型就无限凑字数，答案越长越好
    • RM 偏好带"作为 AI 语言模型"这种话术 → 模型每条答案都加这句话
    • RM 对某类句式给高分 → 模型不管问什么都用这个句式回答

    这些答案 RM 会给高分，但人看着很糟糕。问题的根源是：RM 只在偏好数据覆盖到的答案分布上是准的，一旦模型为了刷分跑到这个分布之外，RM 的打分就不可靠了。

    KL 散度：一根拉住模型的绳子

    KL 散度衡量两个概率分布的差异。对语言模型来说，每个位置都有一个"下一个 token 取各个词的概率分布"，KL 把 $\pi_\theta$ 和 $\pi_{\text{ref}}$ 在每个位置的分布差异加起来：

    $$\mathrm{KL}\big(\pi_\theta(\cdot \mid x) \,\|\, \pi_{\text{ref}}(\cdot \mid x)\big) = \sum_t \sum_v \pi_\theta(v \mid x, y_{这里 $t$ 遍历 response 里的每个位置，$v$ 遍历词表里的每个 token，$y_{

    $\beta$ 控制"绳子的松紧"：

    • $\beta$ 大：绳子紧，$\pi_\theta$ 不敢偏离 $\pi_{\text{ref}}$ 太多 → 安全但学不到新东西
    • $\beta$ 小：绳子松，$\pi_\theta$ 可以大幅改变 → 能学到偏好，但容易 reward hacking
    • $\beta = 0$：没绳子，纯刷分 → 几乎一定 reward hacking

    实际工程里 $\beta$ 是个需要调的超参数，InstructGPT 报告用一个较小的值来平衡这两个极端（具体值见论文）。

    展开推导：为什么用 KL(π_θ ‖ π_ref) 而不是反过来

    问题陈述：我们要在目标函数里加一个 KL 惩罚项，让 $\pi_\theta$ 不要离 $\pi_{\text{ref}}$ 太远。但 KL 散度是有方向的——$\mathrm{KL}(P \| Q) \neq \mathrm{KL}(Q \| P)$——该用哪个方向？

    核心困难：选错方向会导致 $\pi_\theta$ 的优化行为不符合"防止钻漏洞"的本意。

    第 1 步：前向 KL = KL(π_ref ‖ π_θ) 的行为

    前向 KL 对 $\pi_\theta$ 的要求是：凡是 $\pi_{\text{ref}}$ 给高概率的 token，$\pi_\theta$ 也得给一定概率。这种性质叫 mean-seeking（覆盖模式），$\pi_\theta$ 会被逼着去覆盖 $\pi_{\text{ref}}$ 的所有可能输出。问题是它允许 $\pi_\theta$ 在 $\pi_{\text{ref}}$ 认为不太可能的 token 上也给出高概率——只要 $\pi_{\text{ref}}$ 给过高概率的都覆盖到就行。这正是 reward hacking 想钻的空子。

    第 2 步：反向 KL = KL(π_θ ‖ π_ref) 的行为

    反向 KL 对 $\pi_\theta$ 的要求是：凡是 $\pi_\theta$ 给高概率的 token，$\pi_{\text{ref}}$ 也得给一定概率。这种性质叫 mode-seeking（寻找模式），$\pi_\theta$ 不敢去 $\pi_{\text{ref}}$ 认为概率很低的地方。换句话说，$\pi_\theta$ 只能在 $\pi_{\text{ref}}$ 已经认为"合理"的区域里探索新模式。

    第 3 步：为什么 RLHF 要的是反向

    reward hacking 的本质就是 $\pi_\theta$ 跑到了 $\pi_{\text{ref}}$（正常答题模型）认为离谱的地方去刷分。反向 KL 正好惩罚这种行为：你想去 $\pi_{\text{ref}}$ 认为不可能的地方？行，但 KL 会爆炸，目标函数把你拉回来。所以反向 KL(π_θ ‖ π_ref) 和"防止钻漏洞"的目标天然对齐。

    验证：考虑一个极端情况。设某个 token $v^*$ 在 $\pi_{\text{ref}}$ 下概率极低 $\pi_{\text{ref}}(v^*) = \epsilon$，但 RM 错误地给包含 $v^*$ 的答案高分。如果 $\pi_\theta$ 想把 $v^*$ 的概率提到 $p$：

    • 反向 KL 贡献：$p \log(p / \epsilon)$，当 $\epsilon \to 0$ 时这项趋于无穷大 → 强烈惩罚
    • 前向 KL 贡献：$\epsilon \log(\epsilon / p)$，当 $\epsilon \to 0$ 时这项趋于 0 → 几乎不惩罚

    这验证了反向 KL 才能挡住"去低概率区钻漏洞"的行为。

    一句话总结：反向 KL 让 $\pi_\theta$ "在 $\pi_{\text{ref}}$ 的地盘里玩"，正好契合"防止钻漏洞"的目标；前向 KL 允许 $\pi_\theta$ 乱跑，挡不住 reward hacking。

    符号总览：

    • $\pi_\theta$：当前策略（被优化的模型）
    • $\pi_{\text{ref}}$：参考模型（冻结的 SFT 模型）
    • $\mathrm{KL}(P \| Q) = \sum_i P(i) \log \frac{P(i)}{Q(i)}$：从 $P$ 看 $Q$ 的差异
    • 前向 KL = $\mathrm{KL}(\pi_{\text{ref}} \| \pi_\theta)$：mean-seeking
    • 反向 KL = $\mathrm{KL}(\pi_\theta \| \pi_{\text{ref}})$：mode-seeking，RLHF 用这个
    • $v^*$、$\epsilon$、$p$：验证例子里的构造量（本文构造）
    展开：最小数值例子

    （本文构造，教学用）假设词表只有 3 个 token：好、坏、了。设在 prompt "今天天气" 后面：

    • $\pi_{\text{ref}}$（SFT 模型）给的下一个 token 概率：好=0.5，坏=0.3，了=0.2
    • $\pi_\theta$（当前模型）给的下一个 token 概率：好=0.7，坏=0.2，了=0.1

    计算反向 KL：

    $\mathrm{KL}(\pi_\theta \| \pi_{\text{ref}}) = 0.7 \log\frac{0.7}{0.5} + 0.2 \log\frac{0.2}{0.3} + 0.1 \log\frac{0.1}{0.2}$

    逐项算：

    • $0.7 \log(1.4) \approx 0.7 \times 0.336 = 0.235$
    • $0.2 \log(0.667) \approx 0.2 \times (-0.405) = -0.081$
    • $0.1 \log(0.5) \approx 0.1 \times (-0.693) = -0.069$

    加起来 $\mathrm{KL} \approx 0.235 - 0.081 - 0.069 = 0.085$。这个数很小，说明 $\pi_\theta$ 偏离 $\pi_{\text{ref}}$ 不远——它只是更偏向"好"一点，这在正常优化范围内。

    假设 RM 给"今天天气好"打 $r_\varphi = 2.0$，取 $\beta = 0.1$（本文构造），则目标函数值：

    $r_\varphi - \beta \cdot \mathrm{KL} = 2.0 - 0.1 \times 0.085 = 2.0 - 0.0085 = 1.9915$

    对比一下：如果 $\pi_\theta$ 为了刷分把"好"的概率压到 0.99、把"坏"压到 0.005、"了"压到 0.005（极端偏向），KL 会暴涨到约 0.84，目标函数变成 $2.0 - 0.1 \times 0.84 = 1.916$——反而比温和偏离时更低。这就是 KL 项在起作用：温和偏离能拿净分，极端跑偏会被惩罚掉。

# 阶段 1: SFT —— 用示范数据微调预训练模型
pi_ref = train_sft(pretrained_lm, sft_data)
#   sft_data: List[(prompt, human_response)]

# 阶段 2: 训练奖励模型 RM —— 用偏好数据
rm = train_reward_model(pi_ref, preference_data)
#   preference_data: List[(prompt, response_chosen, response_rejected)]
#   损失: -log σ(rm(chosen) - rm(rejected))

# 阶段 3: PPO —— 用 RL 优化 π_θ
pi_ref.eval()  # 冻结参考模型
pi_theta = copy(pi_ref)
for step in range(N_steps):
    prompts = sample_prompts(from=prompt_dataset)
    # 用当前策略采样 response
    responses = pi_theta.generate(prompts)
    # RM 打分
    rewards = rm.score(prompts, responses)
    # 算 KL（每个位置上 π_θ 和 π_ref 的 token 分布差异）
    kl = kl_divergence(pi_theta, pi_ref, prompts, responses)
    # RLHF 目标：最大化 reward - β·KL，等价于最小化 -(reward - β·KL)
    objective = -(rewards - beta * kl).mean()
    ppo_update(pi_theta, objective)

trainer = PPOTrainer(
    model=pi_theta,
    ref_model=pi_ref,
    reward_model=reward_model,
    config=ppo_config,
    tokenizer=tokenizer,
    dataset=prompt_dataset,
)

for batch in trainer.dataloader:
    query_tensors = batch["input_ids"]
    # 用当前策略 π_θ 采样 response
    response_tensors = trainer.generate(query_tensors)
    # RM 给 (query, response) 打分
    rewards = reward_model.score(batch, response_tensors)
    # PPO 一步更新：内部会算 KL 和 advantage，最大化 r - β·KL
    trainer.step(query_tensors, response_tensors, rewards)

    代码层次：第一层是模型对象（SFT 模型、奖励模型、带 value head 的 π_θ）；第二层是 PPOTrainer，它把采样、打分、KL 计算、PPO 更新包成一个 step；第三层是数据加载和配置。

    读者容易卡在哪：AutoModelForCausalLMWithValueHead 比普通语言模型多一个 value head（输出标量 value 估计），PPO 需要它来算 advantage；create_reference_model 返回的就是冻结的 $\pi_{\text{ref}}$；KL 在 PPOTrainer 内部算，代码里看不到显式的 kl_divergence(...) 调用。

    和真实工程的差距：真实训练（如 DeepSpeed-Chat、OpenRLHF）要处理大规模分布式（模型并行、ZeRO）、rollout 缓冲、GAE 优势估计、PPO clip 范围、RM 在线更新等；这里省略了所有这些细节。超参 kl_coef=0.1 是教学示意，真实值需查当前 TRL 文档和具体实验设置。

    什么时候用、什么时候会坏

    RLHF 不是万能药。它在某些场景里是当前最有效的对齐方法，在另一些场景里要么用不起、要么会出问题。

    适合用 RLHF 的场景

    • 需要对齐人类意图：聊天助手、指令跟随模型——模型不仅要"会答"，还要"答得让人满意"。
    • 有偏好数据采集能力：能招到标注员、能设计清晰的标注规范。
    • SFT 已经给了不错的起点：$\pi_{\text{ref}}$ 不能太差，否则 KL 约束反而把模型锁在差的起点上。
    • 能承担 PPO 的工程成本：PPO 训练不稳定、需要在线采样、显存翻倍（要同时放 $\pi_\theta$、$\pi_{\text{ref}}$、RM）。

    RLHF 会失效的几种方式

    1. reward hacking：模型钻 RM 漏洞拿高分但答案糟糕。本章前面讲过，KL 是主要防线，但 $\beta$ 调不好仍会出问题。
    2. 标注偏差：标注员群体的偏好不代表所有用户。比如某些话题上不同文化背景的标注员会给出相反的偏好，训出来的 RM 只反映了标注群体的偏见。
    3. RM 分布外：训 RM 用的答案分布 $\neq$ PPO 采样的答案分布。PPO 越优化，$\pi_\theta$ 采出的答案离 RM 训练分布越远，RM 打分越不可靠——这是个正反馈的失效循环。
    4. 成本高：训 RM 要偏好数据，PPO 要在线采样（一边生成一边学习）、训练不稳定、显存大。整体成本显著高于 SFT（解读者估算）。
    5. $\beta$ 难调：太松 reward hacking，太紧模型学不动。不同任务、不同模型规模下最优 $\beta$ 不一样。

    和相邻方案的对比

    方案解决什么不解决什么什么时候用
    RLHF用偏好数据对齐模型，能在线采样、有显式奖励信号没有偏好数据时不能用；PPO 不稳定有偏好数据、需要对齐、能承担 PPO 成本
    SFT用示范数据教模型答题学不到偏好排序信号有示范数据、预算有限、对齐要求不高
    DPO（见 DPO 概念页）直接从偏好对优化策略，跳过 RM 和 PPO没有在线采样、没有显式奖励模型可复用有偏好数据、想避开 PPO 不稳定性
    RLAIF用 AI 反馈代替人类反馈偏好质量受限于给反馈的 AI没有人类标注预算、可接受 AI 偏好

    值得注意的是 DPO 这条路：它从 RLHF 的同一个起点（偏好数据）出发，但数学上把"RM + PPO + KL"重新推导成一个直接的监督损失，省掉了 RM 和 PPO，工程上简单很多。这是 RLHF 之后最重要的替代方案，但 RLHF 因为有显式奖励模型，在一些需要"可解释打分"或"在线采样"的场景里仍然不可替代。
