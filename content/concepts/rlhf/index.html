    RLHF：让语言模型听人话的三阶段训练法

    问题：监督微调（SFT，Supervised Fine-Tuning，给模型看"问-答"对、用交叉熵学字面答案的训练方式）只能学"标准答案的字面"，但很多任务没有唯一正确答案，且标注员写一条高质量示范 ≈ 比较两个答案谁更好的 10-100 倍成本（InstructGPT 论文 §3.2）。
    方案：RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）用人类对模型输出的偏好（A 比 B 好）训练一个奖励模型 RM（Reward Model，输入 prompt+response 输出标量分数、模拟"人类觉得这个回答有多好"），再用 RM 当奖励通过 PPO（Proximal Policy Optimization，一种用 clip 限制每次更新步长的策略梯度算法）优化语言模型。
    产物：一个听人话的语言模型——1.3B 参数的 InstructGPT 输出在人类偏好评估上超过 175B 的原始 GPT-3（GPT，Generative Pre-trained Transformer，OpenAI 的语言模型家族；InstructGPT 论文 §3.5）。

    30 秒上下文：先知道它站在哪里

    大流程
    大语言模型（LLM，Large Language Model）训练三段式：预训练（海量文本学语言）→ SFT（示范数据学指令跟随）→ 对齐（RLHF/DPO/RLAIF 等让模型符合人类偏好）。RLHF 在第三段。
    旧方案
    只用 SFT：标注员手写标准答案，模型用交叉熵学字面。
    痛点
    ①很多任务没有唯一正确答案（写作、对话、推理）②偏好是相对的（A 比 B 好），不是绝对的③手写高质量示范成本极高。
    改变点
    监督信号从"标准答案"变成"偏好对"；训练目标从交叉熵变成"期望奖励 - KL（Kullback-Leibler 散度，衡量两个概率分布差异的非负量，0 表示完全相同）惩罚"；优化器从 SGD 变成 PPO。

    最容易误解

    • "RLHF = PPO"：错。PPO 只是 RLHF 默认的优化器，是通用 RL 算法。RLHF 是"用 RM 当奖励 + RL 优化"的范式，换成 GRPO / REINFORCE 也是 RLHF。
    • "RLHF = DPO"：错。DPO（Direct Preference Optimization，直接用偏好对优化策略、跳过 RM 和 RL 阶段的方法）是 RLHF 的替代方案，不是 RLHF 的一种。
    • "RLHF 就是让人类给每个回答打分"：不严格。人类标注的是偏好对（A 比 B 好），不是绝对分数。绝对分数一致性差，相对比较一致性高。
    • "RM 越大越准"：不一定。RM 容量受限于人类标注的一致性（InstructGPT 标注员一致性约 73%），RM 太大会过拟合标注噪声。

    来源：InstructGPT 论文（Ouyang et al., NeurIPS 2022, arXiv:2203.02155）；Learning to Summarize from Human Feedback（Stiennon et al., NeurIPS 2020, arXiv:2009.01325）；PPO 原论文（Schulman et al., 2017, arXiv:1707.06347）；DeepSeek-R1（DeepSeek, 2025-01，GRPO 来源）；HuggingFace TRL 实现（github.com/huggingface/trl）。具体数字出处见每处标注和末尾"证据边界声明"。

    小白版一句话定义：RLHF 是让模型"听人话"的训练方法——先教模型说话（SFT），再让人对比模型输出的好坏训一个"打分器"（RM），最后用这个打分器当奖励、用强化学习（PPO）调模型，让它越生成越合人意。

    大模型训练流程里 RLHF 在哪一步

    要理解 RLHF 在干什么，先看一个现代大语言模型（LLM，Large Language Model，给一段文本输出概率 P(text) 的大神经网络）从零到能用的完整流程。业界把它分成三段：

       预训练                SFT                  对齐
  ┌────────┐         ┌────────┐         ┌──────────────┐
  │ 海量文本 │  ───>  │ 示范数据 │  ───>  │ 偏好数据 + RL │
  │ 学语言   │         │ 学指令   │         │ 学人类偏好    │
  └────────┘         └────────┘         └──────────────┘
   GPT-3 原版          会回答问题           听话、安全、有用
   "续写文本"          "回答指令"           "对齐人类"
                                              ↑
                                           RLHF 在这

    三段各自的目标不同：

    • 预训练：在海量互联网文本上做"下一个 token 预测"，让模型学会语言本身。产物是一个会续写但不听指令的模型（你问它"中国的首都是？"，它可能续写"日本的首都是东京"）。
    • SFT（Supervised Fine-Tuning，监督微调）：用人工写的"问-答"示范数据，让模型学会"看到指令就回答"。产物是一个会回答问题的模型，但回答质量取决于示范数据，且容易答得"不像人话"。
    • 对齐：让模型的输出符合人类偏好——更听话、更有用、更安全。RLHF 是这一段的核心方法之一，其他还有 DPO、RLAIF 等。

    RLHF 解决的核心问题是："什么样的回答是好回答"无法用 loss 直接写出来。预训练和 SFT 都有明确的损失函数（下一个 token 的交叉熵），但"好"是一个主观、相对的概念——RLHF 的工作就是把这种主观偏好变成一个可以求导、可以优化的标量目标。

    这章把 RLHF 定位在训练流程的第三段（对齐），知道了它要解决"偏好无法直接写成 loss"的问题。下一章看在 RLHF 之前，第二段的 SFT 具体怎么做、卡在哪。

    在 RLHF 之前：SFT 怎么做、卡在哪

    SFT 的做法很直接：人工标注员写一批高质量的"问-答"对，比如：

    prompt x  =  "把这句话翻译成英文：今天天气不错"
response y =  "The weather is nice today."

    然后把模型的输出概率 P(y | x) 拉高。具体是用交叉熵（衡量两个概率分布差异的损失，越小越接近）作为损失函数，对每个 token 做监督学习。模型参数 θ（神经网络权重）通过梯度下降让交叉熵越来越小，最终模型在看到这个 prompt 时会输出接近 y 的回答。

    SFT 的产物是一个"会说话"的模型——能回答指令。但它在三个地方卡住了：

    卡点 1：很多任务没有唯一正确答案

    翻译任务还能写标准答案，但写文章、对话、推理这类任务没有唯一正解。同一个 prompt "写一首关于秋天的诗"，可以有千百种好回答。SFT 只能学一个固定答案的字面，模型学不到"什么是好"。

    卡点 2：偏好是相对的，不是绝对的

    人类判断"好坏"靠比较，不靠打分。给两个回答 A 和 B，人能轻松说"A 比 B 好"；但要给每个回答打 0-100 分，人与人之间一致性极差（你打 80 我打 60）。SFT 的损失函数没法表达"A 比 B 好"这种偏好关系——它只能表达"答案就是这个"。

    卡点 3：写高质量示范的成本极高

    InstructGPT 论文 §3.2 给了一个关键数字：写一条高质量示范 ≈ 比较两个答案谁更好的 10-100 倍成本。原因很直接——写一条好答案需要人从头创作高质量内容，而比较两个已有答案只需要判断优劣。同样的预算，做偏好标注能拿到 10-100 倍的数据量。

    这三个卡点合起来意味着：SFT 把模型拉到了"能用"的起点，但要把模型从"能用"推到"好用"，需要一种能用偏好数据、能把"好坏"变成可优化目标的方法。

    这章讲了 SFT 的做法（监督交叉熵学字面答案）和它的三个卡点（无唯一答案、偏好相对、标注贵）。下一章看 RLHF 怎么针对这三个卡点改设计。

    RLHF 改了什么：把"好坏"变成可优化目标

    针对上一章的三个卡点，RLHF 做了三个对应的改变：

    改变 1：监督信号从"标准答案"变成"偏好对"

    不再要标注员写答案，改要他们做比较。给标注员一个 prompt 和模型的两个回答 A、B，让他们标"A 比 B 好"还是"B 比 A 好"。这样一条数据形如 (x, yw, yl)——x 是 prompt，yw 是 winner（更好的回答），yl 是 loser（更差的回答）。这种数据叫偏好对，比写示范便宜 10-100 倍。

    改变 2：训练目标从"交叉熵"变成"期望奖励"

    用一个奖励模型 rφ(x, y)（参数 φ，输入 prompt x 和 response y 输出标量分数）模拟人类偏好——它学会了"什么样的回答人觉得好"。然后用它当奖励，让策略 πθ（参数 θ 的语言模型）优化"期望奖励"：

    $$J(\theta) = \mathbb{E}_{x \sim D,\, y \sim \pi_\theta(\cdot|x)}\big[r_\varphi(x, y)\big]$$

    符号说明：

    • J(θ)：优化目标，θ 的函数，越大越好。
    • E[·]：期望，对所有可能的 prompt x 和模型生成的 response y 取平均。
    • D：prompt 的分布（来自用户实际会问的问题）。
    • πθ(·|x)：策略，即参数为 θ 的语言模型，给定 x 输出 y 的概率分布。
    • rφ(x, y)：奖励模型，参数 φ，输入 (x, y) 输出标量分数。

    这个目标说的是："让模型生成的回答在 RM 看来分数尽量高。" 但这样直接优化会出问题——见下一个改变。

    改变 3：加 KL 惩罚防漂移

    RM 只在人类标注过的那批数据分布上学得好。如果模型为了刷高分跑到 RM 没见过的区域，RM 给的分数就不可信了——模型可能钻空子输出一些 RM 觉得高分、但人类觉得垃圾的文本（这叫 reward hacking，奖励钻空子）。比如 RM 学到"包含礼貌用语分数高"，模型可能输出"谢谢 谢谢 谢谢 谢谢"刷分。

    解决办法：把策略 πθ 拉回一个参考模型 πref（通常是 SFT 后冻结的模型，作为锚点——防止漂移的参考点）附近，用 KL 散度做惩罚：

    $$J(\theta) = \mathbb{E}_{x,\, y \sim \pi_\theta}\big[r_\varphi(x, y) - \beta \cdot \mathrm{KL}(\pi_\theta(\cdot|x) \,\|\, \pi_{\mathrm{ref}}(\cdot|x))\big]$$

    符号说明：

    • KL(πθ ‖ πref)：当前策略相对参考模型的 KL 散度。非负，0 表示两个分布完全相同，越大越偏离。
    • β：KL 惩罚系数，标量。控制"允许离参考模型多远"。InstructGPT 用 0.001 量级（论文附录训练超参）。
    • 其余符号同上。

    这个目标就是 RLHF 优化策略时用的核心公式：既要 RM 分数高，又不能离 SFT 模型太远。β 小 → 更激进追求高分（可能 reward hacking）；β 大 → 更保守（接近 SFT 模型，学不到偏好）。

    这章讲了 RLHF 的三个核心改变：偏好对代替答案、期望奖励代替交叉熵、KL 惩罚防漂移。下一章给出 RLHF 的正式定义和三阶段管线。

    RLHF 的正式定义：三阶段管线

    小白版定义：RLHF 是"先教模型说话、再训一个打分器、最后用打分器当奖励调模型"的三步训练法。

    正式技术定义：RLHF 是一种对齐方法，由三个阶段组成——(1) SFT 得到初始策略 πθ0；(2) 用人类偏好对 Dpref 训练奖励模型 rφ；(3) 用 rφ 当奖励、用 PPO 优化策略 πθ，目标为 J(θ) = E[rφ(x,y)] - β·KL(πθ‖πref)，其中 πref = πθ0 冻结。

       阶段 1：SFT             阶段 2：RM                阶段 3：PPO
  ┌──────────────┐       ┌──────────────┐        ┌────────────────┐
  │ 示范数据      │       │ 偏好对数据    │        │ RM 当奖励       │
  │ 交叉熵训练    │ ───>  │ Bradley-Terry │ ───>   │ PPO 优化策略    │
  │              │       │ 训练 r_φ      │        │ + KL 惩罚       │
  └──────────────┘       └──────────────┘        └────────────────┘
   产物: π_SFT            产物: r_φ              产物: π_RLHF
        │                      ↑                       │
        └──────────────────────┴───────────────────────┘
            π_SFT 同时作为 RM 的训练起点和 PPO 的参考模型

    符号说明：

    • πθ：参数为 θ 的语言模型（策略）。给定 prompt x 输出 response y 的概率 P(y|x)。θ 是神经网络权重。
    • πθ0 或 πSFT：SFT 后的初始策略。
    • πref：参考模型，PPO 阶段冻结，作为 KL 锚点。等于 πSFT。
    • rφ(x, y)：奖励模型，参数 φ。输入 (x, y) 输出标量分数。
    • Dpref：偏好数据集，每条形如 (x, yw, yl)。
    • yw, yl：winner / loser，人类标注里更好和更差的回答。
    • β：KL 惩罚系数（标量）。

    这章给了 RLHF 的正式定义和三阶段管线图。下面三章分别拆解每个阶段——SFT、RM、PPO，每个都给直觉、公式、推导、数值例子和可运行代码。

    第一阶段 SFT：让模型会说话

    直觉

    预训练后的模型只会"续写"——你给它"中国的首都"它可能续写成"是日本的首都"而不是回答"是北京"。SFT（监督微调）就是给模型看一批"问-答"示范，让它从"续写模式"切换到"回答指令模式"。这是冷启动（cold start，模型完全没学过任务、需要拉到能用的水平）阶段。

    公式

    对每条示范 (x, y)，其中 y = (y1, y2, …, yT) 是 T 个 token 的序列，SFT 最小化交叉熵损失：

    $$\mathcal{L}_{\mathrm{SFT}}(\theta) = -\sum_{t=1}^{T} \log \pi_\theta(y_t \mid x, y_{

    符号说明：

    • LSFT(θ)：SFT 损失，θ 的函数，越小越好。
    • yt：response 的第 t 个 token。
    • y<t：第 t 个 token 之前的所有 token（y1, …, yt-1）。
    • πθ(yt | x, y<t)：策略在看到 x 和前 t-1 个 token 后，输出第 t 个 token 是 yt 的概率。
    • T：response 长度（token 数）。
    • log：自然对数。

    这个公式的意思是：把 response 拆成 token 序列，对每个位置让模型输出"正确 token"的概率尽量大。-log 把概率变成损失（概率越大损失越小），求和得到整条 response 的损失。

    展开：为什么交叉熵能学字面答案

    问题陈述：为什么最小化 -Σ log πθ(yt | x, y<t) 等价于"让模型在 prompt x 下输出 y 的概率最大"？

    核心困难：response 是 token 序列，整体概率 P(y|x) 和每个 token 的概率 πθ(yt | x, y<t) 之间是什么关系？

    第 1 步：把整体概率拆开。一条 response y = (y1, …, yT) 在 prompt x 下被模型生成的概率，按链式法则（概率论里 P(A,B) = P(A)·P(B|A) 的多步推广）展开：

    $$\pi_\theta(y \mid x) = \prod_{t=1}^{T} \pi_\theta(y_t \mid x, y_{

    验证：T=2 时，πθ(y1,y2|x) = πθ(y1|x)·πθ(y2|x,y1)。符合条件概率定义。

    第 2 步：取对数把乘积变求和。直接最大化乘积难算（数值下溢、梯度复杂），取 log 把乘积变求和：

    $$\log \pi_\theta(y \mid x) = \sum_{t=1}^{T} \log \pi_\theta(y_t \mid x, y_{

    验证：log(AB) = log A + log B，递推得 log(∏) = Σ log。

    第 3 步：最大化 ⇔ 最小化负对数。我们要让 πθ(y|x) 尽量大，等价于让 log πθ(y|x) 尽量大，等价于让 -log πθ(y|x) 尽量小：

    $$\max_\theta \pi_\theta(y \mid x) \iff \min_\theta \big[-\log \pi_\theta(y \mid x)\big] = \min_\theta \Big[-\sum_{t=1}^{T} \log \pi_\theta(y_t \mid x, y_{

    这就是 LSFT 的来源。梯度下降最小化它，模型就会让每个 token 的条件概率逼近"标准答案"。

    一句话总结：交叉熵损失 = 整条 response 概率的负对数，最小化它 = 最大化模型生成标准答案的概率。

    符号总览：πθ(y|x) = 整体概率；πθ(yt|x, y<t) = 第 t 个 token 的条件概率；log 把乘积变求和；负号把最大化变最小化。

    展开：最小数值例子（3 token）

    （本文构造，教学用）

    假设 prompt x = "翻译：good morning"，标准答案 y = ("早", "上", "好") 共 3 个 token。模型当前参数下每个 token 的条件概率：

    位置 t=1: π(早 | x)                = 0.5
位置 t=2: π(上 | x, 早)            = 0.4
位置 t=3: π(好 | x, 早, 上)        = 0.8

    整体概率：π(y|x) = 0.5 × 0.4 × 0.8 = 0.16

    log 概率：log(0.5) + log(0.4) + log(0.8) = -0.693 - 0.916 - 0.223 = -1.832

    交叉熵损失：L = -(-1.832) = 1.832

    梯度下降一步后，模型会让这 3 个概率都变大，比如变成 (0.6, 0.5, 0.85)，新损失 = -[log(0.6)+log(0.5)+log(0.85)] = -[−0.511−0.693−0.163] = 1.367，损失下降了。

    展开：可运行代码（最小 SFT 一步） 
    """最小 SFT：用交叉熵更新一个 tiny 语言模型的一步。
不依赖任何外部库，纯 PyTorch。"""
import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)

# 假设词表大小 V=10，序列长度 T=4
V, T, D = 10, 4, 8  # D 是 embedding 维度

# 一个最小的"语言模型"：embedding + 一层线性
class TinyLM(nn.Module):
    def __init__(self, V, D):
        super().__init__()
        self.emb = nn.Embedding(V, D)
        self.proj = nn.Linear(D, V)
    def forward(self, tokens):
        # tokens: (B, T) -> logits: (B, T, V)
        return self.proj(self.emb(tokens))

model = TinyLM(V, D)
optimizer = torch.optim.Adam(model.parameters(), lr=1e-2)

# 一条示范数据：prompt + response 拼成 token 序列
# 假设前 2 个是 prompt，后 2 个是 response
tokens = torch.tensor([[1, 2, 5, 7]])  # (B=1, T=4)

# SFT loss：对每个位置预测下一个 token
# 输入 tokens[:-1]，目标 tokens[1:]
logits = model(tokens[:, :-1])  # (1, 3, V) 预测位置 1,2,3
targets = tokens[:, 1:]         # (1, 3)    真实位置 1,2,3

loss = F.cross_entropy(
    logits.reshape(-1, V),  # (3, V)
    targets.reshape(-1),    # (3,)
)
print(f"SFT loss = {loss.item():.4f}")

# 反传 + 更新
loss.backward()
optimizer.step()

# 再算一次，loss 应该下降
with torch.no_grad():
    new_logits = model(tokens[:, :-1])
    new_loss = F.cross_entropy(
        new_logits.reshape(-1, V), targets.reshape(-1))
print(f"updated loss = {new_loss.item():.4f}")  # 应该比上面小

    代码层次：第 1 层是数据（tokens），第 2 层是模型（TinyLM：embedding + 线性层），第 3 层是 loss（cross_entropy）+ 优化器（Adam）。真实 SFT 把 TinyLM 换成 Transformer，其他结构一样。

    读者容易卡在哪：(1) 为什么输入是 tokens[:-1] 目标是 tokens[1:]？因为每个位置预测的是下一个 token。(2) cross_entropy 内部已经做了 log_softmax，不要再手动 log。(3) reshape(-1, V) 是把 batch 和序列维度合并，因为 cross_entropy 接受 (N, C) 形状。

    和真实工程的差距：真实模型是几十亿参数的 Transformer，有 causal mask、KV cache、packing（多条数据拼成一串提高 GPU 利用率）、分布式训练（DDP/ZeRO）。但这些都不改变 SFT 的本质——交叉熵最小化。InstructGPT 用约 13k 条示范数据做 SFT（论文 §3.1 表 1）。

    这章讲了 SFT：用交叉熵让模型学标准答案的字面，产物是初始策略 πSFT。它解决了"会说话"的问题，但解决不了"说得好"——下一章看 RM 怎么把"好坏"变成可微的标量。

    第二阶段 RM：把"好坏"变成标量

    直觉

    偏好是相对的（A 比 B 好），不是绝对的（A 80 分）。要把它变成可优化的标量，需要一个函数 r(x, y) 把"好坏"映射成数字。RM 就是学这个函数——它是一个神经网络，输入 prompt x 和 response y，输出一个标量分数 rφ(x, y)。

    关键想法：人类标注的是"A 比 B 好"，但 RM 学的是绝对分数 r(x, y)。怎么从相对比较学到绝对分数？用 Bradley-Terry 模型——一个经典的偏好建模方法：假设每个选项有个"实力值" r，A 比 B 好的概率 = σ(r(A) - r(B))，其中 σ 是 sigmoid。

    数据格式

    偏好数据集 Dpref 每条形如 (x, yw, yl)：

    x     = "解释什么是递归"
y_w   = "递归是函数调用自己..."  (winner，更好)
y_l   = "递归就是循环..."        (loser，更差)

    收集方式：给标注员一个 prompt，让她对模型的 K 个回答排序（InstructGPT 用 K=9，Stiennon 用 K=4）。排序后每两个组成一个偏好对。

    公式

    用 Bradley-Terry 模型，RM 把"A 比 B 好"的概率建模为：

    $$P(y_w \succ y_l \mid x) = \sigma\big(r_\varphi(x, y_w) - r_\varphi(x, y_l)\big) = \frac{1}{1 + e^{-(r_\varphi(x,y_w) - r_\varphi(x,y_l))}}$$

    符号说明：

    • P(yw ≻ yl | x)：在 prompt x 下，yw 比 yl 好的概率。≻ 读作"优于"。
    • σ(z) = 1/(1+e-z)：sigmoid 函数，把任意实数 z 压到 (0, 1)。z=0 时 σ=0.5，z 越大越接近 1。
    • rφ(x, y)：奖励模型，参数 φ，输入 (x, y) 输出标量。φ 是 RM 网络权重。
    • yw, yl：winner / loser。

    RM 训练就是最大化这个概率（等价于最小化负对数似然）：

    $$\mathcal{L}_{\mathrm{RM}}(\varphi) = -\log \sigma\big(r_\varphi(x, y_w) - r_\varphi(x, y_l)\big)$$

    RM 网络结构通常和策略模型相同（InstructGPT 的 RM 是 6B，和策略 1.3B/6B 相当），只是最后输出一个标量而不是 token 分布。

    展开：从偏好数据到 RM 损失的推导

    问题陈述：怎么从"人类标注的偏好对"训出一个能对任意 (x, y) 打分的函数 rφ？

    核心困难：人类标注是离散的"A 比 B 好"，但 RM 要输出连续分数。需要一座桥把"离散偏好"和"连续分数"连起来。

    第 1 步：假设每个 response 有一个"潜在实力值"。给 (x, y) 定义一个分数 rφ(x, y)（RM 网络的输出）。分数越高代表人类觉得越好。这是建模假设——把模糊的"好坏"参数化。

    第 2 步：用 Bradley-Terry 把偏好变成概率。假设 A 比 B 好的概率只取决于两者分数差：

    $$P(A \succ B) = \sigma(r(A) - r(B)) = \frac{1}{1 + e^{-(r(A)-r(B))}}$$

    验证边界：r(A) - r(B) → +∞ 时 σ → 1（A 必胜）；→ -∞ 时 σ → 0（A 必败）；= 0 时 σ = 0.5（平局）。符合直觉。

    分情况讨论：为什么用 sigmoid 而不是别的？

    • 如果用阶跃函数（差 > 0 就 P=1，否则 P=0）：梯度处处为 0，没法训。
    • 如果用线性 P = r(A) - r(B)：可能 < 0 或 > 1，违反概率定义。
    • sigmoid 把任意实数压到 (0, 1)，且处处可导——是建模概率的标准选择。

    第 3 步：最大化标注数据的似然。人类标了"yw 比 yl 好"，我们希望模型给这个事件的概率 P(yw ≻ yl | x) 尽量大。对一批数据取对数似然：

    $$\max_\varphi \sum_{(x,y_w,y_l)} \log P(y_w \succ y_l \mid x) = \max_\varphi \sum \log \sigma\big(r_\varphi(x, y_w) - r_\varphi(x, y_l)\big)$$

    第 4 步：转成最小化损失。最大化对数似然 ⇔ 最小化负对数似然：

    $$\mathcal{L}_{\mathrm{RM}}(\varphi) = -\log \sigma\big(r_\varphi(x, y_w) - r_\varphi(x, y_l)\big)$$

    梯度下降最小化它，RM 就会让 winner 的分数比 loser 高。

    一句话总结：RM 用 Bradley-Terry 把"偏好对"变成"分数差过 sigmoid"，最大化标注似然 = 让 winner 分数比 loser 高。

    符号总览：rφ(x,y) = 潜在分数；σ = sigmoid 把分数差压成概率；P(yw≻yl|x) = 偏好概率；LRM = 负对数似然。

    展开：最小数值例子

    （本文构造，教学用）

    假设 prompt x = "翻译：good morning"，RM 当前给两个回答的分数：

    y_A = "早上好"      r_φ(x, y_A) = 1.2
y_B = "morning"     r_φ(x, y_B) = 0.3

    人类标注：yA 比 yB 好（即 yw = yA, yl = yB）。

    分数差：r(x, yw) - r(x, yl) = 1.2 - 0.3 = 0.9

    偏好概率：P(yA ≻ yB | x) = σ(0.9) = 1 / (1 + e-0.9) ≈ 1 / (1 + 0.407) ≈ 0.71

    RM 损失：L = -log(0.71) ≈ 0.342

    梯度下降一步后，RM 会让 r(x, yA) 变大、r(x, yB) 变小，比如变成 (1.5, 0.1)：新分数差 1.4，新概率 σ(1.4) ≈ 0.802，新损失 -log(0.802) ≈ 0.221，损失下降了。

    展开：可运行代码（最小 RM 一步） 
    """最小 RM：用 Bradley-Terry loss 更新一个 RM 的一步。"""
import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)

# 假设词表 V=10，response 长度 T=3
V, T, D = 10, 3, 8

# RM：embedding + 平均池化 + 线性输出标量
class TinyRM(nn.Module):
    def __init__(self, V, D):
        super().__init__()
        self.emb = nn.Embedding(V, D)
        self.proj = nn.Linear(D, 1)  # 输出一个标量 logit
    def forward(self, tokens):
        # tokens: (B, T) -> score: (B,)
        h = self.emb(tokens).mean(dim=1)  # (B, D) 平均池化
        return self.proj(h).squeeze(-1)   # (B,)

rm = TinyRM(V, D)
optimizer = torch.optim.Adam(rm.parameters(), lr=1e-2)

# 一条偏好对：(x, y_w, y_l) 拼成 token 序列
# 简化：直接给 y_w 和 y_l 的 token 序列
y_w = torch.tensor([[1, 2, 3]])  # winner
y_l = torch.tensor([[4, 5, 6]])  # loser

# Bradley-Terry loss: -log σ(r(y_w) - r(y_l))
r_w = rm(y_w)  # (1,)
r_l = rm(y_l)  # (1,)
loss = -F.logsigmoid(r_w - r_l).sum()
print(f"RM loss = {loss.item():.4f}")

# 反传 + 更新
loss.backward()
optimizer.step()

# 再算一次，loss 应该下降，且 r_w - r_l 应该变大
with torch.no_grad():
    new_r_w = rm(y_w)
    new_r_l = rm(y_l)
    new_loss = -F.logsigmoid(new_r_w - new_r_l).sum()
print(f"updated loss = {new_loss.item():.4f}")
print(f"r_w - r_l: before={r_w.item()-r_l.item():.4f}, "
      f"after={new_r_w.item()-new_r_l.item():.4f}")

    代码层次：第 1 层是 RM 网络结构（embedding + 池化 + 线性），第 2 层是 Bradley-Terry loss（logsigmoid），第 3 层是优化器。真实 RM 把网络换成 Transformer，loss 一样。

    读者容易卡在哪：(1) RM 输出是标量不是分布——和语言模型不同，最后是 Linear(D, 1) 不是 Linear(D, V)。(2) logsigmoid 内部已经做了 log + sigmoid，不要再手动算。(3) RM 通常用 SFT 模型初始化（embedding 共享），不是从头训。

    和真实工程的差距：真实 RM 用 Transformer backbone，处理 prompt 和 response 拼接，对 response 部分做池化（不是平均，而是取最后一个 token 或专门加 reward token）。InstructGPT 用约 31k 偏好对训 RM，只训 1 epoch 防过拟合（论文 §3.2、§3.4）。

    RM 的局限

    • 标注一致性有上限：InstructGPT 标注员一致性约 73%（论文 §3.4）。RM 学的是带噪声的人类判断，再大也学不过 73% 这个天花板。
    • 分布外失效：RM 只在标注数据分布上学得好，模型跑到没见过的 prompt 类型时 RM 分数不可信。
    • 容量有限：RM 把复杂的"好坏"压成一个标量，丢掉了"为什么好"的信息。

    这章讲了 RM：用 Bradley-Terry 把偏好对变成可微的标量损失，产物是奖励函数 rφ。它解决了"好坏怎么变成数字"，但 RM 只能打分不能优化模型——下一章看 PPO 怎么用 RM 当奖励做策略优化。

    第三阶段 PPO：用 RM 当奖励优化策略

    直觉

    现在有了 RM 当奖励函数，怎么用它优化语言模型？直接对 J(θ) = E[rφ(x, y)] 求梯度——这就是策略梯度（一类 RL 算法，直接对"策略参数"求奖励期望的梯度，形式 ∇θJ = E[奖励 × ∇log π(a|s)]）。但朴素策略梯度方差大、步长不稳，容易把模型训崩。PPO 用两个技巧解决：(1) clip 限制每次更新比例；(2) advantage 减小梯度方差。

    关键概念对照 RL 术语：

    • 状态 s = 已生成的 token 序列（prompt + 已生成部分）。
    • 动作 a = 采样下一个 token。
    • 策略 π(a|s) = 语言模型本身，给定已生成部分输出下一个 token 的分布。
    • 奖励 r = RM 给完整 response 打的分（episodic，只在序列结束给奖励）。
    • rollout = 让当前策略实际跑一遍生成 K 个回答（on-policy，策略用当前数据更新后必须重新采样）。

    流程

    1. 采样 rollout：从 prompt 分布 D 取一批 prompt，对每个用当前策略 πθ 生成 K 个 response（Stiennon 用 K=4）。
    2. RM 打分：对每个 (x, y) 算 rφ(x, y)。
    3. 算 advantage：用 value 网络 V(s)（估状态 s 的期望累计奖励）算 A = r - V(s)。A > 0 表示比平均好。
    4. 算概率比：rt(θ) = πθ(at|st) / πold(at|st)，新策略 / 采样时旧策略的概率比。
    5. clip 更新：把 rt(θ) 限制在 [1-ε, 1+ε]（PPO 论文 ε=0.2），防止单步更新太激进。
    6. 加 KL 惩罚：在损失里加 β·KL(πθ‖πref)，把策略拉回参考模型。
    7. 反传更新 θ，回到第 1 步，重复直到收敛（InstructGPT 训 200k-1M steps）。

    公式

    PPO 的核心损失（单条 (st, at)）：

    $$\mathcal{L}_{\mathrm{PPO}}(\theta) = -\mathbb{E}_t\Big[\min\big(r_t(\theta) A_t,\; \mathrm{clip}(r_t(\theta), 1-\varepsilon, 1+\varepsilon) A_t\big)\Big] + \beta \cdot \mathrm{KL}(\pi_\theta \,\|\, \pi_{\mathrm{ref}})$$

    符号说明：

    • LPPO(θ)：PPO 损失，越小越好（前面取负号因为我们要最大化 advantage×ratio）。
    • rt(θ) = πθ(at|st) / πold(at|st)：概率比，新策略 / 旧策略。1 表示没变。
    • At：优势函数 advantage，在状态 st 做动作 at 比平均好多少。At = R - V(st)，其中 R 是 RM 给该 response 的标量奖励，V 是 value 网络。（注意这里 R 是奖励，和上面的概率比 rt(θ) 不是同一个量。）
    • clip(r, 1-ε, 1+ε)：把 r 截断到 [1-ε, 1+ε] 范围内。ε=0.2 表示比例限制在 [0.8, 1.2]。
    • ε：clip 范围，标量。PPO 论文默认 0.2。
    • min(·, ·)：取两者较小值——这是 PPO 的核心，既限制上界也限制下界。
    • β·KL(πθ‖πref)：KL 惩罚项，β 是系数（InstructGPT 用 0.001 量级）。
    • Et：对所有 (st, at) 对取期望（平均）。
    展开：从策略梯度到 PPO clip 的推导

    问题陈述：为什么要 clip？为什么不直接用朴素策略梯度 ∇J = E[A·∇log π]？

    核心困难：朴素策略梯度允许单步更新任意大——如果某个动作 advantage 很高，梯度可能把它的概率推得极高，模型一步就崩了。需要一种机制限制"每次更新能改变策略多少"。

    第 1 步：从策略梯度到概率比。朴素策略梯度：

    $$\nabla_\theta J = \mathbb{E}\big[A_t \cdot \nabla_\theta \log \pi_\theta(a_t|s_t)\big] = \mathbb{E}\Big[A_t \cdot \frac{\nabla_\theta \pi_\theta(a_t|s_t)}{\pi_\theta(a_t|s_t)}\Big]$$

    引入概率比 rt(θ) = πθ(at|st) / πold(at|st)（πold 是采样时的旧策略，固定），可以写成：

    $$\nabla_\theta J = \mathbb{E}\big[A_t \cdot \nabla_\theta r_t(\theta)\big]$$

    验证：∇θ log π = ∇π / π = ∇(π/πold) / (π/πold) = ∇rt / rt。乘 rt 得 ∇rt。

    第 2 步：最大化 E[A·r] 但要限制 r。直接最大化 E[At·rt(θ)] 会让 r 在 A>0 时趋向无穷（πθ >> πold）。TRPO（PPO 前身）用 KL 约束限制，但求解复杂。PPO 改用 clip：

    $$J_{\mathrm{clip}}(\theta) = \mathbb{E}\big[\min(r_t A_t,\; \mathrm{clip}(r_t, 1-\varepsilon, 1+\varepsilon) A_t)\big]$$

    第 3 步：为什么取 min。分两种情况（At 的正负）：

    • At > 0（动作比平均好）：我们想让 rt 变大（多采样这个动作）。但 clip 把 rt 上界限制在 1+ε。如果 rt > 1+ε，clip 项 = (1+ε)At < rtAt，取 min 用 clip 项 → 梯度 = 0，不再奖励"过度增大"。
    • At < 0（动作比平均差）：我们想让 rt 变小。但 clip 把 rt 下界限制在 1-ε。如果 rt < 1-ε，clip 项 = (1-ε)At > rtAt（注意 At 是负数，(1-ε) > rt 所以乘 At 后 (1-ε)At 更小……这里需要仔细看），取 min 用 rt 项 → 梯度 = 0，不再惩罚"过度减小"。

    验证（At > 0, rt = 1.5, ε = 0.2）：clip(1.5, 0.8, 1.2) = 1.2。min(1.5·A, 1.2·A) = 1.2·A。梯度通过 min 选了 clip 项，rt 已经超出 1.2 不再获益。

    一句话总结：PPO 用 clip 把概率比限制在 [1-ε, 1+ε]，超出范围梯度归零，防止单步更新把策略推太远。取 min 保证无论 A 正负都能正确截断。

    符号总览：rt = 概率比；At = advantage；clip = 截断；min = 选更保守的梯度；ε = clip 范围。

    展开：最小数值例子

    （本文构造，教学用）

    假设当前 PPO 一步的数据：

    某个 (s_t, a_t) 的旧策略概率: π_old(a_t|s_t) = 0.25
新策略概率:                π_θ(a_t|s_t)   = 0.375
advantage:                 A_t            = +0.5  (比平均好)
clip 范围:                 ε              = 0.2   (论文默认)

    （1）算概率比 rt = 0.375 / 0.25 = 1.5

    （2）clip rt 到 [1-0.2, 1+0.2] = [0.8, 1.2]。1.5 > 1.2，所以 clip(rt) = 1.2

    （3）算两项

    原项:   r_t · A_t = 1.5 × 0.5 = 0.75
clip 项: clip(r_t) · A_t = 1.2 × 0.5 = 0.60

    （4）取 min = 0.60。因为 rt = 1.5 已超出 clip 上界 1.2，梯度被截断——再增大 rt 也不会增加目标，模型不会被鼓励把这个动作的概率推得更高。

    （5）KL 惩罚（简化估算）。假设 πθ 在某个 token 上 = 0.375，πref = 0.30，KL 贡献 ≈ 0.375·log(0.375/0.30) = 0.375·0.223 ≈ 0.084。若 β = 0.001，惩罚 ≈ 0.000084（很小，主要靠 clip 限制）。

    注意：实际 KL 是对所有 token 求和，这里只算一个 token 演示。

    展开：可运行代码（最小 PPO 一步） 
    """最小 PPO：对一个 tiny 策略做一步 PPO 更新。
简化：跳过 value 网络（用真实 reward 当 advantage 演示 clip 机制）。
真实 PPO 需要训练 value 网络估 V(s)。"""
import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)

V, D = 10, 8  # 词表大小, embedding 维度

class TinyPolicy(nn.Module):
    def __init__(self, V, D):
        super().__init__()
        self.emb = nn.Embedding(V, D)
        self.proj = nn.Linear(D, V)
    def forward(self, tokens):
        return self.proj(self.emb(tokens))  # logits (B, T, V)
    def logp(self, tokens):
        """返回每个位置 log π(a_t|s_t)，shape (B, T)"""
        logits = self.forward(tokens[:, :-1])
        targets = tokens[:, 1:]
        logp = F.log_softmax(logits, dim=-1)
        # 取出对应 target 的 logp
        return logp.gather(-1, targets.unsqueeze(-1)).squeeze(-1)

policy = TinyPolicy(V, D)
ref = TinyPolicy(V, D)
ref.load_state_dict(policy.state_dict())  # π_ref = 初始 π_θ
for p in ref.parameters():
    p.requires_grad_(False)

opt = torch.optim.Adam(policy.parameters(), lr=1e-3)

# 一批 rollout 数据（简化：假设已经采样好）
# old_logp: 采样时旧策略的 log π_old(a_t|s_t)
# reward: RM 给的标量奖励（这里用固定值 1.0 模拟）
# tokens: 采样得到的 token 序列
tokens = torch.tensor([[1, 2, 3, 4, 5]])  # (1, 5)
old_logp = policy.logp(tokens).detach()   # 用当前策略算一次并 detach
reward = torch.tensor([1.0])              # RM 打的分（模拟）
advantage = reward  # 简化：A = r，跳过 value 网络

# PPO 多个 epoch（用同一批数据更新几次，on-policy 但重复利用）
EPS = 0.2
BETA = 0.001

for ppo_step in range(4):
    new_logp = policy.logp(tokens)  # 新策略 log π_θ
    ratio = (new_logp - old_logp).exp()  # r_t = π_θ / π_old
    # advantage 广播到每个 token
    A = advantage.unsqueeze(-1).expand_as(ratio)

    # clip 项
    surr1 = ratio * A
    surr2 = torch.clamp(ratio, 1 - EPS, 1 + EPS) * A
    ppo_loss = -torch.min(surr1, surr2).mean()

    # KL 惩罚（简化：用新策略和 ref 的 logp 差近似）
    with torch.no_grad():
        ref_logp = ref.logp(tokens)
    kl = (new_logp.exp() * (new_logp - ref_logp)).mean()  # 近似 KL
    loss = ppo_loss + BETA * kl

    opt.zero_grad()
    loss.backward()
    opt.step()
    print(f"ppo_step={ppo_step} loss={loss.item():.4f} "
          f"ratio_mean={ratio.mean().item():.4f} kl={kl.item():.4f}")

print("done")

    代码层次：第 1 层是策略网络（TinyPolicy，和 SFT 的 TinyLM 结构一样），第 2 层是 PPO loss（ratio + clip + min），第 3 层是 KL 惩罚（简化估算），第 4 层是多次 epoch 重复利用数据。

    读者容易卡在哪：(1) logp 的 gather 操作：log_softmax 输出 (B, T, V)，要按 target 索引取出对应位置的概率，用 gather。(2) ratio = exp(new_logp - old_logp)：因为 π = exp(logπ)，所以 π_new/π_old = exp(logπ_new - logπ_old)，避免数值溢出。(3) old_logp 必须 detach：它是个常量，不参与梯度。(4) 为什么能跑多个 epoch：PPO 用 clip 保证即使重复利用数据，策略也不会偏离太远——这正是 clip 的设计目的。

    和真实工程的差距：(1) 真实 PPO 有 value 网络估 V(s)，advantage 用 GAE（Generalized Advantage Estimation）算，不是直接用 reward。(2) 真实 KL 是对所有 token 求和，不是 mean。(3) 真实工程用大规模分布式 rollout（多卡同时生成），InstructGPT 训 200k-1M steps，每步 batch 几百到几千 prompt。(4) 真实代码（HuggingFace TRL 的 PPOTrainer）还处理长度 padding、attention mask、value loss 系数等工程细节。本代码只演示 clip + KL 的核心机制。

    这章讲了 PPO：用 RM 当奖励、用 clip 限制更新步长、用 KL 拉回参考模型，产物是最终策略 πRLHF。三阶段讲完了——下一章看 RLHF 的代价和边界。

    RLHF 的边界：什么时候不用

    RLHF 解决了"偏好无法直接写成 loss"的问题，但它本身有代价。这一章讲清楚什么时候该用、什么时候该换别的方法。

    RLHF 的代价

    • 标注仍贵：虽然比较比写答案便宜 10-100 倍，但要做出能用的 RM，InstructGPT 用了约 31k 偏好对（论文 §3.2 表 1）。大规模对齐 still 要花真金白银。
    • 训练不稳：PPO 超参敏感（β、ε、learning rate、value 网络学习率、rollout 数 K），调参比 SFT 难得多。开源社区报告 PPO 复现经常崩。
    • RM 上限：RM 学的是人类标注的判断，标注员一致性 73% 是天花板。RM 越大越过拟合标注噪声。
    • Reward hacking：模型可能钻 RM 空子。InstructGPT 论文描述了案例——模型输出冗长重复内容刷分。KL 惩罚能缓解但不能根治。
    • 在线采样贵：PPO 是 on-policy，每步都要用当前模型生成新 response（rollout）。生成是 LLM 推理，比前向慢。

    替代方案对比

    方法解决什么不解决什么什么时候用
    RLHF（三阶段）用偏好对齐模型、可在线优化、有 RM 可复用训练稳、成本低、RM 噪声需要在线探索、有标注预算、追求 SOTA 对齐质量
    DPO跳过 RM 和 RL，直接用偏好对训策略，训练像 SFT 一样稳没有 RM 可复用、没有在线探索偏好数据已有、不需要在线采样、想要简单稳定的训练
    RLAIF用 AI 评委代替人类，标注成本接近 0AI 评委本身的偏差、人类偏好保真度预算紧、任务适合 AI 评估（如摘要、代码）
    GRPO去掉 value 网络、用 group baseline，比 PPO 简单仍需在线采样、仍可能 reward hacking推理任务（DeepSeek-R1）、想简化 PPO 流程
    SFT only最简单、最稳学不了偏好、上限低冷启动、小模型、对齐要求不高

    选择建议

    1. 预算紧、偏好数据已有 → 优先试 DPO。简单稳定，效果接近 RLHF。
    2. 需要在线探索、追求 SOTA → RLHF（PPO 或 GRPO）。能持续从模型新输出里学。
    3. 任务适合 AI 评估 → RLAIF。但要验证 AI 评委和人类偏好一致。
    4. 推理任务 → GRPO（DeepSeek-R1 路线，group size 64，论文 §3.2）。
    5. 刚起步 → SFT 先把模型拉到能用，再考虑对齐。

    这章讲了 RLHF 的代价（标注贵、训练不稳、RM 上限、reward hacking、在线采样贵）和替代方案（DPO/RLAIF/GRPO/SFT）。选哪种取决于任务、预算、数据和工程能力。
