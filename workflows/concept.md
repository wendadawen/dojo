# 概念学习文档写作流程

**产物**：纯 HTML + KaTeX（本地库）。每个概念一个目录，主入口 `index.html`。

**读者画像**：完全不懂这个领域的小白。有技术基础但不懂这个概念。30 秒能抓要点，展开折叠能看到完整推导、数值例子和可运行代码。

**模板**：`templates/concept/index.html`，拷贝改。

**首页**：新增内容后改 `content.json`，再运行 `python scripts/generate_index.py`。

---

# 一、流程

### 1. 研究阶段（不许碰 HTML）

不许看已有概念页面。每个步骤产出写成文档，放在 `content/concepts/<concept-name>/research/` 下，不提交（加 `.gitignore`）。

1. **确认读者目标**：读者想看懂什么？读完要能回答哪 3-5 个问题？→ `research/reader-goal.md`
2. **确认概念边界**：这个概念指什么？不指什么？有没有同名/相邻概念？→ `research/concept-boundary.md`
3. **收集权威来源**：官方文档、论文、源码、实测。第三方只辅助，不作核心事实来源。→ `research/sources.md`
4. **列术语/符号清单**（硬门槛）：页面会用到的每个概念、符号、术语、缩写、专业比喻，每个写清小白解释和第一次出现的位置。→ `research/terms.md`
5. **列数字来源清单**（硬门槛）：页面会用到的每个数字，标注来源。找不到的查到、标"本文构造"、或删掉。→ `research/numbers.md`
6. **设计理解路径**：按七个认知阶段设计，决定哪些合并、拆分、跳过，为每个阶段想标题。→ `research/understanding-path.md`

### 2. 准备目录

```bash
mkdir -p content/concepts/<concept-name>
cp templates/concept/index.html content/concepts/<concept-name>/index.html
```

### 3. 写顶部模块

按顺序写：标题 → callout（问题/方案/产物）→ context-box（大流程/旧方案/痛点/改变点）→ 读完你能回答（3-5 个）→ 最容易误解（2-4 个）→ meta（来源，不设前置列表）→ 小白版一句话定义。

### 4. 写正文

按理解路径写，覆盖七个认知阶段。具体规范见"二、规范"。

### 5. 读者审计

把自己当完全小白，从头读到尾。逐项检查（见"三、核查清单"）。修完再读一遍，第二遍没有新标记才算通过。

### 6. 更新首页

在 `content.json` 增加条目：

```json
{
  "id": "concept-name",
  "section": "concepts",
  "tag": "concept-name",
  "title": "概念名：一句话概括",
  "desc": "读者点进来能学到什么",
  "path": "content/concepts/concept-name/"
}
```

运行：

```bash
python scripts/generate_index.py
python scripts/validate_content.py
python scripts/audit_concept.py
```

# 二、规范

## 七个认知阶段

读者读完必须能回答：

1. 它在哪：属于哪个大流程
2. 之前怎么做：旧方案
3. 为什么不够：旧方案的问题
4. 它改了什么：核心思路
5. 它是什么：定义
6. 它怎么工作：机制
7. 什么时候用：边界

推荐按这七个阶段组织正文，允许合并、拆分、跳过。

## 主文档结构

```text
标题
阅读时间
callout：问题 / 方案 / 产物
context-box：大流程 / 旧方案 / 痛点 / 改变点
读完你能回答
最容易误解
meta：来源
小白版一句话定义

正文（覆盖七个认知阶段，标题自由命名）
  ……

证据边界声明
```

## 标题

- 是一句话，不是单个词
- 告诉读者这章讲什么
- 不用比喻或抽象词（如"旧世界""断点""新想法"）
- 不超过 20 字

## 检查点

在"它改了什么"阶段末尾，必须有检查点。引导句单独 `<p>`，检查项单独 `<ul>`：

```html
<p>读到这里，你应该已经能解释：</p>
<ul>
  <li>……</li>
</ul>
```

## 导语

每章后用 1-2 句自然导语说明这章推进了哪一步，然后过渡到下一章。不写"本章你将知道"。过渡要告诉读者"这章解决了什么，下一章要解决什么"。

## 术语

- 第一次出现时必须就地解释（括号或破折号）
- 折叠块里的解释不算首次解释
- 专业比喻（锚点、环境、baseline）第一次出现也必须解释
- callout 里出现的术语必须在 callout 里就地解释
- 不设前置列表，所有术语本页解释

## 公式

- 每个符号必须已解释过，没解释的先解释再写公式
- 公式后紧跟完整符号说明列表，每个符号一句话
- 旧世界章节给直觉版公式 + 简短符号说明，完整推导留给机制章节
- 同一公式不重复给完整推导

## 推导折叠块

如果概念有核心公式或算法，推导折叠块必须有。不允许只给公式不给推导。

结构：

```
问题陈述 → 核心困难 → 第 1 步 → 第 2 步 → ... → 一句话总结 → 符号总览
```

- 每步包含：变换 + 为什么需要 + 验证（关键步骤）
- 关键步骤分情况讨论
- 每步变换后读者能解释"为什么允许这样变"
- 核心机制从"为什么不能直接做"讲起，不只讲"怎么做"

## 数值例子折叠块

每个子概念至少一个数值例子。每步展示计算公式和中间结果，不能只给结果。本文构造的数字在例子开头标注"（本文构造，教学用）"。

规模：每个角色都出现、小数字手算、1 分钟走完。算法类 3-5 token / 1-2 步采样；系统类 2-3 个组件 / 1 个请求。

## 代码折叠块

涉及算法实现的概念，必须给可运行代码，不能只给伪代码或 API 示意。伪代码和可运行代码可以同时有，放不同折叠块。

- 关键函数/类必须对应正文讲过的概念
- API 必须查当前文档确认真实
- 超参标来源（论文/工程实践/本文构造）
- 默认 Python
- 可运行代码后必须说明：代码层次、读者容易卡在哪、和真实工程差什么

## 断点

断点要落到具体场景，不写空泛形容词。比如不写"标注成本高"，而是写"写一条高质量示范 ≈ 比较两个答案谁更好的 10-100 倍成本"。

## 因果链

子概念之间要有因果链。读者能看出"为什么 A 不够 → 需要 B → 为什么 B 不够 → 需要 C"。每一步在回答上一步产生的问题。

## 重复控制

每个概念在一个地方讲完整，其他地方只引用。每章只讲自己负责的侧面。同一公式不重复给。

跨章节引用：括号引用（`SFT（见第 X 章）`）或文字指引（`SFT 的做法在第 X 章已经讲过`）。不重复解释，不用脚注链接。

## 列表

- `<ol>`：推导步骤、计算序列、流程步骤。判断标准：跳一步跟不上
- `<ul>`：指标、特征、观察。判断标准：换序不影响理解
- 段落：解释、论证、只有一两步不值得列表的内容

## 图示

该画图：流程多步、组件有层级、数据流有分支或循环。简单用 ASCII（`<pre class="diagram">`），复杂用图片（base64 内联）。不该画图：只有 2 个节点、图和文字说同一件事。

## 折叠块

适合折叠：完整推导、长代码、源码细节、配置示例、数值例子。

不许只放折叠：关键假设、核心直觉、会改变结论的限制条件、主路径术语的解释。

## 子概念

如果概念有多个子流程（如 SFT/RM/PPO），每个都要完整讲：直觉 + 公式 + 推导 + 数值 + 代码。不允许只讲一个，其他略过。

## 证据边界声明

按来源分：官方文档 / 论文 / 官方源码 / 实测 / 解读者推断。事实和推断分开。

# 四、铁律

1. **研究没完成不许碰 HTML**：术语清单和数字清单是硬门槛。
2. **术语第一次出现必须就地解释**：折叠块不算。
3. **公式符号必须先解释**：没解释的符号不许出现在公式里。
4. **每个数字必须标来源**：论文/源码/实测/本文构造。
5. **核心推导不能省**：有公式就有推导折叠块。
6. **子概念必须完整讲**：直觉+公式+推导+数值+代码。
7. **读者审计必须做两遍**：第二遍没有新标记才算通过。
