# step 4：审计

AI 当独立审稿人，扮演读者代言人，从头到尾读 `index.html`，挑出读者会卡住的地方。产出 `step4-审计.md`。

## 角色设定

- 不是作者，是读者代言人
- 不是检查技术违规，是检查读者能不能看懂
- 不是自我审查——这个 AI 不能是写初稿的那个 AI
- 审计报告小白也能看懂——写清"哪里有问题、为什么是问题、读者会卡在哪"

## 输入

- `content/concepts/<name>/index.html` — step 3 的初稿
- `step2-大纲.md` — 应该覆盖哪些认知阶段
- `step1-术语.md` — 术语清单，检查是否都解释了
- `step1-数字.md` — 数字清单，检查是否都标来源
- `step1-推导链条.md` — 推导步骤，检查有没有跳步
- `step1-读者障碍.md` — 障碍点清单，检查是否都解决
- `content-guide.md` — 硬规则清单，检查有没有违反

## 产出

`step4-审计.md`，按问题分类列出：

### 结构问题

- 认知阶段有没有漏
- 子概念详细程度是否按核心/辅助分配
- 折叠块分配是否合理，主文有没有丢关键内容

### 术语问题

- 有没有术语首次出现没解释
- 折叠块外的术语是不是在折叠块外解释
- callout 里术语是不是在 callout 里解释
- 公式符号是不是出现前已解释

### 推导问题

- 核心公式有没有推导折叠块
- 推导有没有跳步
- 每步有没有写变换 + 原因
- 推导三要素（问题陈述/分步骤/总结）全不全

### 数字和证据问题

- 每个数字有没有标来源
- 本文构造的数字有没有标注
- 每条论断有没有出处
- 事实和推断有没有分开

### 代码问题

- 算法概念有没有可运行代码
- 代码后有没有说明和真实工程差在哪
- API 是不是查过当前文档
- 关键函数有没有对应正文概念

### 读者障碍问题

- `step1-读者障碍.md` 里的每个障碍点有没有对应解决位置
- 读者读到哪会卡住、为什么、怎么解决

### 模板残留问题

- HTML 注释、占位符、施工标记有没有删干净
- 旧模板的 class 名有没有残留

## 审计报告格式

每个问题写三段：

1. **位置** — 哪个章节、哪段、哪行
2. **问题** — 读者会卡在哪、为什么会卡
3. **建议** — 怎么改

不要写技术违规清单，要写读者视角的问题描述。

## 审核标准

审计报告是否：

- 覆盖所有 7 类问题（结构/术语/推导/数字证据/代码/读者障碍/模板残留）
- 每个问题都有位置、问题、建议三段
- 用小白能看懂的语言写
- 不是技术性违规清单，是读者视角

报告完整才进 step 5。
