# 阶段 5：修复、复验与发布

本阶段根据 `research/review.md` 修复页面，由原审查者对修复点复验，最终提交人工确认并发布。

---

## 1. 输入

```text
content/concepts/<name>/
├── index.html
└── research/
    ├── review.md
    └── confirmations.md
```

开始修复前确认：`review.md` 每个问题的级别、位置、问题、修法齐全；结论中的处置为"进入修复"。处置为"需改变研究范围"或"需改变教学大纲"时，停止修改，将结论和确认材料提交人工决策，由用户决定返回阶段 1、返回阶段 2 或接受现状。

---

## 2. 修复

- 按阻断 → 重要 → 轻微的顺序处理；同一根因导致的多个问题可以合并修改，但不合并或删除原问题行
- 每条问题修复后，在该行回填：`修复：已改，<一句话说明改动>`；决定不修的问题回填：`修复：不修，遗留，<接受理由>`
- 修复不得引入未经确认的新核心内容；修复中发现新的范围或大纲问题时停止修改，按第 1 节提交人工决策
- 修改涉及声称可运行的代码时，重新执行并核对输出；修改完成后运行一次 `scripts/concept/validate.py`

## 3. 复验

将全部已修复问题交回原审查者复验。优先恢复同一审查上下文；无法恢复时用全新上下文，并把 `review.md` 作为其输入。

审查者按任务包的复验规则逐条回填"复验"字段。修复者不回填"复验"字段。

最多 2 轮：第一轮修复与复验后仍有失败项时，进行第二轮修复与复验；第二轮后仍有未关闭的阻断或重要问题时停止修改，更新结论统计，提交人工决策。

## 4. 最终确认（门槛 3）

确认材料限一页：

- 问题统计：阻断 / 重要 / 轻微的数量与关闭状态
- 遗留轻微问题及接受理由
- `scripts/concept/validate.py` 的命令和结果
- 代码重跑结论：每个代码块的实际执行结果与页面描述一致
- 页面的适用范围和明确不展开的内容（一段）

按 `workflows/concept.md` 第 7 节的仪式执行确认。

## 5. 发布

确认通过后：

1. 更新仓库根目录的 `content.json`
2. 从仓库根目录运行 `python3 scripts/generate_index.py`，确认命令成功退出
3. 检查首页条目标题、描述和链接目标，从首页实际打开概念页确认正常加载
4. 将发布结果追加到 `review.md` 末尾：

```markdown
## 发布记录

- 最终页面版本：<commit 或工作树哈希>
- content.json 更新：<条目 id>
- generate_index.py：退出码 0
- 首页检查：<条目、链接和页面加载的实际结果>
- 时间：<日期和时间>
```

确认退回时不得更新 `content.json` 或首页；按退回意见处理（局部问题新建问题行进入修复；范围或大纲问题提交人工决策）。
