# step 5：修复

按 `step4-审计.md` 修 `index.html`。问题清零后由人工最终确认才发布。

## 输入

- `content/concepts/<name>/index.html` — 待修的初稿
- `step4-审计.md` — 问题清单

## 修复顺序

1. 模板残留问题——删干净 HTML 注释、占位符、施工标记、旧 class 名
2. 结构问题——补漏的认知阶段、调整子概念详细程度、调整折叠块分配
3. 术语问题——补术语首现解释、把折叠块外的术语解释挪到折叠块外
4. 推导问题——补推导折叠块、补跳掉的步骤、补三要素
5. 数字和证据问题——补数字来源、补论断出处、分清事实和推断
6. 代码问题——补可运行代码、补"和真实工程差在哪"、查 API、对应正文概念
7. 读者障碍问题——在每个障碍点位置补解决方案

## 修复要求

- 每个问题独立修，不要顺手改其他东西
- 修完一个问题就更新 `step4-审计.md`，标"已修"
- 修复时如果发现新问题，追加到 `step4-审计.md` 末尾
- 修复不能引入新问题——改完每条都自检有没有破坏别处
- 修复不能偷工减料——"补推导"要补完整步骤，不是补个结论

## 修复完成检查

- `step4-审计.md` 里所有问题都标"已修"
- 没有"待修""未修""待补"标记
- 修复期间追加的新问题也都标"已修"

## 发布

修复完成后由人工最终确认：

- 人工读一遍 `index.html`，重点看修复过的位置
- 人工确认没问题才发布
- 发布前在 `content.json` 增加条目：

```json
{
  "id": "concept-name",
  "section": "concepts",
  "tag": "concept-name",
  "title": "概念名：一句话概括",
  "desc": "读者点进来能学到什么",
  "path": "content/concepts/concept-name/"
}
```

- 运行 `python scripts/generate_index.py` 更新首页

人工确认未通过，回 step 4 重新审计。
