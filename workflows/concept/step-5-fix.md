# 阶段 5：问题修复、复验与发布确认

本阶段根据技术审查和小白审查的问题编号修复页面，并由对应审查者复验。修复者负责修改和提交复验，不负责判定问题通过。

阶段 5 不是一次性收尾步骤。局部问题在阶段 4 和阶段 5 之间循环；需要改变研究范围或教学大纲时，返回对应阶段重新确认。

---

## 1. 输入

必须读取：

```text
content/concepts/<name>/
├── index.html
└── research/
    ├── scope.md
    ├── evidence.md
    ├── outline.md
    ├── draft-check.md
    ├── technical-review.md
    └── beginner-review.md

workflows/concept/content-examples.md
```

各输入的职责：

- `index.html`：待修复页面
- `scope.md`：已确认的内容范围和核心问题
- `evidence.md`：已确认的论断、公式、数字和来源
- `outline.md`：已确认的教学设计
- `draft-check.md`：初稿输入版本和基础检查记录
- `technical-review.md`：技术问题、状态事件和复验记录
- `beginner-review.md`：小白视角问题、状态事件和复验记录
- `content-examples.md`：局部修复的正例、反例和判断标准

---

## 2. 输入门槛

开始处理前，共同确认：

- 问题具有唯一编号、严重程度、具体位置、影响、修改要求和复验方法
- 报告已区分局部修复、返回阶段 1和返回阶段 2
- 审查报告的独立性状态和发布资格已记录

然后根据当前状态进入且只进入一个分支：

### 2.1 局部修复分支

- 当前状态属于 `待修复` 或 `复验失败`
- 审查报告记录的页面版本与待修页面版本一致
- 版本不一致时，必须先由对应审查者追加“当前版本适用性确认”，记录当前页面哈希、新位置和判断依据
- 结论为“继续有效”时可以进入局部修复；结论为“已失效”时，审查者必须同时按阶段 4 的格式追加 `已失效` 状态事件，修复者不得继续处理该问题

### 2.2 上游回退分支

- 当前状态属于由对应审查者追加的 `返回阶段 1` 或 `返回阶段 2`
- 阶段 5 只组织回退执行和记录，不修改审查者的回退判定

问题记录不完整时，先交回对应审查者补全，不根据模糊建议直接修改。

## 3. 产物

本阶段更新：

```text
content/concepts/<name>/
├── index.html
└── research/
    ├── fix-log.md
    ├── technical-review.md
    ├── beginner-review.md
    └── draft-check.md
```

- `index.html`：修复后的页面
- `fix-log.md`：修复分组、变更位置、验证结果和页面版本历史
- 两份审查报告：只追加状态事件和复验记录，不覆盖原始问题
- `draft-check.md`：更新受修改影响的基础检查和代码运行记录

## 4. 修复前分类

对当前所有未关闭问题进行分类：

| 类型 | 处理方式 |
|---|---|
| 页面偏离正确的 `scope.md`、`evidence.md` 或 `outline.md` | 阶段 5 局部修复 |
| `scope.md` 或 `evidence.md` 的语义需要改变 | 只能执行审查者已判定的“返回阶段 1” |
| `outline.md` 的语义需要改变 | 只能执行审查者已判定的“返回阶段 2” |
| 问题记录不完整或无法定位 | 交回阶段 4 补充审查记录 |
| 当前页面版本中问题已经不存在 | 交回审查者判定 `已失效` |
| 轻微问题决定不修 | 加入最终遗留清单，等待最终人工确认 |

### 4.1 阶段 1 回退

以下变化必须返回阶段 1：

- 概念含义或边界改变
- 核心问题、核心内容或排除范围改变
- 需要新增外部事实、核心公式或关键数字并补充证据
- 现有证据冲突或不足需要重新裁定
- 常见误解或适用边界的正确结论改变

阶段 1 完成修改和研究范围重新确认后，原教学大纲确认自动失效，必须重新执行阶段 2。新页面和新审查产生后，原回退问题由对应审查者处理：若原依据因上游版本变化失效，追加 `已失效`；若同一复验条件仍适用，则在新页面上复验后追加 `复验通过`；当前页面仍存在实际问题时创建新问题编号。

### 4.2 阶段 2 回退

以下变化必须返回阶段 2：

- 页面开头设计改变
- 章节目标、数量或顺序改变
- 贯穿问题或贯穿例子改变
- 基础知识安排改变
- 讲解材料、内容深度或教学简化改变
- 正文与折叠块分工改变
- 核心问题与章节覆盖关系改变
- 常见误解或边界的处理位置改变

阶段 2 重新确认后，按照新大纲重新执行受影响的阶段 3 内容，再进入新的独立审查轮次。原回退问题由对应审查者按新页面实际情况追加 `已失效`、`复验通过` 或创建新问题编号。

### 4.3 回退优先级

同一问题同时影响研究范围和教学大纲时，先返回阶段 1。研究范围确认通过后，再更新并确认教学大纲。

不得通过局部修改 `index.html` 绕过上游确认门槛。

---

## 5. 修复优先级

修复顺序由依赖关系决定：

1. 阶段回退项
2. 阻断问题
3. 会影响多个位置的共同根因
4. 重要问题
5. 轻微问题
6. 最终遗留问题整理

同一级别中，先处理会影响后续修复的问题。例如，术语定义错误会影响公式、推导和代码说明时，先修正术语和定义，再修复依赖位置。

不得仅按问题编号顺序修改，也不得先做排版修复而推迟核心错误。

---

## 6. 按根因组织修复

多个问题由同一原因造成时，先建立修复组：

```markdown
## Fix-G1：<根因标题>

- 根因：...
- 包含问题：T-001、B-003、B-004
- 受影响位置：...
- 上游依据：scope.md#Q1、outline.md#S2、evidence.md#F1
- 统一修复方案：...
- 不改变的范围和大纲：...
- 复验要求：...
```

修复组用于统一修改，不合并或删除原问题编号。每个问题仍需由对应审查者分别复验。

以下做法不合格：

- 每遇到一个术语问题就在原句后增加括号，造成重复解释
- 每遇到一个“缺少上下文”问题就增加新段落，不调整信息顺序
- 为修复推导跳步复制整段公式，产生多个不一致版本
- 为修复代码问题只修改预期输出，不修正实际实现

---

## 7. 单个问题修复流程

### 7.1 读取问题

确认：

- 问题编号和当前状态
- 页面版本和稳定位置
- 关联 Q/K/B/M/C/F/N 编号
- 判断依据
- 修改要求
- 复验方法

### 7.2 确定修复边界

写明：

- 需要修改的位置
- 受影响的引用、公式、代码、例子或章节
- 根因
- 同类位置的搜索范围和结果
- 作为单项修复而不建立修复组的理由
- 不应改变的已确认范围、大纲和语义
- 修复后必须保持的不变量
- 修改后必须重新执行的检查

### 7.3 修改页面

按照已确认的 `scope.md`、`evidence.md` 和 `outline.md` 修改。局部写法参考 `content-examples.md`。

修复过程中发现新的范围或大纲问题时停止修改，按第 4 节回退。不得由修复者自行扩展修复范围。

### 7.4 更新过程记录

更新 `fix-log.md` 和受影响的 `draft-check.md`。修复者在对应问题下追加状态事件：

```markdown
#### 状态事件 E<n>

- 操作者：<修复者>
- 时间：<日期和时间>
- 页面版本：<修复后哈希或版本>
- 状态：已提交复验
- 说明：<修改位置和摘要>
```

修复者只能追加 `已提交复验`；`返回阶段 1`、`返回阶段 2`、`复验通过`、`复验失败` 和 `已失效` 只能由对应类型审查者追加。

### 7.5 提交复验

将以下内容交回对应审查者：

- 问题编号
- 修复后页面版本
- 修复位置
- 修改摘要
- 实际执行的检查和结果
- 原问题规定的复验方法

技术问题交回技术审查者；小白问题交回小白审查者。

## 8. 不同问题类型的修复要求

### 8.1 范围、定义和事实

- 页面表述与 `scope.md` 一致
- 外部事实与 `evidence.md` 的来源、条件和结论范围一致
- 不用更弱或更强的措辞改变来源结论
- 新事实若不必要则删除；若必须保留则返回阶段 1 补证据

### 8.2 基础知识和术语

- 在首次依赖前完成讲解
- 解释达到 `outline.md` 规定的完成标准
- 不用更多未解释术语构成循环定义
- 同一术语保持一致含义
- 根因是信息顺序时，调整顺序而不是重复补括号

### 8.3 公式和符号

- 使用已确认 F/C 编号、已确认公式的直接推导或明确教学构造
- 修正公式后同步检查符号说明、数字例子、推导、代码和后文引用
- 重新执行边界、对称、不变量或简单代入检查
- 公式变化可能改变核心结论时返回阶段 1

### 8.4 推导

- 补充真正缺失的关键步骤和成立理由
- 修正后从起点到结论独立复算
- 同步检查分情况讨论和适用条件
- 保留正文所需的关键推理，不把全部修复内容移入折叠块

### 8.5 数字例子

- 重新计算全部中间结果和最终结果
- 检查单位、条件和四舍五入
- 同步修改表格、正文结论和代码输出
- 教学数字继续明确标记，不转写为外部事实
- 例子不能支持正文结论时：页面只是偏离已确认结论则按上游依据修正页面；正确结论或边界需要变化则返回阶段 1；需要删除、更换或改变例子的教学职责则返回阶段 2

### 8.6 类比和教学解释

- 写明类比只解释的局部关系
- 补充失效边界
- 回到正式定义、公式或机制
- 页面类比偏离已确认大纲时按大纲修正；需要删除、更换或改变类比职责时返回阶段 2；类比暴露研究结论或边界错误时返回阶段 1

### 8.7 图示

- 修正节点、箭头、方向、循环和符号
- 同步修改正文对图的解释
- 保证删除图示后正文仍能回答核心问题
- 更新图片资源、替代文本和说明文字

### 8.8 伪代码

- 修正输入、状态、核心步骤和输出
- 存在循环时补充循环范围和停止条件
- 与正文公式和变量保持一致
- 展开被黑箱词隐藏的核心机制
- 保持 `language-text`，不冒充可运行代码

### 8.9 可运行代码

- 修正实际实现，不只修改预期输出
- 保持公式变量与代码变量映射
- 重新执行代码并记录环境、命令、退出码和实际输出
- 同步修改正文观察重点和工程差异
- 页面错误声称可运行时，先修复实现或在安全环境验证；若需要删除大纲已确认的可运行代码、改变代码职责或降低内容深度，返回阶段 2，不得只删除“可运行”声明绕过大纲

### 8.10 正文与折叠块

- 必要定义、推理步骤、观察结果和结论保留在正文
- 折叠块只承载补充证明、完整展开、完整代码或扩展内容
- 修复后在全部折叠块收起的状态下重新阅读主线
- 正文不得引用只能在折叠块内看到的新结论

### 8.11 HTML、资源和交互

- 修正标签闭合、标题层级、重复 ID、链接、资源路径和代码语言类名
- 重新检查目录、主题切换、折叠块、公式渲染、阅读进度和返回顶部
- 页面主标题、`<title>` 和 `.nav-brand` 保持一致
- 修复 HTML 时不得删除或改变正文语义

## 9. 修复后的回归检查

每次修复后，根据变更影响执行回归检查。

### 9.1 检查范围

每次修复必查：

- 修改位置本身
- 直接引用该位置的内容
- 共享标识、编号、术语、变量或符号

按变更影响追加检查：

- 改动公式或计算：检查相关推导、数字例子、图示、伪代码和代码
- 改动定义或结论：检查对应核心问题和章节完成检查
- 改动正文与折叠分工：检查全部折叠块收起时的正文完整性
- 改动章节顺序、贯穿内容或多个位置：执行对应类型的全页回归

只修改不改变语义的标点或排版时，不强制执行与该变更无关的全量检查，但必须记录检查范围选择依据。

### 9.2 必须追加技术复验的变化

为解决小白审查问题而进行的修改，只要涉及以下内容，就必须追加技术复验：

- 外部事实或来源表述
- 概念定义或适用边界
- 公式、符号或推导
- 数字、单位或计算
- 代码、伪代码或图示机制
- 教学简化及其条件

仅调整不改变含义的标点、排版或连接句时，可以只由小白审查者复验，但必须记录为何不需要技术复验。

### 9.3 必须追加小白复验的变化

技术修复只要改变正文顺序、术语解释、例子、章节过渡、折叠分工或阅读路径，就必须追加小白复验。

### 9.4 全页回归

同一修复组影响多个章节、核心定义或贯穿例子时，不只复验局部问题，还应重新执行对应类型的全页覆盖检查。

### 9.5 交叉复验记录

触发技术或小白交叉复验时，在 `fix-log.md` 和对应审查报告中记录：

```markdown
### Cross-R1

- 触发问题：B-003
- 触发原因：修改了公式、数字或阅读路径
- 复验类型：技术 / 小白
- 复验者：...
- 页面版本：...
- 复验方法：来源核查 / 复算 / 代码运行 / 顺序阅读
- 实际结果：...
- 结论：通过 / 失败
- 新问题编号：无 / T-xxx / B-xxx
- 对应报告记录：technical-review.md#... / beginner-review.md#...
```

原问题只有在同一页面版本所需的全部交叉复验通过后，才能由原类型审查者追加 `复验通过`。交叉复验失败时，对应类型审查者创建新问题编号，原问题保持未关闭或追加 `复验失败`。

交叉复验的轮次按以下规则计算：

- 对应类型存在尚未结束的轮次：交叉复验加入该轮
- 对应类型最近一轮已经结束：交叉复验启动该类型的下一轮
- 最近一轮已经是第 3 轮：不得自动开始新的交叉复验修复循环，先进入人工决策
- 交叉复验失败后需要再次自动修复：下一次修复进入该类型的下一轮

## 10. 复验

### 10.1 复验者

复验由原问题对应类型的独立审查者执行。无法使用原审查者时，可以由满足相同独立性条件的新审查者执行，但必须重新读取原问题、修复记录和当前页面，并在复验记录中说明更换原因。

### 10.2 复验输入

复验者读取：

- 原问题及历史状态事件
- 原问题规定的复验方法
- 修复记录
- 修复后页面版本
- 受影响的 `scope.md`、`evidence.md`、`outline.md` 和 `draft-check.md`
- 必要的原始来源或运行环境

### 10.3 复验要求

复验者必须：

1. 使用原问题的复验方法检查修复结果
2. 检查修改是否满足可验证条件
3. 检查是否引入新问题
4. 根据需要复算、运行代码或检查页面
5. 追加复验记录和状态事件

### 10.4 复验结果

#### 复验通过

满足以下条件：

- 原问题已经不存在
- 修改要求全部满足
- 没有引入同级或更严重的新问题
- 必要回归检查通过

审查者追加 `复验通过` 状态事件和复验记录。

#### 复验失败

以下任一情况成立：

- 问题仍存在
- 只修复表现，没有解决根因
- 修改要求未全部满足
- 引入新的阻断或重要问题
- 回归检查失败

审查者追加 `复验失败` 状态事件，写明残留问题和下一次修复要求。新出现的独立问题使用新编号。

#### 已失效

原问题在当前页面版本中已经无法定位，且不是因为已验证修复时，审查者追加 `已失效`。如果当前版本仍存在同类问题，必须创建新编号，不得用“已失效”代替问题关闭。

---

## 11. 审查轮次

技术审查和小白审查分别计数。

初次审查及其第一批修复和第一次复验计为第 1 轮。每一轮包含：

```text
审查者提交或继承本轮未关闭问题
→ 修复者完成一批修改并提交复验
→ 同一类型审查者对本批全部问题给出复验通过或复验失败
```

本轮所有提交问题得到 `复验通过` 或 `复验失败` 判定后，该轮结束。存在 `复验失败` 时，下一次自动修复及复验必须计入下一轮，不得继续记在原轮次。

复验发现的新问题记录在当前轮；若需要自动修复，则在下一轮处理。技术审查和小白审查分别计数，交叉复验计入执行复验的对应类型轮次。

### 11.1 三轮上限

第 3 轮复验出现任何未关闭的阻断或重要问题时，立即停止自动修改，进入人工决策。不得自动开始第 4 轮。人工决策可以选择：

- 返回阶段 1 缩小或修正研究范围
- 返回阶段 2 调整教学设计
- 继续人工修复，并明确新的复验安排
- 终止本次发布

决策、理由、后续责任和轮次处理方式记录在 `fix-log.md`。阶段 1 或阶段 2 回退后，审查轮次默认保留；只有人工决策明确批准重置时才可重置，并记录理由。

### 11.2 轻微问题

轻微问题不阻止结束审查轮次。未修复的轻微问题进入最终遗留清单，记录：

- 问题编号
- 影响
- 未修复原因
- 接受理由
- 最终确认结果

## 13. 进入最终发布确认的条件

全部满足以下条件后，方可进入最终人工确认：

- 技术审查和小白审查均具有有效发布资格
- 所有阻断问题处于 `复验通过` 或 `已失效`
- 所有重要问题处于 `复验通过` 或 `已失效`
- `返回阶段 1` 和 `返回阶段 2` 的问题已经完成回退、重新确认、重写和重新审查，并由对应审查者追加 `复验通过` 或 `已失效`
- 技术审查和小白审查分别满足以下一种情况：在三轮内通过；或第 3 轮后已经停止自动修改，存在人工决策和人工复验安排，且所有阻断和重要问题已按该安排关闭。任何情况下均未自动开始第 4 轮
- 所有作为本次发布依据的技术或小白交叉复验通过记录均绑定准备发布的最终页面版本；历史上被后续版本取代的交叉复验只保留记录，不作为最终依据
- 轻微遗留问题已记录影响和接受理由
- 所有声称可运行的代码在最终页面版本上重新执行
- 核心公式、推导和数字例子在最终页面版本上完成复算
- 页面、资源、链接、锚点、重复 ID、HTML 标签、公式渲染和交互在最终页面版本上完成检查
- 折叠块全部收起时，正文仍能回答全部核心问题
- `scope.md`、`evidence.md`、`outline.md`、`draft-check.md`、两份审查报告的最终记录，以及所有作为本次发布依据的交叉复验通过记录，均绑定准备发布的最终页面版本
- `fix-log.md` 已记录全部修复、复验、交叉复验、轮次快照、遗留问题和最终回归结果

“报告中没有待修复字样”不构成通过条件；必须依据问题最后状态事件和复验记录判断。

## 14. 最终回归检查

最终回归检查针对准备提交确认的页面版本，至少包含：

### 14.1 内容与范围

- 概念含义、核心问题和边界与 `scope.md` 一致
- 页面结构和教学方式与 `outline.md` 一致
- C/F/N 引用与 `evidence.md` 一致
- 没有重新引入被排除内容或证据不足内容

### 14.2 技术内容

- 核心公式和符号前后一致
- 推导关键步骤可复算
- 数字例子和四舍五入正确
- 代码运行结果与正文一致
- 伪代码和图示与正文机制一致
- 教学简化及适用边界准确

### 14.3 小白阅读路径

- 基础知识在首次依赖前讲解
- 核心问题都有完整答案
- 贯穿内容前后一致并逐步推进
- 章节完成检查和过渡成立
- 常见误解和适用边界已处理
- 折叠块全部收起时正文完整

### 14.4 页面功能

- `<title>`、`.nav-brand` 和页面主标题一致
- 标题 ID 唯一，目录与锚点一致
- 本地资源和站内链接有效
- HTML 标签闭合
- 公式成功渲染
- 代码高亮语言正确
- 目录、主题切换、折叠块、阅读进度和返回顶部可用
- 图片和替代文本正常

检查方法、环境、命令和实际结果写入 `fix-log.md`，不得只记录“已检查”。

## 15. 最终发布确认

最终确认材料包括：

- 最终页面路径和版本
- 研究范围和教学大纲确认版本
- 技术审查轮次、结果和发布资格
- 小白审查轮次、结果和发布资格
- 已修复的阻断、重要和轻微问题数量
- 遗留轻微问题及接受理由
- 最终回归检查的实际结果
- 当前页面的适用范围和明确不展开内容

最终确认由人工完成，结果记录为“通过”或“退回”。自动执行者不得代填“通过”。

### 15.1 确认通过

确认通过后方可：

1. 更新仓库根目录的 `content.json`
2. 从仓库根目录运行：

```bash
python3 scripts/generate_index.py
```

3. 确认命令成功退出
4. 检查首页条目的标题、描述和链接目标
5. 打开首页链接，确认最终概念页面正常加载
6. 在 `fix-log.md` 的“发布执行”章节记录页面、`content.json`、生成首页、命令、退出码和实际链接检查结果

### 15.2 确认退回

根据退回意见分类：

- 改变研究范围：返回阶段 1
- 改变教学大纲：返回阶段 2
- 局部内容或页面问题：创建新的 T/B 问题编号；未达到第 3 轮时返回阶段 5 并进入下一审查轮次，已经完成第 3 轮时进入人工决策，不得自动开始第 4 轮
- 仅轻微问题的接受决定改变：更新遗留清单并重新提交最终确认

最终确认退回后，不得更新 `content.json` 或首页。

## 16. 阶段完成条件

本阶段只有在以下条件全部满足后结束：

- 最终发布确认结果为“通过”
- `content.json` 已更新
- `python3 scripts/generate_index.py` 成功执行
- 首页条目和链接已经实际检查
- 最终页面能够从首页正常打开
- `fix-log.md` 已记录发布结果、最终页面版本和配套文件状态

任一条件不满足时，阶段 5 仍处于进行中。
