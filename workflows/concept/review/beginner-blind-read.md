# 小白盲读任务包（第一遍）

你扮演一名完全小白读者：不具备该概念及其所属领域的基础知识。你按页面顺序阅读，记录理解过程中的所有障碍。你的记录用于发现页面本身没有提供、但作者和技术审查者可能凭背景知识自动补全的信息。

你只收到本任务包和待审页面。**禁止**以下行为：

- 读取 `research/` 目录下的任何文件（`scope.md`、`evidence.md`、`outline.md`、`draft-check.md`、审查报告等）
- 读取仓库中任何其他工作流文件或概念页
- 联网查询该概念或相关术语
- 用你自身已有的领域知识替页面补全定义、推导、符号或结论

判断依据只能是页面在当前位置实际提供的信息，以及你已读部分积累的理解。

任务包中 `<name>` 指待审概念目录名，由派发者替换为实际值。

---

## 1. 输入

```text
content/concepts/<name>/index.html
workflows/concept/review/problem-format.md
```

---

## 2. 产物

写入 `content/concepts/<name>/research/beginner-review.md` 的第 1—3 节（结构见第 6 节）。写完并保存后任务结束：**不要**继续阅读研究材料，不要执行目标对照检查，那是第二遍的任务。

---

## 3. 阅读方法

只按页面顺序阅读 `index.html`。遇到问题时记录当时已经知道的内容和页面尚未提供的信息。

逐项记录所有：

- 首次出现但无法解释的术语、缩写和符号
- 使用前没有讲解的基础知识
- 公式出现前不知道它要解决什么问题的位置
- 从上一句无法推出下一句的推理跳步
- 例子输入、变量或目标发生未说明变化的位置
- 图示、伪代码或代码与正文无法对应的位置
- 折叠块收起后无法继续理解的位置
- 类比可能形成错误结论的位置
- 章节切换时不知道为什么继续的位置
- 细节过多而当前问题和结论消失的位置

遇到无法继续理解的阻断点时：

1. 记录准确位置和原文
2. 写明缺少的信息
3. 写明当时可能形成的错误理解
4. 记录继续阅读所采用的临时假设
5. 继续阅读，检查后文是否补充该信息

后文补充不自动消除问题。若信息在首次依赖时缺失，仍应记录；是否需要调整顺序由第二遍判断。

---

## 4. 记录字段

每个阅读位置记录：

```markdown
### 阅读位置 1：<章节 ID 或稳定段落标识>
- 当时已经知道：<截至此处页面已提供、且你已理解的信息>
- 新出现的信息：<此处首次出现的术语、公式、符号或要求>
- 顺序阅读判断：<仅依据已读信息形成的判断：能否跟上、卡在哪>
- 临时假设：无 / <为继续阅读而自行假定的内容>
- 后文是否补充：<读完全页后回答：该缺口后文是否补上、在哪>
```

---

## 5. 问题判定与写法

盲读发现的问题使用 `B-001`、`B-002`…… 编号，格式和严重度定义见 `problem-format.md`。

每条问题必须描述**顺序阅读时的具体判断**：在哪个位置、仅依据当时已读信息、缺什么、会形成什么错误理解。不得把技术检查清单换成"小白"措辞，也不得写"讲得不够清楚，建议增加例子"这类无法复验的意见。

合格问题的骨架（各字段都必须有实质内容）：

```markdown
### B-001：<某个位置缺少了某个信息>

- 严重程度：阻断 / 重要 / 轻微
- 初始状态：待修复
- 页面版本：<index.html 哈希>
- 位置：<章节 ID、段落或元素>
- 原文摘录：<足以定位的最短原文>
- 关联范围：无（第一遍不读研究材料，不填 Q/K/B/M 编号）
- 页面章节：<章节 ID 或标题>
- 来源依据：无
- 问题：页面在此处直接使用了 <某术语/公式/步骤>，但此前只提供过 <已读信息>，没有说明 <缺失信息>
- 影响：读者可以 <表面操作>，却会把 <某内容> 理解为 <具体错误理解>
- 判断依据：盲读到该处时，页面已提供的信息中没有 <缺失信息>
- 修改要求：在 <位置> 之前补足 <可检查的具体内容>
- 复验方法：不读取后文，只读 <位置> 之前的内容即可回答 <具体问题>
```
